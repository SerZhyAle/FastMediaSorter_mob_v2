# FastMediaSorter VR-редакция

## Что такое VR-редакция?

FastMediaSorter VR - выделенная сборка FastMediaSorter для VR-шлемов: Meta Quest 3, Quest Pro, Quest 2 и устройств Android XR. Использует тот же код и те же функции, что и Standard, плюс слой OpenXR для стереоскопического рендеринга в шлеме.

VR-редакция - не отдельное приложение, а тот же код, собранный как `vr` product flavor с дополнительным слоем OpenXR-рендеринга.

**Иммерсивный режим:** per-eye режим в шлеме работает в сборке `vr` и в sideload-сборке `noLegal` (см. [Установка VR через sideload](VR_SIDELOAD-ru.md)). Управление описано на странице [Управление в иммерсивном VR](VR_CONTROLS-ru.md).

## Ключевые отличия от стандартной версии

| Функция | Standard | VR (`vr` / `noLegal`) |
|---------|----------|----|
| Crop 3D-контента (SBS/OU/180/360) в один глаз | Есть, работает в обычном плеере | Есть, тот же код |
| Полный per-eye рендеринг в шлеме | Недоступен | Да |
| Ручной override формата + настройки распознавания | Скрыты | Активны (вкладка 3D в диалоге Control, блок VR/3D в настройках Медиа) |
| Wear OS companion | Включён | Не включён |
| Целевые устройства | Телефоны, планшеты | Телефоны, планшеты, шлемы Quest и Android XR |

## Что идентично

Всё остальное работает так же - файловые операции (копировать, переместить, удалить, переименовать), сортировка, избранное, сетевые диски (SMB, SFTP, FTP), облачные хранилища (Google Drive, OneDrive, Dropbox), субтитры, выбор аудиодорожки, таймер сна, слайд-шоу и все элементы навигации. Трансляции включены полностью - воспроизведение интернет-радио и видеотрансляций (http/HLS/DASH/RTSP), каталог трансляций, встроенный аудиомини-плеер с ICY-метаданными (станция/трек) и фильтры по категории и языку работают так же, как на телефоне.

## Как это работает

1. **Single-eye 3D - на любом флейворе:** контент SBS/OU/180/360 определяется автоматически (по маркерам в имени файла, метаданным MP4/Matroska или опциональной эвристике по соотношению сторон) и обрезается до одного глаза, чтобы нормально воспроизводиться на любом плоском экране - телефон, планшет или обычное 2D-окно шлема. Работает из коробки, без VR-сборки.

2. **Полное погружение - `vr` и `noLegal`:** на Quest или другом OpenXR-шлеме запуск 3D-контента через бейдж VR в плеере, пункт «Open in VR Cinema» в меню файла в Browse или кнопку «Test Immersive» в настройках открывает выделенную OpenXR-сессию с настоящим per-eye рендерингом для SBS/OU/180/360. Полоса HUD в шлеме несёт кнопки воспроизведения, полосу перемотки, громкость, глубину стерео и дорожки аудио и субтитров; стик перематывает, а хват вместе со стиком переключает файлы. **A** или **X** либо кнопка **ВЫХОД** на полосе возвращают к плоскому экрану на той же позиции.

**Просмотр прямо в шлеме:** у immersive-сессии есть собственное окно обзора, поэтому вы не заперты в том единственном файле, которым её открыли. Пункт **«Open in VR Cinema»** для *ресурса* (а не для отдельного файла) открывает этот ресурс сеткой плиток перед вами. Наведите луч контроллера на плитку и нажмите курок или пройдите по сетке стиком: папки раскрываются на месте, а видео или 3D-изображение запускается в immersive-плеере, ни разу не возвращая вас на плоский экран. У плиток есть превью, а 3D-изображения классифицируются той же детекцией SBS/OU/эквирект, что и в плоском плеере.

## Поддерживаемый контент

| Тип контента | Рендеринг |
|-------------|-----------|
| SBS-видео (Side-by-Side) | Crop одного глаза везде; полное per-eye стерео в иммерсивном режиме |
| OU-видео (Over-Under) | То же самое |
| SBS/OU-фото | Crop одного глаза везде; per-eye стерео в иммерсивном режиме |
| Видео и фото 180° / 360° | Полусфера или сфера вокруг вас в иммерсивном режиме |
| 2D-видео / 2D-фото | Обычное воспроизведение и показ, как в Standard |
| Аудио | Стандартное воспроизведение (унаследовано) |
| Интернет-радио (http/HLS, ICY) | Встроенное воспроизведение через мини-плеер Трансляций |
| Видеотрансляция / RTSP | Полноэкранный плеер, как в Standard |

## Дистрибуция

| Магазин | Платформа | Сборка | Иммерсивный режим |
|---------|-----------|--------|--------|
| Meta Horizon Store | Quest 3 / Quest Pro / Quest 2 | `assembleVrRelease` | Да |
| Google Play | Устройства Android XR | `bundleVrRelease` (AAB) | Да |
| Sideload | Телефоны, планшеты, Quest, Android XR | APK `noLegal` | Да |

Имя пакета: `com.sza.fastmediasorter` - общее с флейвором `standard` (см. «Технические ограничения» ниже).

Установка без магазина - см. [Установка VR через sideload](VR_SIDELOAD-ru.md).

## Команды сборки

`build-vr-release.ps1` - единственный VR-сборщик. Debug-сборки и AAB собираются напрямую через Gradle.

```powershell
# Release APK (Meta Horizon Store) - алиас: .\a.ps1 vr
.\scripts\builders\build-vr-release.ps1

# Debug APK
.\gradlew.bat assembleVrDebug

# Release APK / AAB (Google Play / Android XR)
.\gradlew.bat assembleVrRelease
.\gradlew.bat bundleVrRelease
```

Как поставить сборку на шлем - см. [Установка VR через sideload](VR_SIDELOAD-ru.md).

## Технические ограничения

- **Поддерживаемая ABI:** только `arm64-v8a`. Meta Quest 2/3/Pro и гарнитуры Android XR - исключительно 64-битный ARM; для VR-флейворов не собираются слои `armeabi-v7a` или `x86_64`.
- **Минимальный Android:** API 29 (Android 10) для магазинного варианта `vr` - Meta Horizon Store принимает минимум от API 29 до 34, и нижняя граница диапазона сохраняет охват всех моделей Quest. Сайдлоад-сборка `noLegal` остаётся на API 26 (Android 8.0). Quest 2 ≈ Android 10, Quest 3 ≥ Android 12.
- **Целевой Android:** API 34 для магазинного варианта `vr` - Meta требует для иммерсивного приложения именно это значение, а не «не выше». Все остальные варианты целятся в API 36.
- **XR-рантайм:** для входа в иммерсивный режим нужен OpenXR 1.1.48+. Без обнаруженного XR-рантайма приложение работает как обычно, в плоском плеере - отдельного экрана-заглушки нет.
- **Нативный код:** поставляется OpenXR loader AAR плюс `openxr_native.so` (C++ мост, собираемый CMake). Добавляет ~8 МБ нативной нагрузки поверх стандартной сборки.
- **Нет Wear OS companion:** у шлемов нет парных часов, поэтому `SUPPORT_WEAR_COMPANION = false`.
- **Package ID:** у флейвора `vr` нет собственного `applicationIdSuffix` - он делит `com.sza.fastmediasorter` со `standard` и со sideload-сборкой `noLegal`. Одновременно на устройстве может быть установлен только один из трёх - установка другого заменяет уже стоящий.
- **DTS / расширенные кодеки:** всегда вшиты через `fms-ffmpeg-dts.aar`. Hardware Quest везде arm64, поэтому single-ABI AAR достаточно каждому VR-пользователю.

### Каналы дистрибуции

Иммерсивную VR/XR-сессию несут два флейвора:

- **`noLegal`** - ADB sideload через Developer Mode. Универсальная sideload-сборка покрывает телефоны, планшеты, Quest и Android XR одним APK. Всегда содержит DTS, Python+yt-dlp+NewPipeExtractor и полный VR-рантайм вне зависимости от политики магазинов. VR-функциональность gate'ится по runtime: на устройствах без OpenXR-рантайма VR-контролы показываются как disabled с advisory-надписью.
- **`vr`** - Meta Horizon Store / Google Play AAB. Остаётся Store-clean: без GPL-экстракторов, без Python-рантайма, без yt-dlp. Несёт ту же иммерсивную OpenXR-сессию, что и `noLegal`.

> **Историческая заметка.** До 2026-05-19 для VR-only sideload существовал отдельный флейвор `vrUnlicensed`. Он слит в `noLegal` по тикету S0250, потому что `noLegal` уже нёс все нужные для VR зависимости плюс более широкую sideload-поверхность. Текущий список VR / noLegal возможностей остаётся в [FEATURES-ru.md](FEATURES-ru.md) и [DOCS_MAP.md](DOCS_MAP.md).

### Fallback на телефоне

Если APK `vr` запущен на обычном телефоне без XR-рантайма, он работает точно как Standard и всё воспроизводит в обычном плоском плеере.
