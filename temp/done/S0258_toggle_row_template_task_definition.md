# S0258 — Постановка задачи

**Дата:** 2026-05-19
**Ветка:** `DEBUG-v004`
**Инициатор:** ad-hoc user request
**Статус UI-gate:** READY

## Запрос

Во всех формах и экранах настроек приложения накопились toggle/switch-строки, собранные вручную в разных вариантах. Требуется:

- унифицировать их в один канонический шаблон;
- закрепить шаблон как обязательный для всех новых toggle-строк;
- приступить к поэтапной миграции существующих строк.

## Зафиксированный целевой шаблон

- слева расположен toggle/switch;
- справа от toggle расположен текст названия;
- кнопка helper прижата сразу к названию, а не уходит в правый край строки;
- под названием расположен короткий справочный subtitle меньшим шрифтом;
- helper открывает контекстную подсказку;
- новые toggle-строки должны создаваться только через общий шаблон/компонент.

## Scope первой итерации

- `app_v2` only;
- экраны настроек `ui/settings/fragments/*`;
- формы добавления/редактирования ресурса как следующая волна миграции;
- pilot migration на одном небольшом settings-экране в рамках текущего захода.

## Вне скоупа первой итерации

- `wear/`;
- playback/control dialogs, где toggle-строки живут не как настройки формы, а как операционные панели;
- checkbox rows — для них сохраняется отдельный canonical pattern;
- полная одномоментная миграция всех экранов в один коммит.

## UI Clarification Outcome

**Status:** READY

### Approved decisions

- Portrait: один и тот же компонент строки toggle.
- Landscape: тот же компонент; при наличии `layout-land/` миграция идёт парой.
- Placement: switch слева, title + helper в одной верхней строке текстового блока, subtitle под ними.
- Visibility: helper допускается скрывать только там, где у строки пока нет tooltip payload; сам слот в компоненте обязателен.
- Accessibility: компонент обязан поддержать touch, keyboard, D-pad, contentDescription и focus-state.
- Rollout: сначала foundation-компонент, затем pilot screen, потом пакетная миграция остальных settings/form screens.

### Осознанное отклонение от текущего канона

Текущий `docs/ARCHITECTURE.md` и `.github/copilot-instructions.md` требуют help-иконку как rightmost-child строки. По запросу владельца канон меняется: helper переезжает вплотную к title. Это изменение должно быть внесено в load-bearing repo rules вместе с компонентом.
