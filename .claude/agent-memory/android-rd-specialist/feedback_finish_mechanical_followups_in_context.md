---
name: finish-mechanical-followups-in-context
description: Don't defer a mechanical follow-up to a later session/ticket when it can be finished now in-context
type: feedback
---

When a task has a mechanical tail (e.g. applying a config change the strategic doc just decided), finish it NOW in the same session, not parked into a separate child ticket "to do later".

**Why:** Owner (2026-06-30, S0816/S0825): "нет никакой иронии - нужно полностью иследовать и выполнить всё необходимое по этой задаче, сейчас здесь, чтобы потом не переплачивать." Re-opening a parked ticket in a fresh session re-pays the context-loading cost - deferring is the expensive option, not the cheap one. The cost-discipline goal is *less total spend*, not *less spend per session*.

**How to apply:** Splitting doc-policy from mechanical change into separate tickets is fine for *traceability*, but still execute both in the current session when the mechanical part is well-scoped and low-risk. Reserve genuine deferral for work that truly needs new research, owner input, or a build/device gate not available now. When unsure whether to defer, default to finishing in-context and say so. Note: this does NOT override the playbook caution about which skills are safe to change - scope discipline still applies, only the *timing* changes. See [[about-me]], [[argue-then-obey]].
