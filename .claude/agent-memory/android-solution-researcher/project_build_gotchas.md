Build/tooling traps that affect how the researcher INTERPRETS build artefacts and catalog state surfaced by writer agents or sitting in `logs/`/`temp/`.

1. **`build-debug.PS1` flaky daemon stop.** Gradle sometimes fails with `FAILURE: .. Gradle build daemon has been stopped: stop command received` (or a Windows file-lock `NoSuchFileException` in `temp/gradle-tmp/kotlin-backups/*.backup`) at the `:app_v2:compileStandardDebugKotlin` step. Likely cause: the IDE (VSCode/Android Studio with the project open) runs its own Gradle sync after file changes and stops daemons. `build-debug.PS1` only auto-retries for `Failed to store cache entry` and `kapt3/incrementalData` lock errors - **not** for daemon-stop. A `e: Daemon compilation failed: null` / `Backend Internal error: IR fake override builder` line can appear and the build still succeeds (falls back to in-process compile).
   **How to apply (research):** When reading a writer-agent's build failure report or a `temp/*.log` showing daemon-stop, do NOT cite it as a code-level build failure in the research report. Label it "flaky transport - retry expected to pass". A real build failure has a `What went wrong` block with a Kotlin/Java error site, not just "daemon stopped".

2. **`dev/CATALOG/app_v2.jsonl` and `app_v2.md` are gitignored** (confirmed via `git check-ignore`). They are local indexes regenerated by `scripts/catalog_sync.ps1`.
   **How to apply (research):** Use these files freely as a fast index for semantic lookups during research. Do NOT cite them in the report as if they were tracked repo state - their content lags behind disk until the writer agent re-runs the sync. When citing a class for the report, cite the actual `.kt` file path under `src/`, not the catalog row that pointed you to it.

3. **Chaquopy variant gate (S0174/S0175).** When `local.properties` has `chaquopy.enabled=true` (set for IDE sync on noLegal flavor), `isNoLegalBuild=true` fires in `app_v2/build.gradle.kts` and a `beforeVariants` block **disables all non-noLegal variants**. Fixed 2026-05-12 by making explicit `-Pchaquopy.enabled` Gradle property take strict precedence over `local.properties`, and by adding `-Pchaquopy.enabled=false` to ALL non-noLegal build scripts.
   **How to apply (research):** If a build log shows "task `assembleStandardDebug` not found" or "only noLegal variants visible", and the log is from a session where `local.properties` had `chaquopy.enabled=true`, cite this gate as the root cause - not a real build configuration issue.
