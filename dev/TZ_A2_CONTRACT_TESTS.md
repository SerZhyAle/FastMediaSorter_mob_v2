## Описание проблемы

`ResourceEditor` — центральный UI для создания/редактирования ресурсов. Отсутствуют тесты, покрывающие контракт: какие поля отображаются, какие валидации срабатывают, как работают коллапс-секции.

## Цель

Набор контрактных тестов, фиксирующих поведение ResourceEditor для каждого типа ресурса.

---

## Требования

### Покрытие тестами

1. **Схема полей по типу ресурса**
   - LOCAL: path, name, fileTypeFilter
   - SMB/SFTP/FTP: host, port, path, credentials, name
   - Google Drive / OneDrive / Dropbox: account, remotePath, name

2. **Валидации**
   - Обязательные поля не могут быть пустыми
   - Port — только числа в допустимом диапазоне
   - Path — корректный формат
   - Дублирование имён ресурсов — предупреждение

3. **Коллапс-секции**
   - Секции "Advanced" / "Authentication" сворачиваются/разворачиваются
   - Состояние секций сохраняется при повороте экрана

4. **CRUD-операции**
   - Создание нового ресурса → запись в БД
   - Редактирование существующего → обновление записи
   - Копирование ресурса → новая запись с изменённым именем
   - Удаление → запись помечается/удаляется
