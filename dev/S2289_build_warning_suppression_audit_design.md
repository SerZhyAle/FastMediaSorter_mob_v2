# S2289 - Дизайн аудита предупреждений сборки

## Контекст

Стандартная debug-сборка сообщает экспериментальную опцию Android Gradle Plugin, неэффективную minify-конфигурацию watchface и агрегированное предупреждение о deprecated Gradle features. Источники последнего нельзя определить через поддерживаемый путь, поскольку `build-debug.PS1` не передаёт параметры Gradle.

Lint и detekt baseline скрывают исторические замечания. Для detekt подтверждены согласованность format/signal представлений и отсутствие поглощённых записей, но 517 новых замечаний требуют отдельной классификации, а не единой массовой правки.

## Решение

1. Добавить в существующий debug build-wrapper параметр оставшихся аргументов.
2. Добавлять их в конец уже сформированного набора параметров Gradle.
3. Запускать `--warning-mode all` только в диагностическом вызове.
4. Сохранить полный вывод в артефакте тикета и классифицировать каждый источник.
5. Исправлять только локальные подтверждённые предупреждения; крупные или спорные случаи оставить с обоснованием либо выделить в отдельные тикеты.

## Ограничения

- Не вызывать Gradle напрямую.
- Не менять detekt или lint baseline массово.
- Не использовать устройство или эмулятор.
- Обычная сборка без дополнительных аргументов сохраняет прежнее поведение.

## Проверка

- Debug build через wrapper с `--warning-mode all` завершается с фактическим exit code и показывает источник deprecated API.
- Обычный debug build завершается успешно после изменения wrapper.
- Baseline absorption и format/signal split gates остаются зелёными.

## Результат

Единственный источник deprecated Gradle API оказался внутри применяемого плагина, а не в build logic проекта. `DetektPlugin` (detekt 1.23.8) вызывает `ReportingExtension.file("detekt")` и передаёт результат в `DetektExtension.setReportsDir(File)` - это происходит внутри `apply(plugin = ..)`, поэтому конфигурация со стороны проекта не может ни предотвратить, ни заменить вызов. Строка `build.gradle.kts:52` использует `Project.file(Object)`, у которого deprecation отсутствует, и её переписывание предупреждение не снимает.

Практический вывод для будущих аудитов: происхождение deprecation дешевле доказывать дизассемблированием плагина (`javap -p -c` по jar из Gradle cache), чем повторными сборками с `--stacktrace` - сборка показывает только текст предупреждения, а байт-код называет и вызывающий класс, и аргумент. Снятие предупреждения переносится в `S2290` (обновление detekt).
