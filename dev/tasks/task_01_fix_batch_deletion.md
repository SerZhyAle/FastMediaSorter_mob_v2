# Задача 1: Исправление удаления большого числа локальных файлов

## Описание проблемы
При удалении нескольких локальных файлов за один раз удаляются не все и плохо работает обработка ошибок.

## Приоритет
🔴 Высокий (критический баг)

## Затронутые файлы
- `BrowseViewModel.kt` - логика удаления
- `BrowseActivity.kt` - UI для отображения результатов
- Возможно: `FileOperationManager.kt` / `DeleteUseCase.kt`

---

## Промпты для разработки

### Промпт 1: Анализ проблемы
```
Изучи текущую реализацию массового удаления файлов в BrowseViewModel.kt.
Найди метод, который обрабатывает удаление нескольких файлов.
Проверь:
1. Как формируется список файлов для удаления
2. Как вызывается MediaStore.createDeleteRequest() для Android 11+
3. Как обрабатывается результат permission request
4. Есть ли логирование процесса удаления

Покажи найденный код и объясни текущую логику.
```

### Промпт 2: Определение точки сбоя
```
На основе анализа кода определи, на каком этапе может происходить сбой:
1. Permission request - возможно не все файлы включены в запрос
2. Actual deletion - сбой при выполнении удаления
3. UI update - файлы удалены но UI не обновился

Добавь детальное логирование на каждом этапе:
- Перед созданием delete request (сколько файлов)
- После получения разрешений (какие файлы одобрены)
- После попытки удаления (успех/ошибка для каждого файла)
```

### Промпт 3: Исправление логики batch deletion
```
Исправь логику массового удаления:

1. Убедись что MediaStore.createDeleteRequest() вызывается корректно для всех выбранных файлов
2. Проверь что все URIs валидны и доступны
3. Добавь обработку случая когда permission granted только для части файлов
4. Реализуй retry mechanism если некоторые файлы не удалились с первого раза

Используй существующие паттерны из кода (например как сделано в single file deletion).
```

### Промпт 4: Progress indicator
```
Добавь отображение прогресса если удаление занимает >2 секунд:

1. В BrowseViewModel добавь flow или LiveData для progress (current/total файлов)
2. В BrowseActivity подпишись на этот поток и показывай ProgressDialog или ProgressBar
3. Добавь кнопку "Отмена" для прерывания длительной операции
4. При завершении скрывай прогресс и показывай результат

UI компоненты:
- Текст: "Удаление N из M файлов..."
- ProgressBar (horizontal, determinate)
- Button "Отмена"
```

### Промпт 5: Улучшение обработки ошибок
```
Интегрируй с существующим механизмом показа детальных ошибок:

1. Найди где в коде используется настройка "детальные описания ошибок"
2. Используй тот же диалог для показа ошибок при batch deletion
3. Для каждого файла который не удалился, включи в сообщение:
   - Имя файла
   - Причину ошибки (permission denied, file not found, etc)
4. Добавь логирование в Timber для отладки

Если настройка выключена - показывай краткое сообщение: "Удалено N из M файлов"
```

### Промпт 6: Тестирование
```
Создай тестовую функцию в коде (можно временную) для проверки:

1. Выбери программно 5-10 файлов
2. Запусти batch deletion
3. Проверь логи - прошли ли все этапы
4. Проверь UI - обновился ли список файлов

Протестируй вручную:
- Удаление 2-3 файлов
- Удаление 10+ файлов
- Отмена операции в процессе
- Ошибка permission для части файлов

Запиши результаты в комментарии кода.
```

## Критерии готовности
- ✅ Все выбранные файлы удаляются успешно
- ✅ Прогресс показывается если процесс >2 сек
- ✅ Ошибки отображаются через существующий диалог
- ✅ Логи детально описывают процесс удаления
- ✅ UI корректно обновляется после удаления
