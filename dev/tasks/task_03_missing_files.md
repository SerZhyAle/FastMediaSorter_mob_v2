# Задача 3: Не все файлы видны даже с включенными фильтрами

## Описание проблемы
В локальных папках не все файлы отображаются, даже когда включены "показывать скрытые файлы" и "все файлы".

## Приоритет
🔴 Высокий (функциональный баг)

## Примечания
- Проблема замечена на Android 16 (возможно связано с новым Storage API)
- Нужно проверить логику для всех типов ресурсов (Local, SMB, Cloud)

## Затронутые файлы
- `LocalResourceManager.kt` - сканирование локальных файлов
- `MediaFileRepository.kt` - фильтрация
- `BrowseViewModel.kt` - применение фильтров

---

## Промпты для разработки

### Промпт 1: Создание тестового сценария
```
Создай тестовую структуру папок для воспроизведения проблемы:

1. Создай папку `/sdcard/TestHiddenFiles/`
2. Добавь в неё программно:
   - 5 обычных файлов (test1.jpg, test2.mp4, etc)
   - 3 скрытых файла (.hidden1.jpg, .hidden2.png)
   - Подпапку `subfolder/` с 3 файлами
   - Скрытую подпапку `.hidden_folder/` с 2 файлами

3. Открой эту папку в приложении с настройками:
   - "Показывать скрытые файлы" ON
   - "Все файлы" ON
   - "Сканировать подпапки" ON

4. Запиши в логи сколько файлов отобразилось vs сколько реально существует.
```

### Промпт 2: Анализ фильтров
```
Изучи логику фильтрации файлов:

1. Найди в LocalResourceManager.kt метод сканирования файлов
2. Проверь как применяются фильтры:
   - `shouldShowHiddenFiles`
   - `allFilesMode`  
   - `scanSubdirectories`
3. Найди где файлы могут быть пропущены (excluded)

Покажи код фильтрации и объясни логику.
Найди потенциальные баги:
- Фильтр применяется дважды?
- Проверка имени файла некорректна?
- Permissions блокируют доступ?
```

### Промпт 3: Android 16 Storage API
```
Проверь совместимость с Android 16 (API 35):

1. Изучи как используется MediaStore для сканирования
2. Проверь нет ли deprecated API calls
3. Если используется MediaStore - проверь правильность query:
   - Включены ли скрытые файлы в selection?
   - Корректен ли MIME type filter?
4. Возможно нужен MediaStore.setIncludePending() или аналог

Найди документацию Android 16 storage changes.
Покажи текущий MediaStore query и предложи исправления.
```

### Промпт 4: Проверка всех типов ресурсов
```
Проверь логику сканирования для каждого типа ресурса:

1. **Local** (LocalResourceManager):
   - Использует MediaStore или File API?
   - Корректно ли обрабатываются скрытые файлы?

2. **SMB** (SmbResourceManager):
   - Фильтруются ли скрытые файлы на стороне клиента?
   - Есть ли проблемы с путями (backslash/slash)?

3. **Cloud** (GoogleDriveManager, OneDriveManager):
   - Запрашиваются ли trashed/hidden items?

Найди и покажи код сканирования для каждого типа.
Унифицируй логику фильтрации где возможно.
```

### Промпт 5: Логирование пропущенных файлов
```
Добавь детальное логирование пропущенных файлов:

1. В process scanning добавь счетчики:
   - Total files found
   - Files after hidden filter
   - Files after type filter
   - Files after permission check
   - Final files shown

2. Для каждого пропущенного файла логируй:
   - File path
   - Reason: "hidden", "wrong type", "no permission", "other"

3. Добавь DEBUG опцию в настройках:
   - "Показать статистику сканирования"
   - При включении - показать dialog с results

Логи должны помочь найти где именно файлы теряются.
```

### Промпт 6: Исправление и тестирование
```
На основе найденных проблем исправь код:

1. Исправь фильтры если они работают некорректно
2. Добавь proper support для Android 16 storage API
3. Убедись что recursive scanning работает для подпапок
4. Добавь обработку symlinks если нужно

Протестируй:
- Тестовая папка из Промпта 1
- Реальные папки DCIM, Downloads с разными файлами
- Все режимы: скрытые ON/OFF, подпапки ON/OFF
- Разные типы ресурсов

Сравни количество файлов в файловом менеджере vs в приложении.
```

## Критерии готовности
- ✅ Все файлы из тестовой папки отображаются
- ✅ Скрытые файлы видны когда фильтр включен
- ✅ Recursive scanning работает корректно
- ✅ Нет различий между file manager и приложением
- ✅ Работает на Android 16
- ✅ Логирование показывает что файлы не пропускаются
