# План по устранению проблем (на основе анализа логов от 2026-02-28)

Данный документ содержит пошаговый план устранения узких мест производительности и ошибок, выявленных в ходе последнего анализа логов (`temp/current.log`), отсортированный по приоритету.

## Приоритет P0: Критичные оптимизации (Блокируют производительность/стабильность)

### 1. Ранняя проверка существования файла при кросс-протокольном копировании (Bridge Copy)
*   **Проблема:** При копировании из SMB на FTP (и других комбинациях через Bridge), если целевой файл уже существует, а параметр `overwrite` равен `false`, система всё равно сначала скачивает весь исходный файл во временный кэш (например, файл размером 11 МБ кэшируется локально), и лишь потом `AtomicFileOperationStrategy` прерывает операцию с ошибкой "Файл уже существует". Это приводит к колоссальным расходам трафика, памяти и времени.
*   **Решение:** Внести изменения в базовую логику копирования `BaseFileOperationHandler` или `FileOperationUseCase`. Перед началом загрузки во временный файл (Bridge copy) необходимо делать быстрый запрос к целевому обработчику файла (Destination Handler) для проверки: существует ли файл (с учетом правила `overwrite`). Если существует и `overwrite=false`, прерывать операцию сразу, до скачивания.
*   **Ожидаемый результат:** Мгновенный отказ в копировании уже существующих файлов между разными протоколами без паразитного сетевого трафика.

### 2. Кэширование проверки специфичных Credentials для SMB
*   **Проблема:** В логах видно постоянное обращение к базе данных из `SmbOperationStrategy` для получения учетных данных конкретной шары (`NetworkCredentialsRepository: DAO returned NULL`). Так как для расшаренной папки нет своих отдельный кредов, операция каждый раз стучится в БД `Room`, получает NULL, и откатывается к учетным данным хоста SMB. Это создает ненужную нагрузку на I/O-поток и SQLite при каждой операции с файлом из шары.
*   **Решение:** Внедрить легковесное In-Memory кэширование (например, `ConcurrentHashMap`) внутри `NetworkCredentialsRepository` или `SmbOperationStrategy`. Кэш должен сохранять признак отсутствия специфичных учетных данных для конкретного пути в течение текущей сессии (или короткого времени TTL), чтобы последующие операции сразу использовали Host Credentials, минуя запрос к БД.
*   **Ожидаемый результат:** Снижение количества обращений к БД SQLite, ускорение инициализации потоков данных SMB.

## Приоритет P1: Стабилизация UI и устранение спама в логах

### 3. Обработка ошибки аппаратного декодера ExoPlayer (VP8 / WebM)
*   **Проблема:** Зафиксирована ошибка аппаратного кодека: `[OMX.google.vp8.decoder] setPortMode on output to DynamicANWBuffer failed w/ err -1010` при попытке воспроизведения VP8 видео. Обычно ExoPlayer сам переключается на софтверный рендеринг (MediaCodec SW), но эта ошибка может вызывать стартовые фризы воспроизведения на API 28.
*   **Решение:** Проверить настройки конфигурации `ExoPlayer` (`Media3`). Убедиться, что программный (software) декодер разрешен как фоллбэк (`MediaCodecSelector.DEFAULT`). Возможно, потребуется принудительно обходить конкретные старые аппаратные кодеки через кастомный `MediaCodecSelector` для форматов VP8, если фризы подтвердятся.
*   **Ожидаемый результат:** Плавный старт воспроизведения WebM/VP8 без задержек на попытки использования неработающего аппаратного кодека.

### 4. Устранение спама в логах `StaticLayout`
*   **Проблема:** Частые варнинги в логе UI: `StaticLayout: maxLineHeight should not be -1. maxLines:1 lineCount:1`. Возникает в основном из-за конфликта стилей Material3/AppCompat в `TextView` (например, совместное использование `maxLines="1"`, `ellipsize="end"` без указания `includeFontPadding="true"` или с кастомными шрифтами).
*   **Решение:** Провести аудит XML layot'ов (в первую очередь итемы списков `MediaFileAdapter` и элементы управления плеера). Убрать лишние атрибуты, вызывающие внутренние конфликты в `StaticLayout`, либо выставить `android:includeFontPadding="true"`.
*   **Ожидаемый результат:** Более чистый Logcat, минимизация мусорных операций измерения текста в основном потоке UI.
