# План аудита перед релизами (FastMediaSorter v2)

Данный документ описывает шаги проверки проекта перед публикацией в соответствии с требованиями пользователя и файлом `WORK_PLAN_ACTIONABLE_RU.md`.

## 1. Проверка документации
- Проверить актуальность `README.md`, `AGENTS.md`, `GEMINI.md`.
- Убедиться, что новая архитектура (например, унифицированная авторизация `UnifiedCloudAuthManager`) должным образом документирована.

## 2. Проверка реализации запланированного функционала
Основываясь на `WORK_PLAN_ACTIONABLE_RU.md`, проверить следующие незакрытые или частично закрытые пункты:
- **P2-4**: Интеграция и регрессионное тестирование (Expiry токенов мультиаккаунтов).
- **P3-1**: Унифицированная стейт-машина авторизации (убедиться, что она завершена).
- **P4-1**: Инструментарий логгирования (Correlation ID).

## 3. Аудит кода и соответствия стандартам (GEMINI.md)
- **Архитектура:** Clean Architecture, MVVM + Hilt. Отсутствие сложной логики в Activity.
- **Ограничения:** Размеры файлов < 1000 строк (предупреждение > 500 строк).
- **Папки:** Все временные файлы должны быть строго в `temp/`. В корне чисто.
- **Логирование:** Использование `Timber`, запрет на прямые `Log.d()`.
- **Именование:** Соответствие конвенциям (UseCase, Repository, ViewModel, Manager).

## 4. Валидация сборки и статический анализ (Lint)
- Запуск `.\gradlew.bat lintStandardDebug` и проверка отсутствия новых/критичных предупреждений.
- Запуск `.\gradlew.bat testStandardDebugUnitTest` для проверки юнит-тестов (Smoke-тесты StateMachine и Expiry).
- Попытка сборки Release (если возможно) или Debug для подтверждения работоспособности - `.\gradlew.bat assembleStandardRelease`.

## 5. Рекомендации и исправления
- Исправить найденные мелкие неточности в документации и коде.
- Составить итоговый отчет и рекомендации по оптимизации.
