# ТЗ A1: Multi-Account для OneDrive и Google Drive

## Статус: 📋 Запланировано
## Приоритет: 🔴 Критический
## Зависимости: B5 (Security Hardening)

---

## Описание проблемы

Сейчас multi-account решён концептуально через `credentialsId`, но полный цикл (добавление второго аккаунта, переключение, удаление, re-auth) не реализован ни для OneDrive, ни для Google Drive.

## Цель

Полноценная поддержка нескольких аккаунтов для каждого облачного провайдера с корректным UI и data-flow.

---

## Требования

### Функциональные

1. **Добавление аккаунта**
   - Пользователь может добавить 2+ аккаунта одного провайдера.
   - Каждый аккаунт хранится отдельно с уникальным `credentialsId`.
   - OAuth-flow поддерживает `login_hint` / `prompt=select_account`.

2. **Переключение аккаунтов**
   - При создании облачного ресурса доступен выбор аккаунта из списка.
   - В UI отображается текущий аккаунт (email/display name).

3. **Удаление аккаунта**
   - Удаляется credential-запись и корректно обрабатываются связанные ресурсы.
   - Выполняется ревокация токенов при удалении (см. B5).

4. **Re-authentication**
   - При истечении токена выполняется повторный OAuth с тем же `credentialsId`.
   - Пользователь получает понятное сообщение о необходимости re-auth.

### Нефункциональные

- Переключение аккаунтов не деградирует UX.
- Миграция существующих single-account пользователей проходит без потери данных.
- Решение остаётся backward-compatible с текущей схемой БД.

## Критерии приёмки

- [ ] Можно добавить ≥2 аккаунтов Google Drive.
- [ ] Можно добавить ≥2 аккаунтов OneDrive.
- [ ] Ресурсы привязаны к конкретному аккаунту.
- [ ] Удаление аккаунта не ломает остальные.
- [ ] Миграция с предыдущей версии проходит без потерь.
- [ ] Все строки переведены на 3 языка.

## Проверка полноты

- [ ] Нет дублей credentials для одного `provider + accountEmail`.
- [ ] Ресурсы всегда привязаны к конкретному `credentialsId`.
- [ ] Удаление одного аккаунта не влияет на ресурсы других аккаунтов того же провайдера.

---

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| OAuth collision (один email на два credentialsId) | Средняя | Проверка по email перед созданием записи |
| Rate limit Google API при multiple auth | Низкая | Exponential backoff |
| Потеря данных при миграции | Низкая | Backup + проверка через integration test |
