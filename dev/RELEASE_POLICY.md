# Release Policy — FastMediaSorter v2

**Version**: 1.0
**Effective**: 2025-01

---

## 1. Purpose

Defines rules, roles, and gates controlling when and how new versions of
FastMediaSorter are released to production (Google Play Store).

---

## 2. Release Types

| Type | Trigger | Flavors | Versioning | Approver |
|------|---------|---------|------------|---------|
| **Hotfix** | Critical bug, crash spike | standard only | Patch bump (x.y.Z+1) | Owner |
| **Minor** | New features, improvements | all flavors | Minor bump (x.Y+1.0) | Owner |
| **Major** | Architecture, breaking changes | all flavors | Major bump (X+1.0.0) | Owner |
| **RC** | Pre-release testing | all flavors | RC tag (rc/x.y.z) | Owner |

---

## 3. Version Numbering

Format: `MAJOR.MINOR.PATCH` (e.g. `2.7.3`)

- **MAJOR**: Incompatible architecture changes or complete redesigns.
- **MINOR**: New features backward-compatible with existing user data.
- **PATCH**: Bug fixes, performance improvements, no new features.

`versionCode` = `MAJOR * 10000 + MINOR * 100 + PATCH` (auto-generated by `build-with-version.ps1`).

---

## 4. Release Gates

All of the following MUST pass before any release build is tagged:

### 4.1 Automated Gates (CI — blocking)
- ✅ `lintStandardDebug` passes with zero NEW errors vs baseline
- ✅ `testStandardDebugUnitTest` — 100% pass rate
- ✅ `assembleStandardRelease` — build succeeds, APK signed
- ✅ All flavor builds succeed (standard/lite/photos/legacy)

### 4.2 Manual Gates (RELEASE_CHECKLIST — required sign-off)
- ✅ Maestro smoke suite on emulator API 34+
- ✅ Manual smoke on physical device (if hardware-specific features changed)
- ✅ Play Store metadata reviewed (description, screenshots, what's new)
- ✅ Privacy policy up to date (if data handling changed)
- ✅ Security: no hardcoded secrets (`temp/SECRET_AUDIT_REPORT.md` reviewed)

### 4.3 Quality Thresholds (from `QUALITY_BASELINE.md`)
- Crash-free rate: ≥ 99.0% (previous release baseline)
- Unit test pass rate: 100%
- APK size: no regression > 5%

---

## 5. Release Workflow

```
1. Create RC branch: scripts/utils/create-release-candidate.ps1
2. Run full RELEASE_CHECKLIST.md — sign off all items
3. Generate changelog: scripts/utils/generate-changelog.ps1
4. Tag release: git tag -a v<VERSION> -m "Release v<VERSION>"
5. Build release APKs/AAB: gradlew assembleStandardRelease
6. Upload to Play Store (internal → alpha → production)
7. Update DOWNLOADS/builds_versions.lst
8. Generate quality report: scripts/utils/generate-quality-report.ps1
```

---

## 6. Hotfix Process

For production crashes or high-severity bugs:

1. Branch from latest release tag: `git checkout -b hotfix/v<VERSION> v<OLD_TAG>`
2. Apply minimal fix
3. Bump patch version only
4. Run abbreviated checklist (gates 4.1 + critical manual smoke)
5. Fast-track to production (skip alpha if P0)

---

## 7. Rollback Policy

If post-release crash-free rate drops below **98.5%** within 24 hours:
1. Halt rollout in Play Store
2. Prepare hotfix or revert
3. Target recovery within 4 hours
