# Постановка задачи: Резервная доставка перевода (ML Kit) для store/debug сборок

## 1. Цель
Реализовать резервный канал скачивания нативных библиотек перевода Google ML Kit (`libtranslate_jni.so` и `liblanguage_id_l2c_jni.so`) с нашего GitHub-зеркала для отладочных (debug) и sideload-установок магазинных флейворов (`standard`, `legacy`) в случае, если сервисы Google Play недоступны или возвращают ошибку (например, `APP_NOT_OWNED` с кодом `-15`). Это разблокирует тестирование всего сценария перевода на дебаг-версиях без публикации в Play Store.

## 2. Требования
1. **Основной канал**: Попытка скачивания модуля через Google Play DFM (`SplitInstallManager`) остаётся основным (первичным) решением для магазинных сборок.
2. **Резервный канал (HTTP/GitHub)**: Если DFM возвращает ошибку или недоступен (например, на дебаг-сборке), приложение переключается на прямую загрузку нативных библиотек с тега `delivery-so-v1` на GitHub.
3. **Целостность и проверка**: Скачанные с GitHub `.so`-файлы должны проверяться по размеру и SHA-256 (SHA-256 жестко прописывается в кодовой базе аналогично OCR-движкам).
4. **Монтирование библиотек**: Загруженные библиотеки сохраняются в защищённую область `filesDir/delivery/TRANSLATION/` и подключаются динамически в рантайме с помощью `DeliveredNativeLibraryLoader`.
5. **Хостинг**: Все 8 файлов библиотек (для архитектур `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`) будут переименованы по схеме `<abi>-<libname>-v1.so` и загружены в наш GitHub-релиз `delivery-so-v1`.

## 3. Ограничения
- Сохранить разделение флейворов: нативные библиотеки не должны упаковываться в базовые APK для флейворов standard/legacy (исключаются через `excludes` в `jniLibs` аналогично другим `.so`).
- Сохранить работоспособность DFM для пользователей из Google Play Store.
