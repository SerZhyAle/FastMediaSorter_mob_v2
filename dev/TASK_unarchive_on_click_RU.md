# Постановка задачи: разархивация ZIP по клику в Browse

Дата: 2026-04-01

## 1) Краткая цель
Добавить в экран Browse возможность распаковки ZIP-архивов по обычному клику на файл типа BINARY_ARCHIVE. Вместо бинарного меню показываем подтверждение, затем выполняем распаковку с прогрессом и после успеха предлагаем открыть созданную папку.

## 2) Область изменения (модули и классы)
- UI: BrowseActivity, MediaFileAdapter/PagingMediaFileAdapter, новый UnarchiveConfirmDialog, существующий FileOperationProgressDialog.
- ViewModel: BrowseViewModel (новые события и состояние распаковки).
- Domain: новый ExtractArchiveUseCase (ZipInputStream), использование существующего CreateDirectoryUseCase.
- Strings: values/strings.xml + values-ru + values-uk.

## 3) Вход и точка интеграции
- Точка входа: BrowseActivity -> showBinaryFileMenu(file) для MediaType.BINARY_ARCHIVE.
- Для всех остальных BINARY_* остается существующее бинарное меню.

## 4) Ограничения и допущения
- Поддерживается только ZIP (ZipInputStream). RAR/7z/TAR не поддерживаются.
- Только локальные/SD ресурсы. Для SMB/FTP/SFTP/Cloud показывается уведомление "Недоступно для сетевых источников".
- Логирование: только Timber.
- Без доп. UseCase для определения папки; логика выбора папки внутри ExtractArchiveUseCase.
- Без изменений в MediaType/MediaTypeUtils.

## 5) Функциональные требования
- Клик по ZIP-файлу (BINARY_ARCHIVE) вызывает диалог подтверждения распаковки.
- После подтверждения запускается распаковка в фоновом IO-потоке.
- Показ прогресса по текущему файлу/записи.
- После успеха: Snackbar с кнопкой "Открыть" -> переход внутрь новой папки.
- При ошибке: Toast с читабельной ошибкой.
- Отмена: мягкое завершение, без ошибки пользователю.

## 6) Технические требования ExtractArchiveUseCase
- Потоковое чтение/запись без буферизации всего файла в память.
- Сохранение структуры папок (ZipEntry.name).
- Защита от Zip Bomb:
  - лимит итогового размера 2 GB
  - максимум записей 100 000
  - глубина 10
- Защита от path traversal: нормализация пути, запись только внутри targetDir.
- Кодировка: UTF-8 с fallback на CP866.
- Возможность отмены через callback onCancel().

## 7) UI/UX
- Диалог подтверждения: заголовок + сообщение "файл -> папка" + кнопки Распаковать/Отмена.
- Прогресс: использовать существующий FileOperationProgressDialog (адаптировать метод обновления при необходимости).
- Snackbar после успеха с действием "Открыть".

## 8) Локализация
Добавить 7 строк (EN/RU/UK): заголовок/сообщение диалога, прогресс, успех, ошибки, action_open.

## 9) Тесты и проверка
- Юнит-тесты ExtractArchiveUseCase: success, zip bomb, path traversal, cancel, CP866.
- Ручная проверка: локальный ZIP с кириллицей, кнопка "Открыть".

## 10) Вопросы/неопределенности
- Нужен ли WorkManager для больших архивов в v1 или оставляем простую корутину ViewModel?
- Нужна ли поддержка распаковки на съемные SD-карты через SAF (DocumentFile), или допускаем только прямые File API?
- Отображать ли в прогрессе процент или только имя текущего файла?
- Нужна ли логика "перезаписать при конфликте" или всегда создавать папку с суффиксом _1.._99?
