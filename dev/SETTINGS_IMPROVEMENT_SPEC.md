# Спецификация: Улучшение UX и производительности экрана настроек (DEV)

## 1. Цель

Снизить время поиска нужной настройки, убрать UX-конфликты во вкладке `Media`, исключить блокировки главного потока и упростить поддержку кода настроек.

## 2. Область изменений (Scope)

### Включено

1. Глобальный поиск по настройкам.
2. Упрощение структуры `Media` (без nested tabs).
3. Визуальная группировка и улучшение читаемости.
4. Вынос I/O из Main Thread.
5. Унификация биндинга контролов (`Switch`, `Spinner`, поля ввода) через базовый слой.
6. Улучшение UX импорта/экспорта и частичного сброса настроек.

### Не включено

1. Изменение бизнес-логики настроек.
2. Миграция на Compose.
3. Полный редизайн приложения.

## 3. Проблемы текущей реализации

1. Настройки распределены по нескольким уровням вкладок; навигация медленная.
2. Во вкладке `Media` nested tabs создают перегрузку и конфликт свайпов.
3. Есть риск блокировок UI из-за I/O операций и тяжелой инициализации.
4. В коде фрагментов дублируется шаблон биндинга и защиты от циклических обновлений.
5. Импорт/экспорт и секционный reset недостаточно явны для пользователя.

## 4. Целевое решение

### 4.1 Глобальный поиск настроек

**Требования:**

1. Добавить action поиска в `Toolbar` `SettingsActivity`.
2. По вводу показывать плоский список результатов (название, секция, краткое описание).
3. По нажатию на результат:
   - открыть нужный экран/секцию;
   - проскроллить к контролу;
   - подсветить контрол на 1-2 секунды.

**Техническая модель:**

1. Ввести `SettingsSearchIndex` с объектом `SearchEntry`:
   - `key`, `title`, `keywords`, `sectionId`, `destination`, `viewId`.
2. Индекс формировать централизованно, без runtime-рефлексии.
3. Фильтрация: case-insensitive, match по `title + keywords`.

### 4.2 Упрощение вкладки Media

**Решение по умолчанию (обязательное):**

1. Удалить вложенный `ViewPager` из `MediaSettingsFragment`.
2. Перевести `Media` на единый вертикальный экран с секциями.
3. Использовать раскрываемые секции (Expandable Sections): `Images`, `Video`, `Audio`, `Documents`, `Other`.

**Ограничение:**

Не добавлять дополнительные экраны (master-detail) в рамках данной задачи.

### 4.3 Визуальная иерархия

1. Сгруппировать настройки по блокам с заголовками и подзаголовками.
2. Использовать текущую дизайн-систему проекта (без новых цветов/теней вне темы).
3. Убрать визуальный шум: выровнять отступы, унифицировать spacing и размеры заголовков.

### 4.4 Производительность и Main Thread Safety

1. Все операции чтения файлов/логов/диска выполнять в `Dispatchers.IO`.
2. Любые вычислительно тяжелые операции — `Dispatchers.Default`.
3. Не выполнять блокирующую загрузку данных в `onCreateView`.
4. Для длительных операций показывать индикатор загрузки и состояние ошибки.

### 4.5 Базовый слой для биндинга настроек

1. Ввести базовый компонент (`BaseSettingsFragment` или equivalent helper), который покрывает:
   - биндинг `Switch` ↔ state/flow;
   - биндинг `Spinner` ↔ state/flow;
   - защиту от циклических обновлений (`isUpdating` pattern).
2. Убрать дублирование в конкретных фрагментах настроек.

### 4.6 Reset Section + Import/Export UX

1. Для каждой логической секции добавить `Reset section`.
2. Reset влияет только на параметры текущей секции.
3. Импорт/экспорт вынести в явные пункты UI (кнопки/меню с понятными названиями).
4. Для импорт/экспорт/сброса добавить подтверждение и пользовательское сообщение о результате.

## 5. Нефункциональные требования

1. Изменения не должны ломать существующие `BuildConfig` feature flags.
2. Состояние настроек должно оставаться обратно совместимым с текущим хранилищем.
3. Все изменения должны быть безопасны для поворота экрана и повторного входа в `SettingsActivity`.

## 6. Критерии приемки (Acceptance Criteria)

### Поиск

1. Поиск открывается из `Toolbar` и выдает релевантные результаты.
2. Нажатие на результат приводит к нужному контролу и визуально его выделяет.

### Media UX

1. Во вкладке `Media` отсутствуют nested tabs.
2. Все медиа-настройки доступны на одном вертикальном экране с секциями.

### Производительность

1. Нет I/O в Main Thread на пути открытия/использования настроек.
2. Открытие `SettingsActivity` не вызывает заметных UI-freeze.

### Кодовая база

1. Дублирование биндинга контролов уменьшено за счет базового слоя.
2. Код фрагментов стал короче и однообразнее по паттерну обновления state.

### UX операций

1. Есть reset на уровне секции.
2. Импорт/экспорт заметны и понятны в интерфейсе.

## 7. Риски и меры

1. **Риск:** регрессия навигации после удаления nested tabs.  
   **Мера:** добавить явные якоря/идентификаторы секций и автотест навигации по search result.
2. **Риск:** циклические обновления UI/state.  
   **Мера:** единый guard-механизм в базовом слое.
3. **Риск:** деградация при большом числе поисковых записей.  
   **Мера:** prebuilt index + debounce ввода.

## 8. План внедрения (по фазам)

1. **Фаза 1 — Infrastructure:** базовый слой биндинга + перенос I/O с Main Thread.
2. **Фаза 2 — Media UX:** удаление nested tabs, переход на секции.
3. **Фаза 3 — Search:** индекс, UI поиска, навигация к контролу.
4. **Фаза 4 — Operations UX:** reset section, явный импорт/экспорт.
5. **Фаза 5 — Stabilization:** профилирование, регресс-проверки, правки UX.

## 9. Definition of Done

1. Все acceptance criteria выполнены.
2. Debug build проходит без новых критичных warning/error по затронутым модулям.
3. Обновлена документация по поведению поиска, reset section и import/export.
