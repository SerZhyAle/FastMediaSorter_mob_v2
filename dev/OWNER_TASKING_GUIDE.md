# Как ставить задачи агентам, чтобы они тратили меньше токенов

Для владельца. Основание - S3147 (`PLAN/S3147_agent-context-token-cost.md`, `research/01` и `research/02`).

## Откуда берётся расход

- Счёт - это размер контекста, умноженный на число ходов: каждый ход заново отправляет всю накопленную историю сессии.
- Поэтому дорого не одно большое чтение, а длинная сессия. Один безнадзорный `/spec-do` сделал 1188 ходов по ~550 тыс. токенов контекста - 654 млн `cache_read`.
- Ручек две: меньше ходов на задачу и меньше накопленного контекста.

## Постановка задачи

1. **Называйте тикет.** `/spec-all S3147`, а не «доделай ту штуку со статистикой». По id агент сразу берёт спеку, статус и карту контекста - без поиска.
2. **Называйте место.** Файл, экран, настройку, текст ошибки. «Кнопка "Удалить" в диалоге выбора папки, ландшафт» экономит десятки чтений по сравнению с «кнопка кривая».
3. **Называйте ожидаемый результат.** Что должно стать иначе и как это проверить. Без этого агент сначала выясняет, что вообще считается готовым.
4. **Ограничивайте область.** «Только этот файл», «без рефакторинга», «без новых тикетов». Иначе агент добросовестно проверяет соседние места.
5. **Мелочь - самым мелким тиром.** Опечатка, цвет, одна строка - `/quick`; быстрый баг - `/skill-fix`; полный конвейер - только для тикета.
6. **Прикладывайте то, что уже знаете.** Лог, скриншот, номер строки заменяют целое исследование.
7. **Короткие отчёты - `/caveman`.** Сжимает прозу ответа, проверки не трогает.

Что заставляет агента исследовать заново:

- формулировка без места и без результата;
- «посмотри, что там не так со всем приложением»;
- несколько несвязанных задач в одном сообщении;
- продолжение старой задачи в сессии, которая уже делала что-то другое.

## Сессии

- **Новая задача - новая сессия (`/clear`).** История прошлой задачи не помогает новой, но оплачивается на каждом ходе.
- **`/compact` на границе этапа** длинной задачи. Агент выполнить его сам не может - это только ваша команда.
- **Безнадзорно - раннер, а не `/spec-do`.** `.\a.ps1 r1` (и `r2`, `r3` параллельно) запускает каждый тикет в новом процессе, контекст обнуляется сам. `/spec-do` - одна бесконечная сессия, которая не сбрасывается, пока вы не сделаете `/compact`.
- **Повторный заход на тикет дешевле, если есть карта.** При каждом закрытии скрипт пишет `temp/<Sxxxx>/context-map.md`: что правилось, что читалось, какие команды падали. `/spec-all` и `/spec-dev --resume` читают её до исследования.

## Статистика

- Каждое закрытие через `post-change.ps1` с id тикета пишет строку в `temp/agent-cost/ticket-cost.jsonl` - для Claude, Codex и Gemini. Для runtime без известного транскрипта (ZCode) строка пишется с пометкой `transcript: unavailable`.
- Сводка: `pwsh -NoProfile -File scripts/metrics/ticket-cost.ps1 -Verb Summary -Since 2026-09-15`.
- Что смотреть в сводке:
  - **Read but never edited** - агент много читал, но прочитанное не правил: лишний контекст или слишком широкая постановка.
  - **Reads before the first edit** - долгое исследование до первой правки: в задаче не хватило места или результата.
  - **Longest failure streak of one command** - одна команда падала подряд: агент ходит по кругу, стоит остановить и подсказать.
  - **Input tokens per entry** - первый заход на тикет против повторного: так видно, помогает ли карта.
