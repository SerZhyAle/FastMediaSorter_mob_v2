# Спецификация #15: Улучшенный интерфейс редакции ресурсов

## Описание задачи
В приложении отсутствует или сломан интерфейс для полного редактирования параметров ресурсов. Необходимо восстановить эту возможность и реализовать "умную" редакцию, аналогичную процессу создания нового ресурса. Пользователь должен иметь возможность изменять все параметры ресурса (кроме типа и статистики) в удобном, сгруппированном интерфейсе.

## Требования

### Функциональные требования
- **Полное редактирование:** Пользователь может редактировать все параметры ресурса:
  - Имя ресурса
  - Путь / URL
  - Параметры аутентификации (логин, пароль)
  - Настройки сканирования (интервалы, исключения)
  - Типы контента (Аудио, Видео и т.д.)
  - Дополнительные настройки (кодировка, таймауты)
- **Исключения:** Нельзя редактировать:
  - Тип ресурса (SMB, FTP, Local) - так как это фундаментально меняет природу подключения
  - Статистические данные (количество файлов, дата последнего сканирования и т.д.)
- **Умная редакция:**
  - Валидация введенных данных (проверка доступности пути, корректность URL)
  - Возможность "Проверить соединение" без сохранения
  - Визуальные подсказки при ошибках
- **Группировка:** Параметры должны быть логически сгруппированы (как в настройках приложения)

### UI/UX Требования
- Единое унифицированное окно/экран для редакции
- Использование Collapsible/Expandable секций для групп параметров
- Современный дизайн (Material Design 3)
- Понятные метки и описания для полей

## Структура экрана редакции

Экран должен быть разделен на следующие группы (категории):

### 1. Основные настройки (General)
- **Имя ресурса:** Текстовое поле
- **Иконка/Цвет:** Если поддерживается кастомизация
- **Видимость:** Переключатель "Активен/Скрыт"

### 2. Подключение (Connection)
*Для сетевых ресурсов (SMB, FTP)*
- **Адрес сервера:** URL/IP (с валидацией)
- **Путь к папке:** Возможность ручного ввода или вызов диалога выбора (если доступно)
- **Порт:** Числовое поле (с дефолтным значением в placeholder)
- **Имя пользователя:** Текстовое поле
- **Пароль:** Поле с маскировкой и возможностью показа
- **Кнопка "Проверить соединение"** внутри этой секции

### 3. Контент и Сканирование (Content & Scan)
- **Типы файлов:** Чекбоксы (Аудио, Видео, Изображения, Документы)
- **Интервал сканирования:** Выпадающий список или числовой ввод
- ** Игнорируемые папки:** Список папок для исключения (с возможностью добавления/удаления)
- **Генерировать миниатюры:** Переключатель

### 4. Дополнительно (Advanced)
- **Кодировка имен файлов:** Выпадающий список (UTF-8, CP1251 и т.д.)
- **Таймауты:** Настройка времени ожидания
- **Только чтение:** Переключатель (если применимо)

## Пошаговая реализация

### Шаг 1: Анализ текущей модели данных
Определить все поля, доступные в классе `MediaSource` (или аналогичном), которые подлежат редактированию.

```kotlin
data class MediaSource(
    val id: String,
    val type: SourceType, // Read-only
    var name: String,
    var address: String,
    // ... auth ...
    var scanInterval: Long,
    // ...
)
```

### Шаг 2: Создание UI макета (Layout)
Использовать `RecyclerView` с различными типами view holders для заголовков групп и полей ввода, либо `ConstraintLayout` внутри `ScrollView` с кастомными view для секций.

Рекомендуемый подход: **PreferenceFragmentCompat** или **RecyclerView со сложными типами**, чтобы обеспечить единообразие с экраном настроек.

Пример структуры XML (`activity_edit_resource.xml`):
```xml
<androidx.coordinatorlayout.widget.CoordinatorLayout ...>
    <com.google.android.material.appbar.AppBarLayout ...>
        <com.google.android.material.appbar.MaterialToolbar
            android:title="@string/edit_resource" .../>
    </com.google.android.material.appbar.AppBarLayout>

    <androidx.core.widget.NestedScrollView ...>
        <LinearLayout android:orientation="vertical" ...>
            
            <!-- Группа Основное -->
            <include layout="@layout/group_general_settings" />
            
            <!-- Группа Подключение -->
            <include layout="@layout/group_connection_settings" />
            
            <!-- и т.д. -->

            <com.google.android.material.button.MaterialButton
                android:id="@+id/btnSave"
                android:text="@string/save" .../>
                
        </LinearLayout>
    </androidx.core.widget.NestedScrollView>
</androidx.coordinatorlayout.widget.CoordinatorLayout>
```

### Шаг 3: Реализация логики (Activity/Fragment)
Создать `EditResourceActivity`.

1. **Инициализация:** Принимать ID ресурса через Intent.
2. **Загрузка данных:** Загружать текущие параметры ресурса и заполнять поля.
3. **Адаптивность:** Скрывать/показывать поля в зависимости от типа ресурса (например, для локальной папки скрывать поля сервера/пароля).
4. **Валидация:** При нажатии "Сохранить" или потере фокуса проверять корректность (не пустой адрес, валидный порт).
5. **Проверка соединения:** Реализовать асинхронную проверку доступности ресурса с текущими введенными параметрами (не сохраняя их в БД).

### Шаг 4: Обработка сохранения
1. Собрать данные со всех полей.
2. Создать объект обновленного ресурса.
3. Вызвать UseCase/Repository для обновления в базе данных.
4. Если изменились параметры подключения, предложить (или выполнить автоматически) пересканирование ресурса.
5. Вернуть результат в предыдущую Activity.

### Шаг 5: Интеграция
Добавить вызов этого экрана из:
- Списка ресурсов (долгое нажатие -> Редактировать)
- Детального просмотра ресурса (кнопка в меню)

## Тестирование

### Сценарий 1: Изменение имени и интервала
1. Открыть существующий ресурс.
2. Изменить имя.
3. Изменить интервал сканирования.
4. Сохранить.
5. Проверить, что в списке ресурсов отображается новое имя.

### Сценарий 2: Смена пароля SMB
1. Открыть SMB ресурс.
2. Изменить пароль на неверный.
3. Нажать "Проверить соединение" -> Ожидается ошибка.
4. Ввести верный пароль.
5. Нажать "Проверить соединение" -> Ожидается успех.
6. Сохранить.

### Сценарий 3: Локальная папка
1. Открыть локальный ресурс.
2. Убедиться, что поля "Сервер", "Логин", "Пароль" скрыты.
3. Изменить путь к папке.
4. Сохранить.
