# Refuted approaches

This index admits an entry only when a source ticket supplies a measurement. It records
what someone might propose, what the measurement disproved, and what shipped instead.

| Proposed approach | Source and measurement | What shipped instead |
|---|---|---|
| Fix "Back from a Launcher-started target lands in Main or Browse" by starting the target from `LauncherHomeActivity`'s Activity context | S2215 research 02, refuting its own artefact 01 on S2026's device capture of 2026-08-27: the break is task affinity, not launch context. `FLAG_ACTIVITY_NEW_TASK` is documented to join *an existing task with the same affinity*, and every internal target shares the app default affinity with `MainActivity`, so the target lands in `Task{#3657 type=standard A=..debug}` and Back unwinds into what was already there. Starting from the Activity context instead puts the target in the **caller's** task - `Task{#3656 type=home A=..launcherhome}` - and Android refuses `enterPictureInPictureMode()` for a home-type task, which is exactly the defect S2026 shipped the separate affinity to fix. The move trades one ticket's bug for another's. | Leave the start in the shared use case and change only task selection: `FLAG_ACTIVITY_MULTIPLE_TASK` alongside `FLAG_ACTIVITY_NEW_TASK` when the target's component is in our own package, and `FLAG_ACTIVITY_NEW_TASK` alone for a foreign package, whose task is already separate by affinity. |
| Extend the lexical detekt preflight with more size rules | S1595: the three current rules fully cover only 13.9% of attributable failures; nine hand-listed rules reach 48.1%, and flagged and unflagged classes overlap across a 240-line band, so size rules have no lexical threshold. | Run the real analyser over changed files. |
| Turn on detekt `--auto-correct` | S1595: the only switch is the shared `formatting` flag, which would arm about 5,591 findings, 46% of the baseline; line length is not mechanically repaired. | Keep the real analyser scoped and fix findings deliberately. |
| Put a closed `ValidateSet` on document-registry query values | S1597: PowerShell rejects the value before the script body runs, returning the same empty answer more expensively and duplicating the registry vocabulary. | Resolve near-misses and print the live vocabulary. |
| Add a hook that fixes and retries a failed command | S1594: `PostToolUse` cannot rewrite a result and no hook can retry; a failed command is cheaper to prevent with a PATH shim or `PreToolUse` rewrite. | Make names available through a shim or prevent the call before execution. |
| Parallelise closure gates instead of accumulating their failures | S1598: parallelism improves fast-path time but does not solve recovery and breaks deterministic output order. | Run gates through the accumulating facade and report every failure. |
| Price context from `UserPromptSubmit` | `dev/AGENT_PROCESS_AUDIT_2026-07-31.md` section 5, carried by S1338: the cost accrues inside autonomous blocks where no prompt is submitted, so the event is blind to exactly the case that pays. Routing on the same event is the inverse and remains correct - record the boundary, or this refutation gets reused against the nudge hook it does not apply to. | Keep prompt-time routing separate from context measurement. |
| Treat the S1599 zero-hit pattern count as a miss count | S1599: the counter incremented on every call, not only on misses, so the claimed miss total was not evidence. | Count only the narrowed zero-hit condition and stay silent when the widened search is also empty. |
| Detect an open research item by matching the whole status line | S1607: a line-anchored, whole-line `Open` match found 67 of 1506 closed specs; matching `Open` as a word, unanchored, found 134 carrying 372 items. Half the debt is written as `Open` plus an explanatory tail, or mid-line after the item title. | Match `Open` as a word, anywhere in the line, and locate the section by heading text rather than by the number 6. |
| Dot-source `_lib.ps1` into `preview.ps1` to share its helpers | S1621: `_lib.ps1` sets `Set-StrictMode -Version Latest`, and under it `preview.ps1`'s existing `$rec.statusNote` read throws on every catalog record without a note - reproduced live. `preview.ps1` runs once per `/spec-next` candidate, so the throw stops ticket selection, not one field. | Move the shared parse into a leaf file that sets no preferences and holds no state, and dot-source that from both. |
| Count an open research item by a question-mark heuristic when the item has no status line | S1621: the heuristic disagreed with the closing gate on 160 of 1601 spec files, always by counting more, because it answers a different question - "does this item contain a question mark". Keeping it beside the real count would have legalised the divergence the ticket exists to remove. | Count only items whose status line says `Open`, which is the closing gate's own definition. |
| Identify a changelog row by its description including the facade's `[set of N: ..]` tail | S1622: since the tail appeared on 2026-08-08 the dedup guard caught every exact repeat in 25,928 rows, and the only two rows that escaped it differed from their twin by the tail alone - fixing an advisory regenerates a file, and the file joins the set. | Normalise the tail out of both sides of the comparison, and close the signature on the `[branch:` marker so a description still cannot match a prefix of a longer one. |
| Add `ComplexMethod` to the top detekt failure list | S1595: it caused zero failures because `CyclomaticComplexMethod` supersedes it; the capture named the wrong rule. | Follow measured rule names and use the real analyser rather than guessing a list. |
| Probe a higher stream-quality rung seamlessly by fetching one of its segments and measuring it | S1511 section 0, measured by the StreamsPlayer source: a second fetcher steals bandwidth from the same line it is measuring, so it can cause the very stall it is trying to detect. | Probe by really switching the ceiling up one rung and judging it by a survived observation window. |
| Pick a probe cadence without measuring what a probe costs | S1511 section 0 and section 6 Q2: a 60 s base produced 108.9 s of black screen per session (16.6%) against 36.0 s (8.6%) at a 5 min base with per-rung memory, and our own switch measured 3.0-3.5 s with no rendered frame on a Galaxy S21+ - the bottom of the source's 3-18 s, not the near-free switch the ticket assumed. | Adopt the measured arithmetic as it stands: 5 min base, doubling per failure of that rung, capped at 1 h. |
| Blame the Wear audio-player CPU cost on recomposition from the 500 ms position-update loop | S1709 research 01 / S1683 phase 07, measured on the owner's watch (Galaxy Watch 7): stopping the position-update cycle on the dimmed screen gave 679 ticks per 10 s against 672 with it running - no difference, so the recomposition it drives is not the cost. The dominant term is the brand wave/particle animation that runs exactly while playing, not the position text. | Do not start the investigation from the recomposition hypothesis; separate the animation from "everything else" with the 4-point release-build measurement in S1709 section 4 before changing any code. |

| Measure overlay pixels in a unit test because Robolectric "draws for real" | S1716 §6.1, caught by phase 01's own guard and then priced by inspecting the Gradle cache on 2026-08-17: in the default legacy graphics mode the canvas records draw calls without rasterising, so a text-only scene came back byte-identical to a blank bitmap - the silent zero the ticket exists to distinguish from perfect concealment. `@GraphicsMode(NATIVE)` fails at class init not for a missing dependency but for a missing binary: `nativeruntime-dist-compat:1.0.2`, the version `robolectric:4.11.1` pulls, ships only linux-x86_64 and two mac libraries and has no `native/windows/` directory at all. The Windows dll first appears in `nativeruntime-dist-compat:1.0.18`, which arrives with `robolectric:4.16.1`. | Split the axes by what they need: three of the four (found, placement, spill) are rectangle math and shipped without a raster; the pixel axis and the Robolectric upgrade it really costs went to S1782 to be priced on their own. **Priced and shipped 2026-08-25/26 (S1782):** the upgrade to `robolectric:4.16.1` cost nothing - the full `testStandardDebugUnitTest` came back BUILD SUCCESSFUL with 0 failures across 560 test classes, all 87 Robolectric-bearing classes reporting by name - and `@GraphicsMode(NATIVE)` does rasterise on this Windows host, so the pixel axis exists. The refutation above still stands for anyone who forgets the annotation: in legacy mode the canvas still records draw calls without rasterising. |
| Re-inflate one orientation-dependent view group inside an Activity that absorbs the rotation | S1549 phase 06, read off `BaseActivity` itself: it assigns its ViewBinding once (`_binding = getViewBinding()` at `:152`, private, nulled only in `onDestroy`) and exposes no rebind hook, so every binding field would keep pointing at the discarded views. Any helper constructed with that binding - here `CalculatorInputManager` - is silently driving a dead hierarchy after the swap. | Make the screen's state movable, then let the system recreate the Activity and inflate the right variant itself; the state crosses through `onSaveInstanceState`. |
| Give a stream channel a stable identity by rewriting `stream_sources.id` into a value derived from its normalized address | S1832 artefacts 01 and 02, measured on the live 17 628-row bank and read off the tree on 2026-08-20: the rewrite is neither sufficient nor cheap. Not sufficient, because the pin and its position live in the row itself and die with it under any key, so a separate store is needed regardless. Not cheap, because no migration in 51 versions rewrites a primary key with fan-out into `stream_play_outcome` and `launcher_cells`; folding `http` and `https` turns 58 groups over 116 rows into primary-key conflicts that the migration itself would have to merge; and editing a hand-added channel's address (`updateUserFields`, S0660) breaks `id = f(url)` permanently. The codebase had already answered twice - favorites (S0783) key by address, quality memory (S1511) keys by normalized address, and those two are exactly the ones that survive a prune. | File user data under the derived identity and leave the row id an opaque handle. A non-unique identity key also keeps the 58 duplicate rows in the catalog instead of collapsing them. |
| Widen the scoped detekt preflight because the gradle gate catches findings it misses | S1938, measured 2026-08-22 by two independent routes: the same 38 files that the gradle gate had just reported on were fed to `detekt-scoped.ps1`, which returned the same 100 findings with the same rule distribution in 9.6 s - no coverage difference exists, and neither path uses type resolution, so the usual explanation for one does not apply here either. Over the surviving transcript window (2026-08-15 onward, 1450 `post-change` verdicts, dedup by uuid) `[detekt-gate] FAIL` occurred 4 times and never once after a passing preflight, while the S1937 telemetry journal records 4 preflight failures against 0 gate failures. The 43 co-occurrences the ticket was written from cannot be re-derived - that window was rotated away - but the mechanism they were attributed to is disproven by direct reproduction. | Nothing. Both steps stay as they are; the only remaining route to a late failure is `detekt-scoped.ps1` exiting 2 and degrading to its lexical scan, which is deliberate and names itself in the output. |
| Fix a Wear `ScalingLazyColumn` item hidden under a pinned overlay by only changing `rememberScalingLazyListState(initialCenterItemIndex = ..)` | S1945, measured 2026-08-26 on `Wear_OS_XL_Round`: changing only the state's `initialCenterItemIndex` from the library default (1) to 0 produced a byte-identical layout (`uidump` bounds unchanged before/after). `ScalingLazyColumn`'s own `autoCentering` parameter defaults to `AutoCenteringParams(itemIndex = 1)` and sizes the centering spacer for item 1 regardless of the list state's own target, so it keeps fighting `contentPadding.top` until it is matched or disabled. | Set `autoCentering = null` on the `ScalingLazyColumn` call - the library's own documented path for a developer-controlled position (`ScalingLazyColumn.kt:237-239`) - alongside the state's `initialCenterItemIndex`. |
| Move `ACCESS_FINE_LOCATION` out of the store flavors the way S2012 moved all-files access | S2013, read off the tree on 2026-08-26: the S2012 move works because `MANAGE_EXTERNAL_STORAGE` has exactly one consumer and it is `noLegal`-only. Location has three, and the smallest of them - the S0766 camera geotag - ships on all six flavors, so every store flavor still declares the permission after any split. The other two (launcher compass/speed/altitude/map gadgets, Network Monitor GNSS and Wi-Fi) are already confined to `standard`/`noLegal` by their capability seams, and neither `src/launcherEnabled/AndroidManifest.xml` nor `src/networkMonitor/AndroidManifest.xml` declares location today. The split would cost a new source set and remove nothing Play can see. | Correct the disclosure instead: the permission was accurate, the claim about it was not. `perm_rationale_location` said location was used "only" for the geotag on builds that also drive four gadgets and two monitor sections, and Play judges a location declaration against what the app tells the user. The wording is now picked per build through `LauncherModeContract`/`NetworkMonitorContract`. A flavor split becomes worth revisiting only if the geotag itself is dropped. |

| Key the Wear tile target assignment by tile instance so two "Resource" tiles can point at different resources | S2052, measured 2026-08-26 on the owner's Galaxy Watch 7 (SM-L310, Wear OS on Android 16) and read off `androidx.wear.tiles:1.6.2`: the API supports it fully - `TileRequest.getTileId()` returns a real per-instance int (17, 18, 19 observed), add/remove events carry it, and it survived a package reinstall that changed the pid (19 before, 19 after) - but the user cannot reach it. The system tile picker hides a provider already present in the carousel: the app offered 2 of its 3 tiles, and after removing the resource tile from the carousel the same picker offered 3 of 3. The developer broadcast `add-tile` does not work around this either, it replaces (`onTileRemoveEvent 17` then `onTileAddEvent 18`). Independently, `TileUpdateRequester.requestUpdate(Class, int)` is documented to ignore its id on API 36 and lower, which is this repo's own `targetSdk`. | Nothing. `WearTileAssignmentRepository` keeps one key per `WearTileKind`, and S1955 ADR-3 stops being provisional. Revisit only when both preconditions change together: a carousel that admits a second instance AND `targetSdk` above 36. |

| Shrink the format detekt baseline by autocorrecting the module package by package | S2112, measured 2026-08-27 on `core/util` (36 files, 5337 lines, 120 format entries) and then reverted. Three separate mechanisms defeat it. **Autocorrect is not idempotent:** three `-Fix` passes were needed (79 -> 42 -> 10 findings seen), and pass 1 itself manufactured 18 `NoSemicolons` by splitting calls across lines. **Wrapping relocates line-length debt rather than removing it:** `ArgumentListWrapping` lifts a long string literal out of a `Timber.x(..)` call onto its own line, where it is still over 120 characters but under a new signature, so the frozen `MaxLineLength` entry stops matching and the same debt returns as a *new* finding - 8 of the 9 irreducible survivors were exactly this, 125-279 characters each, and no rule in this stack reflows a line or may split a literal. Since `MaxLineLength` + `MaximumLineLength` are 2516 of 7693 format entries (33%), that third is unreachable by autocorrect at all. **A format-only pass is not format-only:** the 9th survivor was `ComplexCondition`, a *signal*-set rule whose baseline signature the reformat invalidated. Cost for nothing: +146 lines (+2.7%, worst file +14.1%), `.\a.ps1 fk` `BUILD SUCCESSFUL` throughout, and **zero** baseline entries retired. The `LargeClass` collision the ticket was written to fear did not fire on this package, but 87 un-baselined files sit at 450-699 lines and +14% on a 560-line file crosses 600. | The prune tool, not the campaign. `scripts/quality/prune-detekt-baseline.ps1` removes a dead baseline entry for a named file set without the whole-module `detektBaseline` re-freeze that absorbs live debt (S1356's incident), and it refuses - exit 1, nothing written - when the files carry a finding the baseline does not hold. Whether to shrink the baseline in some *other* shape (raising the `MaxLineLength` threshold, excluding literal-only lines) is unmeasured and open. Full numbers: `PLAN/S2112_shrink_detekt_format_baseline/research/03__autocorrect-price-report.md`. |

| Give a test folder a dispatcher by copying `doc-drift.tests/Run-Tests.ps1`, which dot-sources its siblings | S2126, read off the three folders on 2026-08-27: the 19-line dispatcher works only because `doc-drift`'s files never call `exit` and share one `$script:TestStats`. Both other folders violate that precondition and each breaks it differently. In `scripts/quality.tests/` every file ends in `exit 0` / `exit 1`, and a dot-sourced `exit` terminates the DISPATCHER - the first file's code becomes the whole folder's verdict, so a green first file reports success for four suites that never ran. That is a refusal that reports success, which is strictly worse than the missing runner it replaces. In `scripts/streams.tests/` the files are Pester specs; dot-sourcing defines `Describe` blocks that nothing executes, so the folder reports green having run zero tests. | One entry-point NAME across folders, one harness PER folder. `quality.tests/Run-Tests.ps1` spawns a child process per file and folds the exit codes (fail > cannot-verify > pass), which survives `exit` and keeps each file runnable by hand; `streams.tests/Run-Tests.ps1` calls `Invoke-Pester` on the folder and exits 2 when the module is absent. This mirrors what `run-script-suites.ps1` already does one level up, so no new concept is introduced. |
| Put `Set-StrictMode -Version Latest` in a runner that invokes Pester 3 | S2126, measured 2026-08-27 on `scripts/streams.tests/` by isolating each preference: the setting is inherited by the specs the runner executes, and Pester 3.4.0 predates it. Without it the folder reports 15 tests and 15 passes; with `-Version Latest` only 10 are discovered and 2 of those report failures that do not exist. `$ErrorActionPreference = 'Stop'` was measured separately in the same folder and is harmless (15/15). A runner that changes what its own suite observes is the unreachable-suite defect wearing a different hat - the number it prints is not about the code under test. | Leave strict mode unset in a Pester 3 entry point and say why in its header. The repo convention applies to scripts that own their logic, not to a wrapper whose preferences leak into someone else's framework. |

| Give a new per-screen session store the same ViewModel-to-store shortcut `StreamsSessionStore` uses | S2199, refuted by the closure gate on 2026-08-28 after the code was already written and compiling. The strategic spec's ADR-6 chose the shortcut on the strength of the one precedent in the tree - `StreamsSessionStore` injected straight into `StreamsViewModel` since S0659 - and neither the research pass nor the tactical plan noticed that two dimensions of `scripts/quality/assert-source-gates.ps1` (S2103) refuse it in a changed file: `ui-imports-data` on the data import, and then `viewmodel-imports-repository` on the interface that was the first attempt to satisfy it. Both baselines only ever fall, so the older shortcuts are frozen history rather than a pattern a new file may join. Two facts made this expensive rather than cheap: the gates run at closure, so the refusal arrived after the implementation, the test and the ARCHITECTURE.md section that documented the shortcut as deliberate; and the second gate only appeared after the first was fixed, so the repository-interface step was wasted work. | The full chain, however short the operation looks: `MainListSessionStore` (data) behind `MainListSessionRepository` (domain), read and written by `ReadMainListSessionUseCase` / `SaveMainListSessionUseCase`, held by `MainListSessionManager` in `ui/main/helpers/`. Cheaper next time: grep the gate dimensions in `scripts/quality/assert-source-gates.ps1` for the layer boundary a plan is about to cross, at planning time - a precedent in the tree proves only that a rule was younger than the code. |
