# FastMediaSorter v2 Agent Protocol

## 1. Source of Truth
- Universal conventions (canon): SZA Unified Rules, shipped as the `sza` Claude Code plugin (`/plugin marketplace add SerZhyAle/sza-unified-rules`; `/plugin install sza@sza-unified-rules`). Consumption model: REFERENCE, not mirrored. This repo is overlay B; per-repo overlay facts and the channel matrix live in the canon at `rules/contrib/fastmediasorter_mob_v2.md`, adoption stamp `.sza-canon.json`. Canon wins for universal principles; fix them in a canon session.
- Rules: `CLAUDE.md`, `.github/copilot-instructions.md`, `dev/PROJECT_OPERATIONS_INDEX.md`, `dev/AGENT_WORKFLOW.md`.
- Stricter rules override. Import order: `CLAUDE.md` -> `.github/copilot-instructions.md` -> prompt/agent file.
- Entry file per runtime, all describing the same repository: Codex CLI and ZCode load `AGENTS.md` (this file), Gemini CLI loads `GEMINI.md`, GitHub Copilot loads `.github/copilot-instructions.md`, Claude Code loads `CLAUDE.md`. `CLAUDE.md` is the strictest and the longest - read it in full before any non-trivial work; the other three are deltas on it.
- Claude Code loads four more rule files lazily - `.claude/rules/*.md`, each with `paths:` frontmatter, each the full mechanism and incident text behind a numbered `CLAUDE.md` statement (S2521): `spec-catalog.md`, `android-source.md`, `agent-chat.md`, `command-authoring.md`. A runtime without that mechanism reads all four at start, right after `CLAUDE.md`. The statements and the rule numbers never left `CLAUDE.md`; only the prose behind them moved.
- **If you are not Claude Code, read §9 before acting.** Most of this repository's enforcement lives in Claude Code hooks and in a command library that only Claude Code auto-loads. Outside it, those rules are ordinary prose that nothing will refuse for you, and the pipelines are files you must open yourself.

## 3. Core Rules
- Stack: Android, Kotlin 2.2.10, Java 17, Hilt, Room, Media3, Timber. The authoritative pins are the generated block in `CLAUDE.md` section 8 - do not restate a version here that the generator owns.
- Directories: `app_v2/`, `wear/`, `dev/`, `docs/`, `scripts/`, `temp/` (scratch/logs). Read-only zones, no exceptions (CLAUDE.md Rule 4): `V1/`, `v2_6/`, `spec_v2/`, `dev/archive/`.
- Temp layout (CLAUDE.md Rule 1): ticket-bound scratch/artifacts -> `temp/Sxxxx/`; no active ticket -> `temp/scratch/`. Fixed infrastructure stays at `temp/` root, never nested - and the names are declared in `scripts/utils/temp-root-inventory.ps1`, never in a rules file, this one included (S3030); a new fixed name needs a row there. Ask the root: `pwsh -NoProfile -File scripts/quality/assert-temp-root-inventory.ps1`. Mechanism: `docs/DEV_OPS.md`.
- File size ceiling 2000 LOC (CLAUDE.md Rule 2): extract logic to `helpers/*Manager.kt` rather than growing a file past it.
- No Activity logic (CLAUDE.md Rule 3): delegate to `helpers/*Manager.kt`.
- No self-cost estimates (CLAUDE.md section 1): never write how long a change will take, how much effort it is, or how many lines it will add - in a spec, a phase file, a plan or a reply. A size read off a real file is a measurement, not an estimate, and stays.
- Backup before a big edit (CLAUDE.md Rule 5): a file over 500 LOC gets a timestamped copy under `temp/Sxxxx/` (or `temp/scratch/`) first.
- Naming (CLAUDE.md Rule 6): `VerbNounUseCase`, `NounRepository`, `NounViewModel`, `NounVerbManager`.
- Lint (CLAUDE.md Rule 7): fix the warnings in the files you touched, not only the ones you introduced.
- Read before editing (CLAUDE.md Rule 8): the comments and KDoc already in the area are requirements - read them first and never override one silently.
- Comment discipline (CLAUDE.md Rule 9): EN-only, explain WHY not WHAT, no trivial comments, remove stale ones.
- Spec catalog is script-owned (CLAUDE.md Rule 12): never hand-edit `PLAN/spec-catalog.jsonl`, never rename an `Sxxxx_` prefix; mutate through `scripts/spec_catalog/*.ps1`.
- Script ownership (CLAUDE.md Rule 13): a project script that is buggy or insufficient gets fixed, not worked around.
- Flavor isolation (CLAUDE.md Rule 14): no `BuildConfig.IS_*` flavor guards in `src/main/` - use an interface plus flavor source sets.
- Input coverage (CLAUDE.md Rule 16): every interactive surface supports keyboard, D-pad/TV and mouse - set `focusable`, `clickable`, `nextFocus*`.
- Lazy optimization (CLAUDE.md Rule 18): Hilt `dagger.Lazy<T>`, `<ViewStub>` for optional layouts, release player/media resources the moment playback pauses.
- Deprecated PackageManager flags (CLAUDE.md Rule 21): no raw-int `getPackageInfo`/`getApplicationInfo`/`queryIntentActivities`/`resolveActivity` in `src/main` - use the `*Compat` helpers in `util/PackageManagerCompat.kt`. Gate: the `deprecated-pm-flags` dimension of `scripts/quality/assert-source-gates.ps1`, run on every closure by `post-change.ps1`.
- What to work on next comes from `PLAN/RELEASE_QUEUE.md` (CLAUDE.md 4): release package ascending, then the owner's line order inside it; then `Implemented` rows in `PLAN/RELEASE_READY.md`, then `--` parked lines, then anything unlisted. Catalog `priority` is a tiebreak for unlisted tickets only. Recommend from that file, quote the package and line, state any deviation. `spec-next-preflight.ps1` and `release-plan.ps1` rank from it. Package = section heading, not a column (S2852).
- Bash `find` safety (CLAUDE.md Rule 24): a `find` with a disk-wide start path or no `-maxdepth` is refused before bash spawns by the canon plugin's `guard-bash.ps1`. Give a concrete start path **and** `-maxdepth N`, or use the `Glob`/`Grep` tools or `dev/CATALOG/scripts/query.ps1`. Contract: `docs/AGENT_HOOKS.md`.
- No `.ps1` as a Bash command head (CLAUDE.md Rule 25): never run a PowerShell script directly in Bash (`./a.ps1 fk`, `scripts/foo.ps1`) - Bash cannot execute a `.ps1` and the failure returns **exit 0**, so a broken build reads as passing. Always `pwsh -NoProfile -File ./a.ps1 <cmd>` from the repo root.
- No fire-and-forget verdict (CLAUDE.md Rule 26): never background a gate, a closure facade or a catalog mutator (`post-change.ps1`, `assert-*.ps1`, the `spec_catalog`/`document_registry`/`all_features` CLIs, `add_to_dev_log.ps1`, `catalog_sync.ps1`, `a.ps1 fk/fkn/fc/fr/fg/dq/ch/ss/bf`). A verdict nobody reads in the same turn is not a verdict. A real long job on the same line still backgrounds normally.
- No slash-command name as an argument value in a Bash-tool `pwsh` call (CLAUDE.md Rule 27): `-Reason "/spec-dev .."` reaches the script as `C:/Program Files/Git/spec-dev ..` because MSYS reads the leading slash as a POSIX path, and the corruption is silent - exit 0, mangled text in the lock, queue and lease diagnostics (S1458). Use `"//spec-dev .."`, prefix `MSYS2_ARG_CONV_EXCL='*'`, or call from PowerShell.
- No command in the Bash tool that cannot exist there (CLAUDE.md Rule 28): a PowerShell cmdlet in command-head position, an interpreter that is not installed (`node`, `npm`, `npx`), and the `& { .. }` batching idiom are all refused - each is an `exit 127` returning nothing. Run the pipeline in PowerShell, or `pwsh -NoProfile -Command "<pipeline>"`. `python3` is deliberately not refused. Only a head is refused.
- Hooks and the inventory (CLAUDE.md Rule 29): a hook may refuse a tool call, rewrite its input, observe its result or warn you, and `docs/AGENT_HOOKS.md` is the complete list - of MCP servers too, with the admission rule for a new one - with each hook's event, verdict shape, escape hatch and whether it is global or project. Two are named in no rule above: `guard-catalog-before-kt-search` refuses an unnarrowed `.kt` search until the class catalogue was queried this session, and `guard-uncapped-read` rewrites a `Read` carrying no explicit window. Registering or removing a hook requires editing both the inventory and `docs/NON_CLAUDE_RUNTIME_RULES.md` in the same change, the second because for a runtime with no hooks that sheet is the whole enforcement (S2872) - one gate, `scripts/quality/assert-hook-inventory.ps1`, refuses either omission.
- Release freeze (CLAUDE.md Rule 36): while `release-freeze.ps1 -Verb Status` reports a freeze held by another session, do not CLAIM a new ticket - finish the one you are on; `PLAN/`, `temp/` and reading are never refused. `docs/DEV_OPS.md` "Release freeze".
- Device fleet (CLAUDE.md Rule 35): `docs/DEVICE_FLEET.md` is the roster and the **only** home of a per-device permission - read it and match the serial before the first `adb` call of a task, because authorization is per device, never per "a device is attached". Four danger classes, and the file says which device is in each: free hand (the dedicated test phone, every emulator); irreplaceable content, so no wipe, no uninstall, no system role and no settings change (the owner's personal phone, the VR headset); read-only (a guest phone); and the workstation, which is never shut down or rebooted. Never restate a device permission in a digest, command, skill or agent - point at the file.
- Timber only (no `Log.d()`). `Sxxxx` ticket ids only in `BlockNeedUserTest` temporary debug logs.
- Strings: prefer `scripts/utils/set-android-string.ps1`.
- Layouts (CLAUDE.md Rule 11): a portrait edit requires the matching `res/layout-land/` edit.
- UI changes (CLAUDE.md Rule 10): run `/ui-clarify` and settle placement/visibility/fallback before implementation.
- WindowInsets (CLAUDE.md Rule 17): systemBars + displayCutout safe bounds (fitsSystemWindows not enough).
- Dialog action pair (S0538/S0684): confirm/cancel in any dialog, bottom sheet or custom layout uses the named styles - `DialogConfirm`, `DialogCancel`, `DialogDestructive`. Never a one-off cancel button. Gate: `scripts/quality/assert-dialog-cancel-style.ps1`.
- Settings docs sync (CLAUDE.md Rule 22): any change to a setting, including one hosted in a dialog, bottom sheet or wizard page, regenerates `docs/settings/settings-manifest.json` + `docs/SETTINGS_REFERENCE*.md` and updates `docs/settings/settings-annotations.json`. A non-screen surface registers in `SettingsDocScopeCatalog`, never in `SettingsSearchLayoutCatalog`. Gate: `scripts/quality/assert-settings-doc-sync.ps1`.
- Thirteen locales for a new UI string (CLAUDE.md Rule 30): author `en`/`ru`/`uk` with the surface; every other locale declared in `app_v2/src/main/res/xml/locales_config.xml` fans out at the release boundary. The refusal sits at `scripts/quality/assert-new-lexemes-translated.ps1`, step 0.8 of `/spec-prerelease`; the authoring call and the ticket close only name what is missing. Producer `scripts/utils/list-new-lexemes.ps1`; loop in `docs/DEV_OPS.md` "Thirteen locales".
- Closing gates (CLAUDE.md section 4): the nine below all run from `Assert-ClosingGates` in `scripts/spec_catalog/_lib.ps1`, so `update.ps1`, `close.ps1` and `bulk-update.ps1` refuse alike. Eight judge a transition INTO a status; one judges the transition OUT of `BlockNeedUserTest`. Each one's mechanism, measurement and incident is `.claude/rules/spec-catalog.md` section `## Closing gates`, which a runtime without path-scoped rule loading reads whole at start. A refusal is fixed by satisfying it, never by re-stamping or retrying.
- Block* note (S2581): every transition INTO a `Block*` status needs `-StatusNote '<reason>'` - what the user must test on device, or what the blocker is and what resolves it. `BlockByOtherTask` also needs the id as a literal `Blocker: Sxxxx` token or a `**Depends on:**` line; a ticket with neither is skipped as `blocker-unresolvable`, which means "fix the spec", not "wait". The note lands in the spec header as `**Status note:**` and clears when the status leaves `Block*`. Gate: `scripts/spec_catalog/check-block-note.ps1`.
- Carried open item (S1607): a transition INTO `Implemented`/`Verified` requires every item in the spec's research section to be `Resolved` or to carry a literal `Carrier: Sxxxx` token naming the ticket that now owns the question. Otherwise a closed ticket leaves the queue and takes the question with it. `Archived` is not gated. Gate: `scripts/spec_catalog/check-open-items-carried.ps1`.
- Recorded audit (S2298): a transition INTO `Verified` requires a non-empty `## Last Audit` block - the one place an audit verdict exists. Matched by heading TEXT, so `## 6. Last Audit` counts. `Implemented` is deliberately ungated: it claims only that the code is done, before any audit has run. Gate: `scripts/spec_catalog/check-audit-recorded.ps1`.
- Present probe (S2324): a transition INTO `BlockNeedUserTest` requires either a `Timber.d("Sxxxx: ..")` probe in `app_v2`/`wear` or a row in `scripts/quality/blockneedusertest-probe-baseline.txt` stating why one cannot exist - without the probe the log cannot tell "the scenario went through the new code" from "it never reached it". An unknown id exits 2, not 1. Forward half: `assert-no-ticket-logs.ps1`; both decide "carries a probe" through the shared `scripts/quality/lib/blockneedusertest-probes.ps1`. Since S2934 it also judges the SHAPE of every probe it finds against `probes.ownLineRegex` - one statement alone on its physical line, since it is deleted in bulk - and a malformed probe does not satisfy presence. Gate: `scripts/spec_catalog/check-probe-present.ps1`.
- Absent probe (S2934): a transition OUT of `BlockNeedUserTest` is refused while any probe of the ticket is still in source - the equivalence's other half, which nothing guarded. A refusal, not a deletion: it prints `probes.removeCommand` filled in with the id. `archive.ps1` never calls `Assert-ClosingGates` and stays ungated. Gate: `scripts/spec_catalog/check-probe-absent.ps1`.
- Unique section heading (S2357): every gated transition requires each `## ` heading to be unique inside its level-1 block, over the strategic spec and every `.md` in the tactical folder. The shared parser stops at the next `## `, so a duplicate silently substitutes the first copy and can invert a gate rather than evade it. Judged per level-1 block, because a compact spec legitimately repeats `## Steps` under each `# Phase NN`. Gate: `scripts/spec_catalog/check-headings-unique.ps1`.
- Verdict against the current task (S2367): `Verified` and `BlockNeedUserTest` require the `## Last Audit` block to carry a `**Task fingerprint:**` that still hashes the spec body, with the `**Status:**`/`**Status note:**`/`**Priority:**` header lines and the audit block excluded. Never re-stamp to pass: re-read the task and re-audit, and if the work no longer covers it that is `Partial` or `Broken`. Gates: `scripts/spec_catalog/check-audit-current.ps1` and the widened `check-audit-recorded.ps1`.
- Open manual check (S1899): a check only a human can run has not happened yet. `/spec-check` counts every unticked `- [ ]` line in `## Last Audit` as `MANUAL`, and a run with zero WARN and FAIL but one open manual line scores `BlockNeedUserTest`, not `Verified`. Only a device pass converts it.
- A found problem ends `BlockNeedUserTest` (owner ruling 2026-08-31): that status means "the verdict is not in yet", never "a known defect is parked here". On any finding the ticket leaves it in the same action - `update.ps1 -Id Sxxxx -Status <Broken|Partial|In Progress|Approved|Draft> -StatusNote '<finding + next step>'` - so it returns to `PLAN/RELEASE_QUEUE.md`. Leaving the status deletes the `Timber.d("Sxxxx:` probes; re-entering it re-inserts them.

## 5. Skill Routing (command bodies live in `.claude/commands/<name>.md`)
- **Where the body is.** Every `/name` below is a file: `.claude/commands/<name>.md`, and that file is the whole procedure. Claude Code injects it on invocation; every other runtime must **read the file in full before the first step** and follow it literally. Some pipelines carry a companion of tables and edge cases at `.claude/reference/<name>.md`, read only when the driver names the condition; verbatim file skeletons live once in `.claude/templates/`.
- **`.github/prompts/` was retired (S1787).** The Copilot prompt mirrors had drifted beyond parity and were deleted. Read the command file.
- `/quick`: tiny fix (design, typo, 1 string), skip spec/build.
- `/skill-fix`: fast bug/UI fix, and the doc/config/script tweak that needs no gradle; skip doc/git/build/dev-log.
- **Reach for the two above first.** The tier ordering was an ungated sentence and measurably never fired. Claude Code now gets an advisory `UserPromptSubmit` nudge, which carries the counts; agents outside it do not, so for them this line is the whole mechanism.
- `/spec*`: spec lifecycle (`/spec`, `/spec-all`, `/spec-tech`, `/spec-update`, `/spec-dev`, `/spec-check`, `/spec-fix`, `/spec-arc`, `/spec-test-device`, `/spec-sweep`), plus five specialized specs: `/spec-next` (pick and drive the top ticket of the queue), `/spec-do` (the same picker with no endpoint), `/spec-code` (the `/spec-all` pipeline with every on-device step removed - the build is the only test, anything that ships ends at `BlockNeedUserTest`), `/spec-draft` (park an out-of-scope finding, CLAUDE.md 3.1), `/spec-quiz` (unstick a spec by asking the owner only the blocking decisions).
- Unattended batches do not use a command at all: `scripts/utils/run-spec-queue.ps1` runs `/spec-all` for one ticket per **fresh child process** (`runner.instances` in `.sza-profile.json`), in the same preflight ranker's order. The process boundary resets the context `/spec-do` accumulates, and two or three instances can run in parallel (`-Instance`). Prefer it whenever the machine is left working without a human.
- Queue model policy (S2696): `-ModelPolicy tiered` picks the model from ticket status - a stronger tier where a decision is left, a lighter one for `Implemented` and tier 1-2 work. `shape` is the opt-in per-instance measurement path that picks by size tier instead; the profile map ships empty, so the deployed behaviour stays `tiered` until the canon runner supports `shape` and the owner enables it. Set it in `.sza-profile.json`, never by editing the runner.
- **Short aliases.** Fourteen of the commands above answer to three extra names each: a two-letter Latin alias (`/sd` -> `/spec-draft`), its Cyrillic transliteration (`/сд`), and the same physical keys on the ЙЦУКЕН layout (`/ыв`). Each alias is its own delegating file under `.claude/commands/`, generated by `scripts/utils/generate-command-aliases.ps1` - add a row and regenerate, never hand-edit one. Runtimes that do not read `.claude/commands/` can ignore the aliases: they add no behaviour.
- **Codex alias resolution.** When the user sends any generated alias, resolve it to the canonical command, read that command's driver, and follow its procedure. This covers the Latin, Cyrillic and ЙЦУКЕН forms, `/arc`, `/арк` and `/фкс` included.
- `/ui-clarify`: resolve UI ambiguity before coding. `/catalog`: class/feature queries, sync catalog. `/doc-update`: docs sync. `/log-reader`: logcat/log analysis.
- `/spec-sweep`: two phases. Phase A drains `BlockNeedUserTest` via batch device-test. Phase B reviews `BlockExternal` tickets for stale blockers using the `next-review:` convention (`.claude/rules/spec-catalog.md`, "Release plan and queue"). `--blocked-only` runs Phase B alone, no device needed.
- `/release`: full release-campaign runbook (assess -> finish work -> `/spec-prerelease` -> docs incl. "What's New" -> `/skill-release` -> distribute -> verify); `/skill-release` is one step. `/skill-release-wear` is the second release entry point - the `wear` module to the Play `wear:production` track, on the watch's own cadence, never a step of the phone release. Terms: `docs/BUILD_VS_RELEASE.md`.
- `/build`: build checklist + reference (local "build" flow). `/git`, `/caveman`, `/caveman-commit`, `/caveman-review`.
- `/verify`: quick on-device sanity check of a change. `/newlog`: intake of a fresh remote-diagnostics bundle. `/skill-fix-release`: post-release hotfix pipeline for one ticket.

## 6. Workflow & PowerShell
- Confirm the working branch before an edit (`git branch --show-current`) - the tree, not the log, is the state (canon `rules/GITHUB_INTERACTION.md` section 1).
- Multi-step: follow `dev/AGENT_WORKFLOW.md` (5 steps).
- After changes (except `/skill-fix`): run `.\scripts\add_to_dev_log.ps1`.
- Kotlin changes: sync catalog via `scripts/catalog_sync.ps1 -Module <app_v2|wear>`.
- Mechanical closure: prefer `scripts/post-change.ps1 -File <p> -Target <t> -Description <d> -ChangeType <Doc|Script|Config|Tooling|Kotlin|Xml|Mixed>` (chains dev-log, catalog-sync, gates). On the always-dirty tree name the whole set with `-Files "a,b"` + `-ScopeToFile` (diff-scoped detekt, advisory project-wide ratchets); omit for release/CI. A fixed-input gate (dot-sources `scripts/quality/lib/fixed-input-scope.ps1`) is fatal only when a file it declares as an input is in the set - otherwise its author is another session (S2824/S2827/S2828). A failed closure writes no changelog row; one that passed with advisories did (S1622).
- Concurrent-agent locks, split by domain (CLAUDE.md Rule 23, S2109): a coordination resource is a **pair, type plus domain**. Domains: `.sza-profile.json` `locks.domains` (S2697): `Build.Phone`, `Build.Wear`, `Code.Phone`, `Code.Wear`, `Code.Scripts`, `Code.Fixture`. Two sessions collide only where their domains overlap. Every script invoking gradle acquires its build domains (`Enter-BuildLockOrExit -Domain <..>`); before a source edit acquire the code domains with `scripts/utils/enter-code-lock.ps1 -Files "<changed paths>" -Reason "..."`, which **derives** them from the paths - a declared domain is the escape hatch, not the norm. Multi-domain work is taken all at once in canonical order, all or nothing.
- A busy domain does not refuse - it **queues** you in order of asking, and `enter-code-lock.ps1` exits **4** for "queued, not yet your turn". Since S2612 a short-class fast check answers a busy `Build.*` domain the same way. Waiting contract: run `scripts/utils/wait-for-lock-turn.ps1 -Name <domain> -Reason "..." -Handoff <path from the exit-4 message>` as a **background** task (S2403) and meanwhile do work needing no lock - reading, research, specs, catalog, log analysis. Abandoning a queued intent requires withdrawing your own place: `scripts/utils/withdraw-lock-ticket.ps1 -Name <domain>`, or `.\a.ps1 uqb` / `uqc`. Order and holder: `lock-status.ps1 -Name <domain> -Queue`.
- You never apply the path table by hand - `enter-code-lock.ps1` derives the domains from the changed set. Hand-edited trees need the lock; `PLAN/` and `temp/` are the two exemptions, so a set confined to them exits 0 with nothing to release. The per-path table: `docs/DEV_OPS.md` "Concurrent-agent locks".
- The lock window is the edit and nothing else (S2419): it opens immediately before the step's first edit and closes the moment that step's last file is written, released by your own `scripts/utils/exit-code-lock.ps1`. Verification, the phase build, the unit suite, the gate batch, the dev log and the catalog all run outside it; `post-change.ps1` releases only as a backstop. Measurements: `docs/DEV_OPS.md` "Concurrent-agent locks".
- Agent chat (CLAUDE.md Rule 34, S2372): the descriptive layer beside the locks - `temp/AGENT-CHAT/progress/` (what a session is doing) and `temp/AGENT-CHAT/findings/` (a measurement or an environment state, dead the moment anything in its declared scope changes). The scripts write it on their own; the model owes three lines through `scripts/utils/agent-chat.ps1 -Verb Post` - a phase start, a stage boundary, giving work up (`-Kind abandon`). It is printed at a refusal (`enter-code-lock.ps1` exit 4, `ticket-lease.ps1` exit 3); `-Verb Read|Find|Status` is the explicit look. Trust rule: the chat decides nothing - no acquisition branches on it and no spec or gate verdict rests on another agent's finding. Identity is `scripts/utils/agent-identity.ps1`, never empty, and every agent speaks under a nickname (`-Verb Whoami`). **If you have no hooks, set `FMS_AGENT_ID` first** (§9.1) and post `-Kind session` yourself at start and end. Detail: `.claude/rules/agent-chat.md`.
- Detekt-clean-first: author touched `.kt` to pass detekt on the first build - log/probe lines `<=120` chars, no bare numeric literals (`TimeUnit`/companion `const`/reuse a const), never `@Suppress` a method with a baselined finding. CLAUDE.md Rule 19.
- Background/foreground - the 120 s threshold (CLAUDE.md Rule 6): the two-sided rule is canon (`rules/AI_USAGE.md` section 1); this repo pins the boundary to the Bash tool's own foreground timeout. **Above it, background**: `a.ps1 d/db/dav/cd/nd/nl/r/fu`. **Below it, do not**: `fk/fkn/fc/fr/dq` and `assert-detekt` run 14-21 s on a warm daemon, `fg` runs 47 s, and the wear targets `fw/fwr/fwu` run 2 s / 1 s / 11 s - wait and read the verdict in the same turn. Enforced by Rule 26.
- PowerShell: `-NoProfile`, one-process batching, and the fresh-interpreter-per-call model have one home, canon `rules/GITHUB_INTERACTION.md` section 6. Repo specifics: write `$` literally, and prefer the project wrappers over hand-rolled invocations.
- PowerShell exit codes (S1070): under `$ErrorActionPreference = 'Stop'` a bare `Write-Error` throws and the `exit N` after it never runs, so the code collapses to 1 while the message still prints. Use `Write-Error $msg -ErrorAction Continue` before `exit N` (N != 1); a header must list the codes actually returned. Gate: `scripts/quality/assert-exit-contract.ps1`.
- Subagent MCP isolation: give every subagent definition an explicit `tools:` frontmatter allowlist that omits every MCP tool name, unless it strictly requires driving the UI/emulator - omitting `tools:` entirely grants the parent's full set, MCP included, and duplicates Node/MCP server instances. (S1348: `enable_mcp_tools` is not a real Claude Code option.)
- Compose boundary (CLAUDE.md Rule 32): `app_v2` is View + XML + ViewBinding, `wear` is Compose. A new `setContent { .. }` under `app_v2/src/main` is refused by the `compose-island` dimension of `scripts/quality/assert-source-gates.ps1` (baseline `scripts/quality/compose-island-baseline.txt`). Existing islands leave opportunistically, never as a campaign, and each removal lowers the baseline. The watch module is untouched by the gate.
- Gate placement (CLAUDE.md Rule 33): a gate whose subject is the whole tree or a shipped artifact runs once over the release scope (`scripts/quality/assert-release-scope-gates.ps1`, step 0.4 of `/spec-prerelease`), not on every changed file - applied per file it cannot attribute its finding and degrades into noise. It stays per-ticket when later work builds on the defect, when the evidence exists only at the moment of the change, or when agents read the artifact between releases. A relocation must be a script with an exit code, never a line of prose in a command file.
- Subagent model routing (CLAUDE.md Rule 31): the built-in `general-purpose` agent has no definition file and cannot be pinned, so name the tier at the call site. Mechanical, search, doc and lookup work goes to a lightweight tier or to the pre-pinned `android-solution-researcher` / `repo-mechanic` / `friendly-android-doc-writer`; reserve the expensive tier for design and Kotlin (`android-kotlin-developer`, `android-rd-specialist`).

## 7. Validation
- Follow `CLAUDE.md` validation ladder. Record `expected: X | actual: Y` for every non-trivial step, naming the command run and its exit code (CLAUDE.md Rule 15).
- The evidence rule has one home, canon `rules/DEVELOPMENT.md` section 5 / `rules/INVARIANTS.md` 7. Treat the red-flag words - "should", "probably", "seems", "looks fixed" - as the signal to stop and run the check first.
- Prefer the cheapest proof that matches the change: `.\a.ps1 fk` for Kotlin symbol edits (`fkn` for noLegal), `.\a.ps1 fr` for resources/manifests, `.\a.ps1 fc` for mixed small changes, `.\a.ps1 fg` to batch the fast static gates in one process, and full debug APK builds only when packaging or install behavior matters.
- The resources/manifest rung is enforced mechanically since S1915: the `resource-link-gate` in `post-change.ps1` links the changed resources and fails the closure on an aapt error. `fk` never links resources, so before that gate a broken layout closed green. Running `fr` yourself first is still the cheaper loop - the gate is the backstop, not the workflow.
- Your own change, your own test classes (S2851): `fu` / `-Mode Unit` with no `-Tests` is 5033 tests, measured 429 s, and holds `Build.Phone` throughout while siblings queue; `-Tests "*YourThingTest"` measured 20 s. Price and per-change-type map: `docs/BUILD_TEST_FAST_PATH.md`.
- Pick the target by module before change type (S1807): `fk`/`fkn`/`fr`/`fc`/`fu` all check `app_v2`. A change under `wear/` is proved by `.\a.ps1 fw` (Kotlin), `fwr` (resources/manifest) or `fwu` (unit suite) - the phone target exits 0 without compiling a watch file, so its green is a verdict about the other module. Each check prints the module it checked in its banner.
## 8. Code Audit Protocol
- Full protocol: `docs/CODE_AUDIT_PROTOCOL.md`. Apply it on any **audit trigger**: new screen/manager/worker/repository/long-lived helper; lifecycle/coroutine/Flow/listener/observer change; shared-state/dispatcher change; Room entity/DAO/query/migration/transaction change; player/image/cache/network change; startup change; DI scope/singleton change; build/manifest/R8/keep-rule change affecting profiling, startup or minification; reported crash/ANR/OOM/jank/leak; **phase boundary in a multi-phase task** - audit the phase just finished before starting the next.
- Phase-boundary audits are mandatory, not deferred to pipeline end: a defect costs one phase's rework when caught at the next boundary, versus every later phase's rework when it surfaces only at the final audit. `/spec-dev` runs it per phase; apply the same discipline outside it.
- Reflection, serialization, DI, manifest and dependency changes are proven on the minified release/target variant, not only debug - which extends dead-weight hygiene (CLAUDE.md Rule 20). The per-layer checklists behind this live only in `docs/CODE_AUDIT_PROTOCOL.md` Layers 1-8.

## 9. Non-Claude Runtimes (Codex, Gemini, Copilot, ZCode)

The rules above were written for a runtime that enforces part of them mechanically. Outside Claude Code that half is missing, and nothing announces its absence - so this section states what you now owe by hand.

### 9.1 What does not run for you

- **Hooks - and `docs/NON_CLAUDE_RUNTIME_RULES.md` is the rule text, not this bullet.** `.claude/hooks/*.ps1` plus per-machine global hooks refuse, rewrite or annotate Claude Code's tool calls; none of them sees yours. **Read that sheet first**: twelve imperatives derived one per hook that guards a decision you make, each here because an agent already got it wrong, plus the closure check and the three hooks that give you no rule at all. It is deliberately the only home of that text - a second phrasing would drift, which is how this section became a description instead of an imperative (S2872). The mechanism behind each hook stays in `docs/AGENT_HOOKS.md`.
- **The command library.** Claude Code injects `.claude/commands/<name>.md` when you type `/name`. Nothing injects it for you - open the file (§5).
- **Subagents.** `.claude/agents/*.md` describe the roles Claude Code can spawn in parallel (device operator, Kotlin developer, R&D specialist, solution researcher, doc writer, repo mechanic). You have no such fan-out: do the work inline, in one context, and keep whatever constraints that role's file states - notably that the researcher and the device operator never edit product code.
- **Agent memory.** `.claude/agent-memory/android-rd-specialist/MEMORY.md` is an index of hard-won project facts that Claude Code always has in context. Read it at session start when the task touches builds, flavors, gates, devices or release; each line points at a file in the same directory. ZCode ships it as the workspace skill `android-rd-specialist-memory`, pointing at that same directory - no second copy exists (S2622).
- **The skill loop.** The mandatory document-registry loop is a Claude Code skill at `.claude/skills/document-registry/SKILL.md`. Read that file and run its four steps yourself: identify area and trigger, query `scripts/document_registry/query.ps1`, read every returned record, state which are affected.
- **Your identity, and it is the first thing you set.** Set `FMS_AGENT_ID` once, to one value you keep for your whole session, before you run anything else - then `FMS_AGENT_RUNTIME` and `FMS_AGENT_MODEL` so the lines name you (CLAUDE.md Rule 34). Without it the chain falls through to the pid of a shell that lives for one command, and a session that looks dead from its first minute has its lease taken by siblings. S2408 gives a floor when you cannot set it, but that floor cannot tell two of your chats apart inside one host process, so setting the variable is still yours to do. `FMS_AGENT_HOST_WALK=0` turns the walk off; `scripts/utils/agent-chat.ps1 -Verb Whoami` prints what you resolve to. The walk, the id shapes and the incident behind them: `docs/DEV_OPS.md` "Agent chat".
- **Complete the call, and reap what you start.** Close the child's stdin or pass `-NonInteractive`, and wait for the child. A missing **mandatory** parameter makes PowerShell prompt on stdin, so an open pipe hangs the script before it runs a line and your runtime records success anyway: `docs/DEV_OPS.md` "Abandoned script processes" (S2610).
- **The agent chat.** Claude Code's session hooks announce a session's start and end to `temp/AGENT-CHAT/`; nothing announces yours. Post them yourself - `pwsh -NoProfile -File scripts/utils/agent-chat.ps1 -Verb Post -Kind session -Note "session started (<your runtime>)"` at the start and `-Note "session ended (<reason>)"` at the end. That first post also takes your nickname, kept for the session; `FMS_AGENT_NAME` sets one of your choosing. The scripts post everything else for you; `.\a.ps1 chat -Verb Status` is the explicit look, and `-Verb Find -Topic "device:*"` tells you whether a finding holds for the tree or device you see.

### 9.2 The development artifacts, and the script that owns each

Never hand-edit a generated or script-owned file; the CLI is the only supported writer.

- Tickets: `PLAN/Sxxxx_<slug>.md` + journal `PLAN/spec-catalog.jsonl`, owned by `scripts/spec_catalog/*.ps1` (`select`, `search`, `next-id`, `insert`, `update`, `close-and-log`, `archive`).
- Release plan: `PLAN/RELEASE_QUEUE.md` (work left) + `PLAN/RELEASE_READY.md` (finished); ranking in section 3.
- Kotlin class index: `dev/CATALOG/<module>.jsonl|.md`, regenerated by `scripts/catalog_sync.ps1 -Module <app_v2|wear>`, queried by `dev/CATALOG/scripts/query.ps1`. Local and gitignored - regenerate, never commit.
- Maintained documents and public pages: `docs/DOCUMENT_REGISTRY.jsonl` with `scripts/document_registry/{query,validate,generate}.ps1`; `docs/DOCS_MAP.md` and `sitemap.xml` are its render targets.
- Shipped capabilities: `docs/ALL_FEATURES.jsonl` via `scripts/all_features/add.ps1`. The public showcase `docs/FEATURES*.md` is written only by the release pipeline.
- Change journal: `dev/CHANGELOG.md`, written only by `scripts/add_to_dev_log.ps1`, one entry per logical change.
- UI strings: `scripts/utils/set-android-string.ps1` (byte-preserving), then `scripts/check_strings_localized.ps1`.
- Closure facade that chains all of the above plus the gates: `scripts/post-change.ps1`; on this always-dirty tree add `-Files "a,b" -ScopeToFile`. Exit 0 passed, 1 a gate failed, 2 could not verify.
- Gates: `scripts/quality/assert-*.ps1`, batched by `pwsh -NoProfile -File ./a.ps1 fg`.
- Builds and checks: `./a.ps1` targets (§7). Locks before them: `scripts/utils/{enter-code-lock,agent-lock,wait-for-lock-turn,lock-status}.ps1` (§6).
- Device work without tokens: `scripts/devtest/adb.ps1 <verb>`.
- The process harness (ticket journal, locks, leases, identity, chat, change journal, document registry, queue runner, capability ledger, alias generator) is CONSUMED from the `sza` canon plugin, not authored here (S2402): the local paths are generated forwarders. What this repository configures lives in `.sza-profile.json` and nowhere else - never edit a harness script body.

### 9.3 Session kickoff

Paste this at the start of a Codex, Gemini or ZCode session, or when the runtime has been reset:

```text
Read, in this order, before doing anything: docs/NON_CLAUDE_RUNTIME_RULES.md (the rules nothing will
```

The closing instruction is deliberate: it ends in a cheap, checkable answer, so a runtime that skipped the reading is visible immediately.
