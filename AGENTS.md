- Directories: `app_v2/`, `wear/`, `dev/`, `docs/`, `scripts/`, `temp/` (scratch/logs). Read-only zones, no exceptions (CLAUDE.md Rule 4): `V1/`, `v2_6/`, `spec_v2/`, `dev/archive/`.

Fixed infra stays at `temp/` root, never nested: the per-domain coordination files `temp/BUILD.PHONE.LOCK`, `temp/BUILD.WEAR.LOCK`, `temp/CODE.PHONE.LOCK`, `temp/CODE.WEAR.LOCK`, `temp/CODE.SCRIPTS.LOCK`, each with a `.QUEUE` directory and a `.TURN-<sessionId>.json` marker (S2109), `temp/spec-all-queue.lock`, `temp/spec-next-skip-cache.json`, raw logcat sinks `temp/current.log` + `temp/fastmediasorter_*.log`, stream-catalog files.

- No Activity logic (CLAUDE.md Rule 3): delegate to `helpers/*Manager.kt`.
- No self-cost estimates (CLAUDE.md section 1): never write how long a change will take, how much effort it is, or how many lines it will add - in a spec, a phase file, a plan or a reply. A size read off a real file (the 2000-LOC ceiling, the 500-LOC backup threshold) is a measurement, not an estimate, and stays.
- Backup before a big edit (CLAUDE.md Rule 5): a file over 500 LOC gets a timestamped copy under `temp/Sxxxx/` (or `temp/scratch/`) first.
- Naming (CLAUDE.md Rule 6): `VerbNounUseCase`, `NounRepository`, `NounViewModel`, `NounVerbManager`.
- Lint (CLAUDE.md Rule 7): fix the warnings in the files you touched, not only the ones you introduced.
- Read before editing (CLAUDE.md Rule 8): the comments and KDoc already in the area are requirements - read them first and never override one silently.
- Comment discipline (CLAUDE.md Rule 9): EN-only, explain WHY not WHAT, no trivial comments, remove stale ones.
- Spec catalog is script-owned (CLAUDE.md Rule 12): never hand-edit `PLAN/spec-catalog.jsonl`, never rename an `Sxxxx_` prefix; mutate through `scripts/spec_catalog/*.ps1`.
- Script ownership (CLAUDE.md Rule 13): a project script that is buggy or insufficient gets fixed, not worked around.
- Flavor isolation (CLAUDE.md Rule 14): no `BuildConfig.IS_*` flavor guards in `src/main/` - use an interface plus flavor source sets.
- Input coverage (CLAUDE.md Rule 16): every interactive surface supports keyboard, D-pad/TV and mouse - set `focusable`, `clickable`, `nextFocus*`.
- Lazy optimization (CLAUDE.md Rule 18): Hilt `dagger.Lazy<T>`, `<ViewStub>` for optional layouts, release player/media resources the moment playback pauses.
- Deprecated PackageManager flags (CLAUDE.md Rule 21): no raw-int `getPackageInfo`/`getApplicationInfo`/`queryIntentActivities`/`resolveActivity` in `src/main` - use the `*Compat` helpers in `util/PackageManagerCompat.kt`. Gate: the `deprecated-pm-flags` dimension of `scripts/quality/assert-source-gates.ps1`, run on every closure via the `neuroslop-gate` umbrella in `post-change.ps1`. `assert-deprecated-pm-flags.ps1` is a named forwarder for running that one rule by hand.
- What to work on next comes from `PLAN/RELEASE_QUEUE.md` (CLAUDE.md 4): release package ascending, then the owner's line order inside it; then `Implemented` rows in `PLAN/RELEASE_READY.md`, then `--` parked lines, then anything unlisted. Catalog `priority` is a tiebreak for unlisted tickets only. Recommend from that file, quote the package and line, state any deviation. `spec-next-preflight.ps1` and `release-plan.ps1` rank from it.
- Bash `find` safety: one home, canon `rules/GITHUB_INTERACTION.md` section 6, and the canon's `sza` plugin now ships the enforcement too (`guard-bash.ps1`). A `find` with a disk-wide start path or no `-maxdepth` is refused before bash spawns, and file/class lookup goes through the `Glob`/`Grep` tools or `dev/CATALOG/scripts/query.ps1`. Detail: CLAUDE.md Rule 24, contract in `docs/AGENT_HOOKS.md`.
- No `.ps1` as a Bash command head (CLAUDE.md Rule 25): never run a PowerShell script directly in Bash (`./a.ps1 fk`, `.\a.ps1 d`, `scripts/foo.ps1`); Bash cannot execute a `.ps1` and the failure returns **exit 0**, so a broken build/check looks like it passed. Always `pwsh -NoProfile -File ./a.ps1 <cmd>` from the repo root. Contract: `docs/AGENT_HOOKS.md`.
- No fire-and-forget verdict (CLAUDE.md Rule 26): never background a gate, a closure facade or a catalog mutator (`post-change.ps1`, `assert-*.ps1`, the `spec_catalog`/`document_registry`/`all_features` CLIs, `add_to_dev_log.ps1`, `catalog_sync.ps1`, `a.ps1 fk/fkn/fc/fr/fg/dq/ch/ss/bf`). It costs an extra turn rather than saving one, and a verdict nobody reads in the same turn is not a verdict. A real long job on the same line still backgrounds normally. Contract: `docs/AGENT_HOOKS.md`.
- No slash-command name as an argument value in a Bash-tool `pwsh` call (CLAUDE.md Rule 27): `-Reason "/spec-dev .."` reaches the script as `C:/Program Files/Git/spec-dev ..` because MSYS reads the leading slash as a POSIX path, and the corruption is silent - exit code 0, mangled text in the lock/queue/lease diagnostics (S1458). Use `-Reason "//spec-dev .."`, or prefix `MSYS2_ARG_CONV_EXCL='*'`, or call from the PowerShell tool. Refused by the canon plugin's `guard-bash.ps1` since 2026-08-18; the project copy was removed rather than run twice. Contract: `docs/AGENT_HOOKS.md`.
- No command in the Bash tool that cannot exist there (CLAUDE.md Rule 28): a **PowerShell cmdlet** in command-head position (`ls | Select-Object -First 3`), an **interpreter that is not installed** (`node`, `npm`, `npx`), and the **batching idiom** `& { .. }` at the start of a command are all refused before the call runs - each is an `exit 127` that returns nothing. Run the pipeline in the PowerShell tool, or `pwsh -NoProfile -Command "<pipeline>"`. `python3` is **not** refused: `~/bin/python3` shims to the `python` on PATH, so the name resolves. Only a head is refused - a cmdlet inside quotes, a heredoc or an argument is fine, and Bash's own `if` and `cmd && { .. }` stay legal. Contract: `docs/AGENT_HOOKS.md`.
- Hooks and the inventory (CLAUDE.md Rule 29): a hook may **refuse** a tool call, **rewrite** its input, **observe** its result or **warn** you, and `docs/AGENT_HOOKS.md` is the complete list - every registered hook, its event, verdict shape, escape hatch, and whether it is global (per-machine, absent on a fresh checkout) or project (travels with the repository). Two are named in no rule above: `guard-catalog-before-kt-search` **refuses** an unnarrowed `.kt` search until the class catalogue was queried this session, and `guard-uncapped-read` **rewrites** a `Read` carrying no explicit window to `limit: 800`, so a long file you did not window is only partly read (`.claude/commands|skills|templates|reference|agents` are exempt; policy in `docs/AGENT_COST_PLAYBOOK.md` "Context hygiene"). Registering or removing a hook requires editing the inventory in the same change - gate `scripts/quality/assert-hook-inventory.ps1` in `.\a.ps1 fg`.
- Device fleet (CLAUDE.md Rule 35): `docs/DEVICE_FLEET.md` is the roster and the only home of a per-device permission - read it and match the serial before the first `adb` call of a task, because authorization is per device, never per "a device is attached". Free hand on the **S21+** test phone, on **emulators** and on the **Galaxy Watch 7**; the owner's **S25 FE** carries his live `noLegal` debug with real private data plus the store STANDARD build he tracks updates on, so install over the top and `pm grant` are allowed while `pm clear`, `uninstall`, a system role and the store build are not; the **S20 FE** guest phone is read-only; this workstation is personal as well as a build machine - no shutdown or reboot, and never kill a process this session did not start. Default target when a ticket needs "some device": emulator -> S21+ -> S25 FE. Never restate a device permission in a command, skill or agent - point at the file.
- Timber only (no `Log.d()`). `Sxxxx` ticket ids only in `BlockNeedUserTest` temporary debug logs.
- Strings: prefer `scripts/utils/set-android-string.ps1`.
- Layouts (CLAUDE.md Rule 11): a portrait edit requires the matching `res/layout-land/` edit.
- UI changes (CLAUDE.md Rule 10): run `/ui-clarify` and settle placement/visibility/fallback before implementation.
- WindowInsets (CLAUDE.md Rule 17): systemBars + displayCutout safe bounds (fitsSystemWindows not enough).
- Dialog action pair (S0538/S0684): confirm/cancel in any dialog/bottom-sheet/custom layout uses the named styles - confirm = `DialogConfirm` (green, wide), cancel = `DialogCancel` (soft-pink tonal, shorter/narrower), destructive = `DialogDestructive` (red). Never a one-off cancel button. Gate: `scripts/quality/assert-dialog-cancel-style.ps1`.
- Settings docs sync (CLAUDE.md Rule 22): any change to a setting, including one hosted in a dialog/bottom-sheet/wizard page, must regenerate `docs/settings/settings-manifest.json` + `docs/SETTINGS_REFERENCE*.md` and update `docs/settings/settings-annotations.json`. A non-screen surface registers in `SettingsDocScopeCatalog`, never in `SettingsSearchLayoutCatalog` (S1035/S1313). Gate: `scripts/quality/assert-settings-doc-sync.ps1`.
- Thirteen locales for a new UI string (CLAUDE.md Rule 30): a key added to `values/strings*.xml` reaches every locale declared in `app_v2/src/main/res/xml/locales_config.xml` before the release, not only the authored `en`/`ru`/`uk`. The refusal sits at the pre-release stage - `scripts/quality/assert-new-lexemes-translated.ps1`, wired as step 0.8 of `/spec-prerelease` - because nothing ships between releases and one bulk round trip clears every key of a release at once, while translating per ticket costs ten translations a key for no shipping benefit (owner ruling 2026-08-14, S1627 ADR-2). The authoring call and the ticket close only name what is missing; they never refuse. The producer is `scripts/utils/list-new-lexemes.ps1` and the loop is written out in `docs/DEV_OPS.md` "Thirteen locales".
- Carried open item (S1607): a transition INTO `Implemented`/`Verified` requires every item in the spec's research section to be `Resolved` or to carry a literal `Carrier: Sxxxx` token naming the ticket that now owns the question - only the literal token is read, as with `Blocker: Sxxxx`. The carrier is an ordinary catalog record, so it returns to `PLAN/RELEASE_QUEUE.md` and is batched into `/spec-quiz`; there is no separate registry of owner decisions. `Archived` is not gated. Gate: `scripts/spec_catalog/check-open-items-carried.ps1`, invoked from `Assert-ClosingGates` in `_lib.ps1` by `update.ps1`, `close.ps1` and `bulk-update.ps1` alike.
- Recorded audit (S2298): a transition INTO `Verified` requires the spec to carry a non-empty `## Last Audit` block - the one place an audit's verdict exists, since `/spec-check` writes it and no separate registry does. Measured 2026-09-01: 7 of 129 live `Verified` specs carry none, closed through three different paths, so the missing check belonged on the shared one. `Implemented` is deliberately not gated - it means the code is done, before any audit has run. The heading is matched by TEXT, so the numbered form `## 6. Last Audit` counts; the literal test that preceded this read it as absent, in the gate and in `preview.ps1`'s `last_audit_present` alike. Gate: `scripts/spec_catalog/check-audit-recorded.ps1`, invoked from `Assert-ClosingGates` in `_lib.ps1`.
- Present probe (S2324): a transition INTO `BlockNeedUserTest` requires either at least one `Timber.d("Sxxxx: ..")` in `app_v2`/`wear`, or a row in `scripts/quality/blockneedusertest-probe-baseline.txt` stating why a probe cannot exist. The status parks a ticket for a human to watch on a device, and without the probe the log cannot tell "the scenario went through the new code" from "it never reached it". The refusal names both exits - refusing a docs/scripts/resources-only ticket outright would make it unclosable. Reverse half of Rule 2; the forward half is `assert-no-ticket-logs.ps1`, and both decide "carries a probe" through the shared `scripts/quality/lib/blockneedusertest-probes.ps1` so they cannot disagree (S1621), a Timber call being able to span physical lines. Measured 2026-09-02: 17 tickets sat in the status with no probe and the set had turned over rather than shrunk, because the only fatal run was the project-wide `.\a.ps1 fg` - `post-change.ps1` scopes the tree gate and downgrades this half to advisory exit 3 (S1912). Not a closing status, so it brings this checker alone and suppresses the capability advisory; an unknown id exits 2, not 1. Gate: `scripts/spec_catalog/check-probe-present.ps1`, invoked from `Assert-ClosingGates` in `_lib.ps1`.
- Verdict against the current task (S2367): the `## Last Audit` block records a `**Task fingerprint:**` - twelve hex of SHA-256 over the spec body minus the parts the pipeline writes itself (the `**Status:**`/`**Status note:**`/`**Priority:**` header lines and the audit block) - and a transition INTO `Verified` or `BlockNeedUserTest` is refused when the file no longer hashes to it. The task is edited under a running pipeline, by the owner, by `/spec-quiz` writing an answer in, or by a sibling session, while the pipeline reads the spec once at Stage 0. The exclusions are what keep it usable: without them the fingerprint would move on the very status flip it guards. Never re-stamp to pass - re-read the task, re-audit, and if the work no longer covers it that is `Partial` or `Broken`. The same ticket widens the S2298 audit-block requirement to `BlockNeedUserTest`, which is a coverage claim exactly as `Verified` is: measured 2026-09-02, 72 of 158 tickets in that status carried no block, because `/spec-code` step 4 forbids `/spec-check` before parking (it would delete the probes S2324 requires). The parking command writes a pre-handoff block itself - `.claude/reference/spec-all.md` section 11a - touching no `.kt` and moving no status. `Implemented` stays ungated. Gates: `scripts/spec_catalog/check-audit-current.ps1` and the widened `check-audit-recorded.ps1`; the hashed text is defined once in `_task-fingerprint.ps1` and printed by `task-fingerprint.ps1` (S1621).
- Open manual check (S1899): `Verified` requires zero `MANUAL`. `/spec-check` counts every unticked `- [ ]` line in a spec's `## Last Audit` as `MANUAL`; zero WARN and FAIL with at least one open manual line scores `BlockNeedUserTest`, not `Verified`. `MANUAL` used to satisfy `Verified`, which let a ticket be declared done carrying a device check nobody had run.
- A found problem ends `BlockNeedUserTest` (owner ruling 2026-08-31): that status means "the verdict is not in yet", never "a known defect is parked here". As soon as a device test, sweep, audit, log read or the owner finds a problem, the ticket leaves it in the same action - `update.ps1 -Id Sxxxx -Status <Broken|Partial|In Progress|Approved|Draft> -StatusNote '<finding + next step>'`, the state chosen by what the finding needs (research -> `Draft`/`Approved`, known fix -> `In Progress`/`Partial`, regression -> `Broken`). Only then does it return to `PLAN/RELEASE_QUEUE.md`; left in `BlockNeedUserTest` it sits in `PLAN/RELEASE_READY.md` and reads as finished content. Never record the finding in the spec and leave the status alone. Leaving the status deletes the `Timber.d("Sxxxx:` probes; re-entering it re-inserts them.

## 5. Skill Routing (command bodies live in `.claude/commands/<name>.md`)
- **Where the body is.** Every `/name` below is a file: `.claude/commands/<name>.md`, 32 of them, and that file is the whole procedure. Claude Code injects it on invocation; every other runtime must **read the file in full before the first step** and follow it literally. Six pipelines carry a companion of tables and edge cases at `.claude/reference/<name>.md`, read only when the driver names the condition, and verbatim file skeletons live once in `.claude/templates/`.

The process boundary resets the context that `/spec-do` accumulates, two or three instances can run in parallel (`-Instance`), and the model is picked per ticket - Opus where a decision is left, Sonnet for `Implemented` and tier 1-2. Prefer it whenever the machine is left working without a human.

## 6. Workflow & PowerShell
- Confirm the working branch before an edit (`git branch --show-current`) - the tree, not the log, is the state (canon `rules/GITHUB_INTERACTION.md` section 1).
- Multi-step: follow `dev/AGENT_WORKFLOW.md` (5 steps).
- After changes (except `/skill-fix`): run `.\scripts\add_to_dev_log.ps1`.
- Kotlin changes: sync catalog via `scripts/catalog_sync.ps1 -Module <app_v2|wear>`.
- Mechanical closure: prefer `scripts/post-change.ps1 -File <p> -Target <t> -Description <d> -ChangeType <Doc|Script|Config|Kotlin|Xml|Mixed>` (chains dev-log + catalog-sync + quality gates). On the always-dirty tree add `-ScopeToFile` (diff-scoped detekt + advisory project-wide ratchets); omit for release/CI. A failed closure writes no changelog row; a closure that passed **with advisories** returned 0 and did write one, and re-running it after fixing what the advisory named still leaves exactly one row - the dev-log guard identifies the change and ignores the size of its `[set of N: ..]` file list (S1622).
- Concurrent-agent locks, split by domain, and their queues (CLAUDE.md Rule 23, S1432, S2109): a coordination resource is a **pair, type plus domain**. Five domains, listed once in `scripts/utils/agent-lock-domains.ps1`: `Build.Phone`, `Build.Wear`, `Code.Phone`, `Code.Wear`, `Code.Scripts`. Two sessions collide only where their domains overlap, so a watch edit, a phone edit and a scripts edit run at the same time. Every script invoking `gradlew`/`gradlew.bat` acquires its build domains (`Enter-BuildLockOrExit -Domain <..>`, defaulting to both); before a multi-file source edit acquire the code domains with `scripts/utils/enter-code-lock.ps1 -Files "<changed paths>" -Reason "..."`, which **derives** them from the paths - a declared domain is the escape hatch, not the norm, and anything that does not decompose (a build file, an unknown path, no file set) takes the full set. Multi-domain work is taken all at once in canonical order, all or nothing; a set that cannot be completed releases every domain it had already taken. A busy domain does not refuse - it **queues** you in order of asking: the build path waits by default (`-NoWait` / `FMS_LOCK_NO_WAIT=1` opts out), and `enter-code-lock.ps1` exits **4** for "queued, not yet your turn - do not edit sources yet". Waiting contract: run `scripts/utils/wait-for-lock-turn.ps1 -Name <domain> -Reason "..." -Handoff <path from the exit-4 message>` as a **background** task (its exit is the "your turn" signal, and a multi-domain wait is granted only when you are head in every domain) and meanwhile do work needing no lock - reading, research, specs, catalog, log analysis. The handoff carries the queue ticket across the process boundary (S2403). The test is not "is it source" but **"is this path already serialised by something finer" (S2338)**: sources, resources, build files, repository scripts, `.claude/`, `.github/`, `docs/` and `dev/` need the lock, being hand-edited with nothing finer over them, and so do the content trees `play/`, `fastlane/`, `store_assets/`, `delivery/`, `maestro/` and the root site pages, documents and icons, which take `Code.Scripts` rather than the full set (S2342) because none of them compiles, links or packs into an APK - while `corex/`, `benchmark/` and `watchface/` still fail closed; `PLAN/` does not, and is the one exemption, because a spec file belongs to exactly one ticket held by `ticket-lease.ps1` and the journals plus both release files are written only through catalog mutators holding the catalog's own mutex. A PLAN-only set resolves to no domain and `enter-code-lock.ps1` exits 0 with nothing to release. The window is the edit and nothing else (S2419): it opens immediately before the step's first edit and closes the moment that step's last file is written, released by your own `scripts/utils/exit-code-lock.ps1` - the verification predicates, `plan-tick.ps1`, the phase's `Project compiles` build (already serialised by `Build.*`), the unit suite, the gate batch, the dev log and the catalog all run outside it, never for a whole ticket. Abandoning a queued intent requires withdrawing your own place (S2098): `scripts/utils/withdraw-lock-ticket.ps1 -Name <domain>`, or `.\a.ps1 uqb` / `uqc`; only a granted-but-unclaimed head self-heals (S2194). Order and holder: `lock-status.ps1 -Name <domain> -Queue`, which prints one section per domain for a bare `Build` or `Code`. Staleness follows the holder's liveness (build domains by process, code domains by owning session); `post-change.ps1` releases exactly the code domains the run holds, before its gate batch and only as the backstop for a run that ended early, owner-checked so it never removes another session's. A build still only warns on a live code lock, never refuses. A pre-split `temp/BUILD.LOCK` or `temp/CODE.LOCK` holds every domain of its type until its owner releases it. The measurements behind each decision: `docs/DEV_OPS.md` "Rule 23 history".
- Agent chat (CLAUDE.md Rule 34, S2372): the descriptive layer beside the locks - `temp/AGENT-CHAT/progress/` (what a session is doing, 180 min of life) and `temp/AGENT-CHAT/findings/` (a measurement or an environment state, dead the moment anything in its declared scope changes, its TTL passes or its device leaves `adb devices`). The coordination scripts, `update.ps1`, `post-change.ps1`, the fast checks and the device probe write it on their own; the model owes three lines through `scripts/utils/agent-chat.ps1 -Verb Post` - a phase start, a stage boundary, giving work up (`-Kind abandon`). It is printed at a refusal (`enter-code-lock.ps1` exit 4, `ticket-lease.ps1` exit 3), in `spec-next-preflight.ps1`'s `leased_ids[].last_chat` and in the monitor; `-Verb Read|Find|Status` is the explicit look. Trust rule: the chat decides nothing - no acquisition branches on it and no spec or gate verdict rests on another agent's finding; a finding spares you repeating cheap idempotent work, never the report. Identity is `scripts/utils/agent-identity.ps1` (`FMS_AGENT_ID`, then `CLAUDE_CODE_SESSION_ID`, then the ancestor host process `host-<name>-<pid>-<startTicks>`, then `pid-<PID>`), never empty, and every agent speaks under a nickname `<adjective>-<animal>-<MMdd>-<HHmm>` taken once per session on its first identity resolution and kept under `temp/AGENT-CHAT/names/` (`FMS_AGENT_NAME` overrides; `-Verb Whoami` tells you yours) - the owner reads names, scripts compare ids. **If you have no hooks, set `FMS_AGENT_ID` first** (section 9.1) and post `-Kind session` yourself at start and end.
- Detekt-clean-first: author touched `.kt` to pass detekt on the first build - log/probe lines `<=120` chars, no bare numeric literals (`TimeUnit`/companion `const`/reuse a const), never `@Suppress` a method with a baselined finding (shifts baseline). CLAUDE.md Rule 19.
- Background/foreground - the 120 s threshold (CLAUDE.md Rule 6): the two-sided rule is canon (`rules/AI_USAGE.md` section 1); this repo pins the boundary to the Bash tool's own foreground timeout. **Above it, background**: `a.ps1 d/db/dav/cd/nd/nl/r/fu`. **Below it, do not**: `fk/fkn/fc/fr/dq` and `assert-detekt` run 14-21 s on a warm daemon, `fg` runs 32 s (S2451, 2026-09-03, 45 gates concurrent), and the wear targets `fw/fwr/fwu` run 2 s / 1 s / 11 s (S1807) - wait and read the verdict in the same turn. Enforced by Rule 26.
- PowerShell: `-NoProfile`, one-process batching, and the fresh-interpreter-per-call model have one home, canon `rules/GITHUB_INTERACTION.md` section 6. Repo specifics: write `$` literally, and prefer the project wrappers over hand-rolled invocations.
- PowerShell exit codes (S1070): under `$ErrorActionPreference = 'Stop'` a bare `Write-Error` throws and the `exit N` after it never runs, so the code collapses to 1 while the message still prints. Use `Write-Error $msg -ErrorAction Continue` before `exit N` (N != 1); a header must list the codes actually returned. Gate: `scripts/quality/assert-exit-contract.ps1`.
- Subagent MCP isolation: When defining a subagent, always give it an explicit `tools:` frontmatter allowlist that omits every MCP tool name, unless the subagent strictly requires driving the UI/emulator (exploratory walkthroughs) - omitting `tools:` entirely grants the full set the parent session has, MCP-registered tools included. This prevents duplicate Node/MCP server instances. (S1348: `enable_mcp_tools` is not a real Claude Code option - do not use it.)
- Compose boundary (CLAUDE.md Rule 32, S1694): `app_v2` is View + XML + ViewBinding, `wear` is Compose. A new `setContent { .. }` under `app_v2/src/main` is refused by the `compose-island` dimension of `scripts/quality/assert-source-gates.ps1` (baseline `scripts/quality/compose-island-baseline.txt`, currently 6). The six existing islands leave opportunistically, never as a campaign, and each removal lowers the baseline. The gate judges `app_v2/src/main` only - Compose in the watch module is untouched. Dropping the Compose dependencies needs the three extended-set media icons migrated to vector drawables first (S0385).
- Gate placement (CLAUDE.md Rule 33, S1939): a gate whose subject is the whole tree or a shipped artifact runs once over the release scope (`scripts/quality/assert-release-scope-gates.ps1`, step 0.4 of `/spec-prerelease`), not on every changed file - applied per file it cannot attribute its finding and degrades into noise or into an advisory nobody acts on. It stays per-ticket when later work builds on the defect, when the evidence exists only at the moment of the change, or when agents read the artifact between releases. A relocation must be a script with an exit code, never a line of prose in a command file.
- Subagent model routing policy (CLAUDE.md Rule 31, S1786): Built-in `general-purpose` defaults to Opus when unpinned (182 spawns in telemetry wasted expensive tokens). Mechanical, search, doc, and lookup subagent tasks must explicitly specify a lightweight model tier (`model: sonnet` or `flash`), or use pre-pinned agents (`android-solution-researcher` / `repo-mechanic` / `friendly-android-doc-writer`), reserving Opus for deep architectural design and Kotlin development (`android-kotlin-developer`).

## 7. Validation
- Follow `CLAUDE.md` validation ladder. Record `expected: X | actual: Y` for every non-trivial step, naming the command run and its exit code (CLAUDE.md Rule 15).
- The evidence rule has one home, canon `rules/DEVELOPMENT.md` section 5 / `rules/INVARIANTS.md` 7. Repo form: record `expected: X | actual: Y`, and treat the red-flag words - "should", "probably", "seems", "looks fixed" - as the signal to stop and run the check first.
- Prefer the cheapest proof that matches the change: `.\a.ps1 fk` for Kotlin symbol edits (`fkn` for noLegal), `.\a.ps1 fr` for resources/manifests, `.\a.ps1 fc` for mixed small changes, `.\a.ps1 fg` to batch the fast static gates in one process, and full debug APK builds only when packaging/install behavior matters.
- The resources/manifest rung is enforced mechanically since S1915: the `resource-link-gate` in `post-change.ps1` links the changed resources and fails the closure on an aapt error, choosing the variant from the touched source set. `fk` never links resources, so before that gate a broken layout closed green and the ticket went to `BlockNeedUserTest` without the installable ever having been built (S1881). Running `fr` yourself first is still the cheaper loop - the gate is the backstop, not the workflow.
- Pick the target by module before change type (CLAUDE.md Rule 9, S1807): `fk`/`fkn`/`fr`/`fc`/`fu` all check `app_v2`. A change under `wear/` is proved by `.\a.ps1 fw` (Kotlin), `.\a.ps1 fwr` (resources/manifest) or `.\a.ps1 fwu` (unit suite) - the phone target exits 0 without compiling a watch file, so its green is a verdict about the other module. Each check prints the module it checked in its banner.

## 8. Code Audit Protocol
- Full protocol: `docs/CODE_AUDIT_PROTOCOL.md`. Apply it on any **audit trigger**: new screen/manager/worker/repository/long-lived helper; lifecycle/coroutine/Flow/listener/observer change; shared-state/dispatcher change; Room entity/DAO/query/migration/transaction change; player/image/cache/network change; startup change; DI scope/singleton change; build/manifest/R8/keep-rule change affecting profiling/startup/minification; reported crash/ANR/OOM/jank/leak; **phase boundary in a multi-phase task** - audit the phase just finished before starting the next.
- Phase-boundary audits are mandatory, not deferred to pipeline end: a defect costs one phase's rework when caught at the next boundary, versus every later phase's rework when it surfaces only at the final audit. `/spec-dev` runs it automatically per phase; apply the same discipline for multi-phase work driven outside `/spec-dev`.
- Tag every finding by severity P0-P3 (P0 crash/leak/data-loss blocks release; P1 race / main-thread I/O / unbounded cache / unreleased resource; P2 hot-path churn / over-eager startup; P3 readability/style). P0/P1 need evidence, not opinion.
- Listener symmetry: every `register*`/`addListener`/`addObserver` has a matching removal on the symmetric lifecycle edge.
- No main-thread Room (`allowMainThreadQueries()` banned); DAO `suspend`/`Flow`; atomic multi-step writes in `@Transaction`/`withTransaction`.
- One owner per `ExoPlayer` with a full release contract (`release()` + `setVideoSurface(null)` + remove listeners + abandon focus); mirror across player hosts. Glide decode-at-size + `clear(target)` on detach.
- Reflection/serialization/DI/manifest/dependency changes are proven on the minified release/target variant, not only debug - which extends dead-weight hygiene (CLAUDE.md Rule 20): orphaned classes, resources, string keys and keep rules are deleted in the same change that orphans them.

## 9. Non-Claude Runtimes (Codex, Gemini, Copilot, ZCode)

The rules above were written for a runtime that enforces part of them mechanically. Outside Claude Code that half is missing, and nothing announces its absence - so this section states what you now owe by hand.

### 9.1 What does not run for you

- **Hooks.** `.claude/hooks/*.ps1` plus per-machine global hooks refuse, rewrite or annotate Claude Code's tool calls; the complete inventory is `docs/AGENT_HOOKS.md`. None of them sees your calls. Every rule below is therefore self-enforced, and each one is here because an agent already got it wrong: `pwsh -NoProfile -File ./a.ps1 <cmd>` never a bare `./a.ps1` (a `.ps1` run as a Bash command head fails with **exit 0**, so a red build reads as green); `find` only with a concrete start path **and** `-maxdepth N`; no PowerShell cmdlet, no `& { .. }` batch idiom and no `node`/`npm`/`npx` inside Bash; under Git Bash on Windows a leading-slash argument value like `-Reason "/spec-dev .."` is silently rewritten to `C:/Program Files/Git/spec-dev ..`, so double it (`"//spec-dev .."`) or pass it from PowerShell; query `dev/CATALOG/scripts/query.ps1` before grepping `.kt`; read a long file in windows rather than whole; try `/quick` and `/skill-fix` before reaching for a spec pipeline.
- **The command library.** Claude Code injects `.claude/commands/<name>.md` when you type `/name`. Nothing injects it for you - open the file (§5).
- **Subagents.** `.claude/agents/*.md` describe six roles Claude Code can spawn in parallel (device operator, Kotlin developer, R&D specialist, solution researcher, doc writer, repo mechanic). You have no such fan-out: do the work inline, in one context, and keep whatever constraints that role's file states - notably that the researcher and the device operator never edit product code.
- **Agent memory.** `.claude/agent-memory/android-rd-specialist/MEMORY.md` is an index of hard-won project facts that Claude Code always has in context. Read it at session start when the task touches builds, flavors, gates, devices or release; each line points at a file in the same directory. ZCode ships the same index as a workspace skill, `android-rd-specialist-memory` (`.agents/skills/android-rd-specialist-memory/SKILL.md`), pointing at the `.agents/MEMORY.md` mirror and its feedback files.
- **The skill loop.** The mandatory document-registry loop is a Claude Code skill at `.claude/skills/document-registry/SKILL.md`. Read that file and run its four steps yourself: identify area and trigger, query `scripts/document_registry/query.ps1`, read every returned record, state which are affected.
- **Your identity, and it is the first thing you set.** Set `FMS_AGENT_ID` once, to one value you keep for your whole session, before you run anything else - then `FMS_AGENT_RUNTIME` and `FMS_AGENT_MODEL` so the lines name you (CLAUDE.md Rule 34). This bullet used to list only the last two, and a runtime did exactly what was written: measured over one hour on 2026-09-02, a single session wrote itself as 46 different agents with 46 different nicknames, because without an id the chain fell through to the pid of a shell that lives for one command. Its lease read as dead from its first minute and a sibling took the ticket; every release it made was forced. **If you cannot set it**, S2408 gives you a floor rather than that: the chain climbs your process's ancestors past shells and interpreters to the first process that outlives a command, and names you `host-<name>-<pid>-<startTicks>` - stable for as long as your host runs, so your own commands agree with each other. Where that climb runs into a machine-wide process such as `explorer`, it takes the ancestor standing directly below it rather than giving up (S2417); only a climb that finds no ancestor at all leaves you on `pid-<PID>`, and `-Verb Whoami` prints which of the two happened in the `hostWalk` field. What it cannot do is tell two of your chats apart inside one host process; they share one identity, which is why setting the variable is still yours to do. `FMS_AGENT_HOST_WALK=0` turns the walk off if the merge harms you. `scripts/utils/agent-chat.ps1 -Verb Whoami` prints what you currently resolve to - run it once at the start and you will see which of the four you got.
- **The agent chat.** Claude Code's session hooks announce a session's start and end to `temp/AGENT-CHAT/`; nothing announces yours. Post them yourself - `pwsh -NoProfile -File scripts/utils/agent-chat.ps1 -Verb Post -Kind session -Note "session started (<your runtime>)"` at the start and `-Note "session ended (<reason>)"` at the end. That first post also takes your nickname - `<adjective>-<animal>-<MMdd>-<HHmm>`, kept for the session under `temp/AGENT-CHAT/names/` - and every later line of yours carries it; `-Verb Whoami` prints it, `FMS_AGENT_NAME` sets one of your choosing. The scripts post everything else for you, and every refusal you meet (`enter-code-lock.ps1` exit 4, `ticket-lease.ps1` exit 3) already prints the holder's last lines; `.\a.ps1 chat -Verb Status` is the explicit look, and `-Verb Find -Topic "device:*"` or `"gates:release-scope"` tells you whether a finding holds for the tree or device you see, while `-Query <bare word>` searches findings by keyword.

### 9.2 The development artifacts, and the script that owns each

Never hand-edit a generated or script-owned file; the CLI is the only supported writer.

- Tickets: `PLAN/Sxxxx_<slug>.md` + journal `PLAN/spec-catalog.jsonl`, owned by `scripts/spec_catalog/*.ps1` (`select`, `search`, `next-id`, `insert`, `update`, `close-and-log`, `archive`).
- What to work on next: `PLAN/RELEASE_QUEUE.md` (work left) and `PLAN/RELEASE_READY.md` (finished content), ranked by `spec-next-preflight.ps1` / `release-plan.ps1`.
- Kotlin class index: `dev/CATALOG/<module>.jsonl|.md`, regenerated by `scripts/catalog_sync.ps1 -Module <app_v2|wear>`, queried by `dev/CATALOG/scripts/query.ps1`. Local and gitignored - regenerate, never commit.
- Maintained documents and public pages: `docs/DOCUMENT_REGISTRY.jsonl` with `scripts/document_registry/{query,validate,generate}.ps1`; `docs/DOCS_MAP.md` and `sitemap.xml` are its render targets.
- Shipped capabilities: `docs/ALL_FEATURES.jsonl` via `scripts/all_features/add.ps1`. The public showcase `docs/FEATURES*.md` is written only by the release pipeline.
- Change journal: `dev/CHANGELOG.md`, written only by `scripts/add_to_dev_log.ps1`, one entry per logical change.
- UI strings: `scripts/utils/set-android-string.ps1` (byte-preserving), then `scripts/check_strings_localized.ps1`.
- Closure facade that chains all of the above plus the gates: `scripts/post-change.ps1 -File <p> -Target <t> -Description <d> -ChangeType <Doc|Script|Config|Tooling|Kotlin|Xml|Mixed>`; on this always-dirty tree add `-Files "a,b"` `-ScopeToFile`. Exit 0 passed, 1 a gate failed, 2 could not verify.
- Gates: `scripts/quality/assert-*.ps1`, batched by `pwsh -NoProfile -File ./a.ps1 fg`.
- Builds and checks: `./a.ps1` targets (§7). Locks before them: `scripts/utils/{enter-code-lock,agent-lock,wait-for-lock-turn,lock-status}.ps1` (§6).
- Device work without tokens: `scripts/devtest/adb.ps1 <verb>`.

### 9.3 Session kickoff

Paste this at the start of a Codex, Gemini or ZCode session, or when the runtime has been reset:

```text
Read, in this order, before doing anything: AGENTS.md (all of it, section 9 included), CLAUDE.md,
dev/PROJECT_OPERATIONS_INDEX.md. You have no hooks, no slash commands and no subagents: a pipeline
named /name is the file .claude/commands/<name>.md and you must read it in full before its first step.
Run every PowerShell script as `pwsh -NoProfile -File <path>` and read its exit code before claiming
anything. Chat with me in Russian; write files, code, comments and commit messages in English.
Then tell me which ticket PLAN/RELEASE_QUEUE.md puts first, and stop.
```

The closing instruction is deliberate: it ends in a cheap, checkable answer, so a runtime that skipped the reading is visible immediately.
