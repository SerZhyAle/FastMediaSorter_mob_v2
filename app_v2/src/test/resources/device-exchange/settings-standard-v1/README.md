# Conformance vectors - application settings standard

DEVICE-EXCHANGE 1.12, items EN to ER ([`../../SETTINGS-STANDARD-2026-11-12.md`](../../SETTINGS-STANDARD-2026-11-12.md)).
Seven samples of the wire shapes, adopted on 2026-11-12 byte for byte from
`../../proposed-vectors/app-settings-exchange-2026-11-10/`, which stays as the record of the proposal. They are
rung 1 evidence of shape (section 11): written by the canon session, not generated by an implementation.

| File | What it shows |
| --- | --- |
| `01-save-standard-request.json` | A valid `settings_save_standard` for `appId` `fms_win`, `formatVersion` 1. |
| `02-save-standard-response.json` | The server's `settings_saved`, `version` 1. |
| `03-get-standard-request.json` | `settings_get_standard`. |
| `04-get-standard-payload-response.json` | `settings_standard_payload` carrying the stored payload and `updatedAt`. |
| `05-refused-not-found.json` | `refused` `not-found`: nothing is stored for the pair. |
| `06-refused-incompatible.json` | `refused` `version-incompatible`: a `formatVersion` the server does not implement. |
| `07-local-exclusion-manifest.json` | The common spellings of the mandatory exclusions and the common group ids (item EQ). The group ids are not a closed list. |

Two things the samples do not say, and the amendment does:

- The bound of `settingsPayload` is 65536 bytes (item EO). The sample `refused` messages are diagnostic English; a
  client shows the words of item CZ.
- The cases with no sample (`app-id-mismatch`, `invalid-payload`, isolation, a guest, the version counter, erasure
  with the account, independence after a read) are listed in the amendment's Conformance table.
