# Admitted secret-shaped literals (S3371, security profile).
#
# There is no baseline here on purpose: a count would let a real secret hide behind a number.
# Every exemption is an entry, and every entry states its reason after a hash sign - an entry
# with no reason is refused by scripts/quality/assert-no-secrets.ps1 itself.
#
# Entry kinds:
#   file:<repo-relative path>   the whole file is exempt (it is a detector, a fixture or a doc
#                               that quotes the shapes being detected).
#   literal:<exact value>       that one matched value is exempt, wherever it appears.
#   match:<regex>               any matched value matching this regex is exempt.
#
# Prefer the narrowest kind that works: a `literal:` ages better than a `file:`, because a file
# exemption also covers the secret somebody pastes into that file next year.

file:scripts/quality/assert-no-secrets.ps1 # the detector itself - its regexes spell out the shapes it looks for.
file:scripts/quality/no-secrets-allowlist.txt # this file - it names the kinds and quotes the shapes.
file:scripts/quality.tests/AssertNoSecrets.Tests.ps1 # the contract suite seeds every detector with a synthetic finding.
match:^sha\d{3}- # npm lock-file integrity digests: a published hash of a public tarball, not a credential.
literal:qwkzLSJrJ7adxFYz-95YY-Uhs0yX6QakWxZWFWtN-ks # google-site-verification token - it is published in the page head by design and proves nothing on its own.
file:wear/src/test/resources/golden/wear-payload/payload_sync_v1.json # S3371 golden fixture: the v1 sync payload must carry an sshPrivateKey field to prove the reader still accepts it, and the value is a stub whose base64 body decodes to the word openssh.
