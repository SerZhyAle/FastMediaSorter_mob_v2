# Registry of scripts that WRITE a path owned by a Code.* lock domain (S2635).
#
# Why this file exists. A script that rewrites a file the domain table assigns to Code.Phone,
# Code.Wear or Code.Scripts must take that domain first, or two sessions writing the same
# generated artifact are not separated by anything. S2615 built the mechanism
# (scripts/utils/code-lock-scope.ps1) and adopted it in eleven render-target generators; S2635
# adopted the rest and added this registry, because the open question S2615 left behind was how a
# NEW writer is stopped from silently bypassing the domain again. The registry is the answer's
# first half; scripts/quality/assert-code-domain-writers.ps1 is the second.
#
# Format, one record per line:   <repo-relative script path> | <class> | <domain(s)> | <what it writes>
#
# CLASS is the distinction S2635 measured, and it decides what a busy domain costs:
#   A  writes from INSIDE the concurrent .\a.ps1 fg battery, on a branch whose verdict is already
#      computed. Takes the domain LAZILY at the write and uses Enter-CodeLockOrSkip, so a busy
#      domain skips the bookkeeping and keeps the verdict. Skipping costs one run of staleness.
#   B  writes on an explicit switch, run by hand in the foreground. Uses Enter-CodeLockOrExit, so
#      a busy domain is exit 4. Skipping here would be work left undone.
#
# The test that assigns the class: if NOT writing is work left undone -> B; if not writing costs
# only staleness a later run repairs -> A.
#
# Adding a writer? Add the line AND the lock, in the same change. The gate checks both.
