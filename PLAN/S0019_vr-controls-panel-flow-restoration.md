## 1. Проблема

Ключевой пользовательский сценарий VR-флейвора сломан: «открыть стерео-видео на плоской панели → настроить стерео-формат / проекцию → применить → перейти в иммерсив 3D». Из иммерсивного режима нет видимой кнопки, открывающей диалог настройки видео — оверлей предлагает только команду «выйти». Команда «выйти» при этом возвращает пользователя в файловый браузер, а не на промежуточную панель управления, обещанную текстом самой команды. Отдельной активити «панель управления стерео» в коде нет: возврат всегда идёт в основной экран приложения. Эффект: пользователь не может изменить стерео-формат текущего файла, не выходя обратно в браузер и не запуская плеер заново.

---

## 2. Цели

1. **Иммерсивный playback HUD.** В иммерсивном просмотре по команде «открыть управление» появляется полупрозрачный (~20%) интерактивный слой поверх сцены, содержащий полный набор playback-команд из плоского плеера: seekbar, play/pause, prev/next, скорость, аудио-дорожки, субтитры, яркость, HUE, операции над файлом, настройки стерео-формата. Пользователь не покидает иммерсив для управления.
2. **Prev/Next без выхода.** В этом же HUD кнопки «предыдущий/следующий файл» переключают файл внутри текущего ресурса (как для видео, так и для фото) **без выхода из иммерсива** — XR-сессия остаётся живой, меняется только воспроизводимый файл.
3. **Команда «выйти в панель» возвращает в плоский плеер**, открытый на том же файле и на той же позиции воспроизведения, а не в файловый браузер. Текст команды совпадает с фактическим назначением.
4. **Команда «вернуться в браузер» — отдельное явное действие** из иммерсивного HUD и из плоской панели.
5. **Сценарий «настроить → применить → 3D» без лишних кликов.** На плоском плеере диалог управления видео имеет: (а) кнопку «применить» (закрывает диалог, новые настройки вступят при следующем входе в иммерсив), (б) кнопку «применить и перейти в 3D» — одним нажатием закрывает диалог + переключает в иммерсив с новыми настройками.
6. **Контекст файла переживает переходы.** Файл, позиция, выбранный стерео-формат и проекция передаются через intent-extras + in-memory состояние без записи на диск; не пересоздавать XR-сессию, если контекст не сменился.

**Non-goals:**

- Не вводится новых стерео-форматов или новых режимов рендера.
- Не меняется логика автоматического определения формата.
- Не меняется логика отключения авто-иммерсива (это объём S0018).
- Не вводится поддержка одновременной работы нескольких VR-плееров.
- Не покрывается восстановление работоспособности самой иммерсивной интерактивной панели на уровне свопчейна (это объём S0020).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. **HUD-оверлей в иммерсиве — основной путь, не fallback.** Полупрозрачный (~20%) слой с полным playback UI должен работать как primary interaction для управления внутри иммерсива; никакого «выкидывания в плоское и обратно». Эталон — лучшие сторонние VR-стереоплееры.
2. **Не плодить новые активити.** Плоская «панель текущего воспроизведения» — это существующий `PlayerActivity` (с уже имеющимися кнопкой «перейти в 3Д» и закладкой 3DVR в диалоге управления). Никаких новых отдельных экранов.
3. **Тексты команд = пункт назначения.** Никаких «выйти в панель», если де-факто ведёт в браузер.
4. **Кнопки prev/next в иммерсиве** — обязательны для перебора файлов ресурса без снятия шлема. Действуют для видео и фото одинаково.
5. **Дополнительная кнопка «применить и перейти в 3D»** в диалоге управления плоского плеера — комбинированное действие одним кликом.
6. Применённые изменения формата запоминаются на сессию текущего файла без записи в глобальные настройки приложения.

### 3.2 Жёсткие ограничения

- **Flavor:** только VR-флейвор. Прочие сборки не имеют этого сценария.
- **API level:** без новых API-зависимостей; минимум проекта сохраняется.
- **Wear OS:** не затрагивается.
- **Производительность:** переходы между иммерсивом и панелью не должны добавлять заметной задержки сверх существующего «холодного старта» XR-сессии; повторный вход в иммерсив не должен пересоздавать XR-сессию, если контекст файла не сменился.
- **HUD-параметры (наследуются от S0009 §6 #4):** head-locked размещение, ~1.0 м ширина × 0.3 м высота на дистанции 1.5 м, угловое смещение вниз ~20°, прозрачность фона ~20%. Изменения этих параметров в S0019 не предусмотрены; дальнейшая подстройка ±30% возможна без архитектурного пересмотра.
- **Совместимость данных:** настройки формата для конкретного файла могут использовать существующее хранилище предпочтений; миграция базы не требуется.
- **Локализация:** EN/RU/UK обязательны для всех новых и переименованных строк команд.
- **Доступность:** команды иммерсивного оверлея должны быть достижимы контроллером (touch-controller) и иметь читаемый ярлык; различимость по форме/иконке, не только по цвету.

## 4. Контекст текущей архитектуры

VR-флейвор имеет одну активити, отвечающую за иммерсивный просмотр, и одну активити, отвечающую за файловый браузер. «Панели управления» как отдельной сущности не существует: команда выхода из иммерсива всегда возвращает на корневой экран приложения. Существующий 2D-диалог управления стерео-форматом доступен из стандартного плеера, но из иммерсивного контекста к нему нет точки доступа. Технически в иммерсиве есть слой «интерактивной панели» поверх сцены, но он сейчас не работоспособен из-за гонки инициализации (объём S0020) — поэтому полагаться только на него для решения этой задачи нельзя.

## 5. Предлагаемый подход

Подход состоит из четырёх логических блоков: иммерсивный HUD, навигация без выхода, плоская панель = существующий плеер, последовательность переходов с сохранением контекста.

### 5.1 Основные столпы / модули

**Иммерсивный playback HUD (главный новый компонент).**
Полупрозрачный (~20%) интерактивный слой поверх иммерсивной сцены. Содержание идентично плоскому плееру: seekbar текущего файла, play/pause, prev/next, скорость, выбор аудио-дорожки/субтитров, яркость, HUE, операции над файлом (delete/move/copy/share/info), плюс закладка стерео-формата и проекции. Открывается по команде «показать управление» (одним нажатием контроллера), закрывается тем же путём. Источник содержимого — тот же диалог управления, что в плоском плеере; различается только контейнер отрисовки.

**Историческая связь с S0009.** S0009 (`spec_vr-immersive-hud-gl`, Partial) построила HUD-канвас как **пассивный индикатор** (§2 цели 1-4 S0009, явный Non-goal: «Интерактивный HUD — это уже решается подсистемой hand-tracking»). S0009 §10 сама обозначила follow-up «spec_vr-ui-composition-layer» именно для полноценного UI с интерактивностью. **S0019 и есть эта анонсированная spec B.** Параметры размещения HUD-слоя (head-locked, ~1.0×0.3 м на дистанции 1.5 м, угол ~20° вниз) наследуются от S0009 §6 #4. Новое в S0019 относительно S0009 — переход от passive-indicator к interactive controls (ray-clicks по seekbar/кнопкам/закладкам), полное наполнение playback UI и стерео-настройки. Подсистема ray-input для кликов по HUD — отдельная зависимость (см. §10, риск нарушения non-goal S0009).

**Навигация prev/next внутри иммерсива.**
Кнопки prev/next в HUD действуют без выхода из иммерсива: переключают файл внутри текущего ресурса, переинициализируя только источник видео/фото без пересоздания XR-сессии. Для фото меняется текстура; для видео — пересоздаётся ExoPlayer-источник, но не XR-сессия. Эта навигация одинакова для всех типов VR-медиа.

**«Панель текущего воспроизведения» = существующий плоский плеер.**
Команда «выйти в панель» открывает обычный `PlayerActivity` на том же файле и той же позиции — без стерео-эффекта (плоский режим). У этого плеера уже есть в верхнем меню кнопка «перейти в 3Д» и закладка 3DVR в диалоге управления видео; их используем как канонический путь. К существующему диалогу добавляется кнопка-партнёр «применить и в 3D» рядом с «применить»: одним нажатием применяет настройки + переключает в иммерсив.

**Согласование текстов команд.**
В HUD, в плеере и в браузере «выйти» без уточнения запрещено: «выйти в панель», «выйти в браузер», «показать управление», «применить», «применить и в 3D». Тексты EN/RU/UK строго соответствуют пункту назначения.

**Сохранение контекста между переходами.**
Файл, позиция, выбранный стерео-формат, проекция, индекс в списке — передаются через intent-extras при запуске активити + дублируются в общий in-memory объект состояния плеера. Никакого DataStore или иной диск-персистенции в этой спеке. Если контекст идентичен (тот же файл и формат) — повторный вход в иммерсив переиспользует XR-сессию.

### 5.2 Потоки данных и событий

Иммерсив → нажатие на «показать управление» → HUD-оверлей виден → пользователь редактирует stream/format/file-ops → нажатие «закрыть» → HUD прячется, изменения применены немедленно (там где это технически возможно: pause, скорость, prev/next, аудио-дорожка) или при следующем эпизоде (формат стерео).
Иммерсив → «выйти в панель» → плоский PlayerActivity на том же файле/позиции (in-memory + intent-extras).
Плоский плеер → диалог управления → «применить» (закрыть) или «применить и в 3D» (закрыть + immediate switch to immersive).
Плоский плеер → «вернуться в браузер» → корневой экран.
Иммерсив → prev/next → следующий/предыдущий файл ресурса в этом же иммерсиве, XR-сессия живёт.

### 5.3 Точки расширяемости

- Каталог команд иммерсивного HUD — единое место добавления новых пунктов.
- HUD как контейнер должен принимать произвольное наполнение из набора существующих диалоговых закладок (стерео-формат, аудио, субтитры, яркость, HUE), без жёсткого захардкоженного списка.
- Логика prev/next в иммерсиве должна работать с любым типом медиа в ресурсе (новые типы добавляются без правок навигации).

## 6. Закрытые решения (бывшие Open research items)

Все 5 вопросов решены владельцем 2026-04-28 в том же файле. Решения зафиксированы здесь как канонические и отражены в §2/§3.1/§5/§9/§11.

1. **Что показывать после команды «выйти в панель» — RESOLVED.**
   Решение: **существующий плоский плеер** (`PlayerActivity`), открытый на тех же ресурсе/файле/позиции, что были в иммерсиве. Никакого нового экрана. У плоского плеера уже есть команда «перейти в 3Д» и диалог управления видео с закладкой 3DVR — этот диалог становится точкой настройки стерео-формата на панели. Превью на 2D отображается БЕЗ стерео-эффекта (как обычное плоское видео); новые настройки формата применяются только при следующем входе в иммерсив.

2. **Где открывается управление в иммерсиве — RESOLVED. Существенный scope-shift.**
   Решение: **полупрозрачный иммерсивный HUD-оверлей (~20% прозрачности) поверх сцены, содержащий ВЕСЬ playback UI плоского плеера** — seekbar, play/pause, prev/next, скорость, выбор аудио-дорожки/субтитров, яркость, HUE, операции над файлом, плюс настройки стереоскопии. По модели лучших VR-стереоплееров. Двухуровневого fallback нет: S0020 закрыла отрисовку UI поверх сцены как надёжный механизм. Команда «открыть управление» вызывает именно этот HUD; «выйти в плоскую панель» — отдельная команда.

3. **Хранение контекста между переходами — RESOLVED.**
   Решение: **в памяти приложения + параметры команды перехода**. Никакого диска, никакого DataStore, никакого `ResumeStateRepository` в этой спеке. Параметров мало (файл, позиция, формат, проекция, индекс в списке) — обычные intent-extras + общий in-memory объект состояния плеера достаточны.

4. **Семантика «применить» — RESOLVED + новая кнопка.**
   Решение: «применить» на плоской панели НЕ перерисовывает превью (плоский плеер не показывает стереоскопию — нет смысла). РЯДОМ с «применить» добавляется **новая кнопка «применить и перейти в 3D»**: одним нажатием закрывает диалог, переключает на иммерсив и применяет новые настройки. Это закрывает раздражающий двухкликовый сценарий «применить → потом нажать ещё одну кнопку чтобы войти в 3D».

5. **VR-фото — RESOLVED. Симметрично + важное дополнение.**
   Решение: **единый сценарий с видео; для фото в HUD скрыть видео-специфичные элементы** (seekbar, перемотка, пауза, громкость). Дополнительное требование, выделенное владельцем: **в иммерсиве должны быть видны кнопки prev/next для переключения файла внутри текущего ресурса БЕЗ выхода из иммерсива** — и это требование действует одинаково для видео и фото.

## 9. Архитектурные решения (ADR)

**ADR-1: Командная пара «выйти в панель» и «выйти в браузер» вместо одной общей «выйти».**

- **Решение:** иммерсивный оверлей и любая иная точка имеет минимум две раздельные команды выхода: одна возвращает в промежуточную панель текущего воспроизведения, вторая — в файловый браузер. Команды «выйти» без уточнения не существует.
- **Альтернативы:** (а) одна команда «выйти», которая по контексту решает, куда вести — отвергнуто, потому что именно эта неоднозначность породила текущий баг; (б) кнопка «выйти» с диалогом «куда выйти?» — отвергнуто как лишний клик в самом частом сценарии.
- **Почему:** пользователь должен видеть назначение действия до его совершения; консистентность текста команды и реального поведения — гигиена UX.

**ADR-2: «Панель текущего воспроизведения» — отдельный режим, а не файловый браузер.**

- **Решение:** возврат из иммерсива в «панель» направляется в специально выделенный режим, содержащий контекст текущего файла, его 2D-превью и набор команд управления. Файловый браузер достижим только из этого режима (или напрямую из иммерсива по отдельной команде).
- **Альтернативы:** (а) показывать управление прямо в файловом браузере (существующее положение) — отвергнуто как нарушающее ожидание пользователя; (б) встроить управление в нижний бар браузера — отвергнуто из-за конфликта с навигацией.
- **Почему:** разделение ответственности: «выбор файла» и «управление текущим файлом» — разные задачи с разной плотностью команд.

**ADR-3: Иммерсивный HUD-оверлей — единственный путь управления внутри иммерсива.**

- **Решение:** управление в иммерсиве (включая stream-команды и настройки стерео) выполняется через полупрозрачный HUD-слой поверх сцены. Двухуровневого fallback в плоский режим нет: S0020 закрыла надёжность отрисовки UI поверх сцены, дополнительный путь избыточен.
- **Альтернативы:** (а) ранее рассматривался двухуровневый fallback — отвергнуто решением владельца 2026-04-28: «не выталкивать пользователя в плоское и обратно — это нарушает опыт и отнимает время»; (б) двусмысленная команда «открыть диалог где придётся» — отвергнуто как UX-неопределённость.
- **Почему:** иммерсивный сценарий должен быть бесшовным; пользователь не должен снимать шлем для рутинных операций (pause, скорость, переключение файла, смена формата).

**ADR-4: Кнопка-партнёр «применить и в 3D» вместо двухкликового сценария.**

- **Решение:** в диалоге управления плоского плеера рядом с «применить» появляется отдельная кнопка «применить и в 3D», выполняющая комбинированное действие: закрыть диалог + переключить в иммерсив + применить настройки.
- **Альтернативы:** (а) одна кнопка «применить», после неё пользователь сам жмёт «перейти в 3Д» — отвергнуто, повторяет частый сценарий двумя кликами; (б) автоматический переход в 3D после «применить» — отвергнуто, нарушает ожидание «применить = просто сохранить выбор».
- **Почему:** комбинированная кнопка убирает один лишний клик в самой частой последовательности «изменил формат → пошёл смотреть».

**ADR-5: Prev/Next без выхода из иммерсива.**

- **Решение:** в иммерсивном HUD кнопки prev/next переключают файл текущего ресурса без пересоздания XR-сессии. Меняется только источник видео/фото внутри уже работающей сцены.
- **Альтернативы:** (а) prev/next через выход в плоскую панель — отвергнуто как навязанное снятие шлема; (б) prev/next без визуальных кнопок (только контроллер-shortcut) — отвергнуто как непрозрачное взаимодействие.
- **Почему:** просмотр VR-фото/видео-альбома — частый кейс; снимать шлем для перехода к следующему файлу разрушает сценарий.

## 10. Связи с другими спеками

- **S0009** (Partial) — `spec_vr-immersive-hud-gl`. **S0019 является той самой «spec B», которую S0009 §10 явно анонсировала** как follow-up «spec_vr-ui-composition-layer» для произвольной Android view-иерархии в иммерсиве. S0009 владеет HUD-канвасом и passive-indicator слоем; S0019 расширяет его до interactive controls с полным playback UI и стерео-настройками. После приземления S0019 транзитивный guard Y-кнопки из S0009 ADR-3 («File ops доступны после выхода из immersive») становится obsolete — см. Proposed Structural Changes P-1 ниже.
- **S0020** (Verified) — `spec_bugfix-vr-panel-swapchain-session-race`. Закрытая зависимость: HUD-оверлей опирается на работающий рендер UI поверх сцены, который S0020 восстановила. Двухуровневый fallback (присутствовавший в ранней редакции этой спеки) больше не нужен — см. ADR-3.
- **S0008** (Partial) — `spec_vr-immersive-controls-panel`. Историческая работа по интерактивной панели. Текущая спека её существенно расширяет (полный playback UI вместо одного диалога настройки) — формально не блокируется, но согласовать терминологию обязательно.
- **S0010** (Archived) — `spec_vr-panel-swapchain-availability`. Архивная; преемник — S0020.
- **S0018** (Verified) — `spec_bugfix-vr-auto-immersive-route-broken`. При выключенном авто-иммерсиве файл сразу попадает на плоский плеер вместо иммерсива; согласовать поведение точек входа в иммерсив (HUD появляется только в реально начатом иммерсивном просмотре).
- **S0006** (Draft) — `spec_vr-fps-counter`. S0009 уже владеет HUD-канвасом и FPS-метрика рисуется в нём как обычный passive indicator; S0019 не меняет это место — FPS остаётся одним из элементов HUD. Координировать только при добавлении новых FPS-параметров.

## 11. Критерии готовности (strategic-level)

1. **HUD-оверлей виден в иммерсиве** по команде «показать управление»; имеет полупрозрачный фон ~20%; содержит seekbar, play/pause, prev/next, скорость, аудио-дорожки, субтитры, яркость, HUE, файловые операции, закладку стерео-формата/проекции.
2. **Prev/next в HUD переключают файл ресурса БЕЗ выхода из иммерсива и без пересоздания XR-сессии** — для видео и для фото; на пять подряд переключений в трёх форматах HUD остаётся работоспособным.
3. **Команда «выйти в панель» из иммерсива** открывает существующий плоский `PlayerActivity` на том же файле и той же позиции; превью показывается без стерео-эффекта; не файловый браузер.
4. **Кнопка «применить и в 3D» в диалоге управления плоского плеера** одним нажатием закрывает диалог, переключает в иммерсив и применяет новые настройки.
5. **Сценарий «выбрать файл в браузере → иммерсив → выйти в панель → сменить формат → вернуться в иммерсив» проходится без повторного выбора файла**, контекст файла сохранён.
6. **Возврат в иммерсив с идентичным контекстом — без перезапуска XR-сессии**; смена формата требует перезапуска с явным лог-маркером.
7. **Все видимые тексты команд EN/RU/UK** строго соответствуют пункту назначения; ручной ревью находит ноль расхождений.
8. **VR-фото проходит сценарий идентично видео**, кроме скрытия видео-специфичных элементов HUD (seekbar, перемотка, скорость, аудио-дорожки, субтитры).

## Proposed Structural Changes

### Proposal P-1 — Update S0009 ADR-3 transitional guard after S0019 lands  (proposed 2026-04-28 by claude-opus-4-7)

**Status:** Proposed
**Affected:** `PLAN/S0009_vr-immersive-hud-gl.md` §9 ADR-3 (locked — Status: Partial)
**Rationale:** S0009 ADR-3 описывает временный guard для Y-кнопки: «открытие файловых операций / диалога управления / шпаргалки в immersive не вызывает Android-панели и не ставит паузу, а показывает HUD-бейдж-подсказку «доступно после выхода из immersive»». Этот guard живёт «до готовности архитектурной спеки B». **S0019 и есть spec B.** После приземления S0019 в иммерсиве доступны все эти панели интерактивно — guard теряет смысл и должен быть удалён, иначе он будет противоречить новому поведению (пользователь увидит «доступно после выхода» когда на самом деле всё доступно прямо здесь).
**Suggested edit:** После приземления S0019 необходимо разблокировать S0009 (через `/spec-fix S0009` → `/spec-check S0009`) и удалить ADR-3 либо пометить его как «обнулён по факту S0019». Также пересмотреть §11 Criterion 3 S0009 («Короткое нажатие Y больше не замораживает плеер»): этот критерий сохраняется — но теперь не через guard-бейдж, а через настоящий HUD-оверлей.

### Proposal P-2 — Resolve interactive-input dependency (S0009 §2 Non-goal #1)  (proposed 2026-04-28 by claude-opus-4-7)

**Status:** Proposed
**Affected:** S0019 §3.1 / §5.1 / новая follow-up спека
**Rationale:** S0009 §2 Non-goal #1: «Интерактивный HUD (клики лучом/рукой, фокус, hover) — это уже решается подсистемой hand-tracking и не относится к данной спеке.» S0019 требует interactivity (ray-clicks по seekbar/кнопкам/закладкам). Сейчас в проекте есть подсистемы для controllers + hand-tracking ввода (S0007), но **нет общего слоя ray-vs-HUD-плоскость пересечения** для plane-quad-слоя HUD. Это либо часть S0019, либо отдельная зависимость S0024+.
**Suggested edit:** На стадии `/spec-tech S0019` принять решение:
- (a) Включить ray-vs-HUD-plane intersection как столп §5.1 в самой S0019 — это расширяет scope ещё на ~1-2 фазы.
- (b) Выделить в новую спеку `S0024 spec_vr-hud-ray-input` (Tier 2-3) и сделать её зависимостью S0019. Эту спеку S0019 объявит как блокер для интерактивности; до её приземления HUD будет показывать только passive-indicator-режим (плюс существующий S0009-функционал).
Решение принимается в начале F2.

### Proposal P-3 — Re-template §6 from "Open research" to "Closed decisions"  (proposed 2026-04-28 by claude-opus-4-7)

**Status:** Proposed
**Affected:** S0019 §6
**Rationale:** Template секции §6 ожидает «Open research items». В S0019 §6 все вопросы закрыты владельцем 2026-04-28, заголовок изменён на «Закрытые решения». Это семантически верно, но отклонение от template создаёт неудобство для автоматических аудитов (ожидающих именно «Open» структуру). Возможны два пути:
- (a) Оставить как есть (название «Закрытые решения») — нарушает template, но содержательно понятнее.
- (b) Восстановить заголовок «Открытые вопросы / Research items», но пометить каждый item как `Status: Resolved` с записью решения.
**Suggested edit:** Принять решение в начале F2 при тактической декомпозиции. По умолчанию — оставить как есть (a), потому что это более читаемо для владельца, а аудиту достаточно проверять отсутствие Open-маркеров.
