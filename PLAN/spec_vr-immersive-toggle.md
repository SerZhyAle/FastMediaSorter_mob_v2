## 1. Проблема

В VR-плеере кнопка переключения между режимами называется «Watch in 3D VR» / «Exit 3D VR». Это название ошибочно сигнализирует, что функция предназначена только для стереоскопического или сферического контента. На практике иммерсивный режим с cinema quad слоем одинаково хорошо работает и для обычного 2D-видео — пользователь смотрит плоское видео в «виде» (void), что само по себе комфортный опыт. Из-за ассоциации «3D» часть пользователей не пробует иммерсив для обычного контента, а тестирование на Meta Quest 3 показало, что пользователь ожидает видеть кнопку переключения режимов для любого видеофайла, вне зависимости от формата.

Дополнительно: кнопка в настоящее время может быть скрыта для 2D-видео (в зависимости от текущей логики видимости в реализации), что усугубляет проблему недоступности переключателя для плоского контента.

---

## 2. Цели

1. Кнопка переключения отображается для **всех** видеофайлов в VR-плеере — включая 2D (плоское MONO), независимо от обнаруженного формата (SBS/OU/equirect/cylinder/плоский).
2. Кнопка называется «В иммерсив» (панель → иммерсив) и «Из иммерсива» (иммерсив → панель) — без привязки к «3D» в названии, чтобы не вводить в заблуждение при плоском контенте.
3. Иконки кнопки остаются функционально различимыми для двух направлений переключения.
4. Поведение маршрутизации для 2D-видео при форсированном переходе в иммерсив не меняется: плоский контент поступает в cinema quad слой с MONO-режимом — ровно так, как это уже реализовано в компоненте принятия решений о маршруте.
5. Строковые ресурсы обновлены на трёх языках (EN/RU/UK).

Non-goals:

- Изменение логики автоматической маршрутизации при первом открытии файла — только при явном нажатии кнопки.
- Добавление кнопки для нон-видео типов (аудио, изображения, PDF) — вне scope.
- Изменение поведения контроллерного ввода (левый стик) — он остаётся как есть.
- Новый визуальный дизайн иконок, если текущие уже функционально различимы.
- Rename функции/класса/метода внутри кода — только пользовательский текст и правило видимости.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Называть режим в интерфейсе «иммерсив» (immersive), а не «3D VR» — это точнее описывает что происходит для любого типа контента.
2. В будущем аналогичное переименование применить к строкам в описании фичи в FEATURES.md, чтобы 2D в иммерсиве было явно упомянуто как поддерживаемый сценарий.

### 3.2 Жёсткие ограничения

- **Flavor:** только VR-сборка (`vr` product flavor). Кнопка переключения скрыта на всех остальных flavors — это не меняется.
- **API level:** без API-специфики; минимальный уровень VR-сборки остаётся прежним.
- **Wear OS:** не затрагивается.
- **Производительность:** нет; изменение чисто UX/строковое.
- **Совместимость данных:** нет.
- **Локализация:** EN/RU/UK — обязательно. Все три файла строковых ресурсов.
- **Доступность:** `contentDescription` кнопки обновляется вместе со строками; формы иконок должны остаться различимыми не только по цвету.

## 4. Контекст текущей архитектуры

В VR-плеере переключатель режимов реализован как отдельный UI-компонент в VR source set: компонент управляет состоянием (иммерсив / панель), иконкой и `contentDescription` кнопки, и делегирует фактический переход маршрутизационной логике через лямбды. Компонент получает обновление состояния после того, как XR-сессия стартует или завершается.

Логика маршрутизации при форсированном переходе в иммерсив уже корректно обрабатывает 2D-контент: плоское видео получает маршрут на cinema quad слой с моноскопическим режимом, без попыток создать ложный SBS-эффект. Это разделение — «компонент UI» и «компонент маршрутизации» — правильное и не нуждается в изменении.

Текущие строки `vr_toggle_enter_description` / `vr_toggle_exit_description` содержат «Watch in 3D VR» / «Exit 3D VR» — именно эти ресурсы требуют обновления. Иконки `ic_vr_3d` / `ic_vr_exit` допустимо оставить как есть, если визуально различимы; при желании — переименовать или заменить.

Правило видимости кнопки (только для `MediaType.VIDEO`) уже включает 2D-файлы, однако необходима верификация на устройстве, что кнопка появляется для плоского MONO-видео на Quest 3.

---

## 5. Предлагаемый подход

Изменение минимально и хирургично: обновить только пользовательский текст и убедиться, что правило видимости не фильтрует 2D-контент.

### 5.1 Основные столпы / модули

1. **Переименование строковых ресурсов.** Заменить содержимое строк переключателя во всех трёх языках. Новый смысл: «Иммерсивный просмотр» / «Панельный режим» — без упоминания «3D».
2. **Верификация правила видимости.** Убедиться, что компонент управления кнопкой показывает её для **любого** `MediaType.VIDEO`, включая файлы без стереоскопических или сферических признаков.
3. **Обновление FEATURES.md.** Перефразировать описание фичи: кнопка доступна для всех видео, а не только 3D/сферических.

### 5.2 Потоки данных и событий

Поток не меняется. Нажатие кнопки → компонент управления переключателем → маршрутизация (панель ↔ иммерсив). Единственное изменение — текст `contentDescription` и строки, которые пользователь читает.

```text
Пользователь видит кнопку [Иммерсив] (показывается для всех видео)
        │
        ▼
Нажатие → компонент переключателя → маршрутизационный компонент
        │
        ├── Плоское 2D видео → cinema quad (MONO) — уже работает
        └── 3D/360 видео → соответствующий XR-слой — без изменений
```

### 5.3 Точки расширяемости

- Если в будущем появится переключатель в HUD (head-locked overlay), те же строки могут быть переиспользованы или форкнуты с тем же смысловым значением «иммерсив».
- Иконки должны оставаться семантически нейтральными («войти в шлем» / «выйти из шлема»), чтобы не нести коннотацию «3D».

## 6. Открытые вопросы / Research items

1. **Кнопка скрыта для 2D на устройстве?**
   - **Вопрос:** Реальная логика видимости в текущей реализации — показывает ли кнопка для плоского MONO-видео на Quest 3?
   - **Варианты:** (а) уже видна — тогда меняем только строки; (б) скрыта — нужна правка правила видимости.
   - **Нужно проверить:** запустить плоский MONO MP4 в VR-плеере, убедиться что кнопка видна на командной панели.
   - **Статус:** Resolved — `CommandPanelController.kt:363` uses `currentFile.type == MediaType.VIDEO`, covers all video including flat MONO. No code change needed.

2. **Достаточно ли текущих иконок?**
   - **Вопрос:** Иконки `ic_vr_3d` и `ic_vr_exit` — содержат ли они «3D»-глиф или другой нейтральный символ?
   - **Нужно проверить:** визуально на устройстве или в превью XML.
   - **Статус:** Resolved — `ic_vr_3d.xml` contained explicit "3D" text indicator paths; replaced with enter-arrow in Phase 01 Step 1.2.

## 8. Влияние на пользователя (docs/FEATURES)

Раздел **VR Edition** в `docs/FEATURES.md` и зеркалах обновляется: кнопку следует описать как переключатель иммерсивного режима для **любого** видео, включая 2D:

> В VR-плеере кнопка «В иммерсив» на командной панели позволяет переключиться между иммерсивным (cinema quad / сферический / стереоскопический) и панельным режимами для любого видеофайла, включая обычное 2D-видео. Позиция воспроизведения сохраняется при переходе.

## 9. Архитектурные решения (ADR)

**ADR-1: Обновляем только строковые ресурсы и правило видимости — не переименовываем внутренние идентификаторы.**

- **Решение:** Пользовательские строки и правило видимости меняются; внутренние идентификаторы (имена полей, классов, методов) остаются без изменений.
- **Альтернативы:** Переименовать всё включая `ic_vr_3d.xml`, `VrToggleButtonManager`, строковые ключи.
- **Почему так:** Рефакторинг внутренних идентификаторов — это отдельная задача, не имеющая ценности для пользователя. Смешивать UI-fix с рефактором значит расширять scope и риск регрессий. Иконку переименовываем или заменяем только если она содержит «3D»-глиф в видимом изображении.

## 11. Критерии готовности (strategic-level)

1. Пользователь видит кнопку «В иммерсив» на командной панели VR-плеера при воспроизведении обычного плоского (2D MONO) видеофайла.
2. При нажатии кнопки плоское видео открывается в иммерсивном cinema quad режиме с сохранением позиции воспроизведения.
3. В иммерсиве кнопка меняет надпись на «Из иммерсива» (или эквивалент) и возвращает в панельный режим с сохранением позиции.
4. На стандартных, lite, photos и legacy сборках кнопка не появляется (изоляция VR flavor не нарушена).
5. Описание фичи в `docs/FEATURES.md` + `_RU` + `_UK` отражает, что переключатель доступен для всех видео, включая 2D.
