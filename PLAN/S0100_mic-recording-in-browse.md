---

## 1. Проблема

Пользователь не может создать аудиозапись прямо в папке, которую сейчас просматривает. Чтобы записать голосовую заметку или черновой аудио-материал, нужно выйти из приложения, открыть сторонний диктофон, а затем вручную перенести файл в нужное место. Это особенно болезненно при работе с сетевыми и облачными ресурсами, куда стандартный диктофон вообще не умеет сохранять. Аналогичная кнопка «камера» в Browse (для фото/видео) уже решила ту же проблему для визуального контента, но для аудио эквивалента нет.

---

## 2. Цели

1. Пользователь может запустить запись с микрофона одним нажатием (удержание кнопки) прямо из Browse, не покидая приложение.
2. Записанный файл автоматически появляется в текущей открытой папке — локальной, SFTP, SMB, FTP или облачной.
3. Имя файла формируется по дате-времени (как у снятия кадра с камеры); при желании пользователь задаёт имя вручную через диалог переименования.
4. Функция отключена по умолчанию и появляется в Browse только после явного включения в настройках.
5. Приложение запрашивает разрешение `RECORD_AUDIO` корректно — в момент первого включения опции или при первом нажатии кнопки, с rationale-диалогом при необходимости.

**Non-goals:**

- Многодорожечная или студийная запись — только однодорожечный моно/стерео WAV/M4A.
- Редактирование или нарезка записанного файла внутри приложения.
- Фоновая запись без открытого Browse.
- Интеграция со Wear OS companion.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Поддержка записи прямо в сетевую (SFTP/SMB) и облачную папку без предварительного скачивания.
2. Среди локальных папок особенно актуальны «смешанные» (Downloads, Audio Library).
3. По аналогии с камерой: настройки должны объединяться в один подраздел в Settings → Audio.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard`, `lite`, `legacy` — везде, где есть поддержка аудио (`SUPPORT_AUDIO=true`). Флейвор `photos` исключён (`SUPPORT_AUDIO=false`).
- **API level:** API 26+ (standard/lite); API 23+ (legacy). Запись с микрофона доступна на обоих диапазонах без дополнительных ограничений.
- **Wear OS:** не затрагивается.
- **Производительность:** запись ведётся в локальный временный файл; передача на сетевой/облачный ресурс происходит после остановки записи, в фоне, с прогресс-индикатором — аналогично camera capture.
- **Совместимость данных:** новые настройки хранятся в существующем хранилище настроек; новая схема Room не требуется.
- **Локализация:** EN/RU/UK — обязательно для всех новых строк UI и диалогов.
- **Доступность:** кнопка микрофона должна иметь content description; touch target ≥ 48 dp; разрешение запрашивается с понятным rationale.

## 4. Контекст текущей архитектуры

Browse является центральным экраном приложения; его командная панель уже содержит кнопку «камера», которая через слой применения инициирует захват медиа внешним приложением и сохранение результата в текущий ресурс. Механизм сохранения файла в ресурс (локальный, сетевой, облачный) является универсальным и уже используется несколькими операциями. Система разрешений приложения обрабатывает runtime-permissions централизованно, с rationale-диалогами и корректной обработкой «отказано навсегда».

Поскольку запись с микрофона ведётся внутри приложения (а не через внешнее приложение-камеру), потребуется собственный слой управления аудиозаписью. При этом его связь с Browse-экраном должна следовать той же схеме делегирования, что и camera capture: кнопка → событие → слой применения → запись/сохранение.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**А. Настройки микрофонных записей (Settings → Audio)**

Новый подраздел «Микрофонные записи» в блоке аудионастроек с двумя опциями:
- *Включить запись с микрофона* (выкл. по умолчанию) — master-переключатель; управляет видимостью кнопки в Browse.
- *Спрашивать имя файла* (вкл. по умолчанию, подчинена master-переключателю) — управляет появлением диалога переименования после записи.

**Б. Кнопка микрофона в Browse**

Отображается в командной панели Browse только при включённом master-переключателе. Поведение: удержание → идёт запись (визуальный индикатор); отпускание → запись завершается; при необходимости (настройка «Спрашивать имя файла») → диалог переименования → сохранение файла в текущую папку. Одиночное нажатие без удержания — отображает короткую подсказку «Удержите для записи».

**В. Подсистема записи**

Внутренний компонент, ответственный за: инициализацию записи с микрофона, управление жизненным циклом (старт/стоп/отмена), буферизацию во временный локальный файл, финализацию (flush, close). Формат выходного файла — M4A/AAC (контейнер совместим с большинством аудиоплееров; MIME `audio/mp4`). Имя по умолчанию: `REC_YYYYMMDD_HHmmss.m4a`.

**Г. Сохранение в ресурс**

После финализации временного файла он передаётся в существующий механизм сохранения, который уже умеет загружать файл в SFTP/SMB/облако — без дублирования кода. На время передачи показывается тот же прогресс-индикатор, что и при camera capture. После успешного сохранения список Browse обновляется и скроллится к новой записи.

**Д. Разрешение RECORD_AUDIO**

Запрос runtime-разрешения при первом включении функции в настройках или при первом нажатии кнопки. Используется существующий централизованный механизм permission-запросов с rationale. При отказе в разрешении кнопка остаётся видимой, но нажатие выводит объяснение вместо начала записи. В манифесте — дополнительное объявление `uses-permission` с `required="false"` (достаточно для Google Play; не является hard-требованием для установки).

### 5.2 Потоки данных и событий

```
Пользователь удерживает кнопку
  → Browse проверяет разрешение RECORD_AUDIO
  → (нет разрешения) → запрос → rationale / отказ: объяснение
  → (есть разрешение) → подсистема записи: старт
  → пользователь отпускает кнопку
  → подсистема записи: стоп → временный файл готов
  → (настройка «Спрашивать имя»?) → диалог → пользователь подтверждает/переименовывает
  → слой применения: передача файла в текущий ресурс
  → (сетевой/облачный ресурс) → фоновая загрузка с прогресс-индикатором
  → список Browse обновлён, скролл к новому файлу
```

### 5.3 Точки расширяемости

- Формат выходного файла может быть расширен (WAV, OGG) через настройку в будущем — подсистема записи изолирована.
- Порог длительности записи (максимум в минутах) — опциональная настройка в будущей итерации.

## 6. Открытые вопросы / Research items

1. **Поведение при прерывании записи (входящий звонок, фокус)**
   - **Вопрос:** Что должно произойти с частично записанным файлом, если запись прервана системным событием (звонок, другое приложение перехватывает аудиофокус)?
   - **Варианты:** (а) Сохранить то, что записано; (б) Молча отменить и удалить временный файл; (в) Показать диалог выбора.
   - **Решение:** Вариант (б) — молча отменить, удалить временный файл.
   - **Статус:** Verified

2. **Флейвор `lite`: поддержка микрофонной записи**
   - **Вопрос:** В `lite` нет фонового аудиовоспроизведения, но `SUPPORT_AUDIO=true`. Включать ли микрофонную запись в `lite`?
   - **Варианты:** (а) Включить — микрофонная запись независима от воспроизведения; (б) Исключить — для простоты `lite`-профиля.
   - **Решение:** Вариант (б) — исключить из флейвора `lite`.
   - **Статус:** Verified

## 9. Архитектурные решения (ADR)

**ADR-1: Запись ведётся внутри приложения, а не через системный интент диктофона**

- **Решение:** Использовать внутреннюю подсистему записи (нативный Android Audio API), а не запускать внешнее приложение-диктофон через системный интент.
- **Альтернативы:** Системный интент диктофона — аналог camera capture; проще, но зависит от наличия стороннего диктофона и не позволяет сохранять напрямую в сетевой ресурс.
- **Почему:** Ключевой сценарий — сохранение прямо в SFTP/облако; внешнее приложение не имеет доступа к этим ресурсам. Внутренняя запись даёт полный контроль над потоком данных.

**ADR-2: Формат файла — M4A/AAC, без настройки по умолчанию**

- **Решение:** Всегда записывать в M4A (AAC), имя `REC_YYYYMMDD_HHmmss.m4a`.
- **Альтернативы:** WAV — несжатый, большой размер; OGG — лучше сжатие, но хуже совместимость с не-Android устройствами.
- **Почему:** M4A совместим с iOS, macOS, Windows Media Player и большинством Android-плееров; разумный компромисс между качеством и размером. WAV может быть добавлен позднее как опция.

## 11. Критерии готовности (strategic-level)

1. В Settings → Audio виден новый подраздел «Микрофонные записи» с двумя переключателями; оба работают и сохраняются между сессиями.
2. При включённой функции в командной панели Browse отображается кнопка с иконкой микрофона.
3. Удержание кнопки запускает запись; визуальный индикатор показывает, что идёт запись.
4. После отпускания кнопки файл появляется в текущей папке (локальной, SFTP, SMB, FTP, облачной).
5. При включённой настройке «Спрашивать имя файла» перед сохранением появляется диалог переименования.
6. Приложение запрашивает `RECORD_AUDIO` в нужный момент; при отказе — показывает объяснение, но не крашится.
7. Временные файлы удаляются при отмене или ошибке — в хранилище нет «мусора».
8. Все строки UI локализованы в EN/RU/UK.
9. Кнопка скрыта во флейворе `photos` и у пользователей с отключённой функцией.
