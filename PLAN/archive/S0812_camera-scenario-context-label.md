## 1. Проблема

Видимую встроенную камеру открывают из разных мест (поток распознавания текста, обычный захват из Browse, пункт «Камера», виджеты), но её интерфейс не сообщает, ради какого сценария камера открыта. Пользователь, дошедший до камеры через «распознать текст», видит обычный видоискатель и может забыть цель съёмки. Область - интерфейс встроенной камеры (feature camera-capture).

---

## 2. Цели

1. В интерактивной камере показывать подпись с названием текущего осмысленного сценария (например, распознавание текста).
2. Подпись оформлена в том же стиле, что и существующие подписи камеры (папка назначения, объектив), и вращается вместе с ориентацией устройства.
3. Подпись расположена над блоком кнопок пресетов зума.
4. Для обычного захвата (без особого сценария) подпись скрыта.

**Non-goals:**

- Показ подписи для headless-жестов «снять и отправить»/«снять и редактировать»/«снять и распознать-перевести» (S0791/S0792/S0794) - там видимой камеры нет.
- Добавление превью камеры в trampoline-активити этих жестов.
- Новые пользовательские настройки для управления подписью.

## 4. Контекст текущей архитектуры

Единый хост встроенной камеры принимает от вызывающих только механические параметры (режим захвата, пути вывода, флаги мультизахвата/автозахвата) - среди них нет параметра, идентифицирующего сценарий вызова. Существующие подписи камеры (папка назначения, название объектива) вычисляются внутри хоста из данных устройства и настроек, а не из сценария вызывающего. Поэтому хост сейчас не знает, ради чего его открыли, и не может отобразить название сценария.

---

## 5. Предлагаемый подход

Ввести в контракт камеры новый типизированный параметр сценария (по образцу существующего перечисления режима захвата). Вызывающие, у которых сценарий осмыслен (поток распознавания текста), передают соответствующее значение; остальные - значение по умолчанию «нет сценария». Хост, получив значение с назначенной локализованной подписью, отображает её над пресетом зума; при значении по умолчанию подпись скрыта.

### 5.1 Основные столпы / модули

- Контракт камеры - единый владелец нового параметра сценария и его чтения.
- Хост камеры - чтение параметра, привязка текста подписи, участие подписи в поворотной группе оверлея.
- Вызывающий сценарий распознавания - передача значения сценария при построении intent.

### 5.2 Потоки данных и событий

- Вызывающий -> intent-параметр сценария -> хост читает один раз при инициализации -> осмысленный сценарий: показать подпись; значение по умолчанию: скрыть.

### 5.3 Точки расширяемости

- Перечисление сценариев открыто к добавлению будущих видимых сценариев (каждый со своей локализованной подписью) без изменения логики хоста.
