---

## 1. Проблема

В редакторе рисования по изображению нет способа удалить редактируемый файл прямо из редактора. Бывает, что после рисования не нужен ни результат, ни исходник - например, при быстрой съёмке и пробном рисовании. Сейчас, чтобы удалить такой файл, надо выйти из редактора и искать его в обзоре, что неудобно.

---

## 2. Цели

1. В меню редактора рисования появляется действие «Удалить файл».
2. Действие удаляет редактируемый файл на текущем ресурсе любого типа (локальный, SMB, FTP, SFTP, облако).
3. После удаления редактор закрывается, пользователь возвращается к обзору.
4. Удаление подтверждается, чтобы исключить случайную потерю.

**Non-goals:**

- Массовое удаление и удаление каталогов.
- Новый механизм удаления - используется существующий.
- Изменение прочих действий меню редактора.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Действие нужно для сценария «порисовал, но ни результат, ни исходник не интересны».
2. Поведение - единообразно с уже существующим удалением файлов в приложении.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки, где доступен редактор рисования; код в общем источнике; новых `BuildConfig`-проверок не вводится.
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Производительность:** не критично.
- **Совместимость данных:** удаление файла - без схемы Room и миграций; если существующее удаление уже умеет корзину / восстановление, поведение наследуется как есть.
- **Локализация:** EN / RU / UK обязательно для пункта меню, подтверждения и сообщений результата.
- **Доступность:** пункт меню фокусируем (клавиатура, D-pad), активируется с клавиатуры, имеет contentDescription.

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** пункт «Удалить файл» размещается в overflow-меню редактора рисования рядом с прочими действиями файла; точное место подтверждается через `/ui-clarify`.
- **Accessibility:** новый пункт меню проходит тот же гейт `/ui-clarify`, что и правки существующих меню.
- **Communication policy:** диалог подтверждения, сообщения успеха и ошибки - по `docs/COMMUNICATION_POLICY.md`, чек-лист тона (§6 политики) обязателен перед интеграцией строк.
- **Localization:** EN / RU / UK обязательны; паритет ключей проверяется до коммита.
- **Validation level:** целевые варианты сборки компилируются; затронутые юнит-тесты проходят; ручная проверка удаления на локальном и сетевом ресурсе.
- **Owner sign-off:** ожидается 2026-06-05.
- **Related tickets:** S0359 (камера-захват открывает результат в редакторе - типичный источник такого удаления). Блокеров нет.

## 4. Контекст текущей архитектуры

Редактор рисования открывается навигационным событием с указанием файла и ресурса, имеет панель инструментов и overflow-меню с действиями (сохранение, отмена, экспорт). Удаление файлов в приложении уже реализовано как доменная операция со стратегиями под каждый тип ресурса (локальный и сетевые). Сейчас редактор этим не пользуется, поэтому удалить открытый файл из него нельзя.

---

## 5. Предлагаемый подход

Добавить в overflow-меню редактора рисования действие удаления редактируемого файла, которое запрашивает подтверждение, вызывает существующую доменную операцию удаления для типа текущего ресурса и по успеху закрывает редактор с возвратом в обзор.

### 5.1 Основные столпы / модули

**Пункт меню удаления.**
- Новое действие в overflow-меню редактора рядом с прочими действиями файла.
- Доступно при наличии открытого файла на ресурсе.

**Подтверждение и удаление.**
- Перед удалением - диалог подтверждения (необратимость согласно текущему поведению удаления в приложении).
- Удаление делегируется существующей доменной операции по типу ресурса; ошибки сети / доступа обрабатываются её сообщениями.

**Завершение.**
- По успеху - закрытие редактора и возврат в обзор; по ошибке - редактор остаётся открытым, показывается сообщение.

### 5.2 Потоки данных и событий

- Пункт меню -> подтверждение -> доменная операция удаления (по типу ресурса) -> успех -> закрытие редактора и возврат -> обзор обновляет список.
- Ошибка удаления -> сообщение -> редактор остаётся открытым.

### 5.3 Точки расширяемости

- Действие опирается на уже существующую доменную операцию удаления, поэтому новые типы ресурсов поддерживаются автоматически.

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользование существующего удаления**

- **Решение:** удаление из редактора делегируется существующей доменной операции, а не вводит свой путь.
- **Альтернативы:** прямое файловое удаление в обход доменного слоя.
- **Почему:** единообразие поведения (включая возможную корзину) и поддержка всех типов ресурсов без дублирования.
