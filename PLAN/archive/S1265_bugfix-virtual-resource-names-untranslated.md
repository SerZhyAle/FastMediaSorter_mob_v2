## 0. Захваченный материал (inbox)

**Захвачено:** 2026-07-28

**Текст:**

Обнаружено при съёмке скриншотов витрины Play (S1256) на `emulator-5556`, сборка standard debug `2.60.7262.102`, при переключении приложения на русскую локаль через `cmd locale set-app-locales .. --locales ru-RU`.

Главный экран переводится частично:

- вкладки и подписи переведены - «ВСЕ», «Локальн..», «Локальные», «180 файлов»;
- заголовки части виртуальных ресурсов переведены - «Недавние медиа», «Вся музыка», «Все видео», «Фото с камеры»;
- заголовок `All Files` остаётся английским;
- описания ресурсов остаются английскими рядом с переведёнными заголовками: «Вся музыка» / `Local audio files (mp3, flac, ogg, aac..)`, «Все видео» / `Local video files (mp4, mkv, mov, wmv..)`.

Похоже, что имена и описания виртуальных ресурсов сохраняются в базе при первом запуске на тогдашнем языке, а не берутся из ресурсов строк при отрисовке - поэтому смена локали их не затрагивает, и первый созданный ресурс остаётся полностью английским.

**Захвачено во время:** S1256

---

## 1. Проблема / симптом

На русской локали главный экран выглядит наполовину переведённым: заголовок `All Files` и описания виртуальных ресурсов остаются на английском рядом с переведёнными заголовками соседних строк. Это первое, что видит пользователь при запуске, и это же попадает в скриншоты магазина.

Эвиденс: скриншот `temp/play-shots/ru-RU/browse.png`, снятый 2026-07-28 на `emulator-5556` (Android 13) при `get-app-locales` = `[ru-RU]`.

Проверить также украинскую локаль - вероятно, симптом тот же.

---

## 2. Корневая причина

Гипотеза §0 верна наполовину: тексты действительно замораживаются в Room при провижининге (`ProvisionDefaultResourcesUseCase`/`ScanLocalFoldersUseCase` пишут `getString(..)` на языке первого запуска). Но механизм перелокализации УЖЕ существует - `RenameVirtualResourcesUseCase`, отложенная стартовая задача `rename-virtual-resources` (`AppStartupInitializer:90`). Он и сломан, тремя независимыми дефектами:

- Дрейф захардкоженной таблицы: `VirtualResourceDefaultNames.TABLE` хранил копии строк с типографским многоточием `…`, тогда как `strings.xml` использует хаус-стайл `..` (`virtual_comment_all_music` = «Local audio files (mp3, flac, ogg, aac..)»). Сравнение `entry.comment == resource.comment` не совпадало никогда -> описания вечно оставались на языке сева. Имена точек не содержат - совпадали и переводились (потому заголовки на скриншоте переведены, а описания нет).
- «All Files» вообще вне покрытия: его путь - реальный корень стораджа (не `virtual://`), фильтр `isVirtualPath` его отбрасывает, а спец-ветки (как у Downloads) для него не было.
- Список языков `listOf("en","ru","uk")` захардкожен - S1190/S1211 добавят языки, и класс снова молча отстанет.

---

## 3. Исправление

Выполнено 2026-07-28:

- `RenameVirtualResourcesUseCase` переписан: дефолты каждого языка резолвятся из САМИХ строковых ресурсов (`createConfigurationContext` на язык, ключи те же, что использует провижининг: `recent_media`/`virtual_all_*` + `virtual_comment_*`). Класс-источник дрейфа `VirtualResourceDefaultNames` удалён (Rule 20).
- Покрытие расширено на предопределённый «All Files»: идентификация по `ResourceProfile.ALL_FILES` (никогда по имени), перевод ключом `all_files`. Ветка Downloads сохранена и переведена на общий хелпер `applyLocalizedDefaults`.
- Языки берутся из `UiLanguageCatalog.supportedTags` - новые локали S1190 подхватятся автоматически.
- Семантика консервативна как раньше: перезаписывается только значение, равное дефолту ДРУГОГО поддержанного языка; пользовательские переименования не трогаются. Старые установки, засеянные из более ранних формулировок strings.xml, остаются как есть (идентифицировать их как «наши» невозможно).

## Last Audit

**Дата:** 2026-07-28. **Вердикт:** Verified.

- Корень: три дефекта в `RenameVirtualResourcesUseCase` (дрейф захардкоженной таблицы `…` vs `..` -> описания никогда не совпадали; All Files вне покрытия из-за не-virtual пути; захардкоженный список языков).
- Фикс: дефолты из строковых ресурсов per-language (createConfigurationContext), таблица-дублёр удалена (Rule 20), All Files по `ResourceProfile.ALL_FILES`, языки из `UiLanguageCatalog.supportedTags` (S1190-совместимо). Пользовательские имена сохраняются (консервативное сравнение с дефолтами других языков).
- Девайс-верификация: en->ru (лог + экран + БД) и ru->en (БД) на 5588.
- S1190 не поглощает: он расширяет языки, а этот класс теперь масштабируется на них автоматически.
