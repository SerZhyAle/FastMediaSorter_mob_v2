## 1. Проблема

OCR и перевод уже существуют, но пользователь не имеет короткого сценария «сфотографировал текст → сразу получил перевод». Сейчас такой путь требует ручного выбора или открытия файла, что плохо подходит для быстрых задач: вывеска, инструкция, чек, экран другого устройства, бумажный документ.

Нужен отдельный flow, который запускается из основного окна или с домашнего экрана, сохраняет сделанный снимок в понятное место, прогоняет его через распознавание и перевод, а затем показывает результат крупно и готовит его к сохранению как текст.

---

## 2. Цели

1. В основном окне появляется команда «Фото-OCR-перевод» в ниспадающем меню.
2. На домашнем экране доступен отдельный widget для запуска того же сценария.
3. После запуска пользователь попадает в режим камеры без промежуточного выбора файла.
4. Сделанное фото сохраняется в каталог камеры устройства, а если он недоступен - в Downloads.
5. Имя снимка формируется универсально по дате и времени, без зависимости от локали устройства.
6. Снимок сохраняется в качестве, достаточном для OCR, без лишнего пережатия ради маленького размера.
7. После сохранения снимка приложение автоматически распознаёт текст.
8. После OCR приложение автоматически переводит распознанный текст.
9. Перевод показывается пользователю крупным, хорошо читаемым текстом.
10. Пользователь может сохранить перевод как текстовый файл.
11. Отмена камеры, пустой OCR и ошибка перевода дают понятный fallback, а не тупик.
12. Функция выключена по умолчанию и включается в `Settings -> Playback -> Other functionality`.
13. В настройках есть подчинённая галочка «Не переводить (только OCR)».
14. В режиме камеры пользователь может открыть диалог и изменить OCR language, target translation language и режим «только OCR»; изменения сохраняются как настройки программы.
15. Экран результата сразу показывает перевод сверху и распознанный OCR-текст ниже.
16. Кнопка «Следующее фото» запускает следующий снимок из того же flow.

**Non-goals:**

- Новый OCR-движок или новая система перевода.
- Замена существующего OCR/перевода для изображений и PDF.
- Массовая обработка нескольких фотографий за один запуск.
- Редактор распознанного текста в первой версии.
- Синхронизация результата в облако без отдельного решения.
- Интеграция с Wear OS в первой версии.
- Автоматическая загрузка модели перевода из camera-flow при её отсутствии.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Основной запуск: из ниспадающего меню основного окна по команде «Фото-OCR-перевод».
2. Второй запуск: через widget домашнего экрана с тем же смыслом «Фото-OCR-перевод».
3. Фото должно сохраняться в каталог камеры устройства.
4. Если каталог камеры недоступен, фото должно сохраняться в Downloads.
5. Имя фото должно быть универсальным и основанным на дате-времени.
6. Качество фото должно быть достаточным для OCR.
7. После фото должен автоматически запускаться OCR.
8. После OCR должен автоматически запускаться перевод.
9. Перевод должен быть показан крупным текстом.
10. Перевод можно сохранить как текстовый файл.
11. Существующие реализации OCR/перевода/камеры должны переиспользоваться, а не переписываться.
12. Функция должна быть opt-in: настройка находится в `Settings -> Playback -> Other functionality`, по умолчанию выключена.
13. Если функция включена, появляются пункт меню основного окна и widget запуска.
14. Helper и документация должны объяснять, что flow использует OCR language и направление перевода из настроек программы.
15. В режиме камеры должна быть кнопка, открывающая диалог настройки OCR source language, target translation language и режима «Не переводить (только OCR)».
16. Изменения в этом диалоге сохраняются как настройки программы и применяются к camera-flow и последующим OCR/translation сценариям, пока пользователь их не изменит.
17. При недоступной модели перевода приложение показывает распознанный OCR-текст и ошибку перевода без автоматической загрузки модели.

### 3.2 Жёсткие ограничения

- **Flavor:** настройка, пункт меню и widget доступны только в app_v2 flavor, где есть OCR + translation; flavor без полного набора возможностей не показывают эту функцию.
- **API level:** сценарий должен уважать текущие минимальные версии поддерживаемых flavor и правила доступа к MediaStore/Downloads.
- **Wear OS:** не затрагивается в первой версии.
- **Производительность:** OCR и перевод не должны блокировать UI; экран должен показывать прогресс между снимком, OCR и переводом.
- **Настройки:** функция имеет основной opt-in переключатель `off` по умолчанию и подчинённую галочку «Не переводить (только OCR)»; OCR language и направление перевода используют существующие настройки программы.
- **Совместимость данных:** новые настройки должны иметь безопасные значения по умолчанию и не сбрасывать существующие OCR/translation предпочтения.
- **Локализация:** EN/RU/UK обязательны для команды меню, widget, прогресса, ошибок, пустых состояний и сохранения результата.
- **Доступность:** запуск из меню и widget, экран результата, кнопка сохранения и ошибки должны поддерживать touch, keyboard, D-pad и TalkBack там, где это применимо.
- **Хранение файлов:** сохранение фото и `.txt` результата не должно писать в корень проекта или приложения; пользовательский файл должен попадать в обычное пользовательское хранилище.
- **UI communication:** все новые видимые строки должны соответствовать `docs/COMMUNICATION_POLICY.md` и пройти tone checklist до интеграции.
- **Ориентации:** экран результата и entry point из основного окна должны быть проверены в портретной и ландшафтной ориентации.

## 4. Контекст текущей архитектуры

Приложение уже имеет отдельные возможности для съёмки, OCR, перевода, сохранения файлов, запуска действий из основного окна и работы с home-screen widget. Эти возможности существуют как раздельные сценарии, но не образуют короткий сквозной поток для «живого» текста перед пользователем.

Новый сценарий должен стать orchestration flow поверх существующих возможностей: вход из UI, захват изображения, сохранение снимка, OCR, перевод, показ результата и сохранение текста. Это не должно переносить бизнес-логику в экран: UI управляет состоянием и действиями пользователя, а прикладной слой последовательно выполняет шаги и возвращает результат или fallback.

---

## 5. Предлагаемый подход

Добавить единый пользовательский flow «Фото-OCR-перевод», который включается в настройках воспроизведения в группе «Прочие функции» и запускается из двух entry point: меню основного окна и home-screen widget. После запуска flow ведёт пользователя по одному сценарию: камера → сохранение фото → OCR → перевод или OCR-only → экран результата → сохранение текста. Flow должен переиспользовать существующие роли съёмки, распознавания, перевода и записи файлов, а новую работу сосредоточить на связке состояний, fallback-поведении, настройках и пользовательском результате.

### 5.1 Основные столпы / модули

- **Entry points** - команда основного меню и home-screen widget запускают один и тот же сценарий, чтобы поведение не расходилось.
- **Feature setting** - основной переключатель выключен по умолчанию; подчинённая галочка управляет режимом «Не переводить (только OCR)».
- **Capture and storage** - снимок сохраняется в пользовательское хранилище с предсказуемым именем и качеством, достаточным для OCR.
- **Camera settings dialog** - во время съёмки пользователь может открыть компактный диалог и изменить OCR source language, target translation language и OCR-only mode.
- **OCR orchestration** - после успешного сохранения снимка автоматически запускается распознавание текста без ручного открытия изображения.
- **Translation orchestration** - распознанный текст автоматически передаётся в перевод с учётом доступности модели, выбранного направления перевода и режима OCR-only.
- **Result surface** - результат показывается отдельным читаемым состоянием: перевод сверху, исходный OCR-текст ниже, прогресс и понятные ошибки.
- **Text export** - пользователь может сохранить перевод как текстовый файл в согласованное место.
- **Fallback discipline** - отмена съёмки, пустой текст, недоступная модель, отказ разрешений и ошибка записи имеют понятный следующий шаг.

### 5.2 Потоки данных и событий

Пользователь включает функцию в настройках → приложение показывает пункт меню и widget → пользователь выбирает команду меню или нажимает widget → приложение открывает камеру → при необходимости пользователь открывает диалог OCR/translation настроек → пользователь делает фото → приложение сохраняет снимок в каталог камеры или Downloads → запускается OCR → если OCR-only выключен, распознанный текст отправляется в перевод → экран результата показывает перевод сверху и OCR-текст ниже → пользователь сохраняет результат как `.txt`, нажимает «Следующее фото» или закрывает экран.

Если пользователь отменяет камеру, flow завершается без побочного файла. Если фото сохранено, но OCR не нашёл текста, пользователь видит пустое состояние с возможностью сделать следующее фото. Если перевод недоступен, пользователь видит распознанный текст и ошибку перевода без автоматической загрузки модели.

### 5.3 Точки расширяемости

- Направление перевода и OCR language должны оставаться глобальными настройками программы, а camera-flow только менять их через компактный диалог.
- Экран результата должен позволять в будущем добавить копирование, шаринг, редактирование OCR-текста или повторный перевод без изменения capture flow.
- Сохранение фото и текста должно иметь единый policy для имени файла и конфликтов.
- Widget должен использовать тот же availability contract, что и пункт меню, чтобы flavor и настройки не расходились.

## 6. Открытые вопросы / Research items

1. **Язык OCR по умолчанию**
   - **Вопрос:** какой OCR source language использовать без явного выбора в camera-flow?
   - **Решение владельца:** текущий язык OCR из настроек программы; если он не задан, использовать `Auto`.
   - **Статус:** Resolved.

2. **Направление перевода**
   - **Вопрос:** откуда брать target translation language?
   - **Решение владельца:** из существующих translation settings программы.
   - **Статус:** Resolved.

3. **Flavor availability**
   - **Вопрос:** что делать во flavor, где нет полного набора OCR + translation?
   - **Решение владельца:** функция доступна в настройках только там, где есть OCR + translation; в остальных flavor настройка, пункт меню и widget не показываются.
   - **Статус:** Resolved.

4. **Widget lifecycle**
   - **Вопрос:** что должен делать уже добавленный widget, если пользователь выключил функцию?
   - **Решение владельца:** не открывать fallback с предложением включить настройку; агент выбирает безопасное нейтральное поведение в рамках реализации.
   - **Статус:** Resolved.

5. **Camera settings dialog**
   - **Вопрос:** какой UI нужен для изменения OCR/translation параметров прямо из камеры?
   - **Решение владельца:** диалог с тремя пунктами: OCR source language, target translation language, галочка «Не переводить (только OCR)».
   - **Статус:** Resolved.

6. **Сохранение `.txt` результата**
   - **Вопрос:** где сохранять текстовый перевод и как называть файл?
   - **Решение владельца:** сохранять в Downloads с тем же timestamp-base-name, что у фото.
   - **Статус:** Resolved.

7. **Форма результата**
   - **Вопрос:** экран результата должен показывать только перевод или также исходный OCR-текст?
   - **Решение владельца:** показывать оба блока сразу; перевод сверху, OCR-текст ниже.
   - **Статус:** Resolved.

8. **Следующий снимок**
   - **Вопрос:** нужна ли отдельная команда повторного фото?
   - **Решение владельца:** нужна кнопка «Следующее фото», она же покрывает повторный снимок.
   - **Статус:** Resolved.

9. **Недоступная модель перевода**
   - **Вопрос:** что делать, если модель перевода недоступна?
   - **Решение владельца:** показать распознанный OCR-текст и ошибку перевода; не запускать автоматическую загрузку модели.
   - **Статус:** Resolved.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| OCR не найдёт текст из-за качества снимка | Средняя | Пользователь увидит пустой результат после успешной съёмки | Сохранять снимок без лишнего пережатия, показывать повтор съёмки и подсказку по качеству |
| Модель перевода недоступна офлайн | Средняя | Flow не сможет построить перевод после OCR | Показать распознанный OCR-текст и ошибку перевода без автоматической загрузки модели |
| Flavor без перевода получит нерабочий entry point | Средняя | Пользователь нажмёт команду, которая не может завершить сценарий | На тактической стадии зафиксировать availability contract для меню и widget |
| Ошибка записи в каталог камеры или Downloads | Средняя | Фото или текст не сохранятся, а OCR может потерять входной файл | Определить fallback записи и проверять фактическое место сохранения перед OCR |
| Widget и меню начнут расходиться по поведению | Средняя | Один вход будет работать иначе, чем другой | Оба entry point должны запускать один flow с общим состоянием доступности |
| Экран результата будет плохо читаем на маленьких экранах или TV | Средняя | Крупный перевод обрежется или нарушит навигацию | Проверить adaptive text, scroll, orientation, D-pad, keyboard и TalkBack |
| Автоматический flow будет выглядеть зависшим | Средняя | Пользователь не поймёт, что идёт OCR или перевод | Показать явные короткие progress-состояния для съёмки, OCR, перевода и сохранения |

## 9. Архитектурные решения (ADR)

**ADR-1: Новый flow поверх существующих OCR/translation/camera возможностей**

- **Решение:** связать существующие capabilities в один пользовательский сценарий вместо переписывания OCR, перевода или камеры.
- **Альтернативы:** создать отдельный OCR/translation стек для камеры; заставить пользователя сначала сохранять фото и затем открывать его вручную.
- **Почему:** владелец указал, что всё уже реализовано, а недостающая часть - новый flow.

**ADR-2: Два entry point, один общий сценарий**

- **Решение:** основное меню и widget запускают один flow с одинаковыми состояниями и fallback.
- **Альтернативы:** реализовать widget как отдельный путь; ограничиться только основным меню.
- **Почему:** два входа нужны для разных ситуаций, но расхождение поведения повысит риск дефектов.

**ADR-3: Фото сохраняется до OCR**

- **Решение:** сделанный снимок сначала попадает в пользовательское хранилище, затем используется для OCR.
- **Альтернативы:** держать снимок только временно; сохранять только после успешного OCR.
- **Почему:** владелец явно указал сохранение фото в каталог камеры или Downloads, а сохранённый файл помогает повторить OCR и проверить источник результата.

**ADR-4: Перевод показывается как основной результат**

- **Решение:** главный экран результата фокусируется на крупном переводе, а исходный OCR-текст и технические детали остаются вторичными.
- **Альтернативы:** показывать только исходный текст; показывать OCR и перевод с равным весом; сразу сохранять файл без экрана результата.
- **Почему:** пользовательский сценарий называется «Фото-OCR-перевод» и завершается именно чтением перевода.

**ADR-5: Настройки OCR/translation являются глобальными настройками программы**

- **Решение:** camera-flow использует текущие OCR language и направление перевода из настроек программы; диалог камеры изменяет эти же настройки, а не создаёт локальный одноразовый профиль.
- **Альтернативы:** хранить отдельные настройки только для camera-flow; спрашивать языки при каждом запуске; использовать только auto-detect без ручного выбора.
- **Почему:** владелец указал, что эти значения должны применяться и к результату камеры, и к последующим сценариям, пока пользователь их не изменит.

**ADR-6: OCR-only режим является подчинённой настройкой функции**

- **Решение:** галочка «Не переводить (только OCR)» живёт внутри этой функции и доступна в настройках и в диалоге камеры.
- **Альтернативы:** делать отдельный независимый OCR-only flow; не добавлять OCR-only режим; скрыть режим только в camera-dialog.
- **Почему:** владелец явно добавил эту галочку как подчинённую настройку данной функции.

## 11. Критерии готовности (strategic-level)

1. В основном окне пользователь видит команду «Фото-OCR-перевод» в согласованном ниспадающем меню, когда сценарий доступен.
2. Пользователь может добавить или использовать widget домашнего экрана для запуска «Фото-OCR-перевод».
3. Оба entry point открывают один и тот же сценарий камеры.
4. После сделанного фото файл появляется в каталоге камеры устройства или в Downloads, если каталог камеры недоступен.
5. Имя сохранённого фото содержит дату-время и не зависит от языка интерфейса.
6. Снимок сохраняется в качестве, пригодном для OCR, без очевидной деградации текста.
7. После снимка пользователь видит прогресс OCR и перевода, а не неподвижный экран.
8. Если OCR находит текст, пользователь получает перевод крупным читаемым шрифтом.
9. Экран результата сразу показывает перевод сверху и распознанный OCR-текст ниже.
10. Если включён режим «Не переводить (только OCR)», пользователь получает OCR-текст без попытки перевода.
11. Если OCR не находит текст, пользователь получает понятное пустое состояние и возможность нажать «Следующее фото».
12. Если перевод недоступен, пользователь видит распознанный OCR-текст и ошибку перевода без автоматической загрузки модели.
13. Пользователь может сохранить результат как `.txt` в Downloads и затем найти файл по timestamp-base-name, связанному со снимком.
14. Отмена камеры не создаёт лишний пользовательский файл и возвращает пользователя в понятное состояние.
15. В режиме камеры пользователь может открыть диалог OCR/translation настроек и сохранить изменения как глобальные настройки программы.
16. Кнопка «Следующее фото» запускает новый снимок без ручного перезапуска flow.
17. Портретная и ландшафтная ориентации не ломают entry point, экран результата и сохранение текста.
18. Touch, keyboard, D-pad и TalkBack покрывают основные действия сценария.
