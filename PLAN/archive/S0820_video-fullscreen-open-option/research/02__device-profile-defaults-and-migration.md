# Research: значения по умолчанию по профилям устройства и миграция существующих установок

**Для:** S0820, §6 item 2
**Дата:** 2026-07-02
**Метод:** чтение кода (android-solution-researcher, read-only)

## Вопрос

Соответствуют ли "профиль аудио" и "профиль читалка" из формулировки задачи существующим профилям устройства один-в-один? Как для существующих установок при обновлении приложения новый флаг получает значение "включено" - нужен ли отдельный шаг миграции?

## Находки

- Система профилей устройства сегодня насчитывает 11 профилей, включая профиль "аудиоплеер" и профиль "читалка" - оба существуют как отдельные, самостоятельные профили (не пересекаются с профилем "фоторамка").
- Для каждого пресетируемого поля настроек пресет-система хранит одну строку CSV со значением на каждый профиль; поле, оставленное пустым для профиля, означает "нет переопределения - действует обычное значение по умолчанию из кода".
- Хранилище настроек не использует Room - обычные булевы поля читаются из хранилища ключ-значение с явным значением по умолчанию в коде на случай отсутствия ключа.
- Для уже установленных приложений, обновляющихся до версии с новым полем, ключ этого поля в хранилище отсутствует так же, как и для новой установки - оба случая одинаково получают значение по умолчанию из кода без какого-либо отдельного шага миграции. Это уже наблюдаемый, действующий паттерн для всех ранее добавленных булевых настроек в проекте.
- Профиль устройств, под который подпадают установки до появления системы профилей ("миграция существующей установки"), не имеет собственного переопределения ни для одного поля пресета - такие установки получают ровно обычное значение по умолчанию из кода, как и любая другая установка без применённого пресета.

## Решение

1. "Профиль аудио" из формулировки задачи = существующий профиль устройства "аудиоплеер"; "профиль читалка" = существующий профиль устройства "читалка". Однозначное соответствие, без пересечения с профилем "фоторамка".
2. Новый флаг подключается к пресет-системе как обычное пресетируемое поле: включено для всех профилей, кроме "аудиоплеер" и "читалка" (выключено), с пустым значением (нет переопределения) для профиля "прочее".
3. Требование "при миграции - становится On тоже" удовлетворяется автоматически самим механизмом хранения настроек (отсутствующий ключ = значение по умолчанию из кода = включено) - отдельный код миграции не требуется и не должен вводиться, это совпало бы с уже существующим поведением каждого ранее добавленного булева поля.
