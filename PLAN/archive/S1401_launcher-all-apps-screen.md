## 1. Проблема

В режиме лаунчера единственный способ добраться до установленного приложения, которого нет на рабочем столе - открыть меню «Пуск» и развернуть внутри него строку «Все приложения». Сетка получается размером в часть высоты меню, без поиска и без выбора порядка, и каждое её открытие заново опрашивает систему и заново декодирует иконку каждого приложения - на устройстве с сотней приложений это несколько секунд ожидания при каждом заходе. Область: режим лаунчера, поверхность рабочего стола и меню «Пуск».

---

## 2. Цели

1. Пользователь открывает список всех установленных приложений на весь экран - кнопкой рядом с «Пуск» и жестом свайпа снизу-вверх по свободному месту рабочего стола.
2. Список появляется мгновенно, без ожидания сборки, в том числе при первом открытии после перезагрузки телефона.
3. Пользователь находит приложение набором части его названия, без прокрутки.
4. Пользователь выбирает порядок списка - по названию, по дате установки, по дате обновления, по частоте и давности запуска, по категории - и выбранный порядок сохраняется между заходами.
5. Долгое нажатие на приложение даёт одно меню со всеми действиями: запустить, положить на рабочий стол, закрепить на панели задач, открыть сведения о приложении, удалить, плюс собственные сценарии приложения.
6. Список сам догоняет реальность: установленное, удалённое или обновлённое приложение отражается без ручного обновления.

**Non-goals:**

- Собственные папки, группы и ручная перестановка иконок внутри списка «Все приложения».
- Скрытие отдельных приложений от списка.
- Сортировка по размеру приложения - требует особого разрешения «Доступ к данным использования» и медленного подсчёта по всем приложениям (решение владельца 2026-08-05).
- Системная статистика использования по всем приложениям - частота считается по собственному журналу запусков лаунчера.
- Замена рабочего стола на прокручиваемые страницы приложений.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Кнопка вызова рядом с «Пуск» - только иконка, без подписи.
2. Экран выглядит как та же сетка приложений, что и в меню «Пуск», но во весь экран.
3. Поиск работает как автофильтр - список сужается по мере ввода, без кнопки «искать».
4. Кеш списка приложений обязателен, ожидание при открытии недопустимо.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard` и `noLegal` - единственные варианты сборки с режимом лаунчера (`SUPPORT_LAUNCHER`). Экран, кнопка и жест целиком живут в наборе исходников режима лаунчера, по правилам `dev/FLAVOR_DEVELOPMENT_RULES.md`; проверки вида `BuildConfig.IS_*` внутри общего кода запрещены (CLAUDE.md Rule 14). Кеш списка приложений - общий, не привязан к лаунчеру, потому что тем же списком пользуется панель запуска приложений.
- **API level:** без API-специфики сверх минимального уровня проекта.
- **Wear OS:** не затрагивается.
- **Производительность:** открытие экрана - без видимого ожидания при заполненном кеше; сборка списка и декодирование иконок только вне главного потока; фоновое обновление кеша не должно подтормаживать рабочий стол.
- **Совместимость данных:** кеш - производные данные, восстановимые из системы; его потеря или несовместимость решается полной пересборкой, а не миграцией пользовательских данных. Выбранный порядок сортировки - пользовательская настройка, переживает обновление приложения.
- **Локализация:** EN/RU/UK - обязательно для всех новых строк.
- **Доступность:** кнопка вызова - только иконка, поэтому обязательно описание для озвучивания и размер зоны нажатия не меньше стандартного; экран полностью проходим с клавиатуры, D-pad и мыши (CLAUDE.md Rule 16); контент не залезает под системные панели в обеих ориентациях (Rule 17); жест свайпа дублируется кнопкой, то есть не является единственным способом вызова.
- **Коммуникация:** новые строки - названия действий меню, подсказка поиска, пустое состояние поиска, сообщение о неудачном запуске - соответствуют `docs/COMMUNICATION_POLICY.md`, проверка тона по чек-листу §6 политики обязательна до интеграции строк.
- **Документация:** переключатель порядка - управляющий элемент содержимого экрана, а не строка настроек, поэтому он не заводится как настроечная поверхность; если он всё же будет собран из настроечных виджетов, его макет обязан быть классифицирован по правилу полноты каталога настроек. Новая способность регистрируется в инвентаре возможностей, иконочные кнопки - в легенде иконок, способ вызова - в пользовательской документации лаунчера.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** `standard` + `noLegal` - оба варианта, где включён режим лаунчера; в остальных вариантах поверхности лаунчера нет вообще.
- **Performance budget:** открытие экрана из заполненного кеша - без индикатора загрузки; полная пересборка списка выполняется в фоне и не блокирует ни рабочий стол, ни уже открытый экран.
- **Data compatibility:** кеш полностью восстановим из системы, схема кеша версионируется и при несовпадении пересобирается; настройка сортировки сохраняется между запусками.
- **Localization:** EN/RU/UK для всех новых строк, паритет ключей обязателен.
- **UI placement contract:** кнопка - иконка на панели задач непосредственно справа от «Пуск», до полосы недавних; экран открывается поверх рабочего стола на весь экран, панель задач при этом скрыта; строка поиска - сверху экрана, справа от неё иконочная кнопка порядка, открывающая меню из пяти порядков с отметкой текущего и отдельным пунктом обратного направления (решение владельца 2026-08-05); сетка занимает всю оставшуюся площадь, число колонок выводится из ширины, поэтому отдельного альбомного макета нет; строка «Все приложения» из меню «Пуск» удаляется вместе с раскрывающейся сеткой (решение владельца 2026-08-05); жест - свайп снизу-вверх по свободному месту рабочего стола, срабатывает только когда рабочий стол не прокручен, иначе тот же свайп сначала возвращает стол наверх.
- **Accessibility:** описание кнопки для озвучивания, полная проходимость экрана клавиатурой и D-pad, соблюдение безопасных границ системных панелей в портрете и ландшафте.
- **Communication policy:** применяется - вводятся видимые пользователю строки меню, поиска, пустого состояния и сообщений об ошибке.
- **Validation level:** сборка вариантов `standard` и `noLegal`, затем ручная проверка на устройстве - вызов кнопкой и жестом, поиск, все режимы сортировки и их сохранение между запусками, все пункты долгого нажатия, скорость открытия после перезагрузки, установка и удаление приложения при открытом экране, обе ориентации.
- **Owner sign-off:** 2026-08-05 - состав полей сортировки, глубина кеша, поведение жеста, состав меню долгого нажатия и судьба строки в «Пуск» согласованы.
- **Related tickets:** S1209 (прокрутка рабочего стола - от неё зависит условие срабатывания жеста), S1205 (размещение сторонних закреплённых ярлыков), S1103 (действия ячеек и сценарии приложений - переиспользуемый механизм меню).

## 4. Контекст текущей архитектуры

Список установленных приложений сейчас собирается по требованию: слой сценариев спрашивает систему, какие приложения умеют запускаться, и тут же для каждого загружает название и иконку. Кеша нет ни на уровне памяти, ни на диске, поэтому цена сборки платится при каждом открытии - и в меню «Пуск» лаунчера, и в выборе приложения для панели запуска. Сама сетка приложений существует только как элемент меню «Пуск»: она встроена в лист-меню, у неё фиксированное число колонок и никакого состояния, кроме списка.

Меню сценариев приложения по долгому нажатию уже реализовано отдельным помощником и вызывается из двух мест - с рабочего стола и из меню «Пуск». Оно показывает исключительно сценарии, опубликованные самим приложением, и ничего не знает про действия лаунчера. Решить задачу §1 в существующем виде нельзя: нет ни слоя хранения списка, ни поверхности, где помещаются поиск и переключатель порядка, ни единого меню, куда сходились бы действия лаунчера и сценарии приложения.

## 5. Предлагаемый подход

Появляются три новые ответственности: хранилище списка приложений с фоновым обновлением, отдельная полноэкранная поверхность списка и объединённое меню действий над приложением. Хранилище - общее для всего приложения, поверхность и меню - принадлежат режиму лаунчера.

### 5.1 Основные столпы / модули

**Кеш списка приложений.** Слой данных, который хранит перечень запускаемых приложений вместе с их названиями, иконками и полями для сортировки - датой установки, датой обновления, категорией - в постоянном хранилище на устройстве. Читатели получают список немедленно, не дожидаясь опроса системы. Хранилище само себя обновляет: подписывается на события установки, удаления и обновления приложений, а также на смену языка системы (названия приложений локализованы) и точечно правит затронутые записи. При первом запуске и при несовпадении версии схемы кеш собирается целиком в фоне. Существующий сценарий получения списка приложений становится тонким читателем этого кеша, поэтому ускорение достаётся и панели запуска приложений, и выбору приложения для ячейки рабочего стола.

**Порядок и поиск.** Слой применения отдаёт поверхности готовый отфильтрованный и отсортированный список. Поля порядка: название, дата установки, дата обновления, частота и давность запуска, категория. Частота берётся из уже существующего журнала запусков лаунчера - это не требует особых разрешений, но учитывает только запуски, сделанные через наш лаунчер. Категория берётся из данных приложения и заполнена не у всех - приложения без неё собираются в отдельную группу в конце. Выбранный порядок хранится как пользовательская настройка и восстанавливается при следующем открытии; поисковый запрос, наоборот, живёт только пока экран открыт.

**Полноэкранная поверхность списка.** Новая поверхность режима лаунчера поверх рабочего стола: строка поиска и переключатель порядка сверху, сетка приложений на всю оставшуюся площадь, число колонок выводится из ширины экрана, поэтому портрет и ландшафт обслуживаются одной логикой. Вызывается двумя способами - иконочной кнопкой на панели задач сразу справа от «Пуск» и свайпом снизу-вверх по свободному месту рабочего стола. Жест распознаётся только когда рабочий стол находится в верхнем положении: если стол прокручен вниз, тот же свайп сначала возвращает его наверх, и только следующий открывает список. Закрывается системным жестом или кнопкой «назад». Строка «Все приложения» и встроенная в меню «Пуск» сетка удаляются - остаётся один список вместо двух.

**Объединённое меню действий.** Долгое нажатие на приложение в списке открывает одно меню, где действия лаунчера и сценарии приложения перечислены вместе: «Запустить», «На рабочий стол», «Закрепить на панели задач», «Сведения о приложении», «Удалить», далее сценарии, опубликованные самим приложением. Пункты, невозможные для конкретного приложения - удаление системного приложения, отсутствующие сценарии - не показываются, а не показываются заблокированными. Существующий механизм показа сценариев расширяется до этого объединённого меню, чтобы рабочий стол и новый экран пользовались одним и тем же поведением, а не двумя похожими.

### 5.2 Потоки данных и событий

- Система → наблюдатель установок/удалений/обновлений → кеш приложений → поток списка → слой применения (фильтр + порядок) → поверхность списка.
- Поверхность списка → слой применения → сценарий запуска приложения → журнал запусков лаунчера → влияет на порядок «по частоте» при следующем чтении.
- Меню действий → сценарии лаунчера (положить на стол, закрепить на панели) или системные намерения (сведения, удаление) или служба сценариев приложения.
- Настройка порядка: поверхность → хранилище настроек → при следующем открытии читается обратно.

### 5.3 Точки расширяемости

- Набор полей сортировки задан списком, а не жёсткой развилкой, чтобы добавить размер приложения или системную статистику использования, если позже владелец согласится на соответствующее разрешение.
- Набор пунктов меню действий расширяем: каждый пункт сам решает, применим ли он к конкретному приложению.
- Кеш отдаёт данные потоком, поэтому подписаться на список могут и другие поверхности - выбор приложения для ячейки рабочего стола, панель запуска, будущие виджеты.
- Отдельный флейворный контракт не заводится: экран, кнопка и жест целиком лежат в наборе исходников режима лаунчера и в сборках без него отсутствуют физически, а кеш нейтрален к варианту сборки и остаётся в общем слое.

## 6. Открытые вопросы / Research items

1. **Какие поля установленного приложения доступны для сортировки**
   - **Вопрос:** какие характеристики приложения можно получить без особых разрешений и во сколько обходится каждая?
   - **Варианты:** название, имя пакета, дата установки, дата обновления, категория, признак системного приложения - бесплатно; размер и системная статистика использования - только с особым разрешением.
   - **Нужно выяснить:** состав бесплатных полей и цена платных.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1401_launcher-all-apps-screen/research/01__sortable-app-fields.md`

2. **Формат постоянного хранения иконок**
   - **Вопрос:** как хранить иконки приложений на диске, чтобы открытие было мгновенным, а объём разумным?
   - **Варианты:** отдельные файлы изображений в каталоге кеша; двоичные поля в базе данных; повторное декодирование из системы при каждом открытии.
   - **Нужно выяснить:** цена каждого варианта для базы данных, резервных копий и первого кадра.
   - **Статус:** Resolved - по одному файлу изображения на приложение в каталоге кеша, путь и дата обновления в строке кеша.
   - **Артефакт:** `PLAN/S1401_launcher-all-apps-screen/research/02__icon-cache-storage.md`

3. **Источник событий установки и удаления**
   - **Вопрос:** от чего обновлять кеш - от служебного наблюдателя приложений, доступного только пока мы являемся домашним приложением, или от общесистемных широковещательных сообщений?
   - **Варианты:** только наблюдатель; только широковещательные сообщения; наблюдатель с откатом на сообщения при потере роли домашнего приложения.
   - **Нужно выяснить:** поведение при потере роли домашнего приложения и в вариантах сборки без режима лаунчера.
   - **Статус:** Resolved - системные широковещательные сообщения о пакетах плюс смена языка; наблюдатель отвергнут, он молчит ровно тогда, когда устаревание заметить труднее всего.
   - **Артефакт:** `PLAN/S1401_launcher-all-apps-screen/research/03__cache-invalidation-source.md`

4. **Наполненность категории приложения**
   - **Вопрос:** у какой доли приложений на реальном устройстве категория заполнена?
   - **Статус:** Resolved решением - сортировка по категории выпускается в любом случае, приложения без категории собираются в группу в конце списка. Реальная доля заполненности измеряется при проверке на устройстве и, если она окажется исчезающе малой, ценность этого порядка пересматривается отдельным тикетом, а не блокирует реализацию.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Свайп снизу-вверх перехватывает прокрутку рабочего стола | Средняя | Стол перестаёт прокручиваться или список открывается случайно | Жест распознаётся только в верхнем положении стола; порог по расстоянию и скорости; вызов дублирован кнопкой |
| Устаревший кеш показывает удалённое приложение | Средняя | Нажатие ведёт в никуда | Обновление кеша по событиям системы; неудачный запуск снимает запись и обновляет список |

## 8. Влияние на пользователя (docs/FEATURES)

Новая способность. Формулировка для `docs/FEATURES.md` и переводов: в режиме лаунчера появился полноэкранный список всех установленных приложений с поиском, выбором порядка и меню действий по долгому нажатию; список открывается кнопкой рядом с «Пуск» или свайпом снизу-вверх и загружается мгновенно.

## 9. Архитектурные решения (ADR)

**ADR-1: Кеш списка приложений живёт в общем слое, а не в режиме лаунчера**

- **Решение:** хранилище списка приложений размещается в общем для всех вариантов сборки слое данных.
- **Альтернативы:** держать кеш внутри набора исходников режима лаунчера.
- **Почему:** тем же списком пользуется панель запуска приложений и выбор приложения для ячейки, то есть поверхности, существующие и без лаунчера; кеш ничем не связан с ролью домашнего приложения.

**ADR-2: Один список вместо двух**

- **Решение:** раскрывающаяся сетка «Все приложения» внутри меню «Пуск» удаляется, остаётся единственный полноэкранный список.
- **Альтернативы:** сохранить обе поверхности.
- **Почему:** решение владельца 2026-08-05; две параллельные сетки с разным набором возможностей пришлось бы поддерживать и объяснять пользователю.

**ADR-3: Частота запуска считается по собственному журналу лаунчера**

- **Решение:** порядок «по частоте и давности» строится на журнале запусков лаунчера.
- **Альтернативы:** системная статистика использования по всем приложениям.
- **Почему:** системная статистика требует особого разрешения, которое пользователь выдаёт вручную в настройках Android; собственный журнал уже ведётся и разрешений не требует, ценой того, что запуски мимо нашего лаунчера не учитываются.

**ADR-4: Жест уступает прокрутке**

- **Решение:** свайп снизу-вверх открывает список только когда рабочий стол находится в верхнем положении.
- **Альтернативы:** узкая зона распознавания у нижней кромки экрана; отказ от жеста.
- **Почему:** решение владельца 2026-08-05; так ведёт себя большинство лаунчеров, а узкая нижняя полоса соседствует с системными жестами Android.

## 11. Критерии готовности (strategic-level)

1. Рядом с кнопкой «Пуск» есть иконочная кнопка, открывающая список всех приложений на весь экран.
2. Свайп снизу-вверх по свободному месту рабочего стола открывает тот же список, когда стол находится в верхнем положении, и возвращает стол наверх, когда он прокручен.
3. Список открывается без индикатора загрузки и без видимой задержки, в том числе при первом открытии после перезагрузки телефона.
4. Ввод части названия в строку поиска сужает список по мере набора; при отсутствии совпадений видно понятное пустое состояние.
5. Порядок списка переключается между названием, датой установки, датой обновления, частотой и давностью запуска и категорией, и выбранный порядок сохраняется после перезапуска приложения.
6. Короткое нажатие на приложение запускает его; долгое открывает меню с пунктами «Запустить», «На рабочий стол», «Закрепить на панели задач», «Сведения о приложении», «Удалить» и сценариями самого приложения.
7. «На рабочий стол» помещает приложение на первое свободное место рабочего стола, «Закрепить на панели задач» - на панель задач.
8. Установка, удаление или обновление приложения отражается в списке без ручного обновления.
9. В меню «Пуск» больше нет строки «Все приложения» и встроенной сетки.
10. Экран корректно выглядит и полностью проходим клавиатурой, D-pad и мышью в портрете и в ландшафте, не залезая под системные панели.
11. Все новые строки присутствуют в EN, RU и UK.
