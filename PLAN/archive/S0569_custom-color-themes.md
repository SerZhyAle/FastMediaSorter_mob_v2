## 1. Проблема

В настоящее время приложение поддерживает только три цветовых режима: системный (следование системным настройкам), принудительный светлый и принудительный тёмный. Пользователи, предпочитающие индивидуальное цветовое оформление (например, тёмные или светлые интерфейсы с зелёными, синими или красными акцентами), ограничены базовыми вариантами. Отсутствует гибкость цветового брендинга интерфейса под личные предпочтения.

---

## 2. Цели

1. Расширить список доступных тем в настройках приложения, добавив тёмно-зелёную, тёмно-синюю, тёмно-красную, светло-зелёную, светло-синюю и светло-красную темы.
2. Обеспечить корректное применение выбранного цветового стиля ко всем визуальным элементам (акценты, фоны, кнопки, переключатели, диалоговые окна) на всех экранах приложения.
3. Сохранить существующие системные настройки (Auto), принудительно светлую (Light) и принудительно тёмную (Dark) темы.
4. Гарантировать персистентность новой выбранной темы при перезапуске приложения и корректное применение на этапе инициализации процесса (до отрисовки первого кадра).

**Non-goals:**

- Динамические темы на основе обоев устройства (Monet / Material You) в рамках данной задачи не внедряются.
- Темы для Wear OS-компаньона не реализуются (wear-модуль продолжает следовать системным тёмным гайдлайнам Wear OS).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Палитра тем должна соответствовать принципам Material Design 3 для обеспечения хорошей контрастности и читаемости текста.
2. Переходы между темами должны происходить через стандартный диалог перезапуска приложения (как и сейчас), чтобы избежать визуальных артефактов неполного обновления контекста.

### 3.2 Жёсткие ограничения

- **Flavor:** Применимо ко всем вариантам сборки (`standard`, `lite`, `photos`, `legacy`). Реализация не должна использовать `BuildConfig.IS_*` в `src/main` (следование `dev/FLAVOR_DEVELOPMENT_RULES.md`).
- **API level:** Поддержка тем должна работать без повышения текущего минимального API (minSdk 26 / minSdk 23 для legacy).
- **Wear OS:** Не затрагивается.
- **Производительность:** Смена темы и перезапуск не должны приводить к деградации времени холодного старта.
- **Совместимость данных:** Выбранная тема сохраняется в существующее хранилище настроек (асинхронное и синхронное хранилища настроек) в виде строки-идентификатора темы.
- **Локализация:** Названия новых тем в настройках должны быть локализованы на EN, RU и UK.
- **Доступность:** Тексты в любом оформлении должны соответствовать стандартам контрастности WCAG AA (минимальный коэффициент контрастности 4.5:1 для обычного текста).
- **Коммуникация:** Все новые пользовательские строки (названия тем в списке) должны пройти проверку по политике `docs/COMMUNICATION_POLICY.md` (§6 чеклист).

## 4. Контекст текущей архитектуры

В текущей реализации за применение темы отвечает центральный синглтон-префс, который считывает выбранную тему ("AUTO", "LIGHT", "DARK") из быстрого хранилища при старте приложения (до инициализации первого экрана) и вызывает системный метод ночного режима. Все базовые экраны наследуются от общего класса, который применяет дополнительные оверлеи (например, для компактного режима диалогов).

Однако текущая схема ориентирована исключительно на стандартные системные режимы (тёмный, светлый и системный). Системный механизм Android не поддерживает «тёмно-зелёную» или «светло-красную» тему из коробки через стандартное переключение. Для реализации кастомных цветовых палитр необходимо совместить переключение ночного режима (чтобы использовать правильные ресурсы day/night) с динамическим наложением стилей/оверлеев (Theme Overlay) на контекст экрана.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

1. **Расширенный реестр тем:** Расширение перечня возможных значений темы в модели настроек и механизме синхронного зеркалирования старта.
2. **Стилистические оверлеи (Theme Overlays):** Определение в ресурсах оверлеев для каждой из 6 новых тем. Оверлеи переопределяют ключевые Material 3 цвета (colorPrimary, colorSurface, android:windowBackground и т.д.) поверх базовой светлой или тёмной темы приложения.
3. **Компонент динамического применения тем:** Архитектурная роль (вызываемая в базовом экране при его создании), которая считывает сохранённую тему, применяет соответствующий режим ночи (светлый для light-акцентированных тем, тёмный для dark-акцентированных тем) и накладывает соответствующий оверлей темы на текущий экран.

### 5.2 Потоки данных и событий

Старт приложения -> Чтение темы из быстрого хранилища -> Применение ночного режима -> Запуск экрана -> Инициализация базового экрана -> Определение нужного оверлея по значению темы -> Применение оверлея к экрану -> Отрисовка контента.
Смена темы в настройках -> Выбор нового значения в списке -> Показ диалога подтверждения -> Сохранение в настройки -> Запись в быстрое хранилище старта -> Перезапуск приложения.

### 5.3 Точки расширяемости

- Добавление новых цветовых комбинаций в будущем потребует только объявления нового XML-стиля и регистрации его в реестре тем, без изменения логики применения в базовом активити.

## 9. Архитектурные решения (ADR)

**ADR-1: Применение тем через Theme Overlay**

- **Решение:** Использовать механизм динамического наложения стилей в базовом экране для динамического наложения цветовых оверлеев поверх базовой темы приложения.
- **Альтернативы:** Использование раздельных полноценных тем для каждого цвета в конфигурации манифеста.
- **Почему:** Механизм оверлеев значительно сокращает дублирование XML-кода, так как все базовые размеры, шрифты и поведение наследованы от основной темы, а оверлей меняет только цвета.

## 11. Критерии готовности (strategic-level)

1. В выпадающем списке «Цветовая тема» настроек присутствуют все 6 новых вариантов на трёх языках (EN, RU, UK).
2. При переключении темы и подтверждении перезапуска приложение успешно перезагружается, и все экраны (Browse, Settings, Player и др.) отображаются в выбранной цветовой гамме.
3. Цвета кнопок, фонов диалогов, текста и выделения соответствуют выбранной теме (например, в тёмно-зелёной теме акцентные элементы зелёные, а фон тёмно-зелёный/серый).
4. Настройки темы успешно сохраняются и восстанавливаются после полного закрытия и повторного запуска приложения.
