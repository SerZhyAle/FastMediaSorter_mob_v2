## Контекст и цель этого документа

S0151 и S0155 были написаны и частично реализованы, однако программа ведёт себя неверно:

- При получении ссылки из Instagram/Threads программа беспорядочно пытается извлечь авторизацию, тогда как в открытом окне встроенного браузера соцсеть уже работает нормально — то есть рабочие куки программа даже не пытается применить.
- Предложение авторизации появляется тогда, когда не нужно, и не появляется, когда нужно.
- Логика взаимодействия с хранилищем авторизаций запутана и непредсказуема.

**Цель этого документа** — описать желаемый сценарий чистым языком, без привязки к существующей реализации (которая будет удалена). Владелец утвердил поведение; следующий шаг — тактическая спека и реализация с нуля.

## 1. Термины и сущности

| Термин | Определение |
|--------|-------------|
| **Ссылка** | URL, пришедший через системный Intent SEND / VIEW из другого приложения |
| **Известная соцсеть** | Хост, для которого в приложении прописан явный тип источника (Instagram, Threads) — не эвристика, а явный список, прошитый в сборке |
| **Неизвестная соцсеть / произвольный хост** | Хост, для которого в приложении нет заранее прописанного типа источника; обрабатывается стандартным конвейером |
| **Реальное медиа** | Видео, изображение или набор изображений (карусель), являющихся основным контентом поста; НЕ превью-картинка из Open Graph / метатегов |
| **Превью** | Картинка из Open Graph (`og:image`) или аналогичного метатега — обложка поста, не его контент |
| **Авторизованная сессия** | Набор cookie/токенов для конкретного аккаунта на конкретном хосте, сохранённых зашифровано |
| **Запись авторизации** | Одна строка в хранилище: хост + идентификатор аккаунта (если известен) + зашифрованные данные сессии |
| **Пустая запись (отказ)** | Запись с нулём куков — создаётся по кнопке [Не предлагать]; означает осознанный отказ пользователя от авторизации для данного хоста |
| **Хранилище авторизаций** | Зашифрованное локальное хранилище записей авторизаций |
| **Предложение входа** | Диалог, предлагающий пользователю войти через встроенный браузер |
| **Повторный вход** | Предложение обновить существующую запись авторизации — появляется, когда сессия была, но реального медиа не дала |
| **Отказ** | Пользователь явно нажал [Отмена] в диалоге предложения входа — не создаёт запись в хранилище |
| **Промах сессии** | Сессия есть, была применена, но реальное медиа не получено — как правило, из-за недостаточного кода парсинга страницы данной соцсети (не обязательно истёкшая сессия) |

## 2. Полный сценарий: получение ссылки

Ниже описан сценарий пошагово — от момента получения Intent до конечного результата.

---

### Шаг 0. Приходит Intent с URL

Приложение получает ссылку. Определяется тип хоста.

**Не известная соцсеть:**
Выполняется стандартный конвейер извлечения медиа. Дополнительно: если конвейер не нашёл реальное медиа или нашёл только превью, приложение предлагает пройти авторизацию и сохранить куки для этого хоста (через встроенный браузер) — с теми же кнопками [Войти] / [Отмена] / [Не предлагать].

**Известная соцсеть:**
Для неё может быть заранее написан специфичный код парсинга страницы (структура DOM, GraphQL-эндпоинты и т.п.). Переходим к Шагу 1.

Список известных соцсетей жёстко прошит в сборке; расширяется только обновлением приложения.

---

### Шаг 1. Проверка хранилища авторизаций

Приложение смотрит в хранилище авторизаций по хосту ссылки. Записи сортируются по дате добавления / обновления (обратный порядок — самая свежая первая).

#### Вариант Ё: Есть запись с нулём куков (пустая запись — осознанный отказ)

Пользователь ранее выбрал [Не предлагать] для этого хоста. Предложение входа не показывается. Запускаем стандартный конвейер — берём первое, что получится (даже если это превью), и завершаем.

#### Вариант A: Записей для хоста нет

Авторизаций не было. Переходим к **Шагу 4 (Предложение первичного входа)**.

#### Вариант B: Есть ровно одна запись для хоста (с куками)

Переходим к **Шагу 2**, используя эту запись.

#### Вариант C: Есть несколько записей для хоста (с куками)

Показываем диалог выбора аккаунта — пользователь выбирает явно. Записи в диалоге упорядочены: самая свежая (последнее обновление) — первая. После выбора переходим к **Шагу 2** с выбранной записью.

---

### Шаг 2. Попытка получить реальное медиа с применением сохранённой сессии

Встроенный браузер (WebView) загружает страницу ссылки с подставленными cookie из выбранной записи авторизации. Пользователь этого не видит — WebView работает фоново.

После загрузки страницы производится **анализ DOM / сети** с целью извлечь реальное медиа:
- Видео-URL из тега `<video>`, из GraphQL-ответа, из перехваченных сетевых запросов страницы.
- Изображения карусели (несколько `<img>` с признаком публикации).

**Что НЕ считается реальным медиа:**
- Единственный элемент — `og:image` (Open Graph превью).
- `og:image` + декоративные иконки / аватары.
- Страница логина или стена подписки.

**Результаты анализа:**

| Результат | Следующий шаг |
|-----------|--------------|
| Реальное медиа найдено | → Шаг 3 (Скачивание) |
| Найдено только превью (og:image) | → Шаг 2a (Промах сессии) |
| Страница выглядит как форма входа / стена подписки | → Шаг 4 (Предложение повторного входа) |
| Ошибка сети / таймаут | → Шаг 6 (Сообщение об ошибке сети) |
| Контент пуст, нет ни медиа, ни превью (пост удалён, закрыт) | → Шаг 5 (Честное сообщение о неудаче) |

#### Шаг 2a. Только превью — промах сессии

Сессия была применена, но реальный контент не получен (только `og:image`). Это **промах сессии** — сессия может быть рабочей, но код парсинга не смог добраться до медиа.

Действие: переходим к **Шагу 4 (Предложение повторного входа)**.

---

### Шаг 3. Скачивание реального медиа

Медиа найдено. Скачивание ставится в очередь и выполняется стандартным конвейером в выбранный ресурс хранилища (фоново).

Приложение немедленно отдаёт фокус обратно вызвавшему приложению (соцсети) — пользователь продолжает скроллить и может шарить следующие ссылки, пока предыдущая скачивается в фоне.

По завершении скачивания — тост с результатом; уведомление не «висит» дольше необходимого.

Лог: `[S0166] download started: real media, url=..., host=instagram.com, account=@user`

**Конец сценария.**

---

### Шаг 4. Предложение первичного входа или повторного входа

Показывается диалог. Идентификатор аккаунта подставляется, если известен; если нет — показывается только хост.

**При первичном входе (записей для хоста нет):**
> «Для скачивания контента с [instagram.com] требуется войти в аккаунт. Войти сейчас?»
> **[Войти]** · **[Отмена]** · **[Не предлагать]**

**При повторном входе (сессия была, но дала промах):**
> «Сохранённая сессия для [@account · instagram.com] не дала результата — возможно, устарела. Войти сейчас?»
> **[Войти]** · **[Отмена]** · **[Не предлагать]**

Если идентификатор аккаунта неизвестен — диалог содержит только хост («для instagram.com»).

#### Поведение кнопок:

| Кнопка | Действие |
|--------|----------|
| **[Войти]** | → Шаг 4a (Встроенный браузер для входа) |
| **[Отмена]** | Запускаем стандартный конвейер — берём первое, что получится (даже превью), завершаем. Существующие записи в хранилище не трогаем, пустую запись не создаём. |
| **[Не предлагать]** | Создаём пустую запись (нулевые куки) для этого хоста. Затем запускаем стандартный конвейер — берём первое, что получится (даже превью), завершаем. При следующей ссылке с этого хоста срабатывает Вариант Ё (Шаг 1) — диалог больше не показывается. |

---

### Шаг 4a. Пользователь нажал [Войти]

Открывается встроенный браузер для входа (существующий компонент).

Завершение входа — по действию пользователя: он вошёл в аккаунт и нажимает **[Сохранить авторизацию]** в интерфейсе приложения.

После сохранения:
- Запись авторизации в хранилище создаётся (если новая) или обновляется (если повторный вход).
- Идентификатор аккаунта (имя пользователя) извлекается из DOM страницы профиля после входа и сохраняется в запись. Если извлечь не удалось — запись сохраняется без идентификатора.

Затем: автоматически возврат к **Шагу 2** с новой сессией и повторная попытка скачивания — без лишних действий от пользователя.

---

### Шаг 5. Честное сообщение о неудаче

Применяется когда: после применения авторизации страница вернула пустой результат (нет ни медиа, ни превью — пост удалён, аккаунт закрыт).

**Когда пользователь авторизован, но контент недоступен:**
> «Контент по этой ссылке недоступен — возможно, пост удалён или аккаунт закрыт.»

Уведомление дружелюбное, не алармовое (чек-лист `docs/COMMUNICATION_POLICY.md §6`).

**Логирование при неудаче:** в лог пишется максимум диагностической информации даже в релизной сборке — URL, хост, тип аккаунта, что было найдено в DOM, какой результат вернул анализ. Это необходимо для последующего улучшения парсинга конкретных соцсетей по реальным логам.

---

### Шаг 6. Сообщение об ошибке сети

Если загрузка страницы не удалась из-за сети (таймаут, нет соединения):
> «Нет соединения или сервер недоступен. Проверьте интернет и попробуйте снова.»

Стандартный тост/диалог сети. Не специфично для соцсетей.

## 3. Хранилище авторизаций: логическая структура

Это не описание Room-схемы, а описание того, что хранится.

### Одна запись авторизации:

| Поле | Описание | Обязательное? |
|------|----------|:-------------:|
| Хост | `instagram.com`, `threads.com`, `threads.net` и т.п. — домен без пути | ✓ |
| Идентификатор аккаунта | `@username` или отображаемое имя, как площадка его называет | Нет |
| Зашифрованные данные сессии | Cookie/токены | ✓ (пустые для записей-отказов) |
| Дата последнего успешного использования | Когда с этой сессией удалось достать реальное медиа | Нет |
| Дата добавления / последнего обновления | Когда пользователь заходил через встроенный браузер | ✓ |

### Ключевые решения по структуре:

- `threads.net` и `threads.com` хранятся как **отдельные записи** (разные хосты). Пользователь при необходимости добавляет авторизации для каждого.
- Для одного хоста может быть несколько записей (несколько аккаунтов). Каждая управляется независимо.
- Пустая запись (нулевые куки) — полноценная запись в хранилище; отличается от обычной только отсутствием данных сессии. Отображается в Настройках как «Вход отклонён».

## 4. Настройки: экран управления авторизациями

Раздел уже существует (S0116/S0144). Требуется доработка.

### Информационный блок над списком (новый)

Над списком добавляется текстовое описание — что такое хранилище авторизаций, для чего нужны записи-отказы (с нулём куков), и как добавить авторизацию для второго аккаунта на том же хосте. Это необходимо, так как без пояснения записи-отказы выглядят как сломанные.

### Желаемый вид списка:

```
  instagram.com
    @myaccount · последнее успешное использование: 10 мая 2026
    [Войти заново]  [Удалить]

  instagram.com
    @workaccount · последнее успешное использование: 2 мая 2026
    [Войти заново]  [Удалить]

  threads.com
    (имя неизвестно) · добавлено 11 мая 2026
    [Войти заново]  [Удалить]

  threads.net
    (вход отклонён) · добавлено 9 мая 2026
    [Удалить]
```

### Кнопка «Добавить аккаунт»

Уже частично реализована. Должна позволять полноценно залогинить через встроенный браузер любое число аккаунтов для любого известного хоста или произвольного хоста, введённого вручную. Добавленная сессия сохраняется как новая запись — не затирает существующие.

## 5. Диагностика (логирование)

| Событие | Метка в логе |
|---------|-------------|
| Получена ссылка, хост определён как известная соцсеть | `[S0166] known social: host=instagram.com` |
| Получена ссылка, хост не является известной соцсетью | `[S0166] unknown host, standard pipeline: host=example.com` |
| Записей для хоста нет | `[S0166] no stored auth for host` |
| Найдена пустая запись (отказ) | `[S0166] rejection record found for host, skipping auth dialog` |
| Показан диалог выбора аккаунта (несколько записей) | `[S0166] account picker shown: count=2, host=instagram.com` |
| Используется запись с аккаунтом | `[S0166] applying session: host=instagram.com, account=@user` |
| Извлечено реальное медиа | `[S0166] real media found: type=video|image|carousel, url=...` |
| Найдено только превью — промах | `[S0166] preview-only result: og:image=..., treating as session miss` |
| Страница выглядит как логин / стена подписки | `[S0166] login-wall detected` |
| Контент пуст (пост удалён, закрыт) | `[S0166] empty result: no media, no preview` |
| Предложение входа показано | `[S0166] auth dialog shown: type=initial|reauth, account=@user|unknown` |
| Пользователь нажал [Войти] | `[S0166] auth accepted` |
| Пользователь нажал [Отмена] | `[S0166] auth dismissed (no record created)` |
| Пользователь нажал [Не предлагать] | `[S0166] auth dismissed with rejection record created` |
| Вход через встроенный браузер успешен | `[S0166] browser login saved: account=@user|unknown` |
| Скачивание поставлено в очередь | `[S0166] download queued: url=..., host=..., account=...` |
| Контент недоступен (удалён, закрыт) | `[S0166] content unavailable, user notified` |

При любой неудаче в лог пишется максимум доступной диагностики: URL, хост, аккаунт, что нашлось в DOM, HTTP-статусы, результат анализа страницы — даже в релизной сборке.

## 6. Принятые решения

| Вопрос | Решение |
|--------|---------|
| Список известных соцсетей | Жёстко прошит в сборке |
| Выбор аккаунта при нескольких | Явный диалог, список упорядочен по свежести |
| Поведение при промахе сессии | Предложение повторного входа (Шаг 4) |
| Идентификатор неизвестен | Показываем только хост |
| Повторить скачивание после входа | Да, автоматически |
| Кнопка [Отмена] | Запускает конвейер без изменений в хранилище |
| Кнопка [Не предлагать] | Создаёт пустую запись; повторных диалогов нет |
| threads.net и threads.com | Разные записи в хранилище |
| Добавить аккаунт | Через Настройки + через шаринг ссылки (обе точки входа) |
| Информационный блок в экране авторизаций | Добавить над списком |

---

## 7. Non-goals этой спеки

- Не обходить защиту площадок: контент, закрытый без авторизации, без входа не получить.
- Не строить универсальный экстрактор для всех соцсетей — фокус Instagram + Threads.
- Не трогать flavor'ы, где скачивание по ссылке отключено.
- Не делать Wear OS.
- Не реализовывать экспорт/импорт авторизаций между устройствами.
- Не рассматривать реализацию: код будет написан с нуля после утверждения этого документа.
