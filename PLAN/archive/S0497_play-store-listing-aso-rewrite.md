### 1. Problem

Current state of the listing source (`fastlane/metadata/android/{en-US,ru-RU,uk-UA}/`):

- All texts are within Play hard limits (title <=30, short <=80, full <=4000):
  - en full 2631, ru full 2659, uk full 2654 chars - ~1300 chars of unused budget.
- The full description is written for **IzzyOnDroid**, not Play. ~40% of it is an
  "Anti-Features / non-free dependencies / licenses / source link" block that is mandatory
  for F-Droid/IzzyOnDroid but dead weight on Play - it burns description budget on a legal
  disclaimer instead of keywords and user benefits.
- Brand name is inconsistent: en title "Fast Media Sorter & Organizer" vs ru/uk
  "FastMedia: сортировка/сортування файлів". Splits ASO signal and recognition.
- Images live only under `en-US/images` and are shared across all locales; screenshots carry
  no localized captions. No tablet / TV screenshots despite TV + gamepad + keyboard being a
  headline capability.
- Pixel dimensions of the current assets are unverified (no ImageMagick locally) against Play
  requirements (icon 512x512, feature graphic 1024x500, screenshot min edge >=320).

Architectural constraint (critical):

- `fastlane/metadata/android/` is the publication source for **IzzyOnDroid / GitHub-store**
  (see `scripts/release/publish-github-release.ps1`, S0214/S0394) and IzzyOnDroid *requires*
  the Anti-Features block. Rewriting full_description in place under fastlane would break the
  IzzyOnDroid listing. Therefore Play needs its own listing source, decoupled from fastlane.

### 2. Goal

- A Play-optimized, keyword-forward, conversion-oriented listing for EN/RU/UK, kept in a
  Play-only source tree separate from the IzzyOnDroid fastlane metadata.
- Fresh phone screenshots with localized caption overlays (EN/RU/UK) generated by script.
- An extended uploader that publishes listing texts + images to Play via the existing
  service-account key, alongside the existing AAB/changelog publish.
- Listing live on Play for all three locales.

Out of scope:

- IzzyOnDroid / GitHub-store metadata - left untouched (keeps Anti-Features block).
- Manual marketing-design of icon and feature graphic (no designer pass requested). Feature
  graphic localization is optional/secondary; icon stays as-is.
- Changelog/release-notes flow - already handled by `publish-play-release.py`.

### 3. Proposed approach

#### 3.1 Decouple Play listing source

- Introduce a Play-only listing source, e.g. `play/listing/<locale>/{title,short_description,full_description}.txt`
  plus `play/listing/<locale>/images/`.
- Seed it from the current fastlane texts, then rewrite (3.2). fastlane stays the IzzyOnDroid source.
- Shared changelogs continue to be read from `fastlane/metadata/android/<locale>/changelogs/` by the AAB uploader.

#### 3.2 ASO text rewrite (EN/RU/UK)

- Unify the brand to a single name across all locales (decision needed - see 3.3).
- Rewrite full_description for Play: lead with the strongest benefit + primary keywords in the
  first ~250 chars (the part shown before "read more"); group capabilities for scannability;
  drop the Anti-Features / license / source-link block; spend reclaimed budget on
  keyword-bearing benefit copy. Keep every claim factually true to shipped features
  (cross-check `docs/ALL_FEATURES.jsonl` + `docs/FEATURES*.md`).
- Tighten short_description toward primary keywords (file manager, media player, photo/video,
  SMB/FTP/cloud) within 80 chars.
- Keep title within 30 chars; align with the unified brand.
- RU/UK: respect Ё/ё and `..`; native phrasing, not literal translation; same keyword intent.

### 3.3 Owner inputs (Approval gate)

- **Unified brand:** "Fast Media Sorter" across all locales (Latin brand + localized descriptor in title).
- **First listing push:** draft edit - preview in Console before committing live (also verifies the service account holds "Edit store listing" rights).
- **Keyword priorities:** delegated to ASO research per locale (no owner-mandated terms).
- **Feature graphic localization:** n/a - out of scope for now (icon + feature graphic untouched).
- **Related tickets:** S0214, S0394 (GitHub-store / IzzyOnDroid publication sharing fastlane metadata).

#### 3.4 Screenshots with localized captions

- Capture a fixed set of screens (browse, image viewer, video player, slideshow, cloud connect,
  PDF/EPUB reader, widgets) on emulator/device via the existing device tooling.
- Compose localized caption overlays (EN/RU/UK) with a script (e.g. ImageMagick / Pillow),
  output to `play/listing/<locale>/images/phoneScreenshots/`.
- Verify each asset meets Play size/format requirements before upload.

#### 3.5 Listing uploader extension

- Add a sibling script (e.g. `scripts/release/publish-play-listing.py` + `.ps1` wrapper) reusing
  the same key/auth as `publish-play-release.py`.
- Calls: `edits().insert()` -> per-locale `edits().listings().update()` (title/short/full)
  -> `edits().images().deleteall()` + `edits().images().upload()` for featureGraphic + phoneScreenshots
  (+ icon if managed here) -> `edits().commit()`.
- Support `-Track`/`-Status draft` style dry-run / preview so the first push can land as a draft
  edit for Console review before commit.
- Precondition: confirm the service account has the "Edit store listing" permission (it commits
  production AAB edits, so it almost certainly does; verify on first draft push).

### 4. Risks

- Service account may lack store-listing edit rights -> first run as a draft edit surfaces this safely.
- Image dimension mismatches rejected by the API -> validate sizes pre-upload.
- ASO rewrite drifting from real features -> cross-check ALL_FEATURES before publish.
- Accidentally editing the IzzyOnDroid source -> enforced by the separate `play/listing/` tree.

### 5. Deliverables

- `play/listing/{en-US,ru-RU,uk-UA}/` with rewritten texts + localized screenshots.
- `scripts/release/publish-play-listing.{py,ps1}`.
- Listing published (draft or production per 3.3) for all three locales.
- `docs/ALL_FEATURES.jsonl` capability record if a new shippable capability is introduced (none expected).
