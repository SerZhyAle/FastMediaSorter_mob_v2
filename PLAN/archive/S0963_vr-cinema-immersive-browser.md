## 1. Проблема

В immersive нет собственного файлового менеджера: пользователь не может внутри очков навигировать по выбранному ресурсу, видеть видеофайлы и 3D-изображения с превью и выбирать элемент для проигрывания. Диагностический путь делает ad-hoc-скан одной папки, не связанный с доменной моделью ресурсов.

---

## 2. Цели (S0773 §2, столп 2)

1. Собственное окно BROWSE в immersive: навигация по ресурсу, показ видеофайлов и 3D-изображений с превью.
2. Чтение через существующий доменный слой браузера и репозитория, а не через диагностический ad-hoc-скан.
3. 3D-изображения классифицируются существующей таксономией стерео-детекции (SBS/OU/эквирект).
4. Выбор элемента передаёт его в immersive-плеер.
5. Пункт «Открыть в VR-кинотеатре» для ресурса открывает ресурс именно в этом браузере (S0773 quiz 2026-07-05).

**Non-goals:**

- Система запуска и точки входа - столп S0962.
- HUD-дорожки - столп S0964.
- Сетевые/облачные источники в первой итерации (по решению по объёму, S0773 §5.3).

## 4. Контекст текущей архитектуры

Столп 1 (S0962) уже проложил транспорт запуска VR с точкой входа «из браузера», которая пока не задействована (ноль call-site'ов) - именно её включает этот столп. Транспорт сегодня несёт цель только как одиночный файл; цели «ресурс/директория» в нём нет, её нужно добавить, не ломая существующие режимы.

Нативная OpenXR-поверхность существует как диагностический путь. Её immersive-Activity близка к лимиту размера, сама сканирует одну тестовую папку по статическому списку имён и не связана с доменной моделью ресурсов и файлов. Нативный рантайм отдаёт ровно два текстурных канала - один медиа-квад и один HUD-квад; независимых пространственных панелей он не поддерживает без изменений нативного слоя. Шлюз входа сегодня жёстко нацелен на единственную диагностическую Activity - для нового immersive-браузера нужна ветка маршрутизации по режиму запуска.

Доменный слой браузера (use-case листинга медиа в ресурсе, отдающий поток списков файлов, с поддержкой навигации по подпапкам) - зрелая точка чтения, через которую должен читать immersive-браузер вместо диагностического ad-hoc-скана. Таксономия стерео-детекции (SBS/OU/эквирект) существует и классифицирует изображения по каскаду имя+метаданные+размеры. Пайплайн превью 2D-браузера декодирует через Glide в размер отображения; в диагностическом пути уже есть heap-бюджетный кап на декод одиночного битмапа - его идиома переиспользуется для превью в сетке.

Ключевое ограничение handoff: перезапуск целой immersive-сессии на каждый выбор элемента платит секундами OpenXR-реинициализации, поэтому переход «браузер -> плеер» должен быть in-process в пределах одной immersive-Activity, а не повторным запуском через use-case.

**Артефакт research:** `PLAN/S0963_vr-cinema-immersive-browser/research/01__immersive-browser-architecture.md` (точные классы/пути/сигнатуры/LOC для тактики).

## 5. Предлагаемый подход

Собственный immersive-браузер поверх существующего доменного слоя браузера/репозитория; рендер окна на существующей OpenXR-базе; выбор элемента -> immersive-плеер. Открыт к расширению охвата источников (локальные -> сетевые/облачные).

---

## 6. Открытые вопросы / Research items

Разрешено research (2026-07-11, артефакт `research/01__immersive-browser-architecture.md`):

1. **Форма рендера BROWSE-окна** - Resolved: сетка превью на одном Canvas-кваде (NxM RectF-ячейки, hit-test UV->pixel, как кнопки существующего HUD). Пространственные панели (несколько независимых 3D-квадов) невозможны без изменений нативного слоя - рантайм отдаёт лишь два текстурных канала (медиа-квад + HUD-квад); вне объёма.
2. **Модель превью в пределах heap-бюджета (S0772 7K OOM)** - Resolved: Glide `asBitmap().override(cellW,cellH)` в пиксельный размер ячейки, композиция на Canvas сетки, проброс через существующий канал квада; кап footprint одного битмапа - существующей идиомой heap-бюджета диагностического пути; декод по требованию только для видимых ячеек.
