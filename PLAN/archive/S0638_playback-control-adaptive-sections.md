## 1. Проблема

Диалог управления плеером содержит до 7 секций (громкость, аудио, субтитры, 3D, оттенок, яркость, скорость). Селектор секций имеет фиксированную ориентацию, которая не помещается ни в одной из ориентаций экрана.

- В портрете селектор - горизонтальная лента с прокруткой без видимого индикатора: на экран попадает примерно треть секций, остальные нужно «сдвигать» вслепую, и пользователь не понимает, что лента скроллится.
- В ландшафте селектор - вертикальный рельс фиксированной ширины, а высота диалога не ограничена высотой экрана: нижние секции уходят за нижнюю кромку и становятся физически недоступными - до части регуляторов (например, скорость, яркость) нельзя добраться вообще.

Итог: набор секций неполно доступен в обеих ориентациях, навигация воспринимается как сломанная.

---

## 2. Цели

1. Любая секция выбирается одним нажатием и сразу показывает всё своё содержимое.
2. Селектор секций полностью доступен в обеих ориентациях - ни одна секция не уходит за край экрана и не требует слепой прокрутки.
3. Селектор адаптируется к ориентации экрана: использует ту ось, где есть запас места (широкий горизонтальный селектор в ландшафте, вертикальный - в портрете).
4. Диалог не выходит за пределы экрана по высоте ни в одной ориентации; при нехватке места прокручивается предсказуемо.
5. Поведение одинаково корректно при изменяющемся числе активных секций (аудио/2 секции против видео/до 7 секций).

**Non-goals:**

- Не менять набор секций, их содержимое и логику применения значений.
- Не трогать оформление самих бегунков (толщина дорожки, размер ползунка) - это отдельный тикет S0619.
- Не вводить новые пользовательские строки, если выбранный вариант их не требует.
- Не затрагивать другие диалоги и экраны плеера.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Формат «пивот»: в ландшафте селектор выводится горизонтально, в портрете - вертикально.
2. Один тап по разделу сразу открывает раздел со всем содержимым, без промежуточных шагов.
3. Сохранить узнаваемость текущего вида диалога - меняется компоновка навигации, а не визуальный язык приложения.

### 3.2 Жёсткие ограничения

- **Flavor:** диалог - часть общего плеера в `src/main`; изменение затрагивает все сборки с видеоплеером. Флейвор-специфичного кода не требуется, источниковые наборы флейворов не задействуются. Секция 3D остаётся условной (показывается при VR-сборке или стереоконтенте), и навигация обязана корректно работать при её отсутствии.
- **API level:** без API-специфики, поведение одинаково на всех поддерживаемых уровнях Android.
- **Wear OS:** не затрагивается.
- **Производительность:** без заметного влияния, изменение чисто компоновочное.
- **Совместимость данных:** не затрагивается; сохранённый выбор последней секции продолжает восстанавливаться при открытии.
- **Локализация:** EN/RU/UK обязательны для любых новых строк; предпочтительно обойтись существующими подписями секций.
- **Доступность:** навигация с клавиатуры и D-pad/TV сохраняется; область нажатия каждого пункта селектора не меньше рекомендованного минимума; выбранный пункт различается не только цветом; содержимое остаётся в безопасных границах системных панелей и выреза.

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** адаптивный пивот «мастер-деталь». Ландшафт - горизонтальная лента секций сверху + область контента под ней. Портрет - вертикальный рельс секций слева + область контента справа. Один тап по пункту сразу показывает всё содержимое секции; селектор всегда виден целиком, при нехватке места прокручивается только он (с видимым индикатором), пункты всегда с иконкой и подписью.
- **Accessibility:** эффективная область нажатия пункта селектора >= 48dp; выбранный пункт различим по форме/состоянию, не только по цвету; фокус с клавиатуры и D-pad/TV сохраняется и обходит все секции; пункт всегда несёт видимую подпись (режим «только иконка» не используется).
- **Validation level:** ручная проверка на устройстве в обоих ориентациях - доступность и выбор каждой активной секции одним нажатием, плюс случай аудио (сокращённый набор секций).
- **Owner sign-off:** 2026-06-23.
- **Related tickets:** S0619 (широкие бегунки в том же диалоге) - смежный, не блокирующий.

## 4. Контекст текущей архитектуры

За диалог отвечает слой UI плеера: один фрагмент-диалог собирает все секции из единой разметки и переключает их видимость по выбору в группе кнопок-секций. Разметка существует в двух вариантах - портрет и ландшафт; в каждом жёстко задана ориентация селектора (горизонтальная лента в портрете, вертикальный рельс в ландшафте). Размер окна диалога задаётся в коде только по ширине, высота остаётся «по содержимому». Поэтому проблему нельзя решить точечной правкой: в портрете лента переполняет ширину, в ландшафте рельс переполняет неограниченную высоту - оба дефекта заложены в самой схеме компоновки селектора и окна.

---

## 5. Предлагаемый подход

Перестроить навигацию по секциям так, чтобы селектор использовал ось с запасом места и оставался полностью доступным, а выбор любой секции одним нажатием сразу показывал её содержимое. Окно диалога ограничивается высотой экрана, а переполнение (если возникает) уходит в предсказуемую прокрутку только области контента, но не самого селектора - селектор всегда виден целиком.

Паттерн селектора зафиксирован: адаптивный пивот «мастер-деталь» (см. §9 ADR-1) - горизонтальная лента сверху в ландшафте, вертикальный рельс слева в портрете, контент рядом. Ниже сформулированы инварианты этого паттерна.

### 5.1 Основные столпы / модули

- **Адаптивный селектор секций.** Раскладка селектора зависит от ориентации: горизонтальная в ландшафте, вертикальная в портрете. В каждой ориентации все активные секции достижимы без слепой прокрутки и без ухода за край экрана.
- **Ограничение окна по высоте.** Диалог не превышает доступную высоту экрана; область контента секции прокручивается при нехватке места, селектор остаётся закреплён и виден полностью.
- **Динамический состав секций.** Селектор корректно отображает переменное число активных секций (аудио против видео, наличие/отсутствие 3D) без пустот и разрывов навигации.

### 5.2 Потоки данных и событий

Нажатие пункта селектора -> выбор секции -> немедленный показ содержимого этой секции и скрытие прочих -> существующая логика применения значений не меняется. Выбранная секция сохраняется и восстанавливается при повторном открытии, как сейчас.

### 5.3 Точки расширяемости

- Схема навигации должна выдерживать добавление/удаление секции без переписывания компоновки.
- Параметры адаптации (когда селектор горизонтальный, когда вертикальный) держать в одном месте, чтобы при необходимости подстроить пороги без правки каждой секции.

## 6. Открытые вопросы / Research items

1. **Паттерн селектора секций**
   - **Вопрос:** какой паттерн навигации обеспечивает «один тап -> секция со всем содержимым» и полную доступность всех секций в обеих ориентациях?
   - **Варианты:**
     - (а) Адаптивный пивот «мастер-деталь»: в ландшафте горизонтальная лента секций сверху + контент под ней; в портрете вертикальный рельс слева + контент справа. Соответствует прямому пожеланию владельца.
     - (б) Аккордеон: вертикальный список секций, нажатие раскрывает содержимое прямо под заголовком, прочие сворачиваются - одинаково в обеих ориентациях.
     - (в) Выпадающий список секций: компактный селектор-список в одну строку, под ним контент - одинаково в обеих ориентациях; компромисс по «одному тапу» (открыть + выбрать).
   - **Нужно выяснить:** какой паттерн владелец выбирает; согласуется ли он с поведением вертикальных/горизонтальных бегунков внутри секций.
   - **Статус:** Resolved - выбран вариант (а), адаптивный пивот «мастер-деталь»: горизонтальная лента сверху в ландшафте, вертикальный рельс слева в портрете, контент рядом.

2. **Поведение при переполнении выбранного селектора**
   - **Вопрос:** что происходит, если даже на «правильной» оси все секции не помещаются (узкий ландшафт по высоте / очень маленький экран)?
   - **Варианты:** прокрутка только селектора с явным индикатором; сжатие пунктов (иконка без подписи); перенос пунктов в несколько рядов/колонок.
   - **Нужно выяснить:** допустимый минимальный размер пункта и приоритет «подпись против компактности».
   - **Статус:** Resolved - прокручивается только селектор с видимым индикатором; пункты сохраняют иконку и подпись, не сжимаются до иконок и не переносятся в несколько рядов.

3. **Подписи и иконки пунктов в компактном режиме**
   - **Вопрос:** допустимо ли в портрете показывать пункты только иконками (с подписью в content-description) ради места под контент, или подпись обязательна всегда?
   - **Нужно выяснить:** требование владельца к читаемости против компактности.
   - **Статус:** Resolved - подпись обязательна всегда; режим «только иконка» не используется, при нехватке места выбирается прокрутка селектора (см. п.2).

## 9. Архитектурные решения (ADR)

**ADR-1: Адаптивный пивот «мастер-деталь» для селектора секций**

- **Решение:** селектор секций меняет ориентацию по экрану - горизонтальная лента сверху в ландшафте, вертикальный рельс слева в портрете; контент секции показывается рядом и сразу по одному нажатию. При нехватке места прокручивается только селектор (с видимым индикатором); пункты всегда несут иконку и подпись.
- **Альтернативы:** аккордеон (вертикальный список с инлайн-раскрытием); выпадающий список секций.
- **Почему:** пивот использует ось с запасом места в каждой ориентации и устраняет оба исходных дефекта (переполнение ширины в портрете, переполнение высоты в ландшафте), сохраняя «один тап -> секция со всем содержимым» и постоянную видимость контента рядом с навигацией. Аккордеон скрывает контент за раскрытием и хуже работает в широком ландшафте; выпадающий список требует двух нажатий на переключение.

### Quiz decisions (2026-06-23)

- Паттерн селектора секций -> Адаптивный пивот «мастер-деталь» (использует ось с запасом места, один тап, контент всегда виден; отвергнуты аккордеон и выпадающий список).
- Поведение при нехватке места -> Подпись + прокрутка: пункты сохраняют иконку и подпись, при переполнении прокручивается только селектор с видимым индикатором (отвергнуты «только иконки» и перенос в ряды/колонки).

## 11. Критерии готовности (strategic-level)

1. В портрете все активные секции доступны и выбираются одним нажатием без слепой прокрутки.
2. В ландшафте все активные секции доступны и выбираются одним нажатием; ни одна не уходит за край экрана.
3. Селектор адаптируется к ориентации: горизонтальный в ландшафте, вертикальный в портрете.
4. Диалог не превышает высоту экрана ни в одной ориентации; при нехватке места прокручивается только область контента.
5. Навигация корректна и при сокращённом наборе секций (аудио), и при полном (видео с 3D).
6. Выбор последней секции восстанавливается при повторном открытии.
7. Навигация по секциям проходится с клавиатуры и D-pad/TV.
