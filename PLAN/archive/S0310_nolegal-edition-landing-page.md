## 1. Проблема

У проекта есть публичный сайт на GitHub Pages (главная `index` на трёх языках), который описывает возможности `standard` и VR-сборок, но не раскрывает sideload-only сборку `noLegal`. Её возможности задокументированы только в локальных gitignored-файлах и нигде публично не представлены.

Владельцу нужна отдельная публичная страница, которая объясняет, что реализовано в `noLegal` относительно VR-версии и чем `noLegal` отличается от `standard`. Страница должна быть опубликована, но не должна рекламироваться с главной: на неё не ведут ссылки с `index`, при этом сама она может ссылаться на другие страницы основного сайта.

Область: статический сайт GitHub Pages в ветке `main`. Кода приложения изменения не затрагивают.

---

## 2. Цели

1. Появляется отдельная публичная страница про `noLegal`-версию на трёх языках (EN/RU/UK) с переключателем языков.
2. Страница объясняет топологию сборок: `standard ⊂ vr ⊂ noLegal` - что наследуется от VR и что добавлено сверх неё.
3. Страница перечисляет noLegal-only возможности и для каждой коротко поясняет, почему она недоступна в магазинных сборках.
4. Страница достижима по прямому URL и индексируется поисковиками (решение владельца), но на неё нет входящих ссылок с `index`.
5. С noLegal-страницы есть исходящие ссылки на релевантные страницы основного сайта (загрузки, FAQ, VR-материалы, исходники).
6. Дизайн визуально согласован с существующим сайтом (та же палитра, типографика, шапка, переключатель языков).

**Non-goals:**

- Публикация локальных gitignored-инвентарей (`docs/FEATURES_noLegal*.md`) как есть - страница пишется отдельно, на основе их содержимого.
- Любые изменения кода приложения, флейвор-сорссетов или сборочной конфигурации.
- Добавление ссылки на noLegal-страницу с `index` или из навигации основного сайта.
- Инструкции по обходу лицензий/политик магазинов - страница описывает возможности, а не способы их распространения.

4. Полный перечень всех noLegal-возможностей с техническими деталями (решение владельца 2026-05-30) - страница раскрывает реализацию, а не только витрину.

## 4. Контекст текущей архитектуры

Публичный сайт - это статический GitHub Pages (Jekyll, тема Cayman + кастомные стили), обслуживаемый из корня репозитория в ветке `main`. Главная состоит из трёх языковых страниц с общим переключателем, единым стилевым файлом, SEO-разметкой (Open Graph, hreflang, canonical) и общим `sitemap.xml`. Возможности `standard`/VR подаются через интерактивный explorer, читающий канонический инвентарь фич.

Возможности `noLegal` сознательно отсутствуют в публичных инвентарях: они зафиксированы только в gitignored-файлах. Поэтому сейчас нет ни одного публичного артефакта, описывающего `noLegal`, и нет страницы-носителя для такого описания - её нужно создать заново, повторно используя существующую дизайн-систему сайта.

## 5. Предлагаемый подход

Создаётся отдельный набор статических языковых страниц (EN/RU/UK), визуально наследующих дизайн-систему существующего сайта (шапка, палитра, типографика, переключатель языков, SEO-разметка), но содержательно посвящённых только `noLegal`. Контент пишется заново на основе локальных инвентарей; сами инвентари не публикуются.

### 5.1 Основные столпы / модули

- **Языковой триплет страниц.** Три согласованные по содержанию страницы EN/RU/UK с общим переключателем языков и взаимными hreflang-связями только между собой.
- **Блок топологии сборок.** Наглядное объяснение `standard ⊂ vr ⊂ noLegal`: что уже есть в `standard`, что добавляет VR, что добавляет `noLegal` поверх VR.
- **Каталог noLegal-возможностей.** Полный перечень реализованных noLegal-only функций с техническими деталями и причиной «почему не в магазине» для каждой (решение владельца - публиковать с деталями).
- **Исходящие связи.** Ссылки на основной сайт: главная (`index` соответствующего языка), VR-материалы, загрузки/FAQ, исходники на GitHub. Обратной ссылки с `index` на noLegal-страницу нет.
- **SEO/обнаружимость.** Индексируемая разметка и записи в `sitemap.xml` для трёх языков, изолированная hreflang-группа noLegal-страниц.

### 5.2 Потоки данных и событий

Статический контент; runtime-потоков данных нет. Источник истины для текста - локальные инвентарь-документы noLegal и материалы VR; они переводятся в публичные формулировки вручную. Переключатель языков и SEO-связи работают так же, как на существующих страницах сайта.

### 5.3 Точки расширяемости

- Каталог возможностей строится так, чтобы добавление новой noLegal-функции означало добавление одной записи в трёх языковых версиях.
- Дизайн-токены и переключатель языков переиспользуются из существующего стиля сайта, без форка стилевой системы.
- Структура страницы допускает будущее вынесение повторяющегося контента в общий механизм сайта без переписывания.

## 9. Архитектурные решения (ADR)

**ADR-1: Отдельная страница, а не секция на `index`**

- **Решение:** noLegal описывается на собственном триплете страниц, не на главной.
- **Альтернативы:** добавить вкладку/секцию в существующий explorer на `index`.
- **Почему:** требование владельца - отсутствие входящих ссылок и рекламы с главной; обособленная страница не нарушает навигацию основного сайта.

**ADR-2: Индексируемая, но не связанная с `index`**

- **Решение:** `robots: index, follow` + записи в `sitemap.xml`, но без обратных ссылок с главной.
- **Альтернативы:** скрытая (`noindex`, вне sitemap) страница.
- **Почему:** прямой выбор владельца 2026-05-30 в пользу SEO-обнаружимости при сохранении отсутствия рекламы с главной.

**ADR-3: Полный перечень с деталями; файлы-инвентари остаются приватными**

- **Решение:** публичная страница раскрывает все noLegal-возможности с техническими деталями; при этом сами `FEATURES_noLegal*.md` остаются gitignored, текст пишется отдельно.
- **Альтернативы:** курируемый поднабор без деталей; прямая публикация `FEATURES_noLegal*.md`.
- **Почему:** прямой выбор владельца 2026-05-30 - полнота и техническая детализация важнее сокрытия; граница проводится по «как распространять/обходить», а не «что реализовано».

## 11. Критерии готовности (strategic-level)

1. По прямому URL открываются три языковые версии noLegal-страницы (EN/RU/UK), переключатель языков работает между ними.
2. Страница визуально согласована с существующим сайтом (шапка, палитра, типографика).
3. На странице явно показано, что добавляет `noLegal` относительно VR и чем отличается от `standard`.
4. Для каждой перечисленной возможности есть краткое пояснение «почему не в магазине».
5. С `index` нет ни одной входящей ссылки на noLegal-страницу.
6. С noLegal-страницы работают исходящие ссылки на согласованные страницы основного сайта.
7. Страница индексируема и присутствует в `sitemap.xml` для всех трёх языков, hreflang связывает только три noLegal-страницы.
8. Изменения опубликованы в ветке `main` и доступны на GitHub Pages.
