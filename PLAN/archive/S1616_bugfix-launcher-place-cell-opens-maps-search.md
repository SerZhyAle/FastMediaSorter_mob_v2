## 0. Захваченный материал (inbox)

**Захвачено:** 2026-08-13

**Текст:**

> нужно починить механизм создания РВК лаунчера при получении точки из Google Maps. Такой RV создается, но при нажатии на него вместо того, чтобы открыть дорога к от текущего состояния местоположения к данной точке. Вместо этого открывается поиск в Google Maps. Там введена строичка это из Rv. Ну, то есть тут надо чуть-чуть починить это не то. Создай короткую быструю спецификацию про это.

---

## 1. Проблема / симптом

- Флейворы с лаунчером - `standard`, `noLegal` (`SUPPORT_LAUNCHER`, `docs/FLAVOR_MATRIX.md`); в остальных пути нет.
- Основную часть захвата закрыл S1585 (`BlockNeedUserTest`): приоритет разбора перевёрнут, короткая ссылка Карт разворачивается в координаты при создании ячейки, нажатие открывает навигацию. Шара, ссылку которой удалось развернуть, поиска больше не открывает.
- Осталась ветка отказа разворота: сети нет, формат ссылки чужой или разворот не отдал координат. Ячейка тогда создаётся как «показ места», а её нажатие открывает в Google Картах поиск по тексту самой ссылки.
- Это ровно тот экран поиска, ради которого заведён тикет, и ровно тот случай, который владелец будет проверять по статус-ноте S1585 («check the airplane-mode case too»).

---

## 2. Корневая причина

- `SHOW_PLACE` исполняется как `geo:0,0?q=<query>` (`ExecuteLauncherCommandUseCase.kt:219-222`). Параметр `q` в схеме `geo:` - поисковая строка, а не адрес ресурса.
- В ветке отказа `query` - сам URL (`LauncherPlaceShareManager.kt:69`), поэтому Карты ищут текст `https://maps.app.goo.gl/..` и показывают пустой результат поиска.
- Цель 4 S1585 («шара, из которой точку установить не удалось, всё равно порождает ярлык показа места») механизмом не достигается: показа места нет, есть поиск по URL.

---

## 3. Исправление

- `SHOW_PLACE`, чей `query` - веб-ссылка: открывать саму ссылку через `ACTION_VIEW` с `setPackage` на Google Карты. Карты разбирают собственную ссылку сами, включая короткую.
- Карт на устройстве нет: тот же `ACTION_VIEW` без `setPackage` - ссылку откроет браузер. Это хуже маршрута, но лучше мёртвой ячейки, и совпадает с уже принятой в S1585 логикой деградации.
- `SHOW_PLACE` с обычным текстом (человеческое название места, ячейки прежних версий) остаётся на `geo:0,0?q=` - для текста это правильный intent, и менять его нечем.
- Признак «query - веб-ссылка» живёт в модели команды, рядом с `query`, чей контракт уже допускает три формы (координаты, текст, URL). Так он проверяется юнит-тестом без устройства.

**Вне объёма:**

- Разворот ссылки в момент нажатия - запрещён ADR-1 S1585: нажатие не должно зависеть от сети.
- `google.navigation:` для этой ветки - точки нет, вести некуда.
- Подпись ячейки: при шаре голой ссылки без названия в подпись попадает URL (`LauncherPlaceShareManager.kt:69`). Отдельная правка UI, требует решения владельца о запасной подписи.

## 4. Проверка

- Юнит-тест: `LauncherCellCommand.Geographic` распознаёт `http://` и `https://` как веб-ссылку и не считает таковой координаты и человеческое название места. Написан в `LauncherCellCommandTest`.
- `.\a.ps1 fk` - expected: exit 0 | actual: exit 0, `BUILD SUCCESSFUL in 24s` (2026-08-14).
- `check-standard-fast.ps1 -Mode Unit -Tests "*LauncherCellCommandTest*"` - expected: exit 0 | actual: exit 1. Прогон не состоялся по чужой причине: `compileStandardDebugUnitTestKotlin` падает на четырёх файлах стримов без параметра `streamQualityMemoryDao` (S1511), это и есть предмет S1635. Файлы S1616 в списке ошибок отсутствуют, то есть компилируются. Тест исполнится, как только закроется S1635.
- На устройстве: выключить сеть, поделиться точкой из Google Карт - ячейка создаётся; включить сеть и нажать ячейку - Карты открывают саму точку, экран поиска по тексту ссылки не появляется.
- На устройстве: ячейка с человеческим названием места по-прежнему открывает это место, а не ссылку.

### Границы проверки

- Шара подавалась настоящим intent'ом `ACTION_SEND` c `text/plain` и `EXTRA_TEXT` на включённый алиас
  `LauncherPlaceShare`, а не тапом по листу «Поделиться» внутри Google Карт. Код приложения начиная с
  `LauncherPlaceShareActivity.onCreate` пройден целиком; не покрыт только показ приложения в системном листе.
- Ячейку `SHOW_PLACE` с обычным текстом ни шара, ни редактор десктопа в текущей сборке не создают - это
  форма «ячеек прежних версий» из §3. Для проверки она была засеяна строкой
  `geo:SHOW_PLACE:<name>:<name>` прямо в `launcher_cells` и удалена сразу после замера; десктоп сверен
  до и после, состав остальных ячеек не изменился.
- Подпись обеих созданных ячеек - сам URL, как и предупреждает §3 («Вне объёма»). При этом иконки
  различаются: маршрутная ячейка получает компас, ячейка показа места - булавку, так что за маршрут она
  себя не выдаёт.
