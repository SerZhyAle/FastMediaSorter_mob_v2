## 1. Проблема

Три операции редактора изображений (обрезка в файл, сжатие, рисование) формируют имя результата по разным правилам: используется разный разделитель между операцией и меткой времени, а операция сжатия называется `shrink` вместо `compress`. Пользователь не может предсказать итоговое имя файла по единому шаблону. Несоответствие проявляется сразу в двух независимых компонентах, что исключает локальную правку одного места.

---

## 2. Цели

1. Все три операции формируют имя результата по единой формуле: `<оригинальное_имя>_<операция>-<YYMMDD-hhmm>.<оригинальное_расширение>`.
2. Метка операции фиксирована: `crop` для обрезки в файл, `compress` для сжатия, `draw` для рисования.
3. Формат метки времени единообразен: `YYMMDD-hhmm` (дефис между датой и временем).
4. Диалог выбора имени файла (если предусмотрен) предзаполняется именно этим значением.

**Non-goals:**

- Изменение самой логики кадрирования, сжатия или рисования.
- Ввод пользовательского шаблона именования в настройках.
- Изменение поведения операции `CROP` (перезапись оригинала) — она не создаёт новый файл.

## 4. Контекст текущей архитектуры

Логика именования результирующего файла сосредоточена в двух отдельных менеджерах: один обслуживает операции кадрирования и сжатия, другой — операцию рисования. Оба компонента находятся в UI-слое и содержат метод, который строит имя по умолчанию и показывает диалог подтверждения.

Текущее состояние:
- Кадрирование в файл: `<base>_crop_<yyMMdd_HHmm>.<ext>` (подчёркивание как разделитель).
- Сжатие: `<base>_shrink_<yyMMdd_HHmm>.<ext>` (неверная метка операции и подчёркивание).
- Рисование: `<base>_draw_<yyMMdd_HHmm>.<ext>` (подчёркивание как разделитель).

Все три компонента используют собственные вызовы форматирования даты без общей утилиты — отсюда расхождение.

---

## 5. Предлагаемый подход

Единый генератор имени файла для операций редактора изображений, доступный обоим компонентам. Генератор принимает исходное имя файла и тип операции, возвращает строку по формуле `<base>_<operation>-<YYMMDD-hhmm>.<ext>`.

### 5.1 Основные столпы

**Формула именования**
- Разделитель между базовым именем и меткой операции: `_` (подчёркивание).
- Разделитель между операцией и временной меткой: `-` (дефис).
- Разделитель между датой и временем внутри метки: `-` (дефис).
- Формат даты: `yyMMdd`, формат времени: `HHmm`.

**Метки операций**
- Обрезка в файл → `crop`.
- Сжатие → `compress`.
- Рисование → `draw`.

**Внедрение**
- Генератор используется в компоненте кадрирования/сжатия и в компоненте рисования вместо инлайн-форматирования.
- Предзаполнение диалога имени файла берётся из генератора.

### 5.2 Потоки данных и событий

Пользователь вызывает операцию → UI-слой обращается к генератору → получает имя → подставляет в диалог → после подтверждения передаёт имя в I/O-компонент.

### 5.3 Точки расширяемости

Генератор должен принимать произвольную метку операции, чтобы новые команды редактора (будущие) подключались без изменения формульной логики.

## 9. Архитектурные решения (ADR)

**ADR-1: Дефис как разделитель операции и времени**

- **Решение:** использовать `-` между меткой операции и временной меткой.
- **Альтернативы:** `_` (подчёркивание) — текущее поведение.
- **Почему:** дефис визуально разделяет смысловые части имени (`что` и `когда`), тогда как `_` между операцией и датой сливает их. Пользователь явно указал желаемую формулу с дефисом.

**ADR-2: Общий генератор вместо правки inline**

- **Решение:** выделить генератор имени в одно место.
- **Альтернативы:** исправить inline-строки в каждом из двух компонентов.
- **Почему:** два компонента уже однажды разошлись в формате — общий генератор исключает повторение.

## 11. Критерии готовности (strategic-level)

1. После «Crop to file» новый файл имеет имя вида `<оригинал>_crop-<YYMMDD-hhmm>.<ext>`.
2. После «Compressed copy» новый файл имеет имя вида `<оригинал>_compress-<YYMMDD-hhmm>.<ext>`.
3. После «Save as new file» из режима рисования новый файл имеет имя вида `<оригинал>_draw-<YYMMDD-hhmm>.<ext>`.
4. Диалог подтверждения имени (во всех трёх сценариях) предзаполнен именно этим значением.
5. Все три операции работают на локальных и сетевых источниках без регрессии.
