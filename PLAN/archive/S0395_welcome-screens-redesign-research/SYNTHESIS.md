# S0395 - Синтез: редизайн welcome-экранов

Документ для владельца. Каждое утверждение опирается на артефакт в `research/`. Дата: 2026-06-10.

> **Sign-off владельца: 2026-06-10, с поправками** (вшиты в текст ниже): кнопка «Пропустить» удаляется целиком; страница сетей выходит сразу декоративной (3 плитки: SMB (intranet), (S)FTP, Cloud), а S0391 получает фазу замены плиток на реальные тумблеры; апгрейдерам указатель не показывается; плитки профилей - полные, с минимальными отступами, малые экраны вверху списка, автопрокрутка к предвыбранному рекомендованному.

## Плюсы

- Новый пользователь сразу получает нужную функциональность: тумблеры страницы функциональности запускают загрузку S0386-элементов ещё в онбординге, приложение готово к работе с первого входа (`research/06`, `research/07`).
- Все четыре декоративные страницы уходят; число страниц НЕ растёт: сейчас 6, станет 5 на старте и 6 после реализации S0391 (`research/01`, `research/10`).
- Каждая страница - реальное решение с безопасным дефолтом: «пролистал за минуту, не трогая ничего - получил рабочее приложение». Это удерживает редизайн в best-practice конверсии (3-5 экранов, контент - предпочтения, а не маркетинг) (`research/10`).
- Почти вся инфраструктура уже существует: язык, цветовые темы, профили с пресетами и автоопределением, delivery-стек, реестр разрешений. Работа - обвязка страниц, а не новые подсистемы (`research/02`, `research/03`, `research/06`).
- Один каркас для всех флейворов через availability-интерфейсы; заодно закрывается старый долг: негейченные карточки страницы 0 и чтение `ENABLE_TRANSLATION` в общем коде (`research/01`, `research/09`).
- Попутная чистка: мёртвый permissions-тип страниц, неиспользуемые строки, враньё «up to 30 destinations» (реальный лимит 10) (`research/01`).

## Минусы

- Плотность решений растёт: шесть страниц-форм вместо четырёх «листалок». Митигация - дефолты и сквозной skip, но первая встреча с приложением становится требовательнее (`research/10`).
- Загрузкам в онбординге нужна новая инфраструктура: текущие загрузки умирают вместе с экраном; нужен живущий на уровне приложения раннер с inline-прогрессом (`research/06`, `research/07`).
- Блокер политики Play: OCR/FFmpeg `.so` сейчас качаются с GitHub и на standard из Play это нарушает запрет на загрузку исполняемого кода мимо Play. До включения OCR-тумблера на standard нужен S0386 follow-up (DFM / гейт по источнику установки / Play Asset Delivery) (`research/07`).
- Страница сетей целиком зависит от нереализованного S0391 (`research/04`).
- Смена темы не даёт live-preview внутри welcome (экран принудительно светлый); честный выход - подпись «применится после настройки» (`research/02`).
- Существующие пользователи новый онбординг автоматически не увидят - флаг завершения переживает обновление (`research/08`).

## Рекомендованная структура

Порядок отличается от черновика владельца одним свопом: функциональность ДО разрешений (см. Отклонение 1).

- Страница 0 - приветствие, язык, тема. Два симметричных ряда по 3 кнопки (EN/RU/UK; Авто/Светлая/Тёмная). Дефолты: текущий язык, тема AUTO. Тема пишется в оба хранилища (DataStore + зеркало) и применяется после онбординга; подпись об этом. Смена языка переживает пересоздание экрана без потерь (`research/02`).
- Страница 1 - профиль устройства. Полные плитки (иконка + название + описание) с минимальными отступами; порядок - устройства с малыми экранами вверху; рекомендованный предвыбран, помечен бейджем и доскроллен автоматически; прокрутка допустима. Выбор применяет пресет на выходе из флоу (поправка владельца 2026-06-10) (`research/03`).
- Страница 2 - сети. Выходит сразу ДЕКОРАТИВНОЙ: три плитки - SMB (intranet), (S)FTP, Cloud (поправка владельца 2026-06-10). S0391 получает фазу замены: те же три плитки становятся групповыми тумблерами, массово пишущими пер-источниковые настройки S0391 (ON по умолчанию); тонкая настройка - в настройках (`research/04`).
- Страница 3 - функциональность. Тумблеры: файловый менеджер (все файлы), аудио, видео, документы (один мастер на 4 поля), OCR (если доступно: флейвор + API≥26 + RAM≥3ГБ), перевод (если доступно: флейвор + Play-установка или bundled), VR (только сборки с `src/vr`). Кнопка «Загружаемые элементы» открывает существующий экран. Тумблер OCR/перевода = постановка загрузки в очередь + inline-прогресс на строке; навигация не блокируется; дефолты = значения после пресета профиля, OCR/перевод OFF (`research/06`, `research/07`).
- Страница 4 - разрешения. Из оверлея становится страницей пейджера (индикатор виден). Набор адаптивен к выборам: экран «все файлы» - только при включённом файловом менеджере или подразумевающем профиле; RECORD_AUDIO - только при включённом аудио; POST_NOTIFICATIONS (API 33+) - в общем батче. Различия по API-уровням (legacy 23-25, 30+, 33+) отрабатываются реестром автоматически (`research/05`).
- Страница 5 - приложение по умолчанию (существующая). После разрешений chooser с образцом файла работает полноценно (`research/05`).

Сквозные свойства:

- Кнопки «Пропустить» НЕТ (поправка владельца 2026-06-10): флоу проходится только «Далее»; каждая страница безопасна по умолчанию, поэтому прогон «только Далее» без касаний остаётся минутным и даёт рабочее приложение (`research/10`).
- Индикатор «шаг X из N» с честным N по collapse-правилу: страница без единого доступного пункта не показывается (`research/09`, `research/10`).
- Страницы - данные с availability-предикатами (без чтения BuildConfig в общем коде); pre-population каждой страницы из реальных настроек - повторный вход и апгрейд консистентны бесплатно (`research/08`, `research/09`).
- Повторный вход чинится: пресет применяется только если профиль реально сменился, с предупреждением как в настройках; возврат к вызвавшему экрану вместо `CLEAR_TASK` (`research/08`).
- Тач-зоны переезжают из онбординга в подсказку первого входа в плеер (легенда в настройках воспроизведения уже существует как fallback) (`research/01`).
- Доступность - наследуемый чеклист: нативная семантика свитчей, stateDescription у плиток, причина недоступности в описании, live-region для прогресса, поглощение LEFT/RIGHT на краях сеток (анти-листание), portrait+landscape в локстепе, ноль «только цветом» (`research/11`).

## Матрица страница × flavor

Нумерация - рекомендованный порядок. Страница 2 (сети) с первого релиза декоративная (3 плитки), после фазы S0391 - тумблеры.

- standard: 0, 1, 2, 3, 4, 5. OCR/перевод по доступности; перевод скрыт на не-Play установках.
- legacy: как standard; на устройствах API 23-25 OCR скрыт; до API 30 нет экрана «все файлы» (обычные runtime-разрешения); до API 29 страница 5 показывается на каждом проходе (существующее поведение).
- noLegal / vr: 0, 1, 2, 3 (+VR-тумблер), 4, 5; 11 профилей вместо 10; онбординг в шлеме - панель + контроллер, работает существующим key-слайдером; нужна только проверка колоночности на устройстве.
- lite: 0, 1, 2 (без плитки Cloud - облака нет в сборке), 3 (файловый менеджер, аудио, видео), 4. Страницы 5 нет.
- photos: 0, 1, 2, 3 (только файловый менеджер), 4, 5 (только кнопка Images).
- Кнопка «Загружаемые элементы» скрыта в lite/photos до фикса фильтрации инвентаря (S0386 follow-up) (`research/09`).

## Отклонения от черновой схемы владельца

1. Своп страниц 3↔4: функциональность ДО разрешений. Причина: батч разрешений становится адаптивным (меньше пугающих системных экранов - «все файлы» видят только те, кому он нужен), загрузки стартуют на страницу раньше и идут, пока пользователь выдаёт разрешения. Черновой порядок тоже работоспособен (ленивый запрос «всех файлов» существует), но строго хуже по UX (`research/05`).
2. Сетевые тумблеры - двумя группами, а не шестью по отдельности: формулировке «какие виды сетей» группы соответствуют лучше, шесть протокольных строк - перегруз для первого запуска; групповой тумблер пишет те же пер-источниковые настройки S0391 (`research/04`).
3. VR-тумблер только в noLegal/vr: в standard ему нечего включать - VR не докачивается, это свойство сборки (`research/06`).
4. Перевод скрыт на не-Play установках standard/legacy: SplitInstall там гарантированно падает (APP_NOT_OWNED) - честнее скрыть, чем показывать обречённый тумблер (`research/06`).
5. «Документы» - один мастер-тумблер поверх четырёх настроек (text/PDF/EPUB/Office); по-форматная гранулярность остаётся в настройках (`research/06`).
6. Тема без live-preview: применяется после онбординга, с подписью. Альтернатива (live) требует переработки нечитаемой тёмной палитры welcome - не стоит того (`research/02`).
7. Тач-зоны не остаются страницей: переезжают в подсказку первого входа в плеер (`research/01`).

## Решения владельца (закрыты 2026-06-10)

1. Показ нового онбординга апгрейдерам: НИЧЕГО не показывать - новый флоу видят новые установки и вручную открывшие его из настроек; флаг завершения не трогается (`research/08`).
2. Плитки профилей: ПОЛНЫЕ (иконка+название+описание), минимальные отступы, малые экраны вверху списка, автопрокрутка к подсвеченному рекомендованному; глубокий скролл принят осознанно (`research/03`).
3. photos: страницу функциональности из одного тумблера ОСТАВИТЬ ради единообразия (`research/09`).
4. Кнопка «Пропустить» удаляется из онбординга целиком; «только Далее» с безопасными дефолтами (`research/10`).
5. Страница сетей выходит декоративной сразу (3 плитки), реальные тумблеры - фаза S0391 (`research/04`).
