## 1. Проблема

Диалог выбора приложения (при добавлении элемента на рабочий стол лаунчера) занимает лишь нижнюю половину экрана и показывает приложения одной колонкой, поэтому в длинном списке приходится много прокручивать. Заголовок и поле поиска отрисованы бесцветным текстом на прозрачной рамке - на затемнённом фоне рабочего стола они плохо читаются. В итоге выбрать приложение медленно и неудобно, а на большом экране место простаивает.

---

## 2. Цели

1. Диалог выбора приложения использует заметно большую высоту экрана.
2. Приложения раскладываются в несколько колонок; число колонок адаптивно по ширине экрана, в портрете - минимум две.
3. Заголовок и поле поиска читаемы: корень диалога имеет непрозрачный surface-фон.
4. Изменения касаются только диалога выбора приложения.

**Non-goals:**

- Resource-, OS-shortcut- и route-picker'ы и диалоги rename / language / network-discovery - остаются компактным одноколоночным списком, их разметка не меняется.
- Фиксированное число колонок (две) - отклонено в пользу адаптивного по ширине.

- **Производительность:** список приложений на переиспользуемой прокрутке; число колонок вычисляется один раз на конфигурацию, без пересчёта на каждый кадр.
- **Совместимость данных:** n/a - изменения только визуальные (высота, число колонок, фон), без хранимого состояния и миграций.
- **Локализация:** EN/RU/UK - обязательно, если меняются или добавляются строки заголовка и подсказки поиска.
- **Доступность:** ячейка приложения - touch target не менее 48dp; читаемый контраст заголовка и поиска на непрозрачном surface; корректный порядок обхода TalkBack по сетке.

## 4. Контекст текущей архитектуры

Диалог выбора приложения - часть UI лаунчера, вызывается при добавлении элемента на рабочий стол. Его разметка сейчас задаёт компактную высоту, одноколоночный список и корень без собственного фона, поэтому текст заголовка и поиска ложится прямо на затемнённый рабочий стол. Без нового варианта разметки (высокий лист, адаптивная сетка, непрозрачный фон) эти замечания не устранить; остальные picker'ы переиспользуют общий компактный шаблон, менять его не требуется.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

- Отдельный вариант разметки для диалога выбора приложения: высокий лист с непрозрачным surface-фоном корня.
- Адаптивная сетка приложений: число колонок выводится из доступной ширины, в портрете - минимум две.
- Прочие picker'ы и диалоги сохраняют общий компактный одноколоночный шаблон.

### 5.2 Потоки данных и событий

- Открытие диалога -> замер доступной ширины -> выбор числа колонок -> раскладка списка приложений сеткой.
- Ввод в поле поиска -> фильтрация списка -> перекомпоновка сетки в том же числе колонок.
- Смена конфигурации (поворот, размер окна) -> повторный замер и пересчёт числа колонок.

### 5.3 Точки расширяемости

- Правило «ширина -> число колонок» вынесено так, чтобы позже подключить тот же грид к другим picker'ам без изменения ядра.
- Вариант высокого листа независим от содержимого списка и переиспользуем для будущих крупных списков.

## 7. Риски

- Много колонок на узком экране даёт слишком мелкие ячейки - митигация: адаптивная формула с минимальной шириной ячейки, в портрете не больше разумного числа колонок.
- Непрозрачный фон визуально утяжеляет лист над затемнённым столом - митигация: брать surface-токен из темы, не хардкодить цвет.
- Расхождение вида с остальными picker'ами - митигация: менять только диалог выбора приложения, прочие оставить на общем шаблоне.

## 11. Критерии готовности (strategic-level)

1. Диалог выбора приложения занимает заметно большую высоту, чем прежний нижний лист.
2. В портрете приложения показаны минимум в две колонки; с ростом ширины экрана число колонок увеличивается.
3. Заголовок и поле поиска читаемы - корень диалога имеет непрозрачный surface-фон.
4. Resource-, OS-shortcut- и route-picker'ы и диалоги rename / language / network-discovery визуально не изменились: одна колонка, компактный лист.
5. Поворот экрана пересчитывает число колонок без потери введённого фильтра поиска.

## Last Audit

### Исправление критерия 5 - 2026-07-25

Аудит показал: при повороте диалог выживает, но остаётся с числом колонок, посчитанным для книжной ориентации. Причина - `LauncherHomeActivity` поглощает поворот через `configChanges`, поэтому диалог не пересоздаётся и `onViewCreated`, где ширина экрана превращается в число колонок, второй раз не выполняется. Ровно то же, что зафиксировано в S1161 ADR-1 на соседнем экране.

Добавлен `onConfigurationChanged` в `AppPickerDialogFragment`: пересчитывает число колонок, размеры окна диалога и высоту списка. Расчёты вынесены в три маленькие функции, которые теперь общие для `onViewCreated`, `onStart` и обработчика поворота, - раньше ширина окна считалась только в `onStart` и после поворота тоже оставалась старой.

**Контроллер намеренно не переприсоединяется.** Меняется только `spanCount` у существующего `GridLayoutManager`. Пересборка списка через `SearchableOptionPickerController.attach` сбросила бы набранный в поиске текст, а сохранение фильтра при повороте - часть того же критерия 5.

Не проверено на устройстве: сам фильтр при повороте. В прогоне 2026-07-24 поле поиска не удалось задействовать вводом с клавиатуры (нажатия уходили в D-pad-фокус), так что эта половина критерия остаётся непроверенной.
