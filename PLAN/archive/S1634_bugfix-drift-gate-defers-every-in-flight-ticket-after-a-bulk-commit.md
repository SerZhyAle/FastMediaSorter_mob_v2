## 1. Проблема / симптом

Условие свежести тактического плана сравнивает дату плана с датой самого свежего коммита в
окне, не разбирая, **относится ли этот коммит к тикету по существу**. Ночной bulk-коммит,
захватывающий десятки файлов, датируется позже всех планов и обнуляет третье доказательство
сразу для всех тикетов в работе.

Ожидалось: живой тактический план с непройденными фазами подтверждает, что маркеры в коде
учтены (это и есть смысл третьего доказательства - см. его обоснование: «Tier-3 тикет
записывает прогресс в счётчики фаз плана»).
Фактически: план объявляется устаревшим из-за постороннего коммита, тикет уходит в
skip-cache с `drift-needs-review` на 3 дня.

---

## 2. Корневая причина

Гейт спрашивал историю коммитов там, где ответ есть в рабочем дереве.

`drift-check.ps1` запускал `git log -S "<id>"` и возвращал каждый коммит, чей патч упоминает id.
В этом репозитории один разработчик, одна ветка и коммит всего дерева под subject-таймштампом,
поэтому такой коммит несёт десятки чужих id и датируется позже любого тактического плана.
`spec-next-preflight.ps1` брал самую свежую из этих дат и объявлял план устаревшим, если его
`Last updated` старше. Один рутинный снимок обнулял третье доказательство сразу для всех тикетов
в работе.

Владелец сформулировал это прямо (2026-08-14): «мы работаем только на этом компьютере и вся
разработка на одной ветке, перестань проверять гит». То же самое уже стояло в CLAUDE.md -
«Working tree = truth» - но гейт этого правила не исполнял.

## 3. Исправление

Два места, обе стороны сравнения теперь берутся из дерева.

- `scripts/spec_catalog/drift-check.ps1` больше не вызывает `git` вообще. Вердикт выводится
  только из inline-маркеров `// Sxxxx:` в `app_v2/src`: есть маркеры - `DRIFT`, нет - `CLEAN`.
  Вердикт `COMMIT_ONLY` выведен из обращения: поле `commits` осталось в JSON пустым списком,
  чтобы старый вызывающий не сломался, но значение не возвращается никогда. Мёртвая ветка вывода
  и печать списка коммитов удалены.
- `scripts/spec_catalog/spec-next-preflight.ps1` считает план свежим, если время последней записи
  `INDEX.md` не раньше времени последней записи тех исходников, где лежат маркеры этого тикета.
  Берётся время файла, а не текст `**Last updated:**`: `plan-tick.ps1` переписывает INDEX на
  каждом отмеченном шаге, поэтому время файла отражает реальную активность плана и не отстаёт из-за
  ручной правки, забывшей заголовок. Учитываются только файлы с маркерами этого тикета - чужой
  исходник, изменённый сегодня, про этот план не говорит ничего.
  В payload добавлены `plan_written_at` и `marked_written_at`, чтобы ответ читался без пересчёта;
  `newest_commit` удалён.

Документы приведены в соответствие: `.claude/commands/spec-next.md` (Stage 3),
`.claude/reference/spec-next.md` (вердикты и третье доказательство), заголовок `drift-check.ps1`.
