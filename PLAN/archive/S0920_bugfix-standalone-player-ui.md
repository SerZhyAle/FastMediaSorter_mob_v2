## 1. Проблема

Standalone-плееры (запуск файла извне через `StandalonePlayerDispatcherActivity` -> `PhotoVideoStandaloneActivity` / `TextStandaloneActivity` / `DocumentStandaloneActivity` / `AudioStandaloneActivity`) имеют пять дефектов вёрстки и поведения, которые владелец видит при обычном открытии файла.

1. Нижние группы «Копировать в..» / «Переместить в..» не разворачиваются по тапу - шеврон крутится, а сетка кнопок не появляется.
2. Окно видео прячет системные бары ОС уже при открытии, оставаясь в режиме с командами - пользователь теряет статус-бар и навигацию вне настоящего полноэкранного проигрывания.
3. Текстовый плеер показывает пункт «Рисовать» в overflow-меню - функция только для изображений, тут это мёртвый тап.
4. Видео игнорирует настройку «Открывать видеофайлы в полноэкранном режиме» и (по отчёту) не начинает сразу проигрываться.
5. Порядок кнопок верхней панели различается между текстом и остальными плеерами - нет единого порядка.

Область: `ui/player/standalone/*` и связанные `ui/player/helpers/Standalone*` + `DestinationButtonsManager`, общее меню и общий bottom-panel include, layout-xml четырёх standalone-хостов.

## 2. Цели

1. Тап по заголовку «Копировать в..» / «Переместить в..» в любом standalone-плеере разворачивает и сворачивает сетку кнопок назначения.
2. Standalone-окно вне настоящего полноэкранного проигрывания показывает системные бары ОС; бары и панель команд скрываются только вместе, как единое полноэкранное состояние.
3. Текстовый плеер не показывает пункт «Рисовать».
4. Видео при включённой настройке «Открывать видеофайлы в полноэкранном режиме» открывается сразу в полноэкранном режиме и начинает проигрывание; при выключенной - открывается в режиме с командами и видимыми барами.
5. Все standalone-плееры используют один порядок кнопок верхней панели.

**Non-goals:**

- Переписывание in-app `PlayerActivity` / `CommandPanelController` - трогаем только standalone-семью.
- Общее соблюдение `hideSystemUiInFullscreen` в `StandaloneFullscreenManager` (отдельный более широкий пробел - в parked-кандидат).
- Изменение набора и логики самих кнопок назначения (Copy/Move targets) - только их разворачивание.
- Удаление deprecated `StandalonePlayerActivity`.

## 4. Контекст текущей архитектуры

Standalone-хосты - независимые `BaseActivity`, не наследники in-app `PlayerActivity`, поэтому не получают его `CommandPanelController` (который в in-app пути вешает слушатели разворачивания панелей) и его чтение `openVideoInFullscreen` / `hideSystemUiInFullscreen`. Каждый хост самостоятельно поднимает `DestinationButtonsManager`, инфлейтит общее меню и общий bottom-panel include, но повторяет настройку вручную - из-за чего один хост (текст) разошёлся по порядку кнопок и по скрытию пунктов меню, а видео-хост скрывает бары безусловно.

Решить из §1 «на месте» нельзя, потому что нужный seam распределён: разворачивание панелей живёт в `DestinationButtonsManager` (но слушатель не привязан), полноэкранный режим - в `StandaloneFullscreenManager` (есть panel-aware вариант, но видео-хост зовёт голый), настройка - в `AppSettings`, а порядок и видимость - в layout/menu xml.

## 5. Предлагаемый подход

Дефекты чинятся точечно в standalone-семье, переиспользуя уже существующие seam-ы; новых ролей не вводится.

### 5.1 Основные столпы / модули

- **Разворачивание панелей (#1):** `DestinationButtonsManager` получает метод-биндер, привязывающий слушатели разворачивания заголовков Copy/Move к своим существующим `setCopyPanelExpanded()` / `setMovePanelExpanded()`; каждый из четырёх хостов вызывает его один раз при настройке.
- **Полноэкранность видео (#2, #4):** видео-хост читает `openVideoInFullscreen` на открытии; при включённом - входит в настоящий полноэкранный режим panel-aware вариантом (бары и панель команд скрываются вместе); при выключенном - не скрывает бары. Панель как источник истины «в фуллскрине».
- **Скрытие «Рисовать» (#3):** текст- и аудио-хосты добавляют пункт draw-overlay в свой список скрытия меню (канон уже задан document-хостом).
- **Единый порядок (#5):** порядок кнопок верхней панели приводится к канону большинства (Rename перед type-specific кластером) правкой layout-xml текст-хоста и его landscape-двойника.

### 5.2 Потоки данных и событий

- Тап заголовка -> `CollapsibleSectionHeader` крутит шеврон и зовёт слушателя -> `DestinationButtonsManager.setCopyPanelExpanded/​setMovePanelExpanded` -> персист collapse-state + переключение видимости сетки.
- Открытие видео -> чтение `openVideoInFullscreen` -> либо `enterFullscreenWithPanel(topCommandPanel)` (fullscreen + autoplay), либо режим команд с видимыми барами.
- Инфляция overflow-меню -> хост скрывает не свои пункты (включая draw-overlay для текста/аудио).

### 5.3 Точки расширяемости

- Метод-биндер разворачивания на `DestinationButtonsManager` - единая точка для будущих standalone-поверхностей.
- Канонический порядок верхней панели - зафиксировать заметкой-конвенцией, чтобы пятая поверхность не разошлась снова.

## 9. Архитектурные решения (ADR)

- Панель команд (`topCommandPanel`) - единственный источник истины «пользователь в полноэкранном режиме»: бары и панель всегда скрываются/показываются вместе через panel-aware варианты `StandaloneFullscreenManager`. Это исключает half-immersive состояние из дефекта #2.
- Единый порядок верхней панели: канон = большинство трёх хостов (Photo/Video, Document, Audio), Rename перед type-specific кластером; текст приводится к нему.

## 11. Критерии готовности (strategic-level)

1. В каждом из четырёх standalone-плееров тап по «Копировать в..» / «Переместить в..» разворачивает и сворачивает сетку кнопок.
2. Standalone-видео вне полноэкранного режима показывает системные бары ОС; в полноэкранном - бары и панель скрыты вместе.
3. Текстовый плеер не показывает пункт «Рисовать» (и аудио-плеер тоже).
4. При включённой «Открывать видеофайлы в полноэкранном режиме» видео открывается в полноэкранном режиме и проигрывается; при выключенной - в режиме команд с видимыми барами.
5. Порядок кнопок верхней панели одинаков во всех standalone-плеерах (Rename перед type-specific кластером).
