## 1. Проблема

Загрузки S0386-элементов живут в скоупе экрана и умирают вместе с ним; «включил тумблер и листаешь дальше» невозможно. Модальный перехватчик на странице с несколькими тумблерами давал бы очередь диалогов.

## 2. Цели

1. Очередь загрузок уровня приложения: постановка при включении тумблера, выживание при смене экрана, сетевые ограничения и повтор.
2. Идемпотентная постановка (установленный элемент - no-op).
3. Переподключаемый inline-прогресс для любой страницы/экрана; уведомления - опционально, при выданном разрешении.
4. Онбординг и приложение никогда не блокируются загрузкой; провал оставляет элемент доступным к повтору в экране элементов.

**Non-goals:** UI страниц (S0398/S0400); изменение состава/хостинга элементов (S0386/S0401).

## 3. Пожелания и ограничения

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты; работает поверх существующих delivery-примитивов.
- **Производительность:** загрузка не блокирует UI-поток и навигацию.
- **Локализация:** EN/RU/UK для строк прогресса/ошибок; тон - по `docs/COMMUNICATION_POLICY.md`.

### 3.3 Owner inputs (Approval gate)

- **Performance budget:** постановка в очередь мгновенна; прогресс - без поллинга UI.
- **Localization:** ~6 новых ключей EN/RU/UK в локстепе.
- **Communication policy:** строки прогресса/ошибок проходят чеклист §6 политики.
- **Validation level:** debug-сборка + ручная проверка очереди (включить → убить экран → загрузка завершилась).
- **Owner sign-off:** 2026-06-10 (в составе sign-off S0395).
- **Related tickets:** S0386 (примитивы доставки), S0400 (потребитель), S0401 (политика .so на standard).

## 4-5. Контекст и подход

Детали - в артефакте S0395/07: раннер класса WorkManager поверх существующего загрузчика с SHA-256-верификацией; запись настройки возможности только после успешной установки (инвариант S0386 сохраняется).

## 6. Открытые вопросы / Research items

## 7. Риски

- Загрузка завершилась, пока приложение убито - состояние «установлено» должно фиксироваться вне UI; митигация - маркер установки пишет раннер, не экран.

## 8. Влияние на пользователя (docs/FEATURES)

Без изменений в docs/FEATURES (инфраструктура; пользовательскую фичу объявит S0400).

## 9. ADR

**ADR-1:** очередь уровня приложения (WorkManager-класс) вместо модального диалога на каждый тумблер - онбординг не может позволить стек диалогов и смерть загрузки при свайпе.

## 10. Связи с другими спеками

- S0386 (BlockNeedUserTest) - примитивы; релиз S0400 ждёт его верификации.
- Блокировок нет; стартует немедленно.

## 11. Критерии готовности (strategic-level)

1. Тумблер ставит загрузку, пользователь уходит с экрана - загрузка завершается, элемент «установлен».
2. Офлайн-постановка не падает: очередь ждёт сеть, UI не заблокирован.
3. Провал загрузки виден в экране элементов с возможностью повтора.
