## Steps

### Step 01.1 - Write the flavor-grid extractor

**Files:** `scripts/docs/generate-flavor-matrix.ps1`

**Depends on:** - start of phase

**Prompt for developer:**

> Create `scripts/docs/generate-flavor-matrix.ps1`. It reads `app_v2/build.gradle.kts` as text, locates the `productFlavors` block, and builds a grid of every `create("<flavor>")` against every `buildConfigField("boolean", "<FLAG>", "<value>")` declared inside that flavor, plus `minSdk` where the flavor overrides it. Represent three distinct cell states: declared `true`, declared `false`, and not declared for that flavor. Fail with a non-zero exit and a diagnostic naming what was missing if fewer than six flavors are found, if any flavor yields an empty flag set, or if a `buildConfigField` line inside the block does not parse - never emit a partial grid. Parameters: `-Json <path>`, `-Markdown <path>`, `-Check`. Document the exit codes in the header comment per CLAUDE.md Rule 7.

**Why:**

Strategic §5.1 makes the build file the only source of truth and this extractor the single derivation from it; strategic §7 records that a silently incomplete read is worse than a hard failure, because a missing flavor would look like a deliberate absence.

**Verification:**

- `Glob` - `scripts/docs/generate-flavor-matrix.ps1` exists.
- `Grep` - `productFlavors` present in the script.
- `Grep` - `-Check` parameter declared in the `param(` block.
- `Grep` - header comment contains `Exit codes` and lists at least codes 0 and 1.
- Run `pwsh -NoProfile -File scripts/quality/assert-exit-contract.ps1` - exit 0.

**Status:** `[x]` done

### Step 01.2 - Emit the machine-readable snapshot

**Files:** `scripts/docs/generate-flavor-matrix.ps1`, `docs/flavors/flavor-matrix.json`

**Depends on:** Step 01.1

**Prompt for developer:**

> Have the script write `docs/flavors/flavor-matrix.json`: the flavor list in `productFlavors` declaration order, the flag list in declaration order, and per-flavor-per-flag one of `true`, `false`, `null` for not declared. Include the resolved `minSdk` per flavor and a `source` field naming `app_v2/build.gradle.kts`. Run the script and confirm the emitted grid matches `research/01__flavor-matrix-surface-inventory.md` §1 cell for cell, including `SUPPORT_VR_PLAYER` false for `vr` and true for `noLegal`, and `VR_UI_COMPOSITION_LAYER_ENABLED` absent for the four non-VR flavors.

**Why:**

Strategic §5.1 requires the snapshot to be the shared input of both the render and the gate, and strategic ADR-3 requires "not declared" to stay distinguishable from "declared false" - collapsing the two is exactly how the VR rows in the operations matrix came to read as enabled.

**Verification:**

- Run `pwsh -NoProfile -File scripts/docs/generate-flavor-matrix.ps1` - exit 0.
- `Glob` - `docs/flavors/flavor-matrix.json` exists.
- `Grep` - all six of `standard`, `noLegal`, `lite`, `photos`, `legacy`, `vr` present in the JSON.
- Read the JSON: `lite.SUPPORT_AUDIO` is `true`, `lite.SUPPORT_STREAMS` is `false`, `vr.SUPPORT_VR_PLAYER` is `false`, `noLegal.SUPPORT_VR_PLAYER` is `true`, `lite.VR_UI_COMPOSITION_LAYER_ENABLED` is `null`, `legacy.minSdk` is `23`.

**Status:** `[x]` done

### Step 01.3 - Render the canonical human-readable table

**Files:** `scripts/docs/generate-flavor-matrix.ps1`, `docs/FLAVOR_MATRIX.md`

**Depends on:** Step 01.2

**Prompt for developer:**

> Have the script render `docs/FLAVOR_MATRIX.md` from the JSON: one table, flavors as columns in declaration order, flags as rows, distinct glyphs for declared-true, declared-false and not-declared with a legend naming all three. Open the file with the same `<!-- GENERATED by ... Do not edit by hand. -->` banner convention `scripts/docs/render-settings-reference.ps1` uses, and state which build file it came from. Add a short lead paragraph telling the reader this file is the answer to "what is available in which flavor" and that every other document defers to it. Confirm `-Check` re-renders into memory and exits non-zero when the file on disk differs.

**Why:**

Strategic §5.1 and §3.1 require exactly one rendered table that both a user and an agent can find, instead of the four incompatible formats the research inventory found; the do-not-edit banner is what keeps it a render target under canon invariant 16.

**Verification:**

- `Glob` - `docs/FLAVOR_MATRIX.md` exists.
- `Grep` - `GENERATED by scripts/docs/generate-flavor-matrix.ps1` present in the file.
- `Grep` - `not declared` (or the chosen legend wording for the third state) present in the legend.
- Run `pwsh -NoProfile -File scripts/docs/generate-flavor-matrix.ps1 -Check` - exit 0.
- Append one stray character to `docs/FLAVOR_MATRIX.md`, re-run with `-Check` - exit non-zero; then re-run without `-Check` to restore.

**Status:** `[x]` done

### Step 01.4 - Register both artifacts in the document registry

**Files:** `docs/DOCUMENT_REGISTRY.jsonl`

**Depends on:** Step 01.3

**Prompt for developer:**

> Add one registry record covering `docs/FLAVOR_MATRIX.md` and `docs/flavors/flavor-matrix.json`: `category` technical, `audience` mixed, `product_areas` including `flavors` and `build`, `update_triggers` including `flavor` and `architecture`, `generated` true. Decide `published`/`indexable` by whether the rendered table should reach the site - it answers a user-facing question, so publish it and index it unless `generate.ps1` rejects the combination. Then run the registry closure trio.

**Why:**

Strategic §5.1 requires the rendered table to sit inside the documentation loop and the docs map; an unregistered document is invisible to the loop that is meant to catch the next drift, which is the recurring control strategic ADR-2 relies on for prose.
