## 1. Проблема

Верхняя командная панель плеера содержит ряд некорректных решений по составу и порядку кнопок для аудио-режима и для плееров в целом. Кнопка «полный экран» бессмысленна для аудио, но отображается. Кнопка «чёрный экран» не появляется, хотя включена в настройках. Кнопка «слайдшоу» расположена вне логической связи с блоком навигации (назад/рандом/вперёд). Кнопка «редактирование» для аудио дублирует уже существующий элемент в нижних командах ExoPlayer и занимает место зря. Наконец, overflow-меню появляется даже когда «не влезла» ровно одна команда — что создаёт лишний клик без смысла.

---

## 2. Цели

1. В аудио-режиме кнопка «полный экран» не видна (полностью скрыта, не только неактивна).
2. Кнопка «чёрный экран» отображается в панели всегда, когда включена в настройках — вне зависимости от типа файла.
3. Кнопка «слайдшоу» стоит непосредственно левее блока «назад / рандом / вперёд» во всех режимах.
4. В аудио-режиме кнопка редактирования полностью скрыта из верхней командной панели.
5. Если в overflow не влезла ровно одна команда, она показывается напрямую вместо кнопки «⋮» — overflow появляется только при двух и более скрытых командах.
6. Все вышеперечисленные правила работают корректно в портрете и ландшафте.

**Non-goals:**

- Изменение состава команд в самом overflow-меню (только условие показа).
- Перекомпоновка нижних ExoPlayer-кнопок.
- Изменения в других плеерах (standalone, VR) — только основной PlayerActivity.
- Новые настройки или пользовательская кастомизация порядка кнопок.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Поведение overflow «N=1 → прямая кнопка» должно быть реализовано как переиспользуемая логика, применимая к любому плееру.

### 3.2 Жёсткие ограничения

- **Flavor:** все (standard, lite, photos, legacy).
- **API level:** без API-специфики, minSdk 26.
- **Wear OS:** не затрагивается.
- **Производительность:** изменения только визибилити, никаких тяжёлых вычислений в UI-потоке.
- **Совместимость данных:** нет изменений в хранилище.
- **Локализация:** новых строк нет; существующие contentDescription остаются.
- **Доступность:** кнопки, скрытые через `GONE`, не должны получать фокус при навигации клавиатурой/геймпадом.

---

## 4. Контекст текущей архитектуры

Верхняя командная панель плеера содержит фиксированный набор `ImageButton`-ов, каждый из которых управляется через `visibility` в зависимости от типа воспроизводимого файла. Логика переключения видимости сосредоточена в менеджерах UI-слоя и вызывается при смене файла. Overflow-кнопка «⋮» появляется тогда, когда контейнер не вмещает все видимые кнопки — сейчас без учёта количества «не влезших».

Слайдшоу-кнопка располагается в центральной группе action-кнопок, тогда как блок навигации (назад/рандом/вперёд) стоит правее — их порядок не привязан к семантической близости.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы

**A. Фильтр кнопок по типу файла (аудио)**
Логика показа «полного экрана» и «редактирования» расширяется: при типе «аудио» оба элемента принудительно переводятся в `GONE`. Место в панели освобождается.

**B. Показ «чёрного экрана» по настройке**
Признак «включена ли кнопка в настройках» уже присутствует в модели настроек. Обновление видимости кнопки «чёрный экран» должно выполняться при каждой смене файла и при инициализации панели — с учётом флага из настроек.

**C. Перемещение слайдшоу**
В XML-разметке портрета и ландшафта кнопка `btnSlideshowCmd` переставляется непосредственно перед блоком «назад/рандом/вперёд». Порядок элементов в разметке определяет визуальный порядок — без кастомного `LayoutManager`.

**D. Умный overflow**
При обновлении видимости панели: подсчитывается количество видимых команд, которые не вмещаются в доступную ширину. Если ровно одна — она показывается напрямую, `btnOverflowMenu` уходит в `GONE`. Если двух и более — показывается `btnOverflowMenu`, сами команды уходят в `GONE`. Логика инкапсулируется так, чтобы другие плееры могли её переиспользовать.

### 5.2 Потоки данных и событий

При смене файла → UI-слой запрашивает тип файла и текущие настройки → вызывается перестройка видимости командной панели → overflow-логика пересчитывается на основе итогового набора видимых кнопок → layout обновляется в одном проходе.

### 5.3 Точки расширяемости

Логика умного overflow должна принимать на вход список кандидатов на скрытие и возвращать решение — это позволит применять её к любому будущему toolbar без дублирования.

## 9. Архитектурные решения (ADR)

**ADR-1: Умный overflow — подсчёт «не влезших» vs. предварительный список кандидатов**

- **Решение:** считать фактически «не влезшие» View на основе их позиции и ширины контейнера после layout-прохода.
- **Альтернативы:** вести явный приоритетный список команд и решать заранее, какая уйдёт в overflow.
- **Почему:** фактический подход устойчив к изменениям набора видимых кнопок в разных режимах; список-приоритет требует ручной синхронизации при каждом добавлении новой кнопки.

## 11. Критерии готовности (strategic-level)

1. Открыв аудиофайл в плеере, пользователь не видит кнопки «полный экран» и «редактирование» в верхней панели — ни в портрете, ни в ландшафте.
2. Открыв любой файл при включённой настройке «чёрный экран», пользователь видит соответствующую кнопку в панели.
3. Кнопка слайдшоу стоит непосредственно левее блока «назад/рандом/вперёд» для любого типа файла в обеих ориентациях.
4. При одной «не влезшей» команде — она показывается напрямую вместо «⋮»; при двух и более — появляется «⋮», отдельные кнопки скрыты.
5. Скрытые кнопки (visibility = GONE) не получают фокус при навигации клавиатурой и геймпадом.
