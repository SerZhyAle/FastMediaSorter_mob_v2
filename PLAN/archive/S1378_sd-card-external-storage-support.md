## 1. Проблема

Приложение не поддерживает SD-карты и подключённые внешние носители как полноценный источник и как цель операций. Съёмный том попадает в приложение только если пользователь сам догадается открыть системный выбор папки - ни список источников, ни диалог добавления ресурса не показывают доступные тома и не называют их по имени.

Записывать на такой том приложение умеет только по одному файлу: перенос или копирование целой папки на выбранный через систему носитель отклоняется до начала работы. Проверки «поместится ли» перед операцией нет вообще, а свободное место в настройках показывается только для встроенной памяти - на съёмном томе операция может оборваться на середине без предупреждения.

Область: выбор и добавление источников, сканирование локальных папок, слой файловых операций, расчёт свободного места.

---

## 2. Цели

1. Доступные съёмные тома видны при добавлении источника без ручного ввода пути - с человеческим именем и объёмом.
2. Медиа со съёмного тома просматривается и сортируется наравне со встроенной памятью.
3. Перенос, копирование и удаление работают в обе стороны - и для отдельных файлов, и для папок целиком, включая вложенные.
3a. Съёмный носитель участвует в переносе папок между ресурсами разных типов наравне с остальными: каталог с фильмами или музыкой переносится с сетевого ресурса или из облака прямо на карту и обратно, через уже существующий механизм межпротокольного переноса дерева.
4. Оценка «поместится ли» считается по тому тому, куда идёт запись.
5. Извлечение носителя во время работы даёт понятное сообщение и корректное состояние списка, а не пустой экран и не сбой.
6. Выданный пользователем доступ к тому переживает перезапуск приложения и не запрашивается повторно без причины.
7. Полный набор операций доступен без всеобъемлющего разрешения на файлы - на устройствах, где оно недоступно или не выдано.

**Non-goals:**

- Прямая работа с USB-накопителем в обход системы (собственный драйвер файловой системы, обработка подключения устройства, отдельное разрешение) - решение владельца от 2026-08-03: объём ограничен томами, которые Android смонтировал сам.
- Сетевые и облачные источники - у них свой слой доступа, он не меняется.
- Форматирование, монтирование, размонтирование и любое управление носителем.
- Перенос самого приложения или его кэша на съёмный носитель.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Отметка в списке ресурсов, что источник живёт на съёмном носителе.
2. Подхват тома при подключении без ручного пересканирования списка.
3. Короткое объяснение перед системным запросом доступа - зачем приложению нужна эта папка.
4. Понятное состояние ресурса «носитель извлечён» вместо исчезновения ресурса из списка.

### 3.2 Жёсткие ограничения

- **Flavor:** все четыре варианта сборки (standard, lite, photos, legacy) - поведение общее, отдельной ветки ни для одного не планируется. Если по ходу работы появится вариант-специфичное правило доступа к дереву папок, оно оформляется интерфейсом в общем коде плюс реализация в наборе исходников варианта, по `dev/FLAVOR_DEVELOPMENT_RULES.md`; проверки `BuildConfig` в общем коде запрещены.
- **API level:** нижняя граница - Android 6 (legacy) и Android 8 (остальные варианты). Поведение расходится на Android 10 (scoped storage) и Android 11+ (доступ ко всем файлам). Обязательное требование: полный набор операций работает и без всеобъемлющего разрешения на файлы, потому что на части устройств оно недоступно, а на ChromeOS системный выбор папки принудителен всегда.
- **Wear OS:** не затрагивается - модуль часов не работает с локальными томами телефона.
- **Производительность:** рекурсивная операция над папкой не блокирует интерфейс, показывает прогресс с обновлением не реже раза в секунду и отменяется в пределах текущего файла. Перечисление томов выполняется вне главного потока.
- **Совместимость данных:** уже сохранённые источники продолжают открываться без повторной выдачи доступа. Форма хранения адреса источника расширяется привязкой к тому только добавлением - без потери и переписывания существующих записей.
- **Локализация:** EN/RU/UK - обязательно для всех новых строк.
- **Доступность:** новые элементы списка томов поддерживают TalkBack и минимальный размер цели нажатия; состояние «недоступен» различимо не только цветом; список проходим с клавиатуры и D-pad.
- **Коммуникации:** все новые пользовательские строки (запрос доступа, отказ, извлечён носитель, недостаточно места) проходят `docs/COMMUNICATION_POLICY.md`, включая чек-лист тона §6, до интеграции.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** все четыре варианта сборки, одинаковое поведение; разделение по вариантам не вводится - причина в §3.2.
- **API level constraints:** Android 6+ для legacy, Android 8+ для остальных; обязательный путь без всеобъемлющего разрешения на файлы для Android 11+ и ChromeOS.
- **Wear OS:** вне объёма - модуль часов не адресует локальные тома телефона.
- **Performance budget:** прогресс не реже раза в секунду, отмена в пределах текущего файла, перечисление томов вне главного потока.
- **Data compatibility:** только расширение формы хранения источника; существующие ресурсы открываются без повторной выдачи доступа.
- **Localization:** EN/RU/UK для всех новых строк, без исключений.
- **UI placement contract:** зафиксирован владельцем через `/ui-clarify` 2026-08-03, см. §3.4. Новый экран не вводится.
- **Accessibility:** TalkBack-описание для каждого тома, состояние «недоступен» не только цветом, проходимость клавиатурой и D-pad.
- **Communication policy:** применяется - четыре новых класса сообщений (запрос доступа, отказ в доступе, носитель извлечён, недостаточно места на томе).
- **Validation level:** сборка плюс проверка на устройстве с физической SD-картой; эмулятор годится только для регрессии внутренней памяти - подключение и извлечение реального носителя он не воспроизводит.
- **Owner sign-off:** 2026-08-03 - объём (только тома, смонтированные системой) и глубина записи (папки целиком) подтверждены владельцем; размещение в интерфейсе - по контракту выше.
- **Related tickets:** S1354 (capture-destination-missing-saf-support) - смежная область, общий слой доступа к дереву папок.

### 3.4 UI clarification record (`/ui-clarify`, 2026-08-03)

Решения владельца, выбранные из предложенных вариантов. Реализация обязана следовать им дословно; отклонение требует нового `/ui-clarify`.

- **Размещение в диалоге выбора папки:** отдельная сворачиваемая секция «Съёмные носители» сразу после существующей секции быстрого выбора папок внутренней памяти. Одна кнопка на том, с именем тома и свободным местом.
- **Когда съёмных носителей нет:** секция скрывается целиком - ни заголовка, ни пустого блока.
- **Пометка ресурса на съёмном носителе:** отдельная иконка источника вместо обычной иконки локальной папки; подпись строки не меняется, работает и в списке, и в сетке.
- **Ориентации:** у диалога есть ландшафтный вариант разметки - секция добавляется в оба, парность обязательна.
- **Состояние «носитель извлечён»:** используется существующий признак недоступности ресурса, отдельного визуального языка не вводится.

## 4. Контекст текущей архитектуры

Обнаружение локальных источников опирается на системный медиа-индекс и на фиксированный набор путей встроенной памяти. Съёмный том нигде не перечисляется как сущность: его папки могут случайно попасть в результат индекса, но приложение не знает ни имени тома, ни его состояния, ни свободного места на нём. Слой доступа к файлам не имеет единой абстракции «место, где лежат файлы» - вместо этого каждый исполнитель сам проверяет вид адреса и выбирает между прямым обращением к файловой системе и обращением через выданный системой доступ к дереву папок.

Из-за этого решение из §1 невозможно локальной правкой. Операции над папкой целиком по адресу, выданному системным выбором, отклоняются намеренной проверкой - за ней нет реализации рекурсивного обхода. Расчёт свободного места жёстко привязан к встроенному хранилищу. Резолв системного адреса обратно в путь тома уже умеет находить съёмные тома, но вызывается только реактивно, после выбора пользователя, и не покрыт тестами.

## 5. Предлагаемый подход

Съёмный носитель не становится новым видом источника - он остаётся локальным источником, у которого отличается способ доступа. Меняется другое: появляется явное знание о томах устройства, а выбор способа доступа поднимается из отдельных исполнителей в один контракт.

### 5.1 Основные столпы / модули

1. **Реестр томов.** Единый источник правды о хранилищах устройства: имя для показа, вид (встроенное или съёмное), состояние (доступно, извлечено), общий и свободный объём. Читается слоем сценариев, отдаётся интерфейсу списком, обновляется при изменении состава носителей.
2. **Адресация источника с привязкой к тому.** Источник хранит адрес и, дополнительно, признак тома, которому он принадлежит. Это позволяет показать «носитель извлечён» вместо исчезновения источника и не пытаться выполнить операцию на отсутствующем томе.
3. **Единый контракт доступа к файлам для локальных мест.** Один контракт вместо разрозненных проверок вида адреса в каждом исполнителе: перечислить, прочитать, создать, переименовать, удалить. Реализации - прямой доступ к файловой системе и доступ через выданное системой дерево папок; выбор делается один раз при разрешении источника, а не в каждом вызове.
4. **Рекурсивные операции над папками для доступа через дерево.** Реальная реализация обхода вложенной структуры с прогрессом, отменой, разрешением конфликтов имён и корректным поведением при частичном отказе. Текущий запрет операций над папкой целиком снимается заменой на эту реализацию, а не ослаблением проверки: пока реализации нет, запрет остаётся.
5. **Оценка свободного места по целевому тому.** Расчёт «поместится ли» получает том назначения, а не встроенное хранилище по умолчанию, и работает для приёмника любого вида.
6. **Жизненный цикл доступа и носителя.** Выданное пользователем право на дерево папок сохраняется и переиспользуется между запусками; при утрате права - явный повторный запрос с объяснением, не молчаливая ошибка. Подключение и извлечение носителя обновляют реестр томов и состояние затронутых источников, в том числе во время выполняющейся операции.

### 5.2 Потоки данных и событий

- Добавление источника: интерфейс выбора папки → сценарий «перечислить тома» → реестр томов → системный слой хранилищ; выбранный том → при необходимости запрос доступа у системы → сохранение источника вместе с привязкой к тому.
- Просмотр: список ресурсов → сценарий разрешения источника → контракт доступа выбирает реализацию по признаку тома и виду адреса → сканирование → список медиа.
- Операция: интерфейс операций → сценарий операции → проверка свободного места на томе назначения → исполнитель операции для выбранной реализации доступа → поток прогресса в интерфейс → итог с числом обработанных и пропущенных элементов.
- Событие носителя: системный слой → реестр томов → список источников и активная операция получают новое состояние.

### 5.3 Точки расширяемости

- Реестр томов допускает добавление нового вида носителя (в том числе прямого USB, вынесенного в non-goals) без изменения слоёв выше.
- Контракт доступа к файлам подключается по той же схеме, что и протоколы сетевых источников, - новая реализация не требует правок в слое сценариев.
- Оценка свободного места выражается через один контракт, пригодный и для сетевых, и для облачных приёмников.
- Рекурсивный обход отделён от способа доступа: одна логика прогресса и отмены на все реализации.

## 6. Открытые вопросы / Research items

1. **Что уже существует в коде и где именно проходит отказ**
   - **Вопрос:** какая часть поддержки съёмных носителей уже реализована и какая проверка блокирует операции над папкой целиком.
   - **Нужно выяснить:** слой обнаружения источников, модель доступа к файлам, место отказа, расчёт свободного места, объявленные разрешения.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1378_sd-card-external-storage-support/research/01__as-is-removable-storage.md`

2. **Запись на съёмный том на Android 6-9**
   - **Вопрос:** нужен ли на нижних уровнях API отдельный путь записи, или доступ через системное дерево папок покрывает и их.
   - **Решение:** единый путь через дерево папок на всех поддерживаемых уровнях. Системный выбор дерева папок существует начиная с Android 5, то есть ниже нижней границы приложения; отдельная ветка для Android 6-9 не вводится. Прямой доступ к файловой системе остаётся только там, где он уже работает - встроенная память.
   - **Статус:** Resolved
   - **Проверка на устройстве:** сценарий записи на карту прогоняется на сборке legacy - несовпадение поведения возвращает вопрос в статус Open.

3. **Извлечение носителя во время длительной операции**
   - **Вопрос:** что считается корректным исходом, если носитель извлекли на середине переноса папки.
   - **Решение:** операция останавливается на текущем элементе и показывает частичный итог - сколько перенесено, сколько осталось. Откат не выполняется: уже записанное на носитель приложению после извлечения недоступно, а удаление исходников идёт только после подтверждённой записи, поэтому потери данных не происходит. Повтор оставшегося пользователь запускает сам, повторив операцию для непереехавшего остатка.
   - **Статус:** Resolved

4. **Стабильность признака тома между подключениями**
   - **Вопрос:** переживает ли привязка источника к тому переподключение носителя и перезагрузку устройства.
   - **Решение:** авторитетным признаком считается выданное пользователем право на дерево папок - оно сохраняется системой и переживает переподключение. Идентификатор тома хранится рядом как признак для показа и для сопоставления с текущим списком томов; его потеря или смена переводит ресурс в состояние «носитель недоступен», но не разрывает привязку и не требует повторной выдачи доступа.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: съёмный том остаётся локальным источником**

- **Решение:** не вводить новый вид источника; съёмный носитель отличается способом доступа и привязкой к тому, а не типом.
- **Альтернативы:** отдельный вид источника наравне с сетевыми протоколами.
- **Почему:** отдельный вид потребовал бы дублирования формы добавления, валидации и правил сортировки при нулевой пользовательской разнице - для пользователя это та же папка на устройстве. Разница целиком лежит в слое доступа, туда её и убираем.

**ADR-2: полный набор операций строится на системном доступе к дереву папок**

- **Решение:** путь без всеобъемлющего разрешения на файлы считается основным и покрывает все операции, включая папки целиком; разрешение на все файлы, если оно есть, только ускоряет работу.
- **Альтернативы:** требовать разрешение на доступ ко всем файлам для работы со съёмными носителями.
- **Почему:** на ChromeOS системный выбор папки принудителен всегда, на части устройств разрешение недоступно, а привязка ключевой функции к спорному разрешению создаёт риск при публикации. Обратный порядок оставил бы функцию неработающей там, где она особенно нужна.

**ADR-3: текущий запрет операций над папкой целиком снимается только вместе с реализацией**

- **Решение:** проверка, отклоняющая папку целиком для доступа через дерево, убирается в том же изменении, что вводит рекурсивный обход, и ни фазой раньше.
- **Альтернативы:** сначала ослабить проверку, реализацию добавить следующей фазой.
- **Почему:** ослабленная проверка без реализации превращает явный отказ в тихую поломку на пользовательских данных - худший из возможных промежуточных результатов.

## 10. Связи с другими спеками

- S1354 (capture-destination-missing-saf-support, Draft) - тот же слой доступа к дереву папок, но другая точка входа (каталог съёмки). Общий контракт доступа из §5.1 закрывает и её; порядок работ определяется очередью релиза, жёсткой блокировки нет.

## 11. Критерии готовности (strategic-level)

1. При добавлении источника пользователь видит подключённые съёмные тома списком, с именем и свободным объёмом, и выбирает нужный без ввода пути.
2. Медиа с выбранного тома открывается, листается и сортируется так же, как из встроенной памяти.
3. Перенос и копирование папки с вложенными подпапками на съёмный том и обратно завершаются успешно, с прогрессом и работающей отменой.
3a. Каталог, перенесённый с сетевого ресурса или из облака на съёмный том, приходит с полной структурой вложенности, и после переноса исходник удаляется только там, где перенос подтверждён.
4. Попытка записать больше, чем помещается, останавливается до начала с сообщением про целевой носитель - сейчас такой проверки нет ни для какого приёмника, она вводится этим тикетом.
5. Извлечение носителя показывает состояние «носитель недоступен» у затронутых источников; после обратного подключения источники снова работают без повторной настройки.
6. Все сценарии из пунктов 1-5 воспроизводятся на устройстве, где разрешение на доступ ко всем файлам не выдано.
7. После перезапуска приложения ранее добавленный источник на съёмном томе открывается без повторного запроса доступа.
