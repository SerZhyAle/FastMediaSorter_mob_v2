## 0. Исходный запрос (verbatim)

## 1. Проблема

Единая встроенная камера приложения с экранным переключением фото/видео (S0563) сейчас доступна только из меню переполнения главного активити: пользователь должен открыть приложение, найти пункт «Камера» и лишь затем снимать. Быстрого запуска именно этой камеры прямо с рабочего стола (домашнего экрана) нет.

Существующий виджет быстрого захвата снимает и сразу сохраняет в заранее настроенную цель в фиксированном режиме (фото **или** видео, выбранном при настройке), без экранного переключения и без выбора режима в момент съёмки. Поэтому он не закрывает потребность «нажал на иконку на рабочем столе - открылась наша камера, и там уже решаю, фото или видео».

## 2. Цели

1. Дать виджет рабочего стола (домашнего экрана), запускающий встроенную единую камеру приложения одним нажатием, без предварительного входа в приложение.
2. В запущенной из виджета камере доступно экранное переключение фото/видео, когда поддержаны оба режима (та же поверхность, что у пункта меню «Камера»).
3. Снятое сохраняется по фактическому виду медиа в публичные папки устройства (фото в папку камеры, видео в папку видео), как и при запуске из меню главного активити.
4. Виджет не требует обязательной предварительной настройки (config-less): нажатие сразу открывает камеру.
5. Корректная деградация: когда доступен только один режим (второй отключён настройкой или не поддержан вариантом сборки) - камера открывается в этом единственном режиме без переключателя; когда камера недоступна вовсе - понятное сообщение, без падения.

**Non-goals:**

- Не заменять и не удалять существующий виджет быстрого захвата «снять и сохранить в цель» - это отдельная способность.
- Не добавлять экранный переключатель режима к точкам входа с жёстким контрактом результата (OCR, захват в ресурс/browse, виджет быстрого захвата) - они остаются с фиксированным режимом.
- Не вводить новых деклараций разрешений - `CAMERA` и `RECORD_AUDIO` уже объявлены ради встроенной камеры.
- Не вводить app-shortcut по долгому нажатию на иконку приложения и pinned-shortcut - возможное расширение, не входит в первую итерацию (см. §5.3).
- Не менять место сохранения и контракт результата встроенной камеры.

## 4. Контекст текущей архитектуры

Встроенный экран захвата (host камеры) уже умеет работать в переключаемом режиме: вызывающая сторона может разрешить экранное переключение фото/видео, host сам владеет выходным файлом и возвращает фактический вид снятого медиа и путь к файлу. Пункт меню «Камера» главного активити запускает этот host в переключаемом режиме и сохраняет результат через общий saver в публичные папки устройства.

Поверхность app-widget в проекте уже развита: есть несколько виджетов камеры, в том числе виджет быстрого захвата с прозрачным trampoline-активити, которое владеет рантайм-разрешением `CAMERA` и результатом съёмки, делегируя всю логику менеджеру (UI без бизнес-логики). Доступность виджетов по вариантам сборки решается слиянием манифеста и рантайм-проверкой инъектируемой поверхности медиа-возможностей.

Чего не хватает: точки входа в переключаемую камеру прямо с домашнего экрана. Существующий виджет захвата запускает host в фиксированном режиме и сохраняет в привязанную цель, а не в публичные папки, поэтому не покрывает запрос «открыть нашу камеру с рабочего стола и снять фото или видео».

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

1. **Провайдер виджета запуска камеры.** Новый app-widget-провайдер: компактная плитка-иконка на домашнем экране без обязательной настройки. Нажатие формирует переход к прозрачному trampoline. Доступность по вариантам сборки - через слияние манифеста и рантайм-проверку медиа-возможностей.
2. **Прозрачный trampoline запуска.** Невидимое активити (пользователь остаётся на домашнем экране), которое владеет рантайм-разрешением `CAMERA`, запускает встроенный host камеры в переключаемом режиме (переключатель доступен, когда поддержаны оба режима) и принимает результат. Бизнес-логики в активити нет - делегирование менеджеру.
3. **Менеджер запуска и сохранения.** Логика: проверить доступность камеры и режимов (настройки + медиа-возможности) -> при необходимости запросить `CAMERA` -> запустить host в переключаемом режиме -> по результату сохранить снятое в публичную папку по фактическому виду медиа через общий saver. Сообщения о недоступности/ошибке - неблокирующие, текстовые. Переиспользует существующий шов сохранения захвата из главного меню без создания параллельной подсистемы сохранения.

### 5.2 Потоки данных и событий

Нажатие на плитку виджета -> прозрачный trampoline -> (рантайм-разрешение `CAMERA` при необходимости) -> встроенный host камеры в переключаемом режиме -> результат (фактический вид медиа + путь) -> общий saver -> публичная папка (фото в папку камеры, видео в папку видео) -> неблокирующее подтверждение -> возврат на домашний экран.

### 5.3 Точки расширяемости

- **Деградация по доступным режимам** переиспользует существующее решение единой камеры: переключатель показывается только при двух доступных режимах, иначе host открывается в единственном доступном режиме.
- **Переиспользование шва сохранения:** логику «сохранить результат переключаемой камеры в публичную папку по виду медиа» желательно держать в общем переиспользуемом помощнике, чтобы запуск из главного меню и из виджета не дублировали маршрутизацию сохранения (конкретная форма выноса - в тактическом плане).
- **Будущие точки входа на рабочий стол:** app-shortcut по долгому нажатию на иконку приложения и pinned-shortcut запуска камеры - возможное расширение поверх того же trampoline; в эту итерацию не входят.
- **Флейвор-гейтинг:** опирается на уже существующую инъектируемую поверхность медиа-возможностей; новой флейвор-абстракции не вводится. Если потребуется различать поведение по варианту сборки сверх медиа-возможностей - расширяется существующая инъектируемая поверхность, без `BuildConfig.IS_*` в `src/main`.

## 9. Архитектурные решения (ADR)

**ADR-1: Виджет запускает переключаемую камеру, а не снимает «в цель»**

- **Решение:** новый виджет открывает встроенный host камеры в переключаемом режиме и сохраняет в публичные папки по виду медиа; он не привязывается к настроенной цели и не дублирует виджет быстрого захвата.
- **Альтернативы:** расширить существующий виджет быстрого захвата опцией «открыть камеру вместо мгновенного захвата».
- **Почему:** у виджета быстрого захвата жёсткий контракт «снять и сохранить в цель в фиксированном режиме»; смешивание с «открыть камеру и выбрать режим» размыло бы его поведение и контракт результата. Раздельные способности яснее для пользователя.

**ADR-2: Config-less запуск**

- **Решение:** виджет не требует экрана настройки; нажатие сразу открывает камеру.
- **Альтернативы:** конфигурируемый виджет (как виджет быстрого захвата с выбором цели).
- **Почему:** цель сохранения фиксирована (публичные папки по виду медиа), привязывать нечего; обязательная настройка была бы лишним трением для «иконки камеры на рабочем столе».

**ADR-3: Переиспользование host и шва сохранения**

- **Решение:** виджет переиспользует встроенный host камеры (переключаемый режим) и существующий шов сохранения в публичные папки.
- **Альтернативы:** отдельный путь захвата/сохранения для виджета.
- **Почему:** единое поведение камеры и сохранения; меньше дублирования и риска расхождений.

## 11. Критерии готовности (strategic-level)

1. На домашнем экране доступен для добавления виджет запуска камеры приложения; после добавления он отображается компактной плиткой-иконкой без шага обязательной настройки.
2. Нажатие на виджет открывает встроенную камеру приложения, оставаясь вне приложения до открытия камеры (прозрачный запуск).
3. Когда доступны оба режима, в открытой из виджета камере есть экранное переключение фото/видео; когда доступен один режим - камера открывается в нём без переключателя.
4. Снятое из виджета фото сохраняется в публичную папку камеры, снятое видео - в публичную папку видео (по фактическому виду медиа).
5. Когда камера недоступна, виджет показывает понятное текстовое сообщение и не падает.
6. В вариантах сборки без встроенной камеры/захвата фото виджет отсутствует среди доступных к добавлению (зеркалит доступность существующего виджета камеры).
