## 1. Проблема

Политика Play (Device and Network Abuse) запрещает загрузку исполняемого кода (`.so`) из источников помимо Play. S0386 решил это для перевода (SplitInstall на store-флейворах), но OCR-движки и FFmpeg-DTS качаются с GitHub без гейта по источнику установки - на standard из Play это exposure на снятие приложения. Онбординг-тумблеры (S0400) многократно усилят частоту таких загрузок. Попутно: экран элементов в lite/photos предлагает строки, которые там не могут установиться.

## 2. Цели

1. На Play-установках store-флейворов `.so`-элементы (OCR, FFmpeg-DTS) доставляются Play-совместимым путём; прямая загрузка `.so` с GitHub остаётся только вне Play-контекста (sideload/debug/noLegal).
2. Данные-payload'ы (traineddata, mp4) остаются на прямой загрузке везде - они кодом не являются.
3. Инвентарь экрана элементов фильтруется по флейвору: lite/photos не видят обречённые строки.

**Non-goals:** изменение хостинга для noLegal/sideload (GitHub-путь остаётся); новые элементы.

## 3. Пожелания и ограничения

### 3.2 Жёсткие ограничения

- **Flavor:** store-флейворы (standard, legacy) против sideload (noLegal); решение - через source set'ы/контракты, без BuildConfig-гейтов в общем коде.
- **Совместимость данных:** установленные элементы и их маркеры переживают переход; повторная загрузка уже установленного не требуется.
- **Локализация:** новые строки (если появятся сообщения о пути доставки) - EN/RU/UK.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** store vs sideload пути; реализация по `dev/FLAVOR_DEVELOPMENT_RULES.md`.
- **Data compatibility:** маркеры установленности сохраняются; форма хранения payload'ов не меняется.
- **Validation level:** release-сборка standard + проверка обоих путей доставки (Play-контекст эмулируется установщиком), BlockNeedUserTest.
- **Owner sign-off:** 2026-06-10 (в составе sign-off S0395).
- **Related tickets:** S0386 (родительская линейка; зависимость - его верификация), S0400 (потребитель: OCR-тумблер на standard из Play ждёт этот тикет).
