**Захвачено:** 2026-07-19

**Текст:**

Встроить deep-signal maintenance-отчёт каталога трансляций в /spec-prerelease Step 0. Сейчас релизный процесс только доливает новые каналы (append + header-probe) и никогда не выметает протухшие: prune существующих строк человеко-гейтед (-CatalogOnly -DeepSignal -PruneDead) и запускается только вручную. Из-за этого shipped-каталог (delivery/stream-catalog/streams.csv, ~2691 строка) копит мёртвые каналы - основная масса iptv-org строк влилась 2026-06-22 только по header-probe, до появления deep-signal append-gate S0805 (2026-07-01), и ни разу не проверялась на реальные сегменты. Задача: в /spec-prerelease Step 0 добавить прогон `collect-stream-candidates.ps1 -CatalogOnly -DeepSignal` (report-only, БЕЗ -PruneDead) по всему каталогу, вывести dead-rate (alive/dead/unknown из temp/stream-catalog-liveness.csv) в отчёт релиза и предложить оператору запустить prune. Политику prune НЕ менять - остаётся консервативной (чистится только status=='dead', 'unknown' остаётся, т.к. мёртвый с нашей сети может быть жив у юзера; см. feedback_stream_catalog_all_live_channels). Гейт информационный: показать число кандидатов на удаление, prune остаётся отдельным ручным действием оператора. Файлы: скилл /spec-prerelease (Step 0), scripts/streams/collect-stream-candidates.ps1 (Invoke-CatalogMaintenance).

**Захвачено во время:** ad-hoc проверка алгоритма liveness каталога трансляций (запрос владельца)

**Update 2026-07-19 - расширение объёма (решения владельца в диалоге):**

Замер deep-signal по всему каталогу (2691 строка, report-only) дал: alive 2194 (81.5%), dead 362 (13.5%), unknown 135 (5.0%). Мёртвые - почти целиком Live TV (361 VIDEO + 1 AUDIO). Отчёт: `temp/stream-catalog-liveness.csv`.

Разбор 135 unknown: 44 отдают HTTP 403 (сильный гео-сигнал), 91 - таймаут/SSL-fail/401-авторизация/4xx-5xx/dns/rtsp-timeout (труп или недоступен по не-гео-причине). Ни одного 451.

Решения владельца, расширяющие объём тикета за пределы «отчёт в prerelease»:

1. **Чистка (prune).** Удалить 362 `dead` + 91 non-geo `unknown` = 453 строки. Каталог 2691 → 2238. Политика больше не «чистим только `dead`»: таймаут-`unknown` тоже труп и удаляется.
2. **Geo-тег.** 44 строки с HTTP 403/451 не удалять, а пометить тегом `geo` (возможно региональный) - «мёртвый с моей сети может быть жив у юзера в его стране». Тег эвристический: 403 - лучший доступный сигнал, но может оказаться hotlink/IP-block, не строго гео (зафиксировать в docs как «возможно», не гарантия).
3. **Разделение в probe.** Сейчас `Invoke-SignalProbe` кладёт 403/451 в то же ведро `unknown`, что и таймауты, поэтому текущим `-PruneDead` «удалить unknown, сохранив гео» невозможно. Нужно: probe отделяет 403/451 (→ пометка geo), prune удаляет `dead` + non-geo `unknown`, гео оставляет.
4. **Схема каталога.** Новая хвостовая колонка (напр. `access` = `geo` / пусто), forward/backward-совместима как `favicon_index` (парсер читает по имени заголовка, старые сборки игнорируют).
5. **Приложение (UI).** Бейдж на карточке гео-канала («🌍 регион») + опц. сообщение «возможно, недоступен в вашем регионе» при провале воспроизведения вместо общей ошибки. Требует /ui-clarify по размещению/виду бейджа.
6. **Prerelease-отчёт.** Исходная задача: deep-signal maintenance-отчёт в /spec-prerelease Step 0 (dead-rate + число кандидатов на prune), информационный гейт, prune остаётся ручным действием оператора.

Note: prune+publish пока НЕ выполнялись - ждут реализации geo-split в probe (иначе снесём и гео). Publish клоббберит `delivery-so-v1` для всех юзеров.

## 1. Проблема

Каталог трансляций копит недоступные каналы: deep-signal проверку по всему списку гоняли впервые и она нашла 13.5% hard-dead плюс балласт из недоступных с релизной сети. Инструмент при этом не умеет отличить регион-ограниченный канал (жив у юзера в его стране) от таймаут-трупа, поэтому чистка либо оставляет мёртвое, либо рискует снести живое-но-региональное. Пользователь в списке тыкает мёртвые каналы и не понимает, что часть недоступна лишь по региону.

---

## 2. Цели

1. Deep-signal отделяет регион-отказ (403/451) от таймаут-трупов отдельным вердиктом.
2. Prune удаляет мёртвое и не-гео-недоступное, но сохраняет и метит регион-ограниченные каналы.
3. Опубликованный каталог очищен, гео-каналы несут признак доступа.
4. Пользователь в приложении видит пометку на регион-ограниченном канале и осмысленный fallback при провале воспроизведения.
5. Релизный прогон показывает раскладку живости, чтобы балласт не копился незаметно.

**Non-goals:**

- Автоматический prune в релизном процессе - гейт информационный, удаление остаётся ручным `-PruneDead`.
- Реальная проверка гео с IP другой страны - тег остаётся эвристикой по 403/451, не гарантией.
- Wear OS.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Тег `geo` вешать только там, где регион-замок доказан (HTTP 403/451) - никаких догадок по таймаутам.
2. Всё, что не гео и не живо (таймаут/SSL/401/5xx), - удалять, а не держать.
3. Гео-каналы показывать в списке приложения с пометкой, а не прятать.

### 3.2 Жёсткие ограничения

- **Flavor:** каталог трансляций общий; бейдж виден там, где включён экран Трансляции - `SUPPORT_STREAMS` = standard/noLegal/legacy/vr (в lite/photos экран скрыт). Тег в CSV forward-совместим и для них.
- **API level:** без API-специфики (CSV-колонка + бейдж на существующей карточке).
- **Wear OS:** не затрагивается.
- **Производительность:** deep-signal прогон по ~2700 строкам долгий - запускать в фоне.
- **Совместимость данных:** колонка `access` добавляется хвостовой (после `favicon_index`); парсер приложения матчит по имени заголовка, старые сборки её игнорируют. Для рендера бейджа в приложении нужна Room-миграция сущности источника (bump schema version) - фаза B.
- **Локализация:** строки бейджа/fallback («возможно, недоступен в вашем регионе») - EN/RU/UK обязательно.
- **Доступность:** бейдж не только цветом - иконка + текст; touch-таргет не ломается.

## 4. Контекст текущей архитектуры

Каталог трансляций собирается офлайн-инструментом (PowerShell) и публикуется как zip-ассет GitHub-релиза, который приложение тянет при импорте. Проверка живости уже двухуровневая (header + deep-signal), но deep-signal единственный сигнал, отличающий «плейлист отвечает» от «реально играет». Сейчас deep-signal классифицирует регион-отказ (403/451) в то же ведро, что и таймаут-трупы, поэтому «удалить мёртвое, но сохранить гео» невозможно одним прогоном. Prune вдобавок консервативен (только `dead`) и ручной, а релизный процесс каталог только доливает - отсюда накопление балласта. На стороне приложения строка каталога проходит парсер (матчит по имени колонки) в сущность источника (Room) и рендерится карточкой в панели трансляций; чтобы показать гео-пометку, признак должен доехать до сущности и адаптера.

---

## 5. Предлагаемый подход

Признак доступности вычисляется офлайн-пробой и едет как данные: deep-signal отделяет регион-отказ в отдельный класс, инструмент пишет его в новую колонку каталога, приложение читает колонку и показывает пометку. Prune становится точнее: удаляет мёртвое и не-гео-недоступное, гео оставляет помеченным.

### 5.1 Основные столпы / модули

- **Проба (офлайн-инструмент):** deep-signal получает третий вердикт «регион-ограничен» помимо живо/мертво/неизвестно.
- **Каталог (данные):** хвостовая колонка признака доступа, forward/backward-совместимая.
- **Импорт + модель (приложение):** признак доезжает от парсера до сущности источника и доменной модели.
- **Панель трансляций (UI):** пометка на карточке гео-канала + осмысленный fallback при провале воспроизведения.
- **Релизный гейт:** deep-signal maintenance-отчёт в пре-релизном прогоне (информационный).

### 5.2 Потоки данных и событий

Офлайн-проба → вердикт доступа → колонка каталога → публикация ассета → импорт в приложении → сущность источника → карточка списка (пометка) и путь воспроизведения (fallback-сообщение).

### 5.3 Точки расширяемости

Класс вердикта доступа - перечисление, открытое к новым значениям (напр. «требует авторизации») без ломки схемы: неизвестное приложению значение деградирует в «без пометки».

## 11. Критерии готовности (strategic-level)

Фаза A (данные/инструмент):
1. Deep-signal probe даёт отдельный вердикт для регион-отказа (403/451), не смешивая его с таймаут-трупами.
2. Prune удаляет мёртвое и не-гео-недоступное, гео-каналы остаются в каталоге с записанным признаком доступа.
3. Опубликованный каталог не содержит hard-dead и не-гео недоступных строк; гео помечены.
4. README каталога описывает значения признака доступа и его эвристичность.
5. Пре-релизный прогон выводит deep-signal раскладку (alive/dead/unknown/geo) и число кандидатов на prune, не удаляя автоматически.

Фаза B (приложение):
6. Регион-ограниченный канал в списке приложения визуально помечен (иконка + текст, не только цвет).
7. При провале воспроизведения гео-канала пользователь видит осмысленное сообщение вместо общей ошибки.
8. Импорт каталога с новой колонкой и апдейт поверх старой базы проходят без сбоя (миграция протестирована).
