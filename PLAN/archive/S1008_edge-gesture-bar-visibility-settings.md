## 1. Проблема

- Единый глобальный тумблер «показывать полосу жеста у левого края» (S0724) живёт вне позонных блоков и покрывает только левую кромку.
- После S0847 краевых зон стало четыре (левая-верхняя, левая-нижняя, правая-верхняя, правая-нижняя), но серую подсказку-полосу можно включить лишь для левого края - у трёх остальных band'ов нет своего переключателя видимости.
- Размещение тумблера рассинхронизировано с позонной структурой блоков: он висит отдельной строкой над блоками, а не внутри своего блока.

---

## 2. Цели

1. Видимость полосы становится позонным свойством: у каждой из четырёх зон свой тумблер.
2. Существующий тумблер переезжает внутрь блока «Левый край - верхняя полоса» с сохранением текущего значения пользователя.
3. Три новых тумблера появляются внутри блоков остальных зон, единообразно с первым.
4. Overlay рисует серую направляющую независимо для каждой видимой зоны на правильной физической кромке (левая/правая) и в своём вертикальном band'е.

**Non-goals:**

- Изменение самих действий жестов, геометрии band'ов, углов классификации.
- Новые кромки/зоны сверх четырёх, введённых S0847.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Все четыре опции оформлены единообразно («аналогично»), без индивидуальной вёрстки.

### 3.2 Жёсткие ограничения

- **Flavor:** только флейворы с capability экранного захвата (standard/screenCapture + noLegal); карточка скрыта там, где контроллера нет.
- **API level:** overlay-путь API 26+, accessibility-путь API 30+ (без новых требований).
- **Wear OS:** не затрагивается.
- **Производительность:** без нового бюджета - перекраска существующих band-View, окна не пересоздаются при смене видимости.
- **Совместимость данных:** старый одиночный флаг мигрирует в видимость зоны LEFT_TOP; остальные три по умолчанию выключены.
- **Локализация:** EN/RU/UK обязательно.
- **Доступность:** переиспользуются штатные toggle-строки (TalkBack/touch-target уже покрыты).

## 4. Контекст текущей архитектуры

Область - подсистема экранного захвата (`core/screencapture` + flavor-хосты overlay) и вкладка настроек Operations. Набор включённых зон уже резолвится хостом overlay из персистентных настроек; видимость же полосы исторически прокидывалась заранее прочитанным булевым значением по сигнатурам контроллера (S0727). Единичный флаг нельзя расширить до четырёх зон без переноса резолва видимости на тот же уровень, где резолвятся включённые зоны.

---

## 5. Предлагаемый подход

Видимость полосы становится позонным свойством настроек и резолвится в хосте overlay ровно так же, как множество включённых зон, а рендер-менеджер гейтит фон каждого band'а по принадлежности зоны к множеству видимых.

### 5.1 Основные столпы / модули

- Доменная модель настроек: одно булево поле заменяется четырьмя позонными + позонный аксессор.
- Стор настроек: четыре новых ключа, старый ключ read-only как источник миграции для LEFT_TOP.
- Диспетчер действий жестов: новый резолвер множества зон с видимой полосой (включённых И видимых).
- Рендер-менеджер overlay: единый флаг видимости заменяется множеством зон; фон band'а прозрачный либо серый по членству.
- Слой настроек UI: строка переносится внутрь блока зоны, добавляются три аналогичные.

### 5.2 Потоки данных и событий

- UI-тумблер -> оптимистичное обновление настроек -> сигнал контроллеру «обнови полосы» -> хост перечитывает множество видимых зон -> перекраска band-View.
- Старт/восстановление overlay -> хост читает включённые зоны и видимые зоны из настроек -> показ band'ов с корректным фоном.

### 5.3 Точки расширяемости

- Позонное множество видимых зон масштабируется на любое будущее число band'ов без изменения сигнатур.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Потеря старой настройки видимости при миграции | Низкая | Пользователь теряет включённую полосу | Read-only fallback старого ключа в LEFT_TOP |
| Рассинхрон между flavor-хостами overlay | Низкая | Полоса ведёт себя по-разному на путях overlay/accessibility | Общий рендер-менеджер и общий резолвер зон |
| Read-after-write при живой перекраске | Низкая | Полоса перекрашивается по устаревшему значению | Тот же механизм, что у шипнутого refresh включения зоны |

## 9. Архитектурные решения (ADR)

- **ADR-1: резолв видимости полосы в хосте overlay (а не прокидывание N булевых).** Множество включённых зон уже резолвится хостом из настроек; видимость резолвится тем же путём. Это исключает сериализацию четырёх флагов через intent/сигнатуры, переиспользует консистентность уже шипнутого refresh включения зоны и снимает read-after-write риск. `setStripVisible` вырождается в сигнал «обнови полосы», зеркаля `setEnabled`.

## 11. Критерии готовности (strategic-level)

1. В каждом из четырёх блоков зоны есть тумблер видимости полосы, единообразно оформленный.
2. Включение тумблера зоны рисует серую направляющую именно на её кромке и band'е; выключение убирает её, не трогая другие зоны.
3. Прежнее значение «показывать у левого края» сохраняется как видимость LEFT_TOP после обновления.
4. Портретная и ландшафтная вёрстки в паритете.
5. Документация настроек (манифест/справочник/аннотации) синхронизирована.
