## 0. Захваченный материал (inbox)

**Захвачено:** 2026-07-13

**Текст владельца (verbatim):**

> в варианты жестов добавить "вызов приложения". И если этот вариант выбран появляется рядом с этим жестом "укажите приложение" - имеется ввиду любое приложение андроид (ну вот как мы выбираем для панели быстрого запуска). Например телеграмм или гмэйл. К сожалению, у нас целых 12 мест где пользователь может задать такое приложение. Нужно сделать красивый и удобный выбор/сброс.

**Решения владельца (2026-07-13):**

- Действие «вызов приложения» реализуется переиспользованием существующего пункта `OPEN_APP`: он начинает означать «запустить выбранное приложение», а при пустом выборе откатывается к текущему поведению (вывести FastMediaSorter на передний план).
- Реализуется после того, как диалог S1035 готов (пер-слотовый пикер приложения ложится в его вкладки по зонам).

---

## 1. Проблема

Среди действий краевого жеста есть пункт `OPEN_APP`, но сейчас он лишь выводит на передний план сам FastMediaSorter - выбрать произвольное Android-приложение (например Telegram или Gmail) для запуска по жесту нельзя. Пользователь ожидает, что «вызов приложения» позволит назначить любое установленное приложение, как это уже делается для панели быстрого запуска. Пер-жестового хранения выбранного приложения в настройках нет. Мест, где такое приложение можно было бы задать, целых двенадцать (четыре зоны края × три направления), поэтому выбор и сброс должны быть удобными и наглядными, а не двенадцатью разрозненными полями.

---

## 2. Цели

1. Пункт действия «вызов приложения» (`OPEN_APP`) означает «запустить выбранное пользователем приложение».
2. Когда для конкретного жеста выбран `OPEN_APP`, рядом появляется управление «укажите приложение», открывающее выбор любого установленного Android-приложения (та же механика, что у панели быстрого запуска).
3. Выбранное приложение хранится отдельно для каждого из двенадцати слотов жестов и запускается при срабатывании соответствующего жеста.
4. Есть удобный сброс выбранного приложения для слота; при пустом выборе `OPEN_APP` откатывается к текущему поведению (вывести FastMediaSorter).
5. Выбор и сброс на все двенадцать мест организованы наглядно (в рамках диалога S1035, во вкладках по зонам) - без двенадцати разрозненных полей на одном экране.

**Non-goals:**

- Не меняется набор зон/направлений и прочие действия жестов.
- Не вводится отдельный новый пункт действия рядом с `OPEN_APP` (владелец выбрал переиспользование существующего).
- Не переносится и не переделывается сам механизм выбора приложения панели быстрого запуска - он переиспользуется как есть.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. «Красивый и удобный» выбор/сброс приложения, распространённый на все двенадцать слотов.
2. Появление управления «укажите приложение» строго рядом с тем жестом, где выбран `OPEN_APP`.

### 3.2 Жёсткие ограничения

- **Flavor:** та же область, что у краевых жестов. Уточнено кодом 2026-08-09 (research 01 §6): гейт краевого жеста - не `fms.screenCapture`, а `fms.edgeGestureOverlay`, и он по умолчанию **выключен**, поэтому на обычной сборке `standard debug` возможности нет вовсе; в `noLegal` она есть всегда и без свойства; в `lite`, `photos`, `legacy` и `vr` исходники жеста не подключаются. Проверка на устройстве идёт на `noLegal debug` либо на `standard` с `-Pfms.edgeGestureOverlay=on`. Новая абстракция флейвора не вводится, гейт в рантайме остаётся непустотой внедрённого набора контроллеров оверлея, а не полем `BuildConfig`.
- **API level:** запуск стороннего приложения и перечисление установленных приложений должны учитывать ограничения видимости пакетов (Android 11+/package visibility) - без объявления неоправданно широких запросов; переиспользовать подход панели быстрого запуска.
- **Wear OS:** не затрагивается.
- **Производительность:** список приложений строится по требованию при открытии пикера, не при старте.
- **Совместимость данных:** новые ключи хранения (пакет приложения на каждый из двенадцати слотов) в существующем хранилище настроек; без Room-миграции; отсутствующее/удалённое приложение трактуется как «не выбрано» (безопасный откат).
- **Локализация:** EN/RU/UK обязательно для новых строк (подпись «укажите приложение», действие сброса, состояние «приложение не выбрано»).
- **Доступность:** элемент выбора приложения фокусируем (клавиатура/D-pad), имеет текстовую подпись выбранного приложения (не только иконку), сброс доступен явным действием.

### 3.3 Owner inputs (Approval gate)

- **Data compatibility:** двенадцать новых строковых ключей (пакет приложения на слот) в текущем хранилище настроек; без Room-миграции; удалённое/пустое приложение = «не выбрано» (откат к выводу FMS).
- **UI placement contract:** управление «укажите приложение» появляется рядом с направлением, где выбран `OPEN_APP`, внутри вкладки зоны диалога S1035; наглядный выбор + явный сброс на все двенадцать слотов.
- **Accessibility:** элемент фокусируем, показывает текстовую подпись выбранного приложения, сброс - отдельное действие.
- **Localization:** EN/RU/UK для новых строк - обязательно.
- **Validation level:** сборка `standard debug` + on-device проверка: выбор приложения по слоту, запуск по жесту, сброс, откат при пустом/удалённом приложении.
- **Owner sign-off:** 2026-07-13 (действие = переиспользовать `OPEN_APP`; порядок = после диалога S1035).
- **Related tickets:** S1035 (блокирующий - диалог-хост), S0663 (панель быстрого запуска - источник механики выбора приложения), S0847 (зоны/направления).

## 4. Контекст текущей архитектуры

Действия краевого жеста заданы перечислением, применяются диспетчером до захвата экрана; `OPEN_APP` сейчас жёстко выводит на передний план сам FastMediaSorter. Настройки жеста (действие на слот) хранятся в общем хранилище настроек; строкового поля «пакет приложения на слот» там нет. Механика выбора любого установленного приложения уже реализована для панели быстрого запуска и учитывает видимость пакетов - её и следует переиспользовать. UI детальной настройки жестов на момент реализации будет жить в отдельном диалоге (S1035) с вкладками по зонам, поэтому пер-слотовый выбор приложения встраивается туда.

---

## 5. Предлагаемый подход

Наделить действие `OPEN_APP` смыслом «запустить выбранное приложение» и добавить пер-слотовое хранение выбранного пакета. В UI жеста, где выбран `OPEN_APP`, показывать элемент выбора приложения с подписью и сбросом; выбор переиспользует существующую механику панели быстрого запуска. Диспетчер при срабатывании читает пакет для слота и запускает приложение; при пустом/недоступном пакете откатывается к текущему поведению.

### 5.1 Основные столпы / модули

1. **Хранение выбора на слот.** Двенадцать строковых значений (пакет приложения) по одному на пару «зона + направление»; пусто = не выбрано. Уточнено кодом 2026-08-09: это хранилище уже существует - его ввёл S1038 как общее пер-слотовое значение, - поэтому столп сводится к потреблению готового, а не к его созданию.
2. **Выбор приложения.** Переиспользование механики выбора установленного приложения от панели быстрого запуска (перечисление с учётом видимости пакетов, иконка + имя, сброс).
3. **UI рядом с жестом.** В диалоге S1035 (вкладка зоны) под направлением с действием `OPEN_APP` появляется строка выбора приложения с подписью выбранного и действием сброса.
4. **Диспетчеризация.** При срабатывании жеста с `OPEN_APP` читается пакет слота; есть - запуск приложения, нет/недоступно - текущий откат (вывести FMS).

### 5.2 Потоки данных и событий

- UI слота (действие = `OPEN_APP`) -> строка выбора приложения -> механика выбора -> хранилище настроек (пакет слота).
- Жест сработал -> диспетчер -> чтение пакета слота -> запуск приложения либо откат.
- Изменение действия слота на не-`OPEN_APP` -> строка выбора скрывается (значение пакета сохраняется/очищается - решить в §6).

### 5.3 Точки расширяемости

- Хранилище пакетов на слот не зависит от числа зон/направлений.
- Механика выбора приложения остаётся общей с панелью быстрого запуска - улучшения пикера распространяются на оба места.

## 6. Открытые вопросы / Research items

1. **Форма хранения двенадцати пакетов.**
   - **Вопрос:** двенадцать отдельных строковых полей настроек или одна структура-отображение «слот -> пакет»?
   - **Статус:** Resolved (2026-08-09, установлено кодом) - вопроса больше нет: двенадцать полей payload на слот уже стоят в модели настроек и уже сохраняются в DataStore ключами вида `gesture_payload_<зона>_<направление>`. Их ввёл S1038 под общее пер-слотовое значение, и его же документация называет этот тикет вторым потребителем. Тикет ничего не заводит, а потребляет готовое: ни новой настройки, ни нового ключа, ни миграции.
   - **Артефакт:** `PLAN/S1036_gesture-launch-app-selection/research/01__per-slot-payload-and-app-picker.md`

2. **Судьба выбранного пакета при смене действия слота.**
   - **Вопрос:** если пользователь сменил действие слота с `OPEN_APP` на другое, а потом вернул - помнить прежнее приложение или очищать при уходе?
   - **Статус:** Resolved (2026-08-09, установлено кодом) - сохранять. Это не выбор, а единообразие: соседнее действие «открыть ссылку» уже ведёт себя так, потому что применение действия payload не трогает. Очистка - только явным сбросом.
   - **Артефакт:** `PLAN/S1036_gesture-launch-app-selection/research/01__per-slot-payload-and-app-picker.md`

3. **«Красивый и удобный» на двенадцать слотов - конкретика.**
   - **Вопрос:** строка выбора приложения появляется только при `OPEN_APP` в этом направлении (инлайн под направлением) - достаточно ли этого, или нужен сводный обзор выбранных приложений по всем слотам?
   - **Статус:** Resolved (2026-08-09, выведено из требований) - инлайн-строка под направлением, постоянная, а не временный диалог. Путь, которым пошло действие «открыть ссылку» - показать диалог сразу после выбора действия и больше ничего не показывать, - здесь не годится: §3.2 требует текстовую подпись выбранного приложения, а §11 п.2 - подпись и сброс рядом с направлением, и после закрытия временного диалога не остаётся ни того, ни другого. Сводный обзор по всем слотам остаётся пожеланием и в объём не входит.
   - **Артефакт:** `PLAN/S1036_gesture-launch-app-selection/research/01__per-slot-payload-and-app-picker.md`

4. **Строки действия `OPEN_APP` описывают прежнее поведение.**
   - **Вопрос:** вскрыто исследованием: название и пояснение действия говорят «открыть главное окно приложения», и после тикета это станет неправдой.
   - **Статус:** Resolved (2026-08-09) - переписываются в EN/RU/UK вместе с реализацией, с проходом по гейту тона `docs/COMMUNICATION_POLICY.md` §6.
   - **Артефакт:** `PLAN/S1036_gesture-launch-app-selection/research/01__per-slot-payload-and-app-picker.md`

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать `OPEN_APP` вместо нового действия.**

- **Решение:** `OPEN_APP` означает «запустить выбранное приложение»; пустой выбор - откат к текущему поведению (вывести FMS).
- **Альтернативы:** отдельное новое действие `LAUNCH_EXTERNAL_APP` рядом с `OPEN_APP`.
- **Почему:** один понятный пункт в списке вместо двух похожих; решение владельца (2026-07-13). Обратная совместимость сохранена через откат при пустом выборе.

**ADR-2: Переиспользовать механику выбора приложения панели быстрого запуска.**

- **Решение:** пер-слотовый выбор приложения опирается на существующую механику выбора установленного приложения.
- **Альтернативы:** отдельный собственный пикер приложений.
- **Почему:** единый UX и одна проверенная реализация видимости пакетов; меньше кода и риска.

## 11. Критерии готовности (strategic-level)

1. В списке действий жеста пункт «вызов приложения» (`OPEN_APP`) означает запуск выбранного приложения.
2. При выборе `OPEN_APP` для направления рядом появляется управление выбора приложения с подписью выбранного и сбросом.
3. Можно выбрать любое установленное приложение (как для панели быстрого запуска) для каждого из двенадцати слотов.
4. По срабатыванию жеста запускается выбранное приложение; при пустом/удалённом выборе - текущий откат (вывести FMS).
5. Сброс возвращает слот в состояние «приложение не выбрано».
6. Новые строки локализованы в EN/RU/UK.
7. Настройка недоступна на сборках без возможности краевых жестов.
