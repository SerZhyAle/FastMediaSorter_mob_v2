# Стратегическая спецификация: S1051 - Перенос кнопки «Открыть спец-возможности» в блок настроек ОС

---

## 1. Проблема

Кнопка «Открыть спец-возможности» открывает системный экран специальных возможностей Android, чтобы пользователь заново включил службу, обеспечивающую скриншоты краевым жестом. Сейчас эта кнопка спрятана внутри диалога настройки краевых жестов и логически не на своём месте. Пользователь, который ищет управление интеграцией с ОС, ожидает найти её в разделе настроек «Взаимодействие с операционной системой», а не в диалоге про жесты.

---

## 2. Цели

1. Кнопка «Открыть спец-возможности» вместе со своей пояснительной подписью появляется в блоке настроек «Взаимодействие с операционной системой».
2. Кнопка исчезает из диалога краевых жестов.
3. Поведение сохраняется: тап открывает системный экран специальных возможностей, а при недоступном интенте показывается обучающий диалог-подсказка.
4. Условие видимости сохраняется: кнопка показывается только там, где доступна возможность «тихого» захвата экрана.

**Non-goals:**

- Изменение действия кнопки или самого механизма специальных возможностей.
- Добавление новой способности или нового экрана.
- Изменение условия, при котором функция «тихого» захвата вообще доступна.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. По возможности переиспользовать уже существующие строковые ключи подписи и кнопки, без заведения новых.

### 3.2 Жёсткие ограничения

- **Flavor:** контрол следует за способностью «тихого» захвата экрана (сейчас доступна в noLegal). Условие видимости остаётся за существующим интерфейсом способности; реализация следует `dev/FLAVOR_DEVELOPMENT_RULES.md` - никаких `BuildConfig.IS_*`-проверок в `src/main`.
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Производительность:** влияние незначительное.
- **Совместимость данных:** миграции не требуется.
- **Локализация:** EN/RU/UK - подпись и текст кнопки уже локализованы, переиспользуются.
- **Доступность:** кнопка остаётся focusable и достижимой с D-pad; подпись остаётся текстовым описанием; отличие не только по цвету.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** видимость только там, где присутствует способность «тихого» захвата экрана (сейчас noLegal); гейт через интерфейс способности, не через флейвор-флаг.
- **UI placement contract:** внутри сворачиваемой группы «Взаимодействие с операционной системой»; пояснительная подпись над кнопкой, как и сейчас в диалоге.
- **Accessibility:** кнопка остаётся focusable и достижимой с D-pad; подпись - её описание; без сигнала только цветом.
- **Validation level:** компиляция плюс проверка на устройстве с noLegal-сборкой: кнопка присутствует в настройках и отсутствует в диалоге.

## 4. Контекст текущей архитектуры

Диалог настройки краевых жестов совмещает несколько разнородных контролов: карту жестов, выбор папки-приёмника скриншотов и этот ярлык специальных возможностей. Кнопка оказалась в диалоге по историческим причинам (S1035). Экран настроек уже содержит группу «Взаимодействие с операционной системой», куда логически относится ярлык. Видимость кнопки управляется способностью контроллера жестов, поэтому целевая группа настроек должна опрашивать ту же способность, а не заводить новый флаг.

---

## 5. Предлагаемый подход

Перенести пару «подпись + кнопка» из презентационной части диалога в группу настроек «Взаимодействие с операционной системой». Группа настроек берёт на себя ответственность: опрос способности «тихого» захвата, показ или скрытие пары, запуск системного интента специальных возможностей и переход к обучающему диалогу-подсказке при неразрешимом интенте. Диалог краевых жестов полностью снимает с себя эту ответственность и связанную с ней вёрстку в обеих ориентациях.

### 5.1 Основные столпы / модули

- **Группа настроек ОС** - новый владелец контрола: видимость, обработка тапа, фолбэк-диалог.
- **Диалог краевых жестов** - теряет пару «подпись + кнопка» и её проводку.

### 5.2 Потоки данных и событий

UI (группа настроек ОС) -> опрос способности «тихого» захвата -> показ или скрытие пары -> тап -> системный интент специальных возможностей -> при неудаче обучающий диалог-подсказка.

### 5.3 Точки расширяемости

Опрос видимости остаётся за уже существующим интерфейсом способности захвата/жестов; новый флейвор-флаг не вводится. Целевая группа настроек должна уметь принимать дополнительный опциональный контрол без переверстки соседних строк.
