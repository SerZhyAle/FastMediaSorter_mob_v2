## 1. Сводка: сколько механизмов

Найдено **два независимых механизма** сворачивания:

1. **Переиспользуемый виджет-заголовок секции** (`ui/common/widget/CollapsibleSectionHeader.kt`, ~315 LOC) - применяется в ~10 местах. Индикатор состояния - текстовые символы `▶` (свёрнуто) / `▼` (развёрнуто) в текстовом префиксе. Тело секции - соседний контейнер, видимостью которого управляет экран-потребитель (виджет сам видимостью тела не управляет).
2. **Список-секция в RecyclerView** (`item_stats_section_header.xml` + адаптер статистики, S0473) - индикатор состояния - графическая иконка-шеврон (`ic_arrow_drop_down`) с анимацией поворота на 180°.

Модуль wear сворачиваемых групп не содержит (layout-директорий нет).

## 3. Зоопарк - в чём расходятся варианты

### A. Индикатор состояния - 3 разных подхода
- Текстовые символы `▶`/`▼` (жёстко в коде виджета) - большинство.
- Графический шеврон `ic_arrow_drop_down` + анимация поворота 180° - статистика.
- Статичные навигационные стрелки `ic_chevron_right` (НЕ сворачивание, переход на подэкран) - часть Operations - визуально путаются со сворачиванием.

### B. Анимация раскрытия
- Везде мгновенное `isVisible = expanded` без перехода.
- Исключение - статистика: анимируется только поворот шеврона (само тело - списком RecyclerView).

### C. Хранение состояния - 4+ варианта
- 4 разных файла SharedPreferences для аналогичных данных (`general_sections_state`, `settings_section_states`, `playback_sections_state`, `media_sections_state`).
- Ещё 2 namespace для редакторов источников.
- in-memory без persist - Duplicates (теряется при пересоздании адаптера), Keybinding (теряется между сессиями).
- Все Settings-оркестраторы читают prefs синхронно на main-thread (обёрнуто в allow-disk-reads).

### D. Оркестрация persist/restore - 8 реализаций
- 2 вынесены в helper-оркестраторы (близки к стандарту).
- 1 - прямо во фрагменте (нарушение «UI без бизнес-логики»).
- остальные - свои data-class и методы в каждом экране, копипаста.
- единого shared-оркестратора нет; общий только сам View-заголовок.

### E. Визуальные токены заголовка
- Фон: `?attr/colorSurfaceVariant` (по умолчанию) vs `?attr/selectableItemBackground` (плеер, статистика) vs внутри MaterialCardView.
- Плеер: жёсткие `@color/white` для текста, hex-цвета фона `#CC004D00` / `#CC00004D` в landscape (нарушение запрета hex в layout), `invisible` в portrait vs `gone` в landscape.
- Разные отступы, размеры текста, bold/not-bold.

### F. Состояние по умолчанию
- Настройки/редакторы - свёрнуто.
- Диалоги - развёрнуто.
- Правило «когда что» нигде не зафиксировано.

### G. Доступность - непоследовательно
- Виджет: `contentDescription` = заголовок, но без объявления состояния (expanded/collapsed) для TalkBack.
- Список-статистика: `contentDescription` не задан вообще.
- AddResource: избыточный `contentDescription` на теге виджета (игнорируется).
- Никто не использует `StateDescription` (API 30+) для объявления состояния.

### H. Landscape-парность нарушена
- 3 экрана с виджетом без `layout-land/` версии (Media settings, ResourceEditor, AddResource).

### I. Информативность свёрнутого состояния
- Только Duplicates показывает в заголовке сводку-счётчик («размер - N файлов»).
- Остальные свёрнутые группы не несут информации, кроме названия.

## 4. Кандидаты в эталон (оценка агентов)

- Самый зрелый по визуалу/парности - секции Settings Playback/Operations (виджет, корректная landscape-парность, управление без хардкодов).
- Самый технически полный пример виджета - VR-секция Media settings (единственная с заполненным help-payload).
- Самый современный индикатор - графический шеврон с ротацией из статистики (Material-стиль, тематизируется через tint, лучше unicode-символов).
- Самый информативный заголовок - Duplicates (динамическая сводка в свёрнутом виде).
- Самый правильный слой хранения - Keybinding (состояние в ViewModel StateFlow), но без persist между сессиями.

**Вывод для §5:** эталон = существующий виджет-заголовок, но с заменой текстового индикатора `▶/▼` на графический шеврон с анимацией (из статистики), плюс единый оркестратор persist/restore поверх единого хранилища, плюс опциональная сводка в свёрнутом заголовке (из Duplicates), плюс state в accessibility. Это объединяет лучшие черты всех найденных вариантов.
