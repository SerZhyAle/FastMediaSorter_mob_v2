# Research 02 - Тактические дизайн-решения по унификации

**Ticket:** S0535
**Дата:** 2026-06-19
**Назначение:** разрешить открытые §6-вопросы стратегии тактическими решениями (research-and-recommend, без owner-вопроса - запрос «выбрать лучший» делегирует выбор). Эти решения задают рамку фаз.

---

## D1. Индикатор состояния (§6.2 - Resolved)

**Решение:** графическая иконка-шеврон с анимацией поворота, тематизируется через `app:tint="?attr/..."`.

- Базовый drawable - существующий `ic_arrow_drop_down` (используется механизмом статистики).
- Свёрнуто - шеврон повёрнут (указывает «развернуть»); развёрнуто - базовая ориентация (вниз). Конкретный угол поворота - деталь Phase 01.
- Заменяет текстовые символы `▶`/`▼`, зашитые в компонент-заголовок.

**Почему:** тематизируется, доступнее, аккуратнее, не зависит от рендеринга unicode, соответствует устоявшейся практике Material и уже применяемому в статистике подходу.

## D2. Хранилище состояния раскрытости (§6.3 - Resolved)

**Решение:** единый consolidated SharedPreferences namespace с консистентной схемой ключей `<screen>__<section>`; НЕ переход на DataStore в рамках S0535. Доступ скрыт за абстракцией стора, чтобы носитель можно было заменить позже без правки экранов.

**Почему:**
- Все текущие потребители уже на SharedPreferences - переход бесшовный.
- Восстановление состояния происходит синхронно в `onViewCreated`; DataStore асинхронный и потребовал бы переписать стартовый поток каждого экрана - несоразмерный риск ради boolean-флагов.
- Объём данных крошечный (флаги раскрытости), преимущества DataStore здесь не реализуются.
- Существующие разрозненные namespace сливаются в один one-time миграцией (см. D5).

**Decay:** при будущей общей миграции проекта на DataStore абстракция стора позволит сменить носитель точечно.

---

## D3. Запоминание раскрытости там, где сейчас её нет (§6.4 - Resolved)

**Решение:** дифференцированно по стабильности идентификатора группы.

- Группы переназначения команд - набор групп фиксирован и стабилен между сессиями, поэтому раскрытость запоминается между сессиями (как у настроек).
- Группы дублей - набор групп и их идентификаторы зависят от результата конкретного сканирования и меняются между сессиями, поэтому стабильного ключа для persist нет; раскрытость остаётся в памяти, но экран приводится к единому компоненту, индикатору и анимации (визуальная унификация без бессмысленного persist).

**Почему:** «единообразие» из запроса означает единый механизм и вид, а не запоминание состояния по нестабильному ключу, которое всё равно не восстановится осмысленно. Единый визуал достигается везде; persist - там, где он имеет смысл.

## D4. Поведение по умолчанию (§6.5 - Resolved)

**Решение:** единое правило раскрытости по умолчанию по типу контекста.

- Плотные конфигурационные экраны (настройки, редакторы источников) - все секции свёрнуты по умолчанию.
- Короткие диалоги с 1-2 группами (выбор папки) - развёрнуты по умолчанию.
- Списочные группировки (дубли, команды, статистика) - свёрнуты по умолчанию.
- Панели плеера (copy/move) - свёрнуты до активации (сохраняется текущее поведение оверлея).

**Почему:** на мелких экранах сворачивание плотных экранов минимизирует скролл (прямая цель запроса); короткие диалоги нет смысла прятать. Правило формализует уже сложившееся поведение, убирая случайные расхождения, и закрепляется в документации (Phase финальной).

---

## D5. Миграция существующего состояния (следствие D2)

**Решение:** one-time перенос существующих ключей раскрытости из всех текущих namespace (`general_sections_state`, `settings_section_states`, `playback_sections_state`, `media_sections_state`, namespace редакторов источников) в единый namespace при первом запуске после обновления; старые namespace после переноса не читаются.

**Почему:** §3.2 «совместимость данных» - текущие пользователи не должны увидеть сброс ранее раскрытых групп.

---

## D6. Анимация (следствие §2.3)

**Решение:** единая лёгкая анимация - поворот шеврона в компоненте-заголовке плюс краткий переход видимости тела, проигрываемый единым оркестратором при переключении; на восстановлении состояния при входе на экран анимация не проигрывается (мгновенно).

**Почему:** §3.2 производительность - анимация не должна мешать прокрутке; начальная отрисовка без анимации исключает мерцание при входе.
