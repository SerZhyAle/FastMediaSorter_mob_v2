## 1. Проблема

Текущая реализация раздела «Возможности приложения» на главной странице проекта представляет собой огромную сетку (grid) из более чем 100 свернутых карточек (details/summary). Все карточки выглядят одинаково, содержат только заголовки и требуют от пользователя клика по каждой плитке для просмотра деталей. Это создает информационный шум («сотни плашек с текстом слаборазичимые друг от друга»), затрудняет быстрое сканирование страницы глазами и не позволяет быстро понять ключевые ценности и палитру функций FastMediaSorter v2.

## 2. Цели

1. Предложить 4 четкие концепции редизайна для презентации палитры возможностей приложения.
2. Составить детальные технические требования к верстке, структуре JS-рендеринга и стилям для каждого варианта.
3. Обеспечить сохранение динамического парсинга данных из канонических файлов возможностей (например, [FEATURES_RU.md](file:///p:/ANDROID/FastMediaSorter_mob_v2/docs/FEATURES_RU.md)) для сохранения SEO-преимуществ и легкого обновления контента в будущем.

**Non-goals:**

- Изменение логики самого парсинга markdown (за исключением адаптации к новой структуре вывода).
- Правка Android-кода или XML-макетов приложения.

## 4. Контекст текущей архитектуры

На текущих страницах сайта ([index.html](file:///p:/ANDROID/FastMediaSorter_mob_v2/index.html) и др.) блок возможностей рендерится скриптом в конце страницы:
1. Загружается соответствующий файл разметки (например, `docs/FEATURES_RU.md`).
2. Разбирается построчно регулярными выражениями: определяются категории (`## Category`) и строки фич (`- **Title** [Tag]: Description`).
3. Для каждого элемента создается элемент `.feature-card` с тегом `<details>` и `<summary>`.
4. Стили стилизованы в [styles.css](file:///p:/ANDROID/FastMediaSorter_mob_v2/styles.css) под стеклянный темный дизайн с HSL-цветами для тегов (`Standard`, `VR`, `Common`).

Поскольку все элементы выводятся одновременно одной сплошной сеткой `.feature-grid`, это перегружает DOM и визуальное восприятие.

## 5. Предлагаемый подход: Четыре варианта реализации

### Вариант 1. Сгруппированный интерактивный рубрикатор (Category Explorer)

Вариант фокусирует внимание пользователя на конкретной теме, скрывая остальные и уменьшая визуальный хаос.

* **Концепция интерфейса:**
  * Панель вкладок (tabs) или боковое меню категорий с иконками слева (на десктопах) или прокручиваемая горизонтальная лента (на мобильных).
  * Разделение на 6–8 укрупненных категорий (например: «Сетевые технологии», «Плееры», «Файловый менеджер», «Заметки и OCR», «Виджеты», «VR-режим»).
  * Внутри активной категории: 2–3 мажорные функции отображаются в виде средних карточек с видимым коротким описанием. Остальные функции отображаются ниже компактным списком-аккордеоном.
* **Логика JavaScript:**
  * При парсинге Markdown группировать объекты фич по массивам категорий.
  * Отрендерить список переключателей вкладок на основе найденных категорий.
  * При клике на вкладку очищать контейнер и рендерить только фичи выбранной категории.
* **CSS / Стилизация:**
  * Класс `.explorer-tabs-vertical` (для десктопов с `flex-direction: column` и `flex: 0 0 250px`) и горизонтальный `.explorer-tabs-horizontal` для мобильных с `overflow-x: auto`.
  * Элемент `.feature-card` внутри категории выстраивается в аккуратную двухколончатую сетку (вместо плотной многоколоночной).

### Вариант 2. Интерактивная карта возможностей (Media Dashboard)

Схема-карта, показывающая полный цикл работы приложения с медиафайлами, позволяющая понять суть программы за секунду.

* **Концепция интерфейса:**
  * 4 больших визуальных блока (колонки или плитки на общем холсте):
    1. **Источники (Sources):** куда подключаемся (SMB, Облако, Локальные папки, Камера).
    2. **Обработка (Processing):** что делаем (Копирование, Поиск дубликатов, ZIP, Рисование).
    3. **Просмотр (Viewers):** как воспроизводим (Видеоплеер 2D/3D, Аудио-служба, PDF/EPUB, Слайд-шоу).
    4. **Среды (Platforms):** где работаем (Android, Android TV, VR-шлемы, Wear OS, Виджеты).
  * Внутри каждого блока отображается плоский аккуратный список ключевых функций в виде ссылок или тегов.
  * При клике на любую функцию открывается компактное всплывающее оверлейное окно (Modal Drawer) справа или снизу с подробным описанием и ссылкой на подробный How-To гайд.
* **Логика JavaScript:**
  * Распределять фичи по 4 фиксированным группам на основе тегов или текстовых совпадений в категориях.
  * Отрендерить статическую HTML-структуру 4 блоков.
  * Написать единый обработчик событий клика, который берет описание фичи из массива данных и выводит в оверлей `.detail-drawer`.
* **CSS / Стилизация:**
  * Макет сетки `.dashboard-map` с `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`.
  * Боковая панель-шторка `.detail-drawer` с переходом `transform: translateX(100%)` для плавного выезда справа при клике.

### Вариант 3. Двухуровневый переключатель («Ключевые» / «Полный список»)

Простой гибридный подход: сначала показать сливки, а подробности оставить для детального изучения.

* **Концепция интерфейса:**
  * Сверху блока возможностей находится крупный стилизованный переключатель: **«✨ Главное»** и **«📋 Все функции»**.
  * Вкладка **«Главное»** показывает фиксированную сетку из 12–16 ключевых, самых красивых и уникальных функций приложения (например, *Очистка дубликатов*, *Стерео-рендер в VR*, *Фоновый плеер*, *OCR-перевод*, *Автобэкап*). Карточки крупные, описание функций (1–2 предложения) открыто сразу, без необходимости клика.
  * Вкладка **«Все функции»** переключает вид на компактный текстовый список с группировкой по категориям, где строка занимает минимум места по высоте.
* **Логика JavaScript:**
  * Задать массив идентификаторов/заголовков ключевых функций `const keyFeatures = [...]`.
  * При рендеринге вкладки «Главное» фильтровать массив по вхождению в `keyFeatures` и выводить карточки в режиме `open` (сразу с текстом описания).
  * При переключении во вторую вкладку выводить упрощенную древовидную структуру без использования тяжелых карточек.
* **CSS / Стилизация:**
  * `.feature-card-major` — крупный шрифт заголовка, градиентная рамка, тень, видимое описание.
  * `.feature-list-compact` — табличная верстка с мелким шрифтом для режима «Все функции».

### Вариант 4. Фильтр возможностей по сценариям использования (Scenario Filter)

Ориентирован на практические задачи пользователя.

* **Концепция интерфейса:**
  * Интеграция с верхним блоком сценариев. При клике на карточку сценария (например, «Цифровая фоторамка») страница плавно прокручивается к списку возможностей, а сам список автоматически отфильтровывается.
  * В списке возможностей остаются только карточки, непосредственно реализующие выбранный сценарий (например, для фоторамки: *Слайд-шоу*, *Фоновая музыка*, *Поддержка ресурсов*, *Интервалы*).
  * Появляется плавающий индикатор фильтра с кнопкой сброса: «Показаны функции для сценария: Цифровая фоторамка (Сбросить ✖)».
* **Логика JavaScript:**
  * Написать функцию `filterFeaturesByScenario(scenarioName)`, которая сопоставляет ключевые слова сценария и описание/заголовки фич.
  * Добавить `addEventListener` на карточки сценариев для вызова фильтрации и плавного скролла `scrollIntoView()`.
* **CSS / Стилизация:**
  * Плавающая панель сброса фильтра `.filter-pill-active` с анимацией появления.
  * Скрытие неподходящих элементов через плавный переход класса `.feature-card.is-hidden { opacity: 0; display: none; }`.

## 13. Заметка о реализации

Все четыре варианта реализованы напрямую в трёх зеркалах лендинга (`index.html`, `index-ru.html`, `index-uk.html`) и стилях `styles.css`: переключатель вариантов, рубрикатор (V1), медиакарта с боковой шторкой (V2), переключатель «Highlights / All» (V3) и фильтр по сценариям (V4) с автопереходом от карточек сценариев.

Исправлен дефект курации: массивы `keyFeatures` и `hiddenFeatureTitles` ссылались на устаревшие названия фич, отсутствующие в текущих `docs/FEATURES*.md`. Из-за этого V1 (мажорные карточки) и V3 (Highlights) показывали ~5 карточек вместо ~14, а скрывающий фильтр был мёртв.

`keyFeatures` пересобран под актуальные заголовки (14 фич, минимум одна на каждую из 7 групп-категорий V1) и локализован для RU/UK по каноническим `FEATURES_RU.md` / `FEATURES_UK.md`. Мёртвый `hiddenFeatureTitles` обнулён, так как FEATURES-файлы уже курированы до одной записи на возможность.

Дополнительно в UK-зеркале выровнены 4 ключа `categoryMapping` (категории 4, 7, 9, 14), которые расходились с заголовками `FEATURES_UK.md` и из-за substring-матча отправляли фичи аудио, слайд-шоу, видео и управления назначениями в дефолтную группу «Настройка» в V1.

Статическая верификация: точное совпадение всех `keyFeatures` с заголовками `- **..**` в соответствующем FEATURES-файле — 14/14 в каждом из трёх зеркал; каждая категория FEATURES сопоставлена ключу `categoryMapping` без дефолтных fallback во всех трёх зеркалах; все 7 групп-категорий V1 покрыты ключевыми фичами. Финальная визуальная проверка в браузере и выбор предпочтительного варианта остаются за владельцем.

## 14. Доработка V4 и ремонт зеркал

Фильтр Variant 4 матчил фичи по вхождению id сценария в URL howto-ссылки, но для большинства id (`video`, `duplicates`, `chromecast`, `vrcinema`, `calculator`, `cloudnotes`, `tv`, `offline`) id отсутствует в URL — фильтр возвращал пусто и панель показывала «функций не найдено». Заменён на явную карту `scenarioFeatureMap` (сценарий → список заголовков фич), по 3–4 фичи на каждый из 16 сценариев, локализованную для EN/RU/UK. Проверено: 0 сценариев с менее чем 3 валидными фичами в каждом зеркале.

При ремонте обнаружена и устранена предсуществующая структурная порча зеркал (из коммитов до этой задачи):
- UK: обрезанная OCR-карточка, отсутствующий заголовок NAS/TV-карточки, продублированная карточка Chromecast, перепутанный порядок, символ-замена `U+FFFD`, отсутствующее закрытие `</body></html>`.
- RU: потерянный хвост страницы — конец roadmap-карточки, секция «Ресурсы и Право» (GitHub/Privacy/Terms), футер со ссылками на Политику и Условия, скрипт анимации шапки.

Оба зеркала восстановлены по образцу целого EN; все три приведены к структурному паритету (31 элемент `<article>`, сбалансировано, валидный HTML).

Опубликовано на GitHub Pages (ветка `main`): live-адреса `index.html`, `index-ru.html`, `index-uk.html`.
