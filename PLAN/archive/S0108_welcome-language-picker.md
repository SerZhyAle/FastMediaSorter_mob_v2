## 1. Проблема

Пользователь, открывающий приложение впервые, видит Welcome-экран полностью на том языке, который определяется системой или предыдущими настройками. Явного выбора языка на стартовом экране нет — он спрятан в Settings, которые новый пользователь ещё не посещал. В результате пользователь с украинским или английским интерфейсом при русскоязычной системе (или наоборот) вынужден читать Welcome на непонятном ему языке до момента, когда он найдёт настройку языка самостоятельно.

---

## 2. Цели

1. На первой странице Welcome появляется компактный переключатель языка (EN / RU / UK).
2. После выбора языка все последующие страницы Welcome немедленно отображаются на выбранном языке.
3. Выбор сохраняется — все экраны и диалоги после закрытия Welcome используют тот же язык.
4. Если пользователь уже выбрал язык ранее (повторный вход в Welcome из Settings), переключатель отражает текущий язык и позволяет его сменить.

**Non-goals:**

- Добавление новых языков помимо уже поддерживаемых (EN/RU/UK).
- Изменение механизма хранения языкового предпочтения (SharedPreferences + Android 13 LocaleManager).
- Отображение переключателя языка на страницах 2–N Welcome.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Переключатель компактный — три кнопки или горизонтальный сегментированный выбор, не выпадающий список.
2. Смена языка без перезапуска и без прерывания Welcome-потока — пользователь остаётся на первой странице, текст обновляется «на месте».

### 3.2 Жёсткие ограничения

- **Flavor:** все (standard, lite, photos, legacy).
- **API level:** minSdk 26 (legacy — 23); решение должно работать и на API 23–32, а не только на Android 13+.
- **Wear OS:** не затрагивается.
- **Производительность:** смена языка не должна вызывать заметную задержку (> 200 мс) или вспышку экрана.
- **Совместимость данных:** изменений в схеме БД нет; язык хранится в SharedPreferences и через LocaleManager — как сейчас.
- **Локализация:** сам переключатель не требует локализации (кнопки — это собственные названия языков: "English", "Русский", "Українська"); все строки остальных страниц Welcome уже локализованы.
- **Доступность:** кнопки языка должны иметь content description; минимальный touch target — 48 dp.

---

## 4. Контекст текущей архитектуры

Welcome-экран построен на ViewPager2 с набором статических страниц. Каждая страница — это `WelcomePage`-объект с ссылками на ресурсы строк. Страницы отрисовываются через общий адаптер; первая страница — приветственная, с тремя feature card-ами.

Локаль применяется в `attachBaseContext()` базовой активности. Смена языка в настройках сейчас требует перезапуска активности. При смене языка через LocaleManager (Android 13+) система сама пересоздаёт активность; на более старых версиях приложение рестартует вручную через `recreate()` или Intent с `FLAG_ACTIVITY_CLEAR_TOP`. ViewPager2 сохраняет текущую страницу через `onSaveInstanceState`.

Текущая архитектура предполагает, что язык фиксируется до старта Welcome. Динамическая смена прямо внутри Welcome-флоу без полного перезапуска активности — нестандартный сценарий, который требует либо пересоздания активности с сохранением страницы, либо обновления строк ViewPager2 в runtime без рестарта.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**Переключатель языка на первой странице Welcome**
- Компонент встраивается только в первую страницу Welcome — ниже заголовка, выше feature card-ов.
- Отображает три варианта: EN / RU / UK, текущий — выделен.
- При смене сохраняет выбор через существующий механизм хранения языка.

**Применение языка без разрыва Welcome-флоу**
- После сохранения нового языка активность пересоздаётся с сохранением номера текущей страницы (уже реализовано через `onSaveInstanceState`).
- При пересоздании локаль применяется в `attachBaseContext` — все строки ViewPager2 уже получат новый язык.
- На Android 13+ LocaleManager инициирует пересоздание самостоятельно; на более старых версиях — `recreate()` вызывается явно.
- Пользователь возвращается на страницу 0 (первую) — выбор языка находится именно там, поэтому «возврат на стартовую страницу» не является деградацией.

**Состояние «язык уже выбран»**
- Если пользователь заходит в Welcome повторно (кнопка в Settings), переключатель инициализируется текущим языком.

### 5.2 Потоки данных и событий

```
Нажатие кнопки языка
  → сохранение языка (SharedPreferences + LocaleManager)
   → пересоздание активности (recreate / LocaleManager-автоматически)
  → attachBaseContext применяет новую локаль
  → ViewPager2 восстанавливается на странице 0
  → все строки первой страницы и далее — на новом языке
```

### 5.3 Точки расширяемости

- Механизм переключателя языка первой страницы может быть использован повторно, если Welcome получит отдельную «языковую» страницу в будущем.
- Список поддерживаемых языков в переключателе должен читаться из единого источника (того же, что используется в Settings), а не дублироваться.

## 6. Открытые вопросы / Research items

1. **Поведение при `recreate()` на Android < 13**
   - **Вопрос:** Нет ли ситуации, когда `recreate()` после смены языка не применяет новую локаль из-за кэша конфигурации?
   - **Нужно выяснить:** Проверить, что `attachBaseContext` с новым языком корректно вызывается после `recreate()` без ручного `FLAG_ACTIVITY_CLEAR_TOP`.
   - **Статус:** Open

2. **Анимация при пересоздании**
   - **Вопрос:** Возникает ли видимая вспышка или мигание фона при `recreate()` на Welcome?
   - **Нужно выяснить:** Можно ли подавить transition-анимацию в момент пересоздания, чтобы смена языка выглядела плавно.
   - **Статус:** Open

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| LocaleManager (API 33+) вызывает полный перезапуск приложения, а не только `recreate()` | Низкая | Состояние Welcome сбрасывается, пользователь видит старт заново | Сохранить флаг «Welcome открыт» и текущую страницу до смены языка; восстановить после |
| `recreate()` на API < 33 не подхватывает новую локаль из-за кэша конфигурации в BaseActivity | Средняя | Welcome остаётся на старом языке после нажатия кнопки | Сбросить кэш локали в LocaleHelper перед `recreate()`; протестировать на эмуляторе API 26, 30, 32 |
| Визуальный артефакт (вспышка) при `recreate()` | Средняя | Неприятный UX при смене языка | `overridePendingTransition(0, 0)` или установка window background до `recreate()` |

## 9. Архитектурные решения (ADR)

**ADR-1: Пересоздание активности вместо runtime-замены строк**

- **Решение:** При смене языка на первой странице Welcome вызывать `recreate()` (или позволить LocaleManager сделать это автоматически), а не обновлять строки ViewPager2 в runtime.
- **Альтернативы:** Динамическое обновление всех текстовых вью через `updateResources()` без рестарта.
- **Почему:** Runtime-обновление требует ручного обхода всех вью во фрагментах адаптера и рискует пропустить скрытые элементы. `recreate()` гарантирует полную корректность локали через существующий `attachBaseContext` без дополнительной логики.

**ADR-2: Переключатель языка только на странице 0, не как отдельная страница**

- **Решение:** Встроить выбор языка в существующую первую страницу Welcome, а не добавлять отдельный нулевой шаг.
- **Альтернативы:** Отдельная языковая страница перед текущими страницами.
- **Почему:** Контент первой страницы достаточно лаконичен, чтобы вместить компактный трёхкнопочный переключатель. Отдельная страница удлиняет флоу без необходимости.

## 11. Критерии готовности (strategic-level)

1. На первой странице Welcome виден компактный переключатель языка с тремя вариантами (EN / RU / UK).
2. После нажатия на кнопку языка, отличного от текущего, все страницы Welcome немедленно отображаются на выбранном языке.
3. После завершения Welcome основной экран приложения и все диалоги работают на выбранном языке.
4. Повторный вход в Welcome (через Settings) показывает переключатель с уже выбранным языком.
5. Функция работает на API 26..35 (все flavors) без видимых артефактов интерфейса.
6. Существующий выбор языка в Settings не нарушен.
