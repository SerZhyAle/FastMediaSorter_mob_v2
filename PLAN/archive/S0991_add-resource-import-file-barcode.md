## 1. Проблема

Пользователь хочет в меню «Добавить ресурс», помимо четырёх типов ресурсов, добавить пункты «Импорт из файла» и «Импорт по штрих-коду».

**Research (2026-07-11, автономно):** сама функциональность импорта из файла и по QR уже реализована (companion-импорт, см. §4). «Меню четырёх типов» - это табы выбора типа ресурса внутри экрана добавления. Ask сводится к размещению новых точек входа рядом с этими табами. Что именно - решает владелец (§6). Сиблинг: S0992 (те же действия как кнопки в заголовке SFTP-формы).

---

## 2. Цели

1. На экране выбора типа ресурса («Добавить ресурс») рядом с четырьмя карточками типов доступны две точки входа: «Импорт из файла» и «Импорт по штрих-коду».
2. Обе точки входа переиспользуют существующий companion-импорт (файл через SAF, QR через камеру) - без новой функциональности импорта.
3. Совместно с S0992 обе кнопки в шапке SFTP-формы переименованы в те же подписи и дёргают тот же единый источник входа (без дублирования логики).
4. Пункт «Импорт по штрих-коду» скрыт на устройствах без камеры (как текущая QR-кнопка).

**Non-goals:**

- Обобщение формата импорта на не-companion источники или произвольный штрих-код (scope остаётся companion `.fmscfg` / companion-QR).
- Импорт ресурсов типов, отличных от SFTP (companion-формат порождает SFTP-ресурсы).
- Изменение бэкенда импорта (`ImportCompanionConfigUseCase`, парсер, coordinator).

## 4. Контекст текущей архитектуры

Добавление ресурса: `btnAddResource` (главный экран) -> `NavigateToAddResource(activeTab)` -> `AddResourceActivity`, где тип выбирается табами (`ResourceTab`: SMB, FTP_SFTP, Cloud, ..). Отдельного «меню четырёх типов» перед экраном нет - это и есть табы.

Импорт уже реализован в SFTP-секции экрана:
- companion `.fmscfg` из файла (SAF) - `AddResourceCompanionCoordinator.importFromUri`, «импорт из файла».
- companion-QR - `CompanionQrScanActivity` -> `importFromPayload` (S0988), «импорт по штрих-коду», виден при наличии камеры.

Бэкенд: `ImportCompanionConfigUseCase`. Импорт сейчас производит SFTP-ресурсы. Значит нужна не новая функциональность, а решение о размещении точек входа среди/рядом с табами типов (§6). Смежно: коллизия host:port при импорте кредов - S0987.

## 5. Предлагаемый подход

Точки входа импорта - чисто UI-надстройка над уже существующим companion-импортом. Никаких новых доменных ролей: экран добавления ресурса получает единый внутренний источник запуска двух действий (выбор файла через SAF, скан QR через камеру), к которому подключаются все места размещения кнопок.

### 5.1 Основные столпы / модули

- **Экран добавления ресурса** - хост обеих точек входа. Единый внутренний запуск действий импорта переиспользуется двумя местами: секцией выбора типа (карточки) и шапкой SFTP-формы (S0992).
- **Companion-импорт (существующий)** - слой применения (парсер + use-case + coordinator). Не меняется.
- **Гейт камеры (существующий)** - системная фича камеры решает видимость точки «по штрих-коду» в обоих местах.

### 5.2 Потоки данных и событий

- UI (карточки типов ИЛИ шапка SFTP) -> единый запуск действия импорта -> существующий слой применения (companion) -> событие результата -> экран закрывается при успехе.
- Видимость точки «по штрих-коду» = наличие камеры; иначе остаётся только «из файла».

### 5.3 Точки расширяемости

- Единый источник входа оставляет открытой возможность в будущем обобщить формат/тип импортируемого ресурса, не трогая места размещения кнопок.

## 11. Критерии готовности (strategic-level)

1. На экране выбора типа ресурса рядом с четырьмя карточками видны две точки входа: «Импорт из файла» и «Импорт по штрих-коду» (EN/RU/UK).
2. Нажатие «Импорт из файла» открывает SAF-выбор `.fmscfg`; успешный импорт добавляет ресурс(ы) и закрывает экран - как текущая кнопка в SFTP-секции.
3. Нажатие «Импорт по штрих-коду» открывает скан камеры; успешный импорт добавляет ресурс(ы) и закрывает экран.
4. На устройстве без камеры точка «Импорт по штрих-коду» скрыта в обоих местах.
5. В SFTP-форме (S0992) те же две кнопки перенесены в шапку и переименованы в те же подписи; старые companion-строки не остаются мёртвыми.
6. Обе точки входа дёргают единый внутренний источник запуска действий - логика импорта не продублирована.
