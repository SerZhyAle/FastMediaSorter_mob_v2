**Захвачено:** 2026-08-22

**Текст:**

Каталог маршрутов: QS-тайл AppLaunchPanelTileService наследует TileService (API 24), но legacy-флейвор с minSdk 23 не вырезает его из манифеста, в отличие от Dropbox AuthActivity. Evidence: app_v2/src/legacy/AndroidManifest.xml:1-23 (нет tools:node="remove" для сервиса) vs app_v2/src/main/AndroidManifest.xml:453 и app_v2/build.gradle.kts:537 (minSdk 23). Найдено разведкой в рамках S1736, вне его объёма. Не подтверждено как краш - требует собственной проверки на API 23.

**Захвачено во время:** S1736

---

## 1. Проблема / симптом

`app_v2/src/main/AndroidManifest.xml:453` объявляет `<service android:name=".core.AppLaunchPanelTileService">`. Класс наследует `android.service.quicksettings.TileService`, появившийся в API 24. Флейвор `legacy` собирается с `minSdk = 23` (`app_v2/build.gradle.kts:537`), и его оверлей `app_v2/src/legacy/AndroidManifest.xml` удаляет через `tools:node="remove"` только Dropbox `AuthActivity`, но не этот сервис.

То есть на устройствах API 23 в манифесте остаётся объявление сервиса, чей базовый класс на этой платформе отсутствует. Симптом не наблюдался на устройстве и не подтверждён как краш: разбор манифеста классы не загружает, а система API 23 не знает про Quick Settings и не должна биндить сервис. Поэтому тикет заведён как проверка, а не как подтверждённый дефект.

Найдено разведкой каталога маршрутов в рамках S1736; к объёму того тикета (единый перечень суб-программ) отношения не имеет.

---

## 2. Корневая причина

Дефекта нет - состояние сознательное, но нигде не записанное, поэтому разведка нашла его как аномалию.

Проверено 2026-08-22:

- Собранный манифест `legacy` (`app_v2/build/intermediates/merged_manifest/legacyDebug/processLegacyDebugMainManifest/AndroidManifest.xml`)
  действительно объявляет `minSdkVersion 23` (строка 8) и сохраняет `<service .. AppLaunchPanelTileService>` (строка 774).
- Класс не упоминается больше нигде: единственные вхождения `AppLaunchPanelTileService` в `app_v2/src` -
  это строка манифеста и объявление самого класса. Приложение его не инстанцирует и не адресует.
- На API 23 системе неизвестно действие `android.service.quicksettings.action.QS_TILE`, поэтому сервис
  не биндится, класс не загружается, а разбор манифеста классы не загружает вовсе. Неизвестное имя в
  `android:permission` при установке не проверяется - оно проверяется при биндинге, которого не будет.

Убрать сервис из `legacy`, как убран Dropbox `AuthActivity`, было бы не безопасностью, а потерей
охвата: `legacy` ставится на любой API от 23 и выше, а сама панель быстрого запуска
(`ui/applaunchpanel/`) лежит в `src/main` и есть во всех флейворах. Тайл на API 24+ работает.

---

## 3. Исправление

В оверлей `app_v2/src/legacy/AndroidManifest.xml` добавлен комментарий, объясняющий, почему сервис
здесь намеренно не удаляется. Место выбрано не случайно: рядом лежит прецедент с Dropbox
`AuthActivity`, и именно туда смотрит следующий аудитор, сравнивая два компонента.

Кода не менялось.
