# Стратегическая спецификация: S0523 - Быстрый захват из overflow-меню в стандартные папки телефона

**Ticket:** S0523
**Status:** Archived
**Priority:** 50

**Roadmap entry:** Ad-hoc - запрос 2026-06-19

> **Scope:** STRATEGIC. Цели, ограничения, открытые вопросы. Без имён классов, путей, лимитов строк, миграций Room, модулей Hilt.

## 1. Проблема

На главном экране есть overflow-меню (три точки), где сейчас живут только «дополнительные инструменты»: калькулятор, быстрый перевод с камеры, мини-игра. Приложение уже умеет записывать аудио, видео и делать фото «в ресурс» (из экрана просмотра), но с главного экрана нет быстрого способа захватить медиа сразу в стандартные публичные папки телефона.

Владелец просит добавить в это же меню три пункта быстрого захвата:
- быстрая запись с диктофона - в стандартную папку звукозаписей телефона;
- быстрая запись видео - в стандартную папку видео телефона;
- быстрый кадр (фото) - в стандартную папку фото телефона.

Каждый пункт работает так же, как существующая «запись в ресурс», но пишет результат не в ресурс сортировки, а в публичную папку устройства. Пункт виден только если включён в настройках; если выключен - его в меню нет. Если не включён ни один пункт меню (старые плюс новые) - кнопка меню не показывается совсем, ровно как это работает сейчас.

---

## 2. Цели

1. Из overflow-меню пользователь может запустить быструю голосовую запись, которая сохраняется в стандартную публичную папку звукозаписей/аудио телефона.
2. Из overflow-меню пользователь может снять быстрое видео, которое сохраняется в стандартную публичную папку видео телефона.
3. Из overflow-меню пользователь может сделать быстрый кадр, который сохраняется в стандартную публичную папку фото телефона.
4. Каждый из трёх пунктов появляется в меню только если включён соответствующий существующий тумблер захвата (микрофон/видео/фото) И сборка/флейвор поддерживает этот тип медиа.
5. Кнопка overflow-меню остаётся скрытой, когда не включён ни один пункт (существующие плюс новые) - поведение не меняется.
6. Захваченные файлы попадают туда, где их видят системная галерея, файловый менеджер и другие приложения (публичные коллекции), как обычные записи/фото/видео телефона.

**Non-goals:**

- Не меняем существующие потоки «запись в ресурс» на экране просмотра.
- Не добавляем редактирование, обрезку или постобработку захваченного медиа.
- Не вводим отдельный экран захвата или встроенную галерею результатов.
- Не трогаем существующие пункты калькулятора, перевода и мини-игры.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Поведение захвата идентично существующей «записи в ресурс» - отличается только назначение (публичная папка телефона вместо ресурса).
2. Каждый пункт управляется уже существующим тумблером захвата (запись микрофона / запись видео / съёмка фото) - отдельные настройки не вводятся (упрощение по фидбэку владельца 2026-06-19).
3. Имена файлов с понятной меткой времени, чтобы результат было легко найти в папке.

### 3.2 Жёсткие ограничения

- **Flavor:** гейт по медиа-возможности, а не по типу пункта. Голосовой пункт - только во флейворах с поддержкой записи микрофона (standard, legacy, noLegal, vr). Видео-пункт - где поддерживается видео (standard, lite, legacy, noLegal, vr). Фото-пункт - где поддерживаются изображения (все флейворы). Для photos доступен только фото-пункт; для lite - видео и фото (без голоса). Реализация следует `dev/FLAVOR_DEVELOPMENT_RULES.md`: гейт через существующую инъектируемую поверхность медиа-возможностей, без `BuildConfig.IS_*`-проверок в `src/main`.
- **API level:** запись в публичные коллекции выполняется по scoped-storage-безопасному пути на API 29+. «Папка по умолчанию для звукозаписей» зависит от версии: выделенная коллекция звукозаписей существует только на новых Android, на более старых (standard 26-30, legacy 23-25) - откат в публичную папку музыки/аудио. Фото - в публичную коллекцию изображений, видео - в публичную коллекцию видео.
- **Wear OS:** не затрагивается.
- **Производительность:** ресурсы записи/камеры освобождаются сразу по завершении или при уходе с экрана в момент захвата - без утечек рекордера/камеры.
- **Совместимость данных:** новых настроек не добавляется (упрощение 2026-06-19) - пункты переиспользуют существующие тумблеры захвата; миграций нет.
- **Локализация:** EN/RU/UK обязательны для всех новых подписей пунктов, заголовков/описаний тумблеров, тостов и сообщений об ошибках.
- **Доступность:** пункты меню и тумблеры достижимы с клавиатуры, D-pad и TalkBack; статус различается не только цветом.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** голос → mic-capable (standard, legacy, noLegal, vr); видео → video-capable (standard, lite, legacy, noLegal, vr); фото → image-capable (все). photos - только фото; lite - видео и фото. Гейт через инъектируемую поверхность медиа-возможностей по `dev/FLAVOR_DEVELOPMENT_RULES.md`.
- **API level constraints:** записи в публичные коллекции через системный медиа-провайдер на API 29+; выделенная коллекция звукозаписей только на API 31+, откат в публичную папку музыки/аудио на API 26-30 и legacy 23-25.
- **Data compatibility:** три аддитивных булевых настройки, дефолт выключено, без разрушающей миграции; матрица пресетов профиля устройства обновляется под новые поля.
- **Localization:** паритет EN/RU/UK для всех новых строк (подписи пунктов, тумблеры, тосты, ошибки).
- **UI placement contract:** три новых пункта в том же overflow-popup главного экрана, в заданном порядке после существующих; кнопка меню скрыта, когда суммарное число включённых пунктов равно нулю.
- **Accessibility:** пункты и тумблеры достижимы с клавиатуры/D-pad/TalkBack, статус не только цветом.
- **Communication policy:** тосты и ошибки (отказ в разрешении, сбой захвата, подтверждение «сохранено в ..») проходят тон-гейт `docs/COMMUNICATION_POLICY.md` (§6 чеклист) перед интеграцией строк.
- **Validation level:** debug-сборки standard/lite/photos/legacy; on-device проверка каждого включённого пункта (файл появляется в публичной папке и виден системе); аудит локализации строк.
- **Owner sign-off:** ожидается (дата при подтверждении владельцем).
- **Related tickets:** S0349, S0464, S0465, S0359, S0100 - связанные, не блокирующие.

## 4. Контекст текущей архитектуры

Главный экран хостит overflow-меню; каждый пункт показывается или скрывается по флагу настройки, а кнопка меню скрыта, когда число включённых пунктов равно нулю. Возможности захвата уже есть: запись аудио, съёмка фото встроенной камерой, запись видео - сегодня они пишут в выбранный ресурс сортировки или в настроенное назначение. Сохранение в публичные медиа-коллекции телефона уже решено scoped-storage-безопасным писателем, которым пользуются существующие пути «захват в публичную папку».

Чего не хватает: самих трёх пунктов меню; их независимых тумблеров; связки действий захвата от хоста главного экрана с назначением, жёстко заданным в стандартную публичную папку, а не в ресурс. Сейчас это невозможно, потому что в меню нет таких пунктов, а менеджеры захвата привязаны к хосту экрана просмотра и к назначениям-ресурсам, а не к меню главного экрана с публичными папками.

## 5. Предлагаемый подход

Переиспользовать существующее поведение захвата (аудио, фото, видео) без нового движка, изменив только назначение на стандартную публичную папку телефона для соответствующего типа медиа, и добавить три условных пункта в overflow-меню главного экрана с независимыми тумблерами.

### 5.1 Основные столпы / модули

- **Пункты меню.** Три новых условных пункта в overflow-меню главного экрана по существующему паттерну изолированного помощника пункта (на каждый пункт: подсчёт количества, наполнение, обработка нажатия). Пункт виден тогда и только тогда, когда включён соответствующий существующий тумблер захвата И поддерживается соответствующая медиа-возможность.
- **Без новых настроек (упрощение 2026-06-19).** Пункты переиспользуют существующие тумблеры захвата: голос - «Включить запись с микрофона» (`micRecordingEnabled`), видео - «Включить запись видео» (`!disableVideoCapture`), фото - «Включить съёмку фото» (`!disableCameraCapture`). Отдельные тумблеры не создаются - они дублировали бы существующие.
- **Действия захвата.** Переиспользуют существующие захваты аудио/фото/видео, но с назначением, зафиксированным в стандартную публичную папку телефона для данного типа. Новый стек захвата не создаётся.
- **Запись в публичную папку.** Все три проходят через существующий scoped-storage-безопасный писатель публичных коллекций, чтобы файлы были видны галерее и файловому менеджеру.
- **Видимость меню.** Переиспользует существующую логику «скрыть кнопку, когда число включённых пунктов равно нулю», расширенную тремя новыми пунктами.

### 5.2 Потоки данных и событий

- Поток настроек → хост главного экрана обновляет флаги включённости по каждому пункту → пересчитывает число включённых пунктов → показывает/скрывает кнопку меню → пересобирает цепочку фокуса. Форма потока не меняется, добавляются три флага.
- Нажатие пункта → действие захвата для своего типа медиа → захват во временный файл → запись в публичную коллекцию (звукозаписи/видео/изображения) → подтверждение пользователю с указанием назначения.
- Гейт медиа-возможности применяется до того, как тумблер начнёт действовать, и до того, как пункт попадёт в подсчёт.

### 5.3 Точки расширяемости

- Паттерн помощника пункта остаётся открытым: будущие инструменты добавляются так же. Стоит обобщить пер-пунктовый учёт флагов в небольшой список/реестр, чтобы добавление N-го пункта не наращивало ветвления хоста (опциональный рефакторинг, нейтральный для продукта).
- Поверхность медиа-возможностей (интерфейс в `src/main`, реализация на флейвор) - единственный гейт флейвор-скоупа; новые типы медиа расширяют её, а не `BuildConfig`-проверку в main.
- Писатель публичных коллекций - единственный шов назначения; новые назначения (в т.ч. распознавание выделенной коллекции звукозаписей) расширяют его.

## 6. Открытые вопросы / Research items

1. **Папка звукозаписей по умолчанию и её индексация**
   - **Вопрос:** куда именно падает голосовая заметка, чтобы пользователь нашёл её как обычную звукозапись, и чтобы она проиндексировалась системой?
   - **Варианты:** выделенная коллекция звукозаписей на новых Android с откатом в публичную папку музыки/аудио на старых.
   - **Нужно выяснить:** точное соответствие коллекции и индексацию в системном медиа-провайдере. Текущий классификатор путей не распознаёт папку звукозаписей как публичную аудио-коллекцию - это нужно покрыть в рамках фичи, иначе на API 29+ файл не проиндексируется.
   - **Статус:** Resolved - `DIRECTORY_RECORDINGS` на API 31+, откат в `DIRECTORY_MUSIC` ниже; классификатор расширяется распознаванием папки звукозаписей. Фаза 02.
   - **Артефакт:** `PLAN/S0523_menu-quick-capture-device-folders/research/01__recordings-folder-indexing.md`

2. **Хост-адаптация захвата с главного экрана**
   - **Вопрос:** существующие менеджеры захвата привязаны к хосту экрана просмотра и к ресурсу. Как запускать старт/стоп голоса и съёмку видео/фото из overflow-меню главного экрана.
   - **Варианты:** нейтральный к хосту вход в существующий рекордер/камеру; либо foreground-service для голоса (старт/стоп одним пунктом).
   - **Нужно выяснить:** минимально инвазивный путь, сохраняющий UX «как запись в ресурс», с корректной регистрацией результата камеры на хосте.
   - **Статус:** Resolved - выделенные хост-нейтральные менеджеры захвата (голос/камера) переиспользуют существующие бэкенды; остаётся один UX-вопрос старт/стоп голоса (owner-гейт по Rule 10, см. INDEX «Pre-Implementation Blockers»). Фазы 03-04.
   - **Артефакт:** `PLAN/S0523_menu-quick-capture-device-folders/research/02__host-capture-adaptation.md`

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать существующие захваты и публичный писатель, менять только назначение**

- **Решение:** не строить новый движок захвата; переиспользовать существующие захваты аудио/видео/фото и существующий scoped-storage-безопасный писатель, меняя только назначение на публичную папку телефона.
- **Альтернативы:** отдельный новый стек захвата для главного экрана.
- **Почему:** минимизирует дублирование, наследует исправления по хранилищу и разрешениям, совпадает с пожеланием владельца «как запись в ресурс».

**ADR-2: Пер-пунктовый гейт по возможности и тумблеру, меню скрыто при нуле**

- **Решение:** каждый пункт = (собственный тумблер) И (поддержка медиа во флейворе); кнопка меню скрыта при нулевом числе включённых пунктов.
- **Альтернативы:** единый общий тумблер «быстрый захват».
- **Почему:** совпадает с формулировкой владельца и с поведением существующих пунктов (калькулятор, мини-игра).

## 11. Критерии готовности (strategic-level)

1. При всех трёх выключенных тумблерах overflow-меню главного экрана ведёт себя ровно как сейчас (кнопка скрыта, если нет других включённых пунктов).
2. Включение голосового тумблера (на mic-capable сборке) показывает голосовой пункт; запись создаёт файл в стандартной публичной папке звукозаписей/аудио, видимый в системном файловом менеджере.
3. Включение видео-тумблера показывает видео-пункт; захват создаёт файл в стандартной публичной папке видео телефона.
4. Включение фото-тумблера показывает фото-пункт; захват создаёт файл в стандартной публичной папке фото телефона.
5. На сборке без нужной возможности (например, голос на lite или photos) соответствующий тумблер и пункт недоступны.
