**Split decision (recorded for context):**

- S0545 keeps the unified in-app capture host but the capture mode is FIXED by the launching command (photo entry -> photo controls only, video entry -> video controls only). ## 1. Проблема

Главное активити в меню переполнения ("три точки") показывает "Фото" и "Видео" как две отдельные команды захвата. После S0545 обе команды ведут в один и тот же встроенный host камеры, но режим фиксируется вызывающей стороной: команда "Фото" открывает host в фоторежиме, "Видео" - в видеорежиме. Для точек входа с жёстким контрактом результата (OCR, быстрый захват в ресурс, виджет) это правильно и менять нельзя.

Но для главного меню, у которого нет жёсткого контракта результата (снимок просто сохраняется в публичную папку), две раздельные кнопки - лишнее дробление. Пользователь, открыв камеру, не может передумать и переключиться между фото и видео без выхода и повторного запуска из меню.

## 2. Цели

1. Объединить в меню переполнения главного активити команды "Фото" и "Видео" в одну команду "Камера".
2. Дать из этой точки входа экранное переключение между фото- и видеорежимом съёмки (тот самый переключатель `PHOTO|VIDEO`, отложенный из S0545).
3. Сохранить контракт результата generic: команда "Камера" принимает либо фото, либо видео и сама определяет место сохранения по фактически снятому виду медиа.
4. Не трогать ни одну точку входа с фиксированным режимом (OCR, быстрый захват в ресурс/browse, виджет) - они продолжают запускать host в фиксированном режиме без переключателя.

**Non-goals:**

- Не добавлять экранный переключатель режима к точкам входа с жёстким контрактом результата.
- Не менять набор camera-контролов S0545 (вспышка, zoom, линзы, фокус, микрофон) - переиспользуются как есть.
- Не вводить новые разрешения манифеста - `CAMERA` и `RECORD_AUDIO` уже объявлены.
- Не менять голосовой захват (третий пункт того же меню) - он остаётся отдельным.

### 3.4 Resolved decisions (open questions answered)

- **Result contract (open Q §3 раннего драфта).** Generic-результат уже технически возможен: host пакует `EXTRA_RESULT_MEDIA_KIND` (фактически снятый вид). Команда "Камера" читает его и выбирает место сохранения; фиксированные точки входа сохраняют строгий контракт, поскольку их режим неизменен.
- **`allowModeSwitch` flag.** В контракт host'а добавляется флаг "разрешить переключение режима" (по умолчанию false). Только команда "Камера" передаёт true. S0545 §3.4 явно требовала оставить под это место - тут оно реализуется.
- **Mode-switch affordance.** Сегментированный контрол `ФОТО|ВИДЕО` над спуском (Samsung-familiar, ADR-7 из S0545). Переключение пересобирает camera-сессию под нужный набор use-cases и обновляет видимость контролов (микрофон только в видео, спуск становится record start/stop).
- **Overflow ordering.** Единая "Камера" занимает позицию бывшей пары "Фото"/"Видео" в том же блоке быстрого захвата; голосовой пункт - рядом, как и раньше.
- **Degenerate gating (default decision).** Когда доступен только один режим (второй отключён настройкой или не поддержан флейвором), команда "Камера" запускает host в этом единственном режиме без переключателя. Переключатель показывается только когда доступны оба режима. Это уважает существующие настройки и не создаёт "мёртвый" переключатель.
- **Temp-file extension.** Поскольку фактический вид медиа решается на экране, вызывающая сторона передаёт каталог и базовое имя без расширения; host дописывает корректное расширение по снятому виду и возвращает фактический путь в результате.

## 4. Контекст текущей архитектуры (по ресёрчу)

- **Host камеры един и режим-осведомлён (S0545).** Встроенный экран захвата принимает режим через контракт интентов и фиксирует его на время сессии. Переключения режима в UI нет. Контракт уже различает результат по виду медиа.
- **Сессия пересобирается под режим.** Внутренний слой camera-сессии выбирает image- или video-use-case по флагу видеорежима при каждом bind; смена линзы уже выполняет повторный bind - тот же механизм годится для смены режима.
- **Главное меню - три пункта быстрого захвата.** Меню переполнения главного активити показывает голос/видео/фото отдельными пунктами; их видимость = (настройка включена) И (медиа-возможность поддержана). Фото и видео ведут в host с фиксированным режимом.
- **Результат главного меню сейчас различается флагом до запуска.** Точка входа главного меню сейчас определяет фото/видео по флагу, выставленному до запуска host'а. При экранном переключении этот флаг станет неверным - результат должен читаться из `EXTRA_RESULT_MEDIA_KIND`, а не из доспускового флага.
- **Сохранение - общий шов.** Захват из главного меню сохраняется через общий saver в публичные папки (фото -> DCIM/Camera, видео -> Movies); этот шов переиспользуется без изменений.
- **Фиксированные точки входа.** OCR (только фото), быстрый захват в ресурс/browse (фото и видео отдельными кнопками) и виджет (режим задан настройкой виджета) - все с жёстким режимом, переключатель к ним не добавляется.

## 5. Предлагаемый подход

1. **Расширить контракт host'а.** Добавить флаг разрешения переключения режима (по умолчанию выключен), способ передать выход как каталог + базовое имя (расширение решит host), и результат-поле с фактическим путём снятого файла. Существующие фиксированные вызовы не меняются.
2. **Дать host'у экранный переключатель.** Когда переключение разрешено, показать сегментированный контрол `ФОТО|ВИДЕО` над спуском. Переключение меняет режим во flow-менеджере, пересобирает camera-сессию и обновляет видимость контролов. Во время записи переключатель заблокирован.
3. **Сделать результат generic.** Host пакует фактический вид медиа и путь файла. Вызывающая сторона главного меню выбирает место сохранения по виду.
4. **Объединить меню.** Заменить пару "Фото"/"Видео" в меню главного активити одной командой "Камера" (голос остаётся отдельным). Видимость - когда доступен хотя бы один режим. Передавать host'у разрешение переключения = доступны оба режима; начальный режим = фото, если доступно, иначе видео.
5. **Не трогать фиксированные точки входа.** OCR, ресурс/browse, виджет продолжают запускать host в фиксированном режиме - регрессий нет.

## 7. Риски

- **Пересборка сессии при переключении режима даёт мерцание preview.** Вероятность средняя. Митигация: переиспользовать уже существующий путь повторного bind (как при смене линзы), без второй сессии.
- **Доспусковой флаг видео в главном меню станет неверным при экранном переключении.** Вероятность высокая, если не переключиться на чтение результата. Митигация: читать вид медиа и путь из результата host'а, убрать опору на доспусковой флаг.
- **Расхождение расширения временного файла с фактически снятым видом.** Вероятность высокая при доспусковом выборе расширения. Митигация: каталог + базовое имя от вызывающей стороны, расширение дописывает host по снятому виду, путь возвращается в результате.
- **Переключение во время записи повреждает запись.** Вероятность средняя. Митигация: блокировать переключатель на время активной записи.
- **Переключатель рассинхронизирован между портретом и ландшафтом.** Вероятность средняя. Митигация: добавить контрол синхронно в оба layout, проверить обе ориентации (CLAUDE.md Rule 11).
- **Видео нельзя надёжно проверить на эмуляторе (унаследовано от S0545).** Вероятность высокая. Митигация: гейт обязательным device-тестом.

## 9. Архитектурные решения (ADR)

**ADR-1: Экранное переключение режима - привилегия точки входа без жёсткого контракта результата**

- **Решение:** переключатель `ФОТО|ВИДЕО` доступен только команде "Камера" главного меню; все точки входа с фиксированным контрактом результата остаются без переключателя.
- **Альтернативы:** дать переключатель всем точкам входа.
- **Почему:** OCR/ресурс/виджет полагаются на предсказуемый вид результата; молчаливая смена фото на видео сломала бы их обработку (исходный owner-довод в §0).

**ADR-2: Generic-результат через вид медиа, а не доспусковой флаг**

- **Решение:** место сохранения выбирается по `EXTRA_RESULT_MEDIA_KIND` из результата, а не по флагу, выставленному до запуска.
- **Альтернативы:** оставить доспусковой флаг.
- **Почему:** при экранном переключении доспусковой флаг становится неверным.

**ADR-3: Host владеет расширением временного файла в режиме переключения**

- **Решение:** в режиме переключения вызывающая сторона передаёт каталог + базовое имя, host дописывает расширение по снятому виду и возвращает фактический путь.
- **Альтернативы:** выбирать расширение до запуска.
- **Почему:** фактический вид медиа известен только после съёмки.

**ADR-4: Вырожденный гейтинг запускает единственный доступный режим без переключателя**

- **Решение:** при одном доступном режиме команда "Камера" открывает host в нём, без переключателя.
- **Альтернативы:** всегда показывать переключатель; прятать команду целиком.
- **Почему:** уважает пользовательские настройки и флейвор, не создаёт "мёртвый" контрол.
