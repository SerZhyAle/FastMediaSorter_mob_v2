## 1. Проблема

Виджет часов на рабочем столе лаунчера пассивен и мелок: короткий тап уже открывает будильники, но нет перехода в календарь, время показано без секунд, а стартовый размер (2x1) слишком мал, чтобы часы читались как главный элемент стола. Погода придёт отдельным виджетом позже (S0426), поэтому ценность часов сейчас - быть крупными, с секундами и функциональными. Область - гаджет часов поверхности лаунчера и его размер/жесты.

---

## 2. Цели

1. Короткий тап по часам открывает будильники устройства (уже есть - сохранить).
2. Долгий тап по часам открывает приложение календаря устройства.
3. Часы показывают секунды.
4. Часы крупные по умолчанию: стартовый размер больше 2x1 (около 4x2), текст крупнее.
5. Размер часов далее меняется штатным механизмом ресайза гаджетов (S1093); пол ужатия часов - 2x1.

**Non-goals:**

- Погода в часах - отдельный виджет позже (S0426).
- Собственный экран будильников/календаря - только переход в системные приложения.
- Настройка формата времени в UI - следует системной настройке 12/24ч, как сейчас.

## 4. Контекст текущей архитектуры

Часы - гаджет поверхности лаунчера: две строки `TextClock` (время без секунд + дата), короткий тап открывает будильники безопасным резолвом. Стартовый размер гаджета берётся из его объявленного default-размера (для добавления через пикер) и из стартового набора (для засева), а пол ужатия при ресайзе (S1093) сейчас берётся из того же default-размера. Поэтому «крупнее по умолчанию, но с полом 2x1» требует развязать объявленный стартовый размер и пол ресайза; долгий тап и секунды - точечные правки гаджета и его разметки.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

- Контракт гаджета получает отдельный минимальный размер (пол ресайза) поверх стартового размера; по умолчанию минимум равен старту, часы объявляют минимум 2x1 при старте 4x2.
- Механизм ресайза (S1093) берёт пол из минимального размера гаджета, а не из стартового.
- Гаджет часов: долгий тап - переход в календарь (безопасный резолв), формат времени с секундами, крупнее по умолчанию.

### 5.2 Потоки данных и событий

- Долгий тап по часам -> построить intent просмотра календаря на текущий момент -> безопасно резолвить и открыть.
- Стартовый размер часов 4x2 (пикер + засев); ресайз ограничен полом 2x1 (минимум гаджета) и потолком «полный экран» (S1093).

### 5.3 Точки расширяемости

- Минимальный размер как отдельное свойство гаджета позволяет будущим гаджетам объявлять свой пол независимо от старта.
- Переход в календарь - единая безопасная точка, переживёт добавление погоды (S0426) в тот же гаджет.

## 9. Архитектурные решения (ADR)

ADR: отдельное свойство минимального размера гаджета (пол ресайза) поверх стартового размера. Обоснование - позволяет «крупный старт, малый пол» без специального кода в ядре ресайза и не меняет остальные гаджеты (их минимум по умолчанию равен старту).

## 11. Критерии готовности (strategic-level)

1. Короткий тап по часам открывает будильники устройства.
2. Долгий тап по часам открывает приложение календаря устройства (или молча ничего не делает, если календаря нет).
3. Часы показывают секунды.
4. Стартовый размер часов заметно больше прежнего 2x1 (около 4x2), текст крупнее.
5. Ресайзом (S1093) часы ужимаются не ниже 2x1 и растут вплоть до полного экрана.
6. Уже размещённые часы не переписываются новым стартовым размером.
