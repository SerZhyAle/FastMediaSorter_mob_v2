# S0964 - VR-кинотеатр, Столп 3: тактический план

## Объём итерации

Immersive-HUD пользовательского пути (`FILE_URI`) становится видимой панелью и получает выбор дорожек:

- Панель `HudCanvasRenderer` рендерится в HUD-квад (сегодня она - невидимая интеракционная модель, визуал занят filename-баннером; см. research 01).
- Два новых ряда управления: аудиодорожка и субтитровая дорожка - циклический выбор `◀ label ▶` поверх `VideoTrackSelectionManager` (ADR-3, без дублирования).
- Навигация (PREV/PLAY/NEXT), громкость и stereo-depth сохраняются; громкость и play-состояние инициализируются из фактического состояния плеера (snapshot).
- Диагностический путь (`DIAGNOSTIC_PLAYLIST`) не меняется: баннер как был (non-goal эпика).

Отложено / вне объёма:

- Рендер субтитровых cue в immersive (выбор дорожки применяется к плееру, текст пока не отображается) - отдельный follow-up тикет.
- Яркость/оттенок/скорость в HUD - позже (non-goal стратегии).
- Immersive-браузер - S0963.

## Последовательность с S0961 (закрывает §6.1 стратегии)

S0961 (серый квад = экспозиция 1x1 плейсхолдера) исправлен 2026-07-11: квад скрыт до первого content-аплоада (`hudContentUploaded`). Столп 3 строится поверх: первый `queueHud` панели открывает квад. Оба тикета проверяются одним on-device прогоном Quest 3.

## Переиспользуемая база (research 01)

- `VideoTrackSelectionManager` (src/main) - конструируется лямбдами, Hilt не нужен; get/select для аудио и субтитров, `trackIndex=-1` = субтитры OFF.
- `HudCanvasRenderer` + `HudInteractionDispatcher` + `HudPlaybackController` (src/vr helpers) - модель панели, UV-диспетчер, main-thread маршалинг к плееру.
- `runtime.queueHud(bytes, w, h)` - принимает произвольные WxH; нативный лоу-латенси курсор уже есть (Canvas-курсор не нужен).
- Нового API требует только размер квада: нативный сеттер (баннер 0.3x0.113 остаётся дефолтом).

## Фазы

- PHASE_01 - native: runtime-сеттер размера HUD-квада.
- PHASE_02 - Kotlin-модель: ряды дорожек в панели, track-контроллер, диспетчер, строки EN/RU/UK.
- PHASE_03 - wiring в DiagnosticXrActivity: панельный пайплайн на FILE_URI, probes, build-гейт.

## Критерии готовности (тактический уровень)

1. На `noLegal` при реальном запуске видео в immersive (из плеера или Browse) виден HUD-панель: имя файла, PREV/PLAY/NEXT, громкость, stereo-depth, ряды AUDIO и SUBS.
2. Клик по стрелкам ряда AUDIO циклически переключает аудиодорожки через `VideoTrackSelectionManager`; label показывает текущую дорожку.
3. Ряд SUBS циклится по OFF + доступным дорожкам; OFF отключает TEXT-тип у плеера.
4. Файл без альтернативных дорожек: ряд показывает единственную дорожку/OFF без краха; стрелки бездействуют или ряд затемнён.
5. Громкость и play/pause в HUD отражают фактическое состояние плеера при входе (snapshot).
6. Диагностический путь (кнопка в настройках) показывает прежний filename-баннер - без изменений.
7. `queueHud` не вызывается покадрово - только на изменения состояния.
8. Компиляция зелёная на `noLegal` (nd - Kotlin + CMake); detekt-гейт по затронутым файлам чистый.
