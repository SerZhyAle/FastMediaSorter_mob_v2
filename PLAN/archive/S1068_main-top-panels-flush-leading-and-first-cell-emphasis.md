# Стратегическая спецификация: S1068 - Первый элемент верхних панелей вровень слева и акцент первой ячейки (+25%)

**Ticket:** S1068
**Status:** Archived
**Priority:** 50
**Date:** 2026-07-15
**Tier:** 3 - Moderate (ad-hoc)
**Roadmap entry:** Ad-hoc - запрос владельца 2026-07-15 (по итогам device-теста S1049)

---

## 1. Проблема

По итогам ручного теста S1049 (Verified 2026-07-15) владелец на реальном экране в портретном режиме зафиксировал: первый рабочий элемент командной панели (кнопка "выход/закрыть") и первый ресурсный таб ("Все") визуально стоят не на первой позиции, а сдвинуты вправо на ширину ведущего якоря (leading anchor, 56dp), тогда как ведущие контролы панели программ (три точки) и панели стримов (cast) стоят вплотную к левому краю. То есть у двух из четырёх верхних полос впереди пустая зона, из-за чего первый элемент выглядит стоящим "со второй позиции".

Дополнительно: ширина всех кнопочных ячеек в портрете сейчас единая (48dp, эталон панели программ из S1049), но владелец хочет выделить первую ячейку каждой полосы - она должна быть немного шире остальных, чтобы ведущий элемент читался как акцент.

## 2. Цели

1. В портретном режиме первый элемент каждой из четырёх верхних полос (командная панель, панель программ, панель стримов, полоса ресурсных табов) стоит вплотную к левому краю (x=0) - без ведущей пустой зоны; все четыре первых элемента выровнены по одному X.
2. Первая ячейка каждой полосы шире остальных на 25% ширины базового модуля (+0.25 модуля = +12dp при модуле 48dp): иконочная ячейка 48 -> 60dp; ресурсный таб "Все" 96 (200%) -> 108dp (225%).
3. Остальные (не-первые) иконочные кнопки в портрете сохраняют единую ширину базового модуля (48dp); границы ячеек всех полос остаются на общей сетке.
4. Кнопки командной панели, не поместившиеся по ширине, уходят в дропдаун (сбор в выпадающее меню), а не молча скрываются; дропдаун может иметь иную ширину, но остальные кнопки остаются ровными.

**Non-goals:**

- Ландшафтная и широкая раскладка (`layout-land/`, `layout-w600dp/`, режим с подписями) - решение владельца 2026-07-15: правится только портрет. Land/wide сохраняют ведущий якорь S1037/S1049 без изменений.
- Пересмотр состава/порядка/иконографики кнопок - меняется только геометрия ведущей зоны и первой ячейки в портрете.
- Ширина/сетка channel-chip'ов панели стримов (scroll-strip контента) - вне охвата.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Первый элемент каждой полосы - вровень с левым краем, как три точки панели программ и cast панели стримов (x=0).
2. Первая ячейка чуть шире остальных (+25% = +12dp), чтобы ведущий элемент был акцентом; таб "Все" при этом ровно 225% (60+48), а не 250%.
3. Ровная колонка кнопок сверху вниз без "ступенек", как и в S1049.

### 3.2 Жёсткие ограничения

- **Flavor:** те же app_v2 flavor'ы, что у S1037/S1049 (главный экран списка ресурсов).
- **Ориентация:** только портрет; land/wide не меняются по существу.
- **Доступность:** touch target ни одной кнопки не опускается ниже платформенного минимума; цепочка D-pad/TalkBack фокуса (nextFocus*) и обнаруживаемость overflow сохраняются.
- **Данные/локализация:** без миграций, без новых строк - только геометрия.

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** ведущий якорь (56dp) убирается из портретной командной панели и портретной полосы табов; первый элемент встаёт на x=0. Ведущие ячейки панелей программ/стримов (три точки / cast) расширяются с 56 до 60dp, чтобы вторая ячейка каждой полосы совпадала по X с остальными (иначе колонка разъезжается на 4dp).
- **Геометрия:** первая ячейка = обычная + 12dp (0.25 модуля 48dp). Иконка 48->60, таб 96->108 (225%). Остальные иконки 48dp, остальные табы 96dp. Границы сетки: иконки {0,60,108,156,204,..}, табы {0,108,204,300,..} - подмножество, колонка выровнена.
- **Overflow:** не-поместившиеся кнопки командной панели собираются в дропдаун вместо скрытия (S0972 прятал Start Player). На типовом портретном телефоне (393dp) все кнопки влезают - дропдаун актуален только на узких экранах.
- **Validation level:** визуальная проверка на реальном устройстве/эмуляторе в портрете на узком и типовом экране - первый элемент всех четырёх полос на X=0, первая ячейка шире на 12dp, остальные ровные, регрессии touch target нет.
- **Owner sign-off:** 2026-07-15 - принято из запроса владельца в чате (device-тест S1049).
- **Related tickets:** S1037 (`main-top-panels-horizontal-alignment`, Verified) ввёл общий ведущий якорь; S1049 (`main-panels-uniform-button-width`, Verified) добавил единую ширину ячейки поверх якоря. S1068 разворачивает решение о ведущем якоре для командной панели и полосы табов в портрете (у S1049 это был явный non-goal) и вводит акцент первой ячейки.

## 4. Контекст текущей архитектуры

Верхняя зона главного экрана - четыре независимые горизонтальные полосы. По S1037/S1049 первый рабочий элемент каждой полосы стартует с общего X=56dp (leading anchor): в командной панели этот отступ задаёт ведущий `Space` в `layoutControlButtons`, в полосе табов - `paddingStart` на `TabLayout`, а в панелях программ/стримов ту же зону физически занимает ведущий сервисный контрол (три точки / cast) на X=0, чей `minWidth` равен 56dp. Из-за этого у панелей программ/стримов "первый = первый" (контрол на краю), а у командной панели и табов впереди пустая зона.

Ширина ячеек в портрете единая (48dp, эталон панели программ); табы - 2 модуля (96dp) с per-tab `tabMinWidth/tabMaxWidth`. Overflow командной панели (`MainLayoutChromeManager.applyControlBarOverflow`, S0972) при нехватке места скрывает Start Player. Дропдаун `btnMainDropdownMenu` (app-actions) показывается только когда панель программ выключена, поэтому как overflow-коллектор в типовом кейсе (панель программ включена) он недоступен.

## 5. Предлагаемый подход

Убрать ведущую пустую зону в портрете (командная панель + табы), поставив первый элемент на X=0; ведущие ячейки всех четырёх полос сделать шире базового модуля на 12dp (акцент первой ячейки), сохранив единый модуль остальных ячеек и общую сетку границ. Портретность обеспечивается редактированием портретного `layout/activity_main.xml` (отдельный от land/wide файл) и код-гейтом по существующему bool `main_*_panel_show_labels` (false в портрете) в менеджерах панелей.

### 5.1 Основные столпы / модули

- Портретный `layout/activity_main.xml`: удалить ведущий `Space` командной панели; `btnExit` = 60dp, прочие командные кнопки = 48dp (фиксированная ширина, файл только портретный); удалить `paddingStart` у `TabLayout`.
- `MainResourceTabsManager`: в портрете (fixed-grid bucket) первый таб = 108dp, остальные = 96dp; полоса без ведущего отступа.
- `MainProgramsPanelManager` / `MainStreamsPanelManager`: ведущая ячейка (три точки / cast) = 60dp в портрете (код-гейт по show-labels), иначе прежняя ширина.
- Overflow командной панели: собирать не-поместившиеся кнопки в дропдаун вместо скрытия (доработка при наличии чистого решения; на типовом портрете не триггерится).

### 5.2 Точки расширяемости

- Новый dimen `main_panel_first_item_width` (60dp) переиспользуем для будущих ведущих ячеек портретных полос.

## 6. Открытые вопросы

Нет - геометрия и охват зафиксированы в §3.3.

## 7. Риски

- Material `TabLayout` может игнорировать per-tab ширину при внутреннем измерении - митигация: проверка на устройстве, при необходимости кастомная ширина TabView вместо tabMin/MaxWidth.
- Overflow-в-дропдаун затрагивает focus chain и app-actions меню - митигация: делать поверх существующего паттерна панели программ, проверять цепочку фокуса; на типовом портрете overflow не наступает.
- Расхождение портрета и land/wide по ведущей зоне - осознанный компромисс (решение владельца), land/wide сохраняют якорь.

## 8. Влияние на пользователя (docs/FEATURES)

Без изменений - визуальная полировка выравнивания уже существующих элементов, не новая способность.

## 9. Критерии готовности (strategic-level)

1. В портрете на реальном устройстве первый элемент всех четырёх верхних полос стоит на X=0, выровнен по одному X.
2. Первая ячейка каждой полосы шире остальных на 12dp: иконка 60dp, таб "Все" 108dp (225%); остальные иконки 48dp, табы 96dp; границы ячеек на общей сетке.
3. Не-первые иконочные кнопки в портрете ровные (равная ширина).
4. Не-поместившиеся кнопки командной панели уходят в дропдаун (или, при отсутствии чистого решения на этот заход, поведение overflow не хуже S0972).
5. Land/wide не изменились по существу; touch target не уменьшился; цепочка фокуса и overflow-обнаруживаемость сохранены.

### Отложено (goal 4, soft)

Сбор не-поместившихся кнопок командной панели в дропдаун (вместо скрытия Start Player по S0972) не реализован в этом заходе: на типовом портретном телефоне (~393dp) все кнопки влезают, кейс актуален только на узких экранах, у владельца формулировка «возможна дропдаун». Ядро goal 4 (равная ширина не-первых кнопок) доставлено. При необходимости - отдельный follow-up.
