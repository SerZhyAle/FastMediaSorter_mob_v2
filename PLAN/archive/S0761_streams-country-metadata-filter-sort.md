/spec-draft добавить новый параметр для трансляций - страна. Определяется по адрресу например еслоли домен .UA - Украина. Виден в списке трансялций в одной строке перед языком. использется в фильтре и сортировке

**Контекст:** пользователь хочет добавить для трансляций новое поле "страна", автоматически определяемое по адресу канала, как минимум по доменной зоне. Новая метадата должна отображаться в списке трансляций перед языком и стать доступной в механизмах фильтрации и сортировки.

**Вложения:**

Вложений нет.

## 1. Проблема

Сейчас у трансляций не хватает явной метадаты страны, хотя для пользователя она может быть не менее полезной, чем язык. При просмотре списка каналов это затрудняет быстрый визуальный отбор и делает фильтрацию менее выразительной, особенно если пользователь ориентируется на географический признак.

Часть информации о стране можно попытаться вывести из самого адреса канала, например по доменной зоне. Пользовательский запрос как раз направлен на то, чтобы превратить такой признак в отдельный параметр, который виден в списке и участвует в отборе и упорядочивании.

---

## 2. Цели

1. Добавить для трансляций новый параметр "страна".
2. В v1 определять страну автоматически из каталожной колонки `country` (ISO alpha-2), без TLD-эвристик для некаталожных строк.
3. Показывать страну в списке трансляций в той же строке, где уже показывается язык, но перед языком.
4. Сделать страну доступной в фильтре трансляций.
5. Сделать страну доступной в сортировке трансляций.
6. Сохранить поведение понятным и устойчивым для трансляций, где страну нельзя уверенно вывести из адреса.

**Non-goals:**

- Не утверждать в этом draft, что доменная зона всегда даёт точную страну без исключений.
- Не ограничивать будущее поле только одним способом определения, если позже понадобится более умная эвристика или явное ручное значение.
- Не превращать тикет в полную переработку всей модели stream metadata.

---

## 3. Черновые пожелания и ограничения

- Новое поле должно быть полезным в реальном списке трансляций, а не существовать только в карточке или деталях.
- Позиция "страна перед языком" важна для визуального сканирования списка.
- Автоматическое определение должно быть достаточно дешёвым и предсказуемым для большого числа каналов.
- Фильтр и сортировка по стране не должны ломать существующие сценарии, если страна не определилась.
- Нужно учитывать, что домен, CDN или хостинг не всегда равны фактической стране канала, поэтому в v1 не опираться на TLD-эвристики.

### 3.3 Owner inputs (Approval gate)

## 4. Открытые вопросы / Research items

> Ресёрч по текущей модели stream-метаданных выполнен.
> **Артефакт:** [research/01__streams-language-handling-and-mirror-plan.md](S0761_streams-country-metadata-filter-sort/research/01__streams-language-handling-and-mirror-plan.md)

### Ключевая находка

Каталог трансляций уже содержит колонку `country` с ISO 3166-1 alpha-2 кодом (`US`, `DE`, `UA`): значение парсится в `ParsedCatalogEntry.country`, но молча отбрасывается при импорте, потому что в `StreamSourceEntity` нет поля `country`. Для каталожных каналов страна станет доступной сразу после добавления поля - так же, как сейчас работает язык. TLD-вывод из URL для каталога не нужен.

### Резолвится зеркалированием языка (решения зафиксированы)

1. **Правило определения** (бывш. №1). v1 - страна берётся из колонки каталога (ISO-код), без TLD-эвристик. Ручные и импортированные строки остаются без страны, ровно как сейчас без языка.
2. **Неизвестная страна** (бывш. №2). Поведение как у пустого языка: чип скрыт, в сортировке уходит в конец (nulls-last), при активном фильтре строка скрыта. Список, фильтр и сортировка не ломаются.
3. **Сортировка** (бывш. №6). Новый режим `COUNTRY`: алфавитно по коду, case-insensitive, неизвестные в конце. Зеркало `SortMode.LANGUAGE`.
4. **Централизация** (бывш. №7). Поле живёт на `StreamSourceEntity` (как язык); все поверхности читают одно значение. Отдельная точка кеширования не нужна.
5. **Персист выбора.** Выбор страны в фильтре сохраняется в `StreamsSessionStore` (ключ `last_country`), зеркало `last_language`.

### Решения владельца (UI / scope)

1. **Объём v1.** Только каталожная страна. TLD-вывод для некаталожных строк в этот тикет не входит и при необходимости выносится в отдельную future-задачу.
2. **Формат показа страны.** В строке списка и в пикере фильтра использовать `flag+code`, например `🇺🇦 UA`.
3. **Размещение 3-го фасета в фильтре.** Страну дать отдельным рядом во всю ширину под существующей парой `Category + Language`.

После фиксации этих 3 решений тикет готов к `/spec-tech` и реализации по mirror-plan.

### Quiz decisions (2026-06-28)

- Scope for v1 country metadata -> catalog-only; no TLD derivation for manual/imported rows in this ticket.
- Country chip display -> flag+code because flags already exist and the code keeps the chip explicit.
- Filter placement -> full-width second row to keep the existing two-column top row readable.

## 6. Критерии готовности (strategic-level)

1. У трансляции появляется новое поле "страна", пригодное для использования в UI и логике списка.
2. Для каталожных каналов страна автоматически определяется по согласованному правилу из колонки `country`; некаталожные строки в v1 могут оставаться без страны.
3. В списке трансляций страна показывается в одной строке перед языком.
4. Пользователь может использовать страну как критерий фильтрации трансляций.
5. Пользователь может использовать страну как критерий сортировки трансляций.
6. Для каналов без надёжно определяемой страны поведение остаётся понятным и не ломает список, фильтр и сортировку.
