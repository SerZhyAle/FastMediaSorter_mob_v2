## 1. Проблема

Пользователю (и тому, кто помогает ему с проблемой удалённо) негде быстро посмотреть и переслать сводку о своём устройстве и текущем состоянии приложения. Сейчас технические факты разбросаны: версия приложения видна как текст на вкладке настроек, объём памяти собирается только для отчёта об ошибке, остальное нигде не показывается единым списком.

Нужна одна кнопка «System info» на вкладке настроек Common, открывающая уже существующий прокручиваемый текстовый диалог с копированием и «отправить..», заполненный всей легко-доступной технической информацией об устройстве, его текущем состоянии и базовых настройках приложения.

---

## 2. Цели

1. На вкладке настроек Common появляется кнопка «System info», достижимая в том же порядке обхода фокуса, что и соседние кнопки.
2. По нажатию открывается уже существующий прокручиваемый текстовый диалог: текст можно листать, выделять, целиком скопировать в буфер обмена и отправить через системный «поделиться».
3. Диалог заполнен сводкой, собранной без специальных разрешений и без заметной задержки: модель и производитель устройства, имя пользователя, версия Android и уровень API, активный вариант сборки (flavor) и версия приложения, оперативная и дисковая память (всего и доступно), параметры экрана, текущая локаль, текущее время и часовой пояс.
4. Сбор данных не блокирует UI-поток.

**Non-goals:**

- Не создаётся отдельный экран «About» - переиспользуется существующий диалог.
- Не собираются данные, требующие новых разрешений или сетевых запросов.
- Не вводится экспорт в файл или ZIP (для этого уже есть экспорт логов).
- Не добавляется автоматическая отправка телеметрии куда-либо.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Сводка читаема человеком: подписанные строки «ключ: значение», логически сгруппированные (устройство / ОС / приложение / память / экран).
2. Значения, отражающие «текущее состояние» (свободная память, свободное место), берутся на момент открытия диалога.
3. Формат удобен для вставки в баг-репорт или сообщение в поддержку.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки (`standard`, `lite`, `photos`, `legacy`). Фича живёт в общем коде, без flavor-специфичного source set; активный flavor показывается только как читаемое значение - без новых `BuildConfig`-гейтов в `src/main` (Strict Rule §15).
- **API level:** без API-специфики; используемые источники данных доступны на всех поддерживаемых уровнях (`minSdk 23` для `legacy`, `26` для остальных).
- **Wear OS:** не затрагивается.
- **Производительность:** сбор сводки выполняется вне главного потока; вычислимая задержка не должна задерживать открытие настроек.
- **Совместимость данных:** persistent-хранилище и миграции не затрагиваются.
- **Локализация:** EN/RU/UK обязательно для подписей кнопки и заголовка диалога. Тело сводки - технические данные; язык подписей полей внутри тела уточняется в §6.
- **Доступность:** кнопка различима не только цветом, имеет понятную TalkBack-метку и поддерживает клавиатуру / D-pad / мышь наравне с соседними кнопками.
- **Коммуникация:** все пользовательские строки соответствуют `docs/COMMUNICATION_POLICY.md` (чек-лист тона §6 политики - обязательный гейт перед интеграцией строк).

### 3.3 Owner inputs (Approval gate)

Каждое поле ниже содержит конкретное значение, чтобы спека могла перейти Draft → Approved. Проверка: `pwsh -NoProfile -File scripts/spec_catalog/check-owner-inputs.ps1 -Id S0335`.

- **UI placement contract:** кнопка «О системе» размещается на вкладке Common (внутренне «General») в одном горизонтальном ряду с кнопкой «Разрешения и доступ»; ширина по содержимому (не растягивается); включается в существующую цепочку обхода фокуса.
- **Accessibility:** кнопка фокусируема и активируема с клавиатуры/D-pad/мыши; имеет текстовую метку для TalkBack; начальный фокус в открытом диалоге уже обеспечивается переиспользуемым диалогом.
- **Communication policy:** заголовок диалога и метка кнопки проходят чек-лист тона §6 политики; тело - технические данные, дружелюбный rewrite к нему не применяется.
- **Localization:** метка кнопки и заголовок диалога - EN/RU/UK обязательно; набор и язык подписей полей тела - см. §6 (open).
- **Validation level:** целевой вариант сборки компилируется; затронутые юнит-тесты проходят; сбор сводки покрывается юнит-тестом, если вынесен в тестируемую роль (см. §6).

## 4. Контекст текущей архитектуры

За вкладку Common отвечает фрагмент настроек, делегирующий работу набору хелперов; один из них уже собирает короткую device-сводку для баг-репорта и уже вызывает прокручиваемый текстовый диалог для показа логов. Сам диалог (общий UI-компонент) уже поддерживает скролл, копирование в буфер и отправку через системный «поделиться» - то есть весь UI-механизм уже существует и переиспользуется.

Чего сейчас нет: единого места сбора технической сводки. Факты об устройстве разбросаны - часть в хелпере настроек (модель, ОЗУ), часть в утилите определения возможностей устройства (RAM/API для OCR), версия и flavor читаются из конфигурации сборки по месту, состояние диска есть в отдельном use case. Поэтому «показать всё одним списком» сегодня требует ручного склеивания этих источников.

---

## 5. Предлагаемый подход

Ввести одну точку сбора технической сводки, которая объединяет уже существующие источники device-фактов в единую человекочитаемую строку, и добавить на вкладку Common кнопку, открывающую существующий прокручиваемый диалог с этой строкой. Никаких новых UI-механизмов: переиспользуется готовый диалог со скроллом, копированием и отправкой.

### 5.1 Основные столпы / модули

- **Сборщик системной сводки.** Единая роль уровня применения/домена: на вход - факты об устройстве, ОС, приложении, памяти, диске, экране, локали; на выход - сгруппированная человекочитаемая строка. Должна быть тестируемой и переиспользовать существующие источники device-фактов вместо дублирования.
- **Точка входа в настройках.** Кнопка «System info» в блоке диагностики вкладки Common; обработчик собирает сводку вне главного потока и передаёт результат в существующий диалог.
- **Показ.** Существующий прокручиваемый текстовый диалог; новых диалоговых компонентов не вводится.

### 5.2 Потоки данных и событий

Нажатие кнопки → слой применения собирает сводку из источников device-фактов вне главного потока → готовая строка передаётся в существующий диалог → пользователь листает, копирует, отправляет.

### 5.3 Точки расширяемости

- Сборщик сводки строится так, чтобы добавление нового поля было локальным изменением в одной роли, без правок UI.
- Если сбор выносится в отдельную тестируемую роль уровня домена - она встаёт в один ряд с уже существующим use case состояния диска (единый стиль single-purpose ролей).

## 6. Открытые вопросы / Research items

1. **Слой сбора сводки**
   - **Вопрос:** выделять ли отдельную тестируемую роль уровня домена для сбора или собирать в хелпере настроек по существующему облегчённому прецеденту?
   - **Варианты:** dedicated use case (тестируемость, единый стиль с состоянием диска) / сбор в хелпере (меньше кода, как текущая device-сводка).
   - **Нужно выяснить:** нужна ли юнит-тестируемость сборки на первой итерации.
   - **Статус:** Open (решается в `/spec-tech`; на стратегию не влияет).

2. **Финальный набор полей**
   - **Вопрос:** какой именно перечень входит в «всю легко-доступную» информацию.
   - **Варианты:** базовый набор из §2.3 (устройство, ОС/API, flavor+версия, ОЗУ всего/свободно, диск всего/свободно, экран, локаль) против расширенного (часовой пояс, аплайнт-аплайм, набор включённых базовых настроек приложения).
   - **Нужно выяснить:** включать ли «базовые настройки приложения» в тело и какие именно.
   - **Статус:** Open.

3. **Язык подписей полей в теле**
   - **Вопрос:** локализовать ли подписи полей внутри тела сводки или держать их фиксированными английскими (метка кнопки и заголовок локализуются всегда).
   - **Варианты:** фиксированный английский (удобнее для пересылки в поддержку) / локализованные подписи.
   - **Нужно выяснить:** предпочтение владельца по удобству баг-репорта.
   - **Статус:** Open.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Дублирование сбора device-фактов (появится третий сборщик рядом с двумя существующими) | Средняя | Фрагментация логики, расхождение значений | Сборщик переиспользует существующие источники, а не копирует их |
| Сбор на главном потоке (доступ к памяти/диску) | Низкая | Подвисание открытия диалога | Сбор вне главного потока по существующему прецеденту лог-диалога |
| Отсутствие приложения-получателя для «поделиться» | Низкая | Падение при отправке | Защищённый вызов системного выбора получателя |
| Рост и так крупного фрагмента настроек | Средняя | Нарушение лимита размера файла | Логика сбора - вне фрагмента, в отдельной роли/хелпере |

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать существующий прокручиваемый диалог, не создавать экран About**

- **Решение:** показывать сводку в уже существующем диалоге со скроллом/копированием/отправкой.
- **Альтернативы:** отдельный экран/Activity «About»; новый кастомный диалог.
- **Почему:** требуемый UX (скролл, копирование, «отправить..») уже реализован и переиспользуется; новый экран - лишняя поверхность и дублирование.

**ADR-2: Единая точка сбора сводки вместо ad-hoc склейки**

- **Решение:** объединить существующие источники device-фактов в одну роль сбора.
- **Альтернативы:** собирать строку по месту в обработчике кнопки.
- **Почему:** уже есть два разрозненных сборщика; третий ad-hoc усилит фрагментацию. Конкретный слой (use case vs хелпер) - в §6.1 / `/spec-tech`.

## 11. Критерии готовности (strategic-level)

1. На вкладке настроек Common видна кнопка «System info», достижимая обходом фокуса наравне с соседними кнопками.
2. Нажатие открывает прокручиваемый диалог с заполненной технической сводкой.
3. Текст в диалоге можно прокрутить, полностью скопировать в буфер обмена и отправить через системный «поделиться».
4. Сводка содержит как минимум: модель/производитель, имя пользователя, версию Android и API, активный flavor и версию приложения, ОЗУ (всего/свободно), диск (всего/свободно), параметры экрана, локаль, текущее время и часовой пояс.
5. Открытие настроек и диалога не сопровождается подвисанием UI.
6. Метка кнопки и заголовок диалога локализованы EN/RU/UK.
