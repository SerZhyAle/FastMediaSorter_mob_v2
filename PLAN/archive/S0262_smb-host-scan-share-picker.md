> **Scope:** STRATEGIC. Сделать результат SMB-сканирования после выбора хоста интерактивным: пользователь должен выбрать найденную шару кликом и продолжить заполнение нового ресурса без ручного переписывания текста.

---

## 1. Проблема

Сейчас в SMB-сценарии существует разрыв между «сканировать хост» и «продолжить создание ресурса». После сканирования пользователь получает список найденных SMB-папок как информационный результат, но не как действие выбора. В итоге найденные шары не переводят форму в следующий шаг, а пользователь вынужден либо вручную переписывать имя, либо вообще не может продолжить заполнение нового ресурса из результата сканирования.

Проблема усугубляется тем, что пустой результат тоже не даёт явного пользовательского завершения сценария: вместо понятного выбора «ничего не найдено → закрыть и вернуться к форме» пользователь видит пассивное сообщение. Для SMB-экрана это создаёт ощущение, что сканирование нашло данные, но приложение не умеет их использовать.

---

## 2. Цели

1. После выбора хоста и завершения SMB-сканирования пользователь получает список найденных ресурсов как интерактивный picker, а не как текстовую справку.
2. Один клик по найденной шаре подставляет её в форму нового SMB-ресурса и позволяет сразу продолжить заполнение остальных полей.
3. Если сканирование ничего не нашло, пользователь получает явный empty-state с кнопкой отмены и понятным возвратом к форме без ложного ощущения ошибки.
4. Ручной ввод имени шары из S0064 остаётся доступным и не ломается.
5. Поведение «сканировать хост» и «сканировать шары» в SMB-потоке становится единообразным по событиям и UX.

**Non-goals:**

- Автоматическое добавление ресурса без подтверждения пользователя.
- Изменение хранения SMB-учётных данных.
- Переработка сценариев SFTP, FTP или cloud.
- Новый отдельный экран для SMB-выбора.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Выбор найденного ресурса должен происходить прямо по клику без дополнительных промежуточных действий.
2. Пустой результат должен иметь явную кнопку отмены, а не только toast/snackbar.
3. Пользователь не должен терять уже введённые host / login / password / media-type настройки формы.

### 3.2 Жёсткие ограничения

- **Flavor:** все сборки `app_v2`, где доступен SMB.
- **API level:** без API-специфичного поведения.
- **Wear OS:** не затрагивается.
- **Производительность:** список найденных шар должен показываться сразу по завершении существующего SMB listShares-вызова, без дополнительного сетевого раунда.
- **Совместимость данных:** существующие SMB-ресурсы и история ручных имён шар не меняются по формату.
- **Локализация:** EN/RU/UK обязательны для новых или изменённых пользовательских строк.
- **Доступность:** picker и empty-state обязаны быть достижимы мышью, клавиатурой, D-pad и TalkBack.
- **UI policy:** любые новые пользовательские формулировки должны пройти `docs/COMMUNICATION_POLICY.md` §6.

## 4. Контекст текущей архитектуры

Экран Add Resource уже умеет работать с SMB по нескольким соседним сценариям: выбор хоста через network discovery, отдельное сканирование шар на сервере, ручной ввод имени шары и последующее добавление ресурса. В коде уже существует picker-путь для выбора имени шары, введённый S0064, но параллельно остаётся другой путь, где результат сканирования превращается в список `resourcesToAdd` и визуально выглядит как текстовый список без явного шага «выбрать и продолжить».

Иными словами, архитектурная проблема не в отсутствии SMB-данных, а в раздвоении SMB result flows. Один поток трактует найденные шары как форму выбора, другой — как полуготовые ресурсы для списка добавления. Именно это расхождение и нужно закрыть.

---

## 5. Предлагаемый подход

Нормализовать результат SMB-сканирования вокруг одного UX-контракта: сканирование хоста или шар должно завершаться одним и тем же интерактивным выбором ресурса. Найденная шара остаётся промежуточным выбором для заполнения формы, а не сразу попадает в список итоговых ресурсов к добавлению.

### 5.1 Основные столпы / модули

- **Единый SMB scan result contract.** Результат сканирования должен передаваться как список selectable share items для UI-слоя, а не как текстовое сообщение или полуготовые `resourcesToAdd`.
- **Интерактивный picker найденных шар.** Уже существующий SMB share picker переиспользуется как основная поверхность выбора после host scan.
- **Пустой результат как явный UX-сценарий.** Если шары не найдены, UI показывает empty-state диалог с кнопкой отмены и возвратом к форме без сайд-эффектов.
- **Продолжение заполнения формы.** После выбора шары форма SMB остаётся на месте, подставляет выбранное имя и сохраняет уже введённые параметры подключения и профиля.

### 5.2 Потоки данных и событий

Пользователь выбирает хост → запускается SMB share scan → UI получает список найденных шар → показывает picker → пользователь кликом выбирает одну шару → имя шары подставляется в SMB-форму → пользователь продолжает редактирование и вручную завершает создание ресурса.

Если список пустой → UI показывает empty-state с кнопкой отмены → по отмене диалог закрывается и форма остаётся в ранее введённом состоянии. Ручной ввод имени шары остаётся доступным отдельным действием из текущего SMB UI.

### 5.3 Точки расширяемости

- Один и тот же picker должен обслуживать и host scan, и прямой share scan.
- В дальнейшем picker можно расширить до single-choice списка с дополнительными маркерами доступа, не меняя форму сохранения ресурса.
- Empty-state должен остаться отдельным состоянием диалога, чтобы позже можно было добавить CTA «ввести вручную» без новой архитектурной ветки.

## 6. Открытые вопросы / Research items

1. **Какой именно SMB scan path выдаёт текстовый список в пользовательском сценарии**
   - **Ответ:** публичный поток `Scan host` идёт через `NetworkDiscoveryDialog` → `AddResourceActivity.onHostSelected` → `AddResourceViewModel.scanShares` → `AddResourceNetworkScanCoordinator` и теперь сразу завершает host selection вызовом share scan.
   - **Наблюдение:** picker-based contract уже жил в `AddResourceNetworkScanCoordinator`; параллельный bulk-flow в `AddResourceSmbCoordinator.scanSmbShares` остаётся legacy-путём для `resourcesToAdd` и не используется кнопками текущего SMB UI.
   - **Статус:** Resolved

2. **Нужен ли empty-state CTA для ручного ввода прямо в диалоге**
   - **Ответ:** для S0262 выбран cancel-only empty-state. Ручной ввод остаётся на базовой SMB-форме и в share picker через `+ Enter share name manually..`; отдельный CTA внутри empty-state не добавляется.
   - **Почему:** это сохраняет один путь ручного ввода без дублирования действий и соответствует цели «явный выход из сценария» из §2.3.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать существующий SMB share picker, а не вводить новый экран**

- **Решение:** все host-scan результаты приводятся к уже существующему механизму выбора шары.
- **Альтернативы:** отдельный bottom sheet, отдельный recycler-блок на форме, авто-перенос в `resourcesToAdd`.
- **Почему:** это минимизирует новый UI-surface и закрывает реальную проблему выбора, а не создаёт вторую параллельную механику.

**ADR-2: Результат host scan остаётся промежуточным выбором формы, а не готовым ресурсом**

- **Решение:** найденная шара только заполняет SMB form field; реальное создание ресурса остаётся отдельным пользовательским действием.
- **Альтернативы:** автоматически создавать временный ресурс или добавлять его в список `resourcesToAdd`.
- **Почему:** запрос пользователя про продолжение заполнения нового ресурса, а не про silent auto-add.

## 11. Критерии готовности (strategic-level)

1. После host scan найденные SMB-шары показываются как список selectable items, а не как пассивный текст.
2. Нажатие на найденную шару подставляет её в SMB share field текущей формы.
3. После выбора пользователь остаётся в сценарии создания ресурса и может продолжить заполнение без повторного ввода host / credentials.
4. При пустом результате пользователь видит отдельный empty-state с кнопкой отмены.
5. Manual share entry из S0064 продолжает работать.
6. Новый или обновлённый picker достижим с touch, keyboard, D-pad и mouse.
