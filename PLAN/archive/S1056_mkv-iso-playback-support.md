## 1. Проблема

Проигрыватель уже распознаёт `.mkv` как видео, а media3 демуксит контейнер Matroska нативно (локально и по сети идентично). Но есть три разрыва:

1. **Сетевой видеопуть обходит тюнингованную фабрику рендереров.** Хелперы SMB/FTP/SFTP/Cloud строят `ExoPlayer.Builder(context)` без `setRenderersFactory`, поэтому уже вшитый FFmpeg-декодер (DTS/APE/WMA/WavPack/TTA/DSD) и `setEnableDecoderFallback` к сетевому видео не применяются. Итог: тот же MKV с DTS-дорожкой локально играет со звуком, а по сети теряет звук (warning-тост) - прямое нарушение требования «на удалённых ресурсах».
2. **Нет программного видео-декодера.** Видео-кодек без аппаратного декодера на конкретном устройстве падает без SW-фолбэка - локально и по сети (media3 FFmpeg = audio-only; SW-видео нет).
3. **ISO не открывается в плеере.** `.iso` уходит в файловое меню бинарников с несуществующим MIME - воспроизвести содержимое диск-образа нельзя.

Эффект на пользователя: удалённые MKV с нестандартным аудио беззвучны; экзотические видео-кодеки (HEVC на старом железе, VC-1, MPEG-2, AV1/VP9 без HW) не играют; ISO нельзя воспроизвести.

Область: `ui/player/helpers` (сетевые хелперы, фабрика рендереров), слой доставки нативных библиотек (`data/delivery`), классификация форматов (`domain/model`, `util`), пофлаворная изоляция (`src/standard`, `src/noLegal`).

## 2. Цели

1. Удалённое видео (SMB/FTP/SFTP/Cloud) получает тот же набор декодеров, что и локальное: вшитый FFmpeg-audio + `setEnableDecoderFallback` + `EXTENSION_RENDERER_MODE_PREFER`. Наблюдаемо: MKV с DTS-дорожкой по сети играет со звуком.
2. Принято обоснованное решение по программному видео-декодированию: какие кодеки закрываются Play-безопасно в `standard` (AV1/VP9), какие - только в `noLegal`.
3. Принято обоснованное решение по ISO: что реально в `standard`, что только в `noLegal`, что не делаем.

**Non-goals:**

- Анимированный WEBP - отдельный тикет S1026.
- Расшифровка Blu-ray (AACS/BD+) и коммерческих DVD (CSS) в `standard`.
- Полноценная DVD-навигация (меню/титры/углы) в первой итерации.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Воспроизведение MKV с любым кодеком - хотя бы в `noLegal`, если Play-ограничения не дают этого в `standard`.
2. Воспроизведение видеодорожки из ISO диск-образа - хотя бы в `noLegal`.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard` = Google Play (патенто/DRM-чувствительное запрещено); `noLegal` = sideload-канал для GPL/патентных расширений. Никаких `BuildConfig.IS_*` гейтов в `src/main` (Rule 14) - только интерфейс + пофлаворные source sets.
- **Play запрещает докачку исполняемых `.so`** (S0971): любой новый нативный декодер в `standard` обязан быть **вшит в APK**; докачка на лету допустима только в `noLegal`.
- **Нативная сборка:** новый `.so` собирается NDK r25c с 16KB page alignment (`-Wl,-z,max-page-size=16384`) для targetSdk 35 / Android 15+. Пайплайн: `scripts/builders/build-ffmpeg-dts.sh` (WSL). Артефакт - внешняя зависимость (в этом проходе не собирается).
- **API level:** без API-специфики (media3 1.2.1, minSdk 26/23-legacy).
- **Wear OS:** не затрагивается.
- **Локализация:** EN/RU/UK - обязательно для любых новых строк.
- **Совместимость данных:** без изменений схемы Room.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S1026 (animated WEBP - только ссылка), S1057 (мёртвый флаг ENABLE_DTS_DECODER - parked), S1058 (фиктивный MIME open-with - parked).
- **Flavor scope (sensitive):** затрагивает `standard` и `noLegal`; Tier B добавляет новую GPL/LGPL нативную зависимость только в `noLegal`.
- **Data/legal scope (sensitive):** libVLC (LGPL) + опционально libdvdcss (DMCA-спорно) - решение владельца о принятии в `noLegal`.
- **API/size scope (sensitive):** нативные декодеры увеличивают размер APK; для `standard` - вшивание обязательно (Play). Решение владельца о бюджете размера.

## 4. Контекст текущей архитектуры

Детально - `research/02__codebase-architecture.md`. Ключевое:

- Тюнингованная фабрика рендереров `createPlaybackRenderersFactory()` (`ui/player/helpers/PlaybackRenderersFactory.kt`) даёт `EXTENSION_RENDERER_MODE_PREFER` + decoder fallback + прикрепление вшитого FFmpeg-DTS. Её используют **только** локальный путь (`PlayerSetupHelper.createPlayer`) и фоновый аудио-сервис.
- Сетевые хелперы (`Smb/Ftp/Sftp/CloudPlaybackHelper`) строят `ExoPlayer.Builder(context)` напрямую - без фабрики рендереров. Отсюда разрыв паритета.
- Демукс контейнеров - штатная `DefaultExtractorsFactory` media3 (включает `MatroskaExtractor`), не переопределяется; MKV работает локально и по сети одинаково на уровне контейнера.
- Все удалённые DataSource seekable (SMB/FTP/SFTP/Cloud/HTTP) - random access есть end-to-end.
- Слой доставки нативных библиотек: `DeliverableSet` + `DeliverableDescriptorCatalog` + `DeliveredNativeLibraryLoader`. Из-за S0971 нативные наборы для Play **вшиты**, не докачиваются.
- ISO: `BinaryFileTypeDetector.DISK_IMAGES` -> `MediaType.BINARY_DISK`; отфильтровывается в плеере (`PlayerMediaFilesLoader` `isPlayerSupportedType = !type.isBinaryFile()`); ISO9660/UDF-парсинга в проекте нет (ZIP через zip4j - не читает ISO).
- Пофлаворная изоляция noLegal-only возможностей: шаблоны `OcrEngineContributor` (multibinding) и `OfficeDocumentViewerHost` (интерфейс + NoOp-в-main + пофлаворная фабрика).

## 5. Предлагаемый подход

Трёхуровневый, от Play-безопасного и немедленного к owner-gated:

### 5.1 Основные столпы / модули

- **Tier 1 (P01) - паритет удалённого декодирования.** Провести сетевые хелперы через тюнингованную фабрику рендереров, чтобы вшитые FFmpeg-audio-декодеры и decoder fallback применялись к удалённому видео так же, как к локальному. Play-безопасно, без нативной сборки, тестируемо. Подчиняет спек-драфт-находку #1 из ресёрча.
- **Tier A (P02) - Play-безопасное расширение SW-видео (`standard`).** Собрать и **вшить** `libgav1` (AV1) + `libvpx` (VP9) через существующий AAR-пайплайн, расширяя покрытие MKV на устройствах без HW AV1/VP9. Не покрывает HEVC/VC-1/MPEG-2 SW (патенты). Гейт: внешняя WSL-сборка + owner-решение о размере APK.
- **Tier B (P03) - noLegal-движок для любого кодека + ISO.** Интегрировать libVLC как альтернативный движок только в `noLegal` (шаблон Contributor): любой кодек MKV (SW HEVC/H.264/VC-1/MPEG-2 + аудио) и воспроизведение DVD/BD ISO (libdvdnav/libbluray, опц. libdvdcss). Гейт: owner-решение (размер/лицензия/сопровождение) + внешняя сборка.

### 5.2 Потоки данных и событий

- P01: сетевой хелпер -> `ExoPlayer.Builder` **с** фабрикой рендереров -> тот же путь декодирования, что локально. Данные без изменений (seekable DataSource как есть).
- P02: новый `DeliverableSet` (вшитый в `standard`) -> `DeliveredNativeLibraryLoader` -> SW-рендереры в фабрике -> media3 выбирает extension-рендерер для AV1/VP9.
- P03: `noLegal` биндит альтернативный движок через multibinding; маршрутизатор форматов направляет ISO (и опционально «любой-кодек» видео) на движок вместо ExoPlayer; сетевой ввод мостируется в media-callbacks движка.

### 5.3 Точки расширяемости

- Фабрика рендереров - единая точка для добавления любых будущих SW-декодеров (после фикса сетевого паритета применяется ко всем путям).
- `DeliverableSet` - расширяемый реестр нативных наборов.
- Маршрутизация форматов (`MediaType` -> плеер) - точка подключения новых псевдотипов (диск-образ) и альтернативного движка.

## 9. Архитектурные решения (ADR)

- **ADR-1:** сетевой паритет декодеров реализуется переиспользованием `createPlaybackRenderersFactory` в сетевых хелперах, а не дублированием конфигурации - единая точка правды для декодеров.
- **ADR-2:** SW-видео для `standard` только вшиванием (Play запрещает докачку `.so`); докачка резервируется за `noLegal`.
- **ADR-3:** любой-кодек и ISO-воспроизведение - через альтернативный движок, изолированный в `noLegal` шаблоном Contributor; ExoPlayer остаётся движком по умолчанию для всех флаворов.

## 11. Критерии готовности (strategic-level)

1. Удалённое видео проходит через тюнингованную фабрику рендереров; сетевой MKV с FFmpeg-декодируемой аудиодорожкой играет со звуком (девайс-тест SMB/Cloud).
2. Решение по Tier A (SW-видео `standard`) зафиксировано: либо реализовано (собран+вшит `.so`), либо явно отложено owner-решением с записанной причиной.
3. Решение по Tier B/ISO (`noLegal`) зафиксировано: объём и флавор определены; при принятии - выделен дочерний тикет с тактическим планом.
4. Спек-драфт-находки #2/#3 запаркованы (S1057/S1058).
