## Steps

### Step 04.1 - Sync the class catalog and declare flavor scope

**Files:** `dev/CATALOG/app_v2.jsonl`
**Depends on:** - start of phase

**Prompt for developer:**

> Run `pwsh -NoProfile -File scripts/catalog_sync.ps1 -Module app_v2` once. Then set role and status for the
> two new classes with `dev/CATALOG/scripts/set.ps1`, and declare their flavor scope with
> `-NoFlavors "lite,photos,legacy,vr"` for both `SearchGadget` and `WebSearchLaunchManager`, because the
> `launcherEnabled` source set compiles only in `standard` and `noLegal`.

**Why:**

Strategic §3.2 limits this feature to the two flavors where `SUPPORT_LAUNCHER` is on, and the catalog is the
first lookup every later task makes, so a class whose flavor scope is unrecorded is one a future ticket will
wrongly assume is available everywhere.

**Verification:**

- `pwsh -NoProfile -File dev/CATALOG/scripts/query.ps1 -ClassMatches "SearchGadget"` returns one record.
- `pwsh -NoProfile -File dev/CATALOG/scripts/query.ps1 -ClassMatches "WebSearchLaunchManager"` returns one record.
- Both records carry a non-empty `role` and the `noFlavors` list above.

**Status:** `[x]` done
