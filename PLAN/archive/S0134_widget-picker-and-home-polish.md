---

## 1. Проблема

Все пять виджетов FastMediaSorter подписаны в системном picker одинаково («FastMediaSorter 1×1») и рисуют дефолтную плейсхолдер-иконку вместо своих preview-изображений — пользователь не может отличить виджеты друг от друга и не понимает, какой выбирать. На рабочем столе виджет Favorites без сохранённых записей выглядит как пустая чёрная плита без объяснения, а единый чёрный фон всех виджетов конфликтует с обоями и темами Material You. Эффект — функционально рабочие виджеты воспринимаются как недоделанная фича.

---

## 2. Цели

1. В системном picker каждый виджет имеет уникальное имя, уникальную иконку-чип и собственный preview без дефолтных плейсхолдеров.
2. Размер виджета в picker отображается корректно — крупный список Favorites показывается как 3×3, остальные четыре — как 1×1.
3. Фон виджетов на Android 12+ адаптируется к цветовой теме лаунчера (Material You); на Android 8..11 показывает читаемый тёмный фон с тонкой границей, не сливающийся с обоями.
4. Виджет Favorites без сохранённых файлов показывает понятный экран «No favorites yet» с подсказкой, как добавить избранное; тап ведёт в приложение в раздел Favorites.

**Non-goals:**

- Реактивные обновления Favorites при изменении БД в реальном времени.
- Показ типа ресурса (SMB/локальный/облако) внутри виджета Resource Launch.
- Виджеты для Wear OS.
- Динамическая генерация preview-изображений в рантайме.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Сохранить уже существующие preview-изображения виджетов как есть — они визуально качественные.
2. Иконки-чипы для picker — монохромные, тинтуемые системой, в едином стиле с остальной иконографикой приложения.
3. Не вводить тяжёлой логики в виджеты — они должны оставаться декларативными.

### 3.2 Жёсткие ограничения

- **Flavor:** все четыре (`standard`, `lite`, `photos`, `legacy`). Виджеты не зависят от BuildConfig-фич, изменения visual-only.
- **API level:** минимальный поддерживаемый — Android 8 (API 26). Material You ветка задействует возможности API 31+, для нижних API — фоллбэк.
- **Wear OS:** не затрагивается — на часах виджетов нет.
- **Производительность:** без дополнительных runtime-затрат (preview — статичные ресурсы; пустое состояние Favorites — ещё один view в существующем layout).
- **Совместимость данных:** изменений схемы БД и формата сохранённых данных нет.
- **Локализация:** новые строки заведомо в EN/RU/UK; пройти проверку `check_strings_localized.ps1`.
- **Доступность:** иконки-чипы и пустое состояние имеют `contentDescription`; touch target пустого состояния ≥ 48dp.
- **Communication policy:** все новые user-visible строки (label виджетов, текст пустого состояния) проходят tone checklist `docs/COMMUNICATION_POLICY.md` §6 перед коммитом.

## 4. Контекст текущей архитектуры

Виджеты живут в выделенном слое `widget/` и регистрируются в манифесте как стандартные `AppWidgetProvider` со ссылкой на XML-метаданные и layout. Текущая реализация полагается на дефолты Android: каждый ресивер не объявляет собственного label/icon, поэтому picker берёт значения из приложения, а опциональный previewLayout перекрывает заранее заготовленные preview-картинки и срывает рендер на thumbnail-размере. Фон виджетов задан одной drawable-формой — нет ветки по версии API, нет интеграции с системными цветами Material You. Виджет Favorites рендерит список через `RemoteViewsService`, но layout не содержит вью пустого состояния, поэтому при нулевой выдаче пользователь видит только заголовок и пустую область.

---

## 5. Предлагаемый подход

Решение разбивается на три независимых столпа: декларативная корректность picker (метаданные провайдеров), визуальная адаптация фона виджетов (двухветочный drawable + системная тема) и пустое состояние Favorites (layout + связь со списком). Все три могут быть реализованы и протестированы по отдельности, но публикуются вместе как единый визуальный апдейт.

### 5.1 Основные столпы / модули

**Pillar A — Корректность Picker.** Каждый widget-провайдер получает в манифесте собственный label и собственную иконку-чип. Из метаданных провайдеров убирается ссылка на «живой» previewLayout — picker возвращается к статичным preview-изображениям, которые уже подготовлены. Заводятся недостающие строки label («Favorites», «Resource Launch») в трёх локалях. Для каждого виджета создаётся монохромный векторный чип 24dp, тематически связанный с назначением виджета.

**Pillar B — Адаптивный фон.** Фон виджетов делится на две версии: на Android 12+ используется системная динамическая палитра (Material You) — фон подстраивается под цветовую тему лаунчера; на Android 8..11 применяется тёмный фон с приподнятой непрозрачностью и тонкой границей, гарантирующий читаемость на любых обоях. Для активации Material You-ветки виджетам декларируется системная тема. Контраст внутренних элементов (карточки Favorites) поднимается под новый фон.

**Pillar C — Пустое состояние Favorites.** В layout виджета Favorites добавляется собственная вью пустого состояния с иконкой-звездой, заголовком и подсказкой; список Favorites привязывается к ней через стандартный механизм empty-view RemoteViews. Когда у пользователя нет избранных файлов, system автоматически показывает пустое состояние; тап открывает приложение в разделе Favorites с включённой подсказкой об использовании.

### 5.2 Потоки данных и событий

- **Picker (Pillar A):** система запрашивает метаданные провайдеров → читает label, icon, preview из манифеста и XML → отображает чипы в picker. Никаких runtime-обращений к коду виджета на этом этапе нет.
- **Размещение виджета (Pillar B):** лаунчер инфлейтит widget layout → background-drawable выбирается ресурс-системой по API лаунчера → на Android 12+ применяется тема, ссылающаяся на системные цвета.
- **Favorites empty-view (Pillar C):** RemoteViewsService отдаёт `count = 0` → система автоматически переключает видимость на empty-view → пустое состояние получает свой PendingIntent на запуск MainActivity с onboarding-флагом.

### 5.3 Точки расширяемости

- Слот для иконки-чипа в манифесте каждого провайдера — добавление нового виджета в будущем требует только нового вектора.
- Двухветочный drawable фона — можно добавить третью ветку (например, для тёмной/светлой темы лаунчера независимо от Material You) без правки кода виджетов.
- Вью пустого состояния в Favorites — заготовка для аналогичных пустых состояний у будущих виджетов со списками.

## 6. Открытые вопросы / Research items

1. **Поведение Material You-темы на сторонних лаунчерах.**
   - **Вопрос:** Какие сторонние лаунчеры (Nova, Niagara, Lawnchair) корректно применяют `android:theme` к виджету на Android 12+, а какие игнорируют?
   - **Варианты:** (а) проверить эмпирически на 3..4 лаунчерах, (б) положиться на фоллбэк-фон.
   - **Нужно выяснить:** деградация на сторонних лаунчерах не должна делать виджет нечитаемым; проверка в рамках pillar B при ручном тестировании.
   - **Статус:** Resolved — план ручного теста: Pixel Launcher + Nova + Niagara во время BlockNeedUserTest.

2. **Текст label «Resource Launch» на русском и украинском.**
   - **Вопрос:** Какой перевод выбрать — буквальный («Запуск ресурса» / «Запуск ресурсу») или функциональный («Папка» / «Тека»)?
   - **Варианты:** буквальный технический термин против короткого пользовательского.
   - **Нужно выяснить:** какой вариант лучше воспринимается в тесном picker-тайле; решается на этапе подготовки строк.
   - **Статус:** Resolved — RU «Папка», UK «Тека».

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Сторонний лаунчер игнорирует `android:theme` для виджета | Средняя | На Android 12+ Material You-фон не применяется; виджет всё равно читаем за счёт фоллбэк-drawable | Двухветочный фон, тёмная ветка остаётся валидной без темы |
| Удаление `previewLayout` ухудшит preview на каком-то лаунчере, который умеет рендерить layout лучше PNG | Низкая | Один из лаунчеров покажет уменьшенный PNG вместо оптимального layout-preview | PNG уже подготовлены вручную и выглядят чисто на любом разрешении |
| Новые иконки-чипы окажутся неразличимыми на тёмной теме лаунчера | Низкая | Picker будет читаем, но иконки сольются | Векторы делаются монохромными с системным тинтом — тинт автоматически инвертируется системой |
| Пустое состояние Favorites покажется и при ошибке загрузки данных, маскируя баг | Низкая | Пользователь не отличит «нет данных» от «данные не загрузились» | Логирование загрузки через Timber; для ошибок остаётся отдельный путь (сейчас уже есть `Timber.e`) |

## 9. Архитектурные решения (ADR)

**ADR-1: Отказаться от `previewLayout` в пользу статичных `previewImage`.**

- **Решение:** Удалить `android:previewLayout` из метаданных всех пяти виджетов; оставить только `android:previewImage`.
- **Альтернативы:** (а) оставить оба — Android 12+ предпочтёт previewLayout; (б) переписать previewLayout под маленькие thumbnail-размеры.
- **Почему:** Готовые PNG уже выглядят качественно и предсказуемо на любом лаунчере; live-рендер layout на маленьком thumbnail регулярно срывается и показывает дефолтный плейсхолдер. Сложность поддержки двух представлений не оправдывает выгоды.

**ADR-2: Двухветочный фон через ресурс-квалификатор API, без runtime-логики.**

- **Решение:** Создать два варианта widget-фона — для базового API и для API 31+ — выбираемых системой по квалификатору. Тема виджета объявляется декларативно, без обращения к коду.
- **Альтернативы:** (а) генерировать фон динамически в `RemoteViews` по версии API; (б) единый фон без Material You.
- **Почему:** Декларативный путь не требует вмешательства в код виджет-провайдеров и автоматически работает на новых версиях Android без правки. Material You даёт ощутимый визуальный прирост на современных устройствах при нулевой стоимости для старых.

**ADR-3: Empty-view как отдельная вью внутри существующего layout, активируемая стандартным механизмом RemoteViews.**

- **Решение:** Расширить layout Favorites вью пустого состояния и связать со списком через системный empty-view API.
- **Альтернативы:** (а) подменять весь layout виджета, когда список пуст; (б) показывать заглушку поверх списка из кода провайдера.
- **Почему:** Стандартный механизм RemoteViews сам решает, что показывать, без runtime-логики в провайдере; меньше кода, меньше точек ошибки, нативная поддержка lifecycle виджета.

## 11. Критерии готовности (strategic-level)

1. В системном picker все пять виджетов FastMediaSorter имеют разные подписи и разные иконки-чипы.
2. Размер виджета Favorites в picker отображается как 3×3, остальные — как 1×1.
3. На устройстве Android 12+ фон установленного виджета визуально подстраивается под цветовую тему лаунчера (светлая/тёмная/Material You).
4. На устройстве Android 8..11 фон установленного виджета имеет читаемый тёмный цвет и тонкую границу, не сливаясь с обоями.
5. Виджет Favorites без сохранённых файлов показывает экран с заголовком «No favorites yet» и подсказкой; тап открывает приложение в разделе Favorites.
6. Все новые строки присутствуют в EN/RU/UK; `check_strings_localized.ps1` возвращает exit 0.
