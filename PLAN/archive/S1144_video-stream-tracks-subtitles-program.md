**Текст:**

У видеотрансляций могут быть субтитры, аудиодорожки , наименование текущей программы в метаданных - все это отлавливать, показывать, позволить выбрать в настройках, запоминать для канала трансляции

## 1. Проблема

У видеотрансляций (HLS/DASH/RTSP/progressive) могут присутствовать несколько аудиодорожек, дорожки субтитров и «имя текущей программы» в потоковых метаданных. Приложение уже умеет перечислять и переключать аудио/субтитры для активного потока, но выбор живёт только в текущей сессии плеера и теряется при ретюне канала или перезапуске приложения - «запомнить для канала» не реализовано. Имя текущей программы из ICY-метаданных для видеопотока уже захватывается движком, но не показывается пользователю нигде в видеоплеере (работает только для радио). В результате пользователь каждый раз заново выставляет дорожку и не видит, что сейчас идёт в эфире.

---

## 2. Цели

1. Запоминать выбранную аудиодорожку и дорожку субтитров для конкретного канала трансляции и автоматически применять их при следующем воспроизведении этого канала.
2. ~~Показывать имя текущей программы (из потоковых метаданных) для видеотрансляции~~ - **вынесено в S1158** (quiz 2026-07-24).
3. Дать пользователю управление предпочтениями дорожек для потоков на уровне настроек (детали поверхности - §6, владельческое решение).
4. Не регрессировать существующий сессионный выбор дорожек и авто-деградацию качества потока (S1128).

**Non-goals:**

- Транскодирование или программная генерация субтитров (только те дорожки, что реально присутствуют в потоке).
- Полноценный EPG/телегид с расписанием - только «имя текущей программы», приходящее в метаданных.
- Изменение локального (файлового) пути воспроизведения - фича ограничена потоками.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Единый, узнаваемый способ показать имя программы - желательно переиспользовать визуальный паттерн radio inline-контрола («Title - Track»).
2. Плавная деградация: если у канала (например RTSP) нет субтитров/несколько аудио - секция просто пустая, без ошибок.

### 3.2 Жёсткие ограничения

- **Flavor:** standard, legacy, noLegal, vr (там, где `SUPPORT_STREAMS = true`). lite/photos - вне объёма (потоки скрыты).
- **API level:** без API-специфики - поведение целиком на Media3 1.2.1 (HLS/DASH/RTSP модули), не на платформенных `@RequiresApi`.
- **Wear OS:** не затрагивается (потоковый видеоплеер в `wear` отсутствует).
- **Производительность:** дополнительное чтение предпочтения канала - один индексный lookup по URL в момент старта воспроизведения (путь не горячий, ручной запуск канала).
- **Совместимость данных:** аддитивная миграция Room (номер версии/класс миграции назначаются в тактическом плане; текущая версия 42, свободный слот 42→43). Только новые nullable-колонки, без переписывания существующих.
- **Локализация:** EN/RU/UK - обязательно для всех новых пользовательских строк.
- **Доступность:** новые визуальные элементы (имя программы, метка выбранной дорожки) - с не-цветовым отличием и корректными touch target; поддержка D-pad/TV для любого нового пикера.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S1128 (авто-деградация качества потока - общий `activeStreamTrackSelector`), S1148 (буферизация live-radio), S0581 (`getByUrl` резолвер канала), S1145/S1147 (per-channel операции над `StreamSourceEntity`)
- **UI scope:** имя текущей программы для видеопотока показывается экранным overlay в плеере, зеркалом radio inline-контрола «Title - Track» (Q1, решено 2026-07-23).
- **Data scope:** новые колонки на `stream_sources` для предпочтений дорожек канала - см. §9 ADR-3.
- **Scope decision:** источник метаданных - только ICY (MVP); HLS ID3/EMSG отложен в отдельную итерацию (Q2, решено 2026-07-23).
- **Settings scope:** поверхность настроек - оба: глобальный дефолт языка потоков в секции настроек плюс per-channel-правка в редакторе канала (Q6, решено 2026-07-23).

## 4. Контекст текущей архитектуры

За воспроизведение потоков отвечает слой плеера (`ui/player/`): единый `ExoPlayer` под управлением оркестратора плеера, видеопоток строится в потоковом helper'е с адаптивной загрузкой и `DefaultTrackSelector`. Перечисление и переключение аудио/субтитров уже вынесено в отдельный менеджер трек-селекции и показывается в существующем диалоге управления воспроизведением - тот же код используется для локального видео и для потоков. Глобальный дефолт языка аудио/субтитров задаётся в диалоге настроек плеера и применяется на каждом старте через параметры трек-селекции.

Проблему из §1 нельзя решить «на месте», потому что: (а) отсутствует слой персистентности предпочтения дорожки, привязанный к каналу - сущность канала в БД не имеет соответствующих полей, а сессионный `TrackSelectionOverride` сбрасывается при пересоздании плеера; (б) захваченное имя программы (ICY) для видеопути не имеет UI-потребителя - нужен новый визуальный биндинг; (в) поверхность настроек потоков не содержит строки предпочтений дорожек. Всё это - новые роли поверх существующих, а не правка одной функции.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

1. **Персистентность предпочтений дорожек канала.** Новая роль хранения: для канала запоминаются язык предпочитаемой аудиодорожки и язык дорожки субтитров (плюс флаг «субтитры вкл/выкл» для канала). Хранилище - расширение сущности канала аддитивными полями.
2. **Применение предпочтения при старте.** В момент старта воспроизведения потока слой применения читает предпочтение канала по стабильному ключу (URL) и, если оно есть, накладывает его поверх глобального дефолта через параметры трек-селекции (предпочтение языка, не сырой индекс).
3. **Обратная запись выбора.** Когда пользователь выбирает дорожку в существующем диалоге для потока, выбранный язык записывается обратно в предпочтение канала.
4. ~~**Отображение имени программы.**~~ **Вынесено в S1158** (quiz 2026-07-24) - экранный overlay в видеоплеере, зеркало radio inline «Title - Track».
5. **Поверхность настроек.** Обе поверхности (Q6): глобальный дефолт языка аудио/субтитров для потоков в секции настроек потоков (зеркало `PlayerSettingsDialog` через существующий `bindDropdown`) плюс per-channel-правка предпочтений дорожек в редакторе канала.

### 5.2 Потоки данных и событий

- Старт канала: UI → слой применения плеера → чтение предпочтения канала (кэш/БД по URL) → наложение поверх глобального дефолта → параметры трек-селекции.
- Ручной выбор дорожки: UI диалога → слой применения (сессионное переключение) → запись предпочтения канала (БД по URL).
- Метаданные эфира: движок (`onMetadata`) → «now playing» состояние → новый визуальный индикатор видеопотока.

### 5.3 Точки расширяемости

- Источник метаданных расширяем: MVP - ICY; ID3/EMSG подключается через тот же `onMetadata`-callback добавлением веток разбора `Metadata.Entry` (без слома контракта).
- Модель предпочтения (язык-код) расширяема до ролей/каналов (например «оригинал», «комментарий») без миграции семантики.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Сброс ручного override дорожки при авто-деградации качества (S1128 переиспользует тот же `DefaultTrackSelector`) | Средняя | Пользовательский выбор дорожки затирается step-down'ом | Накладывать предпочтение через `buildUponParameters` текущего селектора, не заменяя весь builder; согласовать порядок с S1128 |
| Live-манифест доукомплектовывает группы дорожек после открытия диалога (одноразовый снимок `hasMultipleAudioTracks`/`hasSubtitles`) | Средняя | Вкладка дорожек ложно отсутствует | Читать доступность реактивно / повторно при изменении `currentTracks`; вынести как отдельный дефект (кандидат `/spec-draft`) |
| Персист индекса дорожки нестабилен на live-edge | Средняя (если выбрать индекс, а не язык) | Восстанавливается «не та» дорожка | ADR-2: хранить язык-код, применять через `setPreferredAudio/TextLanguage` |
| У RTSP-каналов нет субтитров/явного селектора | Низкая | Пустая секция субтитров | Плавная деградация - пустая секция без ошибки |
| Нулевое тестовое покрытие цепочки | Средняя | Регрессии при рефакторинге | Покрыть новую логику предпочтений юнит-тестами (persist/apply/write-back) |

## 9. Архитектурные решения (ADR)

- **ADR-1:** переиспользовать существующий диалог управления воспроизведением (вкладки AUDIO/SUBTITLES) как UI выбора дорожек для потоков - он уже работает для live-потоков; новой отдельной поверхности выбора не создавать.
- **ADR-2:** запоминать **язык-код** аудио и субтитров (не сырой `TrackSelectionOverride` индекс). Причина: индекс группы/трека нестабилен через релоады live-манифеста; язык-код стабилен и совпадает с моделью глобального дефолта (`PlayerSettingsDialog.LanguageOption`), применяется через `setPreferredAudioLanguage`/`setPreferredTextLanguage`.
- **ADR-3:** хранить предпочтения аддитивными nullable-колонками на сущности канала `stream_sources` (миграция уровня 42→43, зеркало `access`/S1117), ключ - стабильный канал (`id`/`url`). Причина: строка канала уже загружается при воспроизведении, отдельная таблица избыточна; согласуется с `getByUrl`-резолвером.
- **ADR-4:** per-channel-предпочтение переопределяет глобальный дефолт только для своего канала; при отсутствии предпочтения применяется глобальный дефолт (семантика существующего `StereoFormatOverrideEntity`).
- **ADR-5 (Q2 решено 2026-07-23 - ICY-only MVP):** источник метаданных «имени программы» - переиспользовать уже захваченный `player.mediaMetadata` (ICY); HLS ID3/EMSG - расширение того же `onMetadata` в отдельной итерации, вне объёма этого тикета.
- **ADR-6 (DI-путь, решено 2026-07-27):** `StreamTrackPreferenceUseCase` доезжает до `VideoPlayerManager` тем же маршрутом, что и `settingsRepository`: поле `@Inject lateinit var` в `PlayerActivity` -> новое свойство в `VideoPlayerStoreDependencies` -> чтение с `activity.<поле>` в `PlayerViewerFactory.createVideoPlayerManager()`. Причина: `VideoPlayerManager` собирается вручную и вне графа Hilt, а этот маршрут уже несёт `settingsRepository`/`playbackPositionRepository`/`statsSink` (прецедент помечен комментарием S0473). Production-конструктор `VideoPlayerManager` ровно один, так что других мест правки нет. Сид `PlayerViewerFactory` в промпте назван неточно - конкретный шов это `VideoPlayerStoreDependencies`.
- **ADR-7 (API селектора, решено 2026-07-27):** предпочтение языка накладывается через `player.trackSelectionParameters.buildUpon()` в `VideoTrackSelectionManager` - тот же API, которым уже работают глобальный дефолт и ручной выбор дорожки. `selector.buildUponParameters()` не использовать: это единственный вызов S1128 (`StreamPlaybackHelper.applyStreamQualityStepDown`). Оба пути правят один и тот же экземпляр `DefaultTrackSelector`, поэтому composition сохраняется, пока каждый писатель делает `buildUpon()`, а не создаёт `Parameters.Builder()` заново. **Предикат проверки шага 02.2 ошибочен:** grep по литералу `buildUponParameters(` попадёт в строку S1128 и даст ложный PASS - проверять надо `player.trackSelectionParameters.buildUpon(` внутри `VideoTrackSelectionManager.kt`.
- **ADR-8 (язык дорожки и URL канала, решено 2026-07-27):** `TrackInfo` расширяется полем `language: String?` - вариант «перечитывать `player.currentTracks` при записи» отклонён. Причина: язык уже читается ровно там, где `TrackInfo` конструируется (`format.language`), но сегодня сворачивается только в текст подписи; сохранить его полем - чистая проводка без нового I/O, тогда как перечитывание дублировало бы обход дорожек и потребовало бы протащить сырой `Tracks` через намеренно host-агностичный `VideoPlayerHandle`. **Важно:** `TrackInfo` существует двумя независимыми одинаковыми data-классами (`VideoTrackSelectionManager.TrackInfo` и `VideoPlayerManager.TrackInfo`) - поле добавляется в оба, иначе контракт мапперов молча разъезжается. Реальных мапперов два: `VideoPlaybackControlsHelper` и `PlayerActivityVideoHandle` (`PhotoVideoStandaloneVideoHandle` пробрасывает без ремапа). URL текущего канала читается из `PlayerHostCapabilities.currentMediaFile.value?.path`, уже доступного диалогу через `host()`.
- **ADR-9 (внедрение в диалог и поверхности настроек, решено 2026-07-27):** `PlaybackControlDialogFragment` не делать `@AndroidEntryPoint` - использовать `EntryPointAccessors.fromApplication(..)` с маленьким `@EntryPoint @InstallIn(SingletonComponent::class)` интерфейсом, как уже сделано в этом же файле для `MediaCapabilitiesEntryPoint` и в `TranslationSettingsDialog`. Отдельного класса редактора канала не существует: правка канала живёт в `StreamsActivity.showEditDialog(source: StreamSourceEntity)`, а её `StreamsViewModel` - обычный `@HiltViewModel`, поэтому там достаточно конструкторного внедрения. Новые глобальные ключи объявляются по образцу `StreamsSettingsStore` (`stringPreferencesKey`, `Values`, `read()`/`write()`, агрегация в `SettingsRepositoryImpl`); ближайшие соседи - `streamsDefaultSort`, `streamsDefaultMediaFilter`, `streamsCatalogRefreshPolicy`.

## 11. Критерии готовности (strategic-level)
