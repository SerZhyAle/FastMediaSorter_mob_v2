# Стратегическая спецификация: S0799 - Аудит терминологии "ресурс" и "папка"

**Ticket:** S0799
**Status:** Archived
**Priority:** 50
**Date:** 2026-06-29
**Tier:** 4 - Strategic (ad-hoc)
**Roadmap entry:** Ad-hoc - запрос 2026-06-29
**Tactical spec:** реализовано напрямую (мелкие строковые/док-правки, тактический план не потребовался)

---

## 1. Проблема

Во многих местах UI и документации "ресурс" (зарегистрированная сущность приложения) назывался "папкой". Ярчайший случай: кнопка "Добавить ресурс" открывала диалог с заголовком "Додати теку" (UK "Добавить папку"). Причина - EN-исходники сами путали понятия, а переводчики буквально переносили "Folder" в "папка/тека". Единого глоссария не было.

## 2. Цели

1. Развести два понятия и применять их последовательно в строках и документации.
2. Исправить подтверждённые mislabeled-строки во всех локалях (EN/RU/UK).
3. Удалить мёртвые ключи-дубликаты старого редактора ресурса.
4. Зафиксировать правило в каноническом документе и в памяти агента.

**Non-goals:**

- Переименование string-ключей (меняются только значения) - нулевой риск для кода.
- Унификация "Source" -> "Resource" по всему UI (отдельный, более широкий вопрос; "источник" оставлен как мягкий синоним в заголовках разделов настроек).
- Переименование плиток мастера "Local Folder"/"Network Folder" (описывают выбираемую директорию-бэкенд, а не сущность).

## 3. Правило терминологии (решение владельца, 2026-07-01)

- **Ресурс** - внутренняя сущность FastMediaSorter: зарегистрированный адрес (локальный / сеть / облако), созданный вручную или импортированный. Может быть получателем, медиатекой, виртуальным (Вся музыка/видео, избранное, потоки). Ресурс **указывает на** одну папку или ветку папок. Применять для: добавить/изменить/копировать/удалить/выбрать/обновить ресурс, его имя/тип/путь/PIN, список ресурсов.
- **Папка (директория)** - директория файловой системы, существующая **независимо** от приложения (локальная Android-папка или папка на удалённом SMB/(S)FTP/облачном сервере). Применять только для: системный/ручной выбор папки, папка, на которую указывает ресурс, сканирование подпапок, создание папки на диске, ID папок облачных провайдеров, навигация по текущей/родительской директории.
- Следствие: путь, на который указывает ресурс, - это корректно "папка" (`hint_folder_path` не менялся).

## 4. Что сделано

Строки (`app_v2/src/main/res/values{,-ru,-uk}/strings.xml`):

1. Переименованы значения живых mislabeled-ключей: `add_resource_title` (тот самый баг "Додати теку"), `copy_resource`, `copy_resource_title`, `select_resource_type`, `add_sftp_ftp_title`, `resource_name` (EN), `resource_pin_code_hint` (+ заодно en-dash "4–6" -> "4-6").
2. Исправлены near-miss (сущность названа папкой): `tooltip_wear_companion_message`, `open_in_fms_external_file_notice`.
3. Удалены мёртвые ключи (0 ссылок в коде и PLAN): `edit_resource`, `edit_resource_with_type`, `resource_path`, `resource_type`, `add_resource`.
4. Локализационный аудит `check_strings_localized.ps1` - parity EN/RU/UK, exit 0.

Документация:

5. Добавлен раздел "Resource vs Folder" (7.1) в `docs/COMMUNICATION_POLICY.md` + `_RU` + `_UK`; исправлен несогласованный пример empty-state.

Память агента: правило сохранено (`feedback_resource_vs_folder_terminology`).

## 5. Критерии готовности

1. Кнопка "Добавить ресурс" не открывает диалог "Добавить папку"/"Додати теку".
2. Строки редактора ресурса говорят "ресурс", строки работы с директориями - "папка".
3. Глоссарий доступен в COMMUNICATION_POLICY (EN/RU/UK).
4. Сборка ресурсов и локализационный аудит проходят.
