## 1. Проблема

При попытке напечатать PDF или другой документ из плеера на ряде устройств (подтверждено: API 27, x86-эмулятор) диалог печати никогда не открывается. Вместо этого пользователь видит лишь краткое сообщение об ошибке (snackbar). Системный API печати выбрасывает `IllegalStateException: Can print only from an activity` — даже несмотря на то что вызов выполняется на UI-потоке с корректной ссылкой на Activity. Ошибка перехватывается, поэтому краша не происходит, однако функция печати полностью неработоспособна.

---

## 2. Цели

1. Диалог выбора принтера открывается при нажатии кнопки «Печать» на всех поддерживаемых API-уровнях (26–35) и на реальных устройствах.
2. На API 27 (эмулятор и устройства) печать работает так же, как на API 33+.
3. Если печать недоступна по объективным причинам (нет принтеров, системная служба отсутствует) — отображается понятное сообщение об ошибке; в противном случае ошибка не показывается.

**Non-goals:**
- Реализация собственного принт-движка или PDF-рендерера.
- Поддержка беспроводной печати без системного PrintManager.
- Исправление поведения на сторонних прошивках с намеренно отключённой службой печати.

## 4. Контекст текущей архитектуры

Логика печати сосредоточена в хелпере UI-слоя плеера. Хелпер держит ссылку на Activity и получает системный сервис PrintManager через AndroidX-обёртку с Activity-контекстом. Вызов `print()` оборачивается в `Activity.runOnUiThread` и дополнительно в try-catch. Несмотря на это, на API 27 x86-эмуляторе `PrintManager.print()` выбрасывает исключение: внутренняя проверка `mContext instanceof Activity` завершается ошибкой. Причина: `ContextCompat.getSystemService` на этой комбинации API/устройства может возвращать экземпляр PrintManager, созданный с контекстом приложения вместо Activity-контекста. Текущий код перехватывает исключение и деградирует до snackbar, но не предпринимает попыток обойти ограничение.

## 5. Предлагаемый подход

### 5.1 Принудительное использование Activity-контекста

Получать PrintManager напрямую через API Activity, минуя AndroidX-обёртку, которая на API 26–27 может возвращать не тот экземпляр. Конкретный вызов: `activity.getSystemService(Context.PRINT_SERVICE) as? PrintManager`. Это гарантирует, что внутренний `mContext` PrintManager — именно Activity.

### 5.2 Валидация жизненного цикла перед диспатчем

Добавить явную проверку `!activity.isFinishing && !activity.isDestroyed` непосредственно перед вызовом `pm.print()` (сейчас проверка есть только на уровне runOnUiThread-лямбды, но не перед получением PrintManager). Если проверка не пройдена — тихо выйти без показа ошибки пользователю.

### 5.3 Потоки данных и событий

```
[Кнопка «Печать» нажата]
    → UI → хелпер плеера: printCurrentFile
    → [Background] подготовить локальный файл (кэш/сеть)
    → [Main thread] проверить Activity.isFinishing / isDestroyed
    → получить PrintManager с Activity-контекстом (прямой системный сервис)
    → проверить PrintManager != null
    → pm.print() → системный диалог выбора принтера
    → [on error] показать snackbar с локализованным сообщением
```

### 5.4 Точки расширяемости

- Логика получения PrintManager должна быть изолирована, чтобы при необходимости можно было добавить поддержку нового API без изменения вызывающего кода.

## 6. Открытые вопросы / Research items

1. **Почему ContextCompat.getSystemService(activity, PrintManager::class.java) не сохраняет Activity-контекст на API 27?**
   - **Вопрос:** AndroidX на API 23+ делегирует в `activity.getSystemService(serviceClass)`, что должно давать Activity-backed экземпляр. Однако факт исключения указывает на иное. Возможно, AOSP API 27 реализует `getSystemService(Class)` с оборачиванием в ContextWrapper, теряющим прямую ссылку на Activity.
   - **Варианты:** (a) прямой cast `activity.getSystemService(Context.PRINT_SERVICE) as PrintManager` — обходит всю AndroidX-обёртку; (b) передать `activity` явно в `PrintManager()` конструктор (недоступно — это системный сервис).
   - **Нужно выяснить:** добавить лог `pm.javaClass.name` и результат `pm.javaClass.getDeclaredField("mContext")` на API 27 перед вызовом `print()`.
   - **Статус:** Resolved — обход реализован через `activity.getSystemService(Context.PRINT_SERVICE)`, минуя AndroidX-обёртку полностью. Точная причина сбоя `ContextCompat` на API 27 irrelevant — прямой вызов исключает проблему.

2. **Покрыто ли исправление типом IMAGE (PrintHelper) аналогично PDF?**
   - **Вопрос:** `PrintHelper` (AndroidX) принимает Activity напрямую в конструктор. Неясно, есть ли аналогичная проблема для печати изображений.
   - **Нужно выяснить:** проверить PrintHelper на том же API 27-эмуляторе.
   - **Статус:** Resolved — `PrintHelper(activity)` принимает Activity явно в конструктор (`DocumentPrintManager.kt:187`); ContextCompat-обёртка не используется, проблема контекста неприменима.

## 9. Архитектурные решения (ADR)

**ADR-1: Прямой вызов системного сервиса вместо AndroidX-обёртки**
- **Решение:** использовать `activity.getSystemService(Context.PRINT_SERVICE)` напрямую.
- **Альтернативы:** патч AndroidX ContextCompat; использование рефлексии для подмены `mContext`.
- **Почему:** прямой вызов гарантированно передаёт Activity-контекст и не зависит от версии AndroidX. Рефлексия нарушает инкапсуляцию и недоступна в API 28+ (sealed fields).
