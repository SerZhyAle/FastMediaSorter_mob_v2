## 1. Проблема

В окне браузера файлов основное окно настроек программы недостижимо напрямую. Чтобы открыть настройки, пользователь вынужден возвращаться в главное окно и вызывать их оттуда. Это лишний шаг при работе внутри браузера.

Область: `ui/browse` - ниспадающее меню «⋮» верхней командной панели.

## 2. Цели

1. В ниспадающем меню «⋮» окна браузера файлов появляется команда «Настройки программы».
2. Команда открывает основное окно настроек приложения.
3. Команда закреплена в самом низу списка меню (самый низкий приоритет), доступна всегда, независимо от типа ресурса.

**Non-goals:**

- Изменение содержимого или структуры самого окна настроек.
- Пере-приоритизация уже существующих команд меню.
- Дип-линк на конкретную вкладку/секцию настроек - открывается корневой экран.

## 4. Контекст текущей архитектуры

Ниспадающее меню «⋮» браузера строится `ResourceOpsMenuManager` из ресурса меню `menu_resource_ops.xml`. Часть пунктов - это overflow-команды верхней панели (`BrowseCommandOverflowManager`), показываемые по push-модели при нехватке ширины; остальные - самостоятельные команды меню, видимые по своим предикатам. Основное окно настроек - `SettingsActivity`, открывается из главного окна простым `Intent`. До сих пор точки входа в настройки из браузера не было.

---

## 5. Предлагаемый подход

Отдельный, всегда видимый пункт меню, закреплённый последним в `menu_resource_ops.xml`. Обработчик в `ResourceOpsMenuManager` запускает `SettingsActivity`. Пункт не участвует в ширинной overflow-аллокации верхней панели - это чистая команда меню, поэтому «самый низкий приоритет» = фиксированная последняя позиция в списке.

### 5.2 Потоки данных и событий

UI (тап по пункту меню) -> `ResourceOpsMenuManager` -> `startActivity(SettingsActivity)`.
