## 1. Проблема

Гейт проверял только общий `src/test`, поэтому тесты в `src/test<Flavor>` могли запускаться в более узком наборе флейворов, чем их субъект, без какого-либо сигнала. Такой тест компилировался и проходил, но не давал покрытия всем доступным флейворам. Нужна была проверка фактического дома теста без ошибочного принятия каждого импортированного вспомогательного типа за субъект.

---

## 2. Цели

1. Проверять все смонтированные `test<Flavor>` source set вместе с общим `src/test`.
2. Отказывать, когда однозначно определённый субъект теста доступен более широкому или иному набору флейворов, чем дом теста.
3. Сохранить быстрый статический характер гейта без Gradle-задачи.
4. Исправить найденные реальные несовпадения тестовых наборов.

**Non-goals:**

- Не превращать гейт в полноценный анализатор зависимостей - хватит импортов.

## 4. Контекст текущей архитектуры

`flavor-source-map.ps1` уже выводит source set и его mount list из `app_v2/build.gradle.kts`. `assert-shared-test-flavor-scope.ps1` использовал эти данные только для общего тестового набора и для зеркальности общих capability test set. Источник истины о фактическом доме каждого теста уже был на диске, но не участвовал в проверке узких test set.

---

## 5. Предлагаемый подход

Для каждого существующего смонтированного `test<Flavor>` гейт сопоставляет имя файла `XxxTest` с единственным production declaration `Xxx` и сравнивает наборы флейворов. Импорты не используются как субъект: они часто являются легальными вспомогательными типами. Ссылка на scoped тип из того же package имеет приоритет над эвристикой имени и предотвращает ложный отказ для теста, чьё имя описывает состояние, а не тестируемую реализацию.

## 6. Открытые вопросы / Research items

1. **Что считать субъектом теста**
   - **Вопрос:** брать самый узкий набор среди импортов теста, или искать одноимённый производственный
     класс по имени файла без суффикса `Test`?
   - **Варианты:** по импортам - работает всегда, но шумит на тестах с широким набором импортов;
     по имени - точно, но не покрывает parity-тесты и тесты без одноимённого класса.
   - **Статус:** Resolved
   - **Решение:** использовать имя файла без суффикса `Test` только при единственном совпадающем production declaration; импорт не является субъектом. Если тест использует scoped declaration из собственного package, имя файла не применяется как эвристика.
   - **Артефакт:** `scripts/quality/assert-shared-test-flavor-scope.ps1`; synthetic case G7.

2. **Что делать с уже существующими нарушениями**
   - **Вопрос:** нужен ли ratchet-базлайн, или их достаточно мало, чтобы починить все сразу?
   - **Нужно выяснить:** сколько тестов в `src/test<Flavor>` ссылаются на тип из более широкого
     capability set.
   - **Статус:** Resolved
   - **Решение:** baseline не нужен. Первый прогон нашёл три кандидата: один оказался легальным cloud test с same-package субъектом, два реальных XR test home исправлены общей монтировкой `testVr` в noLegal.
   - **Артефакт:** свежий `-Gate` прогон 2026-08-14.
