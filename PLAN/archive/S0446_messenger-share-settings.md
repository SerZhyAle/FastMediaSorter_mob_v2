## 1. Проблема

Команда «отправить файл в мессенджер» сейчас существует только для Telegram, и её видимость управляется лишь фактом установки клиента - отдельной настройки нет. Для WhatsApp и Instagram отправки нет вовсе. Пользователь не может скрыть ненужные ему мессенджеры из меню «отправить в..» и не может отправить файл в WhatsApp/Instagram из приложения. Область - настройки профиля «Плеер» и слой шаринга в плеере и просмотре.

---

## 2. Цели

1. Per-profile тумблеры «Разрешить отправку в Telegram..», «..в WhatsApp..», «..в Instagram..» в сворачиваемой группе «Команды отправить файл в..» на странице настроек «Плеер».
2. По умолчанию все три тумблера выключены - и для новых установок, и при миграции существующих.
3. Команда «отправить в <мессенджер>» видна в меню по всему приложению тогда и только тогда, когда её тумблер включён И клиент мессенджера установлен.
4. Отправка файла в WhatsApp и в Instagram (для Telegram отправка уже работает) - вложение передаётся выбранному приложению.
5. Тумблер недоступного мессенджера (клиент не установлен) показан как disabled с не-цветовой подписью «Не установлено».

**Non-goals:**

- Интеграция с бизнес-API мессенджеров (WhatsApp Business API, Instagram Graph API) и любые серверные токены - вне объёма.
- Хранение/использование собственных авторизованных сессий мессенджеров для отправки в обход системного механизма приложений - вне объёма (см. §6, открытый вопрос осуществимости).
- Создание самой страницы настроек «Плеер» (сделано в S0442) и общего каркаса реестра/хранения/резолвера (сделано в S0452).
- Массовая отправка с серверным выбором получателя без участия UI мессенджера - вне объёма; способ выбора получателя - открытый вопрос (§6).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Прямой выбор получателя внутри приложения, если мессенджеры это допускают; иначе - «открыть в приложении с вложением» как достаточный вариант.

### 3.2 Жёсткие ограничения

- **Flavor:** отправка в мессенджеры - стандартная функция полнофункциональных сборок (флаг CLOUD/share-поверхности); специальной flavor-изоляции не требует, так как это не VR/noLegal-специфика и не урезается в lite/photos сверх их базового набора. Код в общем `src/main`.
- **API level:** без API-специфики, кроме обязательного manifest-объявления видимости пакетов мессенджеров на API 30+.
- **Wear OS:** не затрагивается.
- **Производительность:** проверка установленности клиента (PackageManager) не должна блокировать UI меню; подготовка сетевого файла к отправке идёт вне главного потока, как у прочих share-операций.
- **Совместимость данных:** флаги хранятся app-global в настройках (DataStore), не в Room (ADR-1 S0452) - изменения схемы БД нет. «Миграция» = дефолтное значение флага (выключено) для существующих установок.
- **Локализация:** EN/RU/UK - обязательно.
- **Доступность:** недоступный тумблер показан не только серым, но и текстовой подписью «Не установлено» (не-цветовое отличие); команды соблюдают touch target и фокус-навигацию наравне с остальным меню.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S0452 (foundation - инфраструктура команд «Отправить файл в..», блокирует этот тикет)

## 4. Контекст текущей архитектуры

S0452 уже дал каркас: реестр share-таргетов (регистрация через Hilt-мультибиндинг), app-global хранилище on/off флагов в настройках, единый предикат доступности (пакет установлен / Google / интернет) и единый seam гейтинга (предикат «эффективно включён» + предикат «доступен»). Группа настроек строится из реестра автоматически: каждый зарегистрированный таргет сам появляется тумблером, недоступный показывается disabled. Чего нет - ни одного зарегистрированного таргета мессенджера, проводки гейта в меню плеера и просмотра (S0452 намеренно отложил её в таргет-тикеты, чтобы не трогать горячий командный путь спекулятивно) и отправки в WhatsApp/Instagram. Отправка в Telegram реализована отдельно и гейтится лишь установкой клиента, мимо реестра.

---

## 5. Предлагаемый подход

Зарегистрировать три таргета мессенджеров в существующем реестре с дефолтом «всегда выключено» и доступностью «по установленному пакету». Это автоматически даёт три тумблера в группе настроек без правки каркаса. Затем провести единый seam гейтинга в обе поверхности показа команд (меню плеера и overflow просмотра): команда мессенджера видна по правилу «флаг включён И клиент установлен». Telegram переводится с проверки-по-установке на этот же seam. Отправку в WhatsApp/Instagram реализовать поверх существующего системного инвокера отправки файла с адресацией конкретному приложению и откатом на системный выбор приложений, по образцу пути Telegram.

### 5.1 Основные столпы / модули

- Регистрация таргетов мессенджеров в реестре (декларации: идентификатор, заголовок, дефолт «выключено», доступность по пакету, перечень пакетов клиента).
- Проводка seam гейтинга в горячий командный путь плеера: вычисление «флаг И доступность» для каждого мессенджера и передача результата в планировщик команд.
- Проводка seam гейтинга в overflow просмотра по тому же правилу.
- Реализация отправки файла в WhatsApp и в Instagram поверх системного инвокера (адресация пакету + откат на выбор приложений).
- Видимость пакетов мессенджеров для системы (manifest-объявление, требуется на API 30+).

### 5.2 Потоки данных и событий

- Настройки: реестр → построитель группы → тумблер → запись флага в app-global настройки.
- Меню (плеер/просмотр): точка показа → seam «флаг И доступность» по идентификатору таргета → показ/скрытие команды → действие отправки.
- Отправка: команда → подготовка файла (для сетевых источников - кэш, как у прочих share-операций) → системный инвокер с адресацией пакету мессенджера → при недоступности клиента откат на системный выбор.

### 5.3 Точки расширяемости

- Добавление нового мессенджера - одна регистрация в реестре плюс действие отправки и manifest-видимость; правка каркаса не нужна.
- Способ выбора получателя (прямой выбор внутри приложения vs «открыть в мессенджере с вложением») вынесен в открытый вопрос §6 и не фиксируется этим разделом; реализация по умолчанию - открыть в приложении с вложением.

## 6. Открытые вопросы / Research items

- Resolved: страница «Плеер» уже существует (S0442); группа «Команды отправить файл в..» и каркас реестра/хранения/резолвера готовы (S0452). Создавать их заново не нужно.
- Resolved: текущая отправка в Telegram идёт через системный механизм Android (ACTION_SEND с адресацией пакету клиента и откатом на системный выбор), не через авторизованные сессии. WhatsApp/Instagram реализуются тем же способом.
- Open (блокирует фазу отправки): хранимые авторизации мессенджеров и прямой выбор получателя внутри приложения. Нужно подтвердить, существует ли в принципе санкционированный публичный API, позволяющий выбрать получателя и отправить вложение, не выходя в UI мессенджера. Рабочая гипотеза - нет (бизнес-API мессенджеров требуют серверной интеграции и вне объёма, §2). Результат фиксирует, реализуем ли «прямой выбор получателя» или только «открыть в приложении с вложением».
- Open (блокирует фазу отправки): Instagram - поддерживает ли программную отправку произвольного файла-вложения через share-intent, и для каких типов медиа (есть известные ограничения по типам и по тому, что Instagram принимает только определённые форматы). Нужно определить целевое поведение и сообщение пользователю, когда формат не принимается.
- Open (блокирует фазу отправки): WhatsApp - применимость обычного share-intent для произвольного файла vs ограничения; подтвердить перечень и приоритет пакетов клиента (обычный/Business).
- Resolved (рекомендация): отдельная настройка «выбор получателя внутри приложения» не вводится. По умолчанию - «открыть в мессенджере с вложением» через системный инвокер; при недоступности клиента - системный выбор приложений. Прямой выбор получателя реализуется только если research выше подтвердит санкционированный публичный API.

## 11. Критерии готовности (strategic-level)

1. На странице «Плеер» в группе «Команды отправить файл в..» есть три тумблера: Telegram, WhatsApp, Instagram.
2. Все три по умолчанию выключены - на чистой установке и после обновления существующей.
3. Тумблер мессенджера, клиент которого не установлен, показан disabled с подписью «Не установлено».
4. При выключенном тумблере команда «отправить в <мессенджер>» отсутствует в меню плеера и в overflow просмотра; при включённом и установленном клиенте - присутствует.
5. Включённая команда WhatsApp передаёт текущий файл в WhatsApp (вложение), команда Instagram - в Instagram; при недоступности клиента пользователь получает системный выбор приложений, а не молчаливый сбой.
6. Изменение тумблера применяется к видимости команд без перезапуска приложения.
