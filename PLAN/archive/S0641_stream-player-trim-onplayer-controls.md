## 1. Проблема

S0631 отфильтровал командную панель приложения, но оверлей на самой поверхности видеоплеера
(контроллер ExoPlayer/Media3) для трансляции остался полным: seek-bar по таймлайну с позицией
и длительностью, кнопка порядка воспроизведения, пред./след. файл, перемотка ±. К живому потоку
эти элементы неприменимы (нет конечного таймлайна, нет файлового пред./след. на оверлее).

---

## 2. Решение

- В режиме трансляции на оверлее остаются только: пауза/плей (`exo_play_pause`), кнопка диалога
  управления видео (`btnPlaybackControl`) и PiP (`btnPictureInPicture`, по своему гейту API 31+).
- Скрываются: строка прогресса (`exo_position` / `exo_progress` / `exo_duration`), порядок
  воспроизведения (`exo_repeat`), пред./след. файл (`exo_prev_file` / `exo_next_file`), перемотка
  (`btnRewind10` / `btnForward30`).
- Профиль применяется по id, поэтому покрывает оба макета оверлея - компактный и крупный.

### 2.1 Устойчивость к пере-показу контроллера

- Контроллер Media3 при каждом показе заново прогоняет собственный pass видимости (вернул бы
  seek-bar и кнопку порядка). Поэтому профиль переустанавливается на каждом показе оверлея через
  `PlayerView.ControllerVisibilityListener`, а также при загрузке трансляции
  (`updateTrackButtonsVisibility`).

---

## 3. Критерии готовности

1. В видео-трансляции оверлей плеера показывает только пауза/плей, диалог управления и PiP.
2. Seek-bar, тайминги, порядок воспроизведения, пред./след. файл и перемотка скрыты.
3. Повторное скрытие/показ оверлея не возвращает скрытые элементы.
4. Обычное видео/аудио показывает прежний полный оверлей без изменений.
5. PiP-кнопка подчиняется своему прежнему гейту (видна на API 31+, скрыта ниже).

---

## 4. Затронутые классы

- `ExoPlayerControlsManager` - метод `applyStreamControlProfile`, listener видимости контроллера,
  новый callback-метод `isLiveVideoStream`.
- `PlayerManagerInitializer` - реализация `isLiveVideoStream` из состояния.
- `PlayerActivity.updateTrackButtonsVisibility` - применение профиля при загрузке.
