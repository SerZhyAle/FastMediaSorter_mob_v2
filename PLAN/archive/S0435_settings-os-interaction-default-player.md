## 1. Проблема

Из настроек пропали кнопки назначения приложения программой по умолчанию для медиафайлов. Сейчас эти кнопки регистрации существуют только на экране приветствия (Welcome), а сам экран недоступен, если пользователь скрыл «Экран приветствия» в настройках. В результате после скрытия приветствия у пользователя нет ни одной точки, чтобы сделать приложение обработчиком изображений, аудио, видео или документов по умолчанию.

Параллельно группы страницы «Воспроизведение», отвечающие за интеграцию с операционной системой (системные приложения, входящие ссылки, жесты экрана, поворот экрана вслед за ОС), разрознены и плохо читаются как единый блок.

---

## 2. Цели

1. Пользователь может зарегистрировать приложение как программу по умолчанию для изображений, аудио, видео и документов прямо со страницы «Воспроизведение», не открывая экран приветствия.
2. Доступ к регистрации не зависит от того, скрыт ли экран приветствия.
3. Все элементы интеграции с ОС логически объединены под одной сворачиваемой группой «Взаимодействие с операционной системой».
4. Кнопки регистрации показываются только для включённого в текущей сборке функционала.
5. Раскладка поддержана в портрете и ландшафте; в ландшафте элементы группы могут располагаться в две колонки.

**Non-goals:**

- Изменение самого механизма регистрации обработчика по умолчанию - он переиспользуется как есть.
- Переработка экрана приветствия (Welcome).
- Исправление повторного показа страницы приветствия после де‑регистрации в системе - доступ обеспечивается из настроек, поэтому этот сценарий выходит за объём.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Кнопки регистрации - шириной по собственному тексту (не растянутые на всю ширину).
2. Рядом с кнопками - инструктивный текст «как себя вести для регистрации», аналогичный тексту на экране приветствия.
3. В ландшафте элементы группы желательно располагать в две колонки.

### 3.2 Жёсткие ограничения

- **Flavor:** группа «Программа по умолчанию» видима в сборках с поддержкой назначения по умолчанию (standard, legacy, noLegal, photos); в photos видна только кнопка изображений; в lite функционал не поддержан - группа скрыта целиком. Видимость группы и отдельных кнопок определяется через capability‑слой, а не прямым `BuildConfig` в `src/main` (CLAUDE.md Rule 14). Реализация следует `dev/FLAVOR_DEVELOPMENT_RULES.md`.
- **API level:** регистрация выполняется через системный лист выбора приложения по умолчанию; на API < 29 определение «уже по умолчанию» работает best‑effort, но кнопки остаются доступны.
- **Wear OS:** не затрагивается.
- **Производительность:** подготовка интента регистрации (поиск примерного файла) не должна блокировать UI‑поток; известная проблема синхронной выборки вынесена отдельным тикетом.
- **Совместимость данных:** без миграций; состояние свёртки групп страницы хранится прежним способом.
- **Локализация:** EN/RU/UK обязательно для всех переименований заголовков, подписей кнопок и инструктивного текста.
- **Доступность:** кнопки и чекбокс фокусируемы (клавиатура, D‑pad/TV), заданы `nextFocus*`; touch‑target ≥ 48dp; элементы внутри безопасных границ `systemBars` + `displayCutout` в портрете и ландшафте.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** standard / legacy / noLegal - группа видима полностью; photos - только кнопка изображений; lite - группа скрыта (нет поддержки назначения по умолчанию). Реализация через capability‑слой + flavor source sets, без `BuildConfig` в `src/main`.
- **UI placement contract:** сворачиваемая группа «Взаимодействие с операционной системой» содержит в порядке сверху вниз: чекбокс «Поворачивать экран вслед за ОС» (без собственного заголовка) → подгруппа «Программа по умолчанию» → подгруппа «Реакция на входящие ссылки» → подгруппа «Жесты с левого края экрана». Кнопки регистрации - `wrap_content`. Портрет: один столбец; ландшафт: допускается два столбца.
- **Accessibility:** focusable + `nextFocus*` для всех новых кнопок и перемещённого чекбокса; touch‑target ≥ 48dp; видимость в безопасных границах в обеих ориентациях.
- **Localization:** EN/RU/UK - переименование трёх заголовков групп, четыре подписи кнопок, инструктивный текст регистрации.
- **Communication policy:** инструктивный текст соответствует `docs/COMMUNICATION_POLICY.md` (тон по §6) и переиспользует формулировки экрана приветствия.
- **Validation level:** сборка standard + lite + photos зелёная; ручная проверка на устройстве - видимость по флейворам, порядок групп, портрет/ландшафт, срабатывание системного листа выбора по умолчанию.
- **Owner sign-off:** 2026-06-15.
- **Related tickets:** S0436 (миграция `BuildConfig.SUPPORT_*` в `src/main` на capability‑слой), S0437 (синхронный MediaStore в UI‑потоке при подготовке интента). Архивные предшественники по welcome: S0398..S0409.

## 4. Контекст текущей архитектуры

За страницу «Воспроизведение» отвечает слой UI настроек: фрагмент рендерит набор сворачиваемых групп, состояние свёртки персистится. Механизм назначения приложения обработчиком по умолчанию уже реализован в слое настроек и сейчас вызывается только из потока экрана приветствия: он открывает системный лист выбора по умолчанию через намерение просмотра, а при невозможности - системные настройки приложений по умолчанию.

Проблему из §1 нельзя решить «на месте», потому что единственная точка входа в регистрацию привязана к экрану приветствия, а сам экран условно скрываем. Кроме того, видимость типов медиа в текущем коде определяется напрямую флагами сборки внутри `src/main`, что нарушает изоляцию флейворов и мешает повторному использованию из настроек.

---

## 5. Предлагаемый подход

Перенести точку входа в регистрацию обработчика по умолчанию на страницу «Воспроизведение», переиспользуя существующий доменный механизм (тот же, что на экране приветствия), и заодно собрать все элементы интеграции с ОС в единую сворачиваемую группу.

### 5.1 Основные столпы / модули

- **Подгруппа регистрации (UI):** набор кнопок шириной по тексту, по одной на тип медиа (изображения, аудио, видео, документы). Видимость каждой кнопки - по поддержке соответствующего типа; вся подгруппа скрыта, если назначение по умолчанию не поддержано сборкой. Рядом - инструктивный текст регистрации.
- **Механизм регистрации (домен/применение):** существующий, вызывается из контекста фрагмента настроек; открывает системный лист выбора по умолчанию или fallback в системные настройки.
- **Реструктуризация групп (UI):** переименование сворачиваемой группы в «Взаимодействие с операционной системой», перенос внутрь неё чекбокса поворота экрана (без отдельного заголовка), блока входящих ссылок (переименованного) и блока жестов (переименованного), с сохранением состояния свёртки.
- **Адаптивная раскладка:** портрет - один столбец; ландшафт - допускается два столбца; обе ориентации поддержаны парными layout‑файлами.

### 5.2 Потоки данных и событий

- UI настроек → запрос к capability‑слою о поддержанных типах → отрисовка соответствующих кнопок → нажатие → доменный механизм регистрации → системный лист выбора по умолчанию / системные настройки.
- Состояние «приложение уже по умолчанию» (best‑effort) → опциональное обновление вида кнопки.

### 5.3 Точки расширяемости

- Capability‑слой - единственная точка решения о видимости типов (без `BuildConfig` в `src/main`); добавление нового типа медиа сводится к новой кнопке плюс флагу.
- Общий источник инструктивного текста, переиспользуемый экраном приветствия и настройками, чтобы формулировки совпадали.

## 9. Архитектурные решения (ADR)

**ADR-1: Размещение регистрации в настройках вместо восстановления доступа к экрану приветствия**

- **Решение:** добавить кнопки регистрации на страницу «Воспроизведение».
- **Альтернативы:** чинить повторный показ страницы приветствия после де‑регистрации.
- **Почему:** настройки - постоянно доступная точка, не зависящая от флага показа приветствия; переиспользуется готовый механизм регистрации; единая группа улучшает читаемость интеграции с ОС.

## 11. Критерии готовности (strategic-level)

1. На странице «Воспроизведение» есть сворачиваемая группа «Взаимодействие с операционной системой».
2. Внутри группы порядок сверху вниз: чекбокс «Поворачивать экран вслед за ОС» (без подзаголовка) → «Программа по умолчанию» → «Реакция на входящие ссылки» → «Жесты с левого края экрана».
3. В «Программа по умолчанию» видны только кнопки включённого функционала; в lite группа отсутствует; в photos видна только кнопка изображений.
4. Нажатие кнопки открывает системный выбор приложения по умолчанию или системные настройки как fallback.
5. Рядом с кнопками показан инструктивный текст регистрации, согласованный с формулировками экрана приветствия.
6. Кнопки имеют ширину по собственному тексту; в портрете - один столбец, в ландшафте - два столбца.
7. Переименованы заголовки: «Системные приложения» → «Взаимодействие с операционной системой»; «ЖЕСТЫ ЭКРАНА» → «Жесты с левого края экрана»; «ВХОДЯЩИЕ ССЫЛКИ» → «Реакция на входящие ссылки».
8. Все новые и изменённые строки локализованы EN/RU/UK.
