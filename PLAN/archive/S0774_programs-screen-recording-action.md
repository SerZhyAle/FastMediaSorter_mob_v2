## 1. Проблема

В блоке «программы» есть сценарии разового захвата (скриншот экрана, съёмка фото/видео с камеры, запись с микрофона), но нет записи видео самого экрана. Пользователь не может записать происходящее на экране (в т.ч. в других приложениях) в видеофайл и сохранить его в выбранный ресурс. Область - блок программ Browse + настройки «Дополнительные программы и сценарии».

---

## 2. Цели

1. Новый сценарий «Видеозапись экрана» в блоке программ: кнопка в меню программ и на панели программ.
2. Запуск записи всего экрана через MediaProjection; запись продолжается, когда приложение свёрнуто (foreground-сервис).
3. Во время записи - кнопка «пауза», кнопка «остановить запись» и небольшой таймер длительности; остановка доступна также из уведомления.
4. Готовый файл сохраняется в выбранный ресурс; если ресурс не задан - в Downloads.
5. Настройка-тумблер «Видеозапись экрана» и подчинённая ей «Ресурс результата записи» в «Управление → Дополнительные программы и сценарии», по аналогии с записью микрофона.
6. Звук записи берётся с микрофона.
7. Индикатор записи - компактный, немодальный, закреплён в углу экрана (не полноэкранный диалог); тот же компонент переиспользуется индикатором записи голоса (`MainVoiceCaptureManager`, S0523) для консистентного UX между обоими сценариями блока программ.

**Non-goals:**

- Захват системного (внутреннего) звука - отдельный тикет при необходимости.
- Плавающий overlay поверх других приложений (стоп-контрол живёт в уведомлении и в приложении).
- Встроенный редактор/обрезка записанного видео.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Реализовать «по аналогии с существующими аналогичными настройками» (запись микрофона: тумблер + подчинённый ресурс-назначение, пустое значение → Downloads).
2. Маленький ненавязчивый таймер во время записи. Device-test 2026-07-03 обнаружил нарушение этого пункта: текущая реализация (`MainScreenRecordingManager.showRecordingCard`) - полноэкранный модальный `AlertDialog`, блокирующий содержимое экрана и лишающий запись смысла. Заменяется компактным немодальным индикатором в углу экрана (решение владельца - см. «Quiz decisions» ниже).

### 3.2 Жёсткие ограничения

- **Flavor:** тот же gated-набор, что и съёмка экрана (`src/screenCapture`): standard при `fms.screenCapture=on` плюс noLegal. Не lite/photos/legacy.
- **API level:** MediaProjection-запись + foreground-сервис типа `mediaProjection`; минимум проекта (API 26), современные ограничения FGS на API 34 учитываются.
- **Wear OS:** не затрагивается.
- **Производительность:** аппаратный видеокодек; запись не должна удерживать ресурсы после остановки (немедленный release VirtualDisplay/encoder).
- **Совместимость данных:** новые поля настроек (тумблер + ресурс-назначение) по образцу записи микрофона; форма расширения без слома существующих.
- **Локализация:** EN/RU/UK - обязательно.
- **Доступность:** кнопки програм/стоп - focusable, корректные touch target, не-цветовое отличие состояния записи; таймер читаем TalkBack.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S0755, S0770
- **Flavor reach:** standard (`fms.screenCapture=on`) + noLegal; не lite/photos/legacy (наследует gate набора захвата экрана).
- **Audio source:** микрофон (требуется RECORD_AUDIO и его запрос в UI).
- **Stop control & timer:** действие в уведомлении foreground-сервиса + кнопка/таймер внутри приложения; без разрешения overlay.
- **Capture scope:** весь экран, запись продолжается в фоне (foreground-сервис).
- **New permissions:** RECORD_AUDIO, POST_NOTIFICATIONS, FOREGROUND_SERVICE_MEDIA_PROJECTION (+ существующий MediaProjection consent).
- **Localization:** EN/RU/UK - да.
- **Pause control (решение владельца 2026-07-03):** добавлен в этот тикет, а не в отдельный - переиспользует проверенный паттерн паузы/резюме таймера записи (`CameraRecordingTimer`, S0566, съёмка видео с камеры); `MediaRecorder.pause()/resume()` доступны с API 24, минимум проекта для gated-набора (standard/noLegal) - API 26, ограничений нет.
- **Компактный индикатор (решение владельца 2026-07-03):** один общий немодальный компонент вместо `AlertDialog`, переиспользуется `MainVoiceCaptureManager` (запись голоса из панели программ, S0523 archived) - фикс распространяется на оба места вызова для консистентности.

## 4. Контекст текущей архитектуры

Захват экрана уже существует, но это разовый скриншот: foreground-сервис захвата получает MediaProjection-consent и читает один кадр через ImageReader, затем сохраняет в ресурс-назначение скриншота. Блок программ Browse уже отображает сценарии-кнопки и управляется менеджером панели программ; запись микрофона уже даёт образец «тумблер + подчинённый ресурс-назначение, пусто → Downloads». Чего нет: непрерывного кодирования экрана в видеофайл (VirtualDisplay + видеокодер), индикатора активной записи с таймером и сценария-кнопки записи экрана.

---

## 5. Предлагаемый подход

Расширить существующий MediaProjection-набор записью видео экрана, переиспользуя consent/disclosure и foreground-сервис, и добавить сценарий в блок программ по образцу остальных сценариев.

### 5.1 Основные столпы / модули

- Сценарий «Видеозапись экрана» в блоке программ (кнопка меню + панель), по образцу прочих сценариев захвата.
- Непрерывная запись экрана: MediaProjection → VirtualDisplay → видеокодер → MP4, аудио с микрофона, внутри foreground-сервиса типа `mediaProjection`.
- Индикатор записи: действие «остановить» в уведомлении сервиса + общий компактный немодальный индикатор (таймер, пауза, стоп) внутри приложения, переиспользуемый записью голоса.
- Пауза/резюме доходит до `MediaRecorder` (видеозапись экрана и запись голоса), таймер замораживает накопленное время на паузе - по образцу `CameraRecordingTimer` (S0566).
- Настройки: тумблер включения + подчинённый «Ресурс результата записи» (пусто → Downloads), по образцу записи микрофона.

### 5.2 Потоки данных и событий

UI (кнопка сценария) → запрос MediaProjection-consent (переиспользуется) → foreground-сервис записи (VirtualDisplay + кодер + микрофон) → по «стоп» (из приложения или уведомления) финализация файла → сохранение в выбранный ресурс или Downloads → обновление списка/уведомления.

### 5.3 Точки расширяемости

- Источник звука (добавление системного звука / микс) - оставить расширяемым.
- Параметры качества (разрешение/битрейт) - дефолт от экрана, с заделом под настройку.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Политика Google Play по записи экрана/других приложений | Средняя | Отклонение standard-сборки | Переиспользовать существующий disclosure захвата экрана; при риске - ограничить noLegal |
| Ограничения FGS типа mediaProjection на API 34+ | Средняя | Запись не стартует/прерывается | Корректный тип FGS, старт сервиса из пользовательского действия после consent |

| Пауза/резюме `MediaRecorder` рассинхронизирует таймер с длительностью файла | Низкая | Таймер не совпадает с реальной длительностью | Переиспользовать проверенный accumulate-and-freeze паттерн `CameraRecordingTimer` (S0566), не изобретать новый |

## 11. Критерии готовности (strategic-level)

1. В «Управление → Дополнительные программы и сценарии» есть тумблер «Видеозапись экрана» и (при включении) подчинённый «Ресурс результата записи».
2. При включённой опции в меню и на панели программ доступна кнопка «Видеозапись экрана».
3. Запуск запрашивает consent (и RECORD_AUDIO), начинает запись всего экрана со звуком микрофона, продолжает запись в фоне.
4. Во время записи виден компактный немодальный индикатор в углу экрана (не полноэкранный диалог) с таймером, кнопкой «пауза» и кнопкой «остановить»; остановка доступна также из уведомления.
5. По остановке файл сохраняется в выбранный ресурс, иначе в Downloads.
6. Функция доступна в standard (`fms.screenCapture=on`) и noLegal; отсутствует в lite/photos/legacy.
7. Тот же компактный индикатор (с паузой) используется записью голоса из панели программ (`MainVoiceCaptureManager`) - оба сценария выглядят и ведут себя консистентно.
