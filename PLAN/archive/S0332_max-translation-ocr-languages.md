> **Scope:** STRATEGIC. Цели, ограничения, подход и архитектурные решения; без тактических деталей реализации.

## 1. Проблема

Текущие списки языков перевода и OCR ограничены ручным набором популярных языков и не отражают полный набор, который уже поддерживают подключённые движки или могут поддержать скачиваемые модели. Из-за этого пользователь не может выбрать часть реально доступных языков, включая чешский, хотя базовая поддержка для перевода и латинского OCR существует во внешних движках. Для `standard` и `noLegal` также смешаны разные уровни качества: перевод, базовый OCR, качественный офлайн-OCR и тяжёлые noLegal-модели.

---

## 2. Цели

1. Сделать список языков перевода максимально близким к полному официальному списку поддерживаемых языков ML Kit Translation.
2. Сделать список языков OCR максимально широким, но разделить языки по реальному уровню поддержки: базовое распознавание, приоритетная поддержка, качественная скачиваемая модель, noLegal-модель.
3. Добавить чешский язык как обязательный контрольный пример для перевода и OCR.
4. Убрать расхождение между языковыми списками в настройках, плеере и Camera OCR.
5. Сохранить изоляцию noLegal: тяжёлые PaddleOCR-модели и sideload-only возможности не должны попадать в публичную `standard` сборку.
6. Реализовать интерфейс выбора языков перевода и OCR в виде диалогового окна с текстовым поиском (фильтрацией по первым буквам) вместо стандартных выпадающих списков.
7. Добавить отображение иконок флагов перед названием каждого языка в интерфейсе выбора.
8. Отображать названия языков в формате: имя на языке приложения + самоназвание в скобках, написанное собственным алфавитом/письменностью (например, `Чешский (Čeština)`, `Японский (日本語)`).

**Non-goals:**

- Не добавлять новые движки машинного перевода за пределами текущей on-device translation базы.
- Не бандлить все OCR-модели в APK.
- Не обещать одинаковое качество OCR для всех языков и шрифтов.
- Не менять язык интерфейса приложения; речь только о языках перевода и распознавания.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Максимально расширить список языков, а не добавить только один язык.
2. Включить чешский язык как первый проверяемый пример.
3. Сохранить поддержку и для `standard`, и для `noLegal`.
4. По возможности не ухудшать размер публичной сборки.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard` получает только market-safe зависимости, on-demand модели и публично допустимые возможности; `noLegal` получает расширение поверх `standard` с тяжёлыми OCR-моделями строго внутри своего flavor.
- **API level:** Без изменения общего minSdk.
- **Wear OS:** Не затрагивается.
- **Производительность:** Длинный список языков не должен замедлять открытие настроек, плеера и Camera OCR; OCR-модели загружаются только по требованию.
- **Совместимость данных:** Сохранённые коды языков должны оставаться BCP-47 для перевода и маппиться на OCR-коды без потери старых настроек.
- **Локализация:** Все новые пользовательские подписи, группы, предупреждения и help-тексты требуют EN/RU/UK паритета.
- **Доступность:** Длинные списки языков должны оставаться доступными для TalkBack, D-pad и клавиатуры; группировка или поиск должны иметь понятные contentDescription.
- **Communication policy:** Все новые пользовательские строки проходят `docs/COMMUNICATION_POLICY.md` §6 перед интеграцией.

### 3.3 Owner inputs (Approval gate)

- **Success signal:** Полная поддержка чешского языка в качестве контрольного примера для перевода и OCR, корректное отображение флагов и двуязычных названий для всех языков в новом селекторе с возможностью текстового поиска по первым буквам.
- **Language-set autonomy:** Агент имеет автономность в выборе финального набора языков из официальных списков ML Kit (перевод) и Tesseract/PaddleOCR (для OCR), с исключением проблемных или неподдерживаемых языков при наличии явного обоснования в технической спецификации.
- **Long-list UI decision:** Вместо простых спиннеров вводится диалоговое окно (Searchable Picker) с полем текстового ввода для фильтрации/поиска языка по первым буквам, группировкой языков и отображением emoji-флагов. Имя языка строится как `Имя на языке приложения (Самоназвание)`.
- **Validation level:** `standardDebug` для публичной матрицы языков и базового OCR; `noLegalDebug` для PaddleOCR-расширения; чешский (`cs`/`ces`) - обязательный контрольный smoke перевода и латинского OCR.
- **Related tickets:** S0288 (noLegal PaddleOCR/Paddle-Lite bundle - не подменять его завершение), S0156 (noLegal capability surface - сохранить изоляцию), S0285 (archived кириллический OCR research - основание noLegal-направления).
- **Owner sign-off:** 2026-06-03 - утверждены требования к UI выбора языков (флаги перед названиями, двуязычные названия с самоназванием, текстовый поиск по первым буквам).

## 4. Контекст текущей архитектуры

Перевод и OCR уже включены в `standard` и `noLegal`. Базовый перевод выполняется через ML Kit Translation, язык определяется через ML Kit Language ID, а базовый OCR использует ML Kit Text Recognition и Tesseract. `noLegal` дополнительно содержит ветку PaddleOCR/Paddle-Lite, которая должна оставаться compile-time изолированной.

Сейчас языковые списки живут как ручные массивы и ручные соответствия кодов, из-за чего разные поверхности выбора могут расходиться. OCR-движки также имеют разные модели языковой поддержки: ML Kit работает по письмам, Tesseract по `.traineddata`, PaddleOCR по модельным семействам.

---

## 5. Предлагаемый подход

Ввести единый каталог языков как продуктовую модель, которая описывает каждый язык один раз: код перевода, имя для отображения, родное имя, письмо, доступность OCR в `standard`, доступность OCR в `noLegal`, предпочитаемый OCR-движок и уровень качества. Все пользовательские поверхности выбора берут данные из этого каталога.

### 5.1 Основные столпы / модули

**Единый каталог языков**

- Хранит полный список языков перевода из официального API/документации ML Kit.
- Для каждого языка хранит OCR-метаданные: письмо, доступные движки, уровень поддержки, необходимость скачивания модели.
- Для чешского фиксирует `cs` как код перевода и OCR-язык латиницы.

**Стандартная OCR-матрица**

- Использует ML Kit Text Recognition для поддерживаемых писем и языков.
- Использует Tesseract как офлайн-расширение для языков, где есть официальные `.traineddata` и где качество ML Kit недостаточно или нужна независимость от скриптового recognizer.
- Не бандлит тяжёлые модели; скачивание, проверка и удаление остаются явными пользовательскими действием или on-demand процессом.

**noLegal OCR-матрица**

- Наследует стандартную матрицу.
- Добавляет PaddleOCR-модельные семейства по письмам и языковым группам.
- Поддерживает Latin PP-OCRv5 как noLegal-кандидата для чешского и других латинских языков.

**UI длинного списка**

- Сохраняет текущие точки входа: настройки, плеер, Camera OCR.
- Для длинного списка вводит диалоговое окно выбора (Searchable Language Picker) с полем текстового ввода для регистронезависимого поиска по первым буквам названия или самоназвания.
- Каждый элемент в списке выбора содержит emoji-флаг страны/региона, за которым следует название в формате: `Локализованное название (Самоназвание)` (например: `Чешский (Čeština)`, `Японский (日本語)`).
- Для длинного списка вводит группировку по типу: Auto, Recent, Preferred, Latin, Cyrillic, CJK, Indic, Other.
- Показывает недоступность OCR-модели не через удаление языка, а через состояние и объяснение: "translation only", "basic OCR", "download model", "noLegal only".

### 5.2 Потоки данных и событий

1. Пользователь выбирает язык в настройках или диалоге перевода.
2. UI получает список из единого каталога с фильтром по flavor, режиму и доступности.
3. Настройки сохраняют BCP-47 код языка и выбранный уровень OCR, если он отличается от автоматического.
4. При запуске OCR слой применения выбирает подходящий движок по языку, письму, flavor и установленным моделям.
5. Если нужна модель, пользователь видит явный запрос на скачивание, размер, источник и режим отката.
6. При ошибке выбранного OCR-движка система откатывается на следующий допустимый движок и сообщает об ограничении качества.

### 5.3 Точки расширяемости

- Каталог должен позволять добавлять новые языки без изменения нескольких UI-списков.
- Список перевода должен уметь обновляться по официальному API/документации ML Kit при ревизии зависимости.
- OCR-матрица должна поддерживать новые Tesseract и PaddleOCR модели через метаданные, а не через отдельные ветки UI.
- noLegal-модели должны подключаться без попадания тяжёлых библиотек и моделей в `standard`.

## 6. Открытые вопросы / Research items

1. **Финальный список языков перевода**
   - **Вопрос:** Брать полный `getAllLanguages()` из ML Kit на runtime или фиксировать список в приложении для стабильного UX?
   - **Варианты:** runtime-список; build-time сгенерированный список; ручной whitelist с полным покрытием официальных кодов.
   - **Нужно выяснить:** Поведение ML Kit при добавлении/удалении языка и совместимость с сохранёнными настройками.
   - **Статус:** Open.

2. **Tesseract-модели для `standard`**
   - **Вопрос:** Сколько языков разрешено показывать как "downloadable quality OCR" в публичной сборке?
   - **Варианты:** только приоритетные языки; все официальные `.traineddata`; только языки, выбранные владельцем.
   - **Нужно выяснить:** Бюджет трафика/диска и требования к checksum-метаданным.
   - **Статус:** Open.

3. **PaddleOCR Latin для noLegal**
   - **Вопрос:** Включать ли Latin PP-OCRv5 в первый тактический этап или оставить его после стабилизации текущего кириллического PaddleOCR.
   - **Варианты:** сразу добавить Latin; сначала завершить кириллицу; добавить только Czech smoke path.
   - **Нужно выяснить:** Готовность noLegal PaddleOCR pipeline к реальному postprocess и модельным семействам.
   - **Статус:** Open.

4. **Внешние источники, подтверждённые на 2026-06-02**
   - **Вопрос:** Какие официальные источники считать нормативными для реализации?
   - **Варианты:** ML Kit API reference для перевода, ML Kit Text Recognition language table, Tesseract tessdoc/data repos, PaddleOCR PP-OCRv5 multilingual docs.
   - **Нужно выяснить:** Нужен ли локальный mirror/manifest для воспроизводимости.
   - **Статус:** Resolved - первичные источники определены:
     - ML Kit Translate API: https://developers.google.com/android/reference/com/google/mlkit/nl/translate/TranslateLanguage
     - ML Kit Text Recognition v2 languages: https://developers.google.cn/ml-kit/vision/text-recognition/v2/languages?hl=en
     - Tesseract traineddata: https://tesseract-ocr.github.io/tessdoc/Data-Files.html
     - PaddleOCR PP-OCRv5 multilingual models: https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.en.md

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Полный список языков станет слишком длинным для spinner UI | Высокая | Пользователь не найдёт нужный язык, D-pad навигация станет неудобной | Searchable/grouped picker и Recent/Preferred секция |
| ML Kit и OCR-движки используют разные коды и уровни поддержки | Средняя | Язык перевода выбран, но OCR идёт неправильным движком или откатывается молча | Единая матрица возможностей с явным уровнем поддержки |
| Массовое добавление моделей раздует APK или расход диска | Высокая | `standard` станет тяжелее, noLegal займёт слишком много места | On-demand download, checksum, удаление моделей, noLegal isolation |
| Качество OCR по некоторым языкам будет ниже ожиданий | Высокая | Пользователь считает язык поддержанным, но результат плохой | Маркировать уровни "basic", "quality", "experimental"; не обещать одинаковое качество |
| Внешние списки языков изменятся | Средняя | Каталог устареет или сохранённый язык станет неподдержанным | Build-time проверка, fallback для неизвестного кода, документированная ревизия источников |
| noLegal PaddleOCR расширение затронет `standard` | Низкая | Нарушение flavor isolation и рост публичного APK | Compile-time isolation и проверка отсутствия noLegal моделей/библиотек в `standard` |

## 9. Архитектурные решения (ADR)

**ADR-1: Единый каталог языков вместо ручных UI-массивов**

- **Решение:** Один продуктовый каталог управляет языками перевода, OCR и отображением.
- **Альтернативы:** Добавлять языки в каждый экран отдельно.
- **Почему:** Ручные списки расходятся, ломают сохранённые настройки и затрудняют массовое расширение.

**ADR-2: Максимальное покрытие через capability levels**

- **Решение:** Язык может быть доступен на разных уровнях: translation only, basic OCR, quality OCR, noLegal OCR.
- **Альтернативы:** Показывать только языки с полной поддержкой всех режимов.
- **Почему:** Полная поддержка для всех языков нереалистична, но пользователь должен видеть честный уровень возможностей.

**ADR-3: noLegal расширяет OCR, но не перевод**

- **Решение:** Переводный список общий для `standard` и `noLegal`; noLegal отличается только OCR-модельными семействами.
- **Альтернативы:** Делать отдельные списки перевода для flavor.
- **Почему:** Перевод основан на одной ML Kit базе, а flavor-специфичность нужна только для тяжёлого OCR.

**ADR-4: Чешский как контрольный язык первой волны**

- **Решение:** Czech (`cs`) становится обязательным тестовым языком для новой матрицы.
- **Альтернативы:** Начинать с произвольного набора языков без контрольного примера.
- **Почему:** Чешский проверяет типичный латинский сценарий: перевод поддержан ML Kit, базовый OCR поддержан ML Kit Text Recognition, Tesseract имеет `ces`, noLegal может использовать Latin PP-OCRv5.

## 11. Критерии готовности (strategic-level)

1. Пользователь может выбрать чешский язык как источник и цель перевода во всех существующих поверхностях перевода.
2. Пользователь может выполнить OCR для чешского текста минимум через базовый латинский OCR.
3. Списки языков в настройках, плеере и Camera OCR совпадают по кодам и порядку.
4. Для каждого языка видно, доступен ли перевод, базовый OCR, скачиваемый quality OCR или noLegal OCR.
5. Добавление нового языка не требует изменения нескольких независимых UI-массивов.
6. `standard` не содержит noLegal PaddleOCR-модели и тяжёлые noLegal-only зависимости.
7. noLegal получает расширенную OCR-матрицу поверх standard без потери существующих OCR/translation сценариев.
8. В интерфейсах выбора языков (настройки, плеер, Camera OCR) вместо стандартных спиннеров используется диалоговое окно поиска с текстовым вводом для фильтрации языков по первым буквам.
9. Каждый элемент списка языков содержит emoji-флаг перед названием.
10. Названия языков отображаются в формате `Локализованное имя (Самоназвание)` (например, `Японский (日本語)`).
