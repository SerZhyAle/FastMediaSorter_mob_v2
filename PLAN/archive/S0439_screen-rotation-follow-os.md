## 1. Проблема

Настройка «поворачивать экран вслед за ОС» по смыслу относится ко всей программе, но управление поворотом приложение применяет только в плеере. Когда настройка выключена и пользователь задействует собственное управление поворотом, оно достаёт лишь до плеера: остальные окна (обзор, настройки, просмотрщики) нельзя ни перевести под управляемый приложением поворот, ни осознанно зафиксировать. Название единственной галочки вводит в заблуждение, обещая общесистемный эффект. Пользователю нужна единая настройка поворота на всю программу и отдельное исключение для плеера.

---

## 2. Цели

1. Настройка поворота вслед за ОС управляет ориентацией всех окон программы, а не только плеера.
2. Существующая галочка переименована так, чтобы её область («экран программы») была однозначна.
3. Добавлена отдельная галочка поворота вслед за ОС только для плеера в группе настроек интерфейса и команд плеера.
4. Видимость связана: плеерная галочка показывается, только когда программная выключена; при включённой программной поворот распространяется и на плеер, а плеерная галочка скрыта.
5. Фактическое поведение поворота для уже установленных пользователей сохраняется после обновления.

**Non-goals:**

- Изменение логики собственного управления поворотом внутри плеера (сенсор/блокировка, жесты, кнопка ручного поворота).
- Пер-оконные настройки поворота для каждого отдельного окна.
- Wear OS.

## 4. Контекст текущей архитектуры

Управление ориентацией сегодня сосредоточено в жизненном цикле окна плеера: единый флаг «вслед за ОС» (и его подчинённый флаг собственного управления) читается слоем настроек и применяется только при работе плеера. Остальные окна не запрашивают ориентацию явно, поэтому де-факто делегируют её ОС и системному авто-повороту, но не консультируются ни с каким флагом приложения. UI-переключатель флага ранее жил в настройках плеера, в S0435 был перенесён в группу взаимодействия с ОС, но его эффект остался привязан только к плееру. Поэтому распространить управляемый приложением поворот на всю программу нельзя без отдельной точки применения ориентации на уровне всех окон и без разделения единого флага на программный и плеерный.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

- Программная политика ориентации, применяемая единообразно ко всем окнам, а не только к плееру.
- Плеерное переопределение ориентации, учитываемое только когда программная политика - «не следовать ОС».
- Слой настроек хранит два флага (программный и плеерный) с правилом приоритета и связанной видимостью.

### 5.2 Потоки данных и событий

- UI настроек → слой применения сохраняет программный и плеерный флаги.
- Каждое окно при выходе на передний план спрашивает политику ориентации: следовать ОС или применить управление приложения - и применяет результат.
- Приоритет: программный флаг включён → все окна следуют ОС (плеер тоже, плеерный флаг игнорируется и скрыт). Программный флаг выключен → не-плеерные окна под управлением приложения, плеер следует своему плеерному флагу (вслед за ОС либо собственное управление).

### 5.3 Точки расширяемости

- Решение об ориентации каждого окна идёт через единую общую точку, чтобы будущие пер-оконные переопределения добавлялись без правки каждого окна.

## 6. Открытые вопросы / Research items

1. **Семантика миграции единого флага**
   - **Вопрос:** как отобразить текущее значение единой галочки на новую пару (программный/плеерный), чтобы поведение не изменилось при обновлении?
   - **Решение:** старое значение переносится в программный флаг (тот же концепт «следовать ОС», лишь шире по области); новый плеерный флаг по умолчанию выключен; вложенная плеерная под-настройка не меняется. Не-плеерные окна сегодня уже следуют ОС, поэтому именно наследование программным флагом сохраняет их поведение.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0439_screen-rotation-follow-os/research/01__current-rotation-model.md`

2. **Значения по умолчанию для свежей установки**
   - **Вопрос:** какими должны быть флаги на чистой установке?
   - **Решение:** программный флаг включён (как текущий дефолт - всё следует ОС); плеерный флаг выключен (скрыт, пока программный включён); под-настройка собственного управления плеера включена, как сейчас.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0439_screen-rotation-follow-os/research/01__current-rotation-model.md`

3. **Объём «всех остальных окон»**
   - **Вопрос:** какие именно окна должны следовать программной политике?
   - **Решение:** все окна на переднем плане проходят через единую точку применения ориентации; точное перечисление активностей (обзор, настройки, standalone-просмотрщики, плеер) - тактическая деталь для `/spec-tech`.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0439_screen-rotation-follow-os/research/01__current-rotation-model.md`

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Миграция меняет привычное поведение - окна вдруг начинают или перестают поворачиваться | Средняя | Пользователи видят неожиданную ориентацию окон после обновления | Программный флаг наследует старое значение «следовать ОС»; плеерный по умолчанию выключен (§9 ADR-2) |
| Часть окон имеет жёстко заданную ориентацию и не отреагирует на флаг | Средняя | Настройка частично не работает | На тактическом этапе перечислить все окна и провести их через единую точку |
| Связанная видимость двух галочек путает пользователя | Низкая | Непонимание, какая галочка действует | Чёткое правило зависимости и мгновенное отражение в UI настроек |

## 9. Архитектурные решения (ADR)

**ADR-1: Двухуровневая модель «программа → плеер»**

- **Решение:** программный флаг - зонтичный; плеерный флаг подчинён и учитывается только при выключенном программном; при включённом программном плеерная галочка скрыта.
- **Альтернативы:** два независимых равноправных флага; единый флаг без плеерного исключения.
- **Почему:** совпадает с моделью владельца (программная настройка - общая) и исключает противоречивые состояния.

**ADR-2: Миграция без изменения поведения**

- **Решение:** старое значение единого флага «следовать ОС» переносится в программный флаг; новый плеерный флаг по умолчанию выключен; вложенная плеерная под-настройка собственного управления остаётся без изменений.
- **Альтернативы:** перенести старое значение в плеерный флаг, а программный по умолчанию выключить.
- **Почему:** не-плеерные окна сегодня уже следуют ОС; если бы программный флаг дефолтил в «выключено», они перестали бы поворачиваться при обновлении - регрессия. Наследование одноимённым программным флагом сохраняет поведение и окон, и плеера.

## 11. Критерии готовности (strategic-level)

1. При включённой программной галочке все окна (обзор, настройки, просмотрщики, плеер) следуют ориентации ОС.
2. При выключенной программной галочке не-плеерные окна не следуют ОС - применяется управление приложения, как раньше для плеера.
3. В группе настроек интерфейса и команд плеера присутствует плеерная галочка, видимая только при выключенной программной.
4. При выключенной программной и включённой плеерной только плеер следует ОС; прочие окна под управлением приложения.
5. При включённой программной плеерная галочка скрыта.
6. После обновления фактическое поведение поворота для существующих пользователей не меняется.
7. Подписи обеих галочек присутствуют и согласованы в EN/RU/UK.
8. Обе галочки скрыты на устройствах без датчика ориентации - как текущая настройка.
