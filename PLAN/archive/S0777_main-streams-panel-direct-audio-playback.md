# Стратегическая спецификация: S0777 - Прямой запуск аудио-трансляции с панели главного окна

**Ticket:** S0777
**Status:** Archived
**Priority:** 50
**Date:** 2026-06-29
**Tier:** 3 - Moderate (ad-hoc)
**Roadmap entry:** Ad-hoc - запрос 2026-06-29

---

## 1. Проблема

Тап по аудио-каналу (радио/ICY) на панели трансляций главного окна открывает отдельный экран списка трансляций и запускает воспроизведение уже там. Пользователь покидает главное окно ради одного действия - «включить радио». Достаточно проиграть звук прямо в главном окне с нижней панелью «что сейчас играет», как это уже сделано на самом экране трансляций.

Область: `ui/main` (панель трансляций главного окна) + переиспользование инлайн-аудио из `ui/streams`.

---

## 2. Цели

1. Тап по AUDIO-каналу на панели главного окна запускает воспроизведение инлайн, без открытия экрана списка трансляций.
2. Внизу главного окна появляется липкая мини-панель «что сейчас играет» (название канала + ICY-трек + кнопка стоп), идентичная панели экрана трансляций.
3. Повторный тап по играющему каналу останавливает воспроизведение (тот же жест запускает и останавливает).
4. Поведение фонового аудио (сервис ON / локальный OFF), ICY-метаданные и обработка ошибок совпадают с экраном трансляций.

**Non-goals:**

- VIDEO/RTSP-каналы: поведение не меняется (по-прежнему открывают экран трансляций / полноэкранный плеер - им нужна видео-поверхность).
- Подсветка играющего чипа на панели.
- Запись статуса доступности канала (зелёный/красный буллет) из главного окна - остаётся за экраном трансляций.
- Диалог retry/remove при ошибке - в главном окне краткий Toast; полное управление каналом живёт на экране трансляций.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Максимально переиспользовать существующую инфраструктуру инлайн-аудио (без дублирования логики плеера).

### 3.2 Жёсткие ограничения

- **Flavor:** все, где есть панель трансляций (`SUPPORT_STREAMS`). Изменение flavor-нейтрально - переиспользует общий `StreamInlineAudioManager`; фоновый сервис гейтится существующим `ENABLE_PERSISTENT_AUDIO_PLAYBACK`.
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Производительность:** OFF-режим - локальный ExoPlayer, освобождается при уходе окна в фон; ON-режим - общий `AudioPlaybackService`.
- **Совместимость данных:** миграций нет.
- **Локализация:** новые строки не вводятся (переиспользуются `streams_*`).
- **Доступность:** мини-панель - в безопасных вставках (`applySystemBarInsetPadding`); кнопка стоп фокусируема (D-pad/TV).

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S0756 (панель трансляций главного окна), S0577 (инлайн-аудио + фоновый сервис), S0689 (radio vs video player split), S0778 (вставки мини-панели). Зависимостей-блокеров нет.

---

## 4. Контекст текущей архитектуры

Экран трансляций (`StreamsActivity`) уже классифицирует канал по `StreamSourceEntity.mediaKind`: `AUDIO` играет инлайн через `StreamInlineAudioManager` (липкая нижняя мини-панель + фоновый `AudioPlaybackService` или локальный ExoPlayer), `VIDEO`/`RTSP` уходят в полноэкранный плеер. Панель главного окна (`MainStreamsPanelManager`) этого не делает: её `onPlayChannel` всегда запускает `StreamsActivity` с авто-проигрыванием. Инфраструктура инлайн-аудио уже переиспользуема и не привязана к `StreamsActivity` - не хватает только точки её подключения в главном окне.

---

## 5. Предлагаемый подход

Перенести AUDIO-инлайн-путь экрана трансляций в главное окно, переиспользуя тот же `StreamInlineAudioManager`. Маршрутизацию и жизненный цикл вынести в отдельный координатор-хелпер (Rule 3 - в активити логики нет).

### 5.1 Основные столпы / модули

- Новый координатор в `ui/main/helpers` владеет одним `StreamInlineAudioManager`, классифицирует тап (`AUDIO` -> инлайн, иначе -> колбэк хоста), сам подписывается на жизненный цикл окна (`DefaultLifecycleObserver`).
- Нижняя мини-панель в `activity_main` (3 варианта layout) - якорь снизу `CoordinatorLayout`, по умолчанию `GONE`.
- Координатором владеет существующий менеджер панели трансляций (тап канала - его зона ответственности); `MainActivity` лишь передаёт ему сетевой/настроечный/видео-колбэки. VIDEO/RTSP остаются на прежнем поведении (открыть `StreamsActivity`).

### 5.2 Потоки данных и событий

- Тап чипа -> панель -> координатор: `AUDIO` + уже играет -> стоп; `AUDIO` + сеть есть -> инлайн-плей (фоновый сервис по настройке); нет сети -> Toast; иначе -> хост открывает экран трансляций.
- ICY-метаданные и ошибка -> существующие колбэки `StreamInlineAudioManager`; ошибка -> Toast «канал недоступен».
- Уход окна в фон (`onStop`) -> остановить OFF-режим (локальный плеер); уничтожение окна (`onDestroy`) -> ON-режим (сервис) продолжает играть, OFF освобождается.

### 5.3 Точки расширяемости

- Подсветка играющего чипа: колбэк `onPlayingChanged` уже прокинут (сейчас no-op) - адаптер панели можно расширить позже.
- Богатый диалог retry/remove и запись статуса канала: координатор можно дооснастить колбэками без изменения хоста.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Два инлайн-аудио-владельца (главное окно + экран трансляций) при ON-режиме | Низкая | Гонка контроллеров одного сервиса | `AudioPlaybackService` - один MediaSession, допускает несколько MediaController; OFF-режим останавливается на `onStop` до открытия экрана |

| Рост `MainActivity` сверх 1500 LOC | Низкая | Нарушение Rule 2 | Логика в координаторе; в хосте ~10 строк проводки |

## 8. Влияние на пользователя (docs/FEATURES)

Новая возможность: аудио-трансляция с панели главного окна играет прямо в главном окне с мини-панелью «сейчас играет», без перехода на отдельный экран.

- FEATURES: Tap an audio stream on the home panel to play it right there, with a now-playing bar at the bottom - no need to open the streams list.
- FEATURES_RU: Нажмите на аудио-трансляцию на панели главного окна, чтобы включить её прямо здесь, с панелью «сейчас играет» внизу - без перехода к списку трансляций.
- FEATURES_UK: Натисніть на аудіо-трансляцію на панелі головного вікна, щоб увімкнути її прямо тут, з панеллю «зараз грає» внизу - без переходу до списку трансляцій.

## 9. Архитектурные решения (ADR)

- Координатор переиспользует `StreamInlineAudioManager` (не дублирует движок плеера) - решение по устоявшимся паттернам проекта.
- Владельцем координатора назначен менеджер панели трансляций, а не `MainActivity`: активити уже на пределе лимита размера (Rule 2), поэтому проводка вынесена в хелпер; так в активити добавляется только инъекция и колбэки.

## 11. Критерии готовности (strategic-level)

1. Тап по AUDIO-каналу на панели главного окна играет инлайн; экран списка не открывается.
2. Внизу главного окна показывается мини-панель с названием/ICY-треком и работающей кнопкой стоп.
3. Повторный тап по играющему каналу останавливает его.
4. VIDEO/RTSP-канал по-прежнему открывает экран трансляций.
5. Уход в фон останавливает OFF-режим; при включённом фоновом аудио ON-режим продолжает играть.
6. Сборка `standard` и `noLegal` проходит; новых строк/миграций нет.

## 12. План реализации (tactical)

1. `MainStreamsInlineAudioManager.kt` (`ui/main/helpers`): `@UnstableApi`, `DefaultLifecycleObserver`; владеет `StreamInlineAudioManager`; `playChannel()` (классификация + toggle + сеть-гейт), `onStop`/`onDestroy`.
2. Мини-панель в `layout/`, `layout-land/`, `layout-w600dp/` `activity_main.xml` (якорь снизу, `GONE`, переиспользует `ic_stop`/`streams_stop`).
3. `MainStreamsPanelManager` владеет координатором (конструирует из `ActivityMainBinding` + сетевой/настроечный/видео-колбэки); тап канала маршрутизируется внутри. `MainActivity`: `@Inject NetworkContextAnalyzer` + передача колбэков в менеджер панели.
4. Debug-тег `S0777` в точке входа `playChannel` (на время `BlockNeedUserTest`).
5. Сборка `fk`/`fc`, catalog sync, post-change, запись возможности в `ALL_FEATURES`.
