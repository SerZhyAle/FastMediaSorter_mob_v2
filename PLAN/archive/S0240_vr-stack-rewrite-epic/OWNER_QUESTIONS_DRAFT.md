## Q2. Поддержка устройств в Meta Store — РЕШЕНО

**Ответ владельца:** «все совместимые с Quest3».

**Принято:**

- Поддерживаются: **Quest 2, Quest 3, Quest 3S, Quest Pro** + Android XR (отдельный таргет).
- НЕ поддерживается: Quest 1 (original).
- Quest 2 получает fallback для Quest 3-specific расширений (foveated rendering 2.0, hand-tracking 2.x, повышенный per-eye resolution).

## Q3. Scope cloud features в VR-сборке — РЕШЕНО

**Ответ владельца:** «разумеется! весь функционал стандарта там будет работать. В Quest не работает сквозная авторизация Google, но в Android XR она есть».

**Принято:**

- Все cloud-провайдеры (Google Drive, Dropbox, MSAL, SMB, SFTP, WebDAV, FTP) включаются автоматически через `standard` ⊂ `vr`. Никаких отключений.
- **Технический caveat (research-задача, не owner-вопрос):**
  - На **Quest (Horizon OS)** Google OAuth single-sign-on недоступен — нет встроенного Google Account. Используем web-based-OAuth-flow Google + MSAL + Dropbox.
  - На **Android XR** Google OAuth single-sign-on работает штатно.
  - Зафиксировано в `RESEARCH.md` под-задачей к `R-12`.

**Lesson learned:** этот вопрос задавать не следовало — иерархия `standard` ⊂ `vr` уже отвечала. Записано в agent-memory + Last Audit.

## Q4. Telemetry / data collection — РЕШЕНО

**Ответ владельца:** «не понял вопроса. Для дебага у нас есть дебаг-сборка. Мы на пользователях тесты не проводим — что есть в стандарт, то и останется».

**Контекст вопроса:** Google Play и Meta Store требуют форму Data Safety даже для приложений, ничего не собирающих. Декларация «No data collected» — сам по себе ответ store-формы.

**Принято:**

- Никаких новых telemetry-библиотек (Crashlytics / Sentry / analytics) в VR-сборку не добавляется. Inherit-from-standard.
- Store-форма Data Safety = **«No data collected»** на обеих площадках.
- Если `standard` в будущем начнёт что-то собирать — пересматриваем.
