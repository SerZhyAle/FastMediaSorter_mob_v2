# Research 02 - Доступность программного закрепления ярлыка по API level

**Spec:** S0637
**§6 item:** 2
**Status:** Resolved

## Вопрос

На каких устройствах доступно программное закрепление ярлыка на домашнем экране, и что делать на флейворах с низким minSdk?

## Находки

- Программное закрепление ярлыка пользователем (системный диалог «добавить на главный экран») доступно начиная с Android 8.0 (API 26). До API 26 публичного механизма «попросить лаунчер закрепить ярлык» нет - был только устаревший широковещательный путь, ненадёжный и нерекомендуемый.
- Минимальные SDK флейворов (из `app_v2/build.gradle.kts`, раздел 8 CLAUDE.md): standard/noLegal/VR/photos - minSdk 26; legacy - minSdk 23.
- Следствие: на standard/noLegal/VR закрепление доступно на всём диапазоне устройств. На legacy устройства с API 23-25 не получат программного закрепления.
- Поддержка закрепления зависит ещё и от конкретного лаунчера (даже на API 26+ часть кастомных лаунчеров возвращает «не поддерживается») - перед запросом нужна проверка поддержки и понятный текст при отказе.

## Вывод для спеки

- Целевой механизм - закреплённый ярлык - технически безопасен для standard/noLegal/VR.
- Для legacy ниже API 26 нужна деградация (сообщение) либо виджет-вариант, который работает с API 23. Это один из доводов развилки §6 #1.

## Источники

- developer.android.com - ShortcutManager / pinning shortcuts (требование API 26 для пользовательского закрепления).
- `app_v2/build.gradle.kts` - minSdk по флейворам.
