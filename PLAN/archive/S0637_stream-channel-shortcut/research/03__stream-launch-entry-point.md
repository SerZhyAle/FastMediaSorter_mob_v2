# Research 03 - Точка запуска конкретного канала по идентификатору

**Spec:** S0637
**§6 item:** 3
**Status:** Resolved

## Вопрос

Существует ли способ запустить конкретную трансляцию извне приложения (по идентификатору), или его нужно создавать?

## Находки

- Запуск канала сейчас инициируется только изнутри экрана Трансляций по выбору строки списка (точка воспроизведения `onPlay(source)` в `ui/streams/StreamsActivity.kt`). Внешней точки входа, принимающей идентификатор канала, нет: в `StreamsActivity` отсутствуют обработчики внешнего intent (`onNewIntent`/`ACTION_VIEW`/extra с идентификатором канала).
- Модель канала (`data/local/db/StreamSourceEntity`) уже несёт всё необходимое для deep-link: стабильный `id`, `url`, `title` и `mediaKind` (AUDIO/VIDEO/RTSP), который драйвит маршрутизацию запуска по типу.
- В проекте есть готовый образец параметризованного deep-link: менеджер ярлыков приложения (`core/AppShortcutsManager`) публикует динамические ярлыки, чей intent направлен в главный экран с действием и `EXTRA_*` идентификатором ресурса. Тот же приём (действие + extra с идентификатором канала) переиспользуется для запуска трансляции.

## Вывод для спеки

- Нужна новая внешняя точка входа «запустить трансляцию по идентификатору», которая по `id` находит канал и направляет его в существующий поток запуска по `mediaKind`, не дублируя логику плеера.
- Поведение при отсутствующем `id` (канал удалён) - сообщение и открытие экрана Трансляций (§6 #5).

## Источники

- `ui/streams/StreamsActivity.kt` - `onPlay(source)`; отсутствие внешних intent-обработчиков.
- `data/local/db/StreamSourceEntity.kt` - поля `id`, `mediaKind`.
- `core/AppShortcutsManager.kt` - образец deep-link по идентификатору (динамические ярлыки ресурсов).
