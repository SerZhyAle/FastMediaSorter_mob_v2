## 1. Проблема

В режиме Browse кнопка воспроизведения прямо на карточке файла доступна только в ресурсах типа «Аудиотека». Во всех остальных ресурсах — Downloads, SFTP-папки, локальные папки с записями диктофона и пр. — аудиофайлы открываются через полный плеер, что вынуждает пользователя покидать список. Особенно это ощутимо после записи с микрофона (S0100): файл только что создан в текущей папке, и послушать его без перехода в плеер невозможно. При этом для аудиофайлов полный плеер в большинстве случаев избыточен — достаточно нажать «играть» и услышать содержимое.

---

## 2. Цели

1. Кнопка «играть/пауза» отображается прямо на карточке любого аудиофайла в любом ресурсе Browse — независимо от типа ресурса (локальный, SFTP, SMB, FTP, облако).
2. Нажатие кнопки запускает воспроизведение без открытия полного плеера; повторное нажатие ставит на паузу.
3. Одновременно воспроизводится не более одного файла — запуск нового останавливает предыдущий.
4. Механизм повторно использует существующую инфраструктуру встроенного мини-плеера (уже работающую в Аудиотеке), а не создаёт параллельную.

**Non-goals:**

- Управление очередью воспроизведения из Browse — не в этой итерации.
- Фоновое воспроизведение с уведомлением в notification bar — не в этой итерации (только пока Browse открыт).
- Изменение поведения полного плеера (Audio Player).
- Wear OS companion.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Сценарий «записал диктофоном → тут же прослушал в том же Browse» должен работать без единого лишнего перехода.
2. Визуально поведение карточки с аудиофайлом должно выглядеть так же, как в Аудиотеке, — знакомый паттерн без обучения.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard` ✓, `legacy` ✓, `lite` ✓ (аналогично Аудиотеке — если мини-плеер включён там, он включён и здесь); `photos` — исключён (`SUPPORT_AUDIO=false`).
- **API level:** API 26+ (standard/legacy/lite без изменений).
- **Wear OS:** не затрагивается.
- **Производительность:** кнопка рендерится только на карточках аудиофайлов; отсутствие кнопки на прочих типах файлов — нулевые накладные расходы.
- **Совместимость данных:** новые настройки (если потребуются) — в существующем хранилище; новая схема Room не нужна.
- **Локализация:** EN/RU/UK — для любых новых строк UI и content description кнопки.
- **Доступность:** touch target кнопки ≥ 48 dp; content description.

## 4. Контекст текущей архитектуры

В Browse карточки файлов рендерятся через единый адаптер списка. Поведение при тапе на карточку определяется типом файла: изображения — в просмотрщик, видео — в плеер, документы — в соответствующий вьювер. Для аудиофайлов сейчас тап тоже открывает полный плеер. Встроенный мини-плеер («играть прямо с карточки») уже реализован, но его активация жёстко привязана к ресурсам типа Аудиотека — это условие нужно ослабить до «любой аудиофайл в любом ресурсе».

Слой управления воспроизведением уже изолирован от конкретного ресурса и способен играть файлы по URI — потому расширение сводится к изменению логики отображения кнопки и маршрутизации тапа, а не к переписыванию воспроизведения.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**А. Условие отображения кнопки «играть»**

Кнопка отображается на карточке тогда и только тогда, когда файл имеет аудио-MIME тип. Проверка происходит в слое рендеринга карточки; ресурс-контейнер не влияет на это условие.

**Б. Маршрутизация тапа на карточку**

Тап на кнопку «играть» → запускает мини-плеер (как в Аудиотеке). Поведение тапа на тело карточки — открытый вопрос (§6, п. 2).

**В. Singleton-состояние воспроизведения**

Не более одного файла воспроизводится одновременно в Browse. При запуске нового файла предыдущий останавливается; карточка предыдущего файла возвращается в состояние «играть». Это поведение уже реализовано в Аудиотеке — нужно убедиться, что оно работает и при воспроизведении из ресурсов других типов.

**Г. Поведение на сетевых ресурсах**

Аналогично существующей Аудиотеке: сетевые файлы (SFTP/SMB/FTP/облако) уже поддерживаются мини-плеером — файл буферизуется с прогресс-анимацией (пульсирующая прозрачность иконки). Расширение просто снимает ограничение на тип ресурса, не меняя логику буферизации.

**Д. Визуальный индикатор «сейчас играет»**

Аналогично Аудиотеке: иконка ноты вращается (анимация 360° rotation) во время воспроизведения; при паузе — иконка паузы, вращение сбрасывается.

**Е. Поведение при уходе из папки**

Воспроизведение останавливается при навигации в другую папку или уходе из Browse.

**Ж. Настройка «скрыть команды на сетке» (`hideGridActionButtons`)**

Кнопка «играть» скрывается в сеточном режиме при включённой настройке — наравне с кнопками копирования/перемещения/удаления. Это единственный управляющий переключатель; отдельной настройки для мини-плеера нет.

**З. Тап по телу карточки аудиофайла**

Поведение не меняется: тап по телу карточки открывает полный плеер (текущее поведение). Мини-воспроизведение запускается только явным нажатием кнопки «играть».

### 5.2 Потоки данных и событий

```
Пользователь нажимает «играть» на карточке аудиофайла
  → слой Browse отправляет событие «начать воспроизведение файла X»
  → состояние воспроизведения: предыдущий файл (если есть) → стоп
  → мини-плеер инициирует воспроизведение X
  → карточка X меняет иконку на «пауза»
  
Пользователь нажимает «пауза» на карточке X
  → мини-плеер → пауза
  → карточка X возвращает иконку «играть»
```

### 5.3 Точки расширяемости

- Поведение при навигации из папки (стоп vs. продолжение) может быть реализовано как настройка в будущей итерации.
- Управление очередью и shuffle из Browse — возможное расширение, не входит в текущий объём.

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользование существующего мини-плеера Аудиотеки, а не новая реализация**

- **Решение:** Ослабить условие активации кнопки воспроизведения с «ресурс типа Аудиотека» до «файл с аудио-MIME типом», не создавая второй слой воспроизведения.
- **Альтернативы:** Отдельный упрощённый плеер для «прочих» ресурсов — независимый от Аудиотеки.
- **Почему:** Дублирование плееров приводит к рассинхронизации состояния и двойной поддержке. Переиспользование гарантирует единое состояние и минимальный объём изменений.

## 11. Критерии готовности (strategic-level)

1. Кнопка «играть» видна на карточках аудиофайлов в любом Browse-ресурсе (локальном, SFTP, SMB, FTP, облачном) — не только в Аудиотеке.
2. Нажатие запускает воспроизведение без открытия полного плеера; кнопка меняется на «пауза».
3. Повторное нажатие ставит на паузу; иконка возвращается к «играть».
4. Запуск нового файла автоматически останавливает предыдущий — в списке никогда не играют два файла одновременно.
5. Файл, записанный через S0100 в текущую папку, доступен для прослушивания через кнопку на карточке без перехода куда-либо.
6. Флейвор `photos` кнопки не показывает.
