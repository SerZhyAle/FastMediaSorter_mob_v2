## 1. Проблема

На планках ресурсов главного экрана (список и сетка) набор кнопок операций управляется автоматически: в портретной ориентации телефона показывается кнопка «⋮» с выпадающим меню, а в ландшафте и на планшете — инлайн-кнопки (редактировать, скопировать, переместить вверх/вниз, удалить). Пользователь не может повлиять на этот выбор вручную.

Кроме того, операция «проверить доступность ресурса и обновить счётчик файлов» сейчас не доступна непосредственно из планки ресурса — только через глобальную кнопку «проверить все». В результате быстро обновить статус одного ресурса без лишних тапов невозможно.

---

## 2. Цели

1. В разделе настроек интерфейса появляется переключатель «Операции с ресурсами показывать в меню» (по умолчанию выключен).
2. При включённом переключателе на каждой планке ресурса (список и сетка, портрет и ландшафт) отображается только кнопка «⋮», открывающая выпадающее меню — инлайн-кнопки скрываются.
3. При выключённом переключателе — поведение остаётся полностью прежним (автовыбор inline/overflow по ориентации и размеру экрана).
4. Выпадающее меню в режиме включённого переключателя содержит: редактировать, скопировать ресурс, обновить ресурс (тест ± подсчёт), переместить вверх, переместить вниз, удалить.
5. Операция «обновить ресурс» становится доступна из планки ресурса без открытия полного экрана редактирования.

**Non-goals:**

- Изменение меню на Wear OS.
- Изменение поведения глобальной кнопки «Проверить всё» и механизма фоновой синхронизации.
- Изменение состава меню Browse-экрана (`ResourceOpsMenuManager`) — это отдельная сущность.
- Добавление нового экрана или диалога для выбора содержимого меню.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Пункт «Обновить» в меню запускает тест доступности ресурса: если ресурс недоступен — показывается toast «недоступен»; если доступен — обновляется счётчик файлов и дата сканирования на планке (без toast).
2. Порядок пунктов в меню: Редактировать · Скопировать ресурс · Обновить · Переместить вверх · Переместить вниз · Удалить.
3. Пункт «Скопировать ресурс» скрыт для виртуальных путей (поведение совпадает с текущим).
4. Пункты «Переместить вверх» / «Переместить вниз» присутствуют в overflow-меню: drag-and-drop для переупорядочивания нефункционален (касание воспринимается как вход, долгое — как long-click, жест смещения теряется).

### 3.2 Жёсткие ограничения

- **Flavor:** все флейворы (`standard`, `lite`, `photos`, `legacy`) — переключатель видим везде; состав меню повторяет ограничения каждого флейвора.
- **API level:** без API-специфики (Android 8 / API 26 minimum).
- **Wear OS:** не затрагивается.
- **Производительность:** меню строится на лету при нажатии «⋮»; операция «обновить» выполняется асинхронно без блокировки UI.
- **Совместимость данных:** новый bool-флаг хранится в DataStore; дефолт `false`; миграция Room не требуется.
- **Локализация:** EN/RU/UK — обязательны для label переключателя, подписи кнопки «⋮» (`contentDescription`) и нового пункта меню «Обновить».
- **Доступность:** кнопка «⋮» должна иметь `contentDescription`; touch target ≥ 32 × 32 dp; `PopupMenu` обеспечивает базовую TalkBack-навигацию стандартными средствами Android.
- **Коммуникационная политика:** если операция «обновить» сопровождается toast-сообщением о результате — тон и формулировки должны соответствовать `docs/COMMUNICATION_POLICY.md` (§6 tone checklist обязателен перед коммитом строк).
- **Layout ориентация:** изменение XML-шаблонов планок ресурсов (список и сетка) должно быть применено и к landscape-вариантам, если они существуют.

## 4. Контекст текущей архитектуры

Планки ресурсов на главном экране отображаются через адаптер списка с двумя типами `ViewHolder`: список и сетка. Адаптер читает ресурс `R.bool.is_resource_actions_inline` — это булево значение, зависящее от квалификатора конфигурации (`values/`, `values-land/`, `values-sw600dp/`). Если флаг `true` — рисуются инлайн-кнопки; если `false` — показывается кнопка «⋮» с `PopupMenu`. Текущий `PopupMenu` уже содержит пункты: редактировать, скопировать, переместить вверх/вниз, удалить.

Модель настроек приложения (`AppSettings`) хранит пользовательские флаги и читается из DataStore через репозиторий настроек. Адаптер получает данные через `ViewModel` — поэтому добавление нового флага из настроек потребует прокладки `AppSettings → ViewModel → Adapter`.

Операция «тест + подсчёт» для одного ресурса существует частично: тест доступности есть в ViewModel главного экрана (используется кнопкой «Проверить всё»), но вызова для единственного ресурса из адаптера пока нет — потребуется добавить точку входа в ViewModel.

---

## 5. Предлагаемый подход

Вводится один булев флаг в доменную модель настроек (`false` по умолчанию). Адаптер ресурсов при привязке каждого элемента проверяет этот флаг: если он `true` — принудительно использует overflow-режим независимо от `R.bool.is_resource_actions_inline`; если `false` — поведение остаётся прежним. ViewModel главного экрана раскрывает флаг через UI-состояние и добавляет операцию «обновить один ресурс» как новый публичный метод.

### 5.1 Основные столпы / модули

**А. Модель настроек и персистентность**
- Новый флаг `resourceOpsInOverflowMenu: Boolean = false` в доменной модели настроек.
- Чтение/запись через существующий DataStore-провайдер без изменения схемы Room.

**Б. Экран настроек интерфейса**
- Новый переключатель в секции настроек интерфейса, после ближайшего смежного параметра отображения.
- Label и help-text по canonical UI-паттерну `toggler_title_text_size` / `toggler_desc_text_size` согласно `docs/ARCHITECTURE.md`.

**В. ViewModel главного экрана и UI-состояние**
- Флаг из настроек пробрасывается в UI-состояние главного экрана.
- Добавляется новый метод «обновить один ресурс» (тест доступности + подсчёт файлов) — вызывает тот же механизм, что «Проверить всё», но только для переданного ресурса.

**Г. Адаптер ресурсов**
- Адаптер принимает флаг `overflowEnabled: Boolean` (через `setOverflowMode()` или при каждой привязке через `setViewMode()`-подобный метод).
- Если флаг включён — `btnMoreActions` всегда видима, `layoutInlineActions` скрыта; меню содержит: редактировать, скопировать, обновить, переместить вверх, переместить вниз, удалить.
- Пункты move_up/move_down включены в overflow-меню: drag-and-drop неработоспособен (касание = вход, long-tap = long-click, жест перетаскивания теряется).
- Если флаг выключен — существующая логика `R.bool.is_resource_actions_inline` не меняется.

**Д. XML ресурсы**
- Добавляется пункт `action_scan` (или аналогичный) в `res/menu/resource_item_actions.xml`.
- Строки для нового пункта меню и настройки — в `strings.xml` (EN), `strings-ru.xml`, `strings-uk.xml`.

### 5.2 Потоки данных и событий

```
Пользователь включает переключатель
  → SettingsRepository.update(resourceOpsInOverflowMenu = true)
    → DataStore.write
      → MainViewModel.state обновляется
        → Адаптер перебиндит видимые элементы → ⋮ появляется

Пользователь нажимает ⋮ → открывается PopupMenu
  → «Обновить» → MainViewModel.scanSingleResource(id)
      → тест доступности + подсчёт → обновление tvLastSync / tvStatus на планке
```

### 5.3 Точки расширяемости

- Состав пунктов меню может расширяться без изменения архитектуры — достаточно добавить item в XML меню и обработчик в адаптере.
- Флаг `resourceOpsInOverflowMenu` может применяться к будущим новым типам планок (например, виджет-ресурсы) без изменения слоя настроек.

## 6. Открытые вопросы / Research items

1. **Метод «обновить один ресурс»**
   - **Вопрос:** какой именно результат показывать пользователю: только toast «ресурс доступен / недоступен» или обновлять счётчик файлов на планке?
   - **Ответ:** toast «недоступен» только при сбое; при успехе — обновить счётчик файлов и дату сканирования на планке без toast.
   - **Статус:** Resolved

2. **Скрытие move_up / move_down в overflow-режиме**
   - **Вопрос:** достаточно ли drag-and-drop для переупорядочивания ресурсов в overflow-режиме?
   - **Ответ:** drag-and-drop неработоспособен — касание воспринимается как открытие ресурса, долгое нажатие — как long-click, жест смещения теряется. Пункты «Переместить вверх» / «Переместить вниз» обязательно добавить в overflow-меню.
   - **Статус:** Resolved

|------|:-----------:|-------------|-----------|

## 9. Архитектурные решения (ADR)

**ADR-1: Флаг в настройках vs. Resource-qualifier**

- **Решение:** пользовательский bool-флаг в DataStore; `R.bool.is_resource_actions_inline` остаётся без изменений как запасной механизм для случая «настройка выключена».
- **Альтернативы:** полностью заменить `is_resource_actions_inline` флагом из DataStore.
- **Почему:** обратная совместимость и сохранение автоматического поведения (tablet/landscape inline) при выключённой настройке; минимальная область изменений.

**ADR-2: Операция «обновить» в адаптере**

- **Решение:** callback от адаптера к ViewModel, аналогично `onDeleteClick` / `onEditClick`; ViewModel инициирует асинхронный тест+подсчёт и пушит результат в UI-состояние.
- **Альтернативы:** вызов Use Case непосредственно из адаптера.
- **Почему:** соблюдение Clean MVVM — адаптер не имеет прямого доступа к Use Cases; ViewModel остаётся единственной точкой координации.

## 11. Критерии готовности (strategic-level)

1. В настройках интерфейса присутствует переключатель «Операции с ресурсами показывать в меню»; по умолчанию выключен.
2. При включённом переключателе на каждой планке ресурса (список и сетка, портрет и ландшафт) видна только кнопка «⋮»; инлайн-кнопки не отображаются.
3. Выпадающее меню содержит пункты: редактировать, скопировать ресурс (скрыт для виртуальных путей), обновить, переместить вверх, переместить вниз, удалить.
4. Нажатие «Обновить» запускает проверку доступности ресурса и обновляет его статус на планке без перехода на другой экран.
5. При выключённом переключателе поведение планок идентично текущему (инлайн на ландшафте/планшете, overflow на портретном телефоне).
6. Все строки локализованы на EN/RU/UK.
