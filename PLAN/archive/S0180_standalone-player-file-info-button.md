## 1. Проблема

Standalone-плеер (активируется при открытии медиафайла из внешнего приложения) не предоставляет пользователю доступ к метаданным файла. В нормальном плеере эта функция реализована через кнопку «О файле» в портрете и в ландшафте. Пользователь, открывший файл «снаружи», не может узнать путь, размер, MIME-тип и дату изменения — разрыв в функциональном паритете между режимами плеера.

---

## 2. Цели

1. Пользователь видит действие «О файле» в standalone-плеере в портрете — аналогично нормальному плееру.
2. Пользователь видит действие «О файле» в standalone-плеере в ландшафте — через тот же механизм, что нормальный плеер использует для данной ориентации.
3. Нажатие открывает диалог с корректными метаданными для любого типа медиа, поддерживаемого standalone-плеером (видео, аудио, изображения, документы).
4. Кнопка присутствует во всех сборках (все флейворы).

**Non-goals:**

- Изменение поведения нормального плеера.
- Добавление функции загрузки (standalone работает только с локальными файлами).
- Изменение структуры и содержимого диалога метаданных.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Поведение максимально идентично нормальному плееру — без дополнительной кастомизации под standalone-контекст.

### 3.2 Жёсткие ограничения

- **Flavor:** все (standard, lite, photos, legacy).
- **API level:** minSdk 23 (legacy) — minSdk 26 (остальные).
- **Wear OS:** не затрагивается.
- **Производительность:** нет дополнительного I/O при открытии кнопки — метаданные берутся из уже загруженного объекта файла.
- **Совместимость данных:** миграция БД не требуется.
- **Локализация:** строки «О файле» и ключи диалога уже присутствуют в EN/RU/UK; новых ключей не ожидается.
- **Доступность:** кнопка должна иметь content description, аналогичное нормальному плееру.

---

## 4. Контекст текущей архитектуры

Standalone-плеер — отдельный экран, принимающий `Intent.ACTION_VIEW` от внешних приложений. Он имеет собственный набор helper-менеджеров, которые дублируют часть функциональности нормального плеера: файловые операции (удаление, переименование, шаринг, «Открыть в FMS»), управление воспроизведением и отображением. Диалог метаданных файла и вся инфраструктура его запуска уже реализованы в виде самостоятельных dialog-компонентов, но standalone-плеер к ним не подключён — ни на уровне UI, ни на уровне обработчика файловых операций.

Портретный layout нормального плеера содержит кнопку «О файле»; в ландшафте тот же id в layout отсутствует, что означает иной механизм подачи действия (overflow-меню или toolbar) — уточняется в §6.

---

## 5. Предлагаемый подход

Действие «О файле» в standalone-плеере запускается через тот же dialog-компонент, что и в нормальном плеере, без дублирования логики. Обработчик файловых операций standalone-плеера расширяется новым обработчиком события «показать метаданные», который берёт объект файла из уже загруженного состояния ViewModel и передаёт его в существующий dialog-слой. Параметр загрузки (для сетевых файлов) передаётся как null — standalone всегда работает с локальными источниками.

### 5.1 Основные столпы

**Блок A — Обработчик события**
- Standalone-обработчик файловых операций получает новое действие «О файле».
- Данные файла берутся из резолвленного state ViewModel — без дополнительных запросов к хранилищу.
- Компонент запуска диалога получает объект файла; download-параметр передаётся null.

**Блок B — Портрет**
- Кнопка в портретном layout standalone-плеера подключается к новому обработчику.
- Если standalone-плеер использует тот же layout, что нормальный — переиспользуется существующий view id.
- Если отдельный layout — кнопка добавляется туда, с зеркальным добавлением в landscape-вариант (§6, вопрос 2).

**Блок C — Ландшафт**
- Реализуется тот же механизм, что использует нормальный плеер для ландшафта (overflow-меню, toolbar или иной control-surface).
- Конкретный механизм фиксируется в тактической спеке после уточнения §6, вопрос 1.

### 5.2 Потоки данных

UI (кнопка / пункт меню) → обработчик файловых операций standalone → dialog-запускатель (существующий) → диалог метаданных (существующий).

### 5.3 Точки расширяемости

Если в будущем standalone-плеер получит доступ к сетевым источникам — достаточно подать ненулевой download-параметр в компонент запуска диалога; dialog-слой этого уже поддерживает.

## 6. Открытые вопросы / Research items

1. **Механизм ландшафта в нормальном плеере**
   - **Вопрос:** каким образом действие «О файле» доступно в нормальном плеере в ландшафте — через overflow-меню, дополнительный toolbar, или оно там тоже отсутствует?
   - **Нужно выяснить:** прочитать Activity нормального плеера и landscape-layout; найти точку подключения кнопки «О файле» или аналогичного overflow-item.
   - **Статус:** Open

2. **Layout standalone-плеера**
   - **Вопрос:** standalone-плеер использует тот же `activity_player_unified` (portrait/landscape), что нормальный, или свой отдельный layout?
   - **Нужно выяснить:** прочитать `setContentView` в Activity standalone-плеера.
   - **Статус:** Open

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |

| Standalone-плеер использует отдельный layout без view-id кнопки — потребуется добавить кнопку и landscape-копию | Средняя | Дополнительный XML-редит | Уточняется в тактической фазе (§6, вопрос 2) |

## 11. Критерии готовности (strategic-level)

1. Пользователь нажимает «О файле» в standalone-плеере (portrait) — открывается диалог метаданных с корректными данными файла.
2. Пользователь нажимает «О файле» в standalone-плеере (landscape) — действие доступно тем же способом, что в нормальном плеере.
3. Кнопка недоступна (disabled или скрыта) до момента, когда файл загружен в плеере.
4. Функция работает для всех типов медиа: видео, аудио, изображения, документы.
5. Функция работает на всех флейворах и на API 23+.
