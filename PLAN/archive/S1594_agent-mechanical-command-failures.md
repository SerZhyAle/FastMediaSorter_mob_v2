## 1. Проблема

За измеренную неделю агент потратил около 562 турнов на команды и вызовы, которые не могли дать результата: 181 раз `exit 127` (команда отсутствует в этой системе) и 381 блокировку хука `guard-uncapped-read`, треть которых модель тут же обходит чтением файла целиком. Область - агентская инфраструктура (хуки Claude Code, PATH рабочей станции, правила репозитория), исходники приложения не затрагиваются.

## 2. Цели

1. Вызов `python3` перестаёт падать: интерпретатор доступен под тем именем, под которым его зовут.
2. Командлеты PowerShell, отправленные в Bash-инструмент, отклоняются до запуска с указанием правильного канала, вместо `exit 127` без объяснения.

5. Файлы, которые по своей природе читаются целиком (драйверы команд, шаблоны, навыки), перестают блокироваться вовсе.

## 4. Контекст текущей архитектуры

Механическое принуждение агента в этом репозитории делится на два слоя. Гейты `assert-*` живут в репозитории, версионируются вместе с ним и вызываются фасадом закрытия. Хуки Claude Code живут в домашнем каталоге рабочей станции, регистрируются в её настройках и срабатывают до запуска инструмента - именно они способны отменить вызов, который иначе стоил бы турн. Этот тикет целиком принадлежит второму слою: три из четырёх уже существующих хуков-стражей построены по одной форме, и она же годится для нового.

Решить проблему из §1 правилами нельзя, и это измерено, а не предположено: то же требование про командлеты PowerShell уже записано в §7 правил репозитория, а совет читать файл окном приходит модели в схеме инструмента каждый ход - соблюдение 22%. Аудит 2026-07-31 разделил правила на гейтированные (около 99%) и негейтированные (1-8%); оба этих правила сидят во второй группе. Второе ограничение слоя - хук не умеет ни переписать результат инструмента, ни починить и перезапустить упавшую команду, поэтому лечение возможно только до вызова: сдвигом PATH либо переписыванием входа.

## 5. Предлагаемый подход

Три независимых механизма, каждый закрывает свой класс отказов и не знает об остальных. Общий принцип: перехват до вызова, потому что после вызова харнесс уже ничего не может.

### 5.1 Основные столпы / модули

**Столп A - разрешение имени интерпретатора.** Класс `python3` лечится не запретом, а доступностью: каталог пользовательских шимов уже стоит в PATH и уже содержит один такой шим-переадресатор. Требование: вызов под ожидаемым именем доходит до реального интерпретатора, аргументы и код возврата проходят насквозь.

**Столп B - предкол-страж чужого синтаксиса.** Отклоняет до запуска два вида голов команды: командлет PowerShell, оказавшийся головой сегмента Bash-конвейера, и интерпретатор, которого в системе нет. Требования: разбор сегментов учитывает кавычки и тела heredoc, чтобы упоминание имени внутри строки не считалось головой; отказ называет замену, а не только запрет; ошибка разбора означает пропуск.

**Столп C - переписывающий страж чтения.** Заменяет отказ на подстановку окна. Два поведения вместо одного: каталоги агентской инфраструктуры, которые по природе читаются целиком, пропускаются без изменений; всё остальное получает окно, подставленное хуком. Требования: подстановка сопровождается сообщением модели с реальным размером файла, но только когда окно действительно отсекло содержимое; отсутствие сообщения при полном чтении обязательно, иначе предупреждение обесценивается.

### 5.2 Потоки данных и событий

- Вызов Bash -> предфильтр по признаку в полезной нагрузке -> страж B -> отказ с подсказкой либо пропуск.
- Вызов Read без окна -> предфильтр -> страж C -> либо пропуск как есть, либо переписанный вход плюс сопроводительное сообщение -> инструмент.
- Вызов интерпретатора по имени -> PATH -> шим A -> реальный интерпретатор.

### 5.3 Точки расширяемости

- Список отсутствующих в системе интерпретаторов и список командлетов - данные, а не логика: пополнение не требует переписывания разбора.
- Список каталогов-исключений стража C задаётся отдельно от порога и от размера окна.
- Форма отказа стража B совпадает с уже существующим стражем того же слоя, поэтому следующий класс отказов добавляется копированием формы.

## 9. Архитектурные решения (ADR)

**ADR-1: `python3` лечится шимом в PATH, а не запретом**

- **Решение:** сделать имя разрешимым, а не отклонять вызов.
- **Альтернативы:** страж, отклоняющий `python3` с подсказкой звать `python`.
- **Почему:** отказ стоит ровно тот же турн, что и `exit 127`, и не устраняет причину. Шим стоит ноль турнов и закрывает класс целиком - 91 отказ из 181. Каталог шимов уже в PATH и уже содержит рабочий прецедент.

**ADR-2: командлеты PowerShell и отсутствующие интерпретаторы лечатся отказом, а не подменой**

- **Решение:** отклонять до вызова с указанием правильного канала.
- **Альтернативы:** переписывать вход Bash-инструмента в эквивалентный вызов через интерпретатор.
- **Почему:** эквивалентного перевода конвейера Bash в конвейер PowerShell в общем случае не существует, и молчаливая подмена команды намного опаснее отказа. Отказ не экономит турн, но выдаёт замену, чем гасит повторные попытки того же класса.

**ADR-3: страж чтения переписывает вход, а не отказывает**

- **Решение:** подставлять окно и сообщать об этом.
- **Альтернативы:** оставить отказ, ограничившись расширением списка исключений.
- **Почему:** отказ стоит турн и в 31,8% случаев не даёт экономии - модель повторяет чтение целиком. Подстановка сохраняет экономию контекста и обнуляет стоимость в турнах. Возможность подтверждена экспериментом, а не документацией.

**ADR-4: каталоги агентской инфраструктуры исключаются целиком**

- **Решение:** драйверы команд, шаблоны, навыки и справочники читаются без вмешательства.
- **Альтернативы:** подставлять им окно наравне со всеми.
- **Почему:** это файлы, которые бессмысленно читать частично - пропущенный кусок драйвера означает пропущенный шаг процедуры. Самый блокируемый файл недели относится именно к этому классу.

## 11. Критерии готовности (strategic-level)

1. Вызов `python3` с аргументами отрабатывает и возвращает код возврата реального интерпретатора.
2. Командлет PowerShell в позиции головы Bash-команды отклоняется до запуска, и текст отказа называет правильный канал.
3. Упоминание имени командлета внутри кавычек или тела heredoc не отклоняется.
4. Вызов отсутствующего в системе интерпретатора отклоняется с указанием, что его здесь нет.
5. Чтение файла длиннее порога без окна возвращает содержимое, а не отказ.
6. Такое чтение сопровождается сообщением с реальным числом строк, когда содержимое отсечено, и не сопровождается им, когда не отсечено.
7. Чтение файла из каталога агентской инфраструктуры возвращает файл целиком без вмешательства.
8. Любая ошибка внутри любого из двух хуков приводит к пропуску вызова, а не к его порче.
9. Правило про командлеты PowerShell записано в правилах репозитория со ссылкой на гейт, и синхронизировано в параллельный набор правил.
10. Тестовые наборы обоих хуков лежат в репозитории и проходят.
