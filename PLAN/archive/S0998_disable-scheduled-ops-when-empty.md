## 0. Захваченный материал (inbox)

**Захвачено:** 2026-07-11

**Текст:**

если список запланированных операций пуст, выключать опцию "Использовать операции по-расписанию"

---

## 1. Проблема

- Опция «Использовать операции по-расписанию» остаётся включённой даже когда список запланированных операций пуст - бесполезно активная настройка без единой операции.
- Пользователь видит включённый режим, за которым ничего не стоит; возможно, зря удерживается фоновое планирование.

---

## 2. Цели

1. На экране настроек Operations опция «Использовать операции по-расписанию» сверяется с состоянием списка: пустой список -> снять галочку (off), непустой -> авто-включить (on).

**Non-goals:**

- App-wide/фоновое выключение вне экрана настроек - осознанно не делаем (решение владельца: только экран настроек).
- Дизейбл/скрытие самого тоггла - только снятие/установка галочки.
- Изменение самого планировщика / воркера исполнения операций.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Опция не должна оставаться «висеть» включённой при пустом списке.

### 3.2 Жёсткие ограничения

- **Flavor:** варианты, где scheduled-операции включены (группа скрыта там, где флейвор их отключает).
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Совместимость данных:** меняется только существующий boolean-настройки, без миграции.
- **Локализация:** новых строк не вводится.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** none (подсистема scheduled-операций: `ScheduledOperationsWorker`, `ScheduledOperationsViewModel`, `OperationsScheduledManager`).

---

## 4. Контекст текущей архитектуры

- Настройка «Использовать операции по-расписанию» - boolean в `AppSettings`, тоггл в группе Scheduled экрана Operations (`OperationsSettingsFragment`), делегирован помощнику `OperationsScheduledManager`.
- Список операций - `ScheduledOperationsViewModel` (Room-backed).
- Операции удаляются не только из настроек: также из виджета (`ScheduledTasksWidgetProvider`) и могут сниматься/истекать через `ScheduledOperationsWorker` в фоне. Поэтому «где именно ловить опустошение» - не единственная точка.

---

## 5. Предлагаемый подход

- На экране настроек Operations (`OperationsScheduledManager`, при setup/render) сверять тоггл с состоянием списка `ScheduledOperationsViewModel`: пустой -> снять галочку (off), непустой -> авто-включить (on). Идемпотентно (писать настройку только при реальном изменении, иначе петля render -> write -> render).
- Область - только экран настроек (решение владельца): без долгоживущего app-wide наблюдателя и без молчаливых фоновых записей. Удаление из виджета/воркера отразится при следующем открытии настроек.
- Тоггл остаётся интерактивным (снятие/установка галочки, не disable).

---

## 6. Открытые вопросы / Research items

Все три owner-решения приняты (Quiz decisions ниже) - блокеров перехода Draft -> Approved нет.

1. **Область срабатывания - RESOLVED:** только экран настроек (сверка при setup/render экрана Operations). Без app-wide наблюдателя и молчаливых фоновых записей.
2. **Обратное включение - RESOLVED:** авто-включение при непустом списке. Тоггл выводится из состояния списка на экране настроек (пусто -> off, непусто -> on).
3. **«Выключать опцию» - RESOLVED:** снять галочку (значение `false`), тоггл остаётся интерактивным; контрол не дизейблится.

### Quiz decisions (2026-07-11)

- Область срабатывания -> Только экран настроек (сверка при рендере Operations; без фоновых записей / app-wide наблюдателя; опция «висит» до следующего открытия настроек - принятый компромисс).
- Обратное включение -> Авто-включение (тоггл reconcile'ится к списку: пусто -> off, непусто -> on; перестаёт быть независимым master-переключателем).
- «Выключать опцию» -> Снять галочку (value=false, тоггл интерактивен, без disable контрола).

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Петля render -> write -> render (реконсиляция на рендере) | Низкая | лишние записи / мерцание | писать настройку только при реальном изменении (idempotent) |
| Опция «висит» включённой вне экрана настроек (settings-local) | Низкая | не отражает пустой список до открытия настроек | принятый компромисс (owner: только экран настроек) |

## 9. Архитектурные решения (ADR)

- **ADR-1: сверка на экране настроек, не app-wide и не хук в каждой точке удаления (owner decision).** Тоггл reconcile'ится к списку при setup/render Operations - просто, без фоновых записей; цена - опция «висит» до следующего открытия настроек (владелец счёл приемлемым).

## 11. Критерии готовности (strategic-level)

1. На экране настроек Operations: пустой список -> галочка снята (off); непустой -> галочка авто-включена (on).
2. Реконсиляция идемпотентна (нет петли записи); тоггл остаётся интерактивным.
3. Вне экрана настроек (виджет/воркер) опция не трогается - отражается при следующем открытии настроек.
