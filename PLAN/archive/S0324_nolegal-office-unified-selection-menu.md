## 1. Проблема

Во встроенном Office-просмотрщике (только noLegal, HTML в WebView) нативное выделение текста и системная кнопка «Копировать» уже работают. Но дополнительные действия над выделением (Перевести, Поиск в Google), которые есть в EPUB и текстовом режиме PDF, в Office недоступны: activity-level аугментация `startActionMode` сейчас распознаёт только EPUB, а Office-WebView вдобавок открыт с выключенным JavaScript, из-за чего синхронно прочитать выделенный текст для этих действий нельзя.

---

## 2. Цели

1. В Office-просмотрщике (noLegal) плавающее меню выделения содержит те же действия, что и EPUB: системное «Копировать» + «Перевести» (при `ENABLE_TRANSLATION`) + «Поиск в Google».
2. Поведение и внешний вид меню единообразны с EPUB.

**Non-goals:**

- Любые изменения в рыночных flavors (там Office - внешний хэндофф).
- Изменение самого рендера Office.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Не ослаблять безопасность: JS включать только для локально сгенерированного приложением Office-HTML, не для произвольного веб-контента.

### 3.2 Жёсткие ограничения

- **Flavor:** только `noLegal`. Реализация по `dev/FLAVOR_DEVELOPMENT_RULES.md`: flavor-нейтральный сейзм в `src/main/`, реальная реализация в `src/noLegal/`, привязка через noLegal Hilt-модуль. Никаких `BuildConfig.IS_*` в `src/main`.
- **Безопасность:** включение JavaScript в Office-WebView допустимо только для app-generated контента; оценить риски.
- **Локализация:** действия меню уже локализованы (переиспользуются из общего контракта).

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** noLegal only.
- **Related tickets:** S0323 (родительская фича выделения; ядро Office - нативное Copy - уже работает после S0323).

---

## 4. Контекст текущей архитектуры

Activity-level `startActionMode` в общем коде оборачивает системный callback в аугментированный только при активном EPUB-WebView (флаг доступности EPUB + его callback читают выделение через JS-bridge). Office-просмотрщик существует лишь в noLegal и открывается с выключенным JS; флавор-нейтрального хука для его аугментации нет.

---

## 5. Предлагаемый подход

Ввести flavor-нейтральный сейзм «провайдер аугментации выделения Office»: интерфейс в общем коде с No-Op реализацией по умолчанию, реальная реализация в noLegal. Activity при `TYPE_FLOATING` консультируется с EPUB-веткой (как сейчас) и с Office-провайдером. Для чтения выделения в Office-WebView - включить JS только для app-generated Office-HTML и добавить мостик выделения, аналогичный EPUB.

### 5.1 Основные столпы / модули

- Flavor-нейтральный сейзм провайдера аугментации (main: интерфейс + No-Op).
- noLegal: реальный провайдер + JS-мостик выделения в Office-WebView + Hilt-привязка.

### 5.2 Потоки данных и событий

Выделение в Office-WebView → JS-мостик отдаёт выделенный текст → activity-аугментация добавляет действия → действие → результат.

### 5.3 Точки расширяемости

Сейзм провайдера аугментации - общий механизм, EPUB и Office идут через один путь.

---

## 6. Открытые вопросы / Research items

1. **Безопасность JS в Office-WebView**
   - **Вопрос:** допустимо ли включить JS для app-generated Office-HTML и какие риски (инъекции из содержимого документа)?
   - **Нужно выяснить:** изоляция/санитизация HTML, ограничение JS-интерфейса.
   - **Статус:** Resolved - Office HTML is generated by the app, document text is escaped before insertion, active-content links stay blocked, `allowFileAccess` and `allowContentAccess` remain disabled, and the JavaScript bridge exposes only selected-text capture.

---

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Включение JS в Office-WebView расширяет поверхность атаки | Средняя | Потенциальная инъекция из содержимого документа | JS только для app-generated HTML, минимальный JS-интерфейс, ревью безопасности |
| Регресс существующего нативного Copy в Office | Низкая | Потеря рабочего поведения | Сохранить системные пункты, аугментация только добавляет |
