## 1. Проблема

В портретной раскладке диалога управления видео кнопки слайдер-секций (например, пресеты скорости 0.5x / 1.5x / 2x) лежат горизонтальным рядом и не помещаются по ширине - крайняя кнопка обрезается у правого края. Вертикальный бегунок занимает всю ширину сверху, оставляя кнопкам мало места. Пользователь не может нажать обрезанную кнопку. Область: диалог управления воспроизведением (портретная раскладка).

---

## 2. Цели

1. В портретной раскладке слайдер-секции организованы в две внутренние колонки: кнопки стопкой в одной колонке, вертикальный бегунок - в другой, всегда крайней (под палец).
2. Вместе с существующим столбцом разделов это даёт три визуальные колонки: разделы | кнопки | бегунок.
3. Единый приём применён ко всем слайдер-секциям портрета (Громкость, Скорость, Яркость, Цвет) для консистентности.
4. Кнопки больше не обрезаются - они стопкой и не переполняют ширину.

**Non-goals:**

- Ландшафтная раскладка: там бегунок горизонтальный, кнопки в ряду помещаются (широкий экран), переполнения нет - структурно не меняется.
- Секции без бегунка (Аудио, Субтитры, 3D) - не затрагиваются.
- Логика/поведение контролов - не меняется (только раскладка).

## 4. Контекст текущей архитектуры

Диалог управления использует один набор ID для портретной и ландшафтной раскладок (ViewBinding генерируется из `layout/`). Портретная раскладка - вертикальный рельс разделов слева + контент справа; каждая слайдер-секция - вертикальный стек `подпись / вертикальный бегунок (во всю ширину) / кнопки`. Кнопки скорости лежат горизонтальным рядом и переполняют ширину. Проблему §1 нельзя закрыть без перекомпоновки внутренней раскладки секции: горизонтальный ряд кнопок принципиально переполняется на узком экране.

## 5. Предлагаемый подход

Внутри каждой слайдер-секции портрета заменить вертикальный стек на: подпись сверху, ниже - горизонтальный контейнер из двух колонок: колонка кнопок (вертикальный стек, вес заполняет остаток) и колонка вертикального бегунка фиксированной ширины у внешнего (правого) края. ID всех вью сохраняются, поэтому код-биндинг не меняется. Ландшафт не трогаем (бегунок горизонтальный, переполнения нет).
