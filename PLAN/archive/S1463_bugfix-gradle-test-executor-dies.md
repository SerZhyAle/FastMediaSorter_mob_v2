## 0. Захваченный материал (inbox)

**Захвачено:** 2026-08-07

**Захвачено во время:** S1433 (шаг 01.4, предикат `.\a.ps1 fu`)

**Текст:**

Юнит-тесты невозможно запустить: gradle test executor умирает сразу. Любой прогон `scripts/builders/check-standard-fast.ps1 -Mode Unit` - и полный, и с фильтром `-Tests "*PermissionRegistryRepositoryImplTest*"` - падает за 9-12 секунд с `Process 'Gradle Test Executor NN' finished with non-zero exit value 10`, которому предшествует `org.gradle.internal.remote.internal.MessageIOException: Could not write '/127.0.0.1:PORT'. Caused by: java.io.IOException: Connection reset by peer`. Воспроизведено 3 раза подряд 2026-08-07 (executors 38, 48, 58). Полный `.\a.ps1 fu` в том же окне отработал иначе: worker умер посреди прогона, `418 tests completed, 68 failed`, и `assert-test-suite-complete` справедливо объявил это провалом прогона, а не результатом. При этом gradle сам по себе исправен: в том же окне `-Mode Code -Flavor Lite` дал BUILD SUCCESSFUL за 1m14s, и полная отладочная сборка `dq` тоже прошла. То есть ломается именно тестовый worker, а не компиляция. Отдельно замечено: `PermissionRegistryManifestParityTest` под `standard` даёт `tests=1 skipped=1` - то есть на этом варианте он не проверяет ничего, а его собственный KDoc просит гонять его на вариантах, где композиция отличается. Почему это дорого: `.\a.ps1 fu` - закрывающий предикат множества тактических планов, и недоказуемый юнит-набор превращает каждый такой предикат в необоснованную отметку. Не дубликат S1449 (там детерминированные падения четырёх DataStore-классов по `Unable to rename .preferences_pb.tmp`, worker при этом живёт).

---

## 1. Проблема / симптом

Тестовый worker JVM не доживает до прогона. Наблюдалось 2026-08-07 на `standard` при трёх подряд запусках с разными фильтрами:

```text
org.gradle.internal.remote.internal.MessageIOException: Could not write '/127.0.0.1:56283'.
Caused by: java.io.IOException: Connection reset by peer
> Task :app_v2:testStandardDebugUnitTest FAILED
   > Process 'Gradle Test Executor 48' finished with non-zero exit value 10
BUILD FAILED in 9s
```

Полный прогон `.\a.ps1 fu` в том же окне дал другую форму того же отказа - worker умер посреди набора:

```text
418 tests completed, 68 failed, 5 skipped
assert-test-suite-complete: a Gradle "<N> tests completed" line is printed even when the worker JVM dies mid-run
Fast check failed - the unit run did not cover the whole suite.
```

Компиляция при этом здорова: `-Mode Code -Flavor Lite` -> BUILD SUCCESSFUL за 1m14s, `.\a.ps1 dq` -> BUILD SUCCESSFUL за 2m19s, оба в том же окне.

Побочное наблюдение, требующее собственного решения: `PermissionRegistryManifestParityTest` под `standard` отдаёт `tests=1 skipped=1`, то есть на этом варианте не проверяет ничего.

**Что здесь дефект, а что среда.** Смерть воркера нагрузочно-зависима и на тихом хосте не воспроизводится - см. §2. Дефектом этого тикета является не сама смерть, а то, во что она превращается в выводе: прогон, который не дал результата, отчитывается тем же кодом возврата, что и прогон, нашедший красный тест.

## 2. Корневая причина

### 2.1 Прежний диагноз сюда не переносится

Подпись (`exit value 10` + `Connection reset by peer`) буква в букву совпадает с S1253, где причиной было исчерпание фиксируемой памяти хоста, а лечением - `forkEvery = 100`. Сегодняшние отказы устроены иначе, и это установлено измерением, а не рассуждением - по логам демонов Gradle за 2026-08-07:

- `OutOfMemoryError` - **0** вхождений;
- сообщений менеджера памяти демона (`.. virtual memory requested, .. free`) - **0**;
- файлов `hs_err_pid*.log` в дереве - **0**, то есть нативного падения JVM не было.

Все три признака, на которых держался диагноз S1253, отсутствуют. Значит, совпадение подписи не означает совпадения механизма, и `maxHeapSize`/`forkEvery` трогать не за что.

### 2.2 Где именно умирает воркер

Все **8** событий смерти за 2026-08-07 (`daemon-30316`, `daemon-27216`, `daemon-12936`) несут в стеке один и тот же кадр:

```text
at org.gradle.api.internal.tasks.testing.processors.RestartEveryNTestDefinitionProcessor.endBatch(RestartEveryNTestDefinitionProcessor.java:77)
at org.gradle.api.internal.tasks.testing.worker.ForkingTestDefinitionProcessor.stop(ForkingTestDefinitionProcessor.java:157)
at org.gradle.process.internal.worker.DefaultWorkerProcess.waitForStop(DefaultWorkerProcess.java:230)
at org.gradle.process.internal.DefaultExecHandle$ExecResultImpl.assertNormalExitValue(DefaultExecHandle.java:459)
```

`RestartEveryNTestDefinitionProcessor` есть в цепочке только потому, что включён `forkEvery`. Смерть регистрируется на **остановке** воркера, а не во время тестов - поэтому она бывает и на фильтре в один класс, где накапливать нечего, и поэтому отчёт теста при этом остаётся зелёным (`failures="0"`, ровно как в [S1464]).

Это же объясняет, почему исправление S1253 не устранило отказ, а перераспределило его: `forkEvery = 100` умножает число стартов и остановок JVM за прогон, а отказ живёт именно на остановке.

### 2.3 Общий каталог TMP течёт без границы

`gradlew.bat:39-41` перенаправляет `TMP` и `TEMP` **каждого** процесса сборки в один общий `temp/gradle-tmp`. Его никто не чистит. Замер 2026-08-07:

- 3001 запись, из них 746 нативных библиотек `sqlite-*-sqlitejdbc.dll` общим весом **328 МБ**;
- 407 копий `conscrypt_openjdk_jni-windows-x86_64.dll`;
- 335 boot-архивов `mockk_boot*.jar`, из них **58 за один сегодняшний день**.

Каждый старт тестовой JVM распаковывает туда свежий комплект и не убирает за собой; `forkEvery` умножает число стартов. `mockk_boot*.jar` дописывается в bootstrap classpath - отсюда предупреждение `Sharing is only supported for boot loader classes because bootstrap classpath has been appended` непосредственно перед каждым отказом, а в более ранних логах демонов (`daemon-18836`, `daemon-6692`, `daemon-72568`) тот же путь виден в развёрнутом виде: `*** java.lang.instrument ASSERTION FAILED ***: "!errorOutstanding" .. JPLISAgent.c line: 838` - смерть JVM внутри нативного агента инструментации, которая и переносит код возврата 10 без единой Java-строки.

**Границы утверждения.** Связь «распухший общий TMP -> смерть агента» подтверждена совпадением места (агент инструментации), носителя кода 10 и нагрузочной зависимости, но **не** доказана экспериментом: отказ не воспроизводится по требованию, и одного зелёного прогона для обратного вывода не хватит - ровно эта ловушка описана в S1253 §4. Поэтому уборка TMP заявляется как снятие задокументированного отягчающего фактора с собственным проверяемым предикатом, а не как доказанное лекарство.

### 2.4 Собственно дефект - подмена вердикта

`scripts/builders/check-standard-fast.ps1` превращает «не смог проверить» в «нашёл дефект» двумя разными путями:

- **С фильтром `-Tests`** (строка 82) проверка полноты пропущена намеренно и обоснованно, но никакой другой не появляется: умерший воркер даёт `$gradleExit = 1`, и строка 96 печатает `Fast check failed` с кодом 1. Отличить это от настоящего красного теста по выводу невозможно.
- **Без фильтра** смерть ловит `assert-test-suite-complete`, и текст верен («did not cover the whole suite»), но код возврата - снова **1**. По контракту S1338 «не смог проверить» - это **2**; единица означает «проверил и нашёл дефект».

Читатель обоих вердиктов идёт искать несуществующий красный тест. Это ровно та подмена, что в [S1462] и [S1464], третий её экземпляр в третьем скрипте.

## 3. Исправление

Две меры. Первая чинит заявленную цену тикета и полностью проверяема; вторая снимает отягчающий фактор из §2.3 и проверяется по своему собственному предикату, а не по исчезновению отказа.

### 3.1 Смерть воркера перестаёт выглядеть красным тестом

В `check-standard-fast.ps1`:

- копить вывод Gradle и после прогона сверять его с подписью смерти воркера (`Process 'Gradle Test Executor N' finished with non-zero exit value`, `Test process encountered an unexpected problem`);
- при совпадении - **один** повтор прогона: отказ нагрузочно-зависимый, повтор на тёплом демоне стоит секунды и в большинстве случаев превращает несостоявшийся прогон в настоящий результат;
- если повтор умер так же - печатать явное «прогон не дал вердикта» с указанием на смерть воркера и выходить с кодом **2**, никогда не 1;
- работает одинаково на фильтрованном и полном прогоне.

`assert-test-suite-complete.ps1` не трогается: в своих терминах его вердикт («прогон усечён») верен и задокументирован. Отображение усечения в «нет вердикта» - дело вызывающего.

### 3.2 Общий TMP перестаёт расти без границы

Новый `scripts/utils/prune-gradle-tmp.ps1`: удаляет из `temp/gradle-tmp` записи известных протекающих образцов старше порога (по умолчанию 24 ч). Порог именно такой, потому что живой прогон не бывает суточной давности - это и есть защита от удаления файлов параллельной сессии, то есть от того, чтобы уборка сама не стала причиной отказа. Неудаляемое (занятый файл) пропускается молча, корень каталога не трогается.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S1449 - другие отказы того же набора (DataStore rename), worker при этом жив; S1453 и S1455 - охват общих тестов по флейворам, к которому примыкает наблюдение о пропущенном тесте паритета; S1253 (Archived) - прежний диагноз той же подписи, опровергнут для этого случая в §2.1; S1462 и S1464 - та же подмена вердикта в других скриптах; S1338 - контракт кодов возврата.

## 4. Проверка

Ни один предикат ниже не опирается на исчезновение нагрузочно-зависимого отказа - каждый проверяет ровно то, что изменено.

- **Подмена вердикта снята.** Стенд `scripts/builders/gradle-run-verdict.tests/Run-Tests.ps1`: подпись смерти воркера опознаётся, а настоящий красный тест и зелёный прогон - нет. Ожидание: два разных вердикта на два разных случая.
- **Повтор срабатывает один раз.** В том же стенде: первый прогон умирает, второй проходит - итог 0 за две попытки; оба умирают - `WorkerDeath` за ровно две попытки; красный тест не повторяется вовсе.
- **Настоящий результат не задет.** `.\a.ps1 fu` на тихом хосте доходит до конца набора, `assert-test-suite-complete` отрабатывает и печатает `ratio 1`, а красный тест по-прежнему даёт код **1**, а не 2 - то есть новая ветка не перехватывает настоящий провал. Код 0 здесь недостижим и предикатом быть не может: в наборе живут два красных теста чужих тикетов ([S1472] - `PermissionRegistryManifestParityTest`, и `IconInventoryExportTest`).
- **Утечка TMP ограничена.** `prune-gradle-tmp.ps1 -MaxAgeHours 24` на текущем каталоге: число записей падает с 3001, при этом ни одна запись моложе порога не удалена (проверяется вторым запуском с `-WhatIf`).
- **Побочное наблюдение о `PermissionRegistryManifestParityTest`** (`tests=1 skipped=1` на `standard`) этим тикетом не закрывается - оно принадлежит [S1472] и охвату по флейворам (S1453/S1455).

## Last Audit

**Date:** 2026-08-07. **Verdict:** Verified.

- Прежний диагноз (S1253) опровергнут для этого случая измерением: за 2026-08-07 в логах демонов ноль `OutOfMemoryError`, ноль сообщений менеджера памяти, ноль `hs_err_pid*.log`. Все 8 событий смерти несут кадр `RestartEveryNTestDefinitionProcessor.endBatch`, то есть отказ живёт на остановке воркера.
- Отказ на тихом хосте не воспроизводится: команда из §0 (`-Tests "*PermissionRegistryRepositoryImplTest*"`) - 9 тестов, 0 падений, 14.6 с. Поэтому фиксируется не смерть, а подмена вердикта.
- `scripts/builders/gradle-run-verdict.tests/Run-Tests.ps1` - **18 из 18 PASS, exit 0**: подпись опознаётся, красный тест и зелёный прогон - нет, повтор ровно один, красный тест не повторяется.
- Регрессия, найденная собственным первым живым прогоном: PowerShell разворачивает одноэлементный массив при привязке, и вывод из одной пустой строки ронял помощника. Исправлено `@()`-обёрткой; три формы вывода (пустая строка, одна строка, `$null`) закрыты случаями стенда.
- `.\a.ps1 fu` после правки: `3217 tests completed, 2 failed`, `assert-test-suite-complete: 449 report(s) for 440 *Test.kt (ratio 1.02) PASS`, итог **1** - красные тесты сохраняют свой код и новой веткой не перехватываются. До правки этот же прогон не доходил до гейта полноты вовсе.
- `prune-gradle-tmp.ps1 -MaxAgeHours 24`: 3007 записей -> 1045, освобождено **1510.7 МБ**, 0 занятых пропущено; предварительный `-WhatIf` показал те же 1962 кандидата и ничего не удалил.
- Границы: связь «распухший TMP -> смерть агента» остаётся неподтверждённой экспериментом (§2.3) и намеренно не является предикатом этого тикета.
