**Ticket:** S1070
**Status:** Archived
**Priority:** 45
**Date:** 2026-07-16
**Tier:** 3 - Medium

---

## 0. Захваченный материал (inbox)

**Захвачено:** 2026-07-16, попутно при закрытии S1063 (`/spec-next` -> `/spec-all`).

**Симптом:**

Скрипты документируют тернарный контракт кодов возврата (0 = ок, 1 = отказ по существу, 2 = кривые аргументы / ошибка конфигурации), но состояние 2 недостижимо. Под `$ErrorActionPreference = 'Stop'` голый `Write-Error` порождает терминирующую ошибку и рвёт скрипт ДО следующего `exit 2`, поэтому наружу всегда уходит 1. Вызывающий не может отличить "гейт нашёл нарушение" от "гейт сам сломан / не настроен".

**Эвиденс (дочерние процессы, 2026-07-16):**

```
preview.ps1     -Id NOT_AN_ID -> exit 1 (contract: 2)
drift-check.ps1 -Id NOT_AN_ID -> exit 1 (contract: 2)
close-and-log.ps1 -Id NOT_AN_ID -> exit 2   # уже починен в S1063, эталон
```

**Охват:** 18 сайтов в 9 файлах (аудит: `Write-Error` без `-ErrorAction`, за которым в пределах 2 строк идёт `exit 2..9`, в файлах с `ErrorActionPreference = 'Stop'`).

- `scripts/all_features/patch.ps1` (1)
- `scripts/quality/assert-allfeatures-sync.ps1` (2)
- `scripts/quality/assert-flavor-flags-not-growing.ps1` (1)
- `scripts/quality/assert-no-ticket-logs.ps1` (1)
- `scripts/quality/generate-toolchain-pins.ps1` (4)
- `scripts/spec_catalog/drift-check.ps1` (2)
- `scripts/spec_catalog/list-blockneedusertest.ps1` (1)
- `scripts/spec_catalog/preview.ps1` (3)
- `scripts/spec_catalog/skip-cache.ps1` (3)

**Почему это не косметика:**

- `assert-flavor-flags-not-growing.ps1:44` отдаёт exit 2 на "baseline file missing" - то есть на собственную поломку. Схлопываясь в 1, она читается вызывающим как "флаговых нарушений стало больше". `post-change.ps1` сообщит о нарушении там, где на деле просто нет baseline-файла: неверная причина отказа.
- `preview.ps1` и `drift-check.ps1` вызываются из `spec-next-preflight.ps1`, то есть с них кормится селектор `/spec-next`.
- Тот же класс уже кусал проект: память `spec-catalog-exit-code-contract` фиксирует, что 2026-05-21 batch `/spec-arc` пропустил dev-log для 72 спек из-за пустого `$LASTEXITCODE`. Тогда починили только мутаторы (`trap { exit 1 }` + явный `exit 0`) - у них контракт бинарный. Скрипты с тернарным контрактом остались.

**Лекарство (проверено в S1063):** `Write-Error $msg -ErrorAction Continue` перед `exit N` - сообщение печатается, скрипт не рвётся, код доходит наружу.

## 0a. Поправки к §0 по итогам расследования (2026-07-16)

§0 писался попутно, на беглом аудите. Расследование подтвердило охват, но **опровергло две из трёх посылок**. Оставляю §0 как есть (это захваченный материал) и фиксирую правду здесь.

**Опровергнуто 1: «Скрипты документируют тернарный контракт».** Не документируют - 7 из 9. Что на самом деле обещают заголовки:

- `drift-check.ps1` - **документирует** `0 / 1 / 2` явным блоком `# Exit codes:`.
- `patch.ps1` - **документирует** «Errors (exit 2) if the id is not found».
- `assert-allfeatures-sync.ps1` - «fails closed (**exit 1**)». Про 2 - молчок.
- `assert-flavor-flags-not-growing.ps1` - «-Gate Exit **1** if current > baseline». Про 2 - молчок.
- `assert-no-ticket-logs.ps1` - «exits **1** when any forbidden occurrence remains». Про 2 - молчок.
- `generate-toolchain-pins.ps1` - «exit **1** on any drift or missing block». Про 2 - молчок.
- `skip-cache.ps1` - «exit 0 if active skip, **1** otherwise». Про 2 - молчок.
- `preview.ps1`, `list-blockneedusertest.ps1` - заголовок про коды **не говорит ничего**.

То есть у семи файлов `exit 2` - не нарушенное обещание, а мёртвый код, противоречащий собственному заголовку.

**Опровергнуто 2: «неверная причина отказа».** Под `EAP=Stop` `Write-Error` успевает записать в поток ошибок до того, как порвёт скрипт. Замер дочерними процессами: в выводе видно `Invalid -Id 'NOT_AN_ID' (must match S####)`, `Baseline file missing: ...` и т.д. **Причина отказа человеку видна и верна; врёт только число.** Утверждение §0, что `post-change.ps1` «сообщит о нарушении там, где просто нет baseline-файла», неверно: post-change печатает и сообщение ребёнка тоже.

**Подтверждено: никто не различает 1 и 2.** Проверены все вызывающие:

- `post-change.ps1` -> `Invoke-Step`: `if ($exitCode -ne 0) { throw }`, в отчёт идёт `"child exit code $exitCode"`. Ветвления нет, число только печатается.
- `assert-fast-gates.ps1`: `$status = ($LASTEXITCODE -eq 0) ? 'PASS' : 'FAIL'` - число ребёнка даже не показывает.
- `spec-next-preflight.ps1`: `$LASTEXITCODE` **не читает вообще**; ветвится по наличию и разбираемости вывода (`if (-not $pvRaw) { $malformed += ... }`), а stderr глушит через `2>$null`.
- `patch.ps1`, `list-blockneedusertest.ps1` - вызывающих в репозитории нет (зовут ad-hoc агенты).

**Что осталось настоящим дефектом - и это не то, что названо в §0:**

- **`drift-check.ps1` - единственный живой ложный сигнал.** Он документирует `1 = drift detected`. Значит опечатка в `-Id` возвращает 1, что по его же контракту читается как «дрейф обнаружен». Именно так его и учит читать `/spec-all` (0a-drift: «Exit 1 (`DRIFT`) = git commits with spec id marker»). Битый ввод неотличим от находки - на контракте, который скрипт сам объявил.
- **`patch.ps1`** - обещает 2, отдаёт 1. Механизм иной: рвёт не сам `Write-Error`, а `trap { Write-Error $_; exit 1 }` на строке 40, который ловит терминирующую ошибку строки 100 и гасит её в 1.
- **Остальные 7** - мёртвый `exit 2` при бинарном заголовке. Сегодня никого не обманывает (кода никто не читает), но это мина: первый же вызывающий, решивший различать 2, тихо получит 1.

**Вывод по приоритету:** живого пользовательского вреда нет ни одного. Тикет остаётся оправданным как приведение кода и документации к согласию плюс защита от повторного отрастания класса (третий случай: S0082-эпоха, S1063, этот). Но 45 - потолок, а не заниженная оценка.

## 1. Проблема

В девяти скриптах код и собственная документация расходятся в том, что означает код возврата. У двух (`drift-check.ps1`, `patch.ps1`) заголовок обещает `exit 2`, а код всегда отдаёт 1: `Write-Error` под `$ErrorActionPreference = 'Stop'` рвёт скрипт до `exit 2`. У остальных семи заголовок обещает бинарный контракт, но в теле стоит `exit 2`, который никогда не исполняется.

Единственный живой ложный сигнал - `drift-check.ps1`: он документирует `1 = дрейф обнаружен`, поэтому кривой `-Id` возвращает 1 и читается как находка.

---

## 2. Цели

1. Для каждого из девяти скриптов код возврата и заголовок утверждают одно и то же.
2. `drift-check.ps1` отличает «кривой ввод» от «дрейф найден».
3. Класс не отрастает: механический гейт ловит `Write-Error` без `-ErrorAction`, за которым следует `exit N` (N != 1), в файле с `EAP = Stop`.

**Non-goals:**

- Не заводить новых потребителей кода 2. Никто сегодня 1 и 2 не различает; задача - чтобы контракт не врал, а не чтобы кто-то начал на него опираться.
- Не трогать `trap { ... exit 1 }` как механизм: для неожиданного исключения 1 - правильный ответ.
- Не переписывать `Invoke-Step` / `assert-fast-gates.ps1`: схлопывание в PASS/FAIL - их осознанный контракт.

## 4. Контекст текущей архитектуры

Скрипты репозитория делятся по контракту на два вида. Мутаторы (`insert.ps1`, `update.ps1`, `close.ps1`) после инцидента 2026-05-21 приведены к бинарному виду `trap { exit 1 }` + явный `exit 0`. Гейты и запросы задумывались тернарными: 0 - чисто, 1 - нашли по существу, 2 - сам инструмент не может работать.

Тернарность не состоялась. Все девять файлов ставят `$ErrorActionPreference = 'Stop'` в шапке, а под ним `Write-Error` - терминирующая ошибка: строка `exit 2` следующей уже не исполняется. Заголовки при этом разошлись в разные стороны: два обещают 2, семь обещают бинарность, но код везде одинаковый.

Потребители к тернарности не приспособлены и не пытались: `post-change.ps1` бросает на любом ненулевом, `assert-fast-gates.ps1` схлопывает в PASS/FAIL, `spec-next-preflight.ps1` код вообще не читает. Поэтому расхождение и прожило незамеченным.

## 5. Предлагаемый подход

Привести код к тому, что обещает заголовок, - по каждому скрипту отдельно; там, где заголовок молчит, выбрать контракт по смыслу и записать его. Затем закрыть класс механическим гейтом.

### 5.1 Основные столпы / модули

- Девять скриптов - точечная правка `Write-Error` + выравнивание заголовка.
- Новый `scripts/quality/assert-exit-contract.ps1` - гейт против отрастания.
- `scripts/quality/assert-exit-contract.tests/Run-Tests.ps1` - по конвенции проекта (`scripts/<subject>.tests/Run-Tests.ps1`, `Set-StrictMode -Version Latest`, exit 0/1).

### 5.2 Потоки данных и событий

Дочерний процесс с кривым аргументом -> `Write-Error ... -ErrorAction Continue` печатает причину -> `exit 2` доходит наружу. Успешный путь и отказ по существу не меняются: 0 и 1 как были.

### 5.3 Точки расширяемости

Гейт ищет структурную связку, а не список файлов, поэтому новый скрипт с той же ошибкой ловится без правки гейта.

## 9. Архитектурные решения (ADR)

- **ADR-1: приводить код к заголовку, а не наоборот по всему списку.** Заголовок - это уже принятое кем-то решение о контракте. Там, где он обещает 2, обещание надо выполнить; там, где молчит, - выбрать и записать.
- **ADR-2: у гейтов тернарность оставить.** «Гейт нашёл нарушение» и «гейт сам сломан» - разные события, даже если сегодня никто их не различает. Стоимость - одна строка на сайт; альтернатива (снести `exit 2`) теряет различение навсегда.
- **ADR-3: гейт вместо только правки.** Третье повторение класса (S0082-эпоха, S1063, этот). CLAUDE.md Rule 19/20: повторяющаяся находка -> механический гейт.
