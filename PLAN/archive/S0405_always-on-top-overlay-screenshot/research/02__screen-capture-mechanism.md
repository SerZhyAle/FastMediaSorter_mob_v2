# 02 - Механизм захвата экрана: MediaProjection vs AccessibilityService.takeScreenshot

**Research item:** §6.2
**Дата:** 2026-06-11
**Статус:** Resolved (предварительно); финальный выбор - решение владельца с учётом §6.4 (Play policy)

## Вопрос

Чем снимать текущий экран вне собственных окон приложения и какой ценой.

## Вариант А - MediaProjection

- Токен на захват дисплея выдаётся системным сервисом `MediaProjectionManager` после явного посессионного согласия пользователя.
- Сопровождается системными диалогами и индикатором записи экрана - пользователь всегда видит, что идёт захват.
- Доступен с API 21+ (то есть на всём нашем диапазоне, включая legacy).
- Минус UX: индикатор/согласие на каждой новой сессии; нужно оценить переиспользование одной сессии под флагман-сценарий «касание хэндла → снимок».

## Вариант Б - AccessibilityService.takeScreenshot (API 30+)

- С Android 11 (API 30) `AccessibilityService` получил `takeScreenshot()` - снимок прямо из hardware buffer.
- Полностью тихий: нет уведомления «запись экрана», нет тоста, нет какого-либо индикатора.
- Кадр приходит как `HardwareBuffer` с цветовым пространством - возможна GPU-постобработка.
- Минусы: только API 30+; требует включённого Accessibility-сервиса; именно «тихость» и использование a11y не по прямому назначению - главный вектор отклонения в Google Play (см. §6.4).

## Сопоставление

- Индикация: А - явная (системная); Б - отсутствует.
- Минимальный API: А - весь диапазон; Б - 30+.
- Policy-риск: А - умеренный; Б - высокий (a11y не по назначению).
- Согласие: А - посессионное; Б - однократное включение сервиса.

## Вывод для спеки (предварительный, ADR-2)

- По умолчанию - вариант А (MediaProjection) с явным согласием и видимым индикатором: согласуется с продуктовым требованием §3.2 об индикаторе и минимизирует policy-риск.
- Вариант Б рассматривается только при явном policy-обосновании и решении владельца; на API < 30 он в принципе недоступен.
- На API 26..29 захват - только через А; на legacy (23..25) - уточнить в §6.5.
- Продуктовое требование «видимый индикатор» сохраняется независимо от выбранного API.
