# 09 - Конфликт левого края с системным жестом «Назад»

**Research item:** §6.9
**Дата:** 2026-06-11
**Статус:** Resolved-with-risk - требует решения владельца по митигации

## Вопрос

Не сломает ли прозрачная полоса на левом краю (10–50% высоты) системный жест «Назад» при навигации жестами (Android 10+)?

## Находки

- В навигации жестами (Android 10+) «Назад» - это inward-свайп от ЛЕВОГО или ПРАВОГО края экрана. Наша полоса стоит ровно в этой зоне на левом краю.
- `View.setSystemGestureExclusionRects()` позволяет исключить участки края из системного жеста, НО: лимит 200dp на край, и API предназначен для собственного окна приложения, а не как способ забрать весь край. Google намеренно ограничивает это, чтобы сторонние «edge launcher»-приложения не блокировали «Назад» по всему краю.
- Touchable-оверлей, лежащий поверх приложений на самом краю, конкурирует за `ACTION_DOWN` с системным жестом. Если оверлей перехватит начало касания, системный «Назад» может не сработать - пользователь в этой зоне «теряет» Назад, пока полоса активна.
- Наш жест (диагональ вниз-вправо ~45°) по вектору отличается от «Назад» (горизонтальный inward), что даёт основу для различения.

## Варианты митигации (на решение владельца)

1. **Различение по вектору без блокировки:** перехватывать только подтверждённый диагональный жест; при горизонтальном свайпе не потреблять касание, отдавая «Назад» системе. Риск: на gesture-nav системе начальный перехват всё равно может «съесть» «Назад»; требует on-device проверки.
2. **Смещение полосы от самого края:** начинать зону не от пикселя 0, а с небольшим отступом, чтобы у самого края оставалась полоса для системного «Назад». Снижает конфликт, но усложняет «жест от края».
3. **Правый край вместо левого:** перенос на правый край не убирает конфликт (там тоже «Назад»), но может быть удобнее части пользователей.
4. **Только 3-кнопочная навигация:** на устройствах с навигацией жестами честно предупреждать о конфликте; полноценно поддерживать на 3-кнопочной навигации.
5. **Альтернативный доступ к действию:** действие «скриншот» доступно не только жестом (UI приложения, уведомление, плитка) - чтобы конфликт не лишал функции.

## Вывод для спеки

- Это ключевой риск выполнимости. Технически полоса реализуема, но сосуществование с «Назад» на gesture-nav - не гарантировано без on-device проверки и продуктового компромисса.
- Рекомендация: на фазе `/spec-tech` предусмотреть прототип-проверку перехвата на устройстве с навигацией жестами до полной реализации; зафиксировать выбранную митигацию решением владельца.
