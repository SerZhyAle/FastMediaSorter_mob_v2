## 1. Проблема

У ручной (MANUAL) трансляции в списке уже есть действие «Редактировать» (базово добавлено в S0660), но его диалог позволяет менять только адрес (URL) и название. Тип трансляции (аудио/радио или видео) определяется автоматически по URL и не поддаётся ручной правке, поэтому канал, неверно классифицированный эвристикой (например, аудиопоток на `.m3u8`-адресе), нельзя исправить. Нет единого места, где пользователь видит и меняет все параметры своей трансляции. Дополнительно: изменение URL на уже существующий сталкивается с уникальным индексом адреса и роняет приложение.

Область: подсистема интернет-трансляций, полноэкранный список трансляций (`ui/streams`).

---

## 2. Цели

1. Расширить существующий диалог правки ручной трансляции так, чтобы в одном месте менялись все параметры, определяющие ручной канал: адрес (URL), название и тип.
2. Добавить явный выбор типа: «Авто» (как сейчас - определяется по URL), «Аудио» и «Видео»; явный выбор переопределяет автоопределение и сохраняется.
3. Исключить падение при сохранении URL, совпадающего с другой существующей трансляцией: показывать понятное сообщение, запись при этом не меняется.
4. При «Авто» тип по-прежнему выводится из URL - прежнее поведение сохраняется.

**Non-goals:**

- Правка каталожных полей (категория, тема, язык, страна) на ручных строках - они остаются служебными полями каталога и `null` для MANUAL.
- Кнопка правки в закреплённой панели трансляций на главном экране - правка остаётся на полноэкранном списке.
- Массовое редактирование нескольких трансляций сразу.
- Правка каталожных/импортированных (не-MANUAL) строк.

## 4. Контекст текущей архитектуры

Список трансляций рисуется в `ui/streams` (`StreamsActivity` + `StreamsViewModel` + адаптеры списка и сетки). Строка ручной трансляции уже несёт действие «Редактировать» в меню переполнения (гейт `sourceOrigin == "MANUAL"`), которое открывает общий диалог добавления/правки. Диалог переиспользует разметку `dialog_add_stream.xml` с двумя полями (адрес, название). Запись идёт по цепочке `StreamsViewModel.onEdit` → `UpdateStreamSourceUseCase` → `StreamSourceRepository.updateUserFields` → `StreamSourceDao` (raw `UPDATE .. WHERE id = :id AND sourceOrigin = 'MANUAL'`), после чего Room-Flow сам перерисовывает список.

Проблему из §1 нельзя решить «на месте» по двум причинам: тип трансляции не имеет поля ввода в разметке диалога и жёстко переопределяется классификатором URL на каждой правке; путь записи не защищён от коллизии по уникальному индексу адреса.

## 5. Предлагаемый подход

Расширить уже существующий диалог правки, а не строить новый: в общую разметку диалога добавляется выбор типа (Авто / Аудио / Видео), показываемый в режиме правки. Путь применения получает явный тип и защиту от дубликата адреса.

### 5.1 Основные столпы / модули

- **Диалог правки** (`ui/streams`): добавить контрол выбора типа с тремя значениями; предзаполнять его сохранённым типом строки напрямую (AUDIO -> «Аудио», VIDEO -> «Видео»), чтобы явный выбор оставался виден при повторном открытии, даже если он совпадает с автоопределением. RTSP (нет явного пункта в контроле) предзаполняется как «Авто», поэтому нетронутая rtsp-строка при сохранении по-прежнему пере-выводит тип по URL; «Авто» также остаётся доступным пунктом для повторного автоопределения.
- **Слой применения** (`domain/usecase/streams`): use case правки принимает явный тип (или «Авто»); при «Авто» - прежнее автоопределение по URL, иначе - выбранное значение. Перед записью - проверка на дубликат адреса.
- **Слой данных** (`data/repository` + DAO): запись типа наравне с адресом и названием в существующем столбце; правка по-прежнему ограничена MANUAL-строками на уровне SQL.
- **Валидация и сообщения**: понятная реакция на неподдерживаемый URL и на дубликат адреса (без краша).

### 5.2 Потоки данных и событий

UI (диалог правки: адрес + название + тип) → слой применения (нормализация URL, разрешение типа Авто/явный, проверка дубликата) → репозиторий/DAO (обновление MANUAL-строки) → Room-Flow → перерисовка списка/сетки. Ошибочные случаи (неподдерживаемый URL, дубликат) возвращаются одноразовым событием-сообщением в UI.

### 5.3 Точки расширяемости

- Набор значений типа оставить расширяемым (в будущем возможен RTSP как явный выбор), не завязываясь на ровно три варианта в контрактах.
- Проверку дубликата вынести так, чтобы её можно было переиспользовать в пути добавления (S1147).

## 9. Архитектурные решения (ADR)

- **ADR-1.** Тип трансляции получает явный пользовательский выбор поверх автоопределения; «Авто» сохраняет прежнее поведение. Причина: владелец хочет менять «любой параметр», а тип - единственный параметр ручной трансляции, недоступный к правке сегодня.
- **ADR-2.** Каталожные поля (категория, тема, язык, страна) остаются недоступны для ручных строк. Причина: сохранить инвариант «для MANUAL эти поля `null`», на который опираются несколько мест UI; их правка - отдельная задача.
- **ADR-3.** Защита от дубликата адреса добавляется в путь правки (переиспользуя поиск по URL). Причина: диалог правки напрямую задействует падающий путь записи; правка не должна ронять приложение. Аналогичный путь добавления вынесён в S1147.
- **ADR-4.** Расширяется существующий диалог, а не создаётся новый. Причина: правка URL/названия уже реализована в этом диалоге (S0660); минимальная поверхность изменений.

## 11. Критерии готовности (strategic-level)

1. У ручной (MANUAL) строки списка трансляций действие «Редактировать» открывает диалог со всеми параметрами ручного канала: адрес, название, тип.
2. Тип переключается между «Авто», «Аудио» и «Видео»; выбор сохраняется и виден при повторном открытии диалога.
3. При «Авто» тип определяется по URL - прежнее поведение.
4. Сохранение изменённого URL, совпадающего с другой существующей трансляцией, не роняет приложение: показывается сообщение о дубликате, запись не меняется.
5. Каталожные/импортированные строки по-прежнему не редактируются (действие недоступно).
6. Изменения сразу отражаются в списке и сетке.
7. Строки EN/RU/UK для новых элементов диалога присутствуют.

Fix:
- `resolveEditKindOption` now mirrors the stored kind directly: AUDIO -> "AUDIO", VIDEO -> "VIDEO", else (RTSP) -> "AUTO". RTSP still maps to "AUTO" so an untouched rtsp channel re-derives to RTSP on save (override = null); "Авто" remains a selectable re-derive action. The `StreamMediaKindClassifier` injection (now unused in the ViewModel) was removed.
