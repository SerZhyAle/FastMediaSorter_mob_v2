---

## 1. Проблема

При активации режимов рисования (Draw) и кадрирования (Crop) в плеере изображений верхняя и нижняя командные панели остаются видимы, отнимая полезную площадь экрана и мешая работе с изображением. Кроме того, в режиме Crop функция «Обрезать края» (crop-to-fullscreen) срабатывает согласно глобальным настройкам, хотя в этом режиме она семантически бессмысленна и создаёт конфликт с ручным кадрированием. Жест щипка (pinch-to-zoom) при этом должен оставаться доступным.

---

## 2. Цели

1. При входе в режим Draw — обе командные панели автоматически скрываются; изображение занимает весь экран.
2. При входе в режим Crop — обе командные панели автоматически скрываются; изображение занимает весь экран.
3. При выходе из режима Draw или Crop — панели восстанавливаются в прежнем состоянии.
4. В режиме Crop функция «Обрезать края» принудительно отключена, независимо от глобальных настроек.
5. Жест pinch-to-zoom корректно работает в режиме Crop (масштаб + перемещение для выбора области).

**Non-goals:**

- Изменение поведения панелей в режиме просмотра без Draw/Crop.
- Изменение логики самого crop-to-fullscreen в других режимах.
- Новые визуальные эффекты или анимации переходов сверх минимально необходимых.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Плавная анимация скрытия/показа панелей при входе/выходе из режимов.
2. Статусная строка Android тоже скрывается (true fullscreen), если это технически доступно без конфликтов.

### 3.2 Жёсткие ограничения

- **Flavor:** все flavors (standard, lite, photos, legacy) — плеер изображений присутствует во всех.
- **API level:** без API-специфики; функция доступна с minSdk 26.
- **Wear OS:** не затрагивается.
- **Производительность:** скрытие/показ панелей — сугубо UI-операция; бюджет CPU не критичен.
- **Совместимость данных:** нет изменений в хранении данных.
- **Локализация:** EN/RU/UK — новые строки не предполагаются; если появятся — обязательно.
- **Доступность:** при скрытых панелях доступность (TalkBack) должна оставаться функциональной через стандартный gesture-navigation; жест выхода из режима должен быть явным.

---

## 4. Контекст текущей архитектуры

Плеер изображений живёт в слое UI и реализует просмотр, редактирование (Draw, Crop, Rotate, Flip, Adjust) через набор вложенных режимов. Командные панели — верхняя (навигация и overflow) и нижняя (действия с файлом) — управляются состоянием видимости внутри плеера. Режимы Draw и Crop переключаются через ViewModel, который хранит текущий активный режим. Функция crop-to-fullscreen читает глобальную настройку и применяет её на уровне рендеринга изображения.

Сейчас нет механизма, который при смене режима автоматически влиял бы на видимость панелей — каждый режим управляет только своими собственными контролами. Crop-to-fullscreen не имеет контекстного блокиратора: настройка применяется всегда.

---

## 5. Предлагаемый подход

Состояние активного режима (Draw / Crop / None) уже существует в слое ViewModel. Его нужно расширить сигналом «требуется полноэкранный режим», на который UI-слой реагирует скрытием панелей. При выходе из режима сигнал сбрасывается, панели восстанавливаются.

### 5.1 Основные столпы

**Управление видимостью панелей**
- ViewModel эмитирует булев флаг «иммерсивный режим активен».
- UI-слой подписывается на этот флаг и скрывает/показывает обе панели через стандартный механизм видимости.
- Состояние «было ли скрыто пользователем вручную до входа в режим» не сохраняется — при выходе из Draw/Crop панели всегда восстанавливаются.

**Блокировка crop-to-fullscreen в режиме Crop**
- Логика рендеринга изображения получает контекст активного режима.
- Если режим — Crop, crop-to-fullscreen принудительно считается выключенным независимо от настройки.

**Pinch-to-zoom в режиме Crop**
- Обработчик жестов в режиме Crop не блокирует масштабный жест; он должен продолжать работать для выбора и позиционирования области кадрирования.
- Конфликт между жестом масштаба и жестом выбора области должен быть разрешён: pinch → масштаб + смещение видового окна; однопальцевый drag → перемещение рамки кропа.

### 5.2 Потоки данных и событий

```
Пользователь активирует Draw/Crop
  → ViewModel: activeMode = Draw|Crop
  → UI: наблюдает activeMode → скрывает панели
  → Рендерер изображения: наблюдает activeMode → игнорирует crop-to-fullscreen если Crop
```

```
Пользователь выходит из Draw/Crop
  → ViewModel: activeMode = None
  → UI: наблюдает activeMode → восстанавливает панели
```

### 5.3 Точки расширяемости

- Флаг «иммерсивный режим» может быть переиспользован для будущих редакторских режимов (Color Adjust, OCR и т.п.).
- Логика «какой режим требует иммерсива» централизована в одном месте и расширяется добавлением нового режима в список.

## 9. Архитектурные решения (ADR)

**ADR-1: Управление иммерсивом через ViewModel-флаг, а не через событие из UI**

- **Решение:** ViewModel эмитирует флаг иммерсивного режима; UI пассивно реагирует.
- **Альтернативы:** UI сам вычисляет видимость панелей по режиму, без флага из ViewModel.
- **Почему:** Централизация логики «что считается иммерсивным» в ViewModel упрощает тестирование и исключает дублирование условий в нескольких фрагментах/представлениях.

**ADR-2: Блокировка crop-to-fullscreen контекстно, без изменения настройки**

- **Решение:** Настройка не меняется; рендерер получает переопределение только для режима Crop.
- **Альтернативы:** Временно выключать настройку на время режима и восстанавливать при выходе.
- **Почему:** Мутация пользовательской настройки за его спиной — антипаттерн; контекстное переопределение чище и обратимо.

## 11. Критерии готовности (strategic-level)

1. Вход в режим Draw — обе панели немедленно исчезают; изображение занимает всю высоту экрана.
2. Вход в режим Crop — обе панели немедленно исчезают.
3. Выход из Draw или Crop (кнопка или Back) — панели восстанавливаются.
4. В режиме Crop изображение не обрезается по краям, даже если настройка «Обрезать края» включена.
5. В режиме Crop жест двумя пальцами (pinch) изменяет масштаб и позицию вьюпорта.
6. Смена ориентации устройства внутри режима не оставляет панели в неправильном состоянии.
7. TalkBack: жест выхода из режима доступен при скрытых панелях.
