## 1. Проблема

S0565 дал экран "Трансляции" с ручным добавлением URL и импортом пользовательского `.m3u` по введённой ссылке.. Но у пользователя нет готового набора рабочих свободных источников "из коробки", нет курируемого нами каталога, который мы ведём и раздаём, и нет одно-тапного способа получить/обновить его.. Текущий импорт умеет только `.m3u` (url + название) и не несёт рубрик, тем, языков и параметров стриминга, поэтому он не годится как формат курируемого каталога.. В списке трансляций нет инструментов навигации (фильтр, сортировка, поиск), что делает большой каталог неудобным.. Нет и механизма проверки актуальности источников, чтобы добавлять новые и выбрасывать мёртвые..

## 2. Цели

1. Раздавать курируемый каталог свободных трансляций как загружаемый ресурс проекта на GitHub (табличный формат с рубрикой, темой, языком и полным набором параметров).
2. Дать на экране "Трансляции" одно-тапную загрузку/обновление этого каталога по кнопке "Импорт лист".
3. Поддержать повторное обновление: новые записи добавляются, локальные правки (закреплённые, порядок, свои источники) сохраняются.
4. Показывать в списке тему и язык источника и дать фильтр, сортировку и поиск по списку.
5. Сохранять параметры источника (рубрика, тема, язык, тип медиа, протокол и пр.) настолько, насколько полезно для отображения, фильтрации и маршрутизации.
6. Иметь механизм проверки статуса источников (живой/мёртвый) для ведения каталога: добавлять новые, выбрасывать мёртвые.

**Non-goals:**

- Серверная система каталогов, телегид, расписания, рейтинги, пользовательские правки общего каталога.
- Любые источники вне легального scope (DRM, платное, гео-премиум, серые IPTV-агрегаторы).
- Двусторонняя синхронизация (пользователь -> наш каталог).
- Полный парсинг `.pls`/`.xspf` (остаётся отложенным из S0565).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Каталог хостится на GitHub проекта как другие загружаемые расширения (release-asset, можно zip).
2. Кнопка "Импорт лист" предлагает загрузить/обновить именно наш каталог.
3. Каталог - таблица со всеми параметрами стриминга, по рубрикам, с разбивкой по темам и языкам.
4. В экране "Трансляции" показывать язык и тему, дать фильтр, сортировку и поиск.
5. Владелец периодически пересматривает ресурс; пользователь обновляет у себя; мёртвые источники выбрасываются.

### 3.2 Жёсткие ограничения

- **Формат данных:** курируемый каталог - таблица (CSV, см. артефакт `delivery/stream-catalog/README.md`) с колонками рубрики, темы, языка и параметров, а не `.m3u`; нужен отдельный табличный парсер.. Существующий `.m3u`-импорт остаётся для произвольных пользовательских плейлистов..
- **Хостинг:** как загружаемые расширения - GitHub release-asset (допустимо в zip); приложение скачивает, при необходимости распаковывает и парсит.. Каталог намеренно изменяемый (не SHA-pinned), приложение всегда тянет актуальную версию..
- **Flavor:** наследует S0565 - photos без entry-point; lite играет только progressive-audio (HLS/DASH/RTSP-строки в lite либо фильтруются на импорте, либо отдают существующее сообщение "не поддерживается")..  Гейтинг - через flavor-интерфейс/source-set, не `BuildConfig` в `src/main`..
- **Cleartext:** часть радио - публичный `http://`; полезность их импорта зависит от cleartext-политики S0565..
- **Хранение:** обновление каталога не затирает пользовательские источники, закрепления и порядок; добавление - append с де-дупликацией по нормализованному URL.. Расширение схемы хранилища под рубрику/тему/язык - обратносовместимо..
- **Сеть:** переиспользовать существующий HTTP-клиент проекта; не добавлять новую сетевую зависимость; загрузка/распаковка на IO без блокировки UI..
- **Локализация:** EN/RU/UK для новых пользовательских строк (выбор источника импорта, фильтр/сортировка/поиск, статусы, ошибки)..
- **Доступность:** новые элементы (выбор импорта, поле поиска, контролы фильтра/сортировки) поддерживают keyboard, D-pad/TV, mouse..

### 3.3 Owner inputs (Approval gate) - решения

- **Legal scope:** каталог ограничен явно свободными источниками; free live TV расширяется официальными free-to-air / public-service / gov каналами (DW, France 24, Al Jazeera, Euronews, NHK World, NASA и подобные - только собственные открытые HLS вещателей); серые IPTV-агрегаторы и ре-стримы исключены.. (Owner 2026-06-21.)
- **Hosting model:** как другие загружаемые расширения - GitHub release-asset, допустимо в zip; не SHA-pinned (изменяемый каталог).. (Owner 2026-06-21.)
- **Feature scope:** расширить экран "Трансляции" показом темы и языка плюс фильтр, сортировка и поиск по списку; точная вёрстка - тактический/`/ui-clarify`.. (Owner 2026-06-21.)
- **Catalog maintenance:** ввести механизм проверки статуса источников для периодического обновления каталога (добавить новые, выбросить мёртвые).. (Owner 2026-06-21.)

## 4. Контекст текущей архитектуры (из S0565)

Экран "Трансляции" уже содержит: тулбар с действием `action_stream_import` ("Import list"), диалог ввода URL, импорт `.m3u` через download+parse+de-dup, локальное хранилище источников, use-cases наблюдения/добавления/импорта/закрепления/удаления, inline-аудио и fullscreen-видео маршрутизацию по типу медиа.. Импортный код привязан к `.m3u`-парсеру.. Курируемый каталог уже подготовлен в репозитории (`delivery/stream-catalog/streams.csv` + `README.md`) вместе с maintenance-скриптом проверки статуса (`scripts/stream_catalog/check-liveness.ps1`)..

## 5. Предлагаемый подход

1. **Каталог как ресурс** (готово предшествующей работой): таблица с рубрикой/темой/языком/параметрами + README с форматом, политикой обновления, легальным scope и атрибуцией; раздаётся как загружаемое расширение (release-asset, zip)..
2. **Табличный парсер**: отдельный RFC-4180-совместимый парсер каталога, толерантный к кавычкам/запятым/пустым необязательным полям..
3. **Use case импорта каталога**: скачивание нашего ресурса по встроенному адресу, при необходимости распаковка, парсинг, маппинг строк в источники (рубрика/тема/язык/параметры), merge с де-дупликацией по URL, возврат числа добавленных.. Переиспользует существующий HTTP-клиент и доменную классификацию..
4. **Модель данных**: расширить источник полями рубрики/темы/языка/типа медиа (фильтруемый набор) и пометкой происхождения (`origin=CATALOG` для импортированных из каталога), чтобы вести список по категориям, фильтровать и при обновлении чистить исчезнувшие записи каталога, не трогая ручные/закреплённые..
5. **UX кнопки "Импорт лист"**: предложить "Обновить каталог FastMediaSorter" (основной, одно-тапный) и "Импорт по URL" (существующий ручной плейлист)..
6. **Навигация по списку**: плоский список с темой и языком (чипы) в строке; фильтр (по рубрике/теме/языку/типу медиа), сортировка (имя/тема/язык/недавние) и текстовый поиск сверху; секционная группировка отложена..
7. **Обслуживание каталога**: периодический прогон liveness-механизма (готовый скрипт) для отсева мёртвых и валидации новых источников перед публикацией..
8. **Flavor/cleartext**: импорт уважает возможности сборки (lite/photos) и cleartext-политику S0565..

### 5.1 Потоки данных

```text
[GitHub release-asset (zip -> streams.csv)]
        -> [Import list -> "Обновить каталог FastMediaSorter"]
        -> [Download (+unzip) on IO -> table parse -> map rows]
        -> [Merge into local sources (de-dup by URL, keep pins/order)]
        -> [Список обновлён, "+N добавлено"; тема/язык доступны для показа, фильтра, сортировки, поиска]
```

### 5.2 Рекомендуемый объём 1-й итерации

- Делать первым: табличный парсер; use-case загрузки каталога по встроенному адресу (с распаковкой); хранение рубрики/темы/языка; merge-обновление без потери пользовательских данных; выбор "обновить каталог / импорт по URL"; показ темы и языка; базовые фильтр, сортировка и поиск; локализация EN/RU/UK..
- Отложить: группировку секциями по рубрикам (если дороже плоского списка с темой/языком в строке); хранение полного набора параметров сверх нужного для показа/фильтра; удаление устаревших записей каталога при обновлении; фильтр по возможностям сборки сверх существующего сообщения "не поддерживается"; авто-liveness внутри приложения (на 1-й итерации проверка статуса - наш maintenance-скрипт, не клиентская проверка)..

## 6. Открытые вопросы / Research items

1. **Упаковка ресурса** - Resolved: zip с одним `streams.csv` под фиксированным именем (`stream-catalog.zip`) на delivery-теге; приложение всегда тянет актуальный (не SHA-pinned).. (engineering)
2. **UX кнопки** - Resolved: кнопка открывает выбор - "Обновить каталог FastMediaSorter" (основной, один тап) и "Импорт по URL" (существующий ручной `.m3u`).. (quiz 2026-06-21)
3. **Глубина хранимых полей** - Resolved: фильтруемый набор - рубрика + тема + язык + тип медиа; битрейт/страна/лицензия не хранятся локально в 1-й итерации.. (quiz 2026-06-21)
4. **Группировка vs плоский список** - Resolved: плоский список с темой/языком (чипы) в строке + поиск, фильтр (рубрика/тема/язык/тип) и сортировка сверху; секции отложены.. (quiz 2026-06-21)
5. **Происхождение записей каталога** - Resolved: импортированные из каталога помечаются `origin=CATALOG`; обновление добавляет новые и убирает исчезнувшие из каталога записи, но никогда не трогает ручные/закреплённые.. (quiz 2026-06-21)
6. **Поведение в lite** - Resolved: наследует flavor-gating S0565 (photos без entry-point; lite - existing "не поддерживается" для HLS/DASH/RTSP).. (architecture, S0565)
7. **Версионирование каталога** - Resolved: идемпотентный merge-by-URL без явного version/updated в 1-й итерации.. (engineering)
8. **Клиентская liveness-проверка** - Resolved: в 1-й итерации только maintenance-скрипт (`scripts/stream_catalog/check-liveness.ps1`); клиентская проверка доступности отложена.. (engineering)

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Записи каталога устаревают (тест-URL ротируются, радио/TV меняют хосты) | Высокая | Часть строк не играет | Maintenance liveness-скрипт + периодическая ре-генерация; колонка confidence |
| Cleartext-радио заблокировано политикой | Высокая | Доля радио не грузится | Зависит от cleartext-решения S0565; до него - помечать/фильтровать http-строки |
| Расширение схемы под рубрику/тему/язык | Средняя | Доп. сложность + совместимость | Минимальные nullable-поля; обратная совместимость обязательна |
| Обновление затирает пользовательские данные | Средняя | Потеря закреплений/порядка/своих источников | Merge только append+de-dup; никогда не удалять пользовательские записи |
| HLS/DASH/RTSP строки в lite/photos | Средняя | Мёртвые строки/ошибки в урезанных сборках | Фильтр на импорте или существующее сообщение "не поддерживается" (S0565) |
| Легальный дрейф каталога при расширении free TV | Средняя | Юридический/store-риск | Жёсткий легальный gate (только собственные открытые фиды вещателей); аудит при ре-генерации |
| Фильтр/сортировка/поиск перегрузят UI большого списка | Средняя | Тормоза/нечитабельность | Серверная-подобная фильтрация в ViewModel/БД, DiffUtil, дебаунс поиска |
| release-asset неудобно обновлять | Низкая | Трение в ведении каталога | Фиксированное имя + перезаливка, либо манифест-override URL (паттерн delivery) |

## 8. Критерии готовности (strategic-level)

1. Курируемый каталог доступен как загружаемое расширение на нашем GitHub (release-asset, zip)..
2. Кнопка "Импорт лист" загружает/обновляет наш каталог одним действием..
3. Импорт добавляет источники с рубрикой/темой/языком; повторный импорт обновляет список, не теряя пользовательские источники/закрепления/порядок..
4. В списке видны тема и язык; работают фильтр, сортировка и поиск..
5. Аудио из каталога стартует inline, видео - в полноэкранном просмотре (маршрутизация S0565)..
6. Поведение в lite/photos согласовано с gating S0565 (photos без entry-point)..
7. Есть работающий maintenance-механизм проверки статуса источников (живой/мёртвый)..
8. Новые строки локализованы EN/RU/UK; ошибки сети/распаковки/парсинга не роняют экран..
9. Проверено на устройстве: чистый импорт, повторное обновление, фильтр/сортировка/поиск, сохранение закреплений..
