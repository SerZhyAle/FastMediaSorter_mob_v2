## 2. Опровергнутые подходы и антипаттерны (Refuted Constraints)

При проектировании улучшений строго соблюдаются границы, проверенные и зафиксированные в `dev/REFUTED_APPROACHES.md`:

1. **Запрет `detekt --auto-correct` (S1595, `REFUTED_APPROACHES.md:9`)**:
   - Единственный флаг автоисправления в Detekt — это общий `formatting`, который активирует ~5 591 finding (46% базовой линии) и ломает кодовую базу. Автоисправление возможно только отдельным специализированным скриптом.
2. **Ограничения сортировки импортов (S1328, S1595)**:
   - Сортировка строк в PowerShell через `Sort-Object -CaseSensitive` и `StringComparer::Ordinal` через `Group-Object` дают некорректный порядок для Detekt. Сравнение обязано выполняться исключительно через прямой вызов `[string]::CompareOrdinal` внутри 4 групп (`*`, `java`, `javax`, `kotlin`).
3. **Запрет `enable_mcp_tools: false` (S1348)**:
   - Такого аргумента в Claude Code не существует. Изоляция MCP-инструментов в подагентах достигается исключительно через явный список `tools:` во фронтматтере определения агента. Ошибочная строка в `docs/AGENT_COST_PLAYBOOK.md:37` подлежит исправлению.
4. **Запрет плейсхолдеров для 13 локалей (S1627 ADR-2)**:
   - Перевод UI-строк выполняется пакетно на этапе предрелиза (шаг 0.8 `/spec-prerelease`). Генерация пустых заглушек в `values-<lang>` на этапе разработки ослепит `list-new-lexemes.ps1` и приведет к пропуску непереведенных строк.
5. **Ненужность секторальных `CODE.LOCK` (S1432)**:
   - Блокировки `BUILD.LOCK` и `CODE.LOCK` уже работают через справедливую FIFO-очередь (`enter-code-lock.ps1`, `wait-for-lock-turn.ps1`). Замок берется на одну атомарную правку, а не на весь тикет, поэтому секторальные замки не дают выигрыша для solo-разработчика.
6. **Ограничения авто-санитайзера текста (Canon `DOCUMENTATION_CONCEPT.md`)**:
   - Домашний стиль распространяется только на прозу и UI-строки; спеки, код, логи и команды исключены. Автоматическая расстановка буквы `ё` невозможна (контекст слов «все/всё»). Длинные тире в `.kt` уже механически контролируются через `assert-neuroslop.ps1`.

#### 1.5 Отказ на конвейере, скрывающем код возврата (`| head`, `| tail`)
- **Обоснование, снятое в этой сессии 2026-08-17:** вызов `pwsh -NoProfile -File ./a.ps1 fu 2>&1 | tail -60` вернулся как **exit 0**, тогда как сама обёртка напечатала `Fast check failed`.   2. Родственный класс уже гейтирован (Rule 25, Rule 26, Rule 28), то есть шаблон отказа готов - это ещё один вход в ту же дверь.
- **Ожидаемый эффект:** Устранение класса ошибок, который не лечится правилом в прозе, потому что вызов выглядит успешным.
