## 1. Проблема

Элементы статистики (тоггл «Сбор статистики» и кнопка «Статистика», добавлены в S0473) расположены в секции общих настроек интерфейса, хотя по смыслу относятся к данным/фоновой работе. Логичнее держать их рядом с фоновой синхронизацией, сетью и кэшем. Кнопка «Статистика» занимает лишнюю ширину (не по тексту). Сам экран/диалог статистики на телефонах использует площадь неоптимально - не хватает ещё одной summary-карточки для удобства.

Область: разметка настроек `app_v2` (`fragment_settings_general.xml` + landscape) и экран статистики (`activity_statistics.xml`, S0473).

---

## 2. Цели

1. Тоггл «Сбор статистики» и кнопка «Статистика» перенесены из секции общих настроек интерфейса в секцию «Фоновая синхронизация, сеть и кэш» (portrait + landscape).
2. Кнопка «Статистика» по ширине текста (`wrap_content`), не на всю ширину.
3. В экране/диалоге статистики добавлена 4-я summary-карточка, улучшающая использование площади на телефонах.
4. Поведение тоггла/кнопки не меняется - только размещение и ширина.

**Non-goals:**

- Не меняем саму логику сбора статистики (S0473).
- Не переписываем секционную структуру настроек (это объём S0479).
- Не меняем id, на которые завязаны обработчики.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. На телефонах должно быть удобно - 4-я карточка ради лучшего заполнения экрана.
2. Кнопка по ширине текста.

### 3.2 Жёсткие ограничения

- **Flavor:** standard и все, где доступна статистика (S0473-гейтинг сохраняется).
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Производительность:** нейтрально (разметка + одна карточка-метрика).
- **Совместимость данных:** нет.
- **Локализация:** EN/RU/UK для заголовка/значения новой карточки.
- **Доступность:** touch target ≥48dp, фокус D-pad/TV сохранён при переносе.

### 3.3 Owner inputs (Approval gate)

- **UI placement/visibility:** перенос в секцию «Фоновая синхронизация, сеть и кэш»; точное место внутри секции - см. §6. Видимость элементов и их гейтинг не меняются.
- **Локализация:** EN/RU/UK для новой карточки.
- **Доступность:** см. §3.2.
- **Related tickets:** S0473 (фича статистики), S0479 (декомпозиция секции настроек - правит тот же layout).

## 4. Контекст текущей архитектуры

Настройки рендерятся фрагментом по разметке `fragment_settings_general.xml` (portrait) + `layout-land/` (landscape); блок статистики `layoutEnableStatistics` лежит в верхней (UI) части, целевая секция (`containerSync`/`containerCache`) - ниже в том же файле. Поведение тоггла/кнопки навешивается во ViewModel/менеджерах по id. Экран статистики (`activity_statistics.xml`, S0473) показывает summary-карточки, число колонок которых задаётся orientation-qualified `@integer/statistics_card_span`; карточки наполняются данными статистики. Проблему нельзя «решить из коробки», т.к. размещение зашито в разметке, а 4-я карточка требует новой метрики и её источника.

---

## 5. Предлагаемый подход

Перенести блок статистики внутри разметки настроек в секцию фоновой синхронизации/сети/кэша (обе ориентации), сузить кнопку до ширины текста, добавить 4-ю summary-карточку на экране статистики.

### 5.1 Основные столпы / модули

- Разметка настроек: перемещение блока `layoutEnableStatistics` в целевую секцию, без смены id; кнопка `wrap_content`.
- Экран статистики: 4-я карточка (новая метрика + её данные), вписанная в существующую card-span-сетку.
- Строки: заголовок/значение новой карточки в EN/RU/UK.

### 5.2 Потоки данных и событий

- Настройки: разметка → ViewModel находит элементы по неизменным id → поведение прежнее.
- Статистика: источник данных → новая метрика → 4-я карточка в сетке.

### 5.3 Точки расширяемости

- Card-span-сетка статистики уже параметризована - добавление карточки не ломает reflow.

## 6. Открытые вопросы / Research items

Все вопросы решены владельцем 2026-06-18.

1. **Содержимое 4-й карточки** - РЕШЕНО: «Просмотрено» (`statistics_card_viewed`), метрика = `IMAGES_VIEWED + VIDEOS_WATCHED + AUDIO_PLAYED + DOCUMENTS_OPENED`, формат `COUNT`, иконка `ic_slideshow`. Реальные opt-in счётчики `StatsSnapshot`; новый headline «просмотр/браузинг», не пересекается с тремя существующими карточками. 4 карточки дают ровный 2×2 на телефоне (span = 2 портрет / 3 ландшафт).
2. **Точное место блока статистики** - РЕШЕНО: в конец секции «Фоновая синхронизация, сеть и кэш» (`containerSystem`), после `containerCache`. Самостоятельный data/usage-блок, не вклинивается в контролы sync/cache.
3. **Порядок с S0479** - РЕШЕНО: S0479 в статусе Draft (не начат) → S0499 выполняется первым; координация не требуется.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Расхождение portrait/landscape при переносе | Средняя | Блок только в одной ориентации | Парный перенос (Rule 11), сверка id |
| Конфликт с S0479 (тот же layout) | Средняя | Переделка/merge-боль | Согласовать порядок (§6.3) |
| Потеря фокуса D-pad/TV при переносе | Низкая | Регресс навигации | Проверить `nextFocus*` после переноса |
| 4-я карточка без реального источника данных | Средняя | Пустая/фейковая метрика | Выбрать метрику из реально доступных данных статистики |

## 11. Критерии готовности (strategic-level)

1. Тоггл «Сбор статистики» и кнопка «Статистика» находятся в секции «Фоновая синхронизация, сеть и кэш» в portrait и landscape.

3. На экране статистики присутствует 4-я summary-карточка с реальной метрикой, EN/RU/UK.
4. Поведение тоггла/кнопки не изменилось; id сохранены.
5. Сборка standard debug проходит; ручная device-проверка настроек и экрана статистики - без регрессий.
