## 1. Проблема

Сегодня видеофайл, открытый тапом из браузера ресурсов, запускается в плеере с показанной панелью команд - полноэкранный режим требует отдельного действия пользователя (ручное переключение или поворот устройства в ландшафт). Для пользователей, которые всегда хотят сразу видеть видео без панели поверх изображения, это лишний шаг при каждом открытии. Область - браузер ресурсов и плеер видео.

## 2. Цели

1. Тумблер в разделе настроек "Видео" включает/выключает автоматический запуск видеофайла сразу в полноэкранном режиме при открытии тапом из браузера ресурсов.
2. При включённом тумблере тап по видеофайлу в списке или сетке браузера сразу открывает плеер в полноэкранном режиме - без показанной панели команд, без дополнительного действия пользователя.
3. На новой установке и на существующей установке при обновлении приложения тумблер получает значение "включено" для всех профилей устройства, кроме профиля "аудиоплеер" и профиля "читалка", где значение "выключено" - без ручной настройки со стороны пользователя.
4. Ранее сохранённый явный выбор пользователя показывать панель команд для конкретного ресурса продолжает иметь приоритет над новым тумблером - поведение не меняется для ресурсов с уже заданным выбором.

**Non-goals:**

- Непрерывное переключение режима при переходе между видео и файлами других типов внутри уже открытого смешанного ресурса - затрагивается только момент первого открытия ресурса тапом из браузера.
- Другие пути открытия видео (запуск слайдшоу, случайное воспроизведение, приём через шер/диплинк, восстановление последнего файла при холодном старте, открытие записанного видео после съёмки, запуск из виджета) - остаются на текущем поведении, не наследуют новый тумблер.
- Изменение скрытия системных полос (статус-бар/навигация) в полноэкранном режиме - управляется отдельной уже существующей настройкой независимо от этого тумблера.
- Принудительный поворот ориентации при открытии - не вводится.
- Изменение общего тумблера "показывать панель команд по умолчанию" или его матрицы значений по профилям для остальных типов медиа (изображения, аудио).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. В будущем - переключение полноэкранного режима при переходе между видео и другими типами файлов внутри одного смешанного ресурса прямо во время просмотра, не только при первом открытии.
2. В будущем - аналогичный тумблер для изображений с той же логикой (сейчас затрагивает только видео).

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты с поддержкой видео (standard, lite, photos, legacy) - плеер видео не имеет отдельных флейвор-специфичных реализаций, единый хост обслуживает все сборки.
- **API level:** без API-специфики; действует в рамках существующих минимальных уровней проекта (standard 26, legacy 23).
- **Wear OS:** не затрагивается - браузер ресурсов и плеер видео на Wear отсутствуют.
- **Производительность:** переход в полноэкранный режим при открытии не должен вносить заметную задержку и не должен прерывать или перезапускать воспроизведение; переиспользует существующий переход в полноэкранный режим, а не вводит новый.
- **Совместимость данных:** новый флаг настроек не требует миграции Room - хранится обычным булевым значением в существующем хранилище настроек (не Room). Отсутствующий ключ у уже установленных приложений трактуется как значение по умолчанию тем же механизмом, что и любое ранее добавленное булево поле, поэтому обновление существующей установки получает "включено" без отдельного шага миграции.
- **Локализация:** новая пользовательская строка - метка тумблера в разделе "Видео" (и краткое описание, если того требует стиль раздела) - EN/RU/UK обязательно.
- **Доступность:** тумблер достижим клавиатурой и D-pad/TV по тому же паттерну, что и остальные тумблеры раздела настроек; сам переход в полноэкранный режим переиспользует уже доступный существующий механизм (фокус, TalkBack) - новое недоступное состояние не вводится.

## 4. Контекст текущей архитектуры

Раздел настроек "Видео" уже содержит переключатели, специфичные для видеофайлов, но не управляет начальным режимом отображения плеера. Начальный режим отображения (полноэкранный или с показанной панелью команд) сегодня определяется одним общим значением настроек, действующим одинаково для всех типов медиа, с возможностью переопределения на уровне конкретного ресурса, сохранённого пользователем ранее - такое сохранённое переопределение имеет приоритет. Отдельно от этого уже существует механизм принудительного запуска плеера сразу в полноэкранном режиме для определённого типа контента (используется сегодня для потокового видео) и механизм автоматического переключения режима при повороте устройства в ландшафт, срабатывающий уже после загрузки файла, когда его тип медиа известен на уровне плеера.

Проблема в том, что механизм принудительного запуска сразу в полноэкранном режиме сегодня не распространяется на обычные видеофайлы, открываемые тапом из браузера ресурсов: на момент первого показа экрана плеера тип открываемого файла для обычных (не потоковых) ресурсов ещё не определён на уровне плеера, тогда как на уровне браузера ресурсов, в точке перехода к открытию файла, тип уже известен. Поэтому решение задачи требует передачи решения "открыть сразу в полноэкранном режиме" из точки, где тип файла уже известен (браузер), в точку запуска плеера, гейтированного новым пользовательским тумблером.

## 5. Предлагаемый подход

Вводится новый флаг настроек, специфичный для видео. В точке перехода "тап по видеофайлу в браузере -> запуск плеера" - там, где браузер уже знает тип открываемого файла - решение "запустить сразу в полноэкранном режиме" принимается и передаётся вместе с командой запуска плеера, без ожидания, пока плеер сам определит тип файла после загрузки.

Новый флаг не заменяет существующий общий флаг "показывать панель команд по умолчанию" и не меняет его применение к остальным типам медиа - он действует как дополнительное условие, специфичное для видео, и уступает место ранее сохранённому явному выбору пользователя для конкретного ресурса, если такой выбор уже есть.

Значение по умолчанию для нового флага определяется системой пресетов профиля устройства так же, как для остальных пресетируемых настроек: включено для всех профилей, кроме профиля "аудиоплеер" и профиля "читалка", где оно выключено. Для установок без применённого пресета, включая миграцию существующих установок, действует тот же прикладной default, что и в коде настроек, без отдельного шага миграции.

### 5.1 Основные столпы / модули

- **Настройка "видео сразу в полноэкранном режиме".** Новый булев флаг в модели настроек приложения, отображаемый переключателем в разделе "Видео" настроек, персистентный в существующем хранилище настроек.
- **Точка принятия решения на переходе браузер -> плеер.** Место, где браузер ресурсов уже знает тип открываемого файла на момент построения перехода к плееру, дополняется условием "тип - видео, флаг включён, для ресурса нет сохранённого явного выбора" -> плееру передаётся команда войти в полноэкранный режим сразу при старте.
- **Переиспользование существующего перехода в полноэкранный режим.** Само наступление полноэкранного режима выполняется тем же механизмом, что уже используется для принудительного запуска в полноэкранном режиме и для ручного переключения - новый визуальный переход не вводится.
- **Пресет-система профиля устройства.** Новый флаг подключается к существующему механизму применения пресетов по профилю устройства как ещё одно пресетируемое поле, со значением по каждому профилю.

### 5.2 Потоки данных и событий

Тап по видеофайлу в браузере ресурсов -> браузер определяет тип файла и читает настройку "видео сразу в полноэкранном режиме" и явный выбор пользователя для ресурса, если он есть -> решение "войти в полноэкранный режим при запуске" передаётся вместе с переходом к экрану плеера -> плеер при первом запуске (без пересоздания активности) входит в полноэкранный режим через существующий переход, без прерывания последующей загрузки файла.

### 5.3 Точки расширяемости

- Точка принятия решения остаётся единой, чтобы в будущем расширить условие на другие типы медиа (изображения) без дублирования логики - см. пожелание владельца §3.1.
- Флаг остаётся совместимым с будущим включением непрерывного (не только при первом открытии) переключения режима при переходе между файлами разных типов внутри одного ресурса, если такое расширение будет одобрено отдельно.

## 9. Архитектурные решения (ADR)

**ADR-1: Гейт на уровне браузера, а не плеера**

- **Решение:** условие "видео и флаг включён" проверяется в браузере ресурсов, в момент, когда тип открываемого файла уже известен, а не в плеере после загрузки файла.
- **Альтернативы:** проверка типа файла внутри плеера после первой загрузки медиа - как это уже делает существующий механизм автоповорота, срабатывающий уже после загрузки.
- **Почему:** на момент первого показа экрана плеера тип файла ещё не определён на уровне плеера для обычных (не потоковых) ресурсов - решение необходимо принять раньше, там, где тип уже известен, чтобы избежать позднего или заметного переключения режима сразу после открытия.

**ADR-2: Однократное решение при первом открытии, а не непрерывное отслеживание**

- **Решение:** новый флаг влияет только на решение в момент запуска плеера при первом открытии ресурса из браузера, не на переключение режима при последующей навигации между файлами внутри уже открытого ресурса.
- **Альтернативы:** непрерывное отслеживание типа текущего файла внутри плеера и переключение режима при каждом переходе на видео или с видео.
- **Почему:** непрерывное отслеживание - более широкое по объёму изменение (новая логика на каждый переход между файлами внутри сессии просмотра, взаимодействие с ручным выбором пользователя в рамках той же сессии) и не было явно запрошено в задаче; вынесено в пожелания владельца (§3.1) как возможное будущее расширение.

## 11. Критерии готовности (strategic-level)

1. В разделе настроек "Видео" присутствует переключатель "Открывать видеофайлы в полноэкранном режиме".
2. При включённом переключателе тап по видеофайлу в браузере ресурсов - при отсутствии сохранённого явного выбора для этого ресурса - открывает плеер сразу в полноэкранном режиме, без панели команд.
3. При выключенном переключателе поведение открытия видео из браузера не отличается от текущего.
4. На новой установке переключатель включён для всех профилей устройства, кроме профиля "аудиоплеер" и профиля "читалка", где он выключен.
5. На существующей установке при обновлении приложения переключатель получает значение "включено" (кроме случая, когда профиль устройства уже определён как "аудиоплеер" или "читалка") без ручных действий пользователя.
6. Ранее сохранённый явный выбор пользователя показывать панель команд для конкретного ресурса продолжает соблюдаться независимо от нового переключателя.
7. Воспроизведение не прерывается, и плеерная активность не пересоздаётся при входе в полноэкранный режим по этому переключателю.
