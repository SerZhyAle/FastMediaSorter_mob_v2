# 01 - Получение роли домашнего экрана (Home) по версиям Android

**Связано с §6.1 спеки S0404.** Дата: 2026-06-11.

## Что приложение должно объявить

Активность-домашний-экран объявляет intent-фильтр с тремя элементами:

- action `android.intent.action.MAIN`
- category `android.intent.category.HOME`
- category `android.intent.category.DEFAULT`

Активность с таким фильтром обязана иметь `android:exported="true"`. После этого система видит приложение как кандидата на роль домашнего экрана: при нажатии Home Android строит intent `MAIN` + `CATEGORY_HOME` и резолвит его среди всех совпадающих активностей. Если кандидат один - запускается он; если несколько - система показывает выбор «Always / Just once».

## Как пользователь назначает роль

- **Android 10+ (API 29+):** есть системный механизм ролей. Приложение запрашивает роль домашнего экрана штатным системным запросом - открывается системный диалог подтверждения. Назначение - всегда через системный UI; программно «забрать» роль нельзя.
- **Старее API 29 (в т.ч. legacy 23-25):** отдельного механизма роли нет. Сценарий - отправить пользователя в системный выбор лаунчера по умолчанию (системные настройки домашнего экрана) либо положиться на системный выбор «Always/Just once», который Android показывает сам при первом нажатии Home при наличии нескольких кандидатов.

Общий продуктовый сценарий: единая кнопка «Сделать домашним экраном» → на новых версиях системный запрос роли, на старых - переход в системные настройки выбора лаунчера, с понятной подсказкой, что выбрать.

## Снятие роли

Программно снять роль нельзя ни на одной версии. «Перестать быть домашним экраном» = открыть тот же системный экран настроек домашнего экрана/роли, где пользователь выбирает другой лаунчер. Продукт обязан дать видимый путь к этому экрану из своих настроек, иначе пользователь рискует «застрять».

## Ключевые выводы для спеки

- Нельзя форсить роль программно - только привести пользователя к системному UI. Это не ограничение реализации, а инвариант платформы (отражено в Non-goals и ADR-1).
- Нужна корректная деградация: новая версия → системная роль; старая → системные настройки выбора лаунчера; в обоих случаях базис - объявленный Home-intent-фильтр.
- Обязателен всегда-доступный выход и путь к смене лаунчера (риск «застрял», §7).
