# 03 - Профили лаунчера и охват флейворов

**Связано с §6.3 спеки S0404.** Дата: 2026-06-11.

## Существующий механизм профилей устройства

В проекте уже есть first-run device profile setup и матрица пресетов (`dev/DEVICE_PROFILE_PRESET_MATRIX.md`, данные `app_v2/src/main/assets/device_profile_presets.csv`): пользователь выбирает профиль устройства (телефон, планшет, ТВ, медиабокс, фоторамка, VR-headset и т.д.), и применяются оптимизированные дефолты (типы контента, лейауты, поведение экрана, безопасность). Среди пресетов уже есть «фоторамка» и «медиаплеер».

Вывод: профили лаунчера (фоторамка/аудио/читалка) - не новая сущность, а режимы домашнего экрана поверх существующих пресетов. Маппинг:

- **Фоторамка** → пресет фоторамки; домашний экран = текущий показ/слайдшоу + часы/дата.
- **Аудио** → аудиосценарий; домашний экран = что играет + управление воспроизведением.
- **Читалка** → сценарий чтения; домашний экран = последняя книга + прогресс.

Это исключает дублирование настроек и согласуется с ADR-2.

## Охват флейворов

Из матрицы возможностей флейворов (`app_v2/build.gradle.kts`):

- **standard / legacy:** полный набор (video/audio/images/docs) - все три профиля доступны. Целевые флейворы.
- **photos:** только изображения (нет audio/video/docs). Профиль «фоторамка» - естественен; «аудио»/«читалка» нерелевантны. Если лаунчер включён в `photos`, доступен лишь профиль фоторамки.
- **lite:** video + images, без cloud/docs/audio-фона/default-player (`SUPPORTS_DEFAULT_PLAYER=false`, `ENABLE_PERSISTENT_AUDIO_PLAYBACK=false`). Профиль «аудио» (фоновое аудио выключено) и «читалка» (нет docs) нерелевантны; остаётся только фоторамка. Учитывая минималистичную цель `lite` (старые устройства, экономия), включение режима лаунчера спорно - вынесено на решение владельца (§3.3).
- **vr:** собственная OpenXR-оболочка и системный шелл headset'а - режим Android-лаунчера неприменим. Исключён.

## Что показывать при отсутствии способности профиля

Доступность профиля на домашнем экране должна определяться возможностями флейвора, а не падать. Если профиль нерелевантен флейвору (например, «аудио» в `photos`), он просто не предлагается. Способность лаунчера и набор доступных профилей абстрагируются интерфейсом в `src/main/` с флейвор-специфичными реализациями (включая «нет-способности») - по `dev/FLAVOR_DEVELOPMENT_RULES.md`, без `BuildConfig.IS_*`-гейтов в общем коде (§3.2, ADR-1).

## Ключевые выводы для спеки

- Профиль лаунчера = надстройка над device-profile-пресетом (ADR-2), маппинг 1:1 для трёх сценариев.
- Доступность профилей зависит от возможностей флейвора; `photos` - только фоторамка.
- `lite`: решение владельца (вероятно, только фоторамка либо вовсе без лаунчера).
- `vr` исключён.

## Источники
