# 02 - Видимость и запуск установленных приложений (Android 11+)

**Связано с §6.2 спеки S0404.** Дата: 2026-06-11.

## Проблема видимости пакетов

С Android 11 (API 30), если приложение таргетит API 30+, оно по умолчанию видит лишь отфильтрованный список других приложений. Методы перечисления (запрос активностей по intent, получение списка установленных приложений) без деклараций вернут урезанный/пустой результат. Проект таргетит API 35 - ограничение применимо напрямую.

## Play-совместимый путь для лаунчера

Чтобы видеть запускаемые приложения, лаунчер декларирует в манифесте запрос видимости активностей с фильтром `MAIN` + `CATEGORY_LAUNCHER` (элемент `<queries>` с этим intent). Это штатный, Play-совместимый способ: лаунчерам разрешено видеть все «запускаемые» активности, не запрашивая широкое разрешение.

Широкое разрешение «видеть все пакеты» (`QUERY_ALL_PACKAGES`) - чувствительное и ограничено в Play Console; для перечисления запускаемых приложений оно не нужно и нежелательно (риск отклонения релиза, §7, ADR-3).

## Перечисление и запуск

- **Перечисление:** два штатных подхода - резолв implicit-intent `MAIN`/`LAUNCHER` (после декларации `<queries>`) либо специализированный системный сервис для лаунчеров, который дополнительно профиле-осведомлён (рабочие профили, несколько пользователей устройства). Для «полного списка запускаемых приложений» специализированный сервис предпочтительнее: он изначально предназначен для лаунчеров и корректно отдаёт иконку/метку/профиль.
- **Запуск:** по выбранному приложению запускается его launch-intent. «Избранные приложения профиля» - это просто сохранённый набор идентификаторов приложений из того же перечисления.

## Учёт нескольких профилей пользователя

На устройствах с рабочим профилем/несколькими пользователями один и тот же пакет может присутствовать в разных профилях. Полноценный лаунчер должен учитывать это при перечислении и запуске. Для первой итерации достаточно основного профиля пользователя; мультипрофильность - точка расширяемости реестра приложений (§5.3), не обязательная к первой версии.

## Ключевые выводы для спеки

- Декларация `<queries>` для `MAIN`/`LAUNCHER` - обязательна; `QUERY_ALL_PACKAGES` - не использовать.
- Реестр приложений абстрагируется от способа перечисления, чтобы менять механику под будущие версии Android (§5.3).
- Мультипрофильность - расширение, не блокер первой итерации.
