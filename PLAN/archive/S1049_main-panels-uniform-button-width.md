## 1. Проблема

На главном экране в портретном режиме четыре верхние горизонтальные полосы - командная панель (выход, добавление ресурса, поиск, обновление, настройки, избранное, старт плеера), панель "Программы и сценарии", панель стримов и полоса ресурсных табов - используют разную ширину кнопочной ячейки и разный шаг между кнопками. Из-за этого кнопки не выстраиваются в общую колонку: даже если первая кнопка каждой полосы стартует с одной и той же точки, вторая, третья и последующие кнопки соседних полос уже не оказываются друг под другом. По впечатлению владельца от реального экрана лучший, наиболее удобный "под палец" размер кнопки - у панели "Программы и сценарии"; остальные три полосы к этому эталону сейчас не приведены.

## 2. Цели

1. В портретном режиме кнопки всех четырёх верхних полос (командная панель, панель программ, панель стримов, полоса ресурсных табов) визуально выровнены в общую колонку - видно, что кнопки стоят одна под другой, без ступенчатого смещения.
2. Ширина кнопочной ячейки во всех четырёх полосах приведена к единому эталону - размеру ячейки панели "Программы и сценарии" ("под палец").
3. На узких и широких телефонах выравнивание сохраняется без ручной подгонки под конкретную модель.
4. Существующее поведение прокрутки, переполнения (overflow), сворачивания панелей и переключения ресурсных табов не нарушено.

**Non-goals:**

- Полный редизайн состава, порядка или иконографики кнопок - меняется только геометрия/выравнивание ячеек.
- Ландшафтная раскладка не является основной целью; правится только при необходимости обязательной технической зеркальной правки парного layout.
- Пересмотр уже принятого решения о едином стартовом горизонтальном якоре (leading anchor) для первого элемента полосы - эта спека строится поверх него, а не заменяет его.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Эталон желаемой ширины кнопки - панель "Программы и сценарии": по впечатлению владельца там сейчас лучший, наиболее удобный "под палец" размер.
2. Результат должен читаться как ровная колонка кнопок сверху вниз, без "ступенек" между полосами.

### 3.2 Жёсткие ограничения

- **Flavor:** все app_v2 flavor'ы, где присутствует главный экран списка ресурсов - тот же охват, что и у предшествующей работы по выравниванию верхних полос.
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается - модуль wear/ отдельный, к главному экрану ресурсов app_v2 не относится.
- **Производительность:** без дополнительной измеримой нагрузки - изменение только в геометрии/presentation, не в данных или бизнес-логике.
- **Совместимость данных:** без миграций, без влияния на persisted state панелей.
- **Локализация:** новые строки не требуются - меняется только геометрия существующих кнопок.
- **Доступность:** touch target ни одной кнопки не должен опускаться ниже платформенного минимума при унификации ширины; порядок D-pad/TalkBack фокуса и обнаруживаемость overflow должны сохраниться.

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** унификация ширины кнопочной ячейки применяется к верхней навигационной зоне главного экрана ресурсов (командная панель + панель программ + панель стримов + полоса ресурсных табов), портретная ориентация - основной охват; ландшафтная раскладка не меняется по существу.
- **Accessibility:** унифицированная ширина ячейки не может быть меньше текущего платформенного минимума touch target; существующая цепочка D-pad/TalkBack фокуса (nextFocus*) и обнаруживаемость overflow-кнопок сохраняются без изменений.
- **Validation level:** визуальная проверка на реальном устройстве в портретном режиме на узком и широком экране - колонка кнопок совпадает по X и по ширине ячейки с эталоном панели "Программы и сценарии"; регрессия touch target отсутствует.
- **Owner sign-off:** 2026-07-15 - принято из исходного запроса владельца в чате.
- **Related tickets:** S1037 (`main-top-panels-horizontal-alignment`, статус `BlockNeedUserTest`) - ввёл общий стартовый горизонтальный якорь для первого элемента панели программ, панели стримов и полосы ресурсных табов. Эта спека строится поверх этого якоря, распространяет выравнивание на командную панель (четвёртая полоса, ранее вне охвата S1037) и добавляет требование единой ширины ячейки для всех кнопок, а не только первой.

## 4. Контекст текущей архитектуры

Главный экран собирает верхнюю навигационную зону из четырёх независимых горизонтальных полос: полосы командных кнопок, панели "Программы и сценарии", панели стримов и полосы ресурсных табов. Каждая полоса описывается собственным presentation-компонентом со своей логикой размещения элементов: полоса командных кнопок сейчас не задаёт минимальную ширину ячейки и плотно обтягивает иконки почти без отступа; панели программ и стримов используют общий модуль минимальной ширины кнопки и, по предшествующей работе (см. §3.3, S1037), общий стартовый горизонтальный якорь для первого элемента; полоса ресурсных табов использует стандартное поведение табов с растяжением на всю ширину экрана и равномерным делением этой ширины между видимыми табами.

Эти три разные стратегии размещения - плотное обтягивание по контенту, фиксированный модуль ширины с общим стартовым якорем, равномерное растяжение на всю ширину - не подчинены общему контракту ширины ячейки. Поэтому даже после выравнивания стартовой точки первого элемента кнопки второго, третьего и последующих элементов в разных полосах не совпадают по X-позиции: визуальная колонка "плывёт" начиная со второй ячейки.

## 5. Предлагаемый подход

Ввести единый переиспользуемый модуль ширины кнопочной ячейки, откалиброванный по эталону панели "Программы и сценарии", и распространить его на командную панель и панель стримов поверх уже существующего общего стартового якоря. Полоса ресурсных табов переходит на фиксированную ширину ячейки, кратную этому модулю: по решению владельца (§6) каждый таб занимает две ячейки модуля, так как несёт текстовую подпись, а не только иконку - границы табов остаются на общей сетке, отказ от растяжения на всю ширину принят как осознанный компромисс.

### 5.1 Основные столпы / модули

- Единый модуль ширины кнопочной ячейки для командной панели, панели программ и панели стримов, поверх уже существующего общего стартового якоря.
- Полоса ресурсных табов переходит на фиксированную ширину ячейки, равную двум модулям ширины верхних панелей на таб (решение §6), вместо растяжения на всю ширину.
- Сохранение существующих механизмов прокрутки/overflow/сворачивания панелей без функциональных изменений.

### 5.2 Потоки данных и событий

- Пользователь открывает главный экран ресурсов в портретном режиме.
- Presentation-слой строит все четыре верхние полосы по общему модулю ширины ячейки (для полосы табов - по решению из §6).
- При нехватке места каждая полоса продолжает использовать свой текущий механизм overflow/scroll/collapse, но уже поверх выровненной сетки.

### 5.3 Точки расширяемости

- Общий модуль ширины ячейки должен быть переиспользуем, если в будущем к верхней зоне добавится ещё одна полоса.
- Решение по табам (§6) должно быть задокументировано так, чтобы будущая дополнительная полоса могла явно выбрать одну из тех же двух стратегий.

## 6. Открытые вопросы / Research items

1. **Полоса ресурсных табов: единая ширина ячейки или растяжение на всю ширину**
   - **Вопрос:** должна ли полоса ресурсных табов перейти на тот же модуль ширины ячейки, что и остальные три полосы (тогда после последнего таба на широких экранах останется пустое место), или сохранить текущее растяжение на всю ширину экрана (тогда её колонки не будут в точности совпадать с колонками остальных полос)?
   - **Варианты:** (a) фиксированная ширина ячейки как у панели программ, с пустым хвостом справа на широких экранах; (b) сохранить растяжение на всю ширину, выровняв только общий стартовый якорь (уже сделано предшествующей работой S1037); (c) растяжение на всю ширину, но кратное модулю ширины ячейки (ширина таба = N × модуль), чтобы границы табов попадали в общую сетку там, где это арифметически возможно.
   - **Решение владельца (2026-07-15):** вариант (a) с уточнением - ширина ячейки каждого таба фиксируется равной двум модулям ширины верхних панелей (2× ширина ячейки панели "Программы"), а не одному. Табы несут текстовую подпись ("Все"/"Локальные"/SMB/S-FTP), а не только иконку, поэтому двойная ширина одновременно даёт место под подпись и остаётся кратной общей сетке - граница каждого таба совпадает с границей чётной колонки остальных панелей. Пустой хвост справа принимается как компромисс там, где 4 таба × 2 модуля не дотягивают до полной ширины экрана.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Единый модуль ширины кнопочной ячейки поверх существующего стартового якоря**

- **Решение:** ввести один переиспользуемый модуль минимальной ширины кнопочной ячейки, откалиброванный по панели "Программы и сценарии", и применить его к командной панели и панели стримов; полоса ресурсных табов решается отдельно (§6).
- **Альтернативы:** оставить как есть - только общий стартовый якорь без единой ширины ячейки; отклонено, так как не решает жалобу владельца о расхождении колонки начиная со второй кнопки.
- **Почему:** минимальное расширение поверх уже принятого архитектурного решения (общий стартовый якорь из S1037), без нового слоя абстракции.

## 10. Связи с другими спеками

- S1037 (`main-top-panels-horizontal-alignment`, статус `BlockNeedUserTest`) - предшествующая работа, которая ввела общий стартовый горизонтальный якорь для первого элемента панели программ, панели стримов и полосы ресурсных табов. Эта спека расширяет её на командную панель и добавляет требование единой ширины ячейки для всех кнопок.

## 11. Критерии готовности (strategic-level)

1. В портретном режиме на реальном устройстве кнопки командной панели, панели программ и панели стримов визуально образуют общую колонку - совпадают по X и по ширине ячейки с эталоном панели "Программы и сценарии".
2. Полоса ресурсных табов реализована с шириной ячейки в два модуля на таб (§6) и не создаёт визуально случайного разрыва с остальными тремя полосами.
3. На узком и широком телефоне в портретном режиме выравнивание сохраняется без ручной донастройки под конкретную модель.
4. Overflow, прокрутка, сворачивание панелей и переключение ресурсных табов работают как раньше.
5. Touch target ни одной кнопки не стал меньше текущего платформенного минимума.
