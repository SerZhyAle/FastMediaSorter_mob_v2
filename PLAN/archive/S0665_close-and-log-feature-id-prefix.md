**Захвачено:** 2026-06-24
**Захвачено во время:** S0662 (финализация через close-and-log)

**Текст:**

`scripts/spec_catalog/close-and-log.ps1 -FuncOp ADD` записывает в `docs/ALL_FEATURES.jsonl` запись, у которой `id` начинается с id спеки (`s<NNNN>.<slug>`), а не с area-slug. `scripts/all_features/validate.ps1` это отвергает: "uses a spec id as area prefix; use the area slug" и падает с exit 1.

Симптом наблюдался при финализации S0662: close-and-log создал `s0662.welcome-gesture-enablement` (исправлено вручную на `onboarding.welcome-gesture-enablement`). При этом validate.ps1 выявил ещё 4 пре-существующих записи с тем же дефектом, созданных прошлыми тикетами тем же путём - то есть баг повторяющийся, а не разовый.

Вывод validate.ps1 (после ручного фикса записи S0662):

```
ALL_FEATURES validation FAILED (4 error(s)) in docs/ALL_FEATURES.jsonl
  L397: id 's0646.simple-value-selection-across-settings-unified-to-one' uses a spec id as area prefix; use the area slug
  L398: id 's0656.welcome-onboarding-now-surfaces-a-statistics-collection-toggle' uses a spec id as area prefix; use the area slug
  L399: id 's0644.settings-list-value-trigger-rows-now-show-the' uses a spec id as area prefix; use the area slug
  L400: id 's0648.download-resource-and-screenshot-destination-settings-rows-now' uses a spec id as area prefix; use the area slug
```

Объём работы:
- Починить деривацию `id` в close-and-log (`-FuncOp ADD`) - использовать area-slug (из `-FeatArea`) как префикс, а не id спеки. Согласовать с тем, как `scripts/all_features/add.ps1` строит id напрямую.
- Починить 4 существующие записи (S0646/S0656/S0644/S0648) на корректный `<area-slug>.<feature>`.
- Проверить, что после фикса `validate.ps1` проходит чисто.

**Вложения:**

Вложений нет.

---

## 1. Проблема

`close-and-log.ps1 -FuncOp ADD` выводил `id` записи `ALL_FEATURES` из id спеки (`s<NNNN>.<slug>`), тогда как инвентарь требует `<area-slug>.<feature>`. `validate.ps1` отвергает spec-id как префикс области и падает с exit 1, что блокирует пост-чейндж гейт. Дефект повторялся при каждой финализации с `-FuncOp ADD`, накопив 4 невалидные записи (S0646/S0656/S0644/S0648).

---

## 2. Цели

1. `close-and-log.ps1 -FuncOp ADD` генерирует `id` с area-slug в качестве префикса (слугификация `-FeatArea`), согласованно с `all_features/add.ps1` и контрактом `validate.ps1`.
2. Пустой/отсутствующий `-FeatArea` даёт фолбэк-префикс `general`, а не падение валидации.
3. Четыре существующие невалидные записи (S0646/S0656/S0644/S0648) исправлены на `<area-slug>.<feature>`.
4. `validate.ps1` проходит чисто (exit 0).

**Non-goals:**

- Не трогаем removed-надгробия (например `s0490.*`) - их исторический id заморожен по дизайну `validate.ps1`.
- Не меняем сам контракт id в `add.ps1`/`validate.ps1` - правим только деривацию в `close-and-log.ps1`.
