# S1183 - Вывод adb.ps1 нельзя перенаправить в файл

**Status:** Archived
**Priority:** 45
**Created:** 2026-07-24

## 0. Исходный материал (verbatim)

Обнаружено при device-тесте S1174 на emulator-5554, 2026-07-24.

Сообщение исполнителя:

> **Tooling gap:** `scripts/devtest/adb.ps1` writes its verb output with `Write-Host`, so
> `adb.ps1 shell -Cmd 'logcat -d' | Out-File …` silently produces an empty file. I fell back to
> invoking `adb.exe` directly for the raw logcat captures. Worth making the `shell`/`log` verbs emit
> to the success stream (or having `log` write a raw sink under a caller-supplied path).

## 1. Симптом

`adb.ps1` печатает результат команды через `Write-Host`, то есть в информационный поток, а не в поток успеха. Поэтому конвейер и перенаправление получают пустоту:

```
adb.ps1 shell -Cmd 'logcat -d' | Out-File temp/scratch/raw.log   # файл создан, но пустой
```

На экране агент видит вывод и считает, что команда отработала; на диске остаётся пустой файл. Ошибка не поднимается - молчаливая потеря данных.

## 2. Почему это важно

`adb.ps1` - основной ноль-токенный инструмент для device-работы (CLAUDE.md §9), и типовой сценарий именно такой: снять сырой logcat в файл под `temp/Sxxxx/`, потом грепать файл. Сейчас этот сценарий не работает, и обход - звать `adb.exe` напрямую - ломает правило «сначала обёртки проекта» и теряет автообнаружение adb, `-DeviceId` и коды возврата.

Уже есть смежная ловушка: `adb.ps1 log -Grep` предварительно фильтрует logcat по строкам с именем пакета и потому не находит пробы, залогированные под голым тегом класса. Обе проблемы бьют по одному и тому же - «достать сырой лог и разобрать его самому».

## 3. Почему это отдельный тикет

- Вне контракта S1174: это дефект инструментария, а не приложения.
- Затрагивает каждый device-скилл (`/spec-test-device`, `/spec-sweep`, `/log-reader`), а не один прогон.
- Требует решения по контракту вывода: смена потока может сломать вызывающие стороны, которые сейчас полагаются на то, что вывод только отображается.

## 4. Что предстоит выяснить

**Какие глаголы отдают данные в поток успеха.** Решено по признаку «что является продуктом глагола»:

- Продукт - **данные**: `devices`, `props`, `current`, `log`, `shell`. Их строки переведены на `Write-Output`.
- Продукт - **действие**: `launch`, `stop`, `tap`, `text`, `key`, `install`, `uninstall`, `push`, `logcat-clear`, `wipe-data`. Подтверждение остаётся на информационном потоке - конвейеру оно не нужно.
- Продукт - **файл**: `shot`, `prefs`, `pull`. Путь объявляется на информационном потоке, а для конвейера он есть в `-Json`. Иначе строка с путём поехала бы в данные и её пришлось бы отфильтровывать.
- Сводки, предупреждения и счётчики (`OK N line(s)`, `WARN ..`, `NOTE ..`) остаются на информационном потоке во всех глаголах: сводка - не данные.

**Не сломает ли смена потока существующие вызовы.** Нет. Все вызывающие стороны в дереве зовут скрипт отдельным процессом (`pwsh -NoProfile -File ..`), а `Write-Host` в дочернем процессе всё равно попадает в его stdout - значит внешние потребители, включая `smoke.ps1` и `prerelease-prepare.ps1`, которые матчат свой регекс по всему stdout, видят ровно то же, что и раньше. Меняется только внутрипроцессный случай, и там изменение чисто добавляющее: конвейер, который раньше получал пустоту, теперь получает данные. `-Json` не тронут - он идёт своей веткой до печати строк.

**Нужен ли `-OutFile` для `log`.** Нет. После починки потока `adb.ps1 log | Out-File <path>` работает сам, а полный сырой сток `log` и так всегда пишет в `temp/scratch/adb_log_<TS>.log`, печатает путь и кладёт его в `-Json`. Параметр был бы третьим способом сделать то же самое - лишний вес по правилу 20.

**Пред-фильтрация в `log -Grep`.** Отдельной правки не требует, она уже снята другой работой: S1332 сделал отбор строк по pid процесса приложения, а не по имени пакета в тексте, поэтому строки Timber под голым тегом класса больше не теряются; сверх того `log` печатает предупреждение, когда фильтр отбросил строки, подходящие под `-Grep`, и всегда сохраняет полный сырой захват. Сырой режим без всякой фильтрации теперь доступен прямо: `adb.ps1 shell -Cmd 'logcat -d'` - и именно он стал работать в конвейере благодаря этому тикету.

## 5. Статус проверки

Статически в этой сессии:

- Скрипт разбирается без ошибок; обе строки-полезной-нагрузки (`log`, `shell`) теперь `Write-Output`, как и строки `devices`, `props`, `current`.
- Контракт кодов возврата не изменился: без устройства `devices` по-прежнему отвечает `FAIL (2) - no online device`.
- Шапка скрипта описывает разделение потоков явно, чтобы следующий глагол попал в нужный поток по правилу, а не по образцу соседа.

На устройстве (не проверено - в сессии нет подключённого устройства):

1. `adb.ps1 shell -Cmd 'logcat -d' | Out-File temp/scratch/raw.log` даёт **непустой** файл.
2. `adb.ps1 log -Tail 50 | Measure-Object -Line` считает строки больше нуля, а сводка `OK N line(s)` в файл не попадает.
3. `adb.ps1 devices`, `props`, `current` пайпятся в `Select-String` и находят свои значения.
4. `adb.ps1 launch` в конвейере отдаёт пустоту - подтверждение действия осталось индикацией.
5. `-Json` у всех перечисленных глаголов по-прежнему разбирается как один JSON-объект.

Отладочных меток `Timber.d` тикет не несёт: изменён один `.ps1`, Kotlin не затронут. Доказательство на устройстве - сами файлы и вывод команд.

### Как проверять этот тикет, чтобы проверка что-то значила

- Скрипт вызывается **в том же процессе**, оператором `&`. Дочерний `pwsh -NoProfile -File ..` сливает `Write-Host` в свой stdout, поэтому в нём любая проверка разделения потоков зелёная по неверной причине: проверки 2 и 4 прошли бы и на сломанной версии. Это ровно то различие, которое §4 называет «меняется только внутрипроцессный случай», и проверять надо именно его.
- Ловушка при написании проверки: массив аргументов, переданный сплаттингом (`& $adb @args`), связывается позиционно, поэтому `-Json` до параметра не доходит и глагол молча отвечает обычным текстом. В первом прогоне это дало пять ложных FAIL по пункту 5; после замены на явные вызовы все шесть зелёные. Дефект был в проверке, а не в скрипте.

### Воспроизведение

- Из сессии PowerShell в корне репозитория: `$a = 'scripts/devtest/adb.ps1'; & $a shell -Cmd 'logcat -d' | Out-File -LiteralPath raw.log; (Get-Item raw.log).Length` - ожидаемый результат больше нуля.
- Там же: `@(& $a launch).Count` - ожидаемый результат 0 при видимой на экране строке `LAUNCHED ..`.
