# Research 03 - §6 open-questions resolution (tactical decisions)

**Артефакт research для S0815 F2.** Resolves strategic §6 from codebase evidence (research 01/02). Best-practice defaults chosen and recorded; no owner block required (all four are conveyor/coverage questions the spec itself defers to `/spec-tech`).

## D1 - Inventory source (resolves §6.4)

**Decision:** live-scan generator emitting `docs/icons/icon-inventory.json`, mirroring the shipped settings-manifest system (`SettingsManifestExportTest` + `render-settings-reference.ps1` + `assert-settings-doc-sync.ps1`). Satisfies ADR-1 (derived from registries, not a second source of truth) and the "inventory устаревает" risk (§7) - a live scan self-heals via the drift gate.

- Kotlin-object surfaces scanned in a Robolectric JVM export test: `InternalRouteCatalog`, `OsShortcutCatalog` (+ new public `all()`), resource-type tiles (extracted to enumerable), `ShareTargetModule` `@Provides` (called directly), `PlayerCommand.entries`.
- XML-attr surfaces (settings headers `csh_icon`, rows `str_icon`/`ssr_icon`) scanned via the `XmlAttributeReader` pattern.
- Programs-toolbar-menu merged into the single "Program navigation" surface (overlaps App Launch Panel; not double-documented).
- Manifest entry fields: `surface`, `key`, `feature`, `drawable`, `assetFormat` (`vector`|`raster`|`framework`), `public` (bool).

## D2 - Asset format + location (resolves §6.1)

**Decision:** SVG with `fill="currentColor"`, under `docs/icons/svg/<drawable>.svg`.

- Convert each `vector` drawable (`res/drawable/ic_*.xml`) -> SVG via a PowerShell converter (`android:pathData` maps ~1:1 to SVG `<path d>`). Strip the placeholder `@android:color/white` tint; emit `currentColor` so icons inherit surrounding text color and work with the site light/dark toggle.
- `framework` icons (8 PlayerCommands using `android.R.drawable.*`): no SVG, listed by name in legend with a note.
- `raster` icons (3 cloud-provider brand PNGs): copied to `docs/icons/svg/` as `.png`, referenced via `<img>` (brand logos, legitimately raster).
- Location `docs/icons/` is under the `docs/**` Jekyll trigger; reachable from root HTML (`docs/icons/..`) and nested docs (`icons/..`). Avoids the phantom untracked `assets/**` path.

## D3 - Embedding method (resolves §6.2)

**Decision:** central trilingual **legend/reference page** as iteration-1 deliverable; inline per-feature embedding deferred to iteration 2.

- Iteration 1: `docs/ICON_LEGEND.md` / `_RU.md` / `_UK.md`, generated by `render-icon-legend.ps1` from inventory + annotations, grouped by surface. Each row = inline SVG `<img>` + drawable name + trilingual meaning + alt text (accessibility, §3.2). Linked from `docs/DOCS_MAP.md`.
- Rationale: legend is purely additive (no rewrite of existing prose), lowest-risk, and satisfies strategic criteria 1/2/3(partial)/4/5. The heavy trilingual risk (§7 "большой объём трилингвальных правок") lives in per-page inline embedding - correctly deferred.

## D4 - Meaning sourced from the app's own strings (not hand-authored)

**Decision (corrected):** the inventory's `feature` field is the entry name of the app string resource that labels the icon (verified: `cast_to_chromecast` -> "Cast to.."/"Трансляция..", `menu_crop` -> "Crop"/"Вырезать"). The legend renderer resolves `feature` -> the real string in `values{,-ru,-uk}/strings.xml`, so meanings are accurate, already-translated, and drift-free (ADR-1). A hand-authored `docs/icons/icon-annotations.json` is kept SMALL - only surface headings (5 x 3 locales) + the 7 resource-type enum-name fallbacks + an initially-empty `overrides` map for entries whose live string reads poorly out of context. This replaces the original "hand-author 117 x 3 meanings" plan (huge scope + drift risk).

## D5 - First-iteration coverage + deferred (resolves §6.3, satisfies criterion 5)

**In iteration 1:** inventory manifest + SVG assets + trilingual legend page + drift gate + convention doc. Covers all `public` icons across the 5 (merged to ~6) surfaces.

**Deferred to iteration 2 (documented, not built):**
- Replace emoji with real icons in `index.html`/`index-ru`/`index-uk` card slots and `docs/howto/index.md` (higher-touch trilingual HTML edits).
- Inline per-row icons in generated `docs/SETTINGS_REFERENCE*.md` (mechanical, but a change to the settings renderer - separate blast radius).

## D6 - Convention "icons instead of emoji" (satisfies criterion 4)

**Decision:** record as a docs-authoring convention in `docs/icons/README.md` (icon-usage guide) + one pointer line in `docs/DOCS_MAP.md`. Do NOT add a mechanical emoji-ban gate in iteration 1 (would flag all existing emoji across the site) - the convention governs future edits; a gate is a possible iteration-2 follow-up.

## Drift gate (D5 support)

`scripts/quality/assert-icon-inventory-sync.ps1` (model: `assert-settings-doc-sync.ps1`), wired into `post-change.ps1`:
1. Re-run export -> diff `icon-inventory.json` (freshness).
2. Every `public` icon has an SVG asset (or `framework`/`raster` note) + trilingual annotation (coverage).
3. Re-render legend -> byte-diff `ICON_LEGEND*.md` (freshness).
4. Cross-locale parity: same icons, same order across EN/RU/UK (model: `assert-howto-settings-paths.ps1`).
