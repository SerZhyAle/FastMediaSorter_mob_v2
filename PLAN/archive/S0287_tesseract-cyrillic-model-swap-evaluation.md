## 1. Проблема

Текущая реализация офлайн-распознавания кириллицы на базе Tesseract использует легковесный пакет моделей `tessdata_fast` (суммарный объём для русского и украинского языков составляет около 7.69 МБ). Эти модели оптимизированы под минимальный размер, но имеют невысокую точность распознавания на реальных снимках с шумами, размытием или сложным освещением.

Поскольку стратегические ограничения версии STANDARD запрещают бесконтрольное раздувание APK-файла (лимит до +15 МБ на весь bundled payload), мы не можем включить качественные модели `tessdata_best` (~26.16 МБ для RU + UK) непосредственно в сборку. При этом отсутствие встроенного механизма загрузки данных по требованию (install-on-demand) не позволяет пользователям легальной версии STANDARD получить доступ к качественному офлайн-распознаванию.

## 2. Цели

1. Разработать механизм загрузки и установки языковых моделей Tesseract по требованию пользователя непосредственно из интерфейса настроек приложения.
2. Обеспечить корректную интеграцию загруженных качественных моделей `tessdata_best` (`rus` и `ukr`) в существующий OCR-pipeline Tesseract4Android.
3. Добиться визуально заметного улучшения распознавания кириллического текста в офлайн-режиме на сценариях с естественным освещением и умеренным размытием краёв.
4. Предоставить пользователю возможность очистки кэша и удаления скачанных моделей для экономии дискового пространства.

**Non-goals:**

- Внедрение новых OCR-движков или библиотек в рамках данной спецификации.
- Изменение логики работы ML Kit OCR.
- Автоматическая фоновая загрузка моделей без ведома и явного согласия пользователя.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Процесс загрузки должен сопровождаться понятной индикацией прогресса (процент выполнения, объём данных).
2. Выбор скачиваемых моделей должен быть гранулярным: пользователь должен иметь возможность скачать отдельно русскую модель, отдельно украинскую, либо обе сразу.
3. Система должна автоматически проверять целостность скачанных файлов перед их подключением в движок распознавания.

### 3.2 Жёсткие ограничения

- **Flavor:** `standard` (с автоматическим наследованием для `vr`). Флейворы `lite` и `legacy` не затрагиваются.
- **API level:** Совместимость с текущим minSdk проекта, без повышения требований.
- **Wear OS:** Не затрагивается.
- **Производительность:** Время инициализации движка OCR с новыми моделями не должно увеличиваться более чем на 1.5 секунды на baseline-устройстве (Quest 3 / mid-range phone). Пиковое потребление памяти во время сессии распознавания не должно превышать 2× от текущего уровня.
- **Совместимость данных:** Скачиваемые файлы должны сохраняться в изолированной директории данных приложения, не требуя внешних разрешений на чтение/запись накопителя.
- **Локализация:** Полный паритет EN/RU/UK для всех новых строковых ресурсов (кнопки загрузки, статус-сообщения, диалоги ошибок).
- **Доступность:** Новые элементы интерфейса в настройках должны быть полностью совместимы с TalkBack, поддерживать навигацию с помощью D-pad (три режима ввода) и иметь достаточный контраст.
- **Communication policy:** Все новые диалоги, уведомления о загрузке и сообщения об ошибках сети должны быть согласованы с tone-checklist §6 документа `docs/COMMUNICATION_POLICY.md`.

## 4. Контекст текущей архитектуры

На данный момент OCR-pipeline приложения содержит реестр движков (engine registry), в котором зарегистрирован Tesseract4Android. Этот движок считывает файлы моделей из встроенных ресурсов (assets) или предустановленного каталога приложения. Модели `tessdata_fast` поставляются непосредственно внутри APK-файла.

Текущая архитектура не предусматривает динамического изменения путей к директории моделей (`tessdata/`) или горячего переключения файлов моделей без перезапуска сессии распознавания. Также отсутствует модуль управления сетевыми загрузками пассивных данных, интегрированный с настройками приложения.

---

## 5. Предлагаемый подход

Предлагается расширить существующий класс-менеджер Tesseract4Android, добавив поддержку динамического выбора источника моделей. Вместо чтения исключительно встроенных в APK файлов, движок будет опрашивать пользовательскую директорию данных приложения на наличие валидных файлов `tessdata_best`.

При обнаружении скачанных качественных моделей движок перенаправляет свой внутренний путь инициализации на динамическую директорию. Если файлы повреждены или удалены, система автоматически откатывается на использование встроенных моделей `tessdata_fast` в качестве безопасного fallback-режима.

### 5.1 Основные столпы / модули

* **Модуль динамической загрузки (Data Downloader):**
  * Отвечает за безопасное скачивание файлов моделей по протоколу HTTPS с доверенного зеркала репозитория проекта.
  * Поддерживает докачку при обрыве соединения, валидацию файлов по контрольной сумме (MD5/SHA-256) и обработку сетевых ошибок.
* **Слой управления моделями (Model Manager):**
  * Проверяет наличие скачанных файлов во внутреннем хранилище.
  * Управляет жизненным циклом файлов (установка, проверка целостности, удаление).
  * Предоставляет статус готовности моделей для UI-слоя.
* **Интерфейс управления в Settings:**
  * Интегрируется в существующий экран настроек.
  * Отображает текущий статус моделей (Не загружена / Доступно обновление / Установлена качественная модель).
  * Содержит элементы управления для скачивания и удаления.

### 5.2 Потоки данных и событий

1. Пользователь открывает экран настроек OCR .. опрашивается Слой управления моделями .. UI отображает текущие статусы.
2. Пользователь нажимает "Загрузить качественную модель (RU)" .. запускается Модуль динамической загрузки .. на UI транслируется прогресс операции.
3. По завершении скачивания файл проверяется по хэшу .. Слой управления моделями перемещает его в рабочую директорию и обновляет статус.
4. При следующем запуске сессии OCR Tesseract4Android обращается к Слою управления моделями .. получает путь к качественным файлам .. инициализирует движок с использованием `tessdata_best`.

### 5.3 Точки расширяемости

* **Абстракция сетевого клиента:** Модуль загрузки должен работать через высокоуровневый интерфейс загрузчика, чтобы в будущем можно было переключить источник файлов на другой хостинг без изменения бизнес-логики.
* **Реестр версий моделей:** Структура хранения должна позволять в будущем обновлять версии файлов моделей без изменения кода приложения через удалённый манифест версий.

## 6. Открытые вопросы / Research items

1. **Размещение файлов на хостинге**
   - **Вопрос:** Где физически разместить файлы моделей `tessdata_best` для надёжного и быстрого скачивания пользователями без VPN-ограничений в СНГ и глобально?
   - **Варианты:** GitHub Releases основного репозитория, Cloudflare R2 / AWS S3, зеркало на собственном сервере проекта.
   - **Нужно выяснить:** Скорость доступа и доступность указанных вариантов на тестовых устройствах в разных регионах.
   - **Статус:** Open

2. **Поведение при нехватке памяти во время инициализации best-моделей**
   - **Вопрос:** Насколько сильно возрастает риск OutOfMemory (OOM) на бюджетных устройствах при переходе с моделей `fast` на значительно более тяжёлые `best`?
   - **Нужно выяснить:** Провести профилирование потребления памяти на устройстве с 3-4 ГБ ОЗУ во время инициализации `rus.traineddata` (best) в сравнении с baseline.
   - **Статус:** Open

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Сбой сети или повреждение файла при скачивании | Высокая | Движок OCR не сможет инициализироваться и приложение упадёт | Обязательная проверка контрольной суммы файла перед установкой; автоматический fallback на встроенные `fast` модели при любых ошибках инициализации |
| Превышение лимита памяти (OOM) на старых устройствах | Средняя | Падение процесса при попытке распознавания heavy-изображений | Ограничение использования `best` моделей на устройствах с объёмом оперативной памяти менее 3 ГБ; вывод предупреждения в UI |
| Проблемы с дисковым пространством у пользователя | Средняя | Невозможность завершить скачивание, частичные файлы | Проверка свободного места на диске перед началом скачивания; отображение понятной ошибки нехватки места |

## 9. Архитектурные решения (ADR)

**ADR-1: Использование пассивных файлов данных (Data-only Download)**

- **Решение:** Для улучшения распознавания загружаются исключительно passive data files моделей Tesseract (`.traineddata`). Исполняемые библиотеки (`libtesseract.so` и др.) остаются жестко вкомпилированными в APK.
- **Альтернативы:** Динамическая подгрузка native-библиотек под разные архитектуры (DCL).
- **Почему:** Прямой запрет политик Google Play на dynamic code loading делает подгрузку бинарных файлов критическим риском для блокировки всего портфолио приложений. Пассивные данные не несут рисков безопасности.

**ADR-2: Безопасный Fallback-режим по умолчанию**

- **Решение:** Встроенные в APK модели `tessdata_fast` остаются в проекте навсегда. Качественные модели подключаются как опциональное переопределение.
- **Альтернативы:** Полное удаление встроенных моделей для сокращения размера APK и принудительная загрузка при первом старте.
- **Почему:** Принудительная загрузка ломает базовый offline-first паттерн приложения: пользователь должен иметь возможность базового распознавания сразу после установки из маркета без доступа к сети.

## 11. Критерии готовности (strategic-level)

1. Пользователь видит новые опции загрузки качественных моделей в разделе настроек OCR.
2. Процесс скачивания отображает корректный прогресс в процентах и обрабатывает потерю сети без падения приложения.
3. После успешной загрузки моделей `tessdata_best` движок распознавания переключается на них, обеспечивая более высокую точность на тестовых фотографиях с размытием и перспективой.
4. При удалении моделей через настройки дисковое пространство освобождается, а движок незамедлительно возвращается к работе со встроенными моделями `fast`.
