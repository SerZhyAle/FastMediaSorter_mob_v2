## 1. Проблема

В панельном плеере (`PlayerActivity`) три отдельных, но смежных бага UX, мешающих корректно работать со стерео-форматами:

**Б1 — «Показывать один глаз» отсутствует в настройках лендшафта.**
В коде есть переменная `panelStereoSingleEye=false` (видно в логе на line 555: `VideoPlayerManager: panelStereoSingleEye=false — re-applying video effects`), значит логика «показывать только один глаз стерео-кадра на плоской панели» реализована. Однако соответствующего тумблера в настройках приложения (лендшафтный режим панельного плеера) пользователь не нашёл. Либо UI элемент потерян при рефакторинге, либо не был добавлен изначально. Без UI-контрола функция недоступна.

**Б2 — Триггер «Переопределить тип формата» в диалоге управления видео имеет рассогласованный layout.**
Текст пункта прижат к левому краю строки, тогглер — к правому. У большинства других подобных строк в приложении эти два элемента стоят рядом (текст слева, тогглер сразу справа от текста). Текущий вариант визуально выглядит как баг и нарушает консистентность с остальным UI.

**Б3 — Опция «Автоопределение» в подзакладке 3D диалога управления видео не задерживается.**
При попытке выбрать пункт «Автоопределение» в списке доступных режимов 3D пользователь видит, что выбор моментально перепрыгивает на одну из конкретных опций (например, SBS / OU / Mono). Эффект: пользователь не может зафиксировать «авто-определение по имени и метаданным». При этом сам список содержит пункт «авто», то есть логика его поддержки заявлена в UI.

Все три проблемы — UX-уровневые, не затрагивают рендер или маршрутизацию. Они снижают доверие к диалогу управления видео в целом.

## 2. Цели

1. **Тумблер «Показывать один глаз»** виден в настройках панельного режима плеера. Его состояние сохраняется (как остальные тумблеры) и применяется к воспроизведению.
2. **Layout пункта «Переопределить тип формата»** соответствует общему паттерну приложения: текст и тогглер — рядом друг с другом в одной строке, без визуальных разрывов.
3. **«Автоопределение»** в списке 3D-режимов выбирается и остаётся выбранным. Если фактическая логика «не может определить формат» — это отображается отдельно (например, в подсказке или вторичной строке), но пункт меню продолжает быть в состоянии «выбран = автоопределение».
4. Поведение всех трёх фиксов одинаково на всех флейворах, где доступен `PlayerActivity` (фактически — все).
5. Без новых строк локализации, кроме одной — для тумблера «Показывать один глаз», если её ещё нет (есть подозрение, что строка существует и потерян только UI-элемент).

**Non-goals:**

- Не пересматривается общий дизайн диалога управления видео.
- Не вводятся новые опции в списке 3D-режимов.
- Не меняется логика автоматического определения формата (это объём S0012 / S0026).
- Не покрывается VR-флейвор-специфика: эти проблемы относятся к панельному UI, который есть и в VR, и в phone-сборке.

## 4. Контекст текущей архитектуры

`PlayerActivity` имеет: (а) экран настроек (лендшафтный режим, доступен из toolbar), (б) диалог управления видео (bottom sheet с закладками: общие настройки, 3D-формат, аудио-дорожки, субтитры, и т. д.).

**Б1 — Single-Eye toggle.** Переменная `panelStereoSingleEye` упоминается в `VideoPlayerManager`. Где-то существует чтение этой переменной из настроек (DataStore/SharedPreferences) и где-то — UI-элемент. Если в UI отсутствует — нужно либо вернуть, либо добавить заново. Ключи существующих настроек проверяются по `dev/CATALOG/app_v2.md` через query.

**Б2 — Override-format trigger layout.** Стандартный паттерн «текст + тогглер в одной строке» — это `LinearLayout horizontal` или `ConstraintLayout` с правильными констрейнтами. Текущий вариант — текст с `gravity=start` и тогглер с `gravity=end` без констрейнта, что даёт «прижаты по краям». Фикс — поменять layout на стандартный.

**Б3 — «Авто» в 3D-меню.** Список режимов 3D реализован, скорее всего, как `RecyclerView` или `ListView` с radio-button. Обработчик клика, возможно, имеет преждевременную логику «при выборе авто сразу запустить детекцию и установить detected-режим как выбранный». Это даёт эффект «прыжка». Корректное поведение: «авто» — это собственное состояние пользовательского выбора; детекция же определяет фактический режим рендера, не выбор пользователя.

## 5. Предлагаемый подход

Подход — три независимых фикса, объединённых одной спекой только потому что они в одной зоне UI и без отдельной спеки каждый из них тривиален.

### 5.1 Основные столпы / модули

**Б1 — Восстановление тумблера «Показывать один глаз».**
Найти существующий тумблер в layout-XML настроек панели; если отсутствует — добавить новую строку рядом с другими стерео-связанными тумблерами. Привязать к существующему DataStore-ключу, который уже читается в `VideoPlayerManager`. Если ключа нет — добавить ключ и дефолт `false`. Локализационная строка (текст тумблера + описание) проверяется на наличие в EN/RU/UK; добавляется при отсутствии.

**Б2 — Layout пункта «Переопределить тип формата».**
Найти XML-файл диалога управления видео (или включаемого фрагмента диалога); поправить layout-параметры строки «Override format type» так, чтобы текст и тогглер были в одной горизонтальной группе с минимальным визуальным разрывом. Использовать тот же шаблон, что у соседних строк диалога. Изменения только в XML, без правок Kotlin-логики.

**Б3 — «Авто» в 3D-меню.**
Обработчик клика на пункте «Авто» должен:

1. Сохранить состояние пользовательского выбора как `AUTO`.
2. Запустить детекцию формата (если ещё не запущена).
3. Использовать результат детекции для рендера, **не** меняя UI-выбор «Авто».

Текущее поведение «UI-выбор скачет на конкретный режим» — это смешение двух понятий («что выбрал пользователь» vs «какой режим использует рендерер»). Решение: разделить эти два состояния в ViewModel; UI-выбор отображает первое, рендерер использует второе. Дополнительная строка «определено как: SBS» (вторичная подсказка) допустима, но основной выбор остаётся `AUTO`.

### 5.2 Потоки данных и событий

**Б1.** `Settings UI → toggle changed → DataStore.setBoolean(KEY_PANEL_SINGLE_EYE) → Flow → VideoPlayerManager applies effect`.

**Б2.** Никаких runtime-событий — только статический layout.

**Б3.** `User clicks "Auto" → ViewModel.userStereoPreference = AUTO → DataStore save → StereoDetector runs → ViewModel.effectiveStereoMode = SBS|OU|MONO|... (UI radio remains on AUTO; secondary label shows effective mode)`.

### 5.3 Точки расширяемости

- Если в будущем добавится новый формат стерео — UI-список расширяется без изменения архитектуры «AUTO как самостоятельное состояние».
- Если потребуется per-file (а не per-app) сохранение «авто vs ручной выбор» — расширяется через extension существующего хранилища.

## 9. Архитектурные решения (ADR)

**ADR-1: «User preference» и «effective mode» — разные состояния ViewModel.**

- **Решение:** в ViewModel плеера два независимых поля: `userStereoPreference` (что выбрал пользователь, в т. ч. `AUTO`) и `effectiveStereoMode` (что использует рендерер). UI-radio показывает `userStereoPreference`; рендерер использует `effectiveStereoMode`.
- **Альтернативы:** одно поле «эффективный режим» с лейблом «(auto-detected)» — отвергнуто, потому что не позволяет UI отображать «AUTO» как выбор.
- **Почему:** разделение источников истины убирает класс ошибок «UI-выбор скачет, потому что внутри логика перезаписывает».

**ADR-2: Тумблер «Показывать один глаз» — DataStore-ключ + Flow в ViewModel + view binding.**

- **Решение:** стандартный паттерн настройки приложения: ключ в DataStore, Flow в ViewModel, биндинг к Material Switch в settings layout.
- **Альтернативы:** хранить в SharedPreferences — отвергнуто, проект давно перешёл на DataStore.
- **Почему:** консистентность с остальными настройками.

**ADR-3: Layout-фикс — XML-only.**

- **Решение:** Б2 решается правкой layout-XML без изменений в Kotlin/Java.
- **Альтернативы:** custom view — отвергнуто как избыточное для строки «текст + тогглер».
- **Почему:** XML-fix минимизирует риск регрессии в логике диалога.

## 11. Критерии готовности (strategic-level)

1. В настройках панельного режима плеера присутствует тумблер «Показывать один глаз»; его переключение реально влияет на отображение стерео-файла (плоская панель показывает только левую половину).
2. В диалоге управления видео строка «Переопределить тип формата» имеет текст и тогглер рядом друг с другом, как у других строк диалога.
3. В подзакладке 3D диалога управления видео выбор «Автоопределение» остаётся выбранным; UI-индикатор не скачет на конкретный детектированный режим.
4. Если детекция определила конкретный режим, информация об этом доступна пользователю (опциональная подсказка), но пользовательский выбор «Авто» сохраняется.
5. Поведение одинаково на всех флейворах.
6. Локализация EN/RU/UK содержит строку для тумблера «Показывать один глаз», если её не было.
