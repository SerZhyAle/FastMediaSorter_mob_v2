## 1. Проблема

В режиме системного лаунчера Android одновременно показывает собственную строку состояния и дублирующие часы, сеть и батарею в интерфейсе FMS. Это занимает место на небольших экранах и создаёт визуальный шум. Пользователь должен сам выбрать единственный источник этой информации, не теряя доступ к системному статусу по умолчанию.

---

## 2. Цели

1. Добавить настройку «Замещать системную область уведомлений и статуса» в настройках системного лаунчера.
2. При выключенной настройке оставлять системную строку видимой и скрывать дублирующие часы, сеть и батарею в панели FMS.
3. При включённой настройке скрывать системную строку только на экране лаунчера и показывать собственные индикаторы FMS.
4. Немедленно применять изменение без перезапуска и сохранять выбор между запусками.

**Non-goals:**

- Интерактивные действия по касанию собственных индикаторов.
- Изменение панели навигации Android.
- Изменение системных строк на экранах, не являющихся лаунчером.

## 4. Контекст текущей архитектуры

Режим системного лаунчера уже имеет отдельные настройки состава панели и наблюдает сохранённые настройки на UI-слое. Экран лаунчера одновременно владеет собственной панелью и window-insets, поэтому только он может согласованно скрывать системную область и менять собственные индикаторы.

Текущая настройка «Show clock and status» управляет отображением панели, но не выражает выбор между системной и собственной областью. Нужен отдельный сохранённый выбор с обратной совместимостью: после обновления остаётся системная строка, а дубликаты FMS не отображаются.

---

## 5. Предлагаемый подход

Добавить один флаг предпочтения области статуса в существующую модель настроек и её persistent storage. Экран конфигурации лаунчера меняет этот флаг, а host экрана лаунчера наблюдает его вместе с остальными настройками панели.

При выключенном флаге host показывает системную строку и передаёт в собственную панель режим без часов, сети и батареи. При включённом флаге host скрывает только status bar через совместимый insets API и передаёт полный режим собственной панели. При остановке или уходе с launcher host всегда восстанавливает системную строку.

### 5.1 Основные столпы / модули

1. Сохранённое предпочтение и обратная совместимость.
2. Строка настройки и три локали.
3. Применение системной строки с симметричным восстановлением.
4. Вычисление состава собственной панели без дублирования.

### 5.2 Потоки данных и событий

Настройка UI -> ViewModel -> settings repository -> persistent preferences -> settings Flow -> launcher host -> system bars и модель собственной панели.

### 5.3 Точки расширяемости

Политика состава собственной панели остаётся отдельной от будущих интерактивных действий по индикаторам. Будущие профили устройства могут менять начальное значение только через существующий механизм preset, но не переопределяют явный выбор пользователя.

## 6. Открытые вопросы / Research items

Открытых вопросов нет. Решение владельца: `false` по умолчанию оставляет system status area видимой и убирает дублирующие FMS-индикаторы; `true` скрывает system status area только в launcher и оставляет собственные индикаторы FMS.

## 11. Критерии готовности (strategic-level)

1. Новая настройка видна только там, где доступен системный лаунчер, и имеет EN/RU/UK локализацию.
2. После обновления или чистой установки настройка выключена: Android system status area видима, а FMS не дублирует часы, сеть и батарею.
3. При включении настройки на launcher экранe Android status bar скрыт, а FMS показывает собственные часы, сеть и батарею.
4. При выключении настройки системная строка немедленно возвращается, а FMS-индикаторы исчезают.
5. При выходе из launcher system status area гарантированно восстановлена.
6. Portrait и landscape не пересекают display cutout, system bars или navigation area.
