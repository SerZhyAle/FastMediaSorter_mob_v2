# 05 - Android best practice для больших экранов настроек

**Ticket:** S0474
**§6 item:** 5
**Метод:** эталонные рекомендации Android (developer.android.com - Settings guide, ViewPager2, Fragment lifecycle).

## Эталонные приёмы

1. Nested / sub-screens вместо одного плоского экрана. Android рекомендует группировать настройки и открывать подгруппы как отдельные под-экраны. Подэкран инициализируется только при переходе - встроенный lazy. В кастомной реализации этот же эффект достигается ленивой инициализацией табов/секций (Группа A артефакта 04).

2. Headers + детальный экран (two-pane на больших экранах). Для очень больших наборов настроек - список категорий слева, детали справа на планшетах/TV. Релевантно адаптиву проекта (ландшафт/TV/Wear).

3. Тяжёлые/списочные данные - отдельный экран, не встроенная таблица. Списки переменной длины (назначения, расписания, сессии) логично открывать как самостоятельный экран по действию пользователя, а не держать в общем скролле настроек. Проект уже делает так для Permissions/Auth/Extensions (артефакт 03) - то есть паттерн в кодовой базе устоялся.

4. Никакого синхронного I/O на main thread в lifecycle-колбэках. Дисковые чтения (SharedPreferences/DataStore), PackageManager, парсинг XML - в фон. Прямое следствие для P2/P3/P6.

5. Ленивое создание невидимого содержимого. `offscreenPageLimit` держать минимальным; не inflate-ить то, что пользователь ещё не открыл (`ViewStub`, отложенные транзакции фрагментов). Следствие для P4/P5; согласуется с CLAUDE.md §18 (Lazy optimization).

## Про androidx Preference

`PreferenceFragmentCompat` даёт nested `PreferenceScreen` с ленивой загрузкой подэкранов из коробки. Но:
- Проект осознанно использует кастомные виджеты (`SettingsToggleRow`, collapsible sections, цветовые индикаторы, динамические группы, глобальный поиск по настройкам) - их нет в стандартном Preference.
- Миграция ~2700 строк layouts на Preference-XML - большой объём с высоким риском регресса и потерей кастомного UX.
- Вывод: библиотечный lazy - не аргумент за миграцию; тот же выигрыш достижим ленивой инициализацией в текущей архитектуре дешевле и безопаснее.

## Источник

developer.android.com - руководство «Settings» (компонент настроек), документация ViewPager2 (`offscreenPageLimit`) и жизненного цикла Fragment-транзакций (`commit` vs `commitNow`).
