# 04 - Варианты улучшения с оценкой

**Ticket:** S0474
**§6 item:** 4
**Метод:** синтез артефактов 01-03 + Android best practice (артефакт 05).

Разделены на две группы: безопасные оптимизации работоспособности (невидимы пользователю, низкий риск) и структурные изменения (меняют UX/навигацию, требуют owner-решения).

## Группа A - безопасные оптимизации (невидимы пользователю)

### A1. Снять предзагрузку соседнего таба
- Суть: `offscreenPageLimit = 1` → дефолт (создаётся только активный таб). Эффект: при открытии создаётся 1 фрагмент вместо 2.
- Плюс: существенное ускорение холодного открытия. Минус: первый свайп на соседний таб инициализирует его с небольшой задержкой.
- Сложность: низкая. Эффект: высокий. Адресует P4.

### A2. Lazy inflate дочерних медиа-фрагментов
- Суть: вместо `commitNow()` всех 5-6 child при входе в Media-таб - inflate дочернего фрагмента только при разворачивании секции (по умолчанию свёрнуты).
- Плюс: убирает ~800 строк синхронного XML inflate с critical path. Минус: усложняет search-навигацию (ждать создания фрагмента); возможен placeholder при разворачивании.
- Сложность: средняя. Эффект: высокий. Адресует P5.

### A3. Обернуть/убрать синхронные дисковые чтения
- Суть: добавить `StrictModeHelper.allowDiskReads` или перенести чтение SharedPreferences в фон в `OperationsSettingsFragment.setupExpandableSections()`.
- Плюс: устраняет необёрнутое дисковое чтение на main thread. Сложность: низкая. Эффект: средний. Адресует P2.

### A4. Асинхронная инициализация Send Commands
- Суть: вызовы PackageManager в `setupSendCommandsGroup()` перенести в `Dispatchers.IO`, применять результат на Main.
- Плюс: Playback-таб открывается быстрее. Минус: обработка состояния «строки ещё не созданы» в observeData. Сложность: средняя. Эффект: умеренный. Адресует P3.

### A5. Построение индекса поиска в фоне
- Суть: `SettingsSearchRegistry.allEntries` (XML-скан 9 layouts) строить в `Dispatchers.IO`; overlay показывает loading пока индекс готовится.
- Плюс: убирает XML I/O с main thread при каждом открытии Settings. Минус: первая отрисовка поиска может задержаться на 50-100 мс. Сложность: малая. Эффект: устраняет потенциальный ANR. Адресует P6.

## Группа B - структурные изменения (требуют owner-решения)

### B1. Вынос Destinations и Scheduled Operations в отдельные экраны/диалоги
- Суть: `OperationsSettingsFragment` (1165 LOC) → ~600-700 LOC; T1/T2 (артефакт 03) открываются кнопкой как отдельный экран или BottomSheet.
- Плюс: Operations-таб быстрее, фрагмент в рамках лимита 1500, списки можно lazy-load. Минус: добавляет навигационный слой; T1 - центральная концепция (discoverability ↓); требует пересмотра search-навигации (`SettingsSearchTabMapping`, `SettingsSearchDestination`, `ensureSectionExpanded`).
- Сложность: высокая. Эффект: высокий для структуры, умеренный для перфоманса. Open: §6.6.

### B2. (опционально) Миграция на androidx Preference с nested screens
- Суть: радикальный переход с кастомного ViewPager-хоста на `PreferenceFragmentCompat` с headers + sub-screens (встроенный lazy подэкранов).
- Плюс: библиотечный lazy, меньше ручного кода. Минус: огромный объём переписывания ~2700 строк layouts + потеря кастомных виджетов (`SettingsToggleRow`, collapsible sections, цветовые индикаторы); высокий риск регресса. Оценка: не рекомендуется как первая итерация - см. артефакт 05.

## Рекомендация

1. Сначала Группа A (A1, A3, A5 - дёшево и сразу; A2, A4 - следом). Невидима пользователю, низкий риск, снимает большинство P2-P6.
2. Группа B1 - только после owner-решения по UX Destinations.
3. B2 - отклонить для этой итерации (риск/выгода неблагоприятны).
