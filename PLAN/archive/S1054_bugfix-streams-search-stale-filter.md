## 1. Проблема

В экране трансляций (режим списка) поле поиска работает как автофильтр: по мере ввода список трансляций сокращается. Но при выходе и повторном входе в экран поле поиска отображается пустым, а список по-прежнему отфильтрован по прошлому запросу. Пользователь видит короткий список без видимой причины и не понимает, почему часть трансляций пропала. Единственный способ снять фильтр - зайти в поле, что-нибудь ввести и стереть, только тогда фильтр очищается.

Причина: сессия трансляций восстанавливает сохранённый текст запроса в активный фильтр (список фильтруется), но восстановленное значение никогда не пишется обратно в само поле ввода. Фасетные фильтры (категория/язык/страна/тип) имеют видимый индикатор активности, а текстовый запрос после восстановления остаётся невидимым - поле пустое, а фильтр действует.

---

## 2. Цели

1. После повторного входа в экран трансляций состояние поля поиска и фактически применённого текстового фильтра всегда согласованы: либо оба показывают запрос, либо оба пусты.
2. Пользователь не сталкивается с «невидимым» сокращением списка - если список отфильтрован по тексту, причина видна на экране.
3. Снятие текстового фильтра не требует обходного трюка «ввести и стереть».

**Non-goals:**

- Изменение логики фасетных фильтров (категория/язык/страна/тип/только закреплённые) и их индикатора.
- Изменение поведения восстановления сортировки, режима отображения (список/сетка) и позиции прокрутки.
- Пересмотр самого механизма сессионного восстановления трансляций как фичи.

## 4. Контекст текущей архитектуры

За экран трансляций отвечает связка «экран списка -> вью-модель -> комбинированный поток источников и фильтра». Вью-модель хранит объект фильтра (текстовый запрос плюс фасеты и режим сортировки) и при инициализации восстанавливает сохранённую сессию, включая текст запроса, - это осознанное поведение «продолжить с того места, где остановился» (S0659). Сам экран подписывается на изменения текстового поля и передаёт их во вью-модель, но обратной связи нет: при первом рендере восстановленный запрос отражается только в отфильтрованном списке, а не в поле ввода.

Сейчас проблему нельзя решить «на месте», потому что источник истины (активный фильтр во вью-модели) и его видимое представление (текст в поле) разведены: восстановление наполняет только первый, а поле остаётся в состоянии по умолчанию (пустое). Нужна согласованная политика синхронизации между восстановленным фильтром и полем ввода.

---

## 5. Предлагаемый подход

Устранить рассинхрон, исключив текстовый запрос из восстановления сессии (выбранный владельцем вариант B, §6.1). При каждом открытии экрана текстовый фильтр стартует пустым: поле поиска пусто и список не отфильтрован по тексту. Ранее сохранённое значение запроса становится «мёртвым» и игнорируется при восстановлении. Восстановление сортировки, фасетов, режима отображения и позиции прокрутки не затрагивается.

### 5.1 Основные столпы / модули

- **Слой применения фильтра (вью-модель).** Остаётся единственным источником истины для активного запроса. При восстановлении сессии текстовый запрос принудительно стартует пустым независимо от сохранённого значения; остальные восстанавливаемые поля (сортировка, фасеты, режим, позиция) не меняются.
- **Слой представления списка.** Дополнительная синхронизация поля не требуется: при пустом стартовом запросе поле по умолчанию пусто и уже согласовано с фильтром. Существующий обработчик ввода продолжает работать без изменений.

### 5.2 Потоки данных и событий

- Восстановление: сессия -> активный фильтр во вью-модели с пустым текстовым запросом -> состояние экрана -> неотфильтрованный по тексту список; поле поиска пусто.
- Пользовательский ввод: поле -> обработчик ввода -> активный фильтр -> отфильтрованный список (без изменений).

### 5.3 Точки расширяемости

- Политика «какие поля сессии восстанавливаются» остаётся сосредоточенной во вью-модели, что позволяет будущим полям фильтра единообразно выбирать: восстанавливать значение или стартовать пустым.

## 6. Открытые вопросы / Research items

1. **Направление синхронизации: показывать восстановленный запрос или не сохранять его**
   - **Вопрос:** что считать правильным поведением при повторном входе - восстанавливать текст запроса и отражать его в поле, или вовсе не сохранять текстовый запрос между открытиями экрана?
   - **Варианты:**
     - A (рекомендуется): восстанавливать запрос и писать его в поле - согласуется с намерением S0659 «продолжить сессию», делает скрытый фильтр видимым, правка минимальна.
     - B: исключить запрос из восстановления сессии - при входе поле пусто и список не отфильтрован; ближе к наивному ожиданию, но частично откатывает сессионное восстановление, оставляя восстановление сортировки/фасетов/позиции несогласованным по смыслу.
   - **Нужно выяснить:** какое поведение владелец считает целевым UX. Формулировка задачи («поле пустое, а список отфильтрован») намекает на неожиданность самой персистентности запроса, поэтому решение за владельцем.
   - **Решение:** вариант B - текстовый запрос не сохраняется между открытиями экрана; при входе поле пусто и список не отфильтрован по тексту.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Не сохранять текстовый запрос между открытиями экрана**

- **Решение:** текстовый запрос исключается из восстановления сессии (вариант B из §6.1); при входе поле пусто и список не отфильтрован по тексту.
- **Альтернативы:** восстанавливать запрос и отражать его в поле (вариант A).
- **Почему:** владелец считает целевым UX сброс текстового поиска при каждом открытии - текстовый запрос трактуется как разовый ввод, а не как настройка сессии. Это устраняет неожиданное «невидимое» сокращение списка у корня: нет сохранённого запроса - нет и рассинхрона. Фасеты, сортировка, режим и позиция остаются настройками сессии и восстанавливаются как прежде.

## 11. Критерии готовности (strategic-level)

1. Пользователь вводит запрос в списке трансляций, список сокращается; выходит из экрана и возвращается - поле поиска пусто и список не отфильтрован по тексту.
2. Нет состояния «поле пустое, список отфильтрован по прошлому запросу».
3. Снятие текстового фильтра не требует обходного трюка «ввести и стереть».
4. В рамках одного открытия экрана текстовый поиск работает как прежде: ввод фильтрует список, очистка возвращает полный.
5. Поведение восстановления сортировки, режима отображения, фасетов и позиции прокрутки не изменилось.
