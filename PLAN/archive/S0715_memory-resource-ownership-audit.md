## 0. Источник

Прохождение Layer 3 (Memory ownership) протокола `docs/CODE_AUDIT_PROTOCOL.md` по текущему коду `app_v2/` и `wear/`.

## 1. Проблема

Владение долгоживущими объектами и тяжёлыми ресурсами не проверялось системно. Поверхность риска намерена навскидку: 129 точек `release/addListener/removeListener` в `src/main`; приложение MediaStore-heavy (множество `ContentObserver`), плеер-семья ExoPlayer зеркалится вручную по хостам, превью грузятся через Glide. Несбалансированная регистрация слушателя/обзёрвера или неосвобождённый player/cursor - классический источник утечки `Activity`/`View` (P0).

## 2. Цели

1. Прогнать чек-лист Layer 3: удержание `Context`/`View`/`Activity` в синглтонах и `ViewModel`, обнуление `ViewBinding` в `onDestroyView`, `.use {}` для `Closeable`, ограниченность кэшей.
2. Проверить **симметрию register/unregister**: каждый `registerContentObserver`/`registerReceiver`/`addListener`/`addCallback`/`addObserver` имеет парный сброс на симметричной грани жизненного цикла.
3. Проверить **дисциплину ExoPlayer/Media3**: единственный владелец инстанса, release на `onStop` (multi-window API 24+), `removeListener` симметрично `addListener`, `setVideoSurface(null)` перед release, сброс audio focus; контракт применён ко **всем** хостам плеер-семьи.
4. Проверить **Glide/bitmap**: декодирование в размер показа (`override`), `RGB_565` для непрозрачных превью, `clear(target)` на detach, осознанные размеры кэшей.
5. Прогнать обязательные leak-сценарии протокола под LeakCanary (open/close плеера, browse->player->back, поворот при воспроизведении, диалог/боттом-шит open/dismiss/reopen, смерть процесса через «Don't keep activities»).

**Non-goals:** исправление поведения фич; находки-утечки парковать fix-тикетами.

## 3. Объём и ограничения

- Модули `app_v2/` и `wear/`.
- Аудит-проход не меняет поведение; устранение каждой нетривиальной утечки - отдельный fix-тикет с LeakCanary-доказательством.
- Использовать `audit-shared-state-writers.ps1` для писателей общего состояния и `measure-hotspots.ps1` для ранжирования классов-владельцев.
- Часть проверок упирается в будущий гейт симметрии слушателей (S0721) - ручной прогон не блокируется его наличием.

## 4. Критерии приёмки

- [ ] Каждый `register*`/`add*Listener` в `src/main` сопоставлен с парным сбросом; несбалансированные - находки с серьёзностью.
- [ ] Дисциплина release ExoPlayer проверена по всем хостам плеер-семьи; отклонения - находки.
- [ ] Конфигурация Glide (размер декода, bitmap config, clear на detach) проверена на горячих превью.
- [ ] Все обязательные leak-сценарии Layer 3 прогнаны под LeakCanary; удержания зафиксированы.
- [ ] Находки классифицированы P0-P3; нетривиальные запаркованы fix-тикетами; отчёт записан в `## Last Audit`.
