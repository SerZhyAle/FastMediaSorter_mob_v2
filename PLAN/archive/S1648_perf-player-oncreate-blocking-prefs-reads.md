# Спецификация (compact bugfix): S1648 - SharedPreferences читаются с главного потока в PlayerActivity.onCreate

**Ticket:** S1648
**Status:** Archived
**Priority:** 45
**Date:** 2026-08-14
**Tier:** 3 - Moderate (ad-hoc)

---

## 0. Захваченный материал (inbox)

**Захвачено:** 2026-08-14

**Захвачено во время:** S1207 (проверка на устройстве после переноса инициализации Cast с главного потока)

**Текст:**

Открытие плеера на устройстве по-прежнему держит главный поток четырьмя нарушениями StrictMode
общей длительностью около 252 мс. Причина уже не Cast (её убрал S1207), а чтение SharedPreferences
из двух других мест внутри того же `PlayerActivity.onCreate`. Это тот же класс дефекта -
блокирующий дисковый ввод-вывод на горячем пути открытия плеера - но другие места вызова, поэтому
вне объёма S1207.

**Условия измерения:** устройство RFCR110NBQJ (Galaxy S21, Android 15), сборка standard-debug
`v2.60.8112.319`, файл открыт обзором внутри приложения. Лог: `temp/S1207/logcat_S1207.txt`.
Все четыре нарушения на `tid 25797`, то есть на главном потоке процесса.

---

## 1. Проблема / симптом

Четыре `DiskReadViolation` в одном открытии плеера, двумя кластерами:

- **73 мс, дважды** - `DrawEditorPrefs.prefs(DrawEditorPrefs.kt:131)` и
  `DrawEditorPrefs.getLastColor(:41)`, оба через `DrawEditorPrefs.getCustomColor(:53)` ->
  `ImageDrawOverlayManager.bindToolbar(:335)` -> `PlayerManagerInitializer.initCoreCoordination(:306)`
  -> `PlayerManagerInitializer.initialize(:70)` -> `PlayerActivity.initializeManagers(:627)` ->
  `PlayerActivity.onCreate(:579)`. Внутри - `ContextImpl.getSharedPreferences` и
  `SharedPreferencesImpl.awaitLoadedLocked`.
- **53 мс, дважды** - `VideoPlayerManager.<init>(VideoPlayerManager.kt:235)` ->
  `PlayerViewerFactory.createVideoPlayerManager(:13)` -> `PlayerActivity.getVideoPlayerManager$app_v2(:129)`
  -> `PlayerManagerInitializer.initPlayerControlsAndOcr(:616)` -> тот же `initialize` -> `onCreate`.
  Внутри - `ContextImpl.getDataDir` / `getPreferencesDir` / `getSharedPreferences`.

Наблюдаемый эффект: между `ActivityTaskManager: START` (17:27:12.167) и `onRenderedFirstFrame`
(17:27:13.127) прошло 960 мс, и четверть этого времени приходится на чтение настроек с диска.
Инструмент рисования и цвет кисти при открытии видео пользователю не нужны вовсе.

---

## 2. Корневая причина

Оба кластера - одна и та же форма: файл настроек открывается в момент построения объекта, а не в момент, когда из него что-то читают. Первое обращение к `SharedPreferences` синхронно ждёт загрузки файла, поэтому платит именно тот, кто открыл его первым.

- **Кластер 73 мс.** `bindToolbar` вызывается безусловно из инициализации менеджеров плеера, то есть и при открытии видео, где оверлей рисования никогда не показывается. Внутри он сразу красил свотч своего цвета в сохранённый пользовательский цвет, и это было первым касанием файла настроек редактора рисования. Обработчик нажатия на тот же свотч читает цвет лениво и в горячий путь не попадал.
- **Кластер 53 мс.** `VideoPlayerManager` открывал файл настроек управления воспроизведением в инициализаторе поля, то есть в конструкторе, который вызывается из создания активности. Ни одна строка конструктора значения оттуда не читает.

---

## 3. Исправление

Обе правки переносят открытие файла с момента построения на момент первого настоящего использования, ничего не меняя в поведении.

- Покраска пользовательского свотча убрана из привязки панели и делается при входе в режим рисования, где тот же файл уже читается ради последнего цвета. Обработчик нажатия оставлен как был.
- Поле настроек управления воспроизведением стало ленивым (`LazyThreadSafetyMode.NONE`, доступ идёт с главного потока).

Компиляция после правки: `.\a.ps1 fk` - BUILD SUCCESSFUL, код 0.

## 4. Проверка

Повторить сценарий измерения S1207 на том же устройстве RFCR110NBQJ (Galaxy S21, Android 15), сборка `standard-debug`: открыть видеофайл обзором внутри приложения.

Что должно быть видно в логе:

1. В стеках `StrictMode` при открытии плеера больше нет ни `DrawEditorPrefs`, ни `VideoPlayerManager.<init>`. Четыре нарушения общей длительностью около 252 мс должны исчезнуть; остальные, если появятся, принадлежат другим местам и другим тикетам.
2. Метка `S1648: draw toolbar bound without reading the custom colour` появляется при открытии плеера - это доказывает, что панель по-прежнему привязывается, просто без чтения настроек.
3. Метка `S1648: playback control prefs opened on first use` при открытии видео **не** появляется, а появляется только после первого использования управления воспроизведением.
4. Поведение не изменилось: в режиме рисования свотч пользовательского цвета окрашен сохранённым цветом, а нажатие на него открывает палитру с тем же цветом.
