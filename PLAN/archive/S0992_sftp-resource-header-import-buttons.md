## 1. Проблема

Пользователь хочет на экране создания SFTP-ресурса две кнопки в заголовке: «Импорт из файла» и «Импорт по штрих-коду».

**Research (2026-07-11, автономно):** обе точки входа УЖЕ существуют в SFTP-секции экрана добавления ресурса - см. §4. Ask сводится к размещению (перенос в заголовок) и переименованию, а не к новой функциональности. Что именно требуется - решает владелец (§6).

---

## 2. Цели

1. На экране создания SFTP-ресурса две кнопки импорта находятся в шапке формы (сверху), а не внизу.
2. Кнопки переименованы в единые с S0991 подписи («Импорт из файла» / «Импорт по штрих-коду», EN/RU/UK) и дёргают тот же единый источник входа.
3. Кнопка «по штрих-коду» скрыта на устройствах без камеры.

**Non-goals:**

- Новая функциональность импорта или обобщение формата (остаётся companion `.fmscfg` / companion-QR).
- Изменение бэкенда импорта.

## 4. Контекст текущей архитектуры

Экран добавления ресурса (`AddResourceActivity`, SFTP-секция) уже содержит две кнопки импорта companion-конфига:
- `btnSftpImportCompanion` - импорт `.fmscfg` из файла через SAF (`AddResourceCompanionCoordinator.importFromUri`). Это и есть «импорт из файла».
- `btnSftpScanCompanionQr` - скан companion-QR (`CompanionQrScanActivity` -> `importFromPayload`, S0988), виден только при `FEATURE_CAMERA_ANY`. Это и есть «импорт по штрих-коду».

Бэкенд: `ImportCompanionConfigUseCase` (файл + QR-payload). Формат - companion `.fmscfg` (S0421/S0984). Значит функциональность есть; открыт лишь вопрос размещения/подписи кнопок (§6). Смежно: импорт приносит SFTP-креды -> коллизия host:port из S0987 (нерешённая политика).

---

## 5. Предлагаемый подход

Перенос существующих кнопок импорта в шапку SFTP-формы и переименование, поверх единого внутреннего источника запуска действий, введённого S0991. Бэкенд импорта не меняется.

### 5.1 Основные столпы / модули

- Экран добавления ресурса (SFTP-секция) - место размещения; единый источник запуска действий общий с точками входа у карточек типов (S0991).

### 5.2 Потоки данных и событий

- UI (шапка SFTP) -> единый запуск действия импорта -> существующий companion-слой -> результат -> закрытие экрана при успехе.

### 5.3 Точки расширяемости

- Общий источник входа с S0991 позволяет менять места размещения кнопок независимо от логики импорта.

## 6. Открытые вопросы / Research items (owner decision - блокирует переход)

Функциональность импорта из файла и по QR уже есть в SFTP-секции. Нужны решения владельца:

1. Где именно «заголовок»? Перенести существующие кнопки (`btnSftpImportCompanion`, `btnSftpScanCompanionQr`) в верх/заголовок SFTP-формы, или текущее размещение приемлемо и тикет фактически закрыт?
2. Переименовать подписи в «Импорт из файла» / «Импорт по штрих-коду» (сейчас companion-специфичные формулировки)? Если да - нужны строки EN/RU/UK.
3. Оставить companion-`.fmscfg` как единственный формат «файла» и companion-QR как «штрих-код», или подразумевается обобщённый формат/произвольный штрих-код (новая работа)?
4. Кнопка QR уже скрыта на устройствах без камеры - сохранить это поведение в заголовке?

Пока не решено - BlockQuestions. Смежно: политика коллизии host:port (S0987) влияет на исход импорта.

**Разрешено (2026-07-11, owner):** **перенести существующие кнопки** (`btnSftpImportCompanion`, `btnSftpScanCompanionQr`) в заголовок (верх) SFTP-формы и переименовать в «Импорт из файла» / «Импорт по штрих-коду» (строки EN/RU/UK). QR-кнопку по-прежнему скрывать без камеры. Формат остаётся companion `.fmscfg` / companion-QR (не обобщать). Реализовать согласованно с S0991 (пункты у табов) как одну фичу. Статус -> Approved; layout-детали - в /spec-tech.
