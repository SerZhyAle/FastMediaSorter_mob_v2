## 1. Проблема

Сейчас приложение наследует светлый/тёмный режим только от системной настройки устройства - ручного переключателя темы внутри приложения нет. На части устройств системный night-mode либо отсутствует, либо работает некорректно, либо пользователь хочет тему приложения, отличную от системной. В результате на нескольких устройствах подходящую тему («светлая» или «тёмная») приходится выставлять обходными путями на уровне системы, а внутри приложения это сделать невозможно. Нужна явная опция выбора цветовой темы в настройках интерфейса.

---

## 2. Цели

1. Пользователь может выбрать цветовую тему приложения в настройках: «Авто (за устройством)», «Светлая», «Тёмная».
2. Значение по умолчанию - «Авто (за устройством)»: поведение совпадает с текущим (тема следует системной).
3. Выбор «Светлая» / «Тёмная» применяет соответствующую тему независимо от системной настройки устройства.
4. Выбор сохраняется между запусками и применяется сразу при старте приложения, без необходимости перезапуска вручную.
5. Тема применяется единообразно ко всем экранам приложения (списки, настройки, просмотрщики, диалоги).

**Non-goals:**

- Не вводится кастомная палитра / выбор акцентного цвета - только три режима светлый/тёмный/авто.
- Не меняется отдельная тема просмотрщика текста/EPUB (она остаётся самостоятельной настройкой).
- Не вводится расписание автопереключения по времени суток.
- Не затрагивается модуль Wear OS.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Переключение темы применяется без видимого «моргания» и без потери текущего состояния экрана, насколько это возможно на платформе.
2. Расположение опции - в разделе настроек интерфейса, вслед за выбором языка

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки (`standard`, `lite`, `photos`, `legacy`, а также `vr`/`noLegal`). Опция не флейвор-специфична - живёт в общем коде `src/main/`.
- **API level:** без API-специфики; применяется штатный платформенный механизм переключения night-mode, доступный на `minSdk 23`+.
- **Wear OS:** не затрагивается.
- **Производительность:** применение темы не должно заметно замедлять холодный старт.
- **Совместимость данных:** добавляется одна новая пользовательская настройка с дефолтом «Авто»; существующие профили без сохранённого значения трактуются как «Авто» (поведение не меняется). Без изменения схемы Room.
- **Локализация:** EN/RU/UK - обязательно для всех трёх названий режимов и подписи опции.
- **Доступность:** режимы различимы по тексту (не только по цвету); элемент выбора фокусируется и активируется клавиатурой/D-pad/мышью наравне с прочими настройками (Strict Rule 17).

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** опция «Цветовая тема» размещается в разделе настроек интерфейса, как одиночный селектор из трёх взаимоисключающих значений (Авто/Светлая/Тёмная), по образцу существующих выбора-настроек в этом разделе. Точная форма контрола (выпадающий список / диалог выбора / сегментированный переключатель) уточняется через `/ui-clarify` на этапе тактической спеки.
- **Accessibility:** значения помечены текстом; контрол участвует в общем порядке фокус-навигации настроек; touch target не меньше соседних строк.
- **Localization:** подпись опции и три названия режима локализуются для EN/RU/UK одновременно.
- **Validation level:** целевой вариант (`standardDebug`) собирается; ручная проверка переключения трёх режимов на устройстве (этап `BlockNeedUserTest`).
- **Owner sign-off:** 2026-06-01.
- **Related tickets:** none.

## 4. Контекст текущей архитектуры

За пользовательские настройки отвечает слой настроек: доменная модель настроек, слой их хранения и экран настроек интерфейса. Применение светлого/тёмного оформления сейчас целиком отдано платформе - ресурсы оформления раздвоены на дневной и ночной наборы, и система сама выбирает набор по системному night-mode. Точки, где приложение могло бы навязать собственный режим оформления (на старте процесса и при входе в экраны), на данный момент не задействованы. Поэтому из §1 проблему нельзя решить без введения собственной настройки и единой точки её применения.

---

## 5. Предлагаемый подход

Ввести пользовательскую настройку «цветовая тема» с тремя значениями (авто/светлая/тёмная), хранимую вместе с остальными настройками. На уровне приложения завести единую точку применения этой настройки к режиму оформления: на старте процесса и при изменении выбора. Значение «авто» означает «не навязывать режим - следовать системе» (текущее поведение); «светлая»/«тёмная» - принудительный режим независимо от системы. Экран настроек интерфейса получает соответствующий контрол выбора.

### 5.1 Основные столпы / модули

- **Доменная настройка темы.** Новое поле в модели настроек с тремя допустимыми значениями и дефолтом «авто». Цель: единый источник истины о выбранном режиме.
- **Хранение и чтение настройки.** Слой хранения настроек сериализует/читает выбранный режим; отсутствие значения = «авто».
- **Единая точка применения.** Уровень приложения переводит выбранное значение в платформенный режим оформления и применяет его при старте процесса и при смене значения. Цель: одно место, отвечающее за фактическое переключение темы.
- **Контрол в настройках интерфейса.** Экран настроек показывает текущий выбор и позволяет переключить режим; изменение немедленно отражается в оформлении.

### 5.2 Потоки данных и событий

- Старт приложения → чтение сохранённого режима → применение режима оформления до отрисовки экранов.
- Экран настроек → выбор пользователя → запись в слой хранения → применение режима через единую точку → перерисовка оформления.
- «Авто» → единая точка не навязывает режим → оформление следует системному night-mode.

### 5.3 Точки расширяемости

- Набор значений режима держать перечислимым и расширяемым, чтобы при необходимости в будущем добавить, например, режим «OLED-чёрный» без изменения контракта хранения.
- Единая точка применения остаётся единственным местом трансляции «доменное значение → платформенный режим», чтобы будущие режимы подключались в одном месте.

## 6. Открытые вопросы / Research items

1. **Поведение при смене темы**
   - **Вопрос:** применять выбранный режим мгновенно с пересозданием текущих экранов или через перезапуск?
   - **Решение:** применять через перезапуск приложения, повторно используя уже существующий паттерн «настройка изменена → предложить перезапуск» (как у смены языка и размера кэша). Выбранная тема применяется при старте процесса; после изменения в настройках показывается стандартный диалог перезапуска.
   - **Статус:** Resolved (владелец, 2026-06-01)

2. **Форма контрола выбора**
   - **Вопрос:** выпадающий список, диалог выбора из трёх пунктов или сегментированный переключатель?
   - **Решение:** выпадающий список (Spinner), по образцу уже существующего выбора языка в разделе настроек интерфейса.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: «Авто» как отсутствие навязывания, а не отдельная вычисляемая тема**

- **Решение:** значение «Авто (за устройством)» реализуется как «не навязывать режим» - приложение продолжает следовать системному night-mode штатным платформенным механизмом.
- **Альтернативы:** самостоятельно вычислять системный режим и навязывать его явно.
- **Почему:** минимально отклоняется от текущего поведения, исключает рассинхрон с системой и упрощает дефолт.

**ADR-2: применение через перезапуск по существующему паттерну, а не «на лету»**

- **Решение:** выбранная тема применяется на старте процесса; после изменения в настройках показывается стандартный диалог перезапуска, повторно используя уже имеющийся в проекте паттерн (смена языка, размера кэша, импорт настроек).
- **Альтернативы:** мгновенное применение с автоматическим пересозданием видимых экранов.
- **Почему:** консистентность с уже знакомым пользователю поведением других «требующих перезапуска» настроек; единая, предсказуемая точка применения на старте.

## 11. Критерии готовности (strategic-level)

1. В настройках интерфейса присутствует опция «Цветовая тема» с тремя значениями: «Авто (за устройством)», «Светлая», «Тёмная».
2. По умолчанию выбрано «Авто», и поведение приложения совпадает с текущим (тема следует системе).
3. Выбор «Светлая» делает приложение светлым на устройстве с системной тёмной темой, и наоборот для «Тёмная».
4. Выбранный режим сохраняется между запусками и применяется при старте без ручного перезапуска.
5. Выбранный режим применяется единообразно к спискам, настройкам, просмотрщикам и диалогам.
6. Подпись опции и названия режимов локализованы на EN/RU/UK.
