## 1. Проблема

На рабочем столе лаунчера ярлыки трансляций, контактов и ресурсов часто получают одну и ту же картинку: все трансляции рисуются общим глифом, контакты - монограммой, ресурсы - похожими составными логотипами. Различает соседние ячейки только подпись под иконкой, а она набрана кеглем 12sp в ячейке шириной от ~63dp и обрезается многоточием после нескольких символов. Из-за этого две ячейки, ведущие на разные цели, читаются на столе одинаково.

Вторая половина проблемы - подпись может оказаться пустой: у трансляции без названия и у ресурса с пустым именем в ячейку не попадает ничего, и тогда единственный признак цели исчезает совсем.

---

## 2. Цели

1. Подпись ярлыка набрана самым мелким кеглем, который проект уже применяет к подписям ячеек, - до обрезки многоточием в ту же ячейку помещается заметно больше символов.
2. Контур подписи сохраняется, то есть подпись остаётся читаемой поверх любых обоев без карточки под ней.
3. Кегль подписи имеет одно имя в ресурсах, а не литерал в разметке, - изменить его потом можно одной правкой.
4. Подпись непуста для любого разрешимого ярлыка: у трансляции без названия и у ресурса с пустым именем ячейка показывает производное осмысленное имя, а не пустую строку.

**Non-goals:**

- Иконки ярлыков не меняются - одинаковые логотипы ресурсов лечит S1289.
- Вторая строка подписи не вводится: высота ячейки задана сеткой, и второй строке негде разместиться при мелком размере ячейки.
- Настройка «показывать / скрывать подписи» не вводится.
- Сетка «все приложения» в меню «Пуск» не затрагивается: там ячейки заняты приложениями с собственными различимыми иконками.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Кегль - «самый мелкий», то есть подпись должна занимать минимум площади ячейки, оставляя место иконке.
2. Читаемость обеспечивается обводкой, а не подложкой.

### 3.2 Жёсткие ограничения

- **Flavor:** разметка и размеры лежат в source set `launcherEnabled`, то есть затронуты `standard` и `noLegal` (`SUPPORT_LAUNCHER` в `docs/FLAVOR_MATRIX.md`). Разрешение подписи живёт в `src/main` и компилируется во всех вариантах.
- **API level:** без API-специфики.
- **Wear OS:** не затрагивается.
- **Производительность:** без изменений - правка размерная, дополнительных проходов разметки не появляется.
- **Совместимость данных:** схема не меняется.
- **Локализация:** новых пользовательских строк не появляется; запасное имя выводится из уже сохранённых пути и адреса.
- **Доступность:** кегль задаётся в `sp`, поэтому системное укрупнение шрифта продолжает действовать. Подпись остаётся не единственным каналом: озвучиваемое описание ячейки уже строится отдельно.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S1173 (принесла контурную подпись, ждёт проверки на устройстве), S1289 (составной логотип ресурса - лечит одинаковые иконки, не подписи).
- **Размер кегля:** выбран 10sp - самый мелкий кегль, который проект уже применяет к подписи ячейки (`item_stream_grid_cell.xml`). 9sp в проекте встречается только у второй, вспомогательной строки гаджета.

## 4. Контекст текущей архитектуры

Ячейку рабочего стола собирает связыватель представлений в слое UI лаунчера: он надувает разметку ячейки-ярлыка и кладёт в подпись готовую строку. Саму строку и иконку выдаёт use case разрешения команды - по одной ветке на каждый вид команды: приложение, внутренний маршрут, ресурс, трансляция, системный ярлык, отложенная операция, файл-избранное, контакт.

Проблему §1 нельзя решить в связывателе: кегль подписи задан литералом в разметке ячейки, а пустое имя приходит из хранилища ещё до связывателя - у ветки контакта запасное имя уже есть, у веток трансляции и ресурса его нет.

---

## 5. Предлагаемый подход

Правка идёт в двух местах и обе точечные.

### 5.1 Основные столпы / модули

- **Размер подписи ячейки.** Кегль подписи переезжает из литерала разметки в именованный размер ресурса рядом с уже существующей толщиной контура ячейки, и получает самое мелкое значение из применяемых в проекте к подписям.
- **Полнота подписи.** Ветки разрешения трансляции и ресурса получают ту же дисциплину, что уже действует в ветке контакта: пустое хранимое имя вытесняется производным - последним сегментом пути у ресурса и узлом адреса у трансляции, - и только затем исходным значением целиком.

### 5.2 Потоки данных и событий

Хранилище → разрешение команды (здесь появляется запасное имя) → модель ячейки → связыватель → подпись в разметке (здесь применяется кегль).

### 5.3 Точки расширяемости

Именованный размер подписи - единственная точка, через которую кегль меняется дальше, в том числе если позже появится настройка плотности рабочего стола.

## 9. Архитектурные решения (ADR)

**ADR-1: Кегль подписи - именованный размер, а не литерал разметки**

- **Решение:** ввести `launcher_cell_label_text_size` рядом с `launcher_cell_outline_width` и сослаться на него из разметки ячейки.
- **Альтернативы:** оставить литерал `10sp` в разметке; завести стиль темы для подписи ячейки.
- **Почему:** литерал повторил бы историю толщины контура, которую S1173 пришлось выносить в размер отдельно; стиль темы избыточен для одного свойства одного представления.

**ADR-2: Запасное имя выводится, а не берётся из новой строки ресурсов**

- **Решение:** пустое имя ресурса вытесняется последним сегментом пути, пустое название трансляции - узлом её адреса.
- **Альтернативы:** общая строка вида «Без названия» на трёх языках.
- **Почему:** общая строка вернула бы исходную проблему - две соседние ячейки снова читались бы одинаково; производное имя различает цели и не требует локализации.
