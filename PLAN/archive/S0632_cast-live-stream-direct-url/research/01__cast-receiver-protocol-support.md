# Research 01 - Cast Default Media Receiver protocol support for direct stream URLs

**Spec:** S0632
**§6 item:** 1 (какие протоколы трансляции принимает приёмник Cast при прямой передаче URL)
**Status:** Resolved
**Date:** 2026-06-23

## Question

При прямой передаче адреса трансляции приёмнику Chromecast (без скачивания во временный
файл, без локального прокси) - все ли протоколы, которые умеет открывать встроенный плеер
приложения, примет приёмник? Или часть надо скрывать / сообщать о невозможности?

## Verdict

Default Media (Web) Receiver - тот, что приложение использует по умолчанию
(`DEFAULT_MEDIA_RECEIVER_APPLICATION_ID`) - принимает напрямую:

- HLS (HTTP Live Streaming)
- MPEG-DASH
- SmoothStreaming
- прогрессивную загрузку по http (контейнеры MP4, MP2T, MP3, OGG, WAV, WebM)

НЕ поддерживает: RTSP, RTMP (в списке протоколов Cast их нет).

Приложение классифицирует адрес трансляции как стрим по схемам `http://`, `https://`,
`rtsp://` (классификатор схемы в коллбэке воспроизведения плеера). Из них приёмник Cast
примет только http(s); `rtsp://` приёмнику отдавать бессмысленно.

## Implications for S0632

- http(s)-трансляция (HLS / DASH / прогрессивный http) -> прямой URL приёмнику, тип потока live.
- `rtsp://` -> приёмник не примет: показать сообщение о неподдерживаемом протоколе,
  не пытаться кастить (иначе тихий сбой загрузки на приёмнике).
- Для адаптивных протоколов (HLS/DASH) приёмник требует CORS на ресурсах потока. Публичные
  трансляции обычно отдают корректные заголовки; приватные/локальные источники могут не
  кастится - это вне контроля приложения, покрывается общим фолбэк-сообщением об ошибке
  загрузки на приёмнике.
- HTTPS не обязателен протоколом Cast, но приёмник на современном Chromecast предпочитает
  https; это свойство источника, не приложения.
