The 13 ms gate timing gives it away: the run consumed an existing report instead of producing one. A fresh re-run reproduced the FAIL at the shifted line number. A detekt PASS that returns implausibly fast is not evidence.

The one advisory is `detekt-preflight (exit 1)`, project-wide and explicitly unattributable to this change; a fresh scoped run over the three changed `.kt` files returned `PASS [scoped] - 2 file(s) with new findings project-wide, none among changed files`. `dev/CHANGELOG.md` carries exactly one closure row for this run, as the contract promises for a failed-then-fixed closure.
