# 02 - Дрейф карты монтирования

**Вопрос §6.2:** как удержать список монтирования тестового набора синхронным с основным?

**Дата:** 2026-08-09. **Метод:** чтение блока `sourceSets` в `app_v2/build.gradle.kts` (строки 577-756).

---

## Где живёт карта

Карта монтирования целиком выражена в одном блоке `sourceSets` и нигде не продублирована. Это единственный источник правды, и гейт обязан читать именно его - иначе гейт станет вторым местом дрейфа, чего §6.3 прямо требует избежать.

Карта записана в двух синтаксических формах:

- явный блок `getByName("<набор>") { kotlin.directories.add("src/<общий>/java") }`;
- цикл `listOf("testStandard", "testNoLegal", "testLegacy", "testVr").forEach { getByName(it) { .. } }`.

Три монтирования в `standard` обёрнуты в `if` по gradle-свойствам (`screenCaptureStandardEnabled`, `edgeGestureOverlayStandardEnabled`, `edgeGestureTileStandardEnabled`). Для целей гейта условное монтирование трактуется как «не гарантировано смонтировано»: ссылка из общего теста на такой набор - нарушение при любом значении свойства.

## Требование к разборщику: полнота, а не терпимость

Разборщик должен учитывать **каждую** строку `kotlin.directories.add("src/..")` внутри блока `sourceSets`. Строка, которую он не смог отнести к набору, - не повод молча пропустить её: это повод вернуть «не смог проверить» (exit 2).

Иначе новая синтаксическая форма в build-файле тихо уменьшит зону контроля, и гейт продолжит печатать PASS на неполной карте. Громкий отказ вместо тихого недосмотра - единственная защита от этого класса регресса.

## Правило зеркала

Для каждого общего основного набора `src/<X>`, у которого существует тестовый двойник `src/test<X>`, множество флейворов, монтирующих `src/<X>`, обязано совпадать с множеством тестовых наборов, монтирующих `src/test<X>` (с точностью до префикса `test`).

Состояние на 2026-08-09 - зеркало держится:

- `streamingEnabled` -> standard, noLegal, legacy, vr; `testStreamingEnabled` -> testStandard, testNoLegal, testLegacy, testVr.
- `cloudEnabled` -> standard, noLegal, legacy, vr, photos; `testCloudEnabled` -> те же пять.
- `networkMonitor` -> standard, noLegal; `testNetworkMonitor` -> testStandard, testNoLegal.

## Исключение: тестовый набор без основного двойника

`testDocumentsEnabled` смонтирован в четыре тестовых набора, но каталога `src/documentsEnabled` не существует. Это законная форма: его предмет - один FQCN с пофлейворными копиями (S1455), и набор группирует тесты по флейворам, где включён `SUPPORT_DOCUMENTS`, а не по общему набору исходников.

Правило зеркала поэтому одностороннее: оно применяется, только когда основной двойник существует. Тестовый набор без двойника не считается дрейфом.

## Обратное направление

Обратная асимметрия дефектна и должна ловиться: общий основной набор существует, тестового двойника нет, а в `src/test` лежит тест на тип из него. Это в точности дефект S1450, и он ловится основной проверкой из артефакта 01 - отдельного правила не требует.
