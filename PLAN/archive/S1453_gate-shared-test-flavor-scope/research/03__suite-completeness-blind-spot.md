# 03 - Слепая зона гейта полноты набора

**Вопрос §6.3:** гейт полноты считает исходные классы только по `app_v2/src/test`, поэтому классы из флейвор-наборов не участвуют в проверке на усечённый прогон. Можно ли вывести список наборов для конкретного `-TaskDir` из самого build-файла?

**Дата:** 2026-08-09. **Метод:** чтение `scripts/quality/assert-test-suite-complete.ps1` и блока `sourceSets` в `app_v2/build.gradle.kts`, подсчёт классов `*Test.kt`.

---

## Механика слепой зоны

Гейт строит знаменатель из одного каталога - `<Module>/src/test` - и сравнивает его с числом XML-отчётов, которые прогон реально записал. Отчёты при этом приходят от всех наборов, смонтированных в вариант.

Отсюда два независимых искажения.

- **Коэффициент завышается.** Числитель считает отчёты всех наборов, знаменатель - классы одного. Усечённый прогон может остаться выше порога 0.85 и получить PASS.
- **Проверка пропавших пакетов слепа к флейвор-наборам.** Список `missing` строится только из пакетов `src/test`. Пакет, живущий исключительно во флейвор-наборе, может не дать ни одного отчёта, и гейт этого не заметит.

## Величина зоны на 2026-08-09

Классов `*Test.kt` по наборам: `test` 460, `testNoLegal` 14, `testStandard` 4, `testStreamingEnabled` 3, `testVr` 1, `testCloudEnabled` 1, `testDocumentsEnabled` 1, `testNetworkMonitor` 1.

- Для `testStandardDebugUnitTest` эффективный знаменатель - 470 классов, гейт считает 460: занижение на 2.1 %.
- Для `testNoLegalDebugUnitTest` эффективный знаменатель - 480, гейт считает 460: занижение на 4.2 %.
- Для `testLiteDebugUnitTest` занижения нет: `lite` не монтирует ни одного общего тестового набора.

Зона существовала и до S1450 - `testStandard`, `testNoLegal`, `testVr` не покрывались никогда. S1450 и S1433 добавили в неё ещё пять классов, но не создали её.

## Ответ на вопрос

Да, список выводится из build-файла. Гейт полноты обязан получать эффективный набор источников для своего `-TaskDir` через тот же разборщик карты монтирования, что и основная проверка из артефакта 01, а не через собственную копию карты. Алгоритм:

1. Из имени `-TaskDir` вида `test<Flavor><BuildType>UnitTest` выделить флейвор.
2. Эффективные корни исходников = `src/test` + `src/test<Flavor>` (если каталог существует) + общие тестовые наборы, смонтированные в `test<Flavor>` по карте монтирования.

Условие «если каталог существует» обязательно: `testLegacy` смонтирован в build-файле, но каталога `app_v2/src/testLegacy` на диске нет.

## Следствие для порядка работ

Исправление этого гейта потребляет разборщик карты монтирования, поэтому идёт после того, как разборщик появится, и не является отдельной задачей: общая карта - единственная причина, по которой обе проверки живут в одном тикете.
