## 1. Проблема

На панельках файлов в Browse (список и сетка, портрет и ландшафт) кнопки «копировать», «переместить», «переименовать», «удалить» отображаются в строке каждого элемента. На небольших экранах и в портретной ориентации эти кнопки конкурируют за горизонтальное пространство с именем файла и прочими индикаторами. Пользователи, которые предпочитают компактное отображение списка, не имеют способа убрать эти кнопки из строки, не теряя к ним доступа. Дополнительные операции, специфичные для типа файла (например, «поделиться», «избранное», «запланировать», «добавить ресивер»), сейчас рассеяны по отдельным местам UI или недоступны прямо из строки файла.

---

## 2. Цели

1. Появляется настройка интерфейса «Операции с файлами показывать в меню» (по умолчанию выключена).
2. При включённой настройке на каждой строке файла (портрет и ландшафт, список и сетка) присутствует только одна кнопка «⋮» (три точки), открывающая ниспадающее меню.
3. В меню собраны: копировать, переместить, переименовать, удалить, а также все операции, которые доступны в панели команд плейера для данного файла в данном ресурсе, — кроме встроенного воспроизведения. Список генерируется динамически при нажатии «⋮».
4. Состав меню динамичен: позиции, недоступные из-за настроек разрешений или типа файла, скрыты или задизейблены.
5. Кнопка «Воспроизвести» (inline play) остаётся отдельной — не попадает в меню ни при каких условиях.
6. При выключённой настройке поведение строки файла не отличается от текущего (обратная совместимость полная).

**Non-goals:**

- Изменение поведения кнопок на глобальной панели инструментов Browse (она отвечает за операции с выделением, а не за одиночный файл).
- Изменение логики сортировки, фильтрации и поиска.
- Применение операций из меню «⋮» сразу ко всем выделенным файлам в режиме мультиселекта (меню всегда относится только к файлу, на котором нажали «⋮»).
- Перевод операций в контекстное меню по долгому нажатию (Long Press) вместо отдельной кнопки «⋮».
- Изменение поведения в режиме Wear OS.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Единый пункт меню «⋮» для всех типов файлов, список позиций динамически зависит от типа.
2. Порядок позиций в меню: сначала «базовые» (копировать, переместить, переименовать, удалить), затем «расширенные» (специфичные для типа), разделённые дивайдером.
3. При включении опции рекомендуется показывать toast/hint «Операции перемещены в меню ⋮ на каждом файле» — один раз.

### 3.2 Жёсткие ограничения

- **Flavor:** все флейворы (`standard`, `lite`, `photos`, `legacy`); доступность конкретных позиций меню следует уже существующим flavor-гейтам (копирование — только там, где оно разрешено; аудио-специфичные — только в `standard`/`legacy` и т.д.).
- **API level:** без API-специфики (минимальный Android 8 / API 26).
- **Wear OS:** не затрагивается.
- **Производительность:** `PopupMenu` строится на лету при каждом нажатии «⋮»; видимость позиций определяется уже вычисленным состоянием файла — никаких сетевых или дисковых операций при открытии меню.
- **Совместимость данных:** новый bool-флаг добавляется в DataStore (не Room); миграция схемы не требуется, дефолт `false`.
- **Локализация:** EN/RU/UK — все три обязательны для label кнопки «⋮», label опции в настройках и всех новых строк меню.
- **Доступность:** кнопка «⋮» должна иметь `contentDescription`; `PopupMenu` Android обеспечивает базовую навигацию клавиатурой/TalkBack стандартными средствами; touch target кнопки «⋮» — не менее 32 × 32 dp.
- **Коммуникационная политика:** если при включении/выключении опции показывается подсказка — тон и формула соответствуют `docs/COMMUNICATION_POLICY.md` (§6 tone checklist обязателен перед коммитом строк).

## 4. Контекст текущей архитектуры

Панелька файла в Browse — это `ViewHolder` адаптера списка. В текущей реализации набор кнопок операций (копировать, переместить, переименовать, удалить, воспроизвести) располагается непосредственно в XML-шаблоне строки; видимость кнопок управляется менеджером кнопок, который читает настройки из `AppSettings` и скрывает недоступные позиции. Операции более высокого уровня (поделиться, избранное, открыть во внешнем окне и т.д.) сейчас либо вынесены в отдельные кнопки вне строки, либо доступны только через панель инструментов. `AppSettings` хранит булевы флаги разрешений (`allowRename`, `allowDelete`, `enableCopying`, `enableMoving`) и отдельный флаг `hideGridActionButtons` для сетки — архитектура поддерживает добавление нового глобального флага режима отображения.

Задача требует: нового поля в `AppSettings` + `SettingsManager`; изменения логики менеджера кнопок адаптера (переключение между «прямые кнопки» и «кнопка ⋮ + PopupMenu»); добавления нового пункта в экран настроек интерфейса; обновления XML-шаблонов строк (портрет и ландшафт, список и сетка).

## 5. Предлагаемый подход

Вводится один булев флаг в модели настроек, по умолчанию `false`. Вся логика переключения режима отображения (кнопки vs. меню) сосредоточена в слое управления кнопками адаптера — ViewModel и Use Cases остаются без изменений.

### 5.1 Основные столпы / модули

**А. Модель настроек и персистентность**
- Новый флаг `fileOpsInOverflowMenu: Boolean = false` в доменной модели настроек.
- Чтение/запись через существующий DataStore-провайдер настроек без миграции схемы.

**Б. Экран настроек интерфейса**
- Новый переключатель в секции «Интерфейс» (или ближайшей подходящей) существующего экрана настроек.
- Стандартный паттерн toggle/switch row согласно `docs/ARCHITECTURE.md` § «UI Patterns — Trigger Row».
- Help-текст объясняет: «Кнопки операций убираются в меню ⋮ на каждом файле. Кнопка воспроизведения остаётся отдельно».

**В. Адаптер Browse: логика отображения кнопок**
- При `fileOpsInOverflowMenu = false` — текущее поведение, кнопки показываются напрямую.
- При `fileOpsInOverflowMenu = true` — кнопки операций скрыты, появляется кнопка «⋮»; при нажатии строится `PopupMenu` с позициями, отфильтрованными по типу файла и разрешениям.
- Кнопка `btnPlayInline` (воспроизвести) — всегда отдельная, никогда не попадает в меню.
- XML-шаблоны строк (portrait + landscape, list + grid) обновляются: добавляется кнопка «⋮», видимость управляется из кода.
- **Grid-режим:** при `fileOpsInOverflowMenu = true` кнопка «⋮» появляется в grid-ячейке всегда, независимо от флага `hideGridActionButtons`; последний игнорируется, пока опция включена.
- **Мультиселект:** кнопка «⋮» остаётся видимой в режиме мультиселекта; открывшееся меню применяется только к тому файлу, на котором нажали «⋮», — не ко всем выделенным.

**Г. Матрица операций в меню**
- Базовые (для всех типов, при наличии разрешений): копировать, переместить, переименовать, удалить.
- Расширенные: полный набор команд, доступных в панели команд плейера для данного файла в данном ресурсе. Список вычисляется динамически при нажатии «⋮» — тот же механизм, что строит тулбар плейера. Кнопка воспроизведения из этого набора исключается.
- **Дополнительно в grid-режиме:** операции «переместить вверх» и «переместить вниз» добавляются в меню при `fileOpsInOverflowMenu = true`, даже когда `hideGridActionButtons = true`.
- Порядок: базовые → расширенные, разделённые дивайдером.
- Позиции, недоступные по настройкам (`allowRename = false`, flavor-гейт и т.д.), не отображаются.

### 5.2 Потоки данных и событий

```
Пользователь нажимает ⋮ на строке файла
  → адаптерный менеджер кнопок запрашивает у ViewModel тип файла + AppSettings
  → строится PopupMenu с отфильтрованными позициями
  → выбор позиции → callback в ViewModel → UseCase → Repository
```

Флаг `fileOpsInOverflowMenu` течёт из `SettingsRepository` → `ViewModel` → адаптер при каждом `onBindViewHolder`.

### 5.3 Точки расширяемости

- Матрица операций для каждого типа файла должна оставаться открытой к добавлению новых позиций без изменения базовой логики переключения режима.
- Сам механизм «⋮ → PopupMenu» реализуется как переиспользуемый helper, чтобы его можно было применить и к grid-режиму без дублирования кода.

## 6. Открытые вопросы / Research items

1. **Какие именно «прочие операции» для каждого типа файла попадают в меню**
   - **Вопрос:** нужен точный список операций, специфичных для типа (видео, аудио, изображение, документ, папка), которые сейчас либо выведены отдельными кнопками в строке, либо доступны только по тапу на файл или через глобальную панель.
   - **Решение:** расширенные позиции берутся из того же набора, что формирует панель команд плейера для данного файла в данном ресурсе; меню строится динамически при нажатии «⋮». Воспроизведение из набора исключается.
   - **Статус:** Resolved

2. **Поведение при активной мультиселекции**
   - **Вопрос:** если пользователь включил чекбоксы (multiselect mode) и нажал «⋮» на одном файле — открывается ли меню для него одного, или операция применяется ко всем выделенным?
   - **Решение:** меню применяется только к тому файлу, у которого нажали «⋮»; выделение остальных файлов на операцию не влияет.
   - **Статус:** Resolved

3. **Grid-режим: совместимость с `hideGridActionButtons`**
   - **Вопрос:** существующий флаг `hideGridActionButtons = true` уже убирает кнопки с grid-ячеек. Если `fileOpsInOverflowMenu = true`, нужно ли добавлять «⋮» в grid-ячейку, или в grid-режиме меню недоступно?
   - **Решение:** «⋮» в grid-режиме всегда появляется при включённой опции, игнорируя `hideGridActionButtons`; в меню дополнительно попадают операции «переместить вверх» и «переместить вниз».
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Кнопка «⋮» в строке файла vs. long-press контекстное меню**

- **Решение:** отдельная видимая кнопка «⋮» в строке.
- **Альтернативы:** long-press на строке файла открывает контекстное меню (как в большинстве файловых менеджеров).
- **Почему:** long-press конфликтует с существующим механизмом мультиселекта (он тоже активируется долгим нажатием). Явная кнопка «⋮» дискаверабельна и не создаёт конфликтов жестов.

**ADR-2: Новый флаг в DataStore vs. новый экран настроек «Интерфейс»**

- **Решение:** флаг добавляется в существующую модель настроек; опция размещается в существующем экране «Интерфейс/Общие».
- **Альтернативы:** создание отдельного экрана «Browse UI».
- **Почему:** объём изменений не оправдывает новый экран; будущий рефакторинг настроек вынесет опцию при необходимости.

**ADR-3: Источник расширенных позиций меню — панель команд плейера**

- **Решение:** расширенные пункты «⋮»-меню берутся из того же механизма, что строит тулбар плейера для данного файла+ресурса; отдельной таблицы «что показывать в Browse-меню» нет.
- **Альтернативы:** явная матрица «тип файла → список пунктов», управляемая независимо от плейера.
- **Почему:** единая точка истины для набора операций над файлом устраняет риск рассинхронизации Browse-меню и плейера при добавлении новых команд.

## 11. Критерии готовности (strategic-level)

1. В настройках приложения (секция «Интерфейс» или аналогичная) появился переключатель «Операции с файлами показывать в меню»; при первом включении показывается однократный hint.
2. При включённой опции: на каждой строке файла (список-портрет, список-ландшафт, сетка) отображается кнопка «⋮»; нажатие открывает меню с базовыми и расширенными операциями, отфильтрованными по типу и разрешениям.
3. Расширенный состав меню соответствует набору команд, доступных в панели плейера для данного файла; воспроизведение из меню исключено.
4. В grid-режиме при включённой опции «⋮» отображается всегда (независимо от `hideGridActionButtons`); в меню доступны «переместить вверх» и «переместить вниз».
5. При нажатии «⋮» в режиме мультиселекта меню применяется только к этому файлу; выделение остальных файлов не затрагивается.
6. Кнопка воспроизведения (inline play) присутствует в строке независимо от значения опции.
7. При выключённой опции поведение строки файла не отличается от текущего — регрессий нет.
8. Все строки меню локализованы на EN, RU, UK.
9. Ни один из существующих flavor-гейтов (`allowRename`, `allowDelete`, `enableCopying`, `enableMoving`, flavor-флаги) не нарушен.
