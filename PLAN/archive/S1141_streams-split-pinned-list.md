## 1. Проблема

На экране трансляций все каналы показываются одним списком (сетка или список); закреплённые каналы лишь всплывают наверх того же списка через порядок, но не выделены отдельной секцией. Пользователь не может держать закреплённые каналы всегда на виду, листая при этом основной список - при прокрутке закреплённые уезжают вместе со всеми. Нужна возможность видеть закреплённые каналы постоянно, независимо от прокрутки основного списка.

---

## 2. Цели

1. Разделить экран трансляций на две вертикально стоящие секции: закреплённые (сверху) и основной (снизу).
2. Показывать секцию закреплённых только при наличии хотя бы одного закреплённого канала.
3. Применять к обеим секциям одни и те же правила/фильтры/порядок и режим сетка-список; закреплённая показывает только закреплённые каналы, основная - незакреплённые.
4. Сделать секции независимо прокручиваемыми и одновременно видимыми.
5. Дать каждой секции сворачиваемую шапку: сворачивание отдаёт место другой секции.
6. Гарантировать, что играет только один канал - из верхней или нижней секции.

**Non-goals:**

- Изменение самого механизма закрепления (`pinned`/`sortIndex` уже существуют).
- Персист состояния свёрнутости между сессиями (MVP - обе развёрнуты по умолчанию).
- Новые режимы фильтрации.

## 4. Контекст текущей архитектуры

Экран трансляций (`ui/streams/`) показывает один RecyclerView через адаптеры сетки и списка, с общими фильтрами/порядком из ViewModel; закрепление уже есть в данных канала (`pinned`, `sortIndex`), но лишь влияет на порядок единого списка. Проблему из §1 нельзя решить на месте, потому что одна прокручиваемая область не может одновременно держать закреплённые на виду и листать основной список - нужна двухсекционная компоновка с независимой прокруткой, сворачиваемыми шапками и разделением данных на два потока (закреплённые/незакреплённые) поверх существующего конвейера фильтров.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

1. **Разделение данных на два потока.** Слой представления делит отфильтрованный/упорядоченный список каналов на закреплённые и незакреплённые, применяя одни правила к обоим.
2. **Двухсекционная компоновка.** Две вертикально стоящие прокручиваемые секции (верх - закреплённые, низ - основной), каждая переиспользует существующие адаптеры сетки/списка; верхняя скрыта при отсутствии закреплённых.
3. **Сворачиваемые шапки.** Каждая секция имеет шапку-переключатель; сворачивание перераспределяет вертикальное место в пользу другой секции.
4. **Координация единственного воспроизведения.** Гарантия «играет один канал» независимо от секции - через общий слой выбора активного канала.

### 5.2 Потоки данных и событий

- Данные: ViewModel (фильтр/порядок) → делитель на закреплённые/незакреплённые → два адаптера (верх/низ).
- Сворачивание: тап по шапке → helper перераспределяет высоты секций.
- Воспроизведение: тап по каналу в любой секции → общий слой активного канала (останавливает предыдущий, стартует новый).

### 5.3 Точки расширяемости

- Делитель потоков расширяем под будущие группировки (не только pinned/unpinned).
- Компоновка секций не привязана к режиму сетка-список - оба работают в каждой секции.

## 9. Архитектурные решения (ADR)

- **ADR-1:** две секции - через взвешенные высоты (`LinearLayout` weights) с двумя независимыми RecyclerView, а не общий NestedScrollView. Причина: нужна независимая прокрутка и постоянная видимость обеих.
- **ADR-2:** переиспользовать существующие адаптеры сетки/списка для обеих секций, не создавать новые. Причина: «такой же список» (пожелание владельца), меньше дублирования.
- **ADR-3:** логику секций/сворачивания вынести в новый helper-менеджер (`Streams*SectionsManager`), не в `StreamsActivity`. Причина: активити 898 LOC, Rule 2/3.
- **ADR-4:** единственность воспроизведения - через общий слой активного канала, не через локальное состояние секции. Причина: канал может играть из любой секции.

## 11. Критерии готовности (strategic-level)

1. При наличии закреплённых каналов экран показывает две секции: закреплённые сверху, основной снизу.
2. Секция закреплённых отсутствует, если закреплённых каналов нет.
3. К обеим секциям применяются одни фильтры/порядок и режим сетка-список; верх - закреплённые, низ - незакреплённые.
4. Секции прокручиваются независимо и видны одновременно.
5. Тап по шапке сворачивает секцию, отдавая место другой; закреплённая разворачивается до основной, основной - до низа.
6. Играет только один канал независимо от секции.
7. Все 3 варианта лейаута (portrait/land/w600dp) ведут себя согласованно.
