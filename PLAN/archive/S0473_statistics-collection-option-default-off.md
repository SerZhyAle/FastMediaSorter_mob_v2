## 1. Проблема

Приложение выполняет множество действий пользователя - сортировку, копирование, удаление, просмотр, захват, распознавание, - но нигде не показывает, сколько и чего было сделано. Пользователь не видит ни своей активности, ни пользы (сколько места освобождено, сколько дублей убрано, сколько времени в плеере). Возможности «посмотреть итоги за период» нет.

При этом любой сбор данных об использовании - чувствительная тема. Нужен механизм, который по умолчанию ничего не накапливает и включается только осознанным выбором пользователя, а собранное остаётся строго на устройстве.

Область: сквозная (слой операций над файлами, плееры, захват, источники) плюс новый экран в настройках.

## 2. Цели

1. Дать пользователю наглядную сводку его активности в приложении в отдельном окне «Статистика».
2. Детальный сбор активности - выключен по умолчанию; накапливается только после явного включения тумблера.
3. Минимальный технический набор (первый запуск, число запусков, версия первой установки) копить всегда, независимо от тумблера, - иначе момент первого старта восстановить нельзя.
4. Пункт «Статистика» в настройках показывать только при включённом тумблере; накопленные always-on данные становятся видны после включения сбора.
5. Показывать практическую пользу: освобождённое место, убранные дубли, перенесённые/отсортированные файлы, время в плеере (итоги за всё время).
6. Не влиять на видимую производительность горячих путей операций при включённом сборе.
7. Корректно вести себя по флейворам - показывать только метрики тех возможностей, что доступны в данной сборке.
8. Дать пользователю отправить свою сводку автору одной кнопкой - письмо со статистикой во вложении в его дефолтном email-клиенте, отправку подтверждает сам пользователь.

**Non-goals:**

- Никакой фоновой/автоматической телеметрии и облачной аналитики - данные покидают устройство только по явному действию пользователя (кнопка «Отправить автору»), и только агрегированные числа.
- Не диагностический/отладочный инструмент - это пользовательская сводка, а не лог для разработчика.
- Без межустройственной агрегации в первой итерации (статистика часов Wear, если будет, считается отдельно).
- Без хранения имён файлов/полных путей как PII (счётчики обезличены).
- Без «Сброса статистики» - такой функции не предусмотрено.
- Сводка не включается в Backup & Restore - это снимок активности, а не настройка.
- Без статистики на Wear OS в первой итерации.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Сгруппировать метрики по смыслу (операции, захват, просмотр, редактирование, источники, использование).
2. Сводные «карточки-итоги» сверху окна (самое важное одним взглядом).
3. Простая визуализация распределения по типам файлов (например, доля изображений/видео/аудио/документов).
4. Отправка сводки автору одной кнопкой и, опционально, экспорт в файл.
5. Явная подпись о приватности прямо в окне: данные хранятся на устройстве, письмо автору отправляет сам пользователь.

### 3.2 Жёсткие ограничения

- **Flavor:** все (standard, lite, photos, legacy, vr/noLegal). Набор метрик адаптируется к возможностям флейвора; недоступные категории скрываются, а не показываются с нулём.
- **API level:** без API-специфики; работает от minSdk 23 (legacy) и выше.
- **Wear OS:** в первой итерации не затрагивается.
- **Производительность:** запись счётчиков - вне UI-потока; инкремент в памяти + батчевый сброс на диск (по дебаунсу или при уходе в фон), без посимвольной записи в хранилище на каждое событие. Пакетная операция (массовое копирование/удаление) даёт один сброс, а не запись на файл. Недопустимо тормозить копирование/удаление/листание.
- **Передача данных:** нет фоновой/автоматической отправки. Сводка покидает устройство только по явному нажатию «Отправить автору»: создаётся письмо в дефолтном email-клиенте со статистикой во вложении (формат TXT, читаемый текст), предзаполненными темой и адресом автора; отправку подтверждает сам пользователь.
- **Видимость окна:** пункт «Статистика» в настройках присутствует только при включённом тумблере. При выключенном - пункт скрыт; always-on метрики продолжают копиться, но не показываются, пока сбор не включат.
- **Поведение при выключении:** выключение тумблера стирает накопленную детальную активность; always-on метки (первый запуск, число запусков, версия установки) сохраняются.
- **Период:** в первой итерации - только итоги «за всё время»; разбивки по периодам и графиков-во-времени нет.
- **Совместимость данных:** новое локальное хранилище счётчиков/агрегатов; форма - аддитивная, без ломающих изменений существующих данных.
- **Локализация:** EN/RU/UK - обязательно для всех новых строк (название опции, заголовки окна, подписи метрик, кнопки, подпись о приватности).
- **Доступность:** окно - визуальное; контраст из темы (`?attr`), значения не только цветом, поддержка TalkBack и D-pad/TV-фокуса, корректность в портрете и ландшафте.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** none
- **Placement:** пункт «Статистика» во вкладке настроек General, виден только при включённом тумблере «Сбор статистики».
- **Default state:** тумблер выключен по умолчанию; детальный сбор не идёт, always-on метки копятся всегда.
- **Flavors:** все варианты сборки; категории метрик скрываются по доступным возможностям флейвора.
- **Data egress:** только пользователь-инициированное письмо автору (TXT-вложение); фоновой передачи нет.

## 4. Контекст текущей архитектуры

Действия пользователя проходят через слой use-case'ов операций (копирование, перемещение, удаление, архивирование, поиск дублей), флоу захвата (камера/голос/жестовый скриншот) и плееры (изображение/видео/аудио/документы). Настройки приложения хранятся в локальном preferences-хранилище и репозитории настроек; экран настроек собран из вкладок-фрагментов (General, Operations, Media, Audio, Video, Documents и др.). Аналитики/телеметрии в проекте нет вовсе - это «зелёная поляна», и она должна остаться полностью оффлайновой.

Сейчас исходы операций нигде не агрегируются: результат действия применяется и забывается. Поэтому без новой точки учёта (счётчиков) и хранилища агрегатов показать сводку невозможно - её просто неоткуда взять.

## 5. Предлагаемый подход

Ввести опциональный локальный слой учёта: единый «приёмник событий статистики», который вызывается из уже существующих точек завершения операций и сессий. При выключенном тумблере приёмник - no-op (ничего не пишет). При включённом - асинхронно инкрементирует локальные агрегаты, которые читает экран «Статистика». Никаких сетевых путей.

### 5.1 Основные столпы / модули

- **Always-on baseline** - минимальные технические метки (первый запуск, число запусков, версия первой установки) копятся вне тумблера; иначе момент первого старта не восстановить.
- **Opt-in gate** - флаг «Сбор статистики» в настройках (General), по умолчанию выключен; включает детальный сбор активности и делает видимым пункт «Статистика».
- **Stats sink (приёмник)** - тонкая точка приёма событий активности из горячих путей; при выключенном флаге не делает ничего.
- **Local aggregate store** - локальное хранилище счётчиков и периодических агрегатов (всё на устройстве).
- **Stats dashboard** - окно «Статистика»: чтение итоговых агрегатов за всё время; доступно только при включённом тумблере.
- **Author report sender** - формирование TXT-сводки во вложении (плюс тех. контекст сборки/устройства) и запуск email-intent дефолтного клиента на адрес автора по явному действию. Адрес автора хранится как константа/строковый ресурс.

### 5.2 Потоки данных и событий

- Always-on: первый запуск фиксируется один раз при установке; счётчик запусков и версия первой установки пишутся независимо от тумблера.
- Запись активности: завершение операции/сессии → приёмник (если gate включён) → инкремент счётчика в памяти → батчевый сброс агрегатов в локальное хранилище (дебаунс / уход в фон). Горячий путь не ждёт записи на диск.
- Чтение: окно «Статистика» (видно только при включённом тумблере) → чтение итоговых агрегатов за всё время → рендер карточек, секций и распределения, включая ранее накопленные always-on метки.
- Выключение: тумблер off → детальные агрегаты активности стираются, always-on метки остаются.
- Отправка автору: кнопка → вся видимая сводка + тех. контекст (версия, флейвор, устройство, Android) сериализуются в TXT-вложение → письмо в дефолтном email-клиенте с предзаполненными адресом/темой и вложением → пользователь сам решает, отправлять ли.

### 5.3 Точки расширяемости

- Каталог метрик расширяем: новая возможность приложения добавляет свою метрику без переделки окна.
- Адаптация по флейвору: категория скрывается, если возможность недоступна в сборке.
- Периоды как параметр: today/week/all - расширяемо на пользовательский диапазон позже.

### 5.4 Каталог метрик (предложение)

Группы и конкретные показатели. Каждый счётчик - локальный; где осмысленно, помимо количества учитывается объём (байты) или длительность (время). Категории, недоступные во флейворе, скрываются.

**A. Операции над файлами**
- Скопировано файлов - количество и суммарный объём.
- Перемещено (отсортировано) файлов - количество и объём.
- Удалено файлов - количество и освобождённый объём.
- Заархивировано/разархивировано - количество.
- Создано папок.
- Быстрая сортировка через панель назначений - количество действий, в т.ч. разбивка по избранным папкам-целям.
- Поиск дублей - число запусков, удалено дублей, освобождено места.

**B. Захват**
- Снято фото.
- Записано видео.
- Записано голосовых заметок.
- Сделано жестовых скриншотов (standard).

**C. Просмотр и воспроизведение**
- Просмотрено изображений.
- Воспроизведено видео - количество и суммарное время просмотра.
- Прослушано аудио - количество треков и суммарное время (включая фоновое воспроизведение через сервис).
- Открыто документов (PDF/EPUB/Office) - количество, опц. прочитано страниц.
- Запущено слайдшоу.
- Экспортировано кадров GIF/видео.

**D. Редактирование и создание**
- Отредактировано изображений (кроп/фильтр/коррекция).
- Создано рисунков/аннотаций.
- Создано/изменено текстовых заметок.
- Распознаваний текста (OCR) и переводов выполнено.

**E. Источники и сеть** *(скрыто в lite/photos, где сеть/облака недоступны)*
- Подключено ресурсов - разбивка по типу (local/SMB/FTP/SFTP/cloud).
- Передано по сети - объём (загрузка/выгрузка).
- Сканирований NAS выполнено.

**F. Использование** *(метки с пометкой [always-on] копятся вне тумблера)*
- Дата/время первого запуска и число дней с тех пор. [always-on]
- Версия (и флейвор) приложения на момент первой установки. [always-on]
- Запусков приложения - общий счётчик. [always-on]
- Сессий и суммарное активное время (на переднем плане).
- Самая используемая возможность / самый используемый ресурс.

**G. Обработка файлов по типам**
- Количество обработанных файлов в разбивке по типу медиа (изображения / видео / аудио / документы / прочее).
- Матрица «действие × тип»: сколько изображений/видео/аудио/документов было скопировано, перемещено, удалено - чтобы видеть, что и как обрабатывается чаще.
- Суммарный объём обработанных файлов по типам.

**H. Производные сводки** *(итоги за всё время; разбивки по периодам нет в первой итерации)*
- Топ папок-назначений по числу операций.
- Распределение действий по типам файлов (доли).

### 5.5 Дизайн окна «Статистика»

Отдельный экран, открывается из настроек (General) по пункту «Статистика», который виден только при включённом тумблере. Структура сверху вниз:

- **Шапка**: заголовок «Статистика». Итоги показываются за всё время (переключателя периода нет в первой итерации).
- **Сводные карточки** (2–3 в ряд, переносятся в ландшафте): «Отсортировано файлов», «Освобождено места», «Время в плеере». Крупное значение + подпись + иконка.
- **Распределение по типам**: компактная полоса/кольцо с долями изображений/видео/аудио/документов и легендой значениями (не только цветом).
- **Секции-аккордеоны** по группам каталога (Операции, Захват, Просмотр, Редактирование, Источники, Использование). Каждая строка: иконка + подпись метрики + значение (+ вторичное: объём/время). Пустые/недоступные категории не показываются.
- **Подпись о приватности** под списком: данные хранятся на устройстве; письмо автору вы отправляете сами из своего почтового клиента.
- **Действия внизу**: «Отправить автору» (создаёт письмо на serzhyale@gmail.com в дефолтном email-клиенте со всей видимой сводкой во вложении; отправку подтверждает пользователь) и опционально «Экспортировать» (сохранить сводку в файл). Кнопки «Сбросить» нет.
- **Пустое состояние**: если сбор только что включён и активности ещё нет - дружелюбная заглушка с пояснением, что метрики появятся по мере использования (always-on метки первого запуска уже показаны).

## 9. Архитектурные решения (ADR)

- **ADR-1: Без фоновой телеметрии; отправка только пользователем.** Никаких сетевых путей записи и сторонних SDK аналитики. Сводка покидает устройство исключительно по явному нажатию «Отправить автору»: TXT-письмо со статистикой во вложении (плюс тех. контекст - версия, флейвор, модель устройства, версия Android, без идентификаторов пользователя) создаётся в дефолтном email-клиенте, отправку подтверждает пользователь. Причина: приватность - главный драйвер требования «выключено по умолчанию».
- **ADR-2: Opt-in для детального сбора, always-on для технического минимума, стирание при выключении.** Детальная активность не пишется, пока пользователь не включил тумблер, и стирается при выключении. Исключение: первый запуск, число запусков и версия первой установки копятся всегда - иначе момент первого старта восстановить невозможно. Причина: минимизировать сбор без согласия, не теряя неповторимые технические метки.
- **ADR-7: Только итоги «за всё время» в первой итерации.** Без суточных корзин, разбивок по периодам и графиков-во-времени. Причина: проще хранилище и UI; периоды можно добавить позже.
- **ADR-3: Окно видно только при включённом сборе.** Пункт «Статистика» появляется в настройках лишь когда тумблер включён; always-on метки становятся видны после включения. Причина: не показывать пустой экран и держать единую точку входа за privacy-гейтом.
- **ADR-4: Без «Сброса статистики».** Функция сброса не предусмотрена. Причина: владелец счёл её ненужной.
- **ADR-5: Запись через no-op-приёмник из существующих точек завершения.** Причина: не размазывать условную логику по горячим путям и дёшево отключать сбор.
- **ADR-6: In-memory счётчики + батчевый сброс на диск.** Инкремент в памяти, запись пачкой по дебаунсу/уходу в фон. Причина: исключить видимое влияние на производительность при пакетных операциях.

## 11. Критерии готовности (strategic-level)

1. В настройках (General) есть тумблер «Сбор статистики», по умолчанию выключенный.
2. При выключенном тумблере детальная активность не накапливается, а пункт «Статистика» в настройках скрыт.
3. Always-on метки (дата первого запуска, число запусков, версия первой установки) копятся независимо от тумблера и видны в окне после включения сбора.
4. После включения тумблера пункт «Статистика» появляется и действия пользователя отражаются в окне.
5. При выключении тумблера детальная активность стирается, always-on метки сохраняются.
6. Окно показывает итоги за всё время: сводные карточки, распределение по типам и сгруппированные метрики из §5.4 (включая обработку по типам), релевантные текущему флейвору. Переключателя периода и кнопки «Сбросить» нет.
7. В окне присутствует подпись о приватности (данные на устройстве, письмо отправляет сам пользователь).
8. Кнопка «Отправить автору» создаёт письмо на serzhyale@gmail.com в дефолтном email-клиенте с TXT-сводкой во вложении (метрики + версия/флейвор/устройство/Android); отправку подтверждает пользователь.
9. Все новые строки локализованы EN/RU/UK; окно корректно в портрете и ландшафте, доступно с D-pad и TalkBack.
10. Включённый сбор не вызывает заметных задержек в операциях над файлами и листании, в том числе при пакетных операциях.
