# 01 - Стратегия разрешения при обрезке (§6.1)

**Ticket:** S0679
**Item:** §6.1 - разрешение результата при обрезке
**Status:** Resolved (решение владельца 2026-06-25 + находка в коде)

## Решение владельца

Для локальных файлов обрезка восстанавливает исходное разрешение области; аннотации масштабируются в полный размер. Для не-локальных/сетевых источников и случаев, где исходник недоступен в полном разрешении, - откат на обрезку рабочей (экранной) композиции.

## Находка в коде (что переиспользуем)

Существующий движок файловой обрезки уже реализует ровно нужный полноразрешённый путь:

- Маппинг нормализованного экранного прямоугольника в пиксельные координаты исходника с коррекцией EXIF-ориентации.
- Регион-декод области исходного файла без полной распаковки картинки (поэтапный декодер региона), с поворотом результата под отображаемую ориентацию.
- Перекодирование в исходный формат (JPEG/PNG/WEBP) и атомарная запись.
- Поддержка локальных и сетевых источников: для сетевых сначала скачивается локальная копия в кэш.

Вывод: полноразрешённый кроп области исходника - решённая задача; новый инструмент опирается на тот же подход для базового слоя, а аннотации (хранящиеся в экранных координатах) пересчитываются в систему координат обрезанной области и накладываются в полном масштабе.

## Следствия для тактики

- Базовый слой обрезается из исходного файла (полное разрешение), не из экранного битмапа.
- Аннотации нужно трансформировать: экранные координаты -> нормализованные по области -> пиксели полноразрешённого результата.
- Сетевые/недоступные исходники -> явный откат на рабочую композицию (документировать в строках/поведении).
- Многократная обрезка за сессию должна сохранять привязку к исходнику до тех пор, пока это возможно (см. §6.3).

## Открытое последствие

После первой обрезки «база» уже не равна исходному файлу 1:1 (область + ориентация). Для второй обрезки в той же сессии полноразрешённость опирается на результат первой обрезки, а не на исходный файл - это приемлемо, но должно быть учтено в тактике (composability, без накопления потерь сверх неизбежного перекодирования).
