## 1. Проблема

Экран «Трансляции» показывает источники только списком: строка = иконка-фавикон + название. Чтобы понять, что именно сейчас идёт на канале, пользователь вынужден открывать каждый поток в полноэкранном плеере по очереди. Нет способа обозреть несколько каналов сразу. Запрос владельца: «таблица из телевизоров» - сетка ячеек, в каждой текущий кадр потока, чтобы с одного взгляда видеть, что где транслируется.

---

## 2. Цели

1. В экране «Трансляции» доступен альтернативный режим отображения - сетка ячеек вместо списка.
2. Каждая ячейка сетки показывает снимок текущего кадра соответствующего видеопотока (превью «как на телевизоре»), а не статичный фавикон.
3. Кадры обновляются: при входе в режим и по явному обновлению (pull-to-refresh), плюс периодически в фоне с разумным интервалом.
4. Переключение список/сетка сохраняется между сессиями и не ломает существующие фильтрацию, сортировку, импорт каталога.
5. Тап по ячейке открывает поток так же, как тап по строке списка (поведение воспроизведения не меняется).

**Non-goals:**

- Одновременное непрерывное воспроизведение нескольких живых видео в ячейках («стена живых ТВ» в движении) - вне объёма первой итерации; ячейка несёт снимок текущего кадра, не движущееся видео.
- Звук в ячейках сетки - в режиме сетки все потоки беззвучны.
- Захват кадра для чисто аудио-источников - у них нет видеокадра; ячейка использует существующее фавикон/плейсхолдер-представление.
- Сетка трансляций во flavor'ах без поддержки трансляций (lite, photos).

## 4. Контекст текущей архитектуры

Экран «Трансляции» отображает источники из локальной БД через ViewModel и адаптер списка, привязанный к линейному менеджеру компоновки; ячейки рисуют фавиконы из заранее собранного спрайт-атласа, а не из видео. Воспроизведение потоков - одиночное: видео/RTSP открываются в полноэкранном плеере с единственным движком воспроизведения, аудио - в одном инлайн-движке. Захват кадра уже существует в проекте, но в других контекстах: текущий кадр локального/полноэкранного видео снимается из текстурной поверхности плеера, а постеры/превью VOD-файлов извлекаются метадата-ретривером. Ни один из этих путей не привязан к экрану трансляций и не рассчитан на «снимок живого потока». Сетевой живой поток не имеет фиксированной длины и не перематывается, поэтому метадата-ретривер для него неприменим - кадр можно получить только через кратко-живущий движок воспроизведения, отрисовавший хотя бы один кадр в текстурную поверхность.

Поэтому из §1 нельзя решить задачу «здесь и сейчас»: в области трансляций нет ни сеточной компоновки, ни механизма однократного снимка живого потока, ни кэша превью-кадров.

## 5. Предлагаемый подход

Добавить в экран «Трансляции» режим сетки как альтернативу списку. В режиме сетки каждая ячейка-превью пытается показать снимок текущего кадра своего видеопотока; источники без видео и потоки, кадр которых получить не удалось, откатываются на фавикон/плейсхолдер.

Снимок живого потока получается по схеме «короткой жизни»: открыть поток во временном движке воспроизведения с минимальным буфером и текстурной поверхностью, дождаться первого декодированного кадра, снять кадр с поверхности, немедленно освободить движок. Захваты выполняются последовательно/с малой ограниченной параллельностью под бюджет декодеров и памяти, в порядке видимых ячеек. Полученные кадры кладутся в кэш с TTL, чтобы при прокрутке и пересоздании ячеек не пересоздавать движок без нужды; устаревшие по TTL кадры обновляются при следующем показе/обновлении.

### 5.1 Основные столпы / модули

- **Переключатель режима отображения** - управление список/сетка в тулбаре экрана; выбранный режим персистится в настройках трансляций.
- **Сеточная компоновка** - адаптивное число колонок по ширине/ориентации, переиспользуя существующий в проекте паттерн расчёта числа колонок и отступов сетки.
- **Поставщик снимка кадра живого потока** - однократный жизненный цикл «открыть-дождаться кадра-снять-освободить», с ограничением параллельности и тайм-аутами/вотчдогом на зависший поток.
- **Кэш превью-кадров** - in-memory/временный кэш по URL потока с TTL и привязкой свежести; не персистентная БД.
- **Адаптер/ячейка превью** - отдельное представление ячейки с асинхронной загрузкой кадра, отменой при переиспользовании (как уже сделано для фавиконов) и fallback на фавикон/плейсхолдер.
- **Делегирование из Activity** - логика режима сетки и жизненного цикла снимков выносится в менеджер-хелперы (Activity без бизнес-логики), чтобы не раздувать экран.

### 5.2 Потоки данных и событий

- UI (переключатель) → слой состояния экрана → выбран режим сетки → компоновка переключается на сетку, персист флага.
- Ячейка становится видимой → запрос кадра у кэша → при промахе/устаревании → поставщик снимка (очередь с ограничением параллельности) → временный движок воспроизведения → первый кадр → снимок → кэш → ячейка.
- Поток без видео или неудача/тайм-аут захвата → ячейка показывает фавикон/плейсхолдер.
- Обновление (pull-to-refresh / периодический тик) → инвалидация кадров видимых ячеек по TTL → повторный захват.
- Тап по ячейке → существующий путь открытия потока (без изменений).

### 5.3 Точки расширяемости

- Стратегия захвата (снимок против будущего непрерывного воспроизведения на мощных устройствах) скрыта за ролью «поставщик снимка кадра» - возможна замена/расширение без переписывания UI.
- Политика свежести/частоты обновления (TTL, периодический тик, ручное обновление) вынесена отдельно и настраиваема.
- Лимит параллельности захвата - конфигурируемый, чтобы адаптировать под класс устройства.

## 9. Архитектурные решения (ADR)

- **ADR-1: snapshot вместо непрерывного мультивоспроизведения.** Запрос владельца дословно про «захват текущего кадра» и «видно что где идёт» - статичный текущий кадр удовлетворяет цели. Snapshot обходит аппаратный лимит параллельных декодеров, резко снижает RAM/сеть и реализуем на legacy. Непрерывное воспроизведение оставлено как точка расширения для мощных устройств.
- **ADR-2: гейт по существующей поддержке трансляций, без нового build-флага.** Режим - подрежим уже гейтированного экрана; рантайм-переключатель достаточен, новый flavor-флаг избыточен.
- **ADR-3: кэш кадров с TTL в памяти/временном хранилище, не персистентная БД.** Живой кадр быстро устаревает; персистить его бессмысленно, миграция Room не нужна.

## 11. Критерии готовности (strategic-level)

1. На экране «Трансляции» (flavor'ы с трансляциями) есть переключатель список/сетка; выбор сохраняется между запусками.
2. В режиме сетки видеопотоки показаны ячейками с снимком текущего кадра; аудио-источники и неудавшиеся захваты показывают фавикон/плейсхолдер.
3. Кадры обновляются при входе в режим, по ручному обновлению и периодически; устаревшие кадры заменяются.
4. Режим работоспособен на бюджетном устройстве (legacy) без OOM и без зависания очереди на недоступном потоке.
5. Фильтрация, сортировка, импорт каталога и открытие потока по тапу продолжают работать в обоих режимах.
6. lite/photos не показывают режим; новых build-флагов не добавлено.
7. Новые видимые строки локализованы EN/RU/UK; ячейка фокусируема и доступна.
