## 0. Захваченный материал (inbox)

**Захвачено:** 2026-07-03

**Текст:**

Для панели "быстрокго запуска" расширить список доступных функций FastMediaSorter, которые пользователь может добавить и использовать за счет всех элементов набора "Программы и сценарии", которые сейчас есть (появляются в меню или панели на глвном окне)

---

## 1. Проблема

Панель быстрого запуска (жест по краю экрана / плитка быстрых настроек / виджет) сегодня предлагает добавить лишь узкий фиксированный набор функций FastMediaSorter - калькулятор, мини-игру, OCR-перевод камерой, трансляции и избранное. Одновременно на главном экране существует более широкий и активно поддерживаемый набор "Программы и сценарии" (строка + выпадающее меню «ещё»), включающий также быструю камеру, быструю запись голоса, запись экрана и загрузку по ссылке. Пользователь, который хочет вызывать эти четыре функции без открытия приложения, не может добавить их на панель - хотя технически они уже реализованы и доступны с главного экрана. Разрыв затрагивает панель быстрого запуска (edge-gesture, QS-плитка, домашний виджет) и диалог выбора функции для добавления на неё.

---

## 2. Цели

1. Панель быстрого запуска предлагает пользователю все функции, которые сегодня входят в набор "Программы и сценарии" на главном экране, а не только текущие пять.
2. Пользователь может добавить на панель быструю камеру, быструю запись голоса, запись экрана и загрузку по ссылке - наравне с уже поддерживаемыми калькулятором, мини-игрой, OCR-переводом и трансляциями.
3. Нажатие такой плитки запускает функцию напрямую, без открытия главного экрана приложения - как и остальные плитки панели сегодня.
4. Состав функций панели и состав "Программы и сценарии" перестают быть двумя независимо поддерживаемыми списками - новая функция набора добавляется в реестр панели по тому же образцу, что и существующие пять.

**Non-goals:**

- Изменение состава, порядка или визуального оформления самого меню/строки "Программы и сценарии" на главном экране - эта спека только расширяет панель быстрого запуска.
- "Избранное" как элемент панели - уже существует в реестре панели, но не входит в набор "Программы и сценарии", остаётся без изменений.
- Отдельный экран/шаг выбора целевой папки для быстрой камеры в контексте панели - используется существующее поведение по умолчанию (см. §3.1, §6 п.1).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Загрузка по ссылке с панели ведёт себя так же, как с главного экрана - с диалогом подтверждения содержимого буфера обмена, а не безусловной отправкой без подтверждения.
2. Быстрая камера на панели снимает в папку по умолчанию без отдельного шага выбора цели - как уже происходит при использовании этой функции без предварительной настройки.

### 3.2 Жёсткие ограничения

- **Flavor:** запись экрана доступна на панели только там, где она уже включена сегодня (вариант standard со включённой записью экрана, а также noLegal); на lite/photos/legacy этот пункт не появляется в списке выбора панели - зеркалирует существующий гейт того же пункта в меню "Программы и сценарии".
- **API level:** без API-специфики - переиспользуются уже реализованные и выпущенные точки входа.
- **Wear OS:** не затрагивается.
- **Производительность:** без дополнительного бюджета - новые плитки панели переиспользуют существующие обработчики запуска функций.
- **Совместимость данных:** без миграции - новый элемент панели описывается в рамках уже существующего расширяемого формата хранения плитки, без изменения его структуры.
- **Локализация:** EN/RU/UK обязательна для подписей (название/описание) каждой из четырёх новых функций в списке выбора панели.
- **Доступность:** новые пункты списка выбора наследуют существующий контракт панели (размер области нажатия, TalkBack-подписи) без нового UI-паттерна.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** запись экрана на панели зеркалирует существующий flavor-гейт того же пункта в "Программы и сценарии" (standard с включённой записью экрана + noLegal; не показывается на lite/photos/legacy) - остальные три новые функции без flavor-специфики.
- **Localization:** новые подписи для 4 новых пунктов панели - EN/RU/UK, через существующий строковый пайплайн проекта.
- **UI placement contract:** новые пункты появляются только в существующем диалоге "добавить функцию FastMediaSorter" панели, без нового экрана; порядок пунктов ориентируется на порядок в "Программы и сценарии".
- **Accessibility:** наследуется существующий контракт списка выбора панели - без нового UI-паттерна.
- **Validation level:** функциональная, через `/spec-test-device` - запуск каждой новой плитки на эмуляторе/устройстве, включая проверку отсутствия пункта записи экрана на flavor без этой возможности.
- **Owner sign-off:** 2026-07-03 (ad-hoc-заявка владельца, зафиксирована в §0).
- **Related tickets:** S0663 (архивная спека, создавшая расширяемый реестр панели и явно предусмотревшая этот набор функций как будущее расширение), S0913 (последний пересмотр состава и порядка "Программы и сценарии").

## 4. Контекст текущей архитектуры

Панель быстрого запуска читает состав доступных к добавлению функций из закрытого реестра "наших функций", сегодня ограниченного пятью записями; каждая запись подключена в трёх согласованных местах - сам реестр, построитель команды запуска и проверка доступности. Набор "Программы и сценарии" на главном экране строится независимо другим компонентом и содержит более широкий, активно поддерживаемый список функций. Поскольку эти два списка собираются разным кодом, функция, добавленная в набор "Программы и сценарии", не появляется на панели автоматически - для этого требуется отдельное, намеренное добавление в реестр панели.

Часть функций набора уже имеет самостоятельную форму запуска, не требующую открытия главного экрана - она была построена ранее для других вызывающих сторон (жест по краю экрана, домашний виджет) и по своей природе пригодна для прямого подключения к панели. Оставшаяся часть сегодня вызывается только из обработчика, привязанного к главному экрану приложения, и не имеет собственной автономной формы запуска.

## 5. Предлагаемый подход

Расширить существующий реестр функций панели, добавив запись для каждой функции набора "Программы и сценарии", которая ещё отсутствует. Для функций, уже имеющих самостоятельную точку запуска, - подключить её напрямую к реестру, по образцу уже подключённых пяти. Для функции без такой точки - завести для неё собственную самостоятельную форму запуска, повторяющую архитектуру уже существующих, чтобы весь набор оставался однородным по способу вызова с панели.

### 5.1 Основные столпы / модули

- **Реестр функций панели** - единая точка расширения, где перечисляются все функции приложения, предлагаемые к добавлению на панель, вместе с признаком их доступности на текущем варианте сборки.
- **Самостоятельные точки запуска** - механизм вызова функции без зависимости от главного экрана; уже существует для части функций набора и распространяется на оставшуюся.
- **Диалог выбора функции** - существующий UI панели, где пользователь видит список и добавляет пункт; список пополняется новыми записями без изменения самого диалога.

### 5.2 Потоки данных и событий

Пользователь открывает диалог выбора функции панели -> видит расширенный список, включающий весь набор "Программы и сценарии" -> выбирает пункт -> панель сохраняет ссылку на функцию в уже существующем формате хранения плитки. При нажатии плитки панель разрешает ссылку через реестр, проверяет доступность на текущем варианте сборки и передаёт управление самостоятельной точке запуска функции, минуя главный экран приложения.

### 5.3 Точки расширяемости

Реестр функций панели остаётся единственным местом регистрации новой функции - без необходимости одновременно править несколько разрозненных участков кода при добавлении следующей. Проверка доступности функции (в том числе для случаев, зависящих от варианта сборки) проектируется как неотъемлемая часть той же записи реестра, а не как отдельный переключатель в стороне - чтобы забытая функция не превращалась в молчаливое "недоступно" без объяснения.

## 6. Открытые вопросы / Research items

1. **Целевая папка для быстрой камеры на панели**
   - **Вопрос:** нужен ли отдельный шаг выбора целевой папки при добавлении этой функции на панель, или достаточно поведения по умолчанию?
   - **Варианты:** (a) фиксированная папка по умолчанию, как при использовании функции без предварительной настройки; (b) отдельный экран/шаг выбора цели, аналогичный существующему выбору цели для виджета.
   - **Статус:** Resolved - вариант (a). Отдельный шаг выбора цели вынесен в non-goals первой итерации (см. §2).

   - **Варианты:** (a) диалог подтверждения внутри новой самостоятельной формы запуска, по образцу остальных функций набора; (b) прямая отправка без диалога.
   - **Статус:** Resolved - вариант (a), см. §3.1 п.1. Обеспечивает одинаковое поведение независимо от точки вызова (главный экран или панель).

   - **Варианты:** (a) только по явному добавлению через диалог выбора; (b) добавить в предустановленный набор для новых пользователей.

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать существующие самостоятельные точки запуска вместо маршрутизации через главный экран**

- **Решение:** каждая функция панели вызывается через собственную форму запуска, не зависящую от главного экрана приложения - там, где такая форма уже существует, она переиспользуется как есть; там, где её нет, для неё заводится новая форма того же образца.
- **Альтернативы:** маршрутизировать нажатие плитки через главный экран (открыть приложение, затем вызвать функцию).
- **Почему:** маршрутизация через главный экран противоречит самой цели панели быстрого запуска (вызов функции без открытия приложения) и уже была отвергнута архитектурой панели, заложенной в S0663.

**ADR-2: Единообразная форма запуска для функции без готовой автономной точки**

- **Решение:** загрузка по ссылке получает собственную самостоятельную форму запуска (сохраняющую диалог подтверждения буфера обмена), построенную по тому же образцу, что и уже существующие самостоятельные точки запуска остальных функций набора.
- **Альтернативы:** изменить взаимодействие загрузки по ссылке специально для панели (например, убрать диалог подтверждения только в контексте панели).
- **Почему:** единый образец для всех точек запуска панели проще поддерживать и предсказуемее для пользователя, чем разное поведение одной и той же функции в зависимости от источника вызова.
