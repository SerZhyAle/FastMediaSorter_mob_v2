# Tactical plan: S1612 - Расширение функционала Maestro

**Status:** Tactical
**Owner ruling:** coverage priority = variant B (strategic §3.1) - расширять регрессию вширь по крупнейшим областям инвентаря.

## Phase order and rationale

Порядок задан ADR-1 стратегической спеки: конвенция и гейт предшествуют массовому написанию флоу. Написание по противоречивому руководству воспроизвело бы дефект оракула в масштабе, а стоимость исправления растёт пропорционально числу написанных файлов.

| Phase | Title | Depends on | Produces |
|-------|-------|------------|----------|
| 01 | Конвенция авторства | none - foundation | Непротиворечивое руководство + шаблон, несущий конвенцию |
| 02 | Механический гейт | 01 | `assert-maestro-oracle.ps1` в пакете быстрых проверок, три нарушающих файла исправлены |
| 03 | Достижимость областей | none - можно параллельно 01/02 | Зафиксированный список областей первой итерации с доказанной достижимостью |
| 04 | Расширение покрытия | 02, 03 | По одному проходящему флоу на область из списка Phase 03 |

Phase 03 не зависит от 01 и 02 - это измерение на устройстве, а не правка. Выполняется параллельно, если устройство свободно.

---

## Scope guards

- Два набора не сливаются (ADR-2). Новые флоу капабилити-регрессии идут в корневой `maestro/features/<area>/`, потикетные - в `scripts/devtest/maestro/<Sxxxx>.yaml`.
- Отбор `-Suite all` в `maestro/run-tests.ps1` работает по списку исключений, а не по списку включений: новый каталог под `features/` попадает в набор по умолчанию автоматически. Область, недостижимая на голом эмуляторе, обязана быть либо исключена явно с комментарием-причиной, либо размещена вне `features/`.
- Non-goals стратегической спеки отсекают из списка §3.1: сеть и облако, VR и OpenXR, 3D-видео, головное устройство. Phase 03 отсеивает остальное по факту измерения.

## Области первой итерации (зафиксировано Phase 03, 2026-08-13)

Отбор сделан по `research/01__area-reachability.md`. Из 22 крупнейших областей инвентаря шесть уже покрыты, семь отклонены по non-goals или по недостижимости, три приняты с условием, четыре приняты без условий.

| Область | Каталог | Доказательство флоу | Входит в `-Suite all` |
|---------|---------|---------------------|:---------------------:|
| Settings & Navigation | `maestro/features/settings/` | Поиск находит настройку и переход в раздел открывает его контейнер | да |
| Usage Statistics | `maestro/features/statistics/` | После включения сбора строка появляется, экран открывается, список отрисован | да |
| Text Editor | `maestro/features/text/` | Текстовый файл открывается в наложении плеера, содержимое отрисовано | да |

**Перенесено за пределы первой итерации, с причиной:**

- **Setup & Onboarding** - требует `clearState: true`. Единственное доступное устройство `RFCR110NBQJ` работает домашним экраном, и сброс данных приложения на нём убирает рабочий стол лаунчера. Пишется на эмуляторе.
- **Launcher** - требует роли HOME. Роль на тестовом устройстве выдавать разрешено, но флоу, меняющий домашний экран, обязан его восстанавливать, а прерванный прогон оставит устройство без лаунчера. Пишется на эмуляторе.
- **OCR & Translation** - движок присутствует на этом устройстве, но отсутствует на голом эмуляторе, поэтому флоу обязан доказывать либо распознавание, либо запасной путь - в зависимости от цели. Решение о том, что именно доказывать, принимается при написании.
- **Sources & Storage** - доступ ко всем файлам на этом устройстве выдан, на эмуляторе требует настройки; существующий `features/resource/` уже исключён из набора по умолчанию по этой же причине.
