## Steps

### Step 03.1 - Отсеять области по non-goals и по устройству

**Files:** `PLAN/S1612_add-new-maestro-features/research/01__area-reachability.md`
**Depends on:** - start of phase

**Prompt for developer:**

> Взять список кандидатов из стратегической §3.1 и отсеять области, отсечённые non-goals: требующие сети и облака, VR и OpenXR, реального оборудования. Для каждой оставшейся области записать, требует ли она условия, которого нет на голом эмуляторе - доступ ко всем файлам, полноэкранный аудиоплеер, разрешение на захват экрана, установленный движок распознавания. Основание брать из списка исключений `-Suite all` в `maestro/run-tests.ps1` и из предрелизной матрицы, а не из предположений.

**Why:**

Отбор `-Suite all` работает по списку исключений, поэтому недостижимая область, попавшая в `features/`, автоматически войдёт в набор по умолчанию и сделает его красным (тактический INDEX, Scope guards).

**Verification:**

- `Glob` - файл исследования существует.
- `Grep` - каждая область из §3.1 присутствует в файле с вердиктом достижимости.

**Status:** `[x]` done

### Step 03.2 - Снять точные идентификаторы элементов

**Files:** `PLAN/S1612_add-new-maestro-features/research/01__area-reachability.md`
**Depends on:** Step 03.1

**Prompt for developer:**

> Для каждой достижимой области пройти сценарий на эмуляторе и записать точные имена идентификаторов ресурсов входного экрана, целевого действия и элемента, доказывающего результат. Где стабильного идентификатора нет - записать точный видимый текст и локаль, в которой он снят. Где существует стабильный маркер завершения в журнале - записать его: конвенция предпочитает ожидание по маркеру.

**Why:**

Конвенция запрещает регулярные селекторы и координатные тапы, поэтому флоу можно написать только имея точные идентификаторы; их отсутствие - основная причина, по которой автор скатывается к запрещённым приёмам (стратегическая §7, второй риск).

**Verification:**

- `Grep` - для каждой достижимой области в файле присутствует хотя бы один идентификатор элемента-доказательства.
- Ни один записанный селектор не содержит `.*`.

**Status:** `[x]` done

### Step 03.3 - Зафиксировать список областей первой итерации

**Files:** `PLAN/S1612_add-new-maestro-features/INDEX.md`
**Depends on:** Step 03.2

**Prompt for developer:**

> Записать в INDEX итоговый список областей первой итерации - только достижимые и с полным набором идентификаторов из Step 03.2. Для каждой указать целевой каталог: `maestro/features/<area>/`. Область, достижимую только при дополнительном условии, включить с явной пометкой и решением - либо исключение в `-Suite all` с комментарием-причиной, либо перенос за пределы `features/`.

**Why:**

§3.1 пункт 2 стратегической спеки требует фиксировать список областей после проверки достижимости, а не до неё.

**Verification:**

- `Grep` - INDEX содержит таблицу областей первой итерации с целевыми каталогами.
- Каждая область в таблице имеет вердикт достижимости в файле исследования.
