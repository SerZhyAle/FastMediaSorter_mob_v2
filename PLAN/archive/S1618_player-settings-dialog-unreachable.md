## 0. Захваченный материал (inbox)

**Захвачено:** 2026-08-13 (авто-захват по CLAUDE.md 3.1 в ходе S1612 Phase 02)

**Симптом:**

`PlayerSettingsManager.showPlayerSettingsDialog()` полностью реализован, но не имеет ни одной точки вызова. Диалог «Playback Settings», включающий выбор режима 3D - «Auto-detect», «Side-by-Side (SBS)», «Mono (Disabled)» - недостижим из интерфейса плеера.

**Доказательство:**

- `app_v2/src/main/java/com/sza/fastmediasorter/ui/player/helpers/PlayerSettingsManager.kt:54` - объявление `fun showPlayerSettingsDialog()`.
- Поиск по `app_v2/src/main/java` даёт единственное вхождение имени - само объявление. Вызовов нет.
- `app_v2/src/main/res/layout/custom_player_controls.xml` не содержит кнопки настроек: идентификаторы строки кнопок - `exo_repeat`, `exo_prev_file`, `exo_next_file`, `btnPlaybackControl`, `btnPictureInPicture`, `btnVrLaunch`.
- Два флоу `maestro/device_only/3d-video-sbs.yaml` и `3d-video-switching.yaml` пытаются открыть этот диалог через селекторы-регулярки `id: ".*settings.*"` с `optional: true`, то есть шаги молча не срабатывают, и флоу не могли пройти никогда.

**Почему это важно:** выбор режима 3D - единственный способ переопределить автоопределение SBS. Если диалог недостижим, пользователь не может исправить неверное автоопределение.

**Что выяснить:** удалили ли кнопку намеренно (тогда мёртвый код и оба флоу подлежат удалению) либо она потерялась при переработке панели управления (тогда это регрессия и кнопку нужно вернуть). Различить по истории неуместно - рабочее дерево источник истины, поэтому решение за владельцем.

## 1. Проблема

Вопрос из захвата решается самим кодом, без обращения к владельцу: возможность не потеряна, а переехала. Выбор режима 3D живёт в диалоге управления воспроизведением - `PlaybackControlDialogFragment`, вкладка `btnSectionStereo`, кнопка `btnPlaybackControl` в `custom_player_controls.xml`. Его набор режимов строго шире старого: плоские SBS / OU / Mono плюс сферические 360 mono/SBS/OU, VR180 и цилиндр 180, с подписью распознанного формата и запоминанием выбора для файла.

Старый диалог покрывал скорость, повтор, субтитры, язык дорожки и три плоских 3D-режима. Диалог управления покрывает громкость, аудиодорожку, субтитры, 3D, оттенок, яркость и скорость - то есть всё, кроме выбора *языка* дорожки, который в нём заменён выбором самой дорожки. Отдельная точка входа поэтому не восстанавливается: это была бы вторая, более бедная копия уже работающего экрана.

Остаётся мёртвый груз: недостижимый `PlayerSettingsDialog` с двумя раскладками и своими строками, метод-обёртка в `PlayerDialogHelper`, недостижимый метод и три параметра конструктора в `PlayerSettingsManager`, а также два флоу Maestro, которые никогда не могли пройти и держат исключение в `assert-maestro-oracle.ps1`.

Отдельный факт, важный для честности формулировки: вкладка 3D в диалоге управления доступна не во всех сборках - она требует `supportsVrMediaControls` и включённого пользователем мастер-тумблера 3D/VR. Удаление мёртвого кода этого не меняет: недостижимый диалог не давал переопределения ни в одной сборке.

## 2. Цели

1. В дереве не остаётся кода, разметки и строк, обслуживающих недостижимый диалог настроек плеера.
2. Типы `PlayerSettings` и `LanguageOption`, которыми пользуется живой путь применения настроек к ExoPlayer, сохраняются и переезжают из удаляемого диалога в собственный файл модели.
3. Оба флоу Maestro либо ведут по настоящему пути, либо удаляются; исключение S1618 в `assert-maestro-oracle.ps1` снимается.

**Non-goals:**

- Восстановление отдельной кнопки настроек в панели плеера.
- Расширение доступности вкладки 3D на сборки без `supportsVrMediaControls` - это отдельный вопрос о составе флейворов.
- Перенос выбора *языка* дорожки в диалог управления.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

Из захвата: определить судьбу недостижимого диалога, а не оставлять его в дереве.

### 3.2 Жёсткие ограничения

- **Flavor:** правка живёт в `src/main`, задевает все сборки одинаково; вкладка 3D в диалоге управления остаётся гейтированной как была.
- **Локализация:** осиротевшие ключи удаляются во всех локалях `main/res` через `scripts/utils/set-android-string.ps1`, а не правкой файлов.
- **Совместимость данных:** настройки плеера сессионные, ничего не персистится - удаление UI не трогает хранилище.

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S1612 - в его ходе находка захвачена. S0670 - ввёл секции диалога управления, включая вкладку 3D. S0763 - гейтирование вкладки 3D мастер-тумблером.
- **Flavor scope:** все сборки - удаляемый путь лежит в `src/main` и был недостижим везде.
- **Localization:** удаляются только ключи, на которые не осталось ссылок; тринадцать локалей обслуживает штатный инструмент строк.
- **Validation level:** компиляция standard, гейты закрытия и `assert-maestro-oracle.ps1` без исключений для флоу 3D.
- **Owner sign-off:** не требуется - вопрос захвата снят наблюдением над кодом, а не выбором из вариантов.

2. `scripts/quality/assert-maestro-oracle.ps1` проходит без исключений для флоу 3D.
