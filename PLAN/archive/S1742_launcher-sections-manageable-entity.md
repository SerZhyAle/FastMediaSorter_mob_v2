## 1. Проблема

Раздел рабочего стола лаунчера - неполноценная сущность: его нельзя создать (при добавлении предлагают только выбор из существующих), нельзя переименовать, нельзя переместить. Удаление в режиме редактирования есть, остального нет.

---

## 2. Цели

1. Пользователь может создать собственный раздел (сворачивающийся), а не только выбирать из предустановленных.
2. Раздел можно переименовать.
3. Короткое нажатие на раздел сворачивает/разворачивает его; длинное нажатие (при незаблокированном столе) входит в режим правки раздела.
4. В режиме правки раздел можно переименовать, удалить и переместить (например, на строку вниз - все его ярлыки сдвигаются вместе с ним).

**Non-goals:**

- Правила состава стартовых разделов по умолчанию - это S1746.

## 4. Контекст текущей архитектуры

Раздел сегодня - не отдельная сущность, а ячейка рабочего стола особого вида. Она хранится в той же таблице, что ярлыки и гаджеты, отличается только видом ячейки и адресуется устойчивым ключом, зашитым в её цель. Подпись раздела берётся из кодового каталога предустановленных разделов по этому ключу, а пользовательская подпись ячейки перекрывает вычисленную. **Уточнено ресёрчем 2026-08-18:** перекрытие применяется только поверх успешно вычисленной подписи, а ключ вне кодового каталога вычисленной подписи не даёт вовсе - заголовок с таким ключом рисует «недоступно», и пользовательская подпись его не спасает. Механизм переименования на уровне отрисовки существует, но для пользовательского раздела его недостаточно.

Принадлежность ярлыка разделу нигде не хранится: она вычисляется по расположению - ярлык принадлежит ближайшему заголовку выше и левее. Это решение S1428 и оно же причина, по которой разделы обошлись без миграции схемы. Свёрнутость хранится в общем файле настроек по паре «ориентация + ключ раздела» и применяется только при отрисовке, поэтому разворачивание возвращает раскладку без пересчёта позиций. Короткое нажатие по заголовку сворачивает раздел; длинное нажатие заголовку намеренно запрещено решением S1428, и этот запрет продублирован в объявлении для screen reader.

Создать свой раздел нельзя по одной причине: экран выбора содержимого предлагает ровно тот список, что лежит в кодовом каталоге. Пункта «создать раздел» там нет, ключ придумать негде, а значит нет и того, что можно было бы переименовать.

## 5. Предлагаемый подход

Раздел остаётся ячейкой рабочего стола - позиционная принадлежность и отсутствие миграции схемы сохраняются. Меняется то, что ключ раздела перестаёт быть достоянием кода: к предустановленным добавляется пользовательский, порождаемый при создании и уникальный в пределах рабочего стола, а его подпись живёт в пользовательской подписи ячейки, которая уже имеет приоритет над вычисленной.

### 5.1 Основные столпы / модули

1. **Создание раздела.** Экран выбора содержимого получает отдельный пункт «создать раздел»: он спрашивает имя и размещает заголовок обычным путём размещения ячейки, с той же проверкой перекрытий.
2. **Переименование.** Одно действие правки, записывающее пользовательскую подпись заголовка. Для предустановленного раздела это перекрытие локализованного имени, для пользовательского - единственный источник имени. Чтобы второе вообще стало возможным, резолвер обязан отдавать заголовок и для ключа, которого нет в кодовом каталоге: сегодня он возвращает пустой результат, и пользовательская подпись до отрисовки не доходит (ресёрч 01, п.1).
3. **Режим правки раздела.** Длинное нажатие по заголовку при незаблокированном столе открывает набор действий над разделом: переименовать, переместить, удалить. Те же действия обязаны быть доступны без жеста - через меню - иначе они недостижимы для screen reader.
4. **Перемещение вместе с содержимым.** Перемещение раздела трактуется как перемещение блока: заголовок и все ячейки, принадлежащие ему по текущему расположению, сдвигаются одной операцией, сохраняя взаимный порядок.

### 5.2 Потоки данных и событий

Жест по заголовку -> слой представления определяет намерение (свернуть или править) -> сценарий правки -> репозиторий рабочего стола (запись подписи, перемещение блока, удаление) -> поток ячеек -> перерисовка. Свёрнутость остаётся отдельным потоком, не проходящим через репозиторий.

### 5.3 Точки расширяемости

- Пользовательский ключ раздела не должен отличаться от предустановленного ничем, кроме происхождения: любой код, спрашивающий «какой это раздел», обязан работать одинаково с обоими.
- Набор действий над разделом задуман списком, чтобы соседние тикеты добавляли пункт, а не новый жест.

## 6. Открытые вопросы / Research items

1. **Идентичность пользовательского раздела**
   - **Вопрос:** как порождается ключ пользовательского раздела и что гарантирует его уникальность и устойчивость при резервной копии и восстановлении?
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1742_launcher-sections-manageable-entity/research/01__sections-as-entity.md`
   - **Измерено 2026-08-18:** резервная копия переносит `target` и пользовательскую подпись дословно, обнуляя только идентификатор строки, поэтому личность раздела целиком держится на строке `target` - ключ обязан быть самодостаточным, а не ссылкой на что-то ещё.
   - **Ответ:** ключ порождается с собственным префиксом, отделяющим пользовательское пространство имён от шести предустановленных ключей, и потому не может с ними столкнуться; уникальность внутри стола обеспечивается порождением от момента создания.
   - **Обнаруженное препятствие (важнее самого вопроса):** подпись раздела с неизвестным ключом не отображается вообще. Резолвер возвращает пустой результат для ключа, которого нет в кодовом каталоге, а пользовательская подпись применяется только поверх непустого результата - заголовок рисует «недоступно». Значит одного лишь переименования для пользовательского раздела недостаточно: резолвер обязан отдавать заголовок и для неизвестного ключа. См. §5.1 п.2.

2. **Семантика перемещения блока**
   - **Вопрос:** что происходит при перемещении раздела на занятые строки - сдвиг соседей, отказ или частичное размещение?
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1742_launcher-sections-manageable-entity/research/01__sections-as-entity.md`
   - **Измерено 2026-08-18:** перемещения нескольких ячеек не существует ни в одном виде. Одиночное перемещение отказывает при перекрытии с ячейкой другого размера и меняет местами ячейки одинакового размера. Единственная операция, трогающая много строк сразу, - сдвиг непрерывного хвоста стола вниз на равное число строк (введён S1772); подъёма нет, и произвольный блок он не переносит.
   - **Ответ:** перемещение раздела реализуется не как «переместить N ячеек», а как обмен соседними блоками: раздел и его содержимое меняются местами с соседним разделом целиком. Внутри такого обмена перекрытий не возникает по построению, поэтому вопрос «что делать с занятыми строками» не встаёт, а порядок ярлыков внутри каждого раздела сохраняется.

3. **Свёрнутость при переименовании и удалении**
   - **Вопрос:** переименование не меняет ключ, но удаление раздела оставляет запись свёрнутости - нужна ли уборка?
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1742_launcher-sections-manageable-entity/research/01__sections-as-entity.md`
   - **Измерено 2026-08-18:** уборки нет. Удаление ячейки доходит только до удаления строки в таблице, а запись свёрнутости хранится отдельно, по паре «ориентация + цель ячейки», и остаётся навсегда.
   - **Ответ:** уборка нужна, и не ради объёма - он ничтожен, - а потому, что запись переживает раздел: новый раздел, получивший ту же цель, молча унаследовал бы чужое состояние свёрнутости. Для предустановленных ключей это воспроизводится тривиально (удалить раздел свёрнутым и добавить его заново). Удаление раздела обязано убирать и его запись свёрнутости.

4. **Конфликт жестов**
   - **Вопрос:** длинное нажатие по заголовку против длинного нажатия по рабочему столу и против режима правки стола.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1742_launcher-sections-manageable-entity/research/01__sections-as-entity.md`
   - **Измерено 2026-08-18:** на заголовке обработчика длинного нажатия нет вовсе - не «есть и запрещает», а не зарегистрирован. Заголовок при этом остаётся кликабельным и поглощает касание, поэтому жест не доходит и до обработчика самого стола: сегодня это тихая пустота. В режиме правки поверх каждой ячейки лежит прозрачный перехватчик, чьё длинное нажатие начинает перетаскивание.
   - **Ответ:** конфликта нет ровно потому, что в обычном режиме жест свободен. Достаточно зарегистрировать обработчик на заголовке в обычном разблокированном режиме; режим правки не трогается, там жест остаётся перетаскиванием (решение владельца, пункт 8). Объявление для screen reader сегодня сообщает только свёрнутость и никакого утверждения про длинное нажатие не содержит, поэтому опровергать нечего - его нужно дополнить новым действием.
   - **Измерено 2026-08-17:** в режиме правки поверх каждой ячейки лежит прозрачный перехватчик, и длинное нажатие по нему начинает перетаскивание. То есть в режиме правки жест уже занят, и «длинное нажатие открывает правку раздела» может относиться только к обычному режиму при незаблокированном столе. Это делает вопрос 5 решением владельца, а не выводом из кода.

### Решения владельца (UI-размещение, гейт §5.5 /spec-tech)

Прецедента в лаунчере нет ни для одного пункта: меню действий над ячейкой не существует, экрана переименования ячейки не существует, в режиме правки долгое нажатие занято перетаскиванием. Угадывать размещение запрещено (Rule 10), поэтому тикет ждёт владельца.

5. **Где живёт «создать раздел»**

   - **Статус:** Resolved
   - **Решение:** первая строка в существующем списке разделов.

6. **Как выглядит правка раздела**
   - **Вопрос:** нижняя шторка со списком действий (переименовать / переместить / удалить), диалог, или встроенные кнопки на самом заголовке?
   - **Статус:** Resolved
   - **Решение:** нижняя шторка со списком действий.

7. **Как выполняется перемещение раздела**
   - **Вопрос:** перетаскивание заголовка в режиме правки (тогда перетаскивание должно начать тащить весь блок), или пункт меню «на строку вниз / вверх» - формулировка владельца в записи L-013 ближе ко второму?
   - **Статус:** Resolved
   - **Решение:** действия «вверх» и «вниз» в меню; перетаскивание остаётся перемещением одной ячейки.

8. **Режим, в котором работает длинное нажатие по заголовку**
   - **Вопрос:** обычный режим при незаблокированном столе (в режиме правки жест занят перетаскиванием), или всё же режим правки с другим жестом для перетаскивания?

   - **Решение:** обычный разблокированный режим; в edit mode жест остаётся перетаскиванием.

9. **Безжестовый путь к тем же действиям**

   - **Решение:** в edit mode заголовок получает видимую кнопку действий, открывающую тот же список; она доступна touch, mouse, D-pad и keyboard.

## 9. Архитектурные решения (ADR)

**ADR-1: Раздел остаётся позиционной ячейкой**

- **Решение:** пользовательский раздел - такая же ячейка вида «раздел», с собственным ключом и пользовательской подписью; поля «родительский раздел» у ярлыка не появляется.
- **Альтернативы:** отдельная таблица разделов со ссылкой из ячейки.
- **Почему:** позиционная принадлежность - действующий инвариант S1428, на нём держатся сворачивание и возврат раскладки без пересчёта; отдельная таблица потребовала бы миграции схемы и переписывания геометрии ради свойства, которое пользователь не наблюдает.

**ADR-2: Длинное нажатие по заголовку разрешается**

- **Решение:** запрет S1428 §6.8 на длинное нажатие по заголовку снимается; длинное нажатие открывает правку раздела при незаблокированном столе.
- **Альтернативы:** оставить запрет и держать все действия только в меню.
- **Почему:** владелец явно просит именно этот жест (запись L-013), а прежний запрет вводился только для того, чтобы заголовок не выглядел действием, - меню действий сохраняет доступность и снимает исходное возражение.

## 11. Критерии готовности (strategic-level)

1. Новый раздел создаётся пользователем, получает своё имя, сворачивается коротким нажатием.
2. Длинное нажатие открывает правку: переименование, удаление, перемещение раздела с его ярлыками.
3. Раздел, перемещённый на строку вниз, приходит туда со всеми своими ярлыками, и ни один ярлык не меняет владельца.
4. Все действия над разделом доступны без жеста - через меню.
