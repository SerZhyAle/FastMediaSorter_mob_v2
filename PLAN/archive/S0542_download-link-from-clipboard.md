## 1. Проблема

Скачивание файла по ссылке сейчас доступно только когда ссылка приходит извне через системный Share-sheet (поделиться текстом в приложение). Если пользователь скопировал ссылку в буфер обмена (мессенджер, браузер, заметка), вручную запустить ту же загрузку внутри приложения нельзя - нет ни одной точки входа. Приходится возвращаться в исходное приложение и делать «Поделиться». Затронутая область - главное окно (меню действий по «трём точкам») и подсистема загрузки по ссылке.

---

## 2. Цели

1. Добавить в меню главного окна (по «трём точкам», рядом с калькулятором и мини-игрой) пункт «Загрузить по ссылке».
2. Пункт виден только когда включена существующая настройка автозагрузки по ссылке.
3. По нажатию открывается однострочный диалог «Ссылка для загрузки», заранее заполненный текущим текстом буфера обмена, с кнопками «ОК» и «Отмена».
4. «ОК» запускает ту же загрузку, что и при получении ссылки извне (тот же результат, прогресс, уведомление, обработка авторизации).
5. Никаких новых настроек - переиспользуется существующий тумблер.

**Non-goals:**

- Новая настройка-тумблер для этой функции (используется существующая).
- Изменение самого движка загрузки, набора стратегий извлечения, логики авторизации.
- Пакетная загрузка нескольких ссылок из буфера за один вызов (одна ссылка за раз; множественные ссылки в тексте обрабатываются существующим детектором как есть).
- Wear OS.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Поведение и формулировки максимально близкие к привычным («ОК»/«Отмена» как обычно).
2. Строка диалога предзаполняется именно текущим текстовым буфером обмена.
3. Семантика «ОК» - «скачать эту строку как принятую извне» (как будто ссылку прислали через «Поделиться»).

### 3.2 Жёсткие ограничения

- **Flavor:** все (standard / lite / photos / legacy); движок загрузки и настройка лежат в общем модуле, флейвор-специфичного кода не вводится, новых `BuildConfig`-гейтов нет.
- **API level:** без API-специфики (доступ к буферу обмена и запуск приёмника покрыты текущим минимумом).
- **Wear OS:** не затрагивается.
- **Производительность:** разовое действие по нажатию; фоновых задач не добавляет (загрузка уже идёт в существующем worker).
- **Совместимость данных:** миграций нет - новых полей настроек и сущностей не вводится.
- **Локализация:** EN/RU/UK - обязательно для всех новых строк.
- **Доступность:** пункт меню и диалог должны поддерживать фокус/клавиатуру/D-pad наравне с остальными пунктами меню; цель нажатия не меньше прочих пунктов.

### 3.3 Owner inputs (Approval gate)

- **Видимость пункта:** гейт по существующей настройке автозагрузки по ссылке (как описано в §0); отдельного тумблера не вводить.
- **Источник предзаполнения:** текущий текстовый буфер обмена «как есть»; извлечение/валидация URL остаётся за существующим приёмником.
- **Related tickets:** S0003 (движок автозагрузки по ссылке и настройка - переиспользуются); S0523 (паттерн пунктов меню главного окна quick-capture - образец для нового пункта).

## 4. Контекст текущей архитектуры

Загрузка по ссылке - зрелая подсистема (S0003 и наследники): внешний приёмник принимает текст из Share-sheet, обнаруживает в нём http(s)-ссылку, проверяет настройку автозагрузки и при включённой настройке гонит ссылку через единый координатор загрузки (реестр стратегий извлечения → запись файла → стриминг-пайплайн), показывая прогресс, результат и уведомление. Меню главного окна по «трём точкам» собирается из набора пунктов-менеджеров (калькулятор, мини-игра, быстрый захват, камера-OCR), каждый со своей видимостью.

Проблему из §1 нельзя решить «само собой», потому что единственный триггер загрузки сегодня - входящий Share-интент извне; внутреннего входа, который бы передал произвольную строку (например, из буфера) в тот же путь, не существует.

---

## 5. Предлагаемый подход

Тонкий UI-слой поверх существующего движка: новый пункт меню и однострочный диалог, который передаёт введённую строку в существующий внешний приёмник «как принятую извне», не дублируя ни загрузку, ни авторизацию, ни показ прогресса/результата.

### 5.1 Основные столпы / модули

1. **Пункт меню главного окна** - новый элемент в меню «трёх точек», видимый по условию существующей настройки автозагрузки.
2. **Слой ввода ссылки** - однострочный диалог «Ссылка для загрузки» с предзаполнением текущим текстовым буфером обмена и кнопками подтверждения/отмены.
3. **Переиспользование приёмника** - подтверждение передаёт строку в существующий путь обработки внешней ссылки (тот же приёмник, что и Share-sheet), который сам выполняет извлечение URL, проверку настройки и всю загрузку.
4. **Строковые ресурсы** - новые подписи (пункт меню, заголовок/подсказка диалога) на EN/RU/UK.

### 5.2 Потоки данных и событий

Меню главного окна (виден при включённой настройке) → диалог ввода (предзаполнен буфером) → подтверждение → передача строки во внешний приёмник «как извне» → существующий движок загрузки (прогресс → результат/уведомление).

### 5.3 Точки расширяемости

- Передача строки через тот же канал, что и Share-sheet, оставляет открытой возможность позже добавить иные внутренние источники ссылки (история, избранное) без изменения движка.
- Видимость пункта завязана на существующую настройку - смена правил видимости не требует нового кода загрузки.

## 11. Критерии готовности (strategic-level)

1. При включённой настройке автозагрузки в меню «трёх точек» главного окна виден пункт «Загрузить по ссылке»; при выключенной - отсутствует.
2. Нажатие пункта открывает однострочный диалог «Ссылка для загрузки», предзаполненный текущим текстовым буфером обмена, с кнопками «ОК» и «Отмена».
3. «ОК» с непустой ссылкой запускает ту же загрузку и тот же показ прогресса/результата, что и при получении ссылки через Share-sheet.
4. «Отмена» закрывает диалог без действий.
5. Новые строки присутствуют на EN/RU/UK.
6. Новых настроек, сущностей и флейвор-специфичного кода не добавлено.
