## 1. Проблема

При открытии изображения в режиме редактирования рисованием (вызывается жестом-скриншотом «слева для редакции») доступен набор инструментов аннотации - кисть, прямоугольник, овал, ластик, текст. Среди них нет инструмента обрезки: пользователь не может выделить нужный прямоугольный участок и отсечь всё лишнее прямо внутри сессии редактирования, чтобы затем дорисовать поверх обрезанного и сохранить или отправить результат.

Сейчас обрезка существует только как отдельная файловая операция в overflow-меню верхней командной панели («Обрезать», «Обрезать в файл»), и она не интегрирована с сессией рисования: после неё нельзя продолжить аннотировать тот же холст. Поэтому сценарий «выделил область -> обрезал -> дорисовал -> отправил» в одном проходе невозможен.

Область: редактор изображений (режим рисования/аннотации) в просмотрщике, как во встроенном плеере, так и в standalone-просмотре изображений.

---

## 2. Цели

1. В наборе инструментов редактора рисования появляется инструмент «Обрезка» наравне с кистью, прямоугольником, овалом, ластиком и текстом.
2. При выборе инструмента на холст накладывается перетаскиваемый прямоугольник с ручками по углам и краям; пользователь задаёт область обрезки.
3. По подтверждению (кнопка-галочка) рабочий холст обрезается до выбранной области - и базовое изображение, и уже нанесённые аннотации отсекаются по этому прямоугольнику.
4. После обрезки сессия редактирования продолжается: можно рисовать поверх обрезанного результата и затем сохранить/отправить.
5. Все существующие способы завершения сессии (сохранить на месте, сохранить как новый файл, поделиться, «Отправить в..») выдают именно обрезанный результат с аннотациями.

**Non-goals:**

- Непрямоугольная обрезка (свободная форма, по контуру, по маске).
- Поворот/выравнивание/перспектива при обрезке.
- Изменение существующей файловой операции «Обрезать»/«Обрезать в файл» в overflow-меню.
- Обрезка для видео или иных не-изображений.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Инструмент выбирается там же, где остальные инструменты рисования (единый селектор инструментов), без отдельного входа.
2. Поведение прямоугольника-выделения визуально и по логике совпадает с уже знакомым механизмом обрезки в фото-OCR-переводе (перетаскивание за углы и края, затемнение вне выделения).
3. Возможность продолжить рисование после обрезки в рамках той же сессии.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки с поддержкой изображений (standard, lite, photos, legacy). Функция живёт в общем коде редактора рисования, без флейвор-специфики и без `BuildConfig`-гейтов.
- **API level:** без API-специфики; минимум платформы как у остального редактора изображений.
- **Wear OS:** не затрагивается.
- **Производительность:** обрезка не должна заметно подвешивать UI; тяжёлая работа с пикселями - вне главного потока. Не допускать утечек/неосвобождённых битмапов при многократной обрезке за сессию.
- **Совместимость данных:** новых хранимых данных нет; результат - изображение тех же форматов, что и текущий вывод редактора.
- **Разрешение:** для локального исходного файла обрезка восстанавливает полное разрешение области (база берётся из файла, аннотации масштабируются); для сетевых/недоступных в полном разрешении источников - откат на обрезку рабочей композиции.
- **Локализация:** EN/RU/UK - обязательно для всех новых строк (название инструмента, подсказки, сообщения об ошибке).
- **Доступность:** выделение различимо не только цветом (затемнение/рамка); инструмент достижим с клавиатуры и D-pad (Strict Rule 16/17), ручки выделения имеют достаточную область попадания.

## 4. Контекст текущей архитектуры

Редактор рисования работает как прозрачный слой-аннотация поверх отображаемого изображения: пользовательские штрихи и фигуры накапливаются как список действий и каждый кадр перерисовываются на оверлей-холсте, который при экспорте склеивается с базовым изображением. Базовое изображение в этой сессии - то, что показано на экране; оверлей хранит действия в экранных координатах рабочей области. Завершение сессии (сохранить на месте/как новый файл/поделиться/отправить) формирует итог из «базовое изображение + оверлей».

Отдельно существует файловая обрезка: она перекодирует область исходного файла напрямую и не связана с сессией рисования - после неё нельзя продолжить аннотировать. Поэтому проблему из §1 нельзя решить переиспользованием файловой обрезки «как есть»: нужна обрезка, действующая на рабочую область редактора (базовое изображение вместе с уже нанесёнными аннотациями) и сохраняющая возможность дальнейшего рисования.

## 5. Предлагаемый подход

Добавить в редактор рисования новый режим-инструмент «Обрезка». Он переключается тем же селектором инструментов, что и остальные. При активации поверх рабочей области показывается интерактивный прямоугольник выделения (та же визуальная модель, что в OCR-обрезке: затемнение вне области, рамка, ручки по углам и краям) с экранными элементами подтверждения и отмены.

По подтверждению рабочая область редактора сжимается до выбранного прямоугольника: базовое изображение и накопленные аннотации согласованно отсекаются и пересчитываются в новую систему координат рабочей области, после чего рисование продолжается уже по обрезанному результату. Отмена снимает выделение и возвращает к предыдущему активному инструменту без изменения холста. Итоговый экспорт (на месте/как файл/поделиться/отправить) формируется из обрезанной рабочей области с аннотациями.

### 5.1 Основные столпы / модули

- **Инструмент в наборе редактора.** «Обрезка» регистрируется как ещё один выбираемый инструмент рядом с существующими; выбор активирует режим выделения и скрывает обычное рисование до подтверждения/отмены.
- **Слой выделения области.** Переиспользуемая визуальная модель прямоугольного выделения с ручками углов/краёв, затемнением вне области и подтверждением/отменой; нормализованная область отдаётся применяющему слою.
- **Применение обрезки к рабочей области.** Согласованное отсечение базового изображения и аннотаций по выбранной области и приведение их к новой системе координат, с продолжением сессии рисования.
- **Согласование с завершением сессии.** Все пути вывода используют обрезанную рабочую область как источник, без отдельной ветки «обрезанный/не обрезанный».

### 5.2 Потоки данных и событий

- Выбор инструмента -> активация режима выделения -> показ слоя выделения поверх рабочей области.
- Жесты/клавиши -> изменение прямоугольника выделения -> нормализованная область.
- Подтверждение -> применение обрезки к рабочей области (изображение + аннотации) -> возврат к рисованию по обрезанному холсту.
- Завершение (сохранить/поделиться/отправить) -> вывод из текущей рабочей области.

### 5.3 Точки расширяемости

- Слой прямоугольного выделения остаётся переиспользуемым (общий для OCR-обрезки, файловой обрезки и нового инструмента), чтобы визуал и взаимодействие не расходились.
- Набор инструментов редактора остаётся открытым к добавлению новых инструментов без изменения существующих.
- Модель применения обрезки допускает повторную обрезку в рамках одной сессии.

## 6. Открытые вопросы / Research items

1. **Разрешение результата при обрезке**
   - **Вопрос:** обрезать рабочую (экранную, возможно уменьшенную) композицию или, когда базовое изображение - локальный файл полного разрешения, восстанавливать исходное разрешение области (как делает файловая обрезка) и накладывать аннотации в полном масштабе?
   - **Решение:** гибрид - для локального исходного файла база берётся из файла в полном разрешении (region-decode + EXIF), аннотации масштабируются; для сетевых/недоступных источников - откат на рабочую композицию.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0679_draw-editor-crop-tool/research/01__crop-resolution-strategy.md`

2. **Обрезка и история отмен**
   - **Вопрос:** является ли обрезка отменяемым действием в стеке undo редактора (отменить последнее/отменить всё), или это одностороннее применение к рабочей области?
   - **Решение:** обрезка обратима до первого последующего штриха - пока пользователь не нанёс новое действие поверх обрезанного холста, обрезку можно отменить; после первого штриха обрезка фиксируется.
   - **Статус:** Resolved

3. **Повторная и согласованная обрезка**
   - **Вопрос:** разрешать ли несколько обрезок за сессию и как при этом ведёт себя смена ориентации/перекомпоновка при изменении соотношения сторон рабочей области.
   - **Решение:** несколько обрезок за сессию разрешены; каждая действует на текущую рабочую композицию, полноразрешённость для второй и последующих опирается на результат предыдущей обрезки. Ориентация в режиме редактирования и так заблокирована, поэтому смена соотношения сторон лишь перекомпоновывает (refit) рабочую область.
   - **Статус:** Resolved

4. **Различение с файловой обрезкой**
   - **Вопрос:** как именовать и подавать новый инструмент, чтобы он не путался с уже существующими пунктами «Обрезать»/«Обрезать в файл» в overflow-меню.
   - **Решение:** инструмент в селекторе рисования называется «Обрезка» (Crop / Обрізання) и использует иконку обрезки; пункты файловой обрезки в overflow-меню не меняются. Контекст (селектор инструментов рисования против overflow-меню файловых операций) однозначно их разводит.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Обрезка действует на рабочую область редактора, а не на исходный файл**

- **Решение:** новый инструмент обрезает текущую рабочую композицию (базовое изображение + аннотации) и оставляет сессию рисования активной, вместо вызова существующей файловой обрезки.
- **Альтернативы:** переиспользовать файловую обрезку как есть (перекодирование области исходного файла) и возвращать в режим рисования заново.
- **Почему:** цель - единый проход «выделил -> обрезал -> дорисовал -> отправил»; файловая обрезка завершает работу с файлом и не сохраняет состояние аннотаций.

**ADR-2: Переиспользовать общий слой прямоугольного выделения**

- **Решение:** визуальную модель выделения (ручки углов/краёв, затемнение, подтверждение) брать из общего переиспользуемого слоя, как у OCR-обрезки.
- **Альтернативы:** отдельная реализация выделения только для редактора рисования.
- **Почему:** консистентность взаимодействия и меньше дублирования; владелец явно ссылается на знакомый OCR-механизм.

**ADR-3: Полное разрешение для локальных файлов, откат для остальных**

- **Решение:** для локального исходного файла базовый слой обрезается из файла в полном разрешении (region-decode + EXIF-коррекция), аннотации масштабируются; для сетевых/недоступных источников - обрезка рабочей композиции.
- **Альтернативы:** всегда обрезать только рабочую (экранную) композицию.
- **Почему:** владелец выбрал качество результата (§6.1); полноразрешённый region-decode уже реализован в файловой обрезке и переиспользуется (см. research/01).

**ADR-4: Обрезка обратима до первого последующего штриха**

- **Решение:** обрезку можно отменить, пока поверх обрезанного холста не нанесено новое действие; после первого штриха обрезка фиксируется.
- **Альтернативы:** полноценный обратимый шаг в общем undo; либо точка невозврата с предупреждением.
- **Почему:** выбор владельца (§6.2) - баланс между предсказуемостью и сложностью отката композиции базы+аннотаций.

## 11. Критерии готовности (strategic-level)

1. В селекторе инструментов редактора рисования виден и выбирается инструмент «Обрезка».
2. При его выборе поверх изображения появляется прямоугольник выделения, изменяемый за углы и края.
3. По подтверждению изображение и уже нанесённые аннотации обрезаются по выделению; вне области ничего не остаётся.
4. После обрезки пользователь может продолжить рисовать по обрезанному результату.
5. Сохранение на месте, сохранение как новый файл, «поделиться» и «отправить в..» выдают обрезанный результат с аннотациями.
6. Новые строки локализованы на EN/RU/UK; инструмент доступен с тач, мыши, клавиатуры и D-pad.

Device: emulator-5554 (standard debug). Host: `StandaloneImagePlayer` (VIEW intent on a MediaStore image). Date: 2026-06-26.

- Crop tool in the draw tool selector - PASS. Overflow -> «Draw» -> tool selector (`btn_draw_tool_selector`) lists Brush, Rectangle, Oval, Eraser, Text, **Crop**. Evidence: `temp/s06xx_sweep/S0679_tool_selector_with_crop.png`.
- Selecting Crop shows the selection overlay - PASS. `crop_overlay_view` («Crop selection frame») appears with corner + midpoint round handles and darkening outside the selection, plus on-canvas «Cancel» / «Apply» (confirm). Evidence: `temp/s06xx_sweep/S0679_crop_overlay_active.png`, `S0679_crop_after_drag1.png` (handles + dimming visible).
- Confirm (Apply) crops and the session continues - PASS. Tapping «Apply» fired `StandaloneDrawSaveHelper: S0679: draw-editor crop apply (standalone)`; the compositor ran and the overlay dismissed, returning to the Draw editor (tool selector + Save/Save&close) so drawing can continue on the cropped result. Evidence: `temp/s06xx_sweep/S0679_after_crop_apply_draw_continues.png`.
- Full-res vs working-composite fallback (ADR-3) - PASS (graceful). The content-URI VIEW-intent source has no resolvable file path, so the full-res region decode threw `FileNotFoundException/ENOENT` in `ImageCropManager.decodeRegion`; this was **caught and logged at Timber.i** - `DrawCropCompositor: Draw crop: full-res region decode failed, using working composite` - and the crop applied from the working composite. This is the documented network/unavailable-source fallback path, not an error. (A local-file source via the in-app browser would exercise the full-res region-decode branch instead; not covered here because the standalone host was launched from a content URI.)
- Drag a rectangle (resize the selection) - INCONCLUSIVE-AVD. Three distinct resize-drag attempts (corner + midpoint handles) were defeated: swipe gestures near the top repeatedly pulled down the system notification shade, which then wedged open and intercepted subsequent gestures (known AVD touch-wedge). The selection did not demonstrably resize; «Apply» was therefore exercised on the default full selection.
- Save / Save-as / Share emit the cropped output - INCONCLUSIVE-AVD. Not exercised end-to-end on the post-crop result (would require a successful resize first to make the crop visually verifiable).
- Undo before the first new stroke reverts the crop - INCONCLUSIVE-AVD. Not exercised (depends on a demonstrable crop result).
- Logcat tag - PASS. `StandaloneDrawSaveHelper: S0679: draw-editor crop apply (standalone)` observed on Apply.

**Outcome: PASS (crop tool works from the DRAW EDITOR UI) - one criterion FAILS: Undo-reverts-crop (ADR-4).**

Device: Samsung Galaxy S21+ (RFCR110NBQJ, SM-G996U1, Android 15 / SDK 35, 1080x2400), standard debug. Host: `StandaloneImagePlayer` (VIEW intent on local DCIM image, MediaStore id 22). Date: 2026-06-28. Crop tool driven from the draw-editor tool selector directly (NOT the gesture path - this isolates the S0680 defect; see note below). Gestures driven via `adb input swipe/tap` against uiautomator-dumped bounds (reliable on real hardware; the AVD touch-wedge that defeated the prior run is absent).

- Crop tool in the draw tool selector - PASS. Overflow -> Draw -> `btn_draw_tool_selector` lists Brush, Rectangle, Oval, Eraser, Text, **Crop**. Evidence: `temp/S0679_devtest/01_tool_selector_with_crop.png`.
- Selecting Crop shows the selection overlay - PASS. `crop_overlay_view` ("Crop selection frame") with corner + midpoint handles, darkening outside, on-canvas Cancel (`btn_crop_cancel`) / Apply (`btn_crop_confirm`). Evidence: `02_crop_overlay_active.png`.
- **Drag a resize handle (the AVD-blocked item) - PASS.** Dragging the bottom-right corner handle inward (`adb input swipe 805 1410 -> 560 1080`) demonstrably resized the selection frame (handles + dimming region repositioned). Evidence: `03_crop_after_resize_drag.png`.
- Confirm (Apply) crops base image + session continues (criteria #3, #4) - PASS. Apply fired `StandaloneDrawSaveHelper: S0679: draw-editor crop apply (standalone)`; canvas now shows the tighter cropped composition and the Draw toolbar returns so editing continues on the cropped result. Evidence: `04_after_crop_apply_draw_continues.png`.
- Full-res vs working-composite fallback (ADR-3) - PASS (graceful). The content-URI VIEW source's region decode hit `ENOENT` in `ImageCropManager.decodeRegion` (`ImageCropManager.kt:429`), caught and logged at Timber.i: `DrawCropCompositor: Draw crop: full-res region decode failed, using working composite`. Documented fallback, not an error.
- Share / Send-to emits the cropped output (criterion #5) - PASS. Draw overflow -> Send to.. -> Other apps opened the system chooser whose "1 image" preview is unmistakably the CROPPED image (tighter composition, right-edge fan gone), not the original. Evidence: `06_share_emits_cropped_image.png`.
- **Undo before the first new stroke reverts the crop (ADR-4) - FAIL.** Immediately after Apply, with NO stroke drawn, the Draw overflow shows "Undo last" and "Undo all" GREYED OUT (`enabled="false"` on both clickable rows). Tapping the disabled "Undo last" did nothing (no undo/revert in logcat). The crop is therefore NOT reversible via Undo before the first stroke, contradicting ADR-4 / criterion "Undo before the first stroke reverts the crop". Evidence: `05_overflow_undo_disabled_after_crop.png`. (Whether the crop is meant to live in the stroke-undo stack or a separate revert path is unclear from the UI - either way the spec's stated undo-reverts-crop behavior is not observable here.)
- Logcat tag - PASS. `S0679: draw-editor crop apply (standalone)` observed on Apply.

**Crop-tool-vs-gesture isolation (re S0680):** the crop tool opens and fully functions (overlay, resize-drag, apply, cropped output, share) when invoked from the DRAW EDITOR tool selector. So the S0680 "crop mode never opened" defect is localized to the GESTURE entry path, NOT the crop delegate / `ImageCropManager` / `DrawCropCompositor`, which work correctly here. The only crop-tool-side gap found is the disabled Undo-after-crop (ADR-4).

Evidence: `temp/S0679_devtest/` (01-06 screenshots, crop_trace.txt, logcat_session.txt).
