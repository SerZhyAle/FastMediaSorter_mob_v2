# S0165 — Browse: команда «Создать папку» для ресурсов с каталогами как элементами

## §1. Контекст

В настройках каждого ресурса Browse есть опция «Показывать каталоги отдельными элементами».
Когда она включена, подпапки отображаются в файловом списке наравне с медиафайлами, что позволяет
навигировать по иерархии прямо внутри Browse. Это режим, при котором пользователь ожидает полноценного
файлового управления — в том числе возможности создать новую папку в текущем каталоге.

---

## §2. Проблема

Команда «Создать папку» доступна, но только через вспомогательное popup-меню ресурса (`...`).
Пользователи, работающие в Browse с включёнными каталогами, не видят эту команду в основном
интерфейсе: ни в панели инструментов, ни в командном меню текущего экрана.
Это делает операцию практически ненаходимой без знания о скрытом пункте меню.

---

## §3. Цель

Сделать команду «Создать папку» явно доступной в Browse-интерфейсе для ресурсов, у которых
включён режим «каталоги как элементы», без необходимости заходить в дополнительное меню ресурса.

---

## §4. Критерии приёмки (stakeholder-уровень)

- Пользователь видит команду «Создать папку» в Browse, когда ресурс настроен с каталогами как элементами.
- Команда недоступна (скрыта или отключена) для ресурсов в режиме «только файлы», виртуальных путей и ресурсов только для чтения.
- Нажатие команды открывает диалог ввода имени папки с валидацией.
- После подтверждения — папка создаётся, список обновляется, пользователь получает обратную связь.
- При ошибке создания — отображается понятное сообщение об ошибке.
- Существующая запись в popup-меню ресурса (`...`) сохраняется.

---

## §5. Область изменений (стратегически)

Изменения затрагивают только слой представления Browse-экрана:

- Добавление видимой точки входа для команды создания папки в основной Browse-интерфейс
  (тулбар, панель команд или аналогичное доступное место — конкретное решение в такт-спеке).
- Предикат видимости команды совпадает с уже существующим: ресурс с включёнными «каталогами
  как элементами», не только для чтения, не виртуальный путь.
- Бизнес-логика создания папки, диалог ввода имени и обработка результата уже реализованы
  и переиспользуются без изменений.
- Никаких изменений в доменном слое, слое данных или схеме базы данных не требуется.

---

## §6. Ограничения и риски

- **Ограничение места в UI:** тулбар Browse перегружен. Точное размещение требует UI-clarify
  сессии перед реализацией.
- **Условная видимость:** команда должна появляться/исчезать динамически при смене ресурса или
  изменении его настроек — логика наблюдения за состоянием уже существует в ViewModel.
- **Пересечение с popup-меню ресурса:** дублирование команды допустимо — popup остаётся как
  резервная точка входа. Риск путаницы минимален.
- **Поддержка клавиатуры:** сочетание F7 / Ctrl+Shift+N уже обработано в Browse, новая кнопка
  должна быть с ним согласована (не дублировать обработчик).

## §7. Открытые вопросы

1. Где именно размещать команду в Browse UI? В тулбаре как иконка, в overflow-меню тулбара,
   или в выделенной командной панели? — Решается через `/ui-clarify` перед тактической спекой.
2. Нужен ли тултип / подпись иконки?
3. Поведение при навигации внутри подпапки: команда создаёт папку в **текущем** подкаталоге или
   всегда в корне ресурса? (Текущая реализация использует `currentPath` — поведение корректное, но
   нужно уточнить ожидание пользователя.)
