## 1. Проблема

В FastMediaSorter v2 отсутствует формализованная методология и агентский протокол аудита пользовательского опыта (UX/UI Auditor Protocol) с позиции конечного пользователя на различных целевых классах устройств. Существующие автотесты (Unit, Maestro UI) проверяют лишь базовую корректность функциональных шагов, но не фиксируют эргономику, удобство навигации D-pad/rotary control, визуальные огрехи, неоптимальное использование пространства на часах Wear OS, планшетах, медиацентрах и фоторамках.

---

## 2. Цели

1. Формализовать протокол "Agent User-Auditor" для 5 ключевых классов устройств:
   - **Смартфон** (основной touch-интерфейс, вертикальная и горизонтальная ориентация).
   - **Планшет** (двухпанельный гибридный UI, drag-and-drop, сетка повышенной плотности).
   - **Автомагнитола / Car Head Unit** (крупные touch-элементы, высокая контрастность, D-pad / Rotary knob навигация).
   - **Фоторамка / TV** (Leanback/Slideshow UI, автоматическое воспроизведение, навигация с пульта D-pad).
   - **Часы Wear OS** (компактный круглый/квадратный экран, безель/rotary input, быстрые действия и синхронизация с телефоном).
2. Выделить реестр самых популярных и уникальных пользовательских сценариев FMS (быстрая сортировка медиа, жесты, multi-source выборка, фотосетка/слайдшоу, режим лаунчера, удаленное управление с часов).
3. Создать структурированный чек-лист продуктового, визуального и эргономического анализа (размеры touch target >= 48dp, наглядность D-pad фокуса, отсутствие обрезки текста, WindowInsets, корректность локализации EN/RU/UK).
4. Определить единый формат записи результатов аудита и конвертации выявленных замечаний в инбокс-записи и спецификации улучшений (`PLAN/Sxxxx`).

**Non-goals:**

- Замена функциональных автотестов Maestro UI (аудитор не проверяет assertion-логику кода, а оценивает продуктовый UX/UI).
- Поддержка устаревших Android устройств без поддержки целевых профилей.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Особое внимание уделить компактным экранам и спецификам взаимодействия Wear OS (часы).
2. Использовать пресеты профилей устройств (`device_profile_presets.csv`) и AVD для быстрой воспроизводимости тестов.
3. Оформлять каждую найденную проблему или пожелание в виде четко структурированной инбокс-записи для быстрой конвертации в спеки.

### 3.2 Жёсткие ограничения

- **Flavor:** Все флаворы (`standard`, `noLegal`, `lite`, `photos`, `legacy`, `vr`) в соответствии с матрицей возможностей (`docs/FLAVOR_MATRIX.md`).
- **API level:** Android 8.0+ (API 26+) для смартфона/планшета/TV, Wear OS 3.0+ (API 30+) для часов.
- **Wear OS:** Прямой охват модуля `wear/` и его взаимодействия с `app_v2`.
- **Производительность:** Плавность анимаций (60 fps), отсутствие задержек UI при навигации жестами или D-pad.
- **Совместимость данных:** Не затрагивает схемы Room или миграторы данных.
- **Локализация:** Обязательная проверка текстов интерфейса на трех языках (EN, RU, UK).
- **Доступность:** Соблюдение стандартов Android Accessibility (размеры кнопок >= 48dp, фокус D-pad, читаемый контраст текста).

## 4. Контекст текущей архитектуры

Проект FMS v2 содержит два ключевых модуля: `app_v2` (основной клиент для телефонов, планшетов, TV и автоголов) и `wear` (клиент для часов Wear OS). Адаптация UI происходит за счет ресурсов ресурсов (`layout-land/`, `layout-sw600dp/`, `layout-sw720dp/`), менеджера профилей устройств (`DeviceProfilePresetManager`) и поддержки универсальных устройств ввода (`PackageManagerCompat`, `WindowInsetsCompat`, Keyboard/D-pad/Touch listeners). Из-за фрагментации формы экранов и методов ввода без формализованного аудита пользовательского опыта мелкие дефекты навигации и верстки на нестандартных экранах остаются незамеченными.

---

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

1. **Device Profile Matrix**: Матрица 5 профилей устройств с описанием разрешения, соотношения сторон, ориентации и контроллеров ввода.
2. **Scenario Execution Suite**: Сценарии использования FMS (1: Первичная настройка и обзор источника, 2: Экспресс-сортировка файлов по папкам жестами/кнопками, 3: Режим слайдшоу/фоторамки без участия пользователя, 4: Режим лаунчера/медиацентра с D-pad навигацией, 5: Компактный режим управления Wear OS).
3. **Ergonomic & Visual Evaluation Protocol**: Набор стандартизированных метрик проверки (Touch targets, Focus indicator, Text truncation, Localization, Visual hierarchy, Error recovery).
4. **Auditor Findings Handoff**: Протокол сохранения находок в `PLAN/Sxxxx` или записи в инбокс для последующей обработки.

### 5.2 Потоки данных и событий

`Выбор профиля устройства (Phone/Tablet/Auto/Frame/Watch) -> Запуск AVD/устройства -> Прохождение сценария -> Фиксация находок UI/UX -> Генерация отчетного файла / инбокса`

### 5.3 Точки расширяемости

- Легкое добавление новых сценариев использования в реестр аудитора.
- Добавление специфических аппаратных профилей устройств в конфигурации AVD/пресетов.

## 9. Архитектурные решения (ADR)

**ADR-1: Пять стандартных целевых профилей User-Auditor**

- **Решение:** Закрепить 5 эталонных профилей: Смартфон, Планшет, Автомагнитола, Фоторамка/TV, Часы Wear OS.
- **Альтернативы:** Проводить аудит только для обычного телефона.
- **Почему:** FMS активнее всего используется на специализированных экранах (авто, фоторамки, часы), где ошибки эргономики наиболее критичны.
