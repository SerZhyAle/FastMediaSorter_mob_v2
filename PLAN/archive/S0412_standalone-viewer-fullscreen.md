## 1. Проблема

Автономный просмотрщик (`StandalonePlayerActivity`), который открывает изображения, видео и документы по внешнему `VIEW`-интенту, не предоставляет пользователю видимого способа войти в полноэкранный режим. Режим технически присутствует (скрытие системных баров реализовано), но доступен только через сочетания клавиш — ни кнопки в панели команд, ни жеста для сенсорного экрана нет. Пользователь, открывший файл из стороннего приложения, не может перейти в полноэкранный просмотр так же, как это делается во встроенном плеере FastMediaSorter.

---

## 2. Цели

1. В верхней командной панели автономного просмотрщика появляется кнопка «Полный экран», видимая для изображений, видео, PDF, EPUB и офисных документов.
2. Нажатие кнопки скрывает системные бары и саму командную панель, контент занимает весь экран.
3. Повторное нажатие (или свайп по краю в sticky-режиме) возвращает системные бары и командную панель.
4. Вход документных вьюеров (PDF, EPUB, офисных) в собственный «полноэкранный» режим синхронизируется с уровнем системных баров — они скрываются автоматически.
5. Поведение идентично соответствующей кнопке во встроенном плеере.

**Non-goals:**

- Смена ориентации при входе в полноэкранный режим (ориентация не меняется).
- Добавление кнопки для аудиофайлов (аудиоплеер без видеодорожки — без изменений).
- Picture-in-Picture из полноэкранного режима — отдельная задача.
- Изменение поведения встроенного плеера (`PlayerActivity`).

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. При входе в полноэкранный режим командная панель скрывается вместе с системными барами, а не остаётся поверх контента.
2. Кнопка меняет иконку при переключении состояния (аналогично `btnFullscreenCmd` во встроенном плеере).

### 3.2 Жёсткие ограничения

- **Flavor:** все четыре флейвора (standard, lite, photos, legacy); noLegal наследует через общий layout.
- **API level:** minSdk 23 (legacy); реализация должна работать без API 30+.
- **Wear OS:** не затрагивается.
- **Производительность:** переключение полноэкранного режима не должно вызывать лишних layout-проходов; скрытие/показ системных баров — единственная операция.
- **Совместимость данных:** нет изменений схемы.
- **Локализация:** строка подсказки кнопки («Полный экран» / «Выход из полноэкранного режима») EN/RU/UK — обязательно.
- **Доступность:** кнопка получает корректный `contentDescription`; состояние toggle передаётся через `contentDescription` (не только цвет/иконка).

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** кнопка размещается в `topCommandPanel` автономного просмотрщика справа от существующих кнопок управления файлом; видима для image/video/pdf/epub/office, скрыта для audio и text (текстовый редактор — без изменений).
- **Accessibility:** `contentDescription` меняется на «Выйти из полноэкранного режима» при активном fullscreen; touch target ≥ 48 dp.
- **Validation level:** UI-тест на устройстве: нажать кнопку → убедиться, что системные бары скрыты и командная панель не видна; нажать повторно (или swipe edge) → системные бары возвращаются.
- **Owner sign-off:** —
- **Related tickets:** S0392 (host-seam рефакторинг плеера — наблюдать за конфликтами если будет In Progress параллельно)

## 4. Контекст текущей архитектуры

Автономный просмотрщик и встроенный плеер используют одну activity-layout (`activity_player_unified`), но разные activity-классы. Во встроенном плеере кнопка «Полный экран» (`btnFullscreenCmd`) уже подключена через `CommandPanelController` к `SystemBarsManager`, который учитывает состояние плеера, режим редактирования изображения и состояние документного вьюера. В автономном просмотрщике та же кнопка объявлена в layout как `gone`, вспомогательный класс скрытия системных баров (`StandaloneFullscreenManager`) уже есть и работает через keyboard shortcut, но UI-вход отсутствует. Коллбэки документных вьюеров на вход/выход из fullscreen-режима зашиты как пустые заглушки (`/* not exposed in standalone */`).

---

## 5. Предлагаемый подход

Расширить слой представления автономного просмотрщика: сделать `btnFullscreenCmd` видимой для поддерживаемых типов контента и подключить её к уже существующему механизму скрытия системных баров. Дополнительно связать коллбэки документных вьюеров с тем же механизмом, чтобы вход PDF/EPUB/Office в собственный «полный экран» автоматически скрывал системные бары.

### 5.1 Основные столпы / модули

**А. Кнопка входа в полноэкранный режим**
- Показывать `btnFullscreenCmd` в командной панели автономного просмотрщика для типов: image, video, pdf, epub, office.
- При нажатии — скрывать системные бары и командную панель; менять иконку.
- При повторном нажатии или swipe-by-edge — восстанавливать оба элемента; менять иконку обратно.

**Б. Синхронизация с документными вьюерами**
- Коллбэки `onEnterFullscreenMode` / `onExitFullscreenMode` в хосте документных вьюеров (PDF, EPUB, Office) — заполнить реальными вызовами вместо пустых заглушек.
- При входе вьюера в свой «полный экран» — скрывать системные бары и прятать командную панель.
- При выходе вьюера — восстанавливать.

**В. Сохранение состояния**
- Состояние «полный экран активен» должно переживать смену конфигурации (поворот экрана): при воссоздании activity восстанавливаться в fullscreen, если было активно.

### 5.2 Потоки данных и событий

```
Нажатие кнопки / коллбэк вьюера
  → вспомогательный слой (FullscreenManager)
    → скрытие/показ системных баров
    → скрытие/показ командной панели
    → обновление иконки/contentDescription кнопки
```

### 5.3 Точки расширяемости

- Логика видимости кнопки изолирована: добавление нового типа контента требует изменения только в одном месте.
- Коллбэки вьюеров остаются в интерфейсах — подключение новых документных вьюеров не требует изменения основной логики.

## 6. Открытые вопросы / Research items

1. **Поведение при возврате из fullscreen через swipe**
   - **Вопрос:** когда пользователь делает swipe-by-edge (sticky bars появляются временно), нужно ли при этом автоматически выходить из fullscreen-режима и показывать командную панель?
   - **Варианты:** (а) показывать только системные бары временно (sticky, bar исчезают сами), командная панель не возвращается; (б) любой показ баров = выход из fullscreen, командная панель возвращается.
   - **Нужно выяснить:** проверить поведение встроенного плеера (PlayerActivity) при sticky-swipe — он его образец.
   - **Статус:** Open

2. **Иконка кнопки в состоянии «выйти из fullscreen»**
   - **Вопрос:** использовать уже существующий drawable `ic_fullscreen_exit` или `ic_fullscreen` с измёнённым tint?
   - **Нужно выяснить:** проверить наличие `ic_fullscreen_exit` в ресурсах.
   - **Статус:** Open

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Смена конфигурации (поворот) сбрасывает fullscreen-состояние | Средняя | Пользователь теряет режим при повороте экрана | Сохранять флаг в `ViewModel` / `savedInstanceState` |
| Коллбэки вьюеров вызываются в другом потоке | Низкая | Обновление UI вне main-thread → краш | Гарантировать вызов на main-thread через `lifecycleScope` |
| Конфликт с `StandaloneFullscreenManager` и EPUB-кнопкой выхода | Низкая | Двойное скрытие/восстановление баров | Единая точка управления состоянием fullscreen |

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользование `StandaloneFullscreenManager`, а не адаптация `SystemBarsManager`**

- **Решение:** расширить существующий `StandaloneFullscreenManager` поддержкой скрытия/показа командной панели, а не копировать `SystemBarsManager` из PlayerActivity.
- **Альтернативы:** вынести общий `SystemBarsManager` в shared-модуль и подключить к обоим хостам.
- **Почему:** объём изменений минимален; `SystemBarsManager` из PlayerActivity содержит логику, специфичную для PlayerActivity (image-edit mode, playlist state) — перетаскивать её в standalone нецелесообразно.

## 11. Критерии готовности (strategic-level)

1. Пользователь нажимает кнопку в командной панели автономного просмотрщика — системные бары и панель скрываются, контент (изображение / видео / документ) занимает весь экран.
2. Повторное нажатие кнопки возвращает системные бары и командную панель.
3. При открытии PDF или EPUB в fullscreen-режиме самого вьюера системные бары также автоматически скрываются.
4. Состояние fullscreen сохраняется при повороте экрана.
5. Кнопка отсутствует при просмотре аудиофайлов.
6. Кнопка доступна через D-pad / TV-пульт.
