# Стратегическая спецификация: S1325 - Операции над каталогами наравне с файлами

**Ticket:** S1325
**Status:** Archived

**Tier:** 4 - Strategic (ad-hoc)
**Roadmap entry:** Ad-hoc - запрос владельца 2026-07-31
**Tactical spec:** `PLAN/S1325_folder-selection-copy-move/`
**Tactical plan:** `PLAN/S1325_folder-selection-copy-move/INDEX.md`

---

## 1. Проблема

Когда субкаталоги показываются в списке отдельными элементами, папка выглядит как обычный элемент, но ведёт себя не как он. У строки папки нет галочки - выделить одну папку вручную невозможно. Нет кнопки вызова меню операций, которая есть у файла, поэтому операции над папкой из списка недостижимы. Копирование и перенос папки с воссозданием структуры у приёмника не работают.

Поведение противоречиво: "выделить всё" забирает папки в выделение, то есть выделенная папка для приложения - допустимое состояние, просто пользователь не может получить его вручную. Владелец хочет, чтобы все операции, доступные для файлов, работали над каталогами во всех типах ресурсов.

---

## 2. Цели

1. Отдельная папка выделяется вручную - галочкой или долгим нажатием, как файл; одиночный тап по папке по-прежнему открывает её.
2. У строки папки доступно то же меню операций, что у строки файла, с набором действий, применимых к каталогу.
3. Копирование и перенос папки воссоздают у приёмника всю структуру вложенных подкаталогов вместе с содержимым.
4. Операции над папками работают во всех типах ресурсов, включая перенос папки между ресурсами разных типов.
5. Смешанное выделение из папок и файлов обрабатывается одной операцией без отдельных шагов для пользователя.
6. Во время операции над деревом виден прогресс, а отмена приводит к предсказуемому и объяснённому состоянию.

**Non-goals:**

- Откат уже выполненной операции над папкой (undo) - решение владельца от 2026-07-31, вынесено в S1326.
- Изменение самого режима показа субкаталогов отдельными элементами и момента перезагрузки списка после смены настройки - это S1315.
- Операции, не имеющие смысла для каталога: инлайн-воспроизведение, отметка "избранное", действия над содержимым одного медиафайла.
- Массовые операции над содержимым папки без переноса самой папки.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Перед стартом операции показывать объём того, что предстоит перенести - число элементов и суммарный размер.
2. При совпадении имён у приёмника предлагать выбор: перезаписать, пропустить, переименовать - с возможностью применить решение ко всем последующим совпадениям.
3. В прогрессе показывать имя обрабатываемого сейчас элемента, а не только общий счётчик.
4. Итоговое сообщение с разделением на успешно перенесённые и неуспешные элементы.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки. Новых флагов сборки не вводится, поведение одинаково; отличается только набор доступных типов ресурсов - в `lite` нет сетевых и облачных ресурсов, поэтому там паритет проверяется на локальных папках, в остальных вариантах - на всех типах.
- **API level:** без API-специфичного поведения сверх уже существующего - папка пишется тем же путём, что и одиночный файл (§6.2); приёмник, выбранный системным диалогом выбора папки и не имеющий обычного файлового пути, для папок отклоняется с объяснением (§6.1).
- **Wear OS:** не затрагивается.
- **Производительность:** операция выполняется фоном и не блокирует список; потребление памяти не должно расти пропорционально числу файлов в дереве.
- **Совместимость данных:** схема хранения не меняется; прерванная операция не оставляет пользователя без информации о том, что уже создано у приёмника.
- **Локализация:** EN/RU/UK - обязательно для всех новых сообщений.
- **Доступность:** галочка и кнопка меню у строки папки имеют ту же зону нажатия, что у файла; выделение различимо не только цветом; TalkBack сообщает, что элемент - папка и что она выделена.

### 3.3 Owner inputs (Approval gate)

- **Flavor scope:** все варианты сборки, без flavor-специфичного кода; в `lite` операции над папками проверяются только на локальных ресурсах, так как сетевые и облачные там отключены существующими гейтами.
- **UI placement contract:** галочка и кнопка вызова меню операций у строки папки размещаются там же, где у строки файла, во всех режимах списка и плитки, включая ландшафтные варианты; одиночный тап по папке остаётся навигацией внутрь, долгое нажатие начинает выделение.
- **Accessibility:** зона нажатия галочки и кнопки меню не меньше, чем у файла; состояние выделения передаётся не только цветом; TalkBack проговаривает тип элемента и состояние выделения.
- **Communication policy:** все новые сообщения - отказ операции, конфликт имён, итог, отмена - пишутся по `docs/COMMUNICATION_POLICY.md` и проходят чек-лист тона перед интеграцией строк.
- **Localization:** EN/RU/UK для каждой новой строки, без исключений.
- **Performance budget:** интерфейс остаётся отзывчивым при операции над деревом любого размера; занятая память не зависит от числа файлов в дереве.
- **Validation level:** сборка и модульные тесты на рекурсивный обход, защиту от приёмника внутри источника и отмену; проверка на устройстве по одному сценарию на каждый доступный тип ресурса плюс один сценарий переноса между разными типами.
- **Owner sign-off:** 2026-07-31 - полный паритет с файлами, включая перенос папки между разными типами ресурсов; прогресс обязателен, undo вынесен отдельным тикетом.
- **Related tickets:** S1315 (перезагрузка списка после смены настройки показа субкаталогов), S1224 (фоновое копирование и перенос из плеера), S1326 (undo для операций над папками).

## 4. Контекст текущей архитектуры

Слой данных уже умеет создавать, переименовывать, удалять и рекурсивно копировать или переносить каталоги для каждого типа ресурса, а фоновое выполнение уже принимает смешанный набор из файлов и папок. Эти возможности достижимы только через контекстное меню правой кнопкой мыши - десктопный сценарий; на сенсорном экране путь к ним закрыт.

Закрыт он на уровне представления списка: при привязке строки к данным ветвление по признаку "это каталог" скрывает галочку и кнопку меню, а долгое нажатие для папки не начинает выделение. Хранилище выделения при этом папку и файл не различает - отсюда и наблюдаемое противоречие с "выделить всё".

Отдельно стоит перенос между ресурсами разных типов: для одиночного файла он реализован через промежуточное скачивание и загрузку, а для каталога отклоняется до начала работы, потому что обобщения этого механизма на дерево не существует.

---

## 5. Предлагаемый подход

Ключевая идея: папка перестаёт быть особым случаем в представлении списка и становится обычным элементом с собственным набором применимых операций, а механизм переноса между разными типами ресурсов обобщается с одиночного элемента на дерево.

### 5.1 Основные столпы / модули

**Столп 1 - единая достижимость операций в списке.** Строка папки получает те же точки входа, что и строка файла: выделение галочкой, выделение долгим нажатием, участие в выделении диапазона, кнопка вызова меню операций. Различие между папкой и файлом сводится к составу применимых действий, а не к наличию точек входа. Требование распространяется на все режимы отображения списка и на обе ориентации.

**Столп 2 - единый источник правды о применимости операции.** Ответ на вопрос "применима ли эта операция к этому элементу" даёт один компонент, учитывающий тип элемента, права на запись у ресурса и тип ресурса. Меню элемента, панель групповых действий и обработчики читают ответ оттуда, а не решают самостоятельно - иначе расхождение между местами показа возвращается при каждой новой операции.

**Столп 3 - перенос дерева между типами ресурсов.** Существующий механизм переноса одиночного элемента между разными типами обобщается на рекурсивный сценарий: обход структуры у источника, воссоздание структуры у приёмника, поэлементная передача содержимого с сохранением относительных путей. Обход и создание структуры выражаются через общую абстракцию доступа к ресурсу, чтобы конкретный тип ресурса не протекал в логику переноса.

**Столп 4 - безопасность операции.** До начала работы проверяется, что приёмник не находится внутри источника; обход защищён от зацикливания; конфликты имён обрабатываются явным решением, а не молчаливой перезаписью. Отказ всегда объясняет причину конкретно, а не общим сообщением об ошибке.

**Столп 5 - наблюдаемость.** Прогресс отражает продвижение по дереву, а не только число верхнеуровневых папок. Отмена реагирует в пределах текущего элемента, а не текущей папки. По завершении пользователь получает итог с числом обработанных и необработанных элементов.

### 5.2 Потоки данных и событий

- Список элементов -> хранилище выделения (папки и файлы равноправны) -> проверка применимости операции -> меню или панель действий.
- Запуск операции -> диалог выбора приёмника, показывающий только допустимые цели -> проверки безопасности -> фоновая задача переноса.
- Фоновая задача -> абстракция доступа к ресурсу источника (обход, чтение) и приёмника (создание структуры, запись) -> поток событий прогресса -> уведомление и индикатор в списке.
- Завершение или отмена -> итоговое сообщение -> обновление списка у источника и, если он открыт, у приёмника.

### 5.3 Точки расширяемости

- Абстракция доступа к ресурсу расширяется операциями обхода и создания структуры так, чтобы новый тип ресурса подключался без правок общей логики переноса.
- Набор правил применимости операции открыт к добавлению новых операций без правок в каждом месте показа меню.
- Стратегия разрешения конфликта имён выделяется как точка расширения - перезаписать, пропустить, переименовать.
- Отчёт о ходе операции формируется единообразно для файлов и деревьев, чтобы будущий откат операции (S1326) мог опереться на тот же поток событий.

## 6. Открытые вопросы / Research items

1. **Приёмник, выбранный системным диалогом выбора папки**
   - **Вопрос:** воссоздаётся ли структура каталогов, когда у приёмника нет обычного файлового пути и он представлен системным идентификатором дерева документов?
   - **Решение:** такой приёмник отклоняется для папок до начала работы, с конкретным сообщением; файлы из того же выделения переносятся как раньше. Поддержка дерева документов как приёмника для каталогов - отдельный тикет.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1325_folder-selection-copy-move/research/01__saf-tree-destination.md`

2. **Запись в общую внешнюю память на Android 10+**
   - **Вопрос:** проходит ли рекурсивное копирование локальной папки в общую внешнюю память по тем же правилам, что и копирование отдельного локального файла?
   - **Решение:** расхождения нет - обе операции пишут одинаково, поэтому отдельного разрыва для папок не существует и переписывать локальный путь записи в этом тикете не нужно.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1325_folder-selection-copy-move/research/02__local-write-path-parity.md`

3. **Текущее состояние: где теряется достижимость и что уже готово**
   - **Вопрос:** что именно закрывает операции над папкой в списке и какие возможности уже реализованы ниже уровня представления?
   - **Нужно выяснить:** места ветвления по признаку каталога в представлении списка, состав уже существующих операций над каталогами, границы поддержки переноса между типами ресурсов.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1325_folder-selection-copy-move/research/03__current-state-directory-ops.md`

4. **Состояние после отмены на середине дерева**
   - **Вопрос:** что остаётся у приёмника при отмене - частично созданная структура или ничего?
   - **Решение:** то же поведение, что у файлов - уже записанное остаётся, ничего не откатывается, при переносе элемент удаляется у источника только после подтверждённой записи, итоговое сообщение говорит, сколько элементов успело обработаться.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S1325_folder-selection-copy-move/research/04__cancellation-semantics.md`

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| Приёмник оказывается внутри источника | Средняя | Бесконечное копирование, переполнение хранилища | Проверка до старта операции, отказ с объяснением |

| Появление галочки и кнопки меню у папки ломает привычный тап | Средняя | Пользователь перестаёт попадать в папку одним нажатием | Тап остаётся навигацией, выделение только галочкой и долгим нажатием, проверка во всех режимах отображения |
| Совпадение имён у приёмника | Высокая | Молчаливая перезапись чужих данных | Явное решение по конфликту, по умолчанию не перезаписывать |
| Разные типы ресурсов ведут себя по-разному при создании структуры | Средняя | Операция работает на одном типе и молча ломается на другом | Проверка на устройстве по одному сценарию на каждый доступный тип ресурса |

## 9. Архитектурные решения (ADR)

**ADR-1: единый источник правды о применимости операции**

- **Решение:** применимость операции к элементу определяется в одном месте, а меню и панели действий только читают результат.
- **Альтернативы:** оставить ветвление по признаку каталога в каждом месте показа действий.
- **Почему:** нынешняя проблема и возникла из-за того, что решение о показе действия принимается при привязке строки к данным; повторение этого подхода вернёт расхождение при следующей новой операции.

**ADR-2: обобщение существующего механизма переноса, а не отдельный конвейер для деревьев**

- **Решение:** перенос дерева между разными типами ресурсов строится поверх уже работающего поэлементного переноса.
- **Альтернативы:** отдельный конвейер для каталогов.
- **Почему:** два конвейера разойдутся в поведении при отмене, прогрессе и обработке ошибок; кроме того, одинаковый механизм даёт одинаковые гарантии для смешанного выделения.

**ADR-3: undo для операций над папками вне объёма**

- **Решение:** откат уже выполненного переноса или копирования папки не входит в этот тикет.
- **Альтернативы:** реализовать откат сразу вместе с операциями.
- **Почему:** решение владельца от 2026-07-31; откат частично перенесённого дерева требует собственной модели состояния и отдельной проверки, а без него функция уже закрывает заявленную проблему.

## 11. Критерии готовности (strategic-level)

1. При включённом показе субкаталогов пользователь выделяет одну папку галочкой, не прибегая к "выделить всё".
2. Долгое нажатие на папку начинает выделение, одиночный тап по-прежнему открывает папку.
3. У строки папки есть кнопка вызова меню операций, а в меню - копирование, перенос, переименование и удаление; неприменимые к папке действия не показываются.
4. Копирование папки в другой каталог того же ресурса создаёт у приёмника ту же структуру подпапок со всем содержимым.
5. Перенос папки между ресурсами разных типов завершается успешно, структура у приёмника повторяет исходную, а у источника папка исчезает только после подтверждённой записи.
6. Смешанное выделение из папок и файлов обрабатывается одной операцией.
7. Во время операции над деревом виден прогресс, отмена останавливает работу и сообщает, что уже выполнено.
