# Стратегическая спецификация: S0612 - Группы «Копировать в» / «Переместить в» в standalone-плеерах аудио/документов/текста

**Status:** Archived

**Tier:** 3 - Moderate (ad-hoc)
**Roadmap entry:** Ad-hoc - попутная находка при S0610 (2026-06-22)
**Tactical spec:** `PLAN/S0612_standalone-nonimage-copy-move-groups/`

> **Scope:** STRATEGIC. Цели, ограничения, открытые вопросы. Без имён классов, путей, лимитов строк, миграций Room, модулей Hilt.

## 1. Проблема

Открыв файл из внешнего приложения, пользователь попадает в один из standalone-плееров - отдельный экран просмотра одного файла. Для изображений (после S0610) внизу экрана есть группы команд «Копировать в» и «Переместить в», позволяющие одним касанием разложить файл по заранее настроенным папкам-назначениям. Для остальных типов содержимого этих групп нет.

Конкретно групп переноса нет в трёх standalone-хостах:

1. Аудио - экран прослушивания одиночного аудиофайла, открытого извне.
2. Документы - экран просмотра pdf/epub/office-файла, открытого извне.
3. Текст - экран просмотра текстового файла; присутствует лишь копирование содержимого в буфер обмена, что является иным действием (копируется текст, а не файл).

Из-за этого, открыв аудио/документ/текст извне, пользователь не может быстро скопировать или переместить сам файл в свои папки прямо с экрана просмотра - в отличие от in-app-плеера и (после S0610) standalone-плеера изображений. Возникает расхождение возможностей между типами содержимого в одном и том же сценарии «открыто извне».

Область - feature-path «плеер / standalone-просмотр», слой UI и файловых команд standalone-хостов.

---

## 2. Цели

1. В standalone-плеерах аудио, документов и текста внизу присутствуют группы команд «Копировать в» и «Переместить в», переносящие текущий открытый файл в настроенные папки-назначения.
2. Набор, внешний вид и поведение групп переноса согласованы с тем, как они уже работают в standalone-плеере изображений (S0610) и в in-app-плеере.
3. После успешного копирования экран остаётся открытым; после успешного перемещения экран закрывается (показанный файл исчез) - единообразно с поведением standalone-изображений.
4. Для аудио перемещение проигрываемого файла не приводит к сбою воспроизведения или порче файла: воспроизведение корректно завершается до закрытия экрана.

**Non-goals:**

- Печать и меню «Отправить в..» - вне объёма; это часть S0610 (только хост изображений).
- Изменение состава команд переноса в in-app-плеере или в standalone-хосте изображений.
- Новый механизм выбора папок-назначений сверх уже существующего в приложении.
- Устаревший `StandalonePlayerActivity` (помечен к удалению, S0393) - не затрагивается.
- Любые изменения существующего копирования текста в буфер обмена.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Переиспользовать ровно те же группы кнопок назначений и тот же путь файловых операций, что уже обобщены в S0610, а не создавать параллельную реализацию для каждого типа содержимого.
2. Оставить S0612 отдельным тикетом от S0610 (родитель уже в проверке на устройстве), не объединяя их в один.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты сборки, где доступны соответствующие типы содержимого (аудио - standard/legacy; документы - standard; текст - standard; см. матрицу флейворов). Логика живёт в общем коде standalone-хостов; флейвор-специфичных source set не требуется.
- **API level:** без специфики; перенос использует штатный системный механизм выбора папки и существующий слой файловых операций.
- **Wear OS:** не затрагивается.
- **Производительность:** добавление групп назначений не должно задерживать первичное отображение файла; построение кнопок выполняется отложенно, как в S0610.
- **Совместимость данных:** изменений формы хранения нет.
- **Локализация:** EN/RU/UK обязательны. Приоритет переиспользования существующих строк копирования/перемещения; новые строки - только при отсутствии подходящих.
- **Доступность:** новые элементы фокусируемы с клавиатуры и D-pad/TV (focusable, порядок фокуса), отличимы не только цветом; группы назначений не выходят за безопасные границы системных панелей в портрете и ландшафте.

### 3.3 Owner inputs (Approval gate)

- **UI placement contract:** группы «Копировать в» / «Переместить в» размещаются внизу каждого из трёх standalone-экранов (аудио, документы, текст) по образцу standalone-хоста изображений - свёртываемые ряды кнопок назначений под областью содержимого, внутри safe-area системных панелей. Существующие элементы экранов (контролы воспроизведения аудио, навигация документа, кнопка копирования текста) остаются на местах.
- **Accessibility:** все добавленные элементы фокусируемы с клавиатуры и D-pad, имеют contentDescription, отличимы не только цветом; раскладка остаётся в пределах safe-bounds в обеих ориентациях для всех трёх хостов.
- **Communication policy:** тексты подтверждений/ошибок переноса соответствуют `docs/COMMUNICATION_POLICY.md` (фактологичны, без обещаний); приоритет переиспользования строк, уже применённых в S0610.
- **Validation level:** сборка целевых флейворов + ручная проверка на устройстве (копирование и перемещение открытого извне аудио/документа/текста в настроенную папку, портрет и ландшафт).
- **Owner sign-off:** 2026-06-22.
- **Related tickets:** S0610 (родительский паттерн и переиспользуемые узлы), S0393 (маршрутизация и состав standalone-хостов), S0459 (модель команд плеера).

## 4. Контекст текущей архитектуры

Группы «Копировать в» / «Переместить в» уже обобщены в S0610 до уровня, пригодного к переиспользованию любым standalone-хостом: построение кнопок привязано к корню разметки (а не к конкретному binding), слой облегчённых файловых операций standalone умеет переносить текущий открытый файл с поведением «копирование оставляет экран, перемещение закрывает», а общий include командных панелей подключается к разметке.

Три целевых хоста (аудио, документы, текст) уже выполняют сам перенос через общий слой файловых операций (он подключён к ним ради переименования/SAF). Не подключены лишь видимые группы назначений: хосты не получают список папок-назначений, не строят кнопки и не включают общий include панелей в свои разметки. Поэтому групп переноса на этих экранах нет, хотя исполнительная часть переноса уже доступна.

Для аудио добавляется единственная специфика: при перемещении проигрываемого файла воспроизведение должно завершиться до закрытия экрана, чтобы не было обращения к уже перемещённому файлу.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**Столп A - подключить группы назначений к трём standalone-хостам.**

- Внизу каждого из трёх экранов появляются те же свёртываемые группы кнопок назначений, что и у standalone-изображений, через общий include командных панелей в разметке (портрет и ландшафт).
- Каждый хост получает список настроенных папок-назначений из существующего глобального источника (без ресурс-контекста, как решено в S0610) и строит кнопки отложенно при показе файла.

**Столп B - переиспользовать исполнение переноса.**

- Нажатие кнопки назначения копирует/перемещает текущий открытый файл через уже подключённый слой файловых операций standalone.
- Поведение после операции единообразно: копирование оставляет экран, перемещение закрывает.
- Кнопка «..» выбора произвольной папки переиспользует тот же системный выбор папки, что и в standalone-изображениях.

**Столп C - аудио-специфика завершения воспроизведения.**

- При перемещении проигрываемого аудиофайла воспроизведение завершается до закрытия экрана штатным жизненным циклом экрана; столп фиксирует это как требование и проверяется на устройстве.

### 5.2 Потоки данных и событий

- Список назначений: глобальный источник настроенных папок → построение кнопок групп (отложенно, по разметке) при показе файла.
- Перенос: UI групп назначений → команда копирования/перемещения текущего файла → слой файловых операций standalone → обновление состояния экрана (остаться/закрыться) и пользовательское подтверждение.
- Произвольная папка: кнопка «..» → системный выбор папки → копирование/перемещение в выбранный путь.

### 5.3 Точки расширяемости

- Подключение групп назначений к каждому хосту делается через тот же контракт, что и у standalone-изображений, чтобы любой будущий standalone-хост подключался единообразно.
- Источник списка назначений для безресурсного контекста уже выделен в S0610 и переиспользуется без изменений.

## 6. Открытые вопросы / Research items

1. **Источник папок-назначений в безресурсном standalone-контексте**
   - **Вопрос:** откуда брать список «Копировать в» / «Переместить в» для аудио/документа/текста, открытых извне?
   - **Решение:** переиспользовать решение S0610 - глобальный список назначений без ресурс-контекста; фильтр исключения текущего ресурса не исключает ничего; при пустом списке остаётся кнопка «..».
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0612_standalone-nonimage-copy-move-groups/research/01__host-wiring-inventory.md`

2. **Поведение экрана после успешного переноса**
   - **Вопрос:** оставаться или закрываться после копирования/перемещения для не-изображений?
   - **Решение:** единообразно с S0610 - копирование оставляет экран, перемещение закрывает экран (показанный файл исчез).
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0612_standalone-nonimage-copy-move-groups/research/01__host-wiring-inventory.md`

3. **Завершение воспроизведения при перемещении аудио**
   - **Вопрос:** нужно ли явно останавливать воспроизведение перед перемещением проигрываемого аудиофайла?
   - **Решение:** перенос завершается на диске до закрытия экрана; закрытие экрана штатно приостанавливает и освобождает воспроизведение жизненным циклом. Явная предварительная остановка не требуется; требование проверяется на устройстве.
   - **Статус:** Resolved
   - **Артефакт:** `PLAN/S0612_standalone-nonimage-copy-move-groups/research/01__host-wiring-inventory.md`

## 8. Влияние на пользователя (docs/FEATURES)

Новая воспринимаемая способность: в standalone-просмотре аудио, документа и текста (файл открыт извне) пользователь может быстро копировать или перемещать файл в свои настроенные папки прямо с экрана просмотра, как уже сделано для изображений. Одно предложение для `docs/FEATURES.md` + `_RU` + `_UK` при релизе (наполняется через `/skill-release` из диффа `ALL_FEATURES`).

## 9. Архитектурные решения (ADR)

**ADR-1: Переиспользовать узлы S0610, а не дублировать на каждый хост**

- **Решение:** подключить уже обобщённые построение кнопок назначений и слой файловых операций standalone к трём хостам через общий контракт и общий include.
- **Альтернативы:** отдельная реализация групп для аудио, документов и текста.
- **Почему:** единообразие поведения и внешнего вида, минимум дублирования, родительский паттерн уже проверяется на устройстве.

**ADR-2: Аудио не получает специальной предварительной остановки воспроизведения**

- **Решение:** опираться на штатное завершение воспроизведения жизненным циклом экрана при закрытии после перемещения.
- **Альтернативы:** явный вызов остановки плеера перед перемещением.
- **Почему:** перенос завершается на диске до закрытия экрана, жизненный цикл уже приостанавливает и освобождает плеер; лишний код не нужен. Требование закреплено и проверяется на устройстве.

## 11. Критерии готовности (strategic-level)

1. Внизу экранов standalone-плееров аудио, документов и текста отображаются группы «Копировать в» и «Переместить в».
2. Нажатие кнопки назначения копирует или перемещает текущий открытый файл в выбранную папку, пользователь получает понятное подтверждение результата.
3. После копирования экран остаётся; после перемещения экран закрывается.
4. Для аудио перемещение проигрываемого файла завершается без сбоя воспроизведения и без обращения к перемещённому файлу.
5. Новые элементы доступны с клавиатуры и D-pad, корректно умещаются в портрете и ландшафте на всех трёх экранах.
6. Поведение и внешний вид групп переноса единообразны со standalone-хостом изображений в пределах объёма спеки.
