## 1. Проблема

Секция «Трансляции» в Media settings сейчас даёт только мастер-переключатель функции и кнопку перехода на экран списка каналов. Для первого включения этого достаточно, но для регулярного использования секция почти не помогает настроить поведение самой фичи.

При этом сам экран «Трансляции» уже умеет больше, чем отражено в настройках: есть сортировка, фильтры, импорт каталога, закрепление каналов, статус последнего воспроизведения, фоновое аудио и ярлыки каналов. Пользователь вынужден каждый раз вручную повторять часть предпочтений или искать связанные опции в других разделах.

---

## 2. Цели

1. Дать пользователю 3-6 действительно полезных stream-specific настроек прямо рядом с мастер-переключателем.
2. Перенести в настройки только те решения, которые задают дефолтное поведение фичи, а не дублируют одноразовые действия экрана.
3. Уменьшить число повторяющихся действий при каждом открытии экрана «Трансляции».
4. Не дублировать глобальные настройки, которые уже управляют фоновым аудио, общим кэшем или поведением плеера во всём приложении.
5. Сохранить секцию компактной и понятной, без превращения её в отдельный «экран настроек внутри настроек».

**Non-goals:**

- Полный редизайн экрана списка трансляций.
- Новые протоколы, новый движок воспроизведения или глубокие сетевые тюнинги.
- Дублирование глобальных настроек фонового аудио, cache cleanup или общих player settings.
- Отдельная административная панель для массового редактирования каналов.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Первая итерация должна давать заметное удобство без тяжёлой архитектурной перестройки.
2. Настройки должны быть понятны без чтения документации и без технических терминов вроде HLS buffer или transport retry policy.
3. Приоритет - настройки, которые меняют дефолтное поведение списка и каталога, а не редкие аварийные сценарии.
4. В первой итерации обязательно должны быть настройки `Default sort mode` и `Default media type filter`.
5. Поведение `Remember last filter/search` должно быть встроенным поведением экрана «Трансляции», а не опциональным переключателем.

### 3.2 Жёсткие ограничения

- **Flavor:** только там, где сама фича «Трансляции» уже доступна пользователю; реализация наследует существующий capability/runtime gate
- **API level:** без API-специфики на стратегическом уровне
- **Wear OS:** не затрагивается
- **Производительность:** новые настройки не должны замедлять холодный старт приложения и не должны требовать тяжёлой фоновой работы по умолчанию
- **Совместимость данных:** существующие ручные и импортированные каналы сохраняются без потерь
- **Локализация:** EN/RU/UK
- **Доступность:** каждая новая строка должна быть понятна для TalkBack, D-pad/TV и мыши

### 3.3 Owner inputs (Approval gate)

- **Related tickets:** S0565 (базовая подсистема «Трансляции»), S0575 (секция в Media settings), S0577 (граница с global background audio), S0634 (live-HLS recovery)
- **UI scope:** новые строки в существующей секции «Трансляции» Media settings - три выпадающих списка (default sort mode, default media type filter, catalog refresh policy) и одно действие (clear play statuses); состав и порядок делегированы агенту, итоговый UI-набор зафиксирован в §5.1.0 и утверждается владельцем на device-test
- **Data scope:** новые stream-specific preferences сохраняются через существующее хранилище настроек приложения; Room schema не меняется; ручные и импортированные каналы сохраняются без потерь
- **Flavor scope:** наследует существующий capability/runtime gate фичи «Трансляции» - новый flavor не вводится, новые строки видны только там, где сама фича доступна

## 4. Контекст текущей архитектуры

Подсистема «Трансляции» уже отделена как самостоятельная capability: у неё есть свой экран списка, собственный каталог источников и отдельный пользовательский мастер-переключатель. Текущее место в настройках отражает только факт включения фичи, но почти не отражает её повседневное использование.

С другой стороны, часть связанных решений уже живёт вне этой секции. Поведение фонового аудио и выхода из экрана регулируется общими audio/playback settings, а очистка streaming cache - глобальными cache settings. Поэтому расширение секции «Трансляции» должно добавлять только локальные для фичи дефолты, не размывая ответственность других разделов.

## 5. Предлагаемый подход

Расширить группу «Трансляции» не всеми возможными переключателями подряд, а коротким набором настроек по четырём опорным направлениям: дефолты списка, поведение каталога, поведение проблемных каналов и локальное обслуживание данных. В первой итерации зафиксировать минимум два явных пользовательских дефолта списка и одно неотключаемое поведение восстановления последнего фильтра/поиска.

### 5.1 Основные столпы / модули

#### 0. Состав первой итерации (locked - owner quiz 2026-06-24)

Зафиксированный объём первой итерации (`/spec-all` quiz, владелец): **дефолты списка + поведение каталога** (столпы A и B). Деградация и массовое обслуживание (столпы C, D) - вторая волна, кроме явно затребованного действия сброса статусов.

Строки секции «Трансляции» в первой итерации:

1. **Default sort mode** - выпадающий список: имя / тема / язык / недавно добавленные.
2. **Default media type filter** - выпадающий список: все / только аудио / только видео-RTSP.
3. **Catalog refresh policy** - выпадающий список: только вручную / предлагать при открытии (дефолт) / периодически по Wi‑Fi.
4. **Clear play statuses** - действие: сбросить локальные OK/FAIL индикаторы всех каналов.

Встроенное поведение (без отдельных строк-переключателей):

- **Remember last filter/search** - экран «Трансляции» всегда восстанавливает и применяет последнюю строку поиска и состояние фильтра.
- **OK/FAIL индикатор** - остаётся всегда видимым (без toggle видимости); управляется только действием сброса выше.

Отложено во вторую волну (не реализуется сейчас): автоповтор проблемного канала (C), предпочитаемый способ добавления и download-prompt каталога (B-расширения), скрытие каналов без метаданных (D), мостик/summary к глобальным audio/cache настройкам (research item 2).

#### A. Дефолты списка при открытии

Цель - чтобы экран «Трансляции» открывался уже в удобном для пользователя виде.

Зафиксированные решения первой итерации:

- **Режим сортировки по умолчанию** - имя / тема / язык / недавно добавленные.
- **Фильтр типа по умолчанию** - все / только аудио / только видео-RTSP.
- **Запоминать последний фильтр и поиск** - обязательное поведение экрана «Трансляции»: при повторном открытии он восстанавливает и применяет последнюю строку поиска и последнее состояние фильтра, без отдельного пользовательского переключателя.

Пояснение по границе ответственности:

- `Default sort mode` и `Default media type filter` задают базовый стартовый профиль списка.
- Восстановление последнего filter/search переопределяет «пустой старт» и должно работать автоматически как user convenience behavior окна.

#### B. Поведение каталога и импорта

Цель - сократить ручные действия вокруг каталога станций и не смешивать одноразовый импорт с постоянной настройкой.

Рекомендуемые кандидаты:

- **Обновление каталога источников** - только вручную / предлагать после включения / обновлять при открытии по Wi‑Fi.
- **Предпочитаемый способ добавления** - сначала ручной URL или сначала каталог, если пользователь чаще работает одним сценарием.
- **Показывать предложение скачать каталог после первого включения** - да / нет.

#### C. Поведение при нестабильных каналах

Цель - управлять UX деградации, не вынося в настройки низкоуровневые сетевые параметры.

Рекомендуемые кандидаты:

- **Автоповтор проблемной аудиотрансляции** - выключен / мягкий режим / более настойчивый режим.
- **Показывать индикатор последнего результата воспроизведения** - да / нет.

#### D. Локальное обслуживание списка

Цель - дать пользователю простые действия очистки именно stream-specific состояния.

Рекомендуемые кандидаты:

- **Очистить статусы воспроизведения** - сбросить локальные OK/FAIL индикаторы для всех каналов.
- **Скрывать каналы без метаданных каталога в фильтрах по умолчанию** - полезно для тех, кто хочет видеть в первую очередь «качественный» каталог, а не ручные URL.

### 5.2 Потоки данных и событий

Пользователь задаёт stream-specific дефолты в секции «Трансляции». Экран списка читает эти дефолты при открытии и использует их как начальное состояние списка, фильтрации, сортировки и UX-восстановления. Разовые действия экрана остаются на экране, а настройки определяют только стартовое поведение и постоянные предпочтения.

Для каталога и деградации логика остаётся событийной: открытие секции или экрана может предлагать обновление каталога, а ошибки воспроизведения интерпретируются через выбранный профиль поведения. При этом общие настройки фонового аудио, player exit behavior и streaming cache остаются единым источником правды и не копируются в эту секцию.

### 5.3 Точки расширяемости

- Набор настроек должен позволять добавить вторую волну stream-specific preferences без смены UX-паттерна секции.
- В секции должно быть ясно различимо, что является дефолтом списка, что каталогом, а что обслуживанием данных.
- Если позже появится отдельный экран «Настройки трансляций», текущая секция должна стать его краткой summary/version, а не тупиковым UI.

## 6. Открытые вопросы / Research items

**Артефакт:** `PLAN/S0659_streams-settings-expansion/research/01__streams-settings-architecture.md` - карта архитектуры (секция настроек, DataStore-паттерн, экран списка, play-status, каталог, flavor-gate, строки) + зафиксированные дизайн-решения для тактического плана.

1. **Какой минимальный набор первой итерации**
   - **Вопрос:** какие 3-4 настройки дают максимум пользы без разрастания секции?
   - **Варианты:** только дефолты списка; дефолты списка + каталог; полный набор с деградацией и очисткой
   - **Нужно выяснить:** как дополнить уже зафиксированное ядро из `Default sort mode`, `Default media type filter` и автоматического восстановления последнего filter/search
   - **Статус:** Resolved - первая итерация = ядро (sort/filter/remember) + `Catalog refresh policy` + действие `Clear play statuses`; столпы C/D в остальном отложены (owner quiz 2026-06-24)

2. **Где проходит граница с глобальными audio/cache settings**
   - **Вопрос:** разрешать ли в секции «Трансляции» ссылки/summary на глобальные настройки вместо дублей?
   - **Варианты:** без ссылок; только summary; summary + shortcut
   - **Нужно выяснить:** нужен ли продуктово «мостик» к уже существующим global settings
   - **Статус:** Resolved (для итерации 1) - без мостика/summary к глобальным настройкам (ADR-1: только stream-specific defaults); вопрос моста перенесён во вторую волну

3. **Нужен ли автоапдейт каталога как фоновой политики**
   - **Вопрос:** достаточно ли opportunistic refresh при открытии экрана, или нужен отдельный фоновый режим
   - **Варианты:** только вручную; on-open; периодически по Wi‑Fi
   - **Нужно выяснить:** приемлем ли продуктово сетевой шум ради свежести каталога
   - **Статус:** Resolved - дефолт `предлагать при открытии` (opportunistic on-open); `только вручную` и `периодически по Wi‑Fi` доступны как альтернативы в выпадающем списке (owner quiz 2026-06-24)

4. **Нужно ли хранить последний search/filter per-user постоянно**
   - **Вопрос:** это удобное восстановление контекста или раздражающий «липкий» UI
   - **Варианты:** всегда помнить; отдельный toggle; помнить только sort mode
   - **Нужно выяснить:** дополнительного выяснения не требуется
   - **Статус:** Resolved - экран «Трансляции» всегда помнит, восстанавливает и применяет последнюю строку поиска и последнее состояние фильтра; отдельный toggle не нужен

5. **Нужен ли toggle скрытия индикатора OK/FAIL**
   - **Вопрос:** статус последнего воспроизведения помогает или визуально шумит
   - **Варианты:** всегда показывать; настройка show/hide; оставить только action reset
   - **Нужно выяснить:** воспринимается ли индикатор как полезная диагностика
   - **Статус:** Resolved - индикатор OK/FAIL остаётся всегда видимым (без toggle), добавляется только действие `Clear play statuses` (owner quiz 2026-06-24)

## 9. Архитектурные решения (ADR)

**ADR-1: Не дублировать глобальные audio/cache settings внутри «Трансляций»**

- **Решение:** секция «Трансляции» хранит только локальные для этой capability дефолты и обслуживающие действия.
- **Альтернативы:** скопировать сюда background audio behavior, exit behavior и streaming cache cleanup.
- **Почему:** иначе пользователь получит две точки правды для одних и тех же правил.

**ADR-2: Первая итерация должна быть short-list, а не «всё подряд»**

- **Решение:** начинать с небольшого набора высокоценных настроек списка и каталога.
- **Альтернативы:** сразу открыть отдельный насыщенный экран под Streams preferences.
- **Почему:** текущая проблема не в отсутствии десятков опций, а в отсутствии нескольких дефолтов, которые экономят повторяющиеся действия.

**ADR-3: Предпочтение пользовательских формулировок над техническими**

- **Решение:** любые stream-specific toggles описывать как сценарии поведения, а не как сетевые термины.
- **Альтернативы:** expose retries, timeouts, live edge recovery и другие engine-детали напрямую.
- **Почему:** секция настроек рассчитана на обычное ежедневное использование, а не на инженерный дебаг.

## 11. Критерии готовности (strategic-level)

1. Пользователь видит в секции «Трансляции» не только мастер-переключатель, но и небольшой набор stream-specific настроек, влияющих на дефолтное поведение фичи.
2. В первой итерации секция явно включает `Default sort mode` и `Default media type filter` как отдельные пользовательские настройки.
