## 1. Проблема

При индексировании видеофайлов на SMB-ресурсе системный API извлечения метаданных может завершаться с `RuntimeException` (статус `0x80000000` — общая ошибка ввода-вывода). В текущей реализации исключение перехватывается, файл получает пустые метаданные, и сканирование продолжается — однако ошибка логируется на уровне VERBOSE, что делает её полностью невидимой в production-сборках. Счётчик сбоев не включается в результат скана, поэтому вызывающий код и UI не могут ни отобразить предупреждение, ни отличить «файл без метаданных» от «файл с ошибкой метаданных». Дополнительно: попытка извлечь кадр-превью из файла с битым заголовком порождает системное предупреждение `getFrameAtTime: videoFrame is a NULL pointer`, которое не перехватывается отдельно и создаёт шум в логах.

---

## 2. Цели

1. Ошибки извлечения метаданных из видеофайлов по SMB фиксируются в logcat на уровне W (warning) — видны в production-логах без фильтрации.
2. Результат сканирования папки содержит счётчик файлов, у которых извлечение метаданных завершилось ошибкой.
3. Пользователю отображается ненавязчивое предупреждение (например, подпись в UI), если часть файлов была проиндексирована без метаданных из-за ошибок.
4. `getFrameAtTime`, возвращающий `null`, обрабатывается явно и не попадает в системный лог как неожиданное предупреждение.

**Non-goals:**
- Повторная попытка извлечь метаданные при следующем сканировании (ретраи) — вне объёма.
- Парсинг метаданных альтернативными библиотеками вместо системного API.
- Изменение формата хранения метаданных в Room.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Счётчик ошибок метаданных включить в существующую структуру результата скана — без создания новых экранов.
2. Если ошибки метаданных не влияют на воспроизведение файла, не блокировать операцию сортировки/перемещения.

### 3.2 Жёсткие ограничения

- **Flavor:** standard, lite, legacy — все варианты со SMB-поддержкой.
- **API level:** minSdk 26. Обработка `close()` vs `release()` при API < 29 уже присутствует, не трогать.
- **Wear OS:** не затрагивается.
- **Производительность:** добавление счётчика не должно требовать дополнительных сетевых запросов или пересканирования.
- **Совместимость данных:** структура Room не меняется. Поле `duration`/`width`/`height` остаётся nullable.
- **Локализация:** если добавляется UI-предупреждение — строка должна быть в EN/RU/UK.
- **Доступность:** не затрагивается.

## 4. Контекст текущей архитектуры

Сканирование SMB-директории выполняется в data-слое: компонент читает первые ~1 МБ каждого видеофайла во временный файл и передаёт его системному API извлечения метаданных. Ошибки этого API перехватываются и скрыто проглатываются — функция возвращает `null` без различия между «метаданных нет» и «произошла ошибка». Результат скана передаётся через ViewModel в UI, однако информация о частичных сбоях по пути теряется.

Проблему нельзя решить сейчас, не меняя модель результата скана: текущий контракт между data-слоем и domain/UI не предусматривает поля для счётчика ошибок.

## 5. Предлагаемый подход

### 5.1 Уровень логирования

Заменить VERBOSE на WARNING при перехвате исключения от системного API метаданных. Это единственное изменение, которое не требует изменения контракта.

### 5.2 Счётчик ошибок в результате скана

Добавить в структуру результата сканирования папки атомарный счётчик ошибок метаданных. Инкрементировать его при каждом исключении в процессе извлечения. Передавать значение через ViewModel в UI.

### 5.3 UI-индикация частичного результата

Если счётчик > 0, UI отображает нейтральное предупреждение после завершения скана: «N файлов проиндексированы без метаданных». Это не блокирующий диалог — просто информационный снекбар или подпись в списке.

### 5.4 Явная обработка null-кадра

Добавить ранний возврат при `getFrameAtTime == null` перед попыткой использовать результат, чтобы устранить системный шум в logcat.

### 5.5 Потоки данных и событий

```
[SMB-сканирование: папка]
    → для каждого видеофайла:
        → data: извлечь метаданные (temp file → SystemAPI)
            → SUCCESS: заполнить поля метаданных
            → FAILURE (RuntimeException): лог W + increment errorCount + поля = null
    → data: возвращает ScanResult(files=[], errorCount=N)
    → domain: передаёт в ViewModel
    → UI: если errorCount > 0 — показать snackbar/label
```

### 5.6 Точки расширяемости

- Счётчик ошибок расширяем: в будущем может включать список имён файлов с ошибками (для отладочного экрана).

## 6. Открытые вопросы / Research items

1. **Включает ли текущая структура результата скана поле для ошибок?**
   - **Вопрос:** У результата сканирования папки уже есть поле для частичных ошибок, или его нужно добавлять?
   - **Ответ:** `MediaScanner.scanFolder()` возвращает `List<MediaFile>` — поля для ошибок нет. `GetMediaFilesUseCase` эмитит `Flow<List<MediaFile>>`. Поле нужно добавить через новый метод `onMetadataErrors(count: Int)` в `ScanProgressCallback` (default no-op — не ломает существующие реализации).
   - **Статус:** Resolved

2. **Нужен ли отдельный счётчик для SFTP/FTP сканеров?**
   - **Вопрос:** Аналогичная проблема может быть в SFTP и FTP сканерах.
   - **Ответ:** `SftpMediaScanner` и `FtpMediaScanner` не используют `MediaMetadataRetriever` и не выполняют извлечение метаданных видео при сканировании — исправление касается только SMB.
   - **Статус:** Resolved

## 9. Архитектурные решения (ADR)

**ADR-1: Счётчик ошибок — в результате скана, а не в отдельном событии**
- **Решение:** добавить `metadataErrorCount: Int` в существующую структуру результата.
- **Альтернативы:** отдельный `SharedFlow<ScanError>` событий; отдельная таблица Room с историей ошибок.
- **Почему:** счётчик в результате минимален по объёму изменений, не требует нового канала событий и соответствует уже существующему паттерну scan-result в проекте.

## 11. Критерии готовности (strategic-level)

1. При SMB-сканировании папки с видеофайлом, чей заголовок нечитаем, в logcat появляется строка уровня W (а не V) с именем файла.
2. В результате скана поле `metadataErrorCount` содержит ненулевое значение для сессий с ошибками.
3. Пользователь видит ненавязчивое предупреждение в UI, если хотя бы один файл не получил метаданные.
4. Файлы без метаданных по-прежнему присутствуют в списке и доступны для воспроизведения.
5. Системный шум `getFrameAtTime: videoFrame is a NULL pointer` не воспроизводится при сканировании тех же файлов.
