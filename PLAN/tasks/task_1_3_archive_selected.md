# Фича: Архивация выбранных файлов (task_1_3_archive_selected)

## 1. Цель
Реализовать функцию массовой упаковки выбранных медиафайлов в единый ZIP-архив с возможностью выбора имени архива и целевой директории. Архивация должна происходить асинхронно, не блокируя UI, с отображением прогресса выполнения (особенно для больших файлов).

## 2. Местоположение и Точка входа
- **Экран:** `BrowseActivity`
- **Запуск:** Кнопка `btnArchive` (`ImageButton`) в нижней панели `layoutOperations` — рядом с `btnShare`. Кнопка отображается только при активной выборке (≥1 файл). Это соответствует архитектурному паттерну уже существующих кнопок `btnCopy`, `btnMove`, `btnDelete`, `btnShare`.
- **Ограничение v1:** Архивация работает только для **локальных** файлов (`ResourceType.LOCAL`). Для сетевых (SMB/SFTP/FTP) и облачных ресурсов показывается Snackbar с объяснением ограничения.

> **Исправлено:** Спецификация изначально указывала на `ResourceOpsMenuManager` как точку входа, что противоречит архитектурному паттерну проекта. Операции над выбранными файлами (copy/move/delete/share) реализованы как кнопки тулбара, а не пункты popup-меню. `ResourceOpsMenuManager` используется для операций уровня ресурса (поиск дублей, удаление по размеру, создание папки).

## 3. UI/UX Требования
1. **Состояние пункта меню:**
   - Если в `BrowseSelectionManager` выбрано 0 файлов (или ActionMode выключен) — пункт меню `Заархивировать` скрыт или неактивен.
   - Если выбран хотя бы 1 файл (и файлы поддерживают агрегацию в архив) — пункт активен.
2. **Диалог настройки архивации (`ArchiveConfigurationDialog`):**
   - **Поле ввода имени архива:** 
     - При открытии диалога поле предзаполняется базовым именем (например, `<Имя первого выбранного файла>.zip` или `Архив_YYYYMMDD.zip`).
     - Поддержка валидации символов (недопустимые для файловой системы символы блокируются или подсвечиваются ошибкой).
   - **Выбор папки назначения (селектор директории):**
     - По умолчанию выбрана текущая открытая директория.
     - Возможность выбрать другую локальную папку из доступных ресурсов приложения.
   - **Кнопки:** "Отмена", "Архивировать".
3. **Отображение прогресса:**
   - При старте процесса должен отображаться индикатор прогресса (Dialog, ProgressBar на экране или уведомление), показывающий статус (например, X из Y файлов, или проценты обработки).
4. **Завершение операции:**
   - По завершении скрывается прогресс.
   - Выделение файлов очищается (сброс `ActionMode` через `BrowseSelectionManager`).
   - Если целевая папка архивации совпадает с текущей директорией, список файлов обновляется (например, триггер `GetMediaFilesUseCase` / перезагрузка состояния через `BrowseStateManager`).

## 4. Технические Требования и Архитектура
Для соответствия спецификациям проекта (Clean Architecture + MVVM + Hilt + Coroutines) необходимо реализовать следующий стек:

### 4.1 UI Layer (`app_v2/src/main/java/com/sza/fastmediasorter/ui/browse/`)

- Управлять видимостью `btnArchive` в том же месте, где управляются `btnCopy`, `btnMove` и т.д. (в обозревателе состояния в `BrowseActivity`, ~ строка 1214).
- Создать компонент `ArchiveConfigurationDialog` (`MaterialAlertDialogBuilder`-диалог внутри `BrowseActivity`) для сбора параметров архивации.
- Реализовать логику запуска в `BrowseViewModel.archiveSelectedFiles(archiveName, destinationPath)` и подписку на прогресс.
- Слушать события прогресса в UI слое (показывать `ProgressDialog` / `Toast`, Snackbar с результатом).
- Зарегистрировать новые ресурсы строк (локализацию EN/RU/UK) в `strings.xml` + `strings-ru.xml` + `strings-uk.xml`.

### 4.2 Domain Layer (`com/sza/fastmediasorter/domain/`)
- Создать сущность `ArchiveFilesUseCase`: принимает список `Uri` или путей (MediaItem), имя выходного файла и путь назначения. Возвращает `Flow<ArchiveProgress>` с текущим состоянием процесса (состояния: *Готовится, Выполняется (%), Успех, Ошибка*).
- Внутри UseCase или ассоциированной утилите реализовать логику *Safe Name Resolution* (разрешение коллизий): если файл `<archive_name>.zip` уже существует, генерировать инкремент: `<archive_name>_1.zip`, `_2` и т.д., перед открытием потока записи.

### 4.3 Data Layer / Инфраструктура
- **Обработка данных:** Архивация видео и фото в исходном разрешении ресурсоемка. Реализовать системный `CoroutineWorker` (WorkManager) с Foreground Info для долгих задач, либо использовать выделенный скоуп корутин в `FileRepository` (`Dispatchers.IO`) с поддержкой отмены (`Job.cancel()`). Разработчику следует выбрать оптимальный подход, предотвращающий `OOM` (OutOfMemory).
- **Генерация ZIP:** Использовать класс `java.util.zip.ZipOutputStream` с жесткой буферизацией (оборачиваем потоки в `BufferedOutputStream` и `BufferedInputStream`). Чтение исходных крупных файлов выполнять только чанками (байтовыми массивами, например 8KB-64KB).
- Передавать прогресс в `Flow`, используя потокобезопасные механизмы.

## 5. Корнер-кейсы и Краевые Ситуации
- **Нехватка места на диске:** Перед началом и в процессе создания ZIP проверять доступное свободное место на целевом носителе, перехватывать `IOException` (No space left on device) и выдавать соответствующее сообщение (Snackbar).
- **Отмена/Прерывание операции:** Реализовать поддержку `CancellationException`. Если пользователь или система прерывает корутину/Worker: закрыть `ZipOutputStream` и **обязательно удалить частично записанный .zip файл** (Cleanup механизм).
- **Разные источники файлов:** Убедиться, что `InputStream` корректно открывается через `ContentResolver` для `content://` Uri и через `FileInputStream` для `file://` / raw path.
- **Ошибки доступа (Permissions):** Обработать ситуации отсутствия прав Storage API / MediaStore (Android 10+ Scoped Storage) при попытке создания архива в недоступной директории.
