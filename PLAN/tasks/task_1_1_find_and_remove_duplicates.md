# Детализированное техзадание: Поиск и удаление дубликатов (готово для разработчика)

## 1. Цель задачи
Реализовать эффективный функционал прочесывания текущего ресурса на наличие идентичных файлов-копий (дубликатов) с предоставлением пользователю удобного интерфейса для их просмотра и безопасного массового удаления.

## 2. Местоположение в UI
- **Экран**: `Browse` (базовый экран просмотра содержимого папки/ресурса).
- **Точка входа**: Меню `Resource Operations` (троеточие / Overflow Menu) -> Пункт меню `Найти и удалить дубликаты`.

## 3. Архитектурные требования (Strict Rules)
- **Архитектура**: MVVM + Clean Architecture (запрещена любая бизнес-логика напрямую внутри `Fragment`/`Activity`).
- **Стек**: Kotlin (Coroutines/Flow для асинхронности), Hilt (Dependency Injection).
- **Пакетная структура**: Работать строго в пределах `app_v2/src/main/java/com/sza/fastmediasorter/`.
- **Логирование**: Использовать **ТОЛЬКО** `Timber` (никаких `Log.d()`).
- **Обработка данных**: Анализ файлов выносить в специализированные классы (например, `DuplicateScannerManager` или `FindDuplicatesUseCase`), не перегружать ViewModel на 1000 строк.

## 4. Алгоритм под капотом (Data & Domain Layers)
> **Критическое требование к производительности**: Не вычислять хэш для всех подряд файлов!

Алгоритм должен работать в два этапа:
1. **Предфильтр (Grouping by Size)**:
   - Получить все файлы текущего ресурса.
   - Сгруппировать их по точному размеру в байтах.
   - *Отсеять (discard)* все группы, состоящие из одного элемента (если размер уникален, файл точно не имеет дубликатов в этой папке).
2. **Глубокий анализ (Hashing)**:
   - Для оставшихся групп (где 2+ файла одинакового размера) вычислить контрольную сумму (MD5 / SHA-256).
   - Сгруппировать файлы по совпадению хэша.
   - Вернуть финальный список групп, внутри которых совпадает и размер, и контрольная сумма.

## 5. Требования к UI (Presentation Layer)
1. **Анализ (Loading State)**:
   - При вызове опции из меню, запустить сканирование в `Dispatchers.IO`.
   - Показать блокирующий UI-диалог с прогрессом: тексты типа "Анализ файлов...", "Обработано X из Y".
   - Должна быть кнопка "Отмена" для прерывания (отмены корутины).
2. **Экран результатов (`DuplicatesFragment` или `BottomSheetDialog`)**:
   - При нахождении дубликатов отобразить список (рекомендуется `RecyclerView` с `ConcatAdapter` или просто сложный `ListAdapter`).
   - Каждая "группа" (Group) визуально отделена. Показывается превью/иконка базового файла.
   - **Авто-селект (Важно)**: По умолчанию алгоритм должен оставлять 1 файл (самый старый по File Last Modified) невыделенным, а все остальные его копии в этой группе — отметить галочкой (Checkbox) на удаление.
3. **Действие**:
   - Плавающая или закрепленная снизу кнопка "Удалить выбранные (N шт, общим весом Y МБ)".
   - Модальное подтверждение перед физическим удалением.
   - После успешного удаления вернуть пользователя на экран `Browse` с командой на обновление списка файлов (Refresh).

## 7. Риски и подводные камни
- **Large Files OOM:** Запрещено читать бинарник целиком. Все хеши вычисляются через поток (InputStream).
- **Сетевые хранилища (SMB/Network):** Чтение данных по сети медленное. Если ресурс сетевой, этап вычисления хэша должен брать данные экономно (возможно, брать не весь хэш файла, а лишь заголовка + футера для крупных сетевых медиа-файлов, если это допустимо архитектурой). Тестировать на прерывании задачи `CancellationBuilder`.
- Обновление родительского экрана: не забудьте инвалидировать данные в `BrowseViewModel` после успешного удаления копий.
