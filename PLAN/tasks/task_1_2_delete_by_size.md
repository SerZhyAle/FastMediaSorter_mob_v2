# Техническое задание: Удаление файлов по размеру (Delete by size)

## 1. Контекст задачи
Реализовать в приложении функцию массовой очистки ресурсов от файлов, размер которых не соответствует заданным критериям (слишком мелкие или слишком тяжелые). Функция должна обеспечивать безопасное удаление с предварительным расчетом и подтверждением перед операцией.

## 2. Область применения
- **Экран**: `BrowseActivity` / `BrowseFragment`.
- **Протоколы**: Локальные файлы, SMB, SFTP, FTP, Cloud (Google Drive).
- **Стек**: Kotlin, Coroutines (IO), Hilt, Clean Architecture.

## 3. Требования к UI/UX

### 3.1. Точка входа
- В меню `Resource Operations` (Кнопка «...» в заголовке списка файлов) добавить один пункт: **«Удаление по размеру...»**.
- Консолидировать (удалить) существующие временные пункты "Delete smaller than" / "Delete larger than" в `ResourceOpsMenuManager.kt`.

### 3.2. Диалог настройки (Phase 1)
При выборе пункта открывается диалог со следующими элементами:
- **Условие (RadioGroup/Chips)**: «Меньше чем» (-) или «Больше чем» (+).
- **Поле ввода (EditText)**: Тип `numberDecimal`.
- **Выбор единиц (Spinner/Menu)**: КБ, МБ (по умолчанию), ГБ.
- **Кнопка «Анализ»**: Запускает асинхронный поиск файлов в текущем пути.

### 3.3. Диалог подтверждения (Phase 2)
После сканирования отображается результат:
- **Текст результата**: «Найдено файлов для удаления: **X**\nОбщий освобождаемый объем: **Y**».
- **Предупреждение (только для Network/Cloud)**: «Внимание: для этого ресурса корзина не поддерживается. Удаление будет безвозвратным!» (стилизовано как WARNING).
- **Кнопки**: «Отмена» и «Удалить файлы» (выделена красным).

### 3.4. Процесс удаления (Phase 3)
- Переиспользовать `FileOperationProgressDialog` для отображения прогресса.
- По завершении — уведомление о результате (Toast/Snackbar) и автоматическое обновление списка файлов (`loadResource()`).

## 4. Технические требования

### 4.1. Domain Layer (Clean Architecture)
- **UseCase**: `DeleteByFileSizeUseCase.kt`
  - **Критическое исправление**: Исключить прямое создание `java.io.File(path)` для сетевых ресурсов (SMB/SFTP/FTP/Cloud). Необходимо передавать URI или использовать существующую логику `FileOperationUseCase` для обработки различных схем.
  - **Новый функционал**: Разделить логику на `scan(criteria)` -> `List<MediaFile>` и `execute(files)`.

### 4.2. ViewModel (State Management)
- В `BrowseViewModel.kt` добавить:
  - Состояние процесса анализа (Loading/Success/Empty).
  - Обработку нового события `BrowseEvent.ShowDeleteBySizePreview(count, totalBytes)`.
  - Поддержку отмены процесса сканирования.

### 4.3. UI (Managers)
- Обновить `ResourceOpsMenuManager.kt`: реализовать новый унифицированный диалог.
- Для отображения результата можно использовать `MaterialAlertDialogBuilder` с кастомной View.

### 4.4. Логирование и Hygiene
- Использование `Timber` для логирования всех этапов.
- Не забыть добавить новые строки в `strings.xml`, `values-ru/strings.xml`, `values-uk/strings.xml`.

## 5. Критерии приемки
- [ ] Опция «Удаление по размеру...» видна в меню `Resource Operations`.
- [ ] Диалог позволяет выбрать КБ/МБ/ГБ и условие (><).
- [ ] Кнопка "Анализ" корректно находит файлы на SMB-ресурсе без падений.
- [ ] Кнопка "Удалить" выполняет операцию согласно системным настройкам Trash.
- [ ] Список файлов обновляется автоматически после завершения.
- [ ] Логи операции присутствуют в `Timber`.
