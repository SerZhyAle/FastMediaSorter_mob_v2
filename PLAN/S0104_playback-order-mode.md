## 1. Проблема

В командной панели плеера для аудио и видео файлов есть кнопка управления порядком воспроизведения, но она не реализована: навигация всегда работает в режиме бесконечного цикла по списку. Пользователь не может выбрать однократное воспроизведение с остановом, случайный порядок или повторение одного файла. Это делает плеер менее гибким по сравнению с любым стандартным аудиоплеером.

---

## 2. Цели

1. Кнопка в командной панели плеера циклически переключает режим при каждом нажатии; иконка мгновенно отражает активный режим.
2. Реализованы четыре режима:
   - **LOOP\_LIST** — список воспроизводится по кругу бесконечно (режим по умолчанию); иконка: круговые стрелки.
   - **PLAY\_THROUGH** — список воспроизводится от начала до конца, затем плеер останавливается; иконка: стрелка вниз по списку.
   - **SHUFFLE** — бесконечное случайное воспроизведение без повторений подряд; иконка: кубик (`ic_random_nav`).
   - **REPEAT\_ONE** — текущий файл воспроизводится повторно бесконечно; иконка: `ic_repeat_one`.
3. Режим сохраняется отдельно для аудио и для видео, восстанавливается при повторном запуске плеера.
4. В режиме SHUFFLE порядок файлов перемешивается при каждом полном проходе (новое перемешивание), чтобы не повторять только что прозвучавший трек.
5. Переключение режима отображается кратким тостом с названием нового режима.
6. Режим учитывается во всех путях навигации: кнопки Prev/Next, жесты, touchzones, авто-переход по окончании файла.

**Non-goals:**

- Режим «повторить N раз» — сложен в UX (требует диалога выбора N), откладывается на следующую итерацию.
- Интеграция с Wear OS — носимые не имеют командной панели плеера.
- Изменение поведения слайд-шоу (оно управляется отдельной логикой).
- Изменение логики случайного прыжка (dice button для Audio Library / Photo Storage profiles) — она остаётся без изменений.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Добавить 5-й режим «SHUFFLE\_ONCE» — список перемешивается однократно и воспроизводится до конца, затем стоп. Иконка: кубик + стрелка-вниз (составная, или отдельная иконка). Реализовать во второй итерации, если первые четыре режима стабильны.
2. Поддержать назначение режима на аппаратную клавишу или кнопку TV-пульта через существующую систему привязки клавиш.

### 3.2 Жёсткие ограничения

- **Flavor:** все варианты (standard, lite, photos, legacy) — плеер общий.
- **API level:** без API-специфики; только стандартные механизмы SharedPreferences.
- **Wear OS:** не затрагивается.
- **Производительность:** перемешивание списка — O(n) in-memory; допустимо даже для 10 000 файлов.
- **Совместимость данных:** новое поле в хранилище настроек; значение по умолчанию LOOP\_LIST — поведение существующих установок не меняется.
- **Локализация:** EN/RU/UK — обязательно для строк тостов и accessibility-описаний кнопки.
- **Доступность:** кнопка должна иметь динамический `contentDescription`, отражающий текущий режим; смена иконки не единственный индикатор.

---

## 4. Контекст текущей архитектуры

Навигация между файлами централизована в координаторе уровня ViewModel, который обрабатывает вызовы `nextFile()` / `previousFile()` и реализует жёстко зашитое кольцевое поведение: последний файл списка всегда переходит на первый. Состояние плеера (`PlayerState`) содержит текущий индекс и список файлов, но не содержит никакого поля режима порядка воспроизведения. Командная панель содержит кнопку (ранее служившую для включения слайд-шоу для аудио/видео), которая пока не выполняет функцию циклического переключения режимов — её поведение нужно переосмыслить или рядом добавить отдельную кнопку.

Хранение пользовательских предпочтений воспроизведения ведётся через `SharedPreferences`-обёртку (не через Room/AppSettings DTO), что делает добавление нового поля простым и не требует миграции базы данных.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**Модель режима**
- Перечисление из четырёх значений: LOOP\_LIST, PLAY\_THROUGH, SHUFFLE, REPEAT\_ONE.
- Два поля персистенции: режим для аудио и режим для видео (тип медиа определяется текущим файлом).

**Хранилище предпочтений воспроизведения**
- Существующий уровень предпочтений воспроизведения расширяется двумя ключами.
- Чтение при инициализации плеера; запись немедленно при смене режима.

**Координатор навигации**
- Читает активный режим из состояния плеера.
- LOOP\_LIST: существующее поведение (без изменений).
- PLAY\_THROUGH: `nextFile` при достижении последнего элемента выдаёт событие «стоп» вместо перехода к первому.
- SHUFFLE: хранит перемешанный индексный массив; `nextFile` движется по нему; при исчерпании — новое перемешивание с исключением последнего прозвучавшего трека из первой позиции.
- REPEAT\_ONE: `nextFile` и `previousFile` возвращают тот же индекс (перезапуск файла).

**UI — кнопка режима**
- Отдельная кнопка в командной панели для аудио/видео, первая позиция слева.
- Одиночный тап → следующий режим по кольцу → тост → обновление иконки и `contentDescription`.
- Иконки: круговые стрелки (LOOP\_LIST), стрелка вниз (PLAY\_THROUGH), кубик ic\_random\_nav (SHUFFLE), ic\_repeat\_one (REPEAT\_ONE).

**Состояние ViewModel**
- Поле `playbackOrderMode: PlaybackOrderMode` добавляется в `PlayerState`.
- При SHUFFLE дополнительно хранится перемешанный порядок индексов как вспомогательное поле состояния.

### 5.2 Потоки данных и событий

```
Нажатие кнопки → UI слой → ViewModel.cyclePlaybackOrderMode()
  → обновление PlayerState.playbackOrderMode
  → запись в SharedPreferences
  → обновление иконки + contentDescription
  → тост

Конец файла / нажатие Next → Координатор навигации
  → читает PlayerState.playbackOrderMode
  → вычисляет следующий индекс (или стоп)
  → обновляет PlayerState.currentIndex (или посылает событие Stop)
```

### 5.3 Точки расширяемости

- Режим SHUFFLE\_ONCE легко добавляется: перемешивает список однократно, затем ведёт себя как PLAY\_THROUGH по перемешанному порядку.
- Режим может быть привязан к клавише через существующую систему `PlayerCommandOverrides` без дополнительной архитектуры.

## 6. Открытые вопросы / Research items

1. **Кнопка в командной панели — существующая или новая?**
   - **Вопрос:** Существующий `btnSlideShow` для аудио/видео переиспользуется как кнопка режима, или добавляется отдельная кнопка?
   - **Варианты:** (A) Переиспользовать — меньше изменений в XML, но семантика кнопки меняется. (B) Добавить отдельную кнопку — чище, но занимает пространство панели.
   - **Нужно выяснить:** текущее поведение btnSlideShow в режиме аудио/видео; есть ли слайд-шоу смысл для этих типов медиа.
   - **Статус:** Verified

2. **SHUFFLE и аудио-сервис**
   - **Вопрос:** Фоновый аудио-сервис имеет собственный индекс воспроизведения, который синхронизируется с ViewModel. При режиме SHUFFLE нужно ли синхронизировать перемешанный порядок с сервисом?
   - **Варианты:** (A) ViewModel управляет перемешиванием и сигнализирует сервису следующий индекс. (B) Сервис сам знает о режиме SHUFFLE.
   - **Нужно выяснить:** как сейчас работает `syncAudioServiceIndex` и кто выбирает следующий трек при фоновом воспроизведении.
   - **Статус:** Verified

## 9. Архитектурные решения (ADR)

**ADR-1: Персистенция режима через SharedPreferences, не AppSettings DTO**

- **Решение:** Два ключа в существующем хранилище предпочтений воспроизведения (`playback_control_dialog` SharedPreferences или аналоге).
- **Альтернативы:** Добавить поля в `AppSettings` data class + `SettingsRepository` (потребует Room миграции при переходе на персистенцию через БД).
- **Почему:** Режим воспроизведения — сессионное предпочтение, аналогичное `KEY_SPEED` и `KEY_LAST_TAB`, которые уже хранятся в `PlaybackControlPreferences`. Room-миграция избыточна для двух строковых полей.

**ADR-2: Перемешанный порядок хранится в ViewModel, не в координаторе навигации**

- **Решение:** Массив перемешанных индексов — часть `PlayerState`, что позволяет сохранять его в `SavedStateHandle`.
- **Альтернативы:** Хранить в координаторе навигации как mutable поле — проще, но не переживёт пересоздание ViewModel.
- **Почему:** Сохранность состояния при поворотах экрана критична для непрерывного SHUFFLE-воспроизведения.

## 11. Критерии готовности (strategic-level)

1. Кнопка режима видна в командной панели для аудио и видео файлов; для прочих типов медиа — скрыта.
2. Одиночный тап по кнопке циклически меняет режим: LOOP\_LIST → PLAY\_THROUGH → SHUFFLE → REPEAT\_ONE → LOOP\_LIST.
3. Иконка кнопки мгновенно соответствует активному режиму; тост подтверждает выбор.
4. В режиме PLAY\_THROUGH плеер останавливается после последнего файла, не переходя к первому.
5. В режиме SHUFFLE файлы не повторяются подряд в одном проходе; при исчерпании список перемешивается заново.
6. В режиме REPEAT\_ONE файл перезапускается немедленно после окончания.
7. Выбранный режим восстанавливается после закрытия и повторного открытия плеера (раздельно для аудио и видео).
8. Поворот экрана не сбрасывает режим и перемешанный порядок.
9. Кнопки Prev/Next и touchzones уважают активный режим так же, как авто-переход.
10. Все строки локализованы на EN/RU/UK; `contentDescription` кнопки динамически отражает режим.
