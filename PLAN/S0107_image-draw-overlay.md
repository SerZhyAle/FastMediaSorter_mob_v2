---

## 1. Проблема

При просмотре изображений (фото, скриншоты, схемы) пользователю нередко требуется быстро нанести пометки — стрелку, прямоугольник, надпись маркером — чтобы показать коллеге или сохранить как аннотированную копию. Для этого сейчас нужно покинуть приложение, открыть сторонний редактор, сохранить, вернуться. Бесшовного пути нет.

---

## 2. Цели

1. Добавить команду **«Рисовать»** в меню плеера изображений — аналогично тому, как S0106 добавляет «Вырезать» и «Сжатую копию».
2. Предоставить минимальный набор инструментов: широкая кисть, прямоугольник, ластик.
3. Предоставить палитру из 7 фиксированных цветов: белый, чёрный, серый, красный, синий, зелёный, жёлтый.
4. По завершении рисования дать пользователю возможность **сохранить результат как новый файл** — рисунок слит с оригинальным изображением; оригинал не изменяется.
5. Функция намеренно примитивна: цель — быстрая аннотация/диаграмма, не полноценный редактор.

**Non-goals:**
- Слои, прозрачность, произвольная толщина линии, наклон линии, заливка фигур.
- Редактирование или удаление отдельных нанесённых элементов (только ластик).
- Перезапись оригинального файла рисунком.
- Работа с анимированными форматами (GIF, APNG).
- Работа с векторными форматами.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. **Инструменты:** широкая кисть (свободное рисование), прямоугольник (рисуется тянущим жестом), ластик.
2. **Цвета:** палитра из 7 цветов — белый, чёрный, серый, красный, синий, зелёный, жёлтый. Активный цвет визуально выделен.
3. **Сохранение:** отдельная кнопка «Сохранить как новый файл»; рисунок (overlay) сливается с оригинальным изображением в один растр и записывается как новый файл. Оригинал остаётся нетронутым.
4. **Расположение тулбара:** инструменты и палитра показываются в виде компактного тулбара поверх изображения; можно располагать у нижнего края экрана.
5. **Отмена:** кнопка «Отмена» / выход из режима без сохранения должна отбросить все нарисованные элементы и вернуть плеер в обычный режим.

### 3.2 Жёсткие ограничения

- **Оригинал не изменяется.** Сохранение возможно только как новый файл.
- **Сохраняемый формат:** новый файл создаётся в PNG или JPEG (по расширению оригинала); слияние — побитовое копирование overlay-растра поверх оригинала.
- **Память (OOM):** если оригинальное изображение загружено в память с понижением разрешения (downscale для отображения), сохранение должно производиться именно на том разрешении, которое доступно в памяти — без повторной полной загрузки оригинала. Аннотации рисуются в координатах экранного представления и сохраняются с тем же масштабом.
- **Только для read-only ресурсов:** команда «Рисовать» видна, результат сохраняется в локальную папку `Downloads`.
- **Ориентация:** тулбар и холст корректно работают в портретной и альбомной ориентациях. В Draw Mode ориентация экрана заморожена — войти в режим можно из любой ориентации, но повернуть устройство внутри Draw Mode нельзя.
- **Локализация:** EN/RU/UK для новых пунктов меню, кнопок тулбара, диалога сохранения.
- **API level:** 26+.

## 4. Контекст текущей архитектуры

Плеер изображений уже поддерживает ряд деструктивных операций над файлами (поворот, отражение, коррекция яркости/контрастности, цветовые фильтры) через паттерн UseCase → NetworkImageEditUseCase → запись через DataSource. Все эти команды доступны через overflow-меню плеера. S0106 вводит дополнительные команды в то же меню по тому же паттерну.

Для рисования поверх изображения требуется дополнительный «холст» (overlay view / canvas) поверх текущего ImageView плеера. Холст должен перехватывать touch-события только в режиме рисования; вне этого режима touch-события должны уходить в штатную логику плеера (зум, листание).

---

## 5. Предлагаемый подход

### 5.1 Режим рисования (Draw Mode)

При выборе команды «Рисовать» плеер переходит в Draw Mode:
- Поверх изображения появляется прозрачный холст, перехватывающий touch-события.
- Снизу (или у нижнего края) появляется тулбар с инструментами и палитрой.
- Листание между файлами блокируется на время Draw Mode.
- Ориентация экрана блокируется на время Draw Mode; поворот устройства внутри Draw Mode невозможен. По выходу из режима ориентация разблокируется.
- Выход из режима — кнопка «Отмена» (рисунок отброшен) или кнопка «Сохранить» (рисунок слит с изображением и записан в файл).

### 5.2 Инструменты рисования

- **Широкая кисть:** свободная линия по пути пальца; фиксированная толщина (примерно 8–12 dp).
- **Прямоугольник:** тянущий жест определяет два угла; рамка рисуется сразу (без заливки).
- **Ластик:** стирает ранее нарисованные пиксели overlay-холста по пути пальца.

### 5.3 Слияние и сохранение

При нажатии «Сохранить как новый файл»:
- Экранное представление оригинала (растр, уже загруженный в плеере) берётся за основу.
- Overlay-холст (растр нарисованных элементов) накладывается поверх наложением.
- Результирующее изображение кодируется в соответствующий формат (PNG/JPEG) и записывается через DataSource в тот же каталог (или в `Downloads` для read-only ресурсов).
- Показывается диалог с именем файла (по умолчанию: `<оригинальное_имя>_draw_YYMMDD_hhmm.<расширение_оригинала>`).
- После успешного сохранения плеер переключается на новый файл (если файл создан в том же ресурсе); для `Downloads`-маршрутизации — остаётся на оригинале с Toast-уведомлением о пути сохранения.

### 5.4 Интеграция в меню

Добавляется один новый пункт в overflow-меню плеера изображений — **«Рисовать»**. Видимость: только для статических форматов (JPEG, PNG, WebP); скрывается для GIF, APNG, видео.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
|------|:-----------:|-------------|-----------|
| OOM при создании второго Bitmap для слияния | Средняя | Крэш на слабых устройствах с большими фото | Ограничить разрешение overlay тем, что уже загружено для отображения; не грузить оригинал повторно |
| Некорректное перекрытие touch-событий в Draw Mode | Высокая | Рисование открывает следующий файл или теряет штрихи | Явное блокирование ViewPager/листания в Draw Mode через флаг состояния |
| Коллизия с зумом Pinch-to-zoom в режиме рисования | Средняя | Нечаянный зум вместо рисования | В Draw Mode зум отключать; выход из Draw Mode восстанавливает зум |
| Landscape холст после поворота | **Снято** | — | Draw Mode замораживает ориентацию экрана; поворот внутри режима невозможен (§6-3 resolved). |

## 9. Архитектурные решения (ADR)

**ADR-1: Overlay-холст в памяти, без повторной загрузки оригинала**
- **Решение:** Для слияния использовать экранный Bitmap плеера (уже в памяти) как основу; overlay рисуется в том же разрешении. Повторная загрузка оригинала с полным разрешением не производится.
- **Альтернативы:** Всегда загружать полный оригинал для merge (как в S0106 через регион-декодер).
- **Почему:** Функция заявлена как «максимально простая и примитивная»; качество аннотации соответствует качеству просматриваемой копии. OOM-риск неприемлем ради незначительного прироста качества аннотаций.

**ADR-2: Неизменность оригинала**
- **Решение:** Сохранение допускается только как новый файл; кнопки «перезаписать» нет.
- **Почему:** Аннотации — вспомогательный контент; пользователь никогда не должен случайно уничтожить оригинал. Упрощает логику отката и снимает риск порчи файла при ошибке записи.

**ADR-3: Шаблон имени и навигация к новому файлу**
- **Решение:** Имя по умолчанию — `<оригинальное_имя>_draw_YYMMDD_hhmm.<расширение>` (редактируемо в диалоге). После успешного сохранения в тот же ресурс плеер сразу открывает новый файл — пользователь видит результат и может его сразу отправить.
- **Почему:** Файл создаётся для последующей отправки. Переключение на него позволяет сразу инициировать «Share».

**ADR-4: Заморозка ориентации экрана в Draw Mode**
- **Решение:** При входе в Draw Mode устанавливать `requestedOrientation = SCREEN_ORIENTATION_LOCKED`; при выходе — `SCREEN_ORIENTATION_UNSPECIFIED`.
- **Альтернативы:** (a) Завершать Draw Mode при повороте с Toast; (c) Пересчитывать overlay-матрицу при config-change.
- **Почему:** Пересчёт матрицы (c) сложен и ненадёжен; завершение с потерей рисунка (a) неприемлемо для пользователя. Заморозка — минимально инвазивный вариант, не требующий обработки `onConfigurationChanged`.

## 11. Критерии готовности (strategic-level)

1. Команда «Рисовать» появляется в overflow-меню плеера для статических изображений (JPEG, PNG, WebP).
2. Активация команды переводит плеер в Draw Mode: листание файлов заблокировано, поверх изображения появляется тулбар с инструментами и палитрой.
3. Инструменты «Широкая кисть», «Прямоугольник» и «Ластик» функционируют корректно.
4. Доступны все 7 цветов палитры; активный цвет визуально выделен.
5. Кнопка «Отмена» выходит из Draw Mode без сохранения, рисунок отброшен.
6. Кнопка «Сохранить как новый файл» сохраняет слитое изображение; оригинал остаётся нетронутым.
7. Для read-only ресурсов результат сохраняется в локальную папку Downloads.
8. UI корректно работает в портретной и альбомной ориентациях.
9. Новые строки локализованы в EN/RU/UK.
