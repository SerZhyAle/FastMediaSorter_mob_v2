## 1. Проблема

На landscape-устройствах (Meta Quest 3, ряд планшетов) диалог прогресса файловой операции падает с `NullPointerException` при каждом показе. Android в landscape-ориентации inflates альтернативный layout-файл, который не содержит двух View, ожидаемых кодом диалога. Файлы копируются успешно, но индикатор прогресса не появляется совсем — нарушен UX и нарушено правило CLAUDE.md § «Layout orientation».

Ошибка подтверждена логами сессии 2026-05-04: NPE в методе инициализации диалога, повторяется трижды за сессию.

---

## 2. Цели

1. Диалог прогресса файловой операции показывается без ошибок на landscape-устройствах.
2. Все поля (процент выполнения, ETA) корректно отображаются в landscape-режиме.
3. Portrait-поведение не затронуто.
4. Устраняется нарушение инварианта «все View-ID, используемые кодом, должны присутствовать во всех layout-альтернативах».

**Non-goals:**

- Визуальный редизайн диалога прогресса.
- Изменение бизнес-логики файловых операций.
- Audit прочих диалогов на аналогичный рассинхрон (выходит за объём, но рекомендуется отдельным тикетом).

## 4. Контекст текущей архитектуры

Диалог прогресса файловой операции — самостоятельный UI-компонент (диалог), инициализирующий ссылки на дочерние View в момент создания. Android автоматически выбирает layout-ресурс по текущей конфигурации устройства: при landscape-ориентации используется альтернативный ресурс из `res/layout-land/`. Landscape-версия диалога не обновлялась синхронно с portrait-версией при добавлении двух новых View (процент и ETA), что привело к расхождению наборов View-ID.

Код диалога явно обращается к обоим отсутствующим View — при landscape-inflate они возвращают `null`, что вызывает NPE. Проблема не обнаруживается при разработке на portrait-телефоне и не покрывается существующими тестами UI.

---

## 5. Предлагаемый подход

Добавить в landscape-вариант layout диалога те же два View (прогресс в процентах и ETA), которые присутствуют в portrait-варианте, с теми же идентификаторами. Размещение адаптируется к горизонтальной компоновке: можно объединить с соседней строкой скорости в горизонтальный контейнер. Если пространство критично, View допустимо скрыть (`visibility=gone`), но ID обязаны быть в дереве разметки.

### 5.1 Основные столпы

**Синхронизация layout-альтернатив.** Portrait-layout является эталоном набора View-ID. Landscape-layout обязан содержать те же ID; визуальное расположение может отличаться под компактную высоту экрана.

### 5.2 Потоки данных и событий

Нет изменений в потоке данных. Диалог по-прежнему получает обновления прогресса от того же источника и отображает их через те же View-ссылки — теперь инициализированные корректно в обеих конфигурациях.

### 5.3 Точки расширяемости

Нет — это точечный bugfix без архитектурных изменений.
