# Спецификация: Ассоциация файлов / Приложение по умолчанию

**Версия**: 2.0 (на основе заполненного опросника, март 2026)  
**Статус**: Утверждено

---

## 1. Цель

Реализовать механизм регистрации приложения в ОС Android (API 28–37) как обработчика по умолчанию для медиаданных (Audio, Video, Images) и документов (PDF, EPUB, TXT). При открытии файла из внешнего источника запускается специализированный `StandalonePlayerActivity` без интеграции с ресурсной системой приложения.

---

## 2. Intent Filters — Регистрация в системе

### 2.1 Стратегия: 4 activity-alias

В `AndroidManifest.xml` объявляются **четыре отдельных `activity-alias`**, по одному на тип контента. Это позволяет:
- Включать / отключать обработчик каждого типа **независимо** через `PackageManager.setComponentEnabledSetting()`.
- Не трогать `MainActivity`.

Каждый alias указывает на `StandalonePlayerActivity` (см. §3).

### 2.2 Поддерживаемые расширения

Список строго соответствует фактическим константам в `MediaTypeUtils.kt` / `MediaExtensions.kt`. Спецификация **не расширяет** список — если расширение не поддерживается приложением, его нет в фильтрах.

| Тип | Расширения |
|-----|-----------|
| **Изображения** | `jpg, jpeg, png, webp, heic, heif, bmp, avif` |
| **Видео** | `mp4, mkv, avi, mov, wmv, flv, webm, m4v, 3gp, mpg, mpeg, ts, m2ts, vob, ogv, divx, m2v, mts` |
| **Аудио** | `mp3, flac, aac, ogg, m4a, wma, opus, amr, awb, ac3, ec3, ac4, adts, thd, mka, oga, caf, alac, mid, midi` |
| **Документы** | `pdf, epub, txt` |

> **Примечание**: `gif` **отсутствует** в `IMAGE_EXTENSIONS` в коде → не добавляется в фильтры.

### 2.3 URI schemes

Каждый intent filter объявляет **оба** scheme:
- `android:scheme="content"` — стандарт Android 10+.
- `android:scheme="file"` — совместимость с некоторыми файловыми менеджерами на Android 9.

MIME-тип указывается как `*/*` с ограничением `pathPattern` по расширению, либо попарно `mimeType + extension` — по наилучшей практике для данной версии Android.

### 2.4 Поддерживаемые actions

| Action | Условие активации |
|--------|--------------------|
| `ACTION_VIEW` | Всегда (если alias включён) |
| `ACTION_SEND` | Только если пользователь включил опцию **"Принимать файлы через 'Поделиться'"** в разделе Playback настроек |
| `ACTION_SEND_MULTIPLE` | То же условие |

`ACTION_SEND` / `ACTION_SEND_MULTIPLE` управляются отдельным alias-ом (или отдельным флагом) и включаются/отключаются через `PackageManager.setComponentEnabledSetting()` при изменении настройки.

## 3. Обработка входящего файла — StandalonePlayerActivity

### 3.1 Архитектурное решение

Создаётся **отдельная Activity** — `StandalonePlayerActivity`. Она **не является** продолжением ресурсной системы приложения. Никаких "Временных ресурсов", плейлистов папок, истории "Недавних" — не создаётся.

Визуально Activity наследует UI существующего плеера, но с упрощённым поведением.

### 3.2 Поведение при открытии

1. **Извлечение URI**: `Intent.ACTION_VIEW` / `ACTION_SEND` → `intent.data` (или `EXTRA_STREAM`).
2. **Определение типа**: сначала по MIME-типу из Intent, затем по расширению имени файла (через `ContentResolver.query`). Если тип не определён — показать сообщение об ошибке и закрыть Activity.
3. **Открытие файла**: передать URI напрямую в плеер (аудио/видео/изображение/документ).
4. **Экран**: Activity открывается сразу в режиме плеера/просмотрщика. **Не полноэкранный** по умолчанию — пользователь может перейти в полноэкранный сам.

### 3.3 Ограничения UX

| Элемент | Поведение |
|---------|-----------|
| Кнопки Вперёд / Назад (плейлист) | **Отсутствуют**. Нет плейлиста папки. |
| Выход в BrowseActivity | **Запрещён**. |
| Выход в MainActivity | **Запрещён**. |
| Кнопка закрытия | Находится на **том же месте**, что и стрелка "Назад" в обычном плеере (верхняя командная панель). Визуально отображается как **крестик (✕)** вместо стрелки — пользователь воспринимает её как "Закрыть". Аппаратная кнопка Back работает аналогично. Оба действия полностью закрывают приложение. |
| Операции с файлом | Доступны: переименование, копирование, отправка (Share). |

### 3.4 Конфликт: приложение уже воспроизводит

Если в момент открытия файла приложение активно воспроизводит контент — **прерываем текущее воспроизведение** и открываем StandalonePlayerActivity. Возврата к прерванному воспроизведению не происходит (пользователь закрывает standalone-плеер → приложение закрывается).

### 3.5 Разрешения

*   Если `MANAGE_EXTERNAL_STORAGE` не выдано — **запросить** перед открытием файла.
*   Если разрешение уже запрашивалось и было отклонено — показать сообщение с кнопкой перехода в управление разрешениями (раздел "Файлы и данные" в настройках приложения).
*   Для файлов на SD-карте, FTP, сети — поведение идентично: проверить разрешение → попытаться открыть → при ошибке сообщить и выйти.

## 4. Обработка аппаратных кнопок (Автомобиль / Наушники)

### 4.1 Проблема

Текущее поведение: при нажатии кнопки "Следующий трек" на руле/наушниках наша музыка ставится на паузу, а начинает играть системный плеер устройства. Это происходит из-за отсутствия должной регистрации `MediaSession` / `MediaButtonReceiver`.

### 4.2 Решение

Реализовать `MediaButtonReceiver` + корректную регистрацию `MediaSession` в `AudioPlaybackService` в соответствии со стандартными практиками медиаплееров Android (аналогично VLC, Poweramp и др.).

Поведение при нажатии hardware-кнопок (Play/Pause/Next/Prev):
- Если `AudioPlaybackService` запущен → стандартные команды управления воспроизведением.
- Если приложение было убито ОС и сохранено состояние Resume → **тихий** запуск `AudioPlaybackService` с последним файлом (без уведомлений, пользователь за рулём).

### 4.3 Связь с настройками

Данный функционал **не зависит** от настройки "Play in background".  
Управляется новой опцией в разделе **Playback** настроек приложения:  
**"Использовать как основной медиаплеер системы"** (рабочее название).

При включении этой опции:
- Регистрируется `MediaButtonReceiver`.
- Включаются alias-ы для `ACTION_VIEW` (см. §2).
- Приложение полноценно участвует в Audio Focus.

## 5. Пользовательский интерфейс

### 5.1 Welcome Screen — страница "По умолчанию"

**Позиция**: После страницы с разрешениями (или вместе с ними — зависит от того, требуется ли специальное разрешение Service для данной функции; принимается решение при реализации). Страница **не имеет кнопки "Пропустить"** — аналогично странице разрешений.

**Содержимое**:
- Текст-инструкция на текущем языке (EN / RU / UK) — объяснение, зачем нужно назначить приложение по умолчанию и что произойдёт при нажатии кнопки.
- **4 кнопки** (не тумблеры):
  - "Назначить плеером аудио по умолчанию"
  - "Назначить плеером видео по умолчанию"
  - "Назначить просмотрщиком изображений по умолчанию"
  - "Назначить приложением для документов по умолчанию"
- Каждая кнопка открывает системный экран назначения (см. §5.2).
- Пользователь может нажать часть кнопок и перейти дальше — все кнопки необязательны к нажатию.

> Тумблеры технически невозможны: Android не позволяет программно назначить приложение по умолчанию без участия системного UI.

### 5.2 Settings Screen — кнопки управления

**Расположение**: каждая кнопка — в своей секции настроек медиа.

| Тип | Фрагмент настроек |
|-----|-------------------|
| Аудио | `AudioSettingsFragment` |
| Видео | `VideoSettingsFragment` |
| Изображения | `MediaSettingsFragment` (секция изображений) |
| Документы | Секция документов в `MediaSettingsFragment` |

**Состояния кнопки**:
- `"Назначить плеером аудио по умолчанию"` — не установлено.
- `"✓ Назначено плеером аудио по умолчанию"` — установлено (read-only вид).

Статус проверяется при каждом открытии экрана Settings через `RoleManager.isRoleHeld()` (API 29+) или `PackageManager` (API 28).

**Поведение по нажатию**:
1. Показать диалог-инструкцию (версия-специфичный текст, 3 языка) — объясняет куда нажать в системном экране.
2. Открыть системный экран:
   - **API 29+ (Android 10+)**: `RoleManager.createRequestRoleIntent(ROLE_MUSIC / ROLE_MEDIA_APP)` если доступен у производителя; иначе `ACTION_MANAGE_DEFAULT_APPS_SETTINGS`.
   - **API 28 (Android 9)**: `ACTION_APPLICATION_DETAILS_SETTINGS` с `package:` URI.
3. По возвращении — перепроверить статус и обновить кнопку.

> Реализация должна быть идентична подходу популярных медиаплееров и браузеров (VLC, Firefox и аналогов).

### 5.3 Новая опция в Playback Settings

Добавить в раздел **Playback** новый toggle:  
**"Принимать файлы через 'Поделиться' (ACTION_SEND)"**  
При включении — активирует alias-ы для `ACTION_SEND` / `ACTION_SEND_MULTIPLE`.

## 6. Флаворы (Flavors)

Неподдерживаемые типы **не компилируются** в сборку — ни в выключенном, ни в каком-либо другом состоянии. Нет runtime-отключения через `PackageManager`.

| Флавор | Intent filters | Кнопки в Settings |
|--------|---------------|-------------------|
| `standard` | Все 4 типа | Все 4 кнопки |
| `lite` | Только Images | Только кнопка Images |
| `photos` | Только Images | Только кнопка Images |
| `legacy` | Audio, Video, Images | 3 кнопки (без Docs) |

Реализуется через `BuildConfig`-флаги и flavor-specific `AndroidManifest.xml` (или `manifestPlaceholders`).

## 7. Технические детали и ограничения

### 7.1 Версии Android
- Минимум: **Android 9 (API 28)**.
- Максимум тестирование: Android 17 (API 37).
- API-специфичный код оборачивается в `Build.VERSION.SDK_INT` проверки.

### 7.2 Определение типа файла
Порядок приоритета:
1. MIME-тип из `Intent`.
2. Расширение имени файла (через `ContentResolver.query(uri, DISPLAY_NAME)`).
3. Если тип не определён — показать `Toast`/диалог об ошибке → закрыть Activity.

### 7.3 Разрешения (добавляются в ManifestPermissions)
Возможные дополнительные разрешения (уточнить при реализации):
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK` (API 34+) — для `AudioPlaybackService`.
- `MEDIA_CONTENT_CONTROL` — если требуется для `MediaButtonReceiver` на ряде устройств.

### 7.4 Локализация
Все новые строки (диалоги-инструкции, названия кнопок, тексты Welcome-страницы) реализуются в трёх языках: **EN, RU, UK**.

## 8. Фазы реализации

Каждая фаза должна давать **компилируемую** сборку. Разработка ведётся по правилам репозитория (`dev/AGENT_WORKFLOW.md`): прогресс в чеклисте, логирование в `dev/CHANGELOG.md` через `add_to_dev_log.ps1`, бэкап перед правкой файлов > 500 строк.

| Фаза | Содержание |
|------|-----------|
| **1** | `StandalonePlayerActivity` (базовый UI, открытие через `ACTION_VIEW`, закрытие крестиком) |
| **2** | Intent filters в Manifest (4 alias-а, content:// + file://, все расширения) |
| **3** | Settings: кнопки по умолчанию (4 типа, диалог-инструкция, системный экран, статус-индикатор) |
| **4** | Welcome Screen: страница назначения по умолчанию (4 кнопки, инструкция, не пропускаемая) |
| **5** | `MediaButtonReceiver` + `MediaSession` (корректная обработка hardware-кнопок, новая опция в Playback) |
| **6** | `ACTION_SEND` / `ACTION_SEND_MULTIPLE` + опция в Playback Settings |
| **7** | Flavor-специфичные Manifest и исключение кода (lite, photos, legacy) |
