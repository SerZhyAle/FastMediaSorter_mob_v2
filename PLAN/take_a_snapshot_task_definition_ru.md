# Постановка задачи: сохранение текущего кадра из видео

## Контекст

Есть черновая идея фичи: пользователь хочет сохранять текущий кадр из видео не просто в локальный Downloads, а в заранее выбранный ресурс-получатель. Эта возможность должна настраиваться в разделе видео-настроек и вызываться из самого видеоплеера.

## Уточнённая постановка

Нужно спроектировать и затем реализовать пользовательскую функцию сохранения кадра из видеоплеера с двумя связанными точками входа:

1. Настройка в Настройки → Медиа → Видео:
   - новое поле «Ресурс для сохранения кадров»;
   - выбор только из destination-ресурсов;
   - виртуальные ресурсы исключаются;
   - значение может быть очищено.

2. Команда в видеоплеере:
   - только для MediaType.VIDEO;
   - доступна в верхнем меню в portrait и landscape;
   - имеет низкий приоритет показа;
   - по нажатию сохраняет кадр из текущей позиции.

## Ожидаемое поведение

- Если выбранный ресурс валиден и доступен для записи, кадр сохраняется туда.
- Если ресурс не выбран или запись туда невозможна, выполняется fallback в локальный Downloads.
- Пользователь всегда видит, куда именно сохранён кадр.

## Принятые допущения

- Для первой версии формат сохраняемого кадра: PNG.
- Для первой версии допустим nearest available frame around current playback position, а не строгий GPU-exact surface snapshot.
- Команда может жить в overflow верхнего меню, если это лучше сохраняет приоритеты существующих действий.

## Ключевые ограничения по текущей кодовой базе

- Settings уже хранят похожие resourceId-поля, значит новое поле нужно вести тем же путём.
- Destination filtering уже существует в GetDestinationsUseCase и исключает virtual/read-only.
- Текущий generic ResourcePickerDialog показывает все ресурсы, поэтому его надо ограничить или расширить фильтром.
- Local video frame extraction уже частично поддержана.
- Для remote video прямой MediaMetadataRetriever по path ненадёжен, значит требуется отдельный путь через temp/cache/network frame extraction.

## Критерий готовности спецификации

Спецификация считается достаточной для перехода к design/implementation, если в ней зафиксированы:

- пользовательский сценарий;
- точные functional requirements;
- правила fallback;
- ограничения по local/remote видео;
- интеграционные точки в settings/player/file-transfer;
- acceptance criteria.
