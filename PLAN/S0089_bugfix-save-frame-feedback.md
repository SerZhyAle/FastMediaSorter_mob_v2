---

## 1. Проблема

Кнопка «Снять кадр» в видеоплеере не показывает никакой реакции при нажатии: ни подтверждения успешного сохранения, ни сообщения об ошибке. Операция фактически выполняется корректно, однако Snackbar, привязанный к корневому view полноэкранного плеера, отображается ниже поверхности видео и за пределами видимых insets — пользователь видит «ноль реакции». Это создаёт ощущение сломанной функции и вызывает повторные нажатия.

---

## 2. Цели

1. После успешного сохранения кадра пользователь видит текстовое уведомление с указанием места сохранения.
2. При невозможности захвата кадра (видео не воспроизводится, нехватка памяти) пользователь видит понятное сообщение об ошибке.
3. Механизм уведомления гарантированно отображается поверх видеопотока в полноэкранном режиме без привязки к иерархии view плеера.
4. Поведение одинаково в портретной и ландшафтной ориентации.

**Non-goals:**

- Изменение логики захвата кадра (TextureView.getBitmap()) — механизм работает корректно.
- Добавление action-кнопки «Открыть» в уведомление — отдельный запрос.
- Изменение логики записи файла или выбора папки назначения.
- Изменение поведения VR-варианта (VrStereoSnapshotManager) — уже использует Toast.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. В сообщении об успехе желательно показывать имя папки/ресурса назначения (уже есть в строках локализации).
2. Унифицировать механизм с VR-вариантом (там используется Toast) — единый подход во всём плеере.

### 3.2 Жёсткие ограничения

- **Flavor:** all (standard, lite, photos, legacy) — функция не закрыта BuildConfig-флагами.
- **API level:** minSdk 26; Toast.makeText() доступен с API 1 — ограничений нет.
- **Wear OS:** не затрагивается.
- **Производительность:** уведомление вызывается на главном потоке в конце корутины — бюджет не критичен.
- **Совместимость данных:** нет изменений в БД или SharedPreferences.
- **Локализация:** EN/RU/UK — обязательно. Строки `save_frame_*` уже присутствуют в трёх локалях; новые строки не требуются.
- **Доступность:** Toast читается TalkBack автоматически.

## 4. Контекст текущей архитектуры

Захват кадра и сохранение файла выполняются в отдельном менеджере (слой помощников плеера), который после завершения операции вызывает Snackbar с привязкой к корневому view активности плеера. Плеер работает в полноэкранном edge-to-edge режиме: корневой view частично перекрывается видеопотоком, а системные insets (навигация, статусная строка) могут равняться нулю при погружении в полный экран. В этих условиях Snackbar рендерится в невидимой области — либо за пределами экрана, либо под поверхностью видео, — и пользователь не получает никакой визуальной обратной связи.

VR-ветвь того же плеера идентичную ситуацию решила через `Toast.makeText()`, который отображается в отдельном системном окне поверх любого контента независимо от иерархии view.

---

## 5. Предлагаемый подход

Заменить вызов Snackbar в менеджере захвата кадра на `Toast.makeText()`. Toast отображается в системном оверлее независимо от иерархии view плеера и insets — это гарантирует видимость в любом режиме отображения.

### 5.1 Основные столпы

**Замена механизма уведомления**

Единственный приватный метод показа уведомления в менеджере захвата кадра переключается с Snackbar на Toast. Метод вызывается в четырёх точках: успешное сохранение в ресурс, успешное сохранение в Downloads, ошибка захвата (нет видео), прочие ошибки/OOM.

**Длительность Toast**

- Успех → `LENGTH_SHORT` (соответствует VR-ветви и общей конвенции Android).
- Ошибка → `LENGTH_LONG` (больше времени прочитать сообщение).

### 5.2 Потоки данных и событий

```
Нажатие кнопки (UI)
  → Обработчик команд плеера
      → Менеджер захвата кадра
          → захват кадра с поверхности видео
          → если неудача → Toast (ошибка)
          → запись временного файла (IO)
          → копирование в ресурс / Downloads (IO)
          → Toast (успех или ошибка)
```

### 5.3 Точки расширяемости

Метод показа уведомления инкапсулирован в менеджере — в будущем может быть расширен до Snackbar с action-кнопкой без изменения вызывающего кода, если будет нужна кнопка «Открыть файл».

## 9. Архитектурные решения (ADR)

**ADR-1: Toast вместо Snackbar для уведомлений в полноэкранном плеере**

- **Решение:** Использовать `Toast.makeText()` для всех уведомлений менеджера захвата кадра.
- **Альтернативы:** (a) Snackbar с явным anchor на элемент топ-команд-панели; (b) кастомный оверлей view поверх видео; (c) OverlayManager плеера (если существует).
- **Почему:** Toast — наименее инвазивное изменение, не зависит от иерархии view и insets, уже используется в VR-ветви того же менеджера. Альтернативы (a) требуют стабильной ссылки на якорный view, которая недоступна при погружении; (b) и (c) избыточны для простого текстового уведомления.

## 11. Критерии готовности (strategic-level)

1. Нажатие кнопки «Снять кадр» на видео показывает Toast с именем ресурса или «Downloads».
2. Нажатие «Снять кадр» при отсутствии видео показывает Toast с сообщением об ошибке.
3. Toast виден в портретной и ландшафтной ориентации.
4. Toast виден в полноэкранном режиме (insets = 0).
5. Lint-предупреждений не появляется.
