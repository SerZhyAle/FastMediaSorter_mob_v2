## 1. Контекст и мотивация

Спецификация S0034 («resource-icons-system») внедрила систему пользовательских иконок
для ресурсов: реестр 60 векторных drawable, составной значок с бейджем типа соединения,
экран выбора иконки. После завершения S0034 и первой опытной эксплуатации накопился ряд
визуальных недостатков, которые снижают информативность и эстетику главного экрана.

Настоящая спецификация закрывает пять конкретных проблем без изменения архитектуры
системы иконок. Все задачи независимы и могут реализовываться параллельно.

## 2. Проблемы и цели

### П1 — Иконка видеоресурсов по умолчанию (ico-02-001)

Текущая первая иконка набора «Video» (ico-02-001) не ассоциируется с видеоматериалами.
**Цель:** перерисовать ico-02-001 в стиле исторической видеокамеры (кинокамера /
ретро-камкордер), сохранив общий графический стиль остальных иконок набора.

Затронутые сценарии: виртуальный ресурс «Все видео» (фиксированно ссылается на ico-02-001),
любой ресурс с профилем `VIDEO_LIBRARY` без явно выбранной иконки.

### П2 — «Прочие» ресурсы получают одну и ту же первую иконку (ico-05-001)

При создании нового ресурса с профилем `NONE` / `ALL_FILES` (или при первой инсталляции)
всем таким ресурсам присваивается ico-05-001 — «шарик», одинаковый для всех. Набор
«Other/Abstract» содержит 20 различных иконок (ico-05-001..ico-05-020), из которых
пользователь видит только первую.

**Цель:** при создании нового ресурса и при backfill-миграции для ресурсов набора OTHER
назначать **случайную** иконку из 20 доступных, а не фиксированную ico-05-001.

Ограничение: уже существующие устройства, где backfill уже отработал и ico-05-001
сохранена в БД, трогать не нужно — механизм backfill пропускает ресурсы с непустым
`iconId`.

### П3 — Иконка SMB визуально неузнаваема

Текущий drawable `ic_resource_smb` воспринимается как «непонятная форма» при малом
размере. SMB — это протокол доступа к сетевым папкам Windows. Иконка должна быть легко
читаемой и отличаться от FTP/SFTP-иконок.

**Цель:** заменить `ic_resource_smb` на более узнаваемый образ
(например: стилизованная сетевая папка / три соединённых узла / значок
«общий диск»). Дизайн согласовать с пользователем до реализации.

### П4 — Бейджи типа соединения слишком малы (18dp → 27dp)

Составной значок ресурса — 48dp; бейдж типа соединения (SMB/FTP/SFTP/Cloud) — 18dp
(37,5% от общего размера). При отображении в списке на высокоплотных экранах бейдж
еле различим. Коэффициент увеличения ×1.5 поднимает бейдж до 27dp.

**Цель:** увеличить `resource_icon_badge_size` с 18dp до 27dp; пересмотреть отступы
в `ResourceIconComposer` так, чтобы бейдж по-прежнему располагался в углу и не перекрывал
центральный силуэт основной иконки.

### П5 — Кнопка иконки в заголовке редактора ресурса визуально не читается

В тулбаре редактора ресурса (`toolbar_icon_action.xml`) кнопка смены иконки (`btnPickIcon`)
отрисовывается через `app:tint="?attr/colorOnPrimary"` без подложки — иконка сливается
с фоном тулбара и не воспринимается как интерактивный элемент. Пользователь не понимает,
что её можно нажать.

**Цель:** оформить кнопку так, чтобы она визуально выделялась (тёмная подложка /
кнопочный стиль), однозначно сигнализировала о возможности нажатия и соответствовала
стандарту «trigger row» проекта.

## 4. Текущая архитектура (AS-IS)

### Система иконок (S0034)

Ресурс хранит `iconId: String?` вида `ico-XX-NNN` (в `ResourceEntity`, `MediaResource`).
При значении `null` — legacy-ресурс без иконки.

**Резолюция иконки** (`ResourceIconComposer.resolveThemeDrawable`):
1. `resource.iconId` → `ResourceIconRegistry.resolveDrawable(iconId)` — пользовательский выбор.
2. `ResourceIconDefaults.setForResource(profile, type)` → `firstIdFor(set)` — первая иконка
   набора по умолчанию (именно здесь ico-02-001 / ico-05-001).
3. Устаревший fallback (`legacyIconFor`) — оставлен на период миграции.

**Назначение иконки при создании** (`ResolveResourceIconUseCase`):
- Virtual paths → фиксированный id (ico-01-001, ico-02-001, etc.).
- Profile-based: `VIDEO_LIBRARY → ico-02-001`, `NONE/ALL_FILES → ico-05-001` (всегда первая).

**Backfill** (`ResourceRepositoryImpl.backfillMissingIcons` ← `MainViewModel`):
- Вызывается при старте, перебирает ресурсы с `iconId == null`.
- Вызывает `resolveResourceIconUseCase` — тот же путь: OTHER → всегда ico-05-001.

**Бейдж** (`ConnectionBadgeMapper` → `ResourceIconComposer`):
- SMB → `R.drawable.ic_resource_smb`.
- Badge накладывается в правый нижний угол как `LayerDrawable`.
- Размеры из dimens: composite=48dp, badge=18dp; inset = totalPx − badgePx.

**Кнопка иконки в тулбаре** (`toolbar_icon_action.xml`):
- `ImageButton` 40×40dp, padding 8dp, tint=`?attr/colorOnPrimary`, background=прозрачный.

## 5. Предлагаемое решение (WHAT, без кода)

### П1 — Новая иконка видеокамеры
Перерисовать векторный drawable ico-02-001 в стиле ретро-видеокамеры (кинокамера /
камкордер), соблюдая общий стиль монохромных flat-иконок набора. Замена файла не требует
изменений кода — все ссылки идут через `ResourceIconRegistry`.

### П2 — Случайная иконка для набора OTHER
Изменить `ResolveResourceIconUseCase`: для набора OTHER при создании нового ресурса
(не виртуальный путь) возвращать `randomIdFor(ResourceIconSet.OTHER)` вместо `firstIdFor`.

Аналогично исправить `AddResourceActivity`: начальное превью кнопки тоже должно
показывать случайную иконку из набора OTHER.

Backfill в `ResourceRepositoryImpl` получает исправление автоматически — он вызывает
тот же `ResolveResourceIconUseCase`.

Ресурсы с уже назначенным `iconId` не затрагиваются: `backfillMissingIcons` пропускает
строки, где `iconId IS NOT NULL`.

### П3 — Новая иконка SMB
Разработать новый drawable `ic_resource_smb` — узнаваемый образ сетевой папки /
Windows Share. Предложения:
- **Вариант A** — иконка «папка с сетевым значком» (folder + маленький wi-fi/LAN символ).
- **Вариант B** — три квадрата, соединённые линиями (топология сети).
- **Вариант C** — силуэт «общего диска» (Windows-стиль).

> ⚠️ Решение по варианту требует согласования с пользователем до реализации.

### П4 — Увеличение размера бейджа
Изменить `resource_icon_badge_size` с 18dp до 27dp. Пересчитать inset в `ResourceIconComposer`
(inset = totalPx − badgePx), чтобы бейдж по-прежнему прилегал к правому нижнему углу
составного значка. При необходимости скорректировать `resource_icon_composite_size`
(48dp → 54dp), чтобы сохранить баланс пропорций.

### П5 — Видимая кнопка иконки
Добавить тёмную подложку на `btnPickIcon` (например, `android:background="@drawable/bg_icon_button_dark"`
или атрибут `?attr/selectableItemBackground` с явным цветовым фоном). Как минимум —
оформить кнопку как MaterialButton с иконкой и `style="@style/Widget.Material3.Button.IconButton"`
с явным фоном, чтобы визуально отличить от декоративного элемента.

## 6. Ограничения и зависимости

- Все пять подзадач **независимы** — реализуются в любом порядке.
- П1 и П3 требуют только замены drawable — без изменений кода.
- П3 — перед реализацией необходимо согласовать вариант дизайна.
- П4 — визуальное тестирование на разных плотностях экрана (mdpi / xhdpi / xxhdpi).
- П5 — соответствие «UI Trigger Row» стандарту проекта (см. `docs/ARCHITECTURE.md`).
- Текущие устройства с уже backfill-заполненным `iconId = ico-05-001` **не трогаем** (П2).

| Случайная иконка при backfill изменит вид уже «устроенных» ресурсов | Нет — backfill пропускает `iconId IS NOT NULL` | — |

- [ ] **П5**: кнопка смены иконки в редакторе ресурса визуально выделена, имеет тёмный фон,
