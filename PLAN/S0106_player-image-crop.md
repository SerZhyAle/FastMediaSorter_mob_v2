## 1. Проблема

В текущей реализации просмотра изображений отсутствует базовый функционал кадрирования (crop) и сжатия. Чтобы вырезать часть фотографии (особенно крупного изображения, находящегося на удалённом сервере), пользователю приходится скачивать файл на устройство, открывать сторонний редактор, обрезать, а затем загружать обратно. Это нарушает бесшовный опыт работы с медиафайлами, особенно при просмотре сетевых ресурсов (SMB, SFTP, облака).

---

## 2. Цели

1. Добавить команду **«Вырезать» (Crop)**: позволяет выбрать прямоугольную область на изображении прямо в плеере и перезаписать исходный файл обрезанным фрагментом.
2. Добавить команду **«Вырезать в файл» (Crop to file)**: позволяет сохранить обрезанный фрагмент как новый файл (с запросом имени), оставляя исходник нетронутым.
3. Добавить команду **«Сжатая копия» (Compressed copy)**: создание нового файла в формате JPG с качеством 70% и разрешением по большей стороне не более 1024x768 (сохраняя исходные пропорции). При выборе команды появляется диалог с именем файла.
4. Кадрирование должно выполняться **на основе оригинального разрешения файла**, а не на основе уменьшенной копии, загруженной для предпросмотра (демонстрации) на экране мобильного устройства.
5. Минимизировать сетевой трафик: если изображение небольшое и уже загружено в память целиком, повторная загрузка для обрезки не производится.

**Non-goals:**
- Полноценный фоторедактор (фильтры, цветокоррекция, поворот по произвольному углу, кисти).
- Кадрирование видеофайлов.
- Изменение формата (конвертация PNG -> JPEG и т.д., формат наследуется от исходника).

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. **UX команд**: Новые команды («Вырезать», «Вырезать в файл», «Сжатая копия») имеют низкий приоритет для показа в главном тулбаре и должны по умолчанию уходить в ниспадающее меню (overflow menu).
2. **Оригинальное качество**: Если мы рассматриваем по сети большую фотографию и применяем функцию, редактировать нужно именно оригинальное изображение (скачав его в фоне, если нужно), а затем перезаписать старое.
3. **Именование**: Для «Вырезать в файл» по умолчанию предлагать имя файла, сформированное по текущей дате-времени.
4. **Read-only ресурсы**:
   - Команда «Вырезать» (перезапись) **не видна** для ресурсов "только для чтения".
   - Команды «Вырезать в файл» и «Сжатая копия» **видны** для ресурсов "только для чтения", но результат автоматически сохраняется в локальную папку `Downloads`, а не в исходный каталог.
5. **Иконки**: Требуется разработать три новые иконки для добавленных команд, стилистически соответствующие уже принятому дизайну приложения.

### 3.2 Жёсткие ограничения

- **Память (OOM)**: Работа с оригинальными разрешениями крупных изображений (особенно свыше 10-20 МП) на слабых устройствах может вызвать нехватку памяти (OOM). Необходим механизм потокового кадрирования (регион-декодер) или строгий лимит, предотвращающий загрузку полного растрового изображения в память.
- **Поддерживаемые форматы**: Операции применимы только к стандартным растровым форматам, поддерживаемым Android (JPEG, PNG, WebP).
- **Локализация**: EN/RU/UK — для новых пунктов меню, диалогов и Toast-уведомлений.
- **Ориентация экрана**: UI кадрирования (оверлей с рамкой, маркеры, кнопки управления и диалоги сохранения) обязан корректно работать и иметь отдельные верстки/поведения для портретной (portrait) и альбомной (landscape) ориентаций (согласно правилу `LAYOUT_ORIENTATION`).
- **API level**: API 26+ (минимальная версия проекта).

## 4. Контекст текущей архитектуры

В данный момент плеер изображений загружает даунскейленную версию картинки для отображения на экране с использованием библиотеки (например, Glide или аналогичной), оптимизируя расход памяти. Оригинальный файл остаётся на источнике. Для модификации исходного файла потребуется механизм, который сможет запросить `InputStream` оригинального файла, применить к нему координаты обрезки (пересчитанные с экранных в оригинальные) и записать результат либо поверх оригинала, либо в новый файл.

## 5. Предлагаемый подход

### 5.1 Основные столпы / модули

**А. UI выделения (Crop Overlay)**

При вызове команды «Вырезать» или «Вырезать в файл» плеер переходит в режим кадрирования:
- Появляется наложение (Overlay) с прямоугольной рамкой, которую можно масштабировать и перемещать.
- Поверх изображения отображаются маркеры (углы/стороны) для изменения границ.
- Внизу (или вверху) появляются кнопки подтверждения (Apply/Save) и отмены (Cancel).

**Б. Пересчёт координат**

Рамка кадрирования на экране работает в координатах View. Перед фактической обрезкой эти координаты должны быть пропорционально пересчитаны в координаты оригинального изображения (исходя из соотношения ширины/высоты View и оригинального `ImageWidth`/`ImageHeight` из метаданных).

**В. Обработка файла (Умная загрузка)**

При подтверждении обрезки:
1. Проверяется размер изображения. Если оно маленькое и уже загружено целиком без потери качества (например, ширина < 2000px), используется кэшированная копия.
2. Если изображение большое (и особенно если оно на сетевом ресурсе):
   - Применяется регион-декодер, которому передаётся входной поток исходного файла (через провайдер/датасорс проекта). Это позволяет вырезать нужный фрагмент без загрузки всего 50-мегапиксельного изображения в память.
   - Вырезанный фрагмент сжимается с исходными параметрами качества.

**Г. Маршрутизация сохранения**

- **«Вырезать»**: Исходный файл удаляется/перезаписывается новым. Требует наличия прав на запись.
- **«Вырезать в файл» / «Сжатая копия»**:
  - В обоих случаях пользователю показывается диалог ввода имени (по умолчанию: `{исходное_имя}_crop_YYMMDD_HHmm.{исходное_расширение}` / `{исходное_имя}_shrink_YYMMDD_HHmm.{исходное_расширение}`).
  - Если ресурс доступен для записи: сохраняется в тот же каталог (исходный); плеер автоматически переключается на просмотр нового файла.
  - Если ресурс только для чтения: сохраняется локально в `Downloads`, плеер остаётся на оригинале и показывает Toast «Файл N создан». Диалог также показывается, но с явным указанием, что результат будет помещён в загрузки.

**Д. Интеграция в меню**

Добавление 3 новых пунктов в overflow-меню плеера для изображений. Логика видимости пунктов зависит от типа ресурса (только для чтения / доступен для записи) и типа файла (только статические изображения, исключая GIF/видео).

### 5.2 Потоки данных и событий

Пример: «Вырезать в файл».

- Пользователь открывает фото и выбирает «Вырезать в файл».
- Плеер переходит в режим кадрирования: поверх изображения отображается рамка выделения.
- Пользователь настраивает рамку и подтверждает выбор.
- Координаты рамки (в пространстве экрана) пересчитываются в координаты оригинального изображения.
- Появляется диалог ввода имени файла (по умолчанию: имя на основе текущей даты и времени).
- Пользователь подтверждает имя. Приложение открывает поток к исходному файлу (сетевой или локальный).
- Регион-декодер читает только нужный фрагмент без загрузки всего файла в память.
- Результат записывается в выходной поток нового файла.
- При успехе плеер перезагружает список файлов и переключается на просмотр нового файла (если ресурс доступен на запись; иначе — остаётся на оригинале и показывает Toast).

## 9. Архитектурные решения (ADR)

**ADR-1: Регион-декодирование для обработки оригиналов**
- **Решение:** Для кадрирования не загружать весь файл: передавать входной поток исходного файла в регион-декодер и декодировать только запрошенный фрагмент.
- **Альтернативы:** Полная загрузка изображения в память через библиотеку-загрузчик с последующим кадрированием в памяти.
- **Почему:** Альтернатива приведёт к OOM на 90% устройств при работе с качественными снимками с современных камер.

**ADR-2: Атомарная перезапись при команде "Вырезать"**
- **Решение:** Для сетевых ресурсов сначала сохранять обрезанный файл в кэш-директорию приложения, затем выполнять копирование с перезаписью поверх оригинала.
- **Почему:** Избежание частичной записи и потери исходной фотографии при обрыве SFTP/SMB соединения.

## 11. Критерии готовности (strategic-level)

1. Команды "Вырезать", "Вырезать в файл" и "Сжатая копия" добавлены в overflow-меню плеера изображений.
2. Для read-only папок команда "Вырезать" скрыта. Команда "Вырезать в файл" сохраняет результат в локальную папку Downloads.
3. Инструмент кадрирования позволяет пользователю визуально выделить часть изображения.
4. Кадрирование производится на оригинальном разрешении файла (сохраняется качество).
5. Имя по умолчанию для "Вырезать в файл" генерируется на основе текущей даты/времени.
6. Перезапись ("Вырезать") безопасна и не повреждает файл при обрыве сети.
7. "Сжатая копия" корректно ограничивает разрешение (не больше 1024x768 с сохранением пропорций) и сохраняет в JPG с качеством 70%.

## Bug Report — 2026-05-08

**Severity:** Critical — feature non-functional.
**Triggered by:** tapping "Вырезать в файл" (CROP_TO_FILE) in overflow menu on any image.
**Device log:** `logs/current.log`, lines 2892–2900.

### Symptoms

- После входа в crop-режим оригинальное изображение исчезает с экрана (заменяется чёрной областью).
- Оверлей с маркерами кадрирования появляется, но рамка размещена поверх пустого пространства.
- Панели команд (кнопки копирования/перемещения) остаются видимы в верхней части экрана — визуально всё «съехало».

### Корневая причина (из лога)

До вызова `enterCropMode`:
```
GESTURE_DEBUG: Display rect: RectF(0.0, 191.33331, 720.0, 596.6666)
```
Изображение корректно отображается в PhotoView (720×405 пикселей, вертикально центрировано).

После `ImageCropManager: S0106: enterCropMode mode=CROP_TO_FILE`:
```
GESTURE_DEBUG: Display rect: RectF(360.0, 0.0, 360.0, 0.0)
```
PhotoView схлопывается до вырожденного прямоугольника с нулевыми шириной и высотой (точка в координатах 360, 0). Изображение становится невидимым.

Точка (360, 0) — ровно центр по горизонтали, y=0 — указывает на то, что `enterCropMode` сбрасывает layout-ограничения или скрывает/пересоздаёт PhotoView, после чего он проходит measure с нулевыми размерами. Crop-оверлей при этом всё равно отрисовывается.

### Воспроизведение

1. Открыть любое изображение в плеере (SMB или локальное).
2. Открыть overflow-меню → «Вырезать в файл» (или «Вырезать»).
3. Изображение исчезает; виден только crop-оверлей поверх чёрного фона.

### Что исследовать

- `ImageCropManager.enterCropMode()`: найти место, где изменяются visibility/constraints PhotoView или его контейнера.
- Проверить, не вызывается ли `imageView.visibility = GONE` или `photoView.visibility = GONE` вместо/вместе с показом crop-оверлея.
- Проверить порядок вызовов layout-invalidation: если PhotoView сначала detach-ится, а затем attach-ится обратно — он может пройти measure с wrap_content = 0 до того, как изображение снова прикреплено.
- Display rect `(360, 0, 360, 0)` — ненулевой x при нулевом размере указывает, что view существует в иерархии, но имеет нулевые измеренные размеры.
