## 1. Проблема

Приложение декларирует поддержку устройств без тачскрина (S0075) и уже обрабатывает большинство клавиш TV-пультов: DPAD, медиакнопки, цветные кнопки, BACK. Однако пользователь не может переназначить клавиши TV-пультов через интерфейс переназначения, поскольку они отсутствуют в списке доступных триггеров. Кроме того, навигация фокусом по экрану полностью делегирована системе Android без явных правил обхода — на сетках с большим количеством элементов и в диалогах возможны «ловушки фокуса», из которых невозможно выйти пультом. Дополнительно отсутствует декларация `android.software.leanback` в манифесте, что ограничивает видимость приложения на части Android TV-приставок в Google Play.

---

## 2. Цели

1. Клавиши TV-пультов (цветные кнопки, CHANNEL_UP/DOWN, медиакнопки) доступны для переназначения в разделе настроек наравне с клавишами клавиатуры.
2. Навигация фокусом по основным экранам (браузер файлов, плеер, диалоги) не содержит ловушек: пользователь всегда может добраться до любого активного элемента управления и покинуть любой экран с помощью пульта.
3. Добавлена декларация `android.software.leanback required="false"`, что расширяет охват в Google Play на Android TV-приставках без перехода в TV-режим.
4. Длинные списки в браузере допускают ускоренную прокрутку с зажатым DPAD (или по нескольку элементов за шаг), чтобы не перебирать сотни файлов пошагово.

**Non-goals:**

- Полноценный Android TV / Google TV UI: leanback-компоненты, D-pad-only UX, TV Recommendations API — отдельная задача.
- Интеграция с голосовым поиском TV-пультов.
- Поддержка ChromeOS как первоклассного форм-фактора.
- Любые изменения в VR-флавёре или VR-контроллерах.
- Адаптация layout'ов под телевизионный экран (крупный шрифт, 10-foot UI).

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Цветные кнопки пульта (RED/GREEN/YELLOW/BLUE) должны оставаться функциональными даже без явного переназначения — текущее поведение (Delete/Copy/Move/Rename) является разумным дефолтом.
2. Ускоренная прокрутка не должна менять визуальное поведение на телефонах и планшетах.
3. Аудит ловушек фокуса проводится на основных поверхностях (браузер, плеер, диалог добавления ресурса, настройки) — полный обход всех экранов не требуется в первой итерации.

### 3.2 Жёсткие ограничения

- **Flavor:** standard, lite, photos, legacy — все четыре; VR-флавёр вне scope.
- **API level:** minSdk 26 (standard/lite/photos), 23 (legacy) — не меняется.
- **Wear OS:** не затрагивается.
- **Производительность:** ускоренная прокрутка не должна вызывать лишних запросов к сети или превентивной загрузки миниатюр.
- **Совместимость данных:** не затрагивается (изменения в UI и манифесте, схема БД неизменна).
- **Локализация:** EN/RU/UK — названия новых клавиш в UI переназначения должны быть локализованы во всех трёх языках.
- **Доступность:** изменения фокусной навигации не должны ухудшать поведение TalkBack.

## 4. Контекст текущей архитектуры

Обработка ввода в приложении разделена на несколько слоёв: системные события клавиш перехватываются на уровне активностей и маршрутизируются через специализированные обработчики ввода. Слой переназначения хранит пользовательские привязки в базе данных и предоставляет UI-экран для их редактирования. Управление фокусом реализовано через отдельный компонент с поддержкой сеточной навигации, однако для нестандартных раскладок экранов полагается на стандартный механизм поиска фокуса Android, который не знает о границах секций и не имеет явных правил перехода в крайних ячейках.

Текущий список доступных для переназначения триггеров сформирован исторически под клавиатуру и геймпад; TV-специфичные коды клавиш в него не включены. Манифест не содержит `android.software.leanback`, что может препятствовать индексации приложения в Play Store на некоторых TV-устройствах.

---

## 5. Предлагаемый подход

Все изменения — эволюционные дополнения к существующей инфраструктуре, без замены архитектурных слоёв.

### 5.1 Основные столпы

**Столп A — Расширение списка доступных триггеров для переназначения.**
TV-специфичные клавиши (цветные кнопки, CHANNEL_UP/DOWN, медиакнопки) добавляются в реестр известных триггеров наравне с существующими клавишами клавиатуры. В UI переназначения они выделяются в отдельную группу «TV-пульт» для удобства обнаружения.

**Столп B — Аудит и фиксация ловушек фокуса.**
Для каждой из приоритетных поверхностей (браузер файлов, плеер, ключевые диалоги) составляется карта переходов фокуса. Для ячеек на краях сеток задаются явные правила цикличного обхода или «паркинга» фокуса, исключающие тупики. Изменения применяются в layout-ресурсах без переписывания бизнес-логики.

**Столп C — Манифест: декларация leanback.**
Добавляется `<uses-feature android:name="android.software.leanback" android:required="false" />` — декларативное изменение, расширяющее видимость в Play Store на Android TV без включения TV-режима.

**Столп D — Ускоренная DPAD-прокрутка в длинных списках.**
При удерживании DPAD UP/DOWN шаг прокрутки масштабируется (например, каждые N повторных событий — прыжок на строку, а не на элемент). Поведение активируется только при `repeatCount > threshold`, не меняя поведение одиночного нажатия.

### 5.2 Потоки данных и событий

```
TV-пульт → системное событие клавиши → активность
  → слой маршрутизации ввода
    → реестр триггеров (новые TV-коды в реестре)
      → переназначение пользователя (если задано)
        → CommandId → обработчик команды
```

Фокусная навигация остаётся на стороне View-системы; правила переходов задаются декларативно в layout-файлах (`nextFocusUp/Down/Left/Right`, `focusable`, `focusableInTouchMode`).

### 5.3 Точки расширяемости

- Реестр триггеров должен быть открыт к добавлению новых кодов клавиш без изменения логики диспетчеризации.
- Механизм ускоренной прокрутки параметризуется порогом повторений, что позволяет настраивать скорость без переработки логики.

## 6. Открытые вопросы / Research items

1. **Полный список TV-кодов клавиш, не охваченных текущим реестром**
   - **Вопрос:** Какие `KEYCODE_*` генерируют распространённые Android TV-приставки помимо уже обработанных?
   - **Результаты исследования (2026-05-04):**
     - **Chromecast with Google TV** — нет цветных кнопок, нет CHANNEL_UP/DOWN. Кнопки: DPAD × 4 + CENTER, BACK, HOME (системный), MEDIA_PLAY_PAUSE, шорткаты стриминговых сервисов (перехватить нельзя).
     - **Amazon Fire TV** (официальная документация) — нет цветных кнопок. Есть: DPAD × 5, BACK, MENU, MEDIA_PLAY_PAUSE, MEDIA_REWIND, MEDIA_FAST_FORWARD, **CHANNEL_UP (166), CHANNEL_DOWN (167)**.
     - **NVIDIA Shield** — нет цветных кнопок. Кнопки пульта: DPAD × 5, BACK, HOME, BUTTON_A, BUTTON_B; медиакнопки на некоторых моделях.
     - **Xiaomi Mi Box** — нет цветных кнопок на стандартном пульте. Кнопки: DPAD × 5, BACK, HOME, MEDIA_PLAY_PAUSE.
     - **Цветные кнопки (KEYCODE_PROG_RED/GREEN/YELLOW/BLUE = 183–186)** присутствуют на: (а) встроенных пультах Android-телевизоров (Sony/Hisense/Philips с Android TV/Google TV), (б) IPTV/кабельных Android-приставках (европейский рынок DVB-T), (в) некоторых китайских Android TV-боксах (серия HOMETEQ и аналоги). **Большинство заводских прошивок не активирует PROG_-коды даже при наличии цветных кнопок на пульте** — их нужно явно прописать в keylayout-файлах устройства.
     - **Дополнительный кандидат:** `KEYCODE_INFO (165)` — кнопка «Info» присутствует на многих IPTV-пультах и пультах Smart TV; логично привязать к команде `sorting.show_info` (или существующему `system.toggle_info`).
     - **Вывод:** плановые дополнения в `default_bindings.json` (PROG_RED → delete, PROG_GREEN → copy, PROG_YELLOW → move, PROG_BLUE → rename, CHANNEL_UP → next_file, CHANNEL_DOWN → prev_file) остаются корректными. Дополнительно добавить триггер `key:165:0` (`KEYCODE_INFO`) → `system.toggle_info`.
   - **Статус:** Verified

2. **Конфликт `leanback required=false` с фильтрацией Play Store**
   - **Вопрос:** Не приведёт ли декларация `android.software.leanback required="false"` к появлению приложения на нежелательных TV-устройствах или к изменению категоризации в Play Store?
   - **Варианты:** (а) добавить только как `required="false"` — Play расширит охват; (б) не добавлять — текущее поведение сохраняется.
   - **Нужно выяснить:** Официальная документация Google однозначна: `required="false"` только расширяет охват, не меняет категоризацию. Риск минимальный.
   - **Статус:** Verified

## 9. Архитектурные решения (ADR)

**ADR-1: Расширить существующий реестр триггеров, не создавать отдельный реестр TV-клавиш**

- **Решение:** TV-коды клавиш добавляются в единый реестр существующей системы переназначения с группировкой по источнику («TV-пульт»).
- **Альтернативы:** (а) отдельный TV-реестр с собственным хранилищем — избыточная сложность; (б) жёстко закодированные дефолты без возможности переназначения — ухудшает гибкость.
- **Почему:** единый реестр упрощает логику разрешения команд и не требует изменений в слое диспетчеризации.

**ADR-2: Фокусные правила — декларативно в layout'ах, не в коде**

- **Решение:** Ловушки фокуса устраняются через атрибуты `nextFocusUp/Down/Left/Right` в XML, а не через программные переопределения `focusSearch()`.
- **Альтернативы:** (а) переопределить `focusSearch()` — гибче, но сложнее в поддержке; (б) использовать кастомный `FocusNavigationListener` — повышает связность.
- **Почему:** декларативный подход легко верифицировать визуально и не требует изменений бизнес-логики.

## 11. Критерии готовности (strategic-level)

1. В UI переназначения клавиш доступна группа «TV-пульт» с цветными кнопками, CHANNEL_UP/DOWN и медиакнопками; пользователь может назначить на них любую команду.
2. На тестовом устройстве без тачскрина (или в эмуляторе с DPAD) навигация по браузеру файлов, плееру и диалогам не застревает — любой активный элемент достижим, любой экран можно покинуть.
3. В браузере с >50 элементами удерживание DPAD DOWN перемещает фокус быстрее, чем пошаговое нажатие.
4. `android.software.leanback android:required="false"` присутствует в манифесте.
5. `docs/FEATURES.md` + `_RU.md` + `_UK.md` обновлены.
6. Изменения задокументированы в `dev/CHANGELOG.md`.
