# Спецификация: сохранение текущего кадра из видеоплеера

## 1. Цель

Добавить в приложение возможность сохранить текущий кадр из видео в заранее настроенный ресурс-получатель.

Функция должна:

- настраиваться в Настройки → Медиа → Видео;
- быть доступной из верхнего меню видеоплеера;
- работать как во время воспроизведения, так и на паузе;
- сохранять кадр в выбранный ресурс-получатель;
- при невозможности сохранить в ресурс выполнять fallback в локальный Downloads;
- показывать пользователю точное место сохранения.

## 2. Пользовательский сценарий

1. Пользователь открывает Настройки → Медиа → Видео.
2. Пользователь выбирает поле «Ресурс для сохранения кадров».
3. В поле показывается список ресурсов-получателей, уже отмеченных как destination.
4. В список не попадают виртуальные, read-only и недоступные для записи ресурсы.
5. Пользователь открывает видео в плеере.
6. В верхнем меню плеера появляется действие «Сохранить кадр».
7. При нажатии приложение извлекает кадр, соответствующий текущей позиции видео.
8. Если настроенный ресурс доступен, кадр сохраняется туда.
9. Если ресурс не выбран, удалён, стал недоступен или запись в него завершилась ошибкой, кадр сохраняется в локальный Downloads.
10. Пользователь получает сообщение с фактическим местом сохранения.

## 3. Функциональные требования

### 3.1. Новая настройка

В разделе Настройки → Медиа → Видео добавить новое поле:

- Название: «Ресурс для сохранения кадров»
- Тип: выбор одного ресурса
- Источник данных: список получателей destination
- Разрешено очистить значение: да
- Значение по умолчанию: не выбрано

Правила списка:

- показывать только destination-ресурсы;
- исключать виртуальные ресурсы;
- исключать read-only ресурсы;
- исключать ресурсы без записи;

Хранимое значение:

- идентификатор ресурса, а не имя и не путь;
- при удалении ресурса настройка не должна падать, а просто считаться невалидной до следующего выбора.

### 3.2. Команда в плеере

Для видеофайлов добавить действие «Сохранить кадр» в верхнее меню плеера.

Требования к размещению:

- команда должна быть доступна в портретной ориентации;
- команда должна быть доступна в ландшафтной ориентации;
- у команды низкий приоритет демонстрации;
- допустимо, чтобы в portrait она уходила в overflow и не вытесняла более важные команды;
- команда показывается только для MediaType.VIDEO;
- команда работает для любых источников (local, SMB, SFTP, FTP, cloud) — кадр снимается с уже отображаемой поверхности плеера, а не перечитывается из файла;
- команда не должна показываться для audio, image, gif, pdf, txt, epub.

### 3.3. Поведение команды

При нажатии на «Сохранить кадр»:

1. С поверхности PlayerView снимается bitmap текущего отображаемого кадра (PixelCopy API).
2. Кадр кодируется в PNG-файл.
3. Если настроен валидный ресурс для сохранения кадров, файл сохраняется в него.
4. Если настроенный ресурс пустой или недоступен, файл сохраняется в локальный Downloads.
5. Пользователю показывается сообщение об успехе с фактическим местом сохранения.

Ожидаемое UX-поведение:

- команда доступна и на паузе, и во время проигрывания;
- нажатие не должно принудительно останавливать воспроизведение;
- если для получения кадра нужен короткий фоновой этап, UI не должен зависать;
- при ошибке пользователь получает понятное сообщение, а не silent fail.

## 4. Правила сохранения

### 4.1. Формат файла

MVP-формат сохранения: PNG.

Причины:

- уже используется понятная схема сохранения bitmap в других частях проекта;
- PNG предсказуем для стоп-кадров;
- не требует отдельной логики выбора качества, как JPEG/WebP.

### 4.2. Имя файла

Рекомендуемый шаблон имени:

- originalVideoName_frame_yyyyMMdd_HHmmss_SSS.png

Требования:

- имя должно быть уникальным;
- имя должно быть безопасным для local/network/cloud путей;
- нельзя перезаписывать существующий файл без явной политики overwrite.

### 4.3. Fallback

Fallback в Downloads обязателен в следующих случаях:

- настройка не заполнена;
- ресурс не найден по id;
- ресурс больше не является destination;
- ресурс виртуальный;
- ресурс read-only;
- ресурс недоступен;
- произошла ошибка записи в ресурс;
- для выбранного ресурса не удалось завершить передачу.

Сообщение пользователю должно отражать реальный результат:

- «Кадр сохранён в ресурс: <имя ресурса>»
- или «Кадр сохранён в Downloads»
- или «Не удалось сохранить кадр» при полном провале и для ресурса, и для fallback.

## 5. AS-IS исследование по кодовой базе

### 5.1. Что уже есть

- Video settings уже вынесены в отдельный экран VideoSettingsFragment.
- AppSettings уже хранит media/video-настройки и подходит для добавления нового resourceId-поля.
- SettingsViewModel уже обновляет media-секцию через единый updateSettings(current.copy(...)).
- В проекте уже есть ResourcePickerDialog для выбора ресурса в настройках.
- GetDestinationsUseCase уже фильтрует destination-ресурсы и исключает виртуальные и read-only.
- Верхнее меню плеера уже строится через CommandPanelLayoutPlanner и CommandPanelController.
- Видеоплеер уже умеет получать frame bitmap через MediaMetadataRetriever для локальных видео.
- Для network/video thumbnail extraction уже есть NetworkVideoFrameDecoder и связанная инфраструктура.
- Для межпротокольной записи файлов уже есть UnifiedFileOperationHandler и temp-file pipeline.

### 5.2. Что важно учесть

- Текущий ResourcePickerDialog показывает все ресурсы, а не только destinations, значит для новой настройки его нужно ограничить правильным datasource или добавить специализированный режим фильтрации.
- Текущее извлечение кадра в VideoPlayerManager использует MediaMetadataRetriever и рассчитано на local path.
- Для SMB/SFTP/FTP/cloud текущая логика first-frame capture уже прямо отмечает ограничение: прямой MediaMetadataRetriever там не работает.
- Значит сохранение кадра для удалённых видео должно идти либо через существующий network frame extractor, либо через временный локальный файл.

## 6. Рекомендуемое решение

### 6.1. Настройки

Добавить в AppSettings новое nullable-поле:

- videoSnapshotResourceId: Long?

Поле должно:

- сохраняться в SettingsRepositoryImpl;
- участвовать в export/import backup settings;
- сбрасываться в resetMediaSection;
- отображаться в VideoSettingsFragment.

### 6.2. UI настройки

В VideoSettingsFragment добавить блок:

- заголовок «Ресурс для сохранения кадров»;
- строку с текущим выбранным ресурсом или состоянием «Не выбран»;
- кнопку выбора ресурса;
- кнопку очистки через allowClear или эквивалент;
- help tooltip с объяснением fallback в Downloads.

Источник выбора должен быть не общий список ресурсов, а список destinations, уже очищенный от виртуальных ресурсов.

### 6.3. Команда плеера

Добавить новую player command:

- id меню для overflow;
- string resource для названия;
- icon resource;
- callback в CommandPanelController;
- обработчик в callback implementation;
- условие показа только для MediaType.VIDEO.

Низкий приоритет демонстрации рекомендуется реализовать так:

- либо overflow-only командой;
- либо bar-capable командой с более низким приоритетом, чем rename/edit/cast.

Для MVP предпочтительнее overflow-only или near-overflow вариант, чтобы не ломать текущую плотность command bar.

### 6.4. Извлечение кадра

Метод: **PixelCopy** с поверхности PlayerView/SurfaceView.

Почему этот подход:

- кадр уже декодирован и отображён — не нужно повторно читать файл;
- работает для любого источника (local, SMB, SFTP, FTP, cloud);
- сохраняется именно тот кадр, который пользователь видит на экране;
- `PixelCopy.request()` доступен с API 26 = minSdk проекта.

Алгоритм:

1. Получить ссылку на `SurfaceView` внутри `PlayerView`.
2. Создать `Bitmap` с размерами поверхности.
3. Вызвать `PixelCopy.request(surfaceView, bitmap, callback, handler)`.
4. В callback получить готовый bitmap и передать дальше в pipeline.

ADR для MVP:

- использовать PixelCopy вместо MediaMetadataRetriever;
- это единственный подход, который одновременно: даёт точный текущий кадр, не зависит от источника, не требует доступа к файлу;
- если PlayerView настроен на TextureView вместо SurfaceView — использовать `textureView.getBitmap()` как более простую альтернативу.

Ограничения PixelCopy:

- вызов возможен только пока Activity/View находится на экране (foreground);
- в DRM-защищённом контенте PixelCopy вернёт ошибку `ERROR_SOURCE_INVALID` — в этом случае показать сообщение пользователю;
- не захватывает субтитры и overlay-элементы UI — только чистый видеокадр.

### 6.5. Сохранение в ресурс

После получения bitmap:

1. сохранить PNG во временный локальный файл;
2. если выбран destination-ресурс валиден, передать файл в существующий pipeline file operation/copy;
3. если destination невалиден или copy failed, сохранить тот же PNG в Downloads;
4. после успешной операции очистить temp-файл;
5. уведомить MediaStore, если сохранение ушло в локальную файловую систему.

## 7. Scope

### Flavors

Функция применяется к flavor-ам: **standard, lite, legacy** (все имеют видео).
Флавор **photos** не затронут — видео в нём отсутствует.

### In scope

- новая video-настройка выбора ресурса для кадров;
- новая команда «Сохранить кадр» в верхнем меню video player;
- поддержка portrait и landscape;
- поддержка всех источников видео (local, SMB, SFTP, FTP, cloud) — кадр с экрана;
- fallback в Downloads;
- пользовательское сообщение с фактическим местом сохранения;
- сохранение настройки в DataStore/SettingsRepository;
- участие новой настройки в export/import/reset;
- unit tests для SaveVideoFrameUseCase и fallback logic.

### Out of scope

- массовое сохранение кадров;
- выбор формата PNG/JPEG/WebP пользователем;
- отдельный редактор кадра после сохранения;
- пакетное извлечение кадров из видео;
- отдельная галерея сохранённых кадров;
- точное GPU-level снятие текущего экрана плеера с субтитрами/overlay.

## 8. Acceptance criteria

1. В Настройки → Медиа → Видео есть новое поле «Ресурс для сохранения кадров».
2. В поле выбора показываются только destination-ресурсы без виртуальных.
3. Пользователь может очистить выбранное значение.
4. В видеоплеере для видео доступна команда «Сохранить кадр».
5. Команда доступна в portrait.
6. Команда доступна в landscape.
7. Нажатие на команду во время play сохраняет точный текущий кадр с экрана.
8. Нажатие на команду на pause сохраняет точный текущий кадр с экрана.
9. Если выбранный ресурс валиден, файл сохраняется именно туда.
10. Если ресурс не выбран или недоступен, файл сохраняется в Downloads.
11. Пользователь получает сообщение с реальным местом сохранения.
12. При ошибке записи в выбранный ресурс fallback в Downloads выполняется автоматически.
13. При полном отказе сохранения пользователь получает сообщение об ошибке.
14. Новая настройка корректно переживает перезапуск приложения.
15. Export/import/reset settings не теряют новое поле.
16. Команда работает для local и remote-видео (SMB/SFTP/FTP/cloud) — кадр снимается с экрана.
17. При попытке снять кадр из DRM-контента пользователь получает сообщение об ошибке.
18. Unit tests покрывают: успешное сохранение в ресурс, все случаи fallback в Downloads, ошибку PixelCopy.

## 10. Риски и замечания

### 10.1. Риск: DRM-контент

PixelCopy возвращает `ERROR_SOURCE_INVALID` для видео с DRM-защитой (Widevine L1/L2). Проверка по источнику невозможна заранее — ошибка приходит только в callback. Обработка: показать пользователю сообщение «Защищённый контент не может быть сохранён».

### 10.2. Риск: Activity не в foreground

PixelCopy работает только пока SurfaceView видима на экране. Если Activity ушла в background в момент нажатия — PixelCopy завершится с ошибкой. Обработка: стандартная ошибка + fallback to Downloads не применяется (нет кадра — нечего сохранять), показать сообщение.

### 10.3. Риск: нет destination-ресурсов

Если у пользователя не настроено ни одного destination-ресурса, поле выбора в VideoSettingsFragment должно показывать пустой список с подсказкой «Сначала добавьте ресурс-получатель». Команда в плеере должна работать через fallback в Downloads без обращения к несуществующему ресурсу.
