## 1. Проблема

В иммерсивном режиме объёмный 180-градусный контент (`VR180_FISHEYE_SBS`) рендерится с инвертированной ориентацией: изображение перевёрнуто по вертикали и сдвинуто за затылок пользователя — чтобы что-то увидеть, нужно физически развернуться на ~180° назад. При этом HUD с прогресс-баром (S0009) остаётся перед лицом и ориентирован корректно, что подтверждает: композитор OpenXR-слоёв работает, развёрнут именно видеослой.

Прецедент: первая реализация плеера (~неделю назад от 2026-04-29) показывала тот же контент корректно. Регрессия совпала по времени с работами над HUD (S0009 + S0019). Это даёт сильный сигнал, что параметры геометрии видеослоя (повороты, переносы, axis-mapping) были изменены или замусорены при добавлении HUD-слоя.

Эффект на пользователя: VR180 стерео-контент де-факто не пригоден к просмотру — ни один обычный пользователь не будет крутиться на 180° назад, чтобы увидеть «правильную» картинку. Это блокирует основной сценарий VR-флейвора.

---

## 2. Цели

1. Объёмный 180/360 контент в иммерсивном режиме открывается «лицом к пользователю» — центр кадра совпадает с прямым взглядом при стандартной позе сидя/стоя.
2. Ориентация по всем трём осям (yaw/pitch/roll) совпадает с оригиналом видео: верх кадра — это верх для пользователя; левый глаз видит левую половину стерео-кадра.
3. После recenter-команды ориентация «лицом к пользователю» восстанавливается без перезапуска плеера.
4. HUD-слой (S0009) и видеослой не конкурируют по геометрии: переключение между cinema-quad / cylinder / equirect геометрией видеослоя не сдвигает HUD и наоборот.
5. Регрессия покрыта тестом на ориентацию: стандартный 180-файл рендерится с известным ожидаемым azimuth/elevation для центрального пикселя.

**Non-goals:**

- Не вводится новый пользовательский контрол ориентации (если он понадобится — отдельная спека).
- Не покрывается коррекция fisheye-дисторсии (это объём S0012).
- Не покрывается стерео-рассогласование (left/right swap) — отдельный класс ошибок, рассматривается только если найден в той же точке кода.
- Не покрывается панельный плеер: регрессия касается только иммерсивного рендера.

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Желательно «сбросить настройки демонстрации» — иметь явный путь возврата к корректной геометрии без выкатывания фикса по каждому параметру.
2. Желательно зафиксировать референсный набор параметров видеослоя (orientation quaternion, position, layer geometry) и сравнивать с ним в каждом релизе.
3. Желательно, чтобы расхождение между «как должно быть» и «как есть» было видно в логе — без необходимости надевать шлем, чтобы заметить регрессию.

### 3.2 Жёсткие ограничения

- **Flavor:** только VR-флейвор.
- **API level:** без новых API-зависимостей; OpenXR runtime Quest 3 (текущий), без Meta-private расширений за пределами тех, что уже используются.
- **Wear OS:** не затрагивается.
- **Производительность:** ноль; правильная ориентация — это другой набор параметров слоя, не другой алгоритм рендера.
- **Совместимость данных:** без миграций.
- **Локализация:** без новых строк UI.
- **Доступность:** без изменений.

## 4. Контекст текущей архитектуры

VR-плеер собирает в композиции OpenXR минимум один слой: `EQUIRECT_2` для 180/360 контента или `CINEMA_QUAD` для плоского. Геометрия слоя задаётся через позу (orientation quaternion + position) и параметры формы (для equirect — central angle, radius, upper/lower angle). Эти параметры рассчитываются один раз при выборе режима рендера и пересчитываются при recenter.

S0009 (Partial) добавила второй слой (HUD). Параметры HUD-слоя — head-locked ~1.0×0.3 м на дистанции 1.5 м, угол ~20° вниз. HUD рендерится корректно — пользователь видит его перед лицом. Видео же — нет; это означает, что регрессия локализована в коде, отвечающем за параметры **видеослоя**, не композитора в целом.

Возможные точки регрессии:

- При добавлении HUD-слоя могла измениться общая система координат (поза reference-space) — обычно это влияет на оба слоя одинаково, но если HUD считается в head-locked, а видео — в local или stage, расхождение возможно.
- Параметры orientation quaternion видеослоя могли быть скопированы из шаблона, рассчитанного для другого формата.
- Оси axis-mapping (Y-up vs Z-up, RH vs LH coordinate system) могли быть инвертированы при рефакторинге.
- Параметры stereo eye-views (eye-IPD, eye-rotation) могли быть зеркалированы.

Точная причина устанавливается на стадии тактической спеки — стратегически важно зафиксировать правило «один источник истины для геометрии видеослоя».

## 5. Предлагаемый подход

Подход — три блока: фиксация эталона, защита эталона тестами, путь восстановления.

### 5.1 Основные столпы / модули

**Эталонные параметры геометрии видеослоя.**
Для каждого режима рендера (`CINEMA_QUAD`, `EQUIRECT_2 180`, `EQUIRECT_2 360`, `CYLINDER`) фиксируются эталонные значения orientation quaternion, position, central angle, upper/lower angle. Эталон — это то, что давало корректную картинку в первой работающей реализации (1-2 недели до 2026-04-29). Эталон документируется как inline-комментарий рядом с расчётом параметров; ни одно изменение параметров не происходит без корректировки эталона.

**Восстановление корректных параметров.**
Сначала откатывается видеослой к эталону: через git-archeology находится коммит, в котором ориентация была корректной, и параметры геометрии переносятся в текущий код без полного отката других изменений. Если эталон не находится в истории — параметры восстанавливаются через сравнение с известной рабочей конфигурацией (Meta Media Player, ALVR, аналогичные приложения).

**Изоляция HUD-слоя от видеослоя.**
Параметры HUD-слоя и видеослоя считаются в **независимых** функциях; ни одна функция не читает поля другого слоя. Если в текущей реализации есть общий «layer geometry helper» — он разделяется на два независимых хелпера. Recenter-команда применяется к видеослою; HUD остаётся head-locked.

**Лог-проверка ориентации.**
При создании видеослоя в лог пишется единичная строка с финальными параметрами geometry: `orientation=(x,y,z,w), position=(x,y,z), centralAngle=N, upper=N, lower=N`. Эта строка сравнивается с эталоном тестом; рассинхрон ловится в CI.

### 5.2 Потоки данных и событий

```text
Выбор режима рендера (S0026 → CINEMA_QUAD | EQUIRECT_2_180 | EQUIRECT_2_360)
        │
        ▼
Расчёт геометрии видеослоя (эталонная функция)
        │
        ├── orientation quaternion
        ├── position
        ├── central angle / upper / lower (для equirect)
        └── eye-views (для стерео)
        │
        ▼
Лог-строка `VideoLayerGeometry: ...`
        │
        ▼
Composition layer attach
        │
        ▼
Recenter: применяется ТОЛЬКО к видеослою; HUD не сдвигается
```

### 5.3 Точки расширяемости

- Добавление нового режима рендера (например, fisheye-projection из S0012) добавляется как новая ветка в эталонной функции, без правок в HUD-коде.
- Если потребуется конфигурируемая ориентация (пользователь подкручивает ось) — эталонные параметры остаются default'ом, поверх ложится дельта.

## 6. Открытые вопросы / Research items

1. **Точка регрессии: HUD-PR или другая?**
   - **Вопрос:** регрессия совпадает по времени с работами над HUD, но не доказано, что причина именно там. Возможен другой PR (cold-start S0014, ray-input S0024, panel-restoration S0019).
   - **Варианты:** git-bisect между «работало» и «не работает»; ручной обзор diff'ов файлов VR-рендера за последние 2 недели.
   - **Нужно выяснить:** до начала фикса локализовать коммит-источник; это влияет на риск «починить и сломать снова».
   - **Статус:** Open.

2. **Reference space: head-locked, local или stage?**
   - **Вопрос:** в каком reference space рассчитываются orientation video-слоя — head-locked (всегда «лицом»), local (центрируется по recenter), stage (привязан к комнате)?
   - **Варианты:** local (классика для immersive video); stage (если стерео-файл должен быть «стационарной сценой»); head-locked (не подходит для стерео из-за рассинхрона глаз).
   - **Нужно выяснить:** что использует первая работающая реализация; что используют референсные приложения; согласовать с поведением recenter.
   - **Статус:** Open.

3. **Recenter и HUD.**
   - **Вопрос:** после recenter HUD должен оставаться перед лицом (head-locked) или сдвинуться вместе с видео (local)?
   - **Варианты:** «HUD всегда перед лицом» (тогда recenter не двигает HUD); «HUD привязан к сцене» (тогда recenter двигает оба).
   - **Нужно выяснить:** ожидание владельца; как S0019 описывает recenter behavior.
   - **Статус:** Open.

4. **Подтверждение бага из полевого лога — зависимость от S0026**
   - **Вопрос:** можно ли подтвердить ориентационный баг §1 из лога 2026-04-29?
   - **Данные:** в сессии `logs/fastmediasorter_20260429_022215.log` `VrPlayerActivity` оба запуска (02:22 и 02:25) немедленно уходила в фолбэк S0026 (`route=STANDARD_PANEL_FALLBACK reason=plain-2d-video`); иммерсивного рендера не было (`dbgRenderFrameCount=0`). Ориентационный баг наблюдался в предшествующей сессии (~неделю до 2026-04-29), когда иммерсив работал до регрессии HUD (S0009).
   - **Вывод:** подтвердить/опровергнуть баг S0027 из лога 2026-04-29 невозможно — сначала должен быть исправлен S0026. **S0027 разблокируется после S0026.**
   - **Статус:** Resolved.

## 7. Риски

| Риск | Вероятность | Последствия | Митигация |
| ------ | :-----------: | ------------- | ----------- |
| Откат к эталону ломает другие изменения, накопившиеся с момента «работало» | Средняя | Регрессия в смежных VR-фичах | Эталон применяется только к параметрам геометрии слоя, не к коду рендера в целом; точечный откат |

## 9. Архитектурные решения (ADR)

**ADR-1: Эталонная функция геометрии видеослоя — источник истины.**

- **Решение:** для каждого режима рендера существует ровно одна функция, возвращающая параметры геометрии (`orientation`, `position`, `central angle`, `upper/lower angle`, `eye-views`). Никакой другой код не пишет эти параметры напрямую.
- **Альтернативы:** распределённое вычисление (как сейчас) — отвергнуто, потому что это и есть источник регрессии.
- **Почему:** один файл-источник проверяется тестами; рассинхрон между «как должно быть» и «как есть» становится невозможным.

**ADR-2: HUD-слой и видеослой имеют независимые reference spaces.**

- **Решение:** HUD рассчитывается в head-locked space; видео — в local space (центрируется по recenter). Ни один параметр одного слоя не влияет на другой.
- **Альтернативы:** общий reference space — отвергнуто, потому что HUD должен оставаться перед лицом, а видео — соответствовать пространству.
- **Почему:** изоляция спейсов исключает класс ошибок «изменили HUD — сдвинулось видео».

**ADR-3: Лог `VideoLayerGeometry` — единый источник для тестов.**

- **Решение:** при каждом создании видеослоя лог пишет полный набор параметров одной строкой. Тесты сравнивают её с эталоном.
- **Альтернативы:** рантайм-инвариант (assert) — не подходит, потому что параметры считаются на разных платформах с разными floating-point округлениями; allowable diff фиксируется в тесте.
- **Почему:** наблюдаемый эталон — единственный способ заметить регрессию без надевания шлема.

## 10. Связи с другими спеками

- **S0009** (Partial) — `vr-immersive-hud-gl`. Подозреваемый источник регрессии. После S0027 HUD-слой и видеослой явно изолированы по reference space; параметры HUD из S0009 §6 #4 остаются.

- **S0014** (In Progress) — `vr-xr-cold-start`. Возможный источник регрессии (если cold-start меняет порядок инициализации reference space). Координация с S0014 — на стадии тактики.
- **S0019** (Partial) — `vr-controls-panel-flow-restoration`. Возможный источник регрессии (panel restoration трогает recenter). Координация — на стадии тактики.
- **S0024** (In Progress) — `vr-hud-ray-input`. Использует HUD-плоскость для ray-intersection; после S0027 геометрия HUD стабильна и расчёты ray не «съезжают» при изменении видео-режима.

## 11. Критерии готовности (strategic-level)

1. На Quest 3 при открытии 180-стерео-файла центр кадра расположен прямо перед лицом пользователя в стандартной позе; разворачиваться назад не нужно.
2. Верх кадра видео совпадает с верхом для пользователя; левый глаз видит левую половину стерео-кадра.
3. После recenter-команды видео центрируется заново; HUD остаётся перед лицом без смещения.
4. Параметры геометрии видеослоя пишутся одной строкой `VideoLayerGeometry` в лог; тестовый snapshot для каждого формата (180/360/cinema) совпадает с эталоном.
5. Регрессионный тест ловит инверсию orientation quaternion (тест намеренно поворачивает на 180° — падает).
6. На пять подряд cold-start иммерсивных сессий ориентация воспроизводится одинаково; первая и пятая дают идентичный VideoLayerGeometry лог.
