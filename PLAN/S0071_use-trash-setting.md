---

## 1. Проблема

При удалении локальных файлов приложение всегда перемещает их во временную папку-корзину (`.trash/`) вместо физического уничтожения. Это поведение задаётся хардкодом на уровне отдельных компонентов и не определяется пользовательской настройкой, хотя поле `useTrash` в модели настроек и соответствующий UseCase уже существуют. В результате дисковое пространство не освобождается немедленно, а пользователь не имеет возможности изменить режим удаления. Обнаружено через лог: после удаления двух видеофайлов место на устройстве не изменилось.

---

## 2. Цели

1. Пользователь может включить или отключить режим «Удалять в корзину» через настройки приложения.
2. При отключённой корзине (новый дефолт) локальные файлы немедленно уничтожаются, место освобождается сразу.
3. При включённой корзине поведение остаётся прежним: файл перемещается в `.trash/` и может быть восстановлен через Undo.
4. Все пути удаления (из браузера файлов, из плеера) читают один и тот же флаг настройки.
5. При отключённой корзине кнопка Undo после удаления не появляется — операция необратима.
6. Рядом с переключателем «Удалять в корзину» (когда он включён) отображается кнопка-иконка «Очистить корзину», при нажатии которой приложение итерирует все ресурсы и удаляет папки `.trash` из каждого.

**Non-goals:**

- Реализация полноценной «корзины» с UI просмотра и очистки — это отдельная фича.
- Изменение поведения для сетевых и облачных путей — там корзина не поддерживается по техническим причинам и всегда применяется жёсткое удаление.
- Автоматическая очистка корзины по расписанию — существующий `TrashCleanupWorker` не затрагивается.

---

## 3. Пожелания и ограничения

### 3.1 Пожелания владельца

1. Переключатель логически примыкает к группе «Безопасность / Подтверждения» в настройках операций.
2. Если корзина отключена и undo активна для других операций (перемещение, переименование) — undo на удаление не должна отображаться, но undo на остальные операции работает без изменений.

### 3.2 Жёсткие ограничения

- **Flavor:** все флейворы (`standard`, `lite`, `photos`, `legacy`) — `allowDelete` уже гейтит функцию удаления.
- **API level:** без API-специфики; механизм мягкого/жёсткого удаления уже различает Android-версии внутри.
- **Wear OS:** не затрагивается.
- **Производительность:** нет дополнительной нагрузки — одно чтение настройки перед операцией.
- **Совместимость данных:** изменение хранимого флага не требует миграции схемы БД, `useTrash` уже присутствует в модели; дефолт изменён на `false`.
- **Локализация:** EN/RU/UK — метки переключателя и tooltip обязательны во всех трёх языках.
- **Доступность:** переключатель стандартный Material Switch с явным label; дополнительных требований нет.

## 4. Контекст текущей архитектуры

Функция удаления реализована на нескольких уровнях. На уровне домена существует UseCase, который правильно читает настройку `useTrash` из репозитория настроек и вычисляет эффективный режим удаления. Однако два ключевых компонента UI-слоя — менеджер удаления в экране обзора файлов и координатор удаления в плеере — не используют этот UseCase. Вместо этого они самостоятельно решают, применять ли мягкое удаление, опираясь только на тип пути (локальный vs. сетевой), полностью игнорируя пользовательскую настройку. Переключатель в экране настроек отсутствует, поэтому поле `useTrash: Boolean = true` в модели настроек никогда не меняется пользователем и фактически является мёртвым кодом.

## 5. Предлагаемый подход

### 5.1 Основные столпы

**А — UI настроек.** Добавить переключатель «Удалять в корзину» в секцию «Безопасность / Подтверждения» экрана настроек операций. Переключатель доступен независимо от `enableSafeMode`. По умолчанию выключен. Tooltip поясняет, что при выключении удаление необратимо. Рядом с переключателем (справа, в одну строку) отображается кнопка «Очистить корзину», видимая только при включённом переключателе; по нажатию приложение удаляет папки `.trash` у всех ресурсов и показывает тост с результатом.

**Б — Менеджер удаления в браузере.** Получить доступ к настройкам через слой зависимостей. При выполнении удаления читать флаг `useTrash` и вычислять эффективный режим: `effectiveSoftDelete = useTrash && canSoftDelete(path)`. Передавать это значение в операцию удаления. При `effectiveSoftDelete = false` не сохранять Undo-операцию — удаление необратимо.

**В — Координатор удаления в плеере.** Аналогично столпу Б: вычитать `useTrash` из уже инжектированного репозитория настроек перед тем, как формировать операцию удаления. При `effectiveSoftDelete = false` не сохранять UndoOperation и не показывать Undo-снэкбар.

**Г — Путь "удаление по размеру".** Этот путь уже корректно проходит через правильный UseCase — изменений не требует.

### 5.2 Потоки данных и событий

```
Пользователь нажимает «Удалить»
  → Менеджер удаления читает настройку useTrash из репозитория
  → Вычисляет effectiveSoftDelete = useTrash && pathAllowsSoftDelete
  → Передаёт флаг в операцию удаления
  → Если effectiveSoftDelete=true: файл переименовывается в .trash/, создаётся Undo
  → Если effectiveSoftDelete=false: файл удаляется через MediaStore/File.delete(), Undo не создаётся
```

### 5.3 Точки расширяемости

- Логика `effectiveSoftDelete` должна быть вычислена в одном месте (предпочтительно UseCase), чтобы будущие точки входа удаления не дублировали её.

## 9. Архитектурные решения (ADR)

**ADR-1: Флаг `useTrash` читается на уровне компонента UI-слоя, а не переносится в UseCase**

- **Решение:** `BrowseDeleteManager` и `PlayerDeleteUndoCoordinator` читают настройку напрямую перед вызовом операции.
- **Альтернативы:** создать новый UseCase-обёртку, который инкапсулирует логику `effectiveSoftDelete`; направить оба компонента через `DeleteFilesUseCase`.
- **Почему:** минимальный diff — репозиторий настроек уже инжектирован или легко добавляется; переход на общий UseCase — отдельный рефакторинг, который не блокирует данную фикс.

**ADR-2: Undo не предлагается при жёстком удалении**

- **Решение:** при `effectiveSoftDelete=false` Undo-операция не сохраняется и Undo-снэкбар не показывается.
- **Альтернативы:** показать снэкбар с неактивной кнопкой Undo.
- **Почему:** неактивная кнопка Undo вводит в заблуждение; лучше явно не предлагать невозможное действие.

## 11. Критерии готовности (strategic-level)

1. В настройках приложения (секция «Операции») есть переключатель «Удалять в корзину» с tooltip.
2. При отключённом переключателе удаление локального файла из браузера освобождает место немедленно (файл не появляется в `.trash/`).
3. При отключённом переключателе после удаления из браузера кнопка Undo не отображается.
4. При отключённом переключателе удаление файла из плеера также освобождает место немедленно и Undo-снэкбар не появляется.
5. При включённом переключателе поведение идентично текущему: файл в `.trash/`, Undo работает; кнопка «Очистить корзину» видна и позволяет разово удалить все `.trash/` папки у всех ресурсов.
6. Для сетевых/облачных файлов поведение не изменилось — всегда жёсткое удаление.
7. Строки интерфейса локализованы на EN/RU/UK.
