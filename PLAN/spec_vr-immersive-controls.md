# Specification: VR-IMMERSIVE-CONTROLS — Управление в иммерсивном режиме VR

**Status:** Draft (UX-фаза; техническая спецификация — следующим документом после согласования)
**Date:** 2026-04-24
**Tier:** будет проставлен на этапе технической спецификации
**Roadmap entry:** Ad-hoc — выявлено пользователем 2026-04-24 после того, как `spec_vr-hybrid-app-model` привёл OpenXR-сессию в состояние `FOCUSED` и иммерсивный режим наконец стал виден на Quest 3. Текущее состояние: 3D-контент отображается, но изнутри гарнитуры у пользователя нет ни одного средства управления воспроизведением — единственный способ вмешаться — нажать системную кнопку Meta на правом контроллере, открыть оверлей ОС и принудительно закрыть приложение.

---

## 1. Проблема

После исправления иммерсивного запуска (`spec_vr-hybrid-app-model`) пользователь видит корректный 3D/стерео-контент, но изнутри гарнитуры управлять им нельзя. Единственный способ вмешаться — нажать системную кнопку Meta на правом контроллере и закрыть приложение через оверлей Horizon OS.

**Почему имеющиеся в коде хендлеры не срабатывают.** В `VrPlayerActivity.dispatchKeyEvent` ([VrPlayerActivity.kt:631-668](../app_v2/src/vr/java/com/sza/fastmediasorter/vr/VrPlayerActivity.kt#L631-L668)) обрабатываются `KEYCODE_BUTTON_X / B / MENU / BACK / THUMBL`. На Quest в **иммерсивном** режиме контроллеры Touch Plus **не шлют Android-`KeyEvent`** — ввод идёт через OpenXR action system (`xrCreateActionSet` → `xrCreateAction` → `xrSuggestInteractionProfileBindings` → `xrAttachSessionActionSets` → per-frame `xrSyncActions` + `xrGetActionStateBoolean/Float/Vector2f`). Проверено по коду: в [app_v2/src/vr/cpp/OpenXrNative.cpp](../app_v2/src/vr/cpp/OpenXrNative.cpp) (1256 строк) **нет ни одного** вызова `xrCreate*Action*`, `xrSuggest*`, `xrSync*`, `xrGetActionState*` — подсистема ввода OpenXR не создана. То есть нажатия XR-контроллера в принципе никуда не поступают: ни в нативку, ни в `dispatchKeyEvent`.

**Параллельная поверхность ввода — Bluetooth-клавиатура и мышь.** Пользователь явно просит учесть сценарий "подключил BT-клавиатуру и мышь к очкам" (частый кейс на Quest — набор текста, presenter-стиль управления). Клавиатурные события HID-устройств в Android-иммерсиве **идут** через стандартный пайплайн `dispatchKeyEvent`/`onKeyDown`/`onKeyUp`, а мышь — через `onGenericMotionEvent` с `SOURCE_MOUSE` (движение) плюс `KEYCODE_BUTTON_PRIMARY/SECONDARY/TERTIARY` (клики). Это **не OpenXR**, а обычный Android-ввод; теоретически существующие `KeyEvent`-обработчики **могут уже частично ловить** BT-клавиатуру, хотя никто пока не проверял на устройстве.

Итого управление нужно строить **на двух параллельных слоях**:

1. **OpenXR action system** (C++) — для контроллеров Touch Plus. Требует новой нативной подсистемы ввода в `OpenXrNative.cpp` и JNI-моста для проброса состояний на Kotlin-уровень.
2. **Android Input pipeline** (Kotlin, `dispatchKeyEvent` + `onGenericMotionEvent`) — для BT-клавиатуры, BT-мыши, аппаратных кнопок громкости на шлеме.

Цель этого документа — утвердить **UX-слой**: раскладка, визуальная обратная связь, сценарии. Техническая часть (как конкретно реализовать action set, как построить JNI-мост, как объединить два слоя ввода в единый `VrControllerInputManager`) — выйдет отдельным документом после согласования UX.

## 2. Цели пользовательского опыта

**Управление воспроизведением:**

1. Из иммерсивного режима всегда доступен мгновенный выход в 2D-панель (сохраняем текущее поведение, закрепляем за двумя кнопками для защиты от потери ориентации).
2. Пауза / возобновление без снятия гарнитуры, одной кнопкой.
3. Регулировка громкости без снятия гарнитуры.
4. Перемотка на фиксированный шаг (три уровня: 3 с / 10 с / 60 с).
5. Переход к предыдущему / следующему файлу текущего ресурса.
6. Вызов диалога настроек воспроизведения (`PlaybackControlDialog`) — стерео-формат, аудиодорожка, субтитры, скорость, яркость.
7. Приближение / удаление изображения (zoom экрана / купола).
8. Центрирование сцены перед лицом (re-center) — критично после поворота в кресле.
9. Переключение "иммерсивный ↔ плоский экран внутри VR-задачи" (уже реализовано в `VrToggleButtonManager`, сохраняем).
10. Первичная подсказка — шпаргалка маппинга при первом входе.

**Управление файлом (сортировка — основное назначение приложения):**

1. **Скопировать в..** — выбрать папку назначения и скопировать текущий файл, не выходя из иммерсива.
2. **Переместить в..** — аналогично переместить. После перемещения файл пропадает из текущего ресурса и плеер переходит к следующему.
3. **Удалить** — удалить текущий файл с подтверждением. После — автопереход к следующему.
4. **Переименовать** — задать новое имя файла. Требует ввода текста (BT-клавиатура или экранная клавиатура).
5. **О файле** — информация о текущем файле: имя, путь, размер, разрешение, длительность, стерео-формат, битрейт. Только для чтения.

**Поддержка устройств:** Quest 2, Quest 3, Quest Pro — всё в рамках этого спека.

Различия по профилям контроллеров:

- **Quest 2 + Quest 3 (Touch Plus):** используют один и тот же OpenXR-профиль `/interaction_profiles/oculus/touch_controller`. Один вызов `xrSuggestInteractionProfileBindings` покрывает оба устройства без дополнительной работы.
- **Quest Pro (Touch Pro):** использует профиль `/interaction_profiles/oculus/touch_pro_controller` — нужен второй вызов `xrSuggestInteractionProfileBindings` с теми же action-биндингами. Touch Pro добавляет `thumbrest/force`, `stylus/nib/value` и другую форму грипа; для нашего маппинга это не влияет на логику, нужно только зарегистрировать второй профиль.

**Non-goals для этой итерации:**
- Голосовое управление.
- Hand-tracking (управление руками без контроллеров) — в спеке `spec_vr-hand-tracking.md`.
- Перемещение / вращение экрана в пространстве руками (только zoom, не move).
- Переназначение клавиш пользователем — в спеке `spec_player-keybinding-remapping.md`.
- Управление с геймпада во всём приложении — в спеке `spec_gamepad-support.md`. BT-геймпад в иммерсиве будет работать через существующий `dispatchKeyEvent` (слой D), но отдельного UX под него не проектируем.
- Управление с левого контроллера в одноручном режиме — симметричный маппинг §4.1 частично решает задачу, выделенного режима нет.

## 3. Опорные конвенции VR-плееров

Краткое резюме того, как делают ведущие VR-видеоплееры (Skybox VR Player, DeoVR, Bigscreen, Pigasus, Meta Quest TV). Это опорная точка — не закон, но отклонения должны быть обоснованы.

| Приём | Как реализовано в индустрии |
|-------|------------------------------|
| **Луч-указатель** | Правый контроллер излучает видимый луч, пока активен триггер или при наведении на оверлей. Триггер работает как "клик мыши" по элементам оверлея. |
| **Play / Pause одной кнопкой** | `A` на правом контроллере — либо клик триггером по кнопке Play оверлея. В Skybox пользователи регулярно просят "one-click pause" без вызова оверлея — принято считать лучшей практикой. |
| **Выход / Back** | `B` на правом контроллере — общепринято как "назад / выход". Дублируется системной `BACK`. На Quest конвенция "B = назад" идёт ещё со Gear VR. |
| **Открытие меню / настроек** | Кнопка `≡` (меню, левый контроллер) либо нажатие правого триггера по иконке шестерёнки на оверлее. Системная кнопка Meta не перехватывается приложениями — всегда открывает оверлей ОС. |
| **Громкость** | Стик вверх / вниз (чаще левый). Второй распространённый вариант — аппаратные кнопки на нижней грани шлема (всегда работают параллельно, не перехватываются). |
| **Перемотка по таймлайну** | Стик влево / вправо. Шаг 5-15 с в зависимости от плеера. Skybox по умолчанию 15 с. Альтернатива — захват ползунка таймлайна лучом. |
| **Следующий / Предыдущий файл** | Часто отсутствует как отдельная клавиша, приходится идти в меню. Лучшая практика: назначить на стик второй руки, чтобы не конфликтовать с громкостью / перемоткой. |
| **Zoom экрана** | Грипы (grip / squeeze) — удерживать один грип и двигать рукой = приближение / удаление. Удерживать оба грипа и разводить = увеличение (pinch-like). В Bigscreen так перемещают экран; в Skybox / DeoVR — регулируют размер. |
| **Ре-центр** | Клик стика (чаще правого). Также повсеместно: долгое удержание системной кнопки Meta — но это системное поведение ОС. |
| **Переключение 2D ↔ immersive внутри плеера** | Отдельная кнопка на оверлее либо клик стика. В нашей реализации уже `VrToggleButtonManager` + клик левого стика. |
| **Видимость оверлея** | Скрывается через ~3 с бездействия; возвращается по любому движению контроллера / триггеру / клику стика. Never auto-show overlay во время паузы. |

### 3.1 Техническая подоплёка: OpenXR action system + Android input

Meta и Khronos документируют, что на Quest нативное приложение в immersive-сессии обязано получать ввод Touch-контроллеров **только через OpenXR actions** — никакой Android-`KeyEvent` им не предоставляется. Пайплайн на цикл кадра:

1. Один раз при создании сессии:
   - xrCreateActionSet(..) → создаётся XrActionSet (например, "playback").
   - xrCreateAction(..) для каждой логической команды (pause_toggle, volume_delta, seek_delta, zoom_delta, recenter, open_menu, exit, ..), с правильным типом (BOOLEAN_INPUT, FLOAT_INPUT, VECTOR2F_INPUT).
   - xrStringToPath(..) для каждой строки пути binding-а.
   - xrSuggestInteractionProfileBindings(instance, "/interaction_profiles/oculus/touch_controller", ..) — привязка действий к физическим элементам.
   - xrAttachSessionActionSets(session, ..) — action set прицепляется к сессии (после этого bindings уже не меняются).
2. Каждый кадр:
   - xrSyncActions(session, ..) — обновить состояния.
   - xrGetActionStateBoolean/Float/Vector2f(..) — прочитать состояние каждого action и сравнить с предыдущим для detect edge-событий.
3. При состоянии `XR_SESSION_STATE_LOSS_PENDING` — очистка.

Пути элементов для `/interaction_profiles/oculus/touch_controller` (Touch Plus, Quest 3 совместим):

**Левая рука (`/user/hand/left/input/..`):**

- `x/click` (bool) — кнопка X
- `y/click` (bool) — кнопка Y
- `menu/click` (bool) — кнопка ≡ (меню), **доступна приложению**
- `trigger/value` (float) — индекс-триггер
- `squeeze/value` (float) — грип
- `thumbstick/x` (float) — стик по X
- `thumbstick/y` (float) — стик по Y
- `thumbstick/click` (bool) — клик стика

**Правая рука (`/user/hand/right/input/..`):**

- `a/click` (bool) — кнопка A
- `b/click` (bool) — кнопка B
- `system/click` (bool) — кнопка Meta, **зарезервирована OS**, приложению недоступна
- `trigger/value` (float) — индекс-триггер
- `squeeze/value` (float) — грип
- `thumbstick/x` (float) — стик по X
- `thumbstick/y` (float) — стик по Y
- `thumbstick/click` (bool) — клик стика

Референс-реализация от Meta: [Meta-OpenXR-SDK/Samples/XrSamples/XrInput](https://github.com/meta-quest/Meta-OpenXR-SDK) — полный рабочий пример action system на Quest 2/3/Pro.

Bluetooth-периферия (HID):

- **Клавиатура** → Android разбирает HID-коды и отдаёт обычные `KeyEvent` (`KEYCODE_SPACE`, `KEYCODE_DPAD_*`, `KEYCODE_VOLUME_*`, `KEYCODE_ENTER`, ..) через `Activity.dispatchKeyEvent`. Работает и в иммерсиве, потому что ввод клавиатуры не в ведении OpenXR.
- **Мышь** → движение приходит в `View.onGenericMotionEvent` / `Activity.onGenericMotionEvent` как `MotionEvent` с источником `SOURCE_MOUSE` и action `ACTION_HOVER_MOVE`. Клики мыши — как `KeyEvent` с кодами `KEYCODE_BUTTON_PRIMARY` (ЛКМ), `KEYCODE_BUTTON_SECONDARY` (ПКМ), `KEYCODE_BUTTON_TERTIARY` (колесо-нажатие). Колесо — `MotionEvent.AXIS_VSCROLL`.
- **Геймпад** через Bluetooth (например Xbox) — шлёт `KEYCODE_BUTTON_A/B/X/Y`, `KEYCODE_BUTTON_L1/R1`, `AXIS_X/Y/Z/RZ`. В отличие от **XR-контроллеров в immersive**, геймпад-события в Android-пайплайн **доходят** — именно поэтому в коде остались `KEYCODE_BUTTON_X`-хендлеры: изначально их писали в расчёте на эту поверхность, но для Touch-контроллеров они не работают.

## 4. Предлагаемый маппинг

Управление строится на **трёх независимых слоях ввода**, каждый со своим Android/OpenXR-пайплайном (см. §3.1):

- **Слой A — контроллеры Touch Plus в immersive** — через OpenXR action system (нативно, C++).
- **Слой B — Bluetooth-клавиатура** — через Android `dispatchKeyEvent`.
- **Слой C — Bluetooth-мышь** — через Android `onGenericMotionEvent` + `dispatchKeyEvent` для клавиш.

Ни один слой не является основным: все три должны делать одно и то же множество действий, насколько физически возможно. Пользователь выбирает, чем ему удобнее в данный момент.

В таблицах колонка **Реализовано?** отражает реальное положение на 2026-04-24: для XR-контроллеров — **Нет** для всего, потому что OpenXR actions в [app_v2/src/vr/cpp/OpenXrNative.cpp](../app_v2/src/vr/cpp/OpenXrNative.cpp) не создаются вообще. Существующие `KEYCODE_*` хендлеры в [VrPlayerActivity.kt:631-668](../app_v2/src/vr/java/com/sza/fastmediasorter/vr/VrPlayerActivity.kt#L631-L668) **не вызываются** нажатиями Touch-контроллеров, но могут срабатывать на BT-геймпад или BT-клавиатуру — на устройстве не проверено.

### 4.1 Слой A — контроллеры Touch Plus (OpenXR actions)

#### 4.1.1 Левый контроллер

Все действия — **Реализовано? — Нет** (OpenXR action system отсутствует, см. §1 и §3.1).

- **Кнопка X** (`x/click`, bool) — выход в 2D-панель. Дублирует `B` правой руки для защиты от потери ориентации.
- **Кнопка Y** (`y/click`, bool) — открыть панель **файловых операций** (Копировать в / Переместить в / Удалить / Переименовать / О файле). Короткое нажатие. Программа — сортировщик, поэтому файловые операции важнее шпаргалки как постоянный жест.
- **Долгое нажатие Y** (`y/click` удержание > 0.8 с) — показать / скрыть шпаргалку маппинга.
- **Кнопка ≡ меню** (`menu/click`, bool) — открыть диалог **настроек воспроизведения** `PlaybackControlDialog` (стерео-формат, аудиодорожка, субтитры, яркость, скорость).
- **Триггер** (`trigger/value`, float, порог ~0.5) — активный луч-указатель от левой руки. Отпускание на элементе = клик.
- **Грип** (`squeeze/value`, float, порог ~0.7) — **Zoom**: удерживать и двигать рукой вперёд/назад = изменение масштаба. Два грипа одновременно зажаты > 1 с — сброс к 1.0×.
- **Стик ↑ / ↓** (`thumbstick/y`, edge на ±0.7) — громкость + / −. Один шаг = один уровень Android `AudioManager`. Автоповтор ~150 мс.
- **Стик ← / →** (`thumbstick/x`, edge на ±0.7) — перемотка −10 с / +10 с. Только edge-срабатывание, **без автоповтора** — защита от случайного ухода.
- **Клик стика** (`thumbstick/click`, bool) — переключить "immersive ↔ плоский экран" внутри VR-задачи (`VrToggleButtonManager.onToggleRequested()`). В текущем `dispatchKeyEvent` есть обработчик `KEYCODE_BUTTON_THUMBL`, но он в иммерсиве не вызывается.

#### 4.1.2 Правый контроллер

Все действия — **Реализовано? — Нет**.

- **Кнопка A** (`a/click`, bool) — **пауза / воспроизведение**. Главная клавиша плеера.
- **Кнопка B** (`b/click`, bool) — выход в 2D-панель. Главная клавиша выхода.
- **Кнопка Meta** (`system/click`) — зарезервирована OS (системный оверлей Horizon OS), приложению недоступна.
- **Триггер** (`trigger/value`, float, порог ~0.5) — луч-указатель от правой руки + клик по элементу при отпускании на нём. Основной инструмент работы с оверлеем и диалогом.
- **Грип** (`squeeze/value`, float, порог ~0.7) — Zoom, симметрично левому (см. 4.1.1).
- **Стик ↑ / ↓** (`thumbstick/y`) — громкость + / − (дубль левого). Дубль критичен для one-handed usage.
- **Стик ← / →** (`thumbstick/x`, edge) — предыдущий / следующий файл. Только edge-срабатывание. Попытка "за границу списка" — гаптика + индикатор "это первый / последний файл".
- **Клик стика** (`thumbstick/click`, bool) — **ре-центр** сцены перед лицом. Двойной клик < 0.5 с — дополнительно сброс zoom к 1.0×.

#### 4.1.3 Гаптика

OpenXR action `/output/haptic` (обе руки). Короткий импульс ~0.02 с на: пауза/плей, перемотка, смена файла, ре-центр. Длинный импульс ~0.15 с на: попытку выйти за границы списка файлов, сигнал недоступности действия (кнопка зажата во время загрузки).

### 4.2 Слой B — Bluetooth-клавиатура

Клавиатура получает события через `Activity.dispatchKeyEvent` / `onKeyDown`. Это **уже работает** на уровне Android-пайплайна — нужно только добавить обработку нужных кодов в `VrPlayerActivity`.

**Приоритет конвенций** (от старшего к новому — каждый уровень добавляет дубли, не ломает предыдущий):

1. **DOS / Norton Commander** — F-клавиши, Esc, Enter, стрелки.
2. **Windows / MPC-HC / VLC** — Space, Alt+F4, Ctrl+стрелки для крупного шага.
3. **Браузерный YouTube** — J/L, K, M, I.
4. **Медиаклавиши BT-пультов** — KEYCODE_MEDIA_*.

---

**Уровень 1 — DOS/Norton Commander (первичный):**

- **F1** (`KEYCODE_F1`) — справка: шпаргалка маппинга. **NC: F1 = Help.**
- **F3** (`KEYCODE_F3`) — информация о файле ("О файле"). **NC: F3 = View** — читать файл; здесь: просмотр метаданных.
- **F4** (`KEYCODE_F4`) — настройки воспроизведения `PlaybackControlDialog`. **NC: F4 = Edit.**
- **F5** (`KEYCODE_F5`) — **Скопировать в..** NC: F5 = Copy. Прямое попадание.
- **F6** (`KEYCODE_F6`) — **Переместить в..** NC: F6 = Move/RenMov. Прямое попадание.
- **F7** (`KEYCODE_F7`) — открыть панель всех файловых операций (аналог NC: F7 = MkDir → "сделать что-то с деревом"). Резервная точка входа, если пользователь забыл F5/F6/F8.
- **F8** (`KEYCODE_F8`) — **Удалить** (с подтверждением). **NC: F8 = Delete.** Прямое попадание.
- **F2** (`KEYCODE_F2`) — **Переименовать**. В NC: F2 = User menu (вариативно); здесь осмысленная альтернатива — ближе к TC (Total Commander) где F2 = Rename.
- **F10** (`KEYCODE_F10`) — выход в 2D-панель. **NC: F10 = Quit.**
- **Esc** (`KEYCODE_ESCAPE`) — выход в 2D-панель (дубль F10). NC/DOS universal "отмена/выход".
- **← / →** (`KEYCODE_DPAD_LEFT / RIGHT`) — перемотка −10 с / +10 с. Стрелки = навигация — базово.
- **↑ / ↓** (`KEYCODE_DPAD_UP / DOWN`) — громкость + / −.
- **Enter** (`KEYCODE_ENTER`) — подтвердить фокусированный элемент оверлея / диалога / панели файлов.

**Уровень 2 — Windows / MPC-HC / VLC:**

- **Alt+F4** (`KEYCODE_F4` + meta `ALT_ON`) — выход в 2D-панель. Windows: закрыть окно.
- **Space** (`KEYCODE_SPACE`) — пауза / воспроизведение. WMP / VLC / MPC-HC стандарт.
- **Ctrl+← / →** (`KEYCODE_DPAD_LEFT/RIGHT` + meta `CTRL_ON`) — перемотка −60 с / +60 с. VLC: Ctrl+Left = 1 min seek.
- **Shift+← / →** (`KEYCODE_DPAD_LEFT/RIGHT` + meta `SHIFT_ON`) — перемотка −3 с / +3 с. VLC: Shift+Left = 3 s micro-seek.
- **M** (`KEYCODE_M`) — mute / unmute. VLC / WMP стандарт.
- **Page Up / Page Down** (`KEYCODE_PAGE_UP / DOWN`) — предыдущий / следующий файл. NC: PgDn/PgUp = scroll, переосмыслено как "следующий элемент".
- **+ / −** (`KEYCODE_PLUS / MINUS`) — zoom in / zoom out дискретными шагами (1.0× → 1.2× → 1.5× → 2.0×). VLC: + / - = rate; мы — zoom.
- **0** (`KEYCODE_0`) — сброс zoom к 1.0×. Конвенция графических редакторов.
- **Delete** (`KEYCODE_FORWARD_DEL`) — удалить файл (с подтверждением). Windows Explorer: клавиша Delete на выделенном файле.
- **Ctrl+R** (`KEYCODE_R` + `CTRL_ON`) — переименовать (дубль F2). Windows Explorer: переименование выделенного объекта.
- **Ctrl+C** (`KEYCODE_C` + `CTRL_ON`) — скопировать в.. (дубль F5). Windows Explorer: копировать; в нашем контексте — открыть выбор папки назначения.
- **Ctrl+X** (`KEYCODE_X` + `CTRL_ON`) — переместить в.. (дубль F6). Windows Explorer: вырезать → переместить.
- **Ctrl+I** (`KEYCODE_I` + `CTRL_ON`) — о файле (дубль F3). Windows Explorer / macOS Finder: свойства / информация о файле.
- **Ctrl+Y** (`KEYCODE_Y` + `CTRL_ON`) — открыть панель файловых операций (дубль кнопки Y контроллера / F7).

**Уровень 3 — YouTube-браузерный стиль:**

- **K** (`KEYCODE_K`) — пауза / воспроизведение (дубль Space в YouTube-стиле).
- **J / L** (`KEYCODE_J / L`) — перемотка −10 с / +10 с (YouTube one-handed seek).
- **N / P** (`KEYCODE_N / P`) — следующий / предыдущий файл (Next/Previous).
- **Tab** (`KEYCODE_TAB`) — открыть диалог `PlaybackControlDialog` (дубль F4).
- **C** (`KEYCODE_C`) — ре-центр сцены ("Center" — нет прямой конвенции, логичная буква).
- **V** (`KEYCODE_V`) — переключить immersive ↔ плоский экран (VR-специфично, нет исторического аналога).

**Уровень 4 — BT-пульты с медиаклавишами:**

- **Media Play/Pause** (`KEYCODE_MEDIA_PLAY_PAUSE`) — пауза / воспроизведение.
- **Media Next/Prev** (`KEYCODE_MEDIA_NEXT / PREVIOUS`) — следующий / предыдущий файл.
- **Vol +/−/Mute** (`KEYCODE_VOLUME_*`) — **не перехватываем**: Android системный, и так работает.

### 4.3 Слой C — Bluetooth-мышь

Мышь получает движение через `Activity.onGenericMotionEvent` (`MotionEvent` с `SOURCE_MOUSE`, `ACTION_HOVER_MOVE`). Клики мыши приходят как `KeyEvent.KEYCODE_BUTTON_PRIMARY/SECONDARY/TERTIARY`. Колесо — `MotionEvent.AXIS_VSCROLL`.

- **Движение мыши** (`onGenericMotionEvent` + `SOURCE_MOUSE` + `ACTION_HOVER_MOVE`) — управление **курсором на оверлее / диалоге** (плоский 2D-курсор в координатах surface). Альтернатива лучу-указателю контроллера.
- **ЛКМ** (`KEYCODE_BUTTON_PRIMARY`) — клик по элементу под курсором, если оверлей видим. Если оверлей скрыт — пауза / плей (стандарт YouTube Desktop: "клик по пустому = пауза").
- **ПКМ** (`KEYCODE_BUTTON_SECONDARY`) — открыть диалог `PlaybackControlDialog`. Правая кнопка = контекстное меню.
- **Колесо ↑ / ↓** (`AXIS_VSCROLL`) — громкость + / −. Аналогично YouTube Desktop.
- **Shift + Колесо** (`AXIS_VSCROLL` + meta-state `SHIFT_ON`) — перемотка −10 с / +10 с. Чтобы перематывать колесом без смены режима.
- **СКМ** (`KEYCODE_BUTTON_TERTIARY`) — ре-центр сцены. Конвенция "нажатое колесо = специальное действие".
- **Button 4 / 5** (`KEYCODE_BUTTON_4 / 5`) — предыдущий / следующий файл. Боковые кнопки игровой мыши.

**Важно:** курсор мыши на оверлее — это **альтернатива** лазерному лучу с контроллера. В один момент активен один из трёх источников указания (луч левой руки / луч правой руки / курсор мыши) — последний изменивший позицию.

### 4.4 Аппаратные кнопки на шлеме

- Кнопки громкости на нижней грани шлема — работают всегда параллельно стикам и клавиатуре (системное поведение, не перехватываем).
- Длинное удержание кнопки Meta — системный ре-центр на уровне OS (не конфликтует с нашим ре-центром).

```
                 ┌─────────────────────────┐        ┌─────────────────────────┐
                 │     ЛЕВЫЙ КОНТРОЛЛЕР    │        │    ПРАВЫЙ КОНТРОЛЛЕР    │
                 ├─────────────────────────┤        ├─────────────────────────┤
  кнопка  X   →  │ выход в 2D-панель       │        │ кнопка A  → ПАУЗА/ПЛЕЙ  │

  триггер     →  │ луч-указатель           │        │ триггер   → луч+клик    │
```

## 5. Визуальная обратная связь

Маппинг без индикации = игра в слепую. Минимальный набор HUD-элементов:

### 5.1 Всплывающие индикаторы (floating toasts)

| Действие | Индикатор | Длительность |
|----------|-----------|---------------|
| Пауза / воспроизведение | Крупная иконка `▶` или `❚❚` в центре на 0.8 с | ~0.8 с |
| Громкость | Вертикальная шкала справа по центру взгляда, отсчёт от 0 до максимума, цифра % над шкалой | 1.5 с после последнего изменения |
| Перемотка | Внизу по центру взгляда: `◀◀ −10с  [текущее / общее]` или `[текущее / общее]  +10с ▶▶` | 1.2 с |
| Следующий / Предыдущий файл | Справа вверху по центру взгляда: имя файла и индикатор `3 / 12` | 2.0 с |
| Zoom | Кратность масштаба (`1.2×`, `0.8×`) в центре | 1.0 с после отпускания грипа |
| Ре-центр | Короткая вспышка белой рамки по периметру экрана | 0.3 с |
| 3D ↔ плоский | Крупный текст "Плоский экран" / "3D VR" на 1.2 с | 1.2 с |

Индикаторы **не блокируют** основной оверлей (`VrControlOverlay`) — рендерятся поверх него или в отдельном слое на уровне шлема. Пропадают сами; не требуют дисмисса.

### 5.2 Оверлей с таймлайном (`VrControlOverlay`)

Существующий XR-оверлей. Логика видимости:

- **Появляется** при любом движении контроллера, клике любого стика, нажатии триггера.
- **Скрывается** через 3 с бездействия.
- Во время паузы — остаётся видимым постоянно.
- При открытом диалоге (`PlaybackControlDialog`) — скрыт принудительно.

Состав оверлея уточним на технической фазе; предположительно — таймлайн-ползунок, кнопки Play / Pause / Prev / Next / Settings / Exit — всё дублирует клавиатурный маппинг. Клик лучом по элементу = то же, что клавиша.

### 5.3 Шпаргалка маппинга (долгое нажатие Y)

При первом входе в иммерсивный режим (однократно после установки) — шпаргалка показывается автоматически на 4 с. В дальнейшем — по долгому нажатию Y (>0.8 с) или клавише F1 на BT-клавиатуре.

Содержимое: картинка контроллеров со стрелками + таблица F-клавиш. Текст на языке интерфейса приложения (EN/RU/UK).

### 5.4 Диалог настроек воспроизведения (`PlaybackControlDialog`)

Существующий `PlaybackControlDialogFragment`. Открывается кнопкой ≡ / F4. Внутри — подбор стерео-формата, аудиодорожки, субтитров, скорости, яркости. В технической фазе проверим hit-target для луча-указателя.

### 5.5 Панель файловых операций (кнопка Y / F5/F6/F8)

Новый оверлей, специфичный для FastMediaSorter. Открывается кнопкой Y или прямыми F-клавишами. Видео при открытии **автоматически ставится на паузу**.

**Структура панели** — вертикальный список из 5 действий, навигация лучом-указателем или стрелками ↑↓:

```
┌────────────────────────────────────────┐
│  📋  Скопировать в..        [F5]       │
│  ✂️  Переместить в..        [F6]       │
│  🗑  Удалить                [F8]       │
│  ✏️  Переименовать           [F2]       │
│  ℹ️  О файле                [F3]       │
│                    [Esc / B — закрыть] │
└────────────────────────────────────────┘
```

Панель позиционируется у нижнего края поля зрения (не перекрывает центр экрана). Закрытие — B / Esc / повторное Y / клик вне области.

**Выбор папки для "Скопировать в" и "Переместить в":**

Полноценный 3D-браузер папок в VR сложен в реализации и в пользовании. Предлагаемый подход — двухуровневый:

```text
┌──────────────────────────────────────────────┐
│  Куда копировать?                            │
│  ─────────────────────────────────────────── │
│  ★  /storage/sdcard/Sorted/VR180             │  ← последние
│  ★  /storage/sdcard/Sorted/3D                │    5–10 папок
│  ★  /storage/sdcard/Sorted/Favourites        │
│  ─────────────────────────────────────────── │
│  📂  Выбрать другую папку..   (→ 2D-панель) │
│  ─────────────────────────────────────────── │
│  [Enter / A — ОК]           [Esc / B — отмена]│
└──────────────────────────────────────────────┘
```

- **Последние папки** (список `recent_destinations` из Room) — выбор одной кнопкой, операция выполняется без выхода из VR.
- **"Выбрать другую папку.."** — выходит в 2D-панель (`VrTaskTransition.exitImmersiveToPanel`), открывает браузер папок, после выбора возвращается в VR с тем же файлом. Детали механизма — в технической фазе.

**Удаление** — перед выполнением показывает подтверждение:

```text
  Удалить файл?
  "dragon_3d_180.mp4"  (2.1 ГБ)
  [A / Enter — Удалить]   [B / Esc — Отмена]
```

## 6. Сценарии пользователя

Каждый сценарий — что именно делает пользователь и каким будет ответ системы.

### 6.1 Первый запуск иммерсивного режима

1. Пользователь тапает VR-файл в браузере → открывается иммерсивный VR.
2. В течение первых 4 с над экраном видна **шпаргалка маппинга**.
3. Шпаргалка пропадает сама. Пользователь начинает смотреть.

### 6.2 Пауза и возобновление

1. В процессе просмотра — нажатие **A** на правом контроллере.
2. Видео останавливается, в центре на 0.8 с появляется иконка `❚❚`.
3. Оверлей с таймлайном становится видимым и не пропадает (индикация паузы).
4. Повторное нажатие **A** — видео возобновляется, иконка `▶`, оверлей через 3 с исчезает.

### 6.3 Регулировка громкости

1. Пользователь наклоняет стик любого контроллера **вверх** — громкость +1.
2. Справа в поле зрения появляется вертикальная шкала; остаётся 1.5 с.
3. Удержание стика вверх продолжает повышать громкость шагами по 1 единице каждые ~150 мс.
4. Отпускание стика — шкала остаётся видимой ещё 1.5 с и пропадает.

### 6.4 Перемотка

1. Пользователь щёлкает стиком **левого** контроллера **вправо**.
2. Видео перематывается на +10 с; внизу появляется индикатор `[01:32 / 14:20] +10с ▶▶`.
3. Отдельные щелчки — суммируются по 10 с каждый. Удержание стика — **не автоповтор** (защита от "улетания").

### 6.5 Смена файла

1. Пользователь щёлкает стиком **правого** контроллера **вправо**.
2. Текущий файл закрывается, следующий загружается; справа вверху на 2 с появляется имя файла и позиция `3 / 12`.
3. Если файл следующего типа требует другого стерео-формата — запускается авто-определение; при неудаче открывается диалог настроек с предложением выбрать вручную.

### 6.6 Настройка стерео-формата и аудиодорожки

1. Во время просмотра пользователь видит, что стерео-формат определён неверно (двоится).
2. Нажимает **≡** на левом контроллере.
3. Открывается `PlaybackControlDialog`; луч-указатель автоматически активен.
4. Пользователь лучом правого контроллера выбирает нужный пункт стерео-формата / аудио.
5. Закрывает диалог крестиком или повторным ≡. Настройка применяется мгновенно.

### 6.7 Zoom и ре-центр

1. Пользователь зажимает **грип** правого контроллера и двигает рукой вперёд.
2. Картинка приближается; по центру кратковременно видно `1.3×`.
3. Отпускает грип — масштаб фиксируется.
4. Далее он поворачивает голову влево и теряет ощущение центра. Щёлкает **стик правого** контроллера.
5. Экран переносится прямо перед лицом, вспышка белой рамки; угол сброшен.
6. Чтобы вернуться к 100% — двойной щелчок стика правого контроллера.

### 6.8 Выход

1. Пользователь нажимает **B** на правом контроллере (или **X**, или системную `BACK`).
2. Иммерсивный режим закрывается; возвращается 2D-панель `MainActivity` (через `VrTaskTransition.exitImmersiveToPanel`, реализовано в `spec_vr-hybrid-app-model`).

### 6.9 Переключение в плоский экран внутри VR

1. Пользователь хочет посмотреть 2D-фильм не выходя из VR — щёлкает **стик левого** контроллера.
2. `VrPlayerActivity` перезапускается в режиме плоского экрана; на 1.2 с видна надпись "Плоский экран".
3. Повторный щелчок — возврат в иммерсивный 3D.

### 6.10 Копирование файла в папку из иммерсива

1. Пользователь смотрит VR-ролик и хочет переложить его в "Избранное" — нажимает **Y** (или **F5**).
2. Видео автоматически встаёт на паузу. Открывается панель файловых операций.
3. Пользователь наводит луч на "Скопировать в.." и нажимает триггер (или жмёт Enter/A).
4. Открывается список последних папок-назначений. Выбирает `/Sorted/Favourites` лучом + триггер.
5. Копирование выполняется в фоне. На 2 с появляется индикатор "Скопировано в Favourites ✓".
6. Панель закрывается, видео возобновляется автоматически.

### 6.11 Удаление "мусорного" файла прямо во время просмотра

1. Пользователь видит что файл плохого качества — нажимает **Y**, затем лучом "Удалить" (или сразу **F8**).
2. Появляется диалог подтверждения с именем и размером файла.
3. Нажимает **A / Enter** — файл удаляется. Плеер автоматически переходит к следующему файлу в ресурсе.
4. Если файл был последним — плеер закрывается и возвращается в 2D-панель.

### 6.12 Просмотр информации о файле

1. Пользователь сомневается в стерео-формате файла перед настройкой — нажимает **F3** (или Y → О файле).
2. Панель "О файле" показывает разрешение, длительность, кодек, детектированный стерео-формат.
3. Пользователь видит `SBS-Full` и понимает что нужно выставить именно этот формат.
4. Закрывает панель (**Esc**), нажимает **≡** / **F4** → открывает `PlaybackControlDialog` → выбирает стерео.

## 7. Крайние случаи и защита от случайных нажатий

| Ситуация | Поведение |
|----------|-----------|
| Случайное задевание стика во время поворота головы | Перемотка и смена файла работают **только по щелчку** (порог 70% отклонения стика, возврат в ноль перед новым срабатыванием) — никакого автоповтора. |
| Случайный зажим грипа при хватании контроллера | Zoom начинает срабатывать только при движении руки > 10 см **при зажатом грипе** — малые тремор-движения игнорируются. |
| Пользователь не помнит маппинг | Долгое нажатие **Y** (>0.8 с) всегда вызывает шпаргалку, **F1** на клавиатуре — тоже. |
| Нечаянное нажатие Y во время просмотра | Пауза применяется, панель открывается. Esc / B сразу закрывает без действий, видео возобновляется. |
| Удалить файл не тот | Ступень подтверждения обязательна — нельзя удалить без второго нажатия. |
| "Скопировать в.." — нужной папки нет в recent | Пункт "Выбрать другую папку.." выходит в 2D-панель для полноценного выбора из дерева. |
| Сеть недоступна при копировании облачного файла | Показывается toast-ошибка "Нет сети" на 3 с. Видео остаётся на паузе, панель открыта. |
| Панель файлов открыта, пользователь нажал B/Esc | Панель закрывается без действий, видео возобновляется. |
| Диалог `PlaybackControlDialog` открыт, пользователь нажал **A** | `A` блокируется — пауза через диалог вызвала бы конфликт фокуса. Только кнопки диалога доступны. Закрытие диалога возвращает общий маппинг. |
| Оверлей скрыт, пользователь ищет таймлайн | Любое касание стика / триггера возвращает оверлей. |
| Двойное быстрое нажатие **B** / **X** | Первое — выход. Повторное — уже в 2D-панели, не перехватывается. |
| Зажаты оба грипа | Сброс zoom к 100% — только если оба грипа зажаты более 1 с (защита от случайности). |
| Пользователь нажал **A** во время загрузки файла | Игнорируется до события `Player.STATE_READY`. Индикация: иконка `❚❚` моргает серым. |
| Пользователь нажал стик ±файл, а следующего файла нет (конец списка) | Короткое "бзз" (гаптика) + индикатор "Это последний файл" на 1.5 с. Не делаем переход на первый. |
| Сбой XR-сессии во время просмотра | Текущее поведение `launchVrFailureRecovery` сохраняется — выход в 2D-панель; этот спек не меняет recovery-flow. |

## 8. Accessibility

- Все действия, включая пауза, выход, настройки — доступны **только клавишами контроллера** (без луча-указателя). Луч — ускоряющий инструмент, не единственный.
- Пауза / плей продублирована в двух местах: `A` правого контроллера и кнопка на оверлее.
- Выход продублирован трижды: `B`, `X`, `BACK`.
- Громкость продублирована: стик любого контроллера + аппаратные клавиши на шлеме.
- Цветовые индикаторы (пауза, ре-центр) сопровождаются формой (иконка, рамка) — не только цветом.
- Шпаргалка выводится на языке интерфейса приложения (EN/RU/UK).
- Размер hit-target в оверлее для луча — не менее 5° углового размера (эквивалент ≈48 dp на плоской поверхности с дистанции просмотра). Уточняется на технической фазе.

**Что осознанно отложено:**
- Поддержка субтитров и звукового описания для слабовидящих / слабослышащих остаётся в рамках текущих возможностей ExoPlayer — в этой итерации специально не улучшается.
- Переназначение клавиш — откладывается (non-goal).
- Поддержка одной руки как отдельного режима — откладывается; симметричный маппинг частично решает задачу.

## 9. Что меняется для остальных поверхностей

- **Обычный `PlayerActivity` (не-VR)** — не затрагивается. Этот спек живёт только внутри `VrPlayerActivity` и VR-flavor.
- **Wear OS** — не затрагивается.
- **Flavors standard / lite / photos / legacy** — не затрагиваются (`BuildConfig.SUPPORT_VR_PLAYER=false`).
- **Flavors vr / vrUnlicensed** — область действия всего спека.
- **FEATURES документация** — планируется минимальное обновление (одна строка "иммерсивный VR управляется контроллерами Touch"), детали зафиксируем в технической фазе.

## 10. Вопросы, которые блокируют переход к технической фазе

Нужен явный ответ пользователя до старта реализации. Ниже — список того, что неоднозначно в предложенном маппинге или в UX-решениях.

1. **Маппинг A / B / X / Y — подтверждение:**
   - A (правый) = пауза/плей. **OK?**
   - B (правый) = выход в 2D. **OK?**
   - X (левый) = выход (дубль). **OK?** Или X использовать иначе (например, быстро заскринить через `stereoSnapshotManager`)?
   - Y (левый) = шпаргалка. **OK?** Или Y занять под часто нужную функцию (например, "следующий файл") и шпаргалку повесить на клик стика?

2. **Громкость или перемотка на левом стике по вертикали:**
   - Сейчас предложено: **влево/вправо = перемотка**, **вверх/вниз = громкость**.
   - Альтернатива (как в части плееров): **вверх/вниз = перемотка**, **влево/вправо = громкость**.
   - **Какой вариант вам ближе?**

3. **Дубль громкости на правом стике:**
   - Предложено: громкость доступна с обоих стиков по вертикали.
   - Альтернатива: на правом стике вверх/вниз повесить **яркость** (VR-плеер Skybox так делает).
   - **Громкость-дубль или яркость?**

4. **Шаги перемотки:**
   - Предложены три уровня по VLC: `Shift+←→` = 3 с (микро), `←→` = 10 с (основной), `Ctrl+←→` = 60 с (крупный).
   - На контроллере один шаг стика = 10 с (без модификаторов).
   - **Цифры 3/10/60 — OK?** Альтернатива VLC-default: 3/10/60 совпадает. MPC-HC по умолчанию 5/30/300 — если привычнее, скажите.

5. **Zoom:**
   - Предложено: удержание грипа + движение руки вперёд/назад меняет масштаб.
   - Альтернатива: клик грипа (а не удержание) циклически переключает **фиксированные уровни** 0.5× → 1.0× → 1.5× → 2.0× → 0.5×.
   - **Плавный** (удержание+движение) **или дискретный** (клик-клик-клик)? Плавный VR-native, но сложнее реализовать.

6. **Ре-центр:**
   - Предложено: клик стика правого контроллера.
   - Альтернатива: не назначать ре-центр вовсе, положиться на системную кнопку Meta (долгое удержание) — она ре-центрит всё пространство Horizon OS.
   - **Делаем собственный ре-центр внутри приложения или полагаемся только на системный?**

7. **Переключение 3D ↔ плоский экран:**
   - Сейчас: клик стика **левого** контроллера (`THUMBL`).
   - Вопрос: оставлять ли, учитывая что этот же клик мог бы пригодиться под "пауза альтернативная"? Мой голос — оставить как есть (работает, пользователи уже знают), но хочу подтверждения.

8. **Триггер / луч-указатель:**
   - Предложено: луч появляется при удержании триггера, клик = отпускание на элементе.
   - Альтернатива: луч виден **всегда** (как в системном shell Horizon OS), триггер = клик.
   - **Какой вариант?** "Всегда виден" более привычен Horizon-пользователям, но может мешать погружению.

9. **Шпаргалка маппинга при первом запуске:**
   - Предложено: показывать автоматически 4 с **однократно** после установки. Потом только по кнопке Y.
   - Альтернатива: показывать **каждый** первый иммерсивный запуск внутри сессии приложения, чтобы легко вспомнить.
   - **Однократно или каждую сессию?**

10. **Блокировка A во время диалога:**
    - Предложено: при открытом `PlaybackControlDialog` кнопка A игнорируется.
    - Альтернатива: A закрывает диалог и ставит на паузу (короткий путь).
    - **Что логичнее?**

11. **Haptic / вибрация:**
    - Предложено: короткая вибрация "бзз" при попытке перейти с последнего файла на несуществующий следующий.
    - Расширить? Например: лёгкая вибрация при каждом шаге перемотки (чтобы чувствовать шаг без индикатора)?
    - **Минимум или расширенный набор тактильной обратной связи?**

12. **Текущие хендлеры `dispatchKeyEvent` в `VrPlayerActivity` (X / B / MENU / BACK / THUMBL):**
    - В иммерсиве на Touch Plus они не срабатывают (см. §1 и §3.1). Но могут пригодиться как back-channel для BT-геймпадов.
    - **Оставлять ли их** как дополнительный слой "D — BT-геймпад" (с теми же действиями X/B/Menu), или **удалить**, раз XR-контроллеры идут через OpenXR, а BT-клавиатуру покрываем §4.2?

13. **Есть ли у вас предпочтение по длительности индикаторов** (0.8 с для паузы, 1.5 с для громкости, 2.0 с для имени файла)? Можно настроить под вас.

14. **Маппинг BT-клавиатуры (§4.2) — утверждение:**
    - Предложен обширный набор из ~20 клавиш с дублями (Space/K, ←→/J/L и т.д.). Это перекликается с YouTube / VLC / MPV. **Утвердить полный набор?** Или сократить до минимума (Space, ←→, ↑↓, Esc, Tab, C)?
    - Если у вас есть конкретный BT-пульт / клавиатура, которые планируете использовать, — можно подстроить раскладку под них (пришлите модель).

15. **Маппинг BT-мыши (§4.3) — утверждение:**
    - Курсор мыши на оверлее — параллельная поверхность указания (не заменяет луч, а сосуществует). **OK?**
    - Клик по пустому пространству = пауза / плей (YouTube Desktop-стиль). **OK?** Или ЛКМ всегда только клик по элементу, а пауза — строго через клавишу?
    - Колесо = громкость, Shift+колесо = перемотка. **OK?** Альтернатива: колесо = перемотка, Shift+колесо = громкость (кому-то привычнее).

16. **Приоритет реализации трёх слоёв ввода:**
    - Слой A (OpenXR контроллеры) требует нового C++ кода, JNI-моста, подсистемы action state sync, интеграции с кадровым циклом OpenXR — самая тяжёлая часть.
    - Слои B и C (BT-клавиатура / мышь) — правки только в Kotlin (`dispatchKeyEvent`, `onGenericMotionEvent`), пара сотен строк.
    - **Делать всё сразу одной волной**, или **сначала Слои B+C** (клавиатура / мышь) как быстрый win (будет хоть какое-то управление на тестовой сцене), **потом Слой A** (полноценный OpenXR)?

## 11. Что будет в технической спецификации (преамбула)

После того как ответы по разделу 10 зафиксированы, следующий документ (`spec_vr-immersive-controls-tech.md` или аналогичное имя) опишет реализацию **трёх слоёв ввода** отдельно и интеграцию между ними.

**Слой A — OpenXR action system (C++):**

- Расширить [app_v2/src/vr/cpp/OpenXrNative.cpp](../app_v2/src/vr/cpp/OpenXrNative.cpp) новой подсистемой:
  - `xrCreateActionSet("playback")`, `xrCreateAction(..)` для каждой логической команды (bool / float / vector2f).
  - `xrStringToPath(..)` для всех binding-путей из §3.1.
  - `xrSuggestInteractionProfileBindings(instance, "/interaction_profiles/oculus/touch_controller", ..)`.
  - `xrAttachSessionActionSets(session, ..)` после создания сессии.
  - Per-frame `xrSyncActions` + `xrGetActionStateBoolean/Float/Vector2f` в основном рендер-цикле `OpenXrSessionManager`.
  - `xrApplyHapticFeedback` для вибрации.
  - Edge-детекция в C++ (сравнение с предыдущим состоянием) для bool-actions; порог + hysteresis для float/vector2f → bool.
- Новый JNI-мост: callback из C++ в Kotlin при событиях action (`VrInputCallback.onPause()`, `onVolumeDelta(+1)`, `onSeekDelta(+10)`, `onZoomDelta(delta)`, `onRecenter()`, `onOpenMenu()`, `onExit()`, `onTogglePanel()`, `onCheatsheet()`, ..).

**Слой B — Bluetooth-клавиатура (Kotlin):**

- В `VrPlayerActivity.dispatchKeyEvent` добавить обработку `KEYCODE_SPACE`, `KEYCODE_DPAD_*`, `KEYCODE_J/K/L/M/N/P/Q/V/C`, `KEYCODE_ESCAPE`, `KEYCODE_TAB`, `KEYCODE_ENTER`, `KEYCODE_F1`, `KEYCODE_SLASH`, `KEYCODE_PAGE_UP/DOWN`, `KEYCODE_PLUS/MINUS`, `KEYCODE_0`, `KEYCODE_MEDIA_*` — маршрутизировать в те же callback-методы, что и Слой A.
- Проверить, что `VrPhoneFallbackActivity` не блокирует эту клавиатурную поверхность (на phone fallback всё равно полезно).

**Слой C — Bluetooth-мышь (Kotlin):**

- Добавить `Activity.onGenericMotionEvent(event)` в `VrPlayerActivity`: фильтр `event.source and InputDevice.SOURCE_MOUSE`; action `ACTION_HOVER_MOVE` → обновить координаты 2D-курсора на `VrControlOverlay`.
- В `dispatchKeyEvent` добавить `KEYCODE_BUTTON_PRIMARY/SECONDARY/TERTIARY/4/5`.
- Для `AXIS_VSCROLL` — отдельная ветка в `onGenericMotionEvent`.

**Общий слой интеграции:**

- Новый менеджер `VrControllerInputManager` (≤300 LOC) в `app_v2/src/vr/java/com/sza/fastmediasorter/vr/helpers/`, принимает события из всех трёх слоёв и превращает в набор `PlaybackCommand` (существующий sealed class в `VrPlayerActivity`) с расширением новыми командами (`VolumeDelta`, `ZoomDelta`, `Recenter`, `ToggleCheatsheet`).
- HUD-индикаторы: `VrHudIndicatorManager` (≤250 LOC) — таймеры пропадания, очередь индикаторов, интеграция с `VrControlOverlay`.
- Шпаргалка: `VrCheatsheetOverlayManager` (≤200 LOC) + ресурсы (SVG / PNG карточек Touch Plus).
- Zoom-логика: `VrZoomManager` (≤150 LOC) — интерполяция при грип+движение, кламп границ (0.3×–3.0×), сброс.
- Ре-центр: метод в `OpenXrSessionManager` — `recenterView()`, работает через `xrLocateSpace` со сбросом reference space.
- Строки EN/RU/UK (`values*/strings.xml`): индикаторы, шпаргалка, сообщения "первый/последний файл".
- Изменения в `PlaybackControlDialogFragment` для работы с лучом-указателем / курсором мыши — размер hit-target, focusable state.
- Тесты: unit для `VrControllerInputManager` (edge detection, hysteresis), unit для `VrZoomManager` (bounds, двойной грип), manual на Quest 3 (все сценарии §6).
- Обновления `dev/CATALOG/` и `docs/FEATURES*.md`, `dev/CHANGELOG.md` через `add_to_dev_log.ps1`.

**Документация для пользователей (обязательный deliverable после завершения реализации):**
