# Specification: PLAYER-KEYBINDING — Переназначение клавиш в настройках воспроизведения

**Status:** Backlog
**Date:** 2026-04-24
**Tier:** будет проставлен при активации
**Roadmap entry:** Ad-hoc — запрос пользователя 2026-04-24. Покрывает как VR-контроллеры (слои A/B/C из `spec_vr-immersive-controls.md`), так и клавиатурные сочетания в обычном `PlayerActivity`.

---

## 1. Проблема

Все маппинги клавиш/кнопок зашиты в код. Разные пользователи привыкли к разным раскладкам (YouTube-style, VLC-style, медиапульт). Нет способа переназначить, например, перемотку с `J/L` на `A/D` или поменять местами "следующий файл" и "громкость" на стике контроллера. Это блокирует пользователей с нестандартными BT-устройствами.

---

## 2. Цели

1. В `PlaybackControlDialog` (или отдельной вкладке настроек `Settings → Playback → Controls`) появляется экран "Управление — настройка клавиш".
2. Пользователь видит список всех логических действий (`PlaybackCommand` + `VrPlaybackCommand`) с текущим маппингом.
3. Нажатие на действие → режим "ожидание нажатия" → любая клавиша клавиатуры / кнопка контроллера / кнопка мыши записывается как новый биндинг.
4. Каждое действие допускает до 2 пользовательских биндинга в дополнение к системным дефолтам. Дефолты нельзя удалить, но можно добавить.
5. Настройки хранятся в Room-таблице `KeyBindingEntity` и загружаются при старте каждой сессии плеера.
6. Кнопка "Сбросить к дефолтам" — для всего профиля целиком.
7. Профили не привязаны к устройству — одни настройки для всех устройств этого аккаунта (Cloud sync в будущем).

Non-goals:
- Биндинги для навигации по браузеру или файловому менеджеру.
- Синхронизация через облако (локальное хранение достаточно для первой итерации).
- Биндинги для OpenXR XR_EXT_hand_tracking жестов — отдельный спек.
- Конфликт-детекция между биндингами (предупреждение, но не блокировка).

---

## 3. Техническая сложность: СРЕДНЯЯ

Ключевые компоненты:
- Новая Room-таблица `KeyBindingEntity(actionId, deviceType, keyCode, axis, threshold)` + DAO + Repository + UseCase.
- Новый Hilt-биндинг `KeyBindingRepository`.
- Экран настроек биндингов — `Fragment` + `RecyclerView` + ViewModel.
- "Capture mode" view — полноэкранный слой, перехватывающий следующий `KeyEvent` / `MotionEvent`, отображает "Нажмите кнопку..".
- Слой применения: `VrControllerInputManager` и `PlayerActivity.dispatchKeyEvent` вместо хардкода делают поиск в кэше биндингов (загружен при старте).
- Миграция Room — новая таблица, `version++`.

Сложность выше, чем просто UI, из-за:
- Необходимости перехватывать OpenXR float-actions в capture mode (для стика — нужно указать ось и порог отдельно).
- Корректного отображения имён кнопок контроллера в UI (у `thumbstick/y` нет стандартного `KeyEvent` — нужен свой маппинг названий).

---

## 4. Зависимости

- `spec_vr-immersive-controls.md` должен определить полный список `VrPlaybackCommand` — именно этот список станет источником для экрана биндингов VR.
- `PlayerActivity` / `PlaybackCommand` для обычного плеера.

---

## 5. Затрагиваемые флейворы

Все флейворы (`standard`, `lite`, `photos`, `legacy`, `vr`) — клавиатурные биндинги актуальны везде. VR-специфичные биндинги (контроллеры) видны только в VR-флейворе.
