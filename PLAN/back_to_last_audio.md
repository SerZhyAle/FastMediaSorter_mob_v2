# Задание: Возобновление воспроизведения последнего медиафайла при перезапуске приложения

## 1. Описание задачи и бизнес-цель
Реализовать функцию автоматического восстановления последнего активного состояния воспроизведения (для аудио и видео) при повторном запуске приложения, если оно было закрыто нештатным образом (любое прерывание процесса: убито системой, выключено устройство, смахнули из недавних и т.д.).

**Пользовательский сценарий (User Case):**
Приложение работает на медиасистеме (планшете) в автомобиле. Пользователь слушает музыку (в браузере файлов или в плеере) или смотрит видео. При выключении зажигания питание планшета отключается, и приложение завершается системой. При следующем запуске автомобиля и открытии приложения по иконке оно должно автоматически восстановить:
- Нужный экран (Файловый браузер или Плеер).
- Тот же самый ресурс и директорию.
- Тот же медиафайл.
- Состояние воспроизведения (играло — продолжит играть, было на паузе — откроется на паузе).
- Настройки контекста (активная сортировка файлов для правильного определения следующего трека, режим слайд-шоу плеера и т.д.).

В итоге пользователь может использовать приложение вместо встроенного медиаплеера авто без необходимости заново искать файл при каждом запуске.

## 2. Логика работы
- **Сохранение и обновление состояния:** При проигрывании медиафайла приложение должно периодически сохранять «глобальное состояние последнего файла». Мы интегрируемся в текущий механизм сохранения позиции, который уже существует. Частоты сохранения достаточно (небольшие погрешности в 10-20 секунд допустимы).
- **Очистка состояния (Сброс):** 
  - Если пользователь *явно* выходит из плеера или браузера (нажимает кнопку «Назад», крестик, штатно покидает экран и `Activity` вызывает `finish()`), сохраненное состояние "последнего файла" должно быть **обнулено**. 
  - Если пользователь переключается на **совершенно другой ресурс** (например, с локальной памяти на SMB-сервер) ИЛИ явно останавливает воспроизведение (нажатие Стоп / закрытие плеера), стейт **очищается**. Перемещение по папкам *внутри* одного ресурса при работающем inline-воспроизведении стейт **НЕ** сбрасывает.
- **Восстановление состояния:** 
  - Возобновление срабатывает **только при запуске через главную иконку приложения**. В случае запуска через виджеты конкретных папок или Intent'ы (открытие файла извне), возобновление игнорируется. В будущем может появиться отдельный виджет "Возобновить".
  - Если при старте по иконке обнаруживается необнуленный сохранённый стейт, приложение автоматически выполняет роутинг на сохраненный экран (с нужным ресурсом) и возобновляет медиа в том же состоянии (Play/Pause), в котором оно было.
- **Обработка ошибок при восстановлении:** Если ресурс недоступен (нет сети, файл удален/перемещен и т.д.), восстановление прерывается. Пользователю показывается короткий Toast ("Возобновление невозможно: файл отсутствует" / "недоступна сеть"), состояние возобновления **очищается**, и открывается стандартный главный экран приложения.
- **Поведение при восстановлении зависит от типа ресурса и типа файла:**
  - **Локальные файлы (LOCAL) — аудио и видео:** восстанавливается в том состоянии, в каком оставили (играло → продолжает играть, пауза → пауза). Никаких задержек.
  - **Сетевые файлы (SMB / FTP / SFTP) — аудио:** приложение открывает файл и начинает буферизацию с прогресс-индикатором. Воспроизведение стартует автоматически с сохранённой позиции, как только буфер готов.
  - **Сетевые файлы (SMB / FTP / SFTP) — видео:** файл открывается, но **в режиме Паузы**. Пользователь сам решает, когда нажать Play. Это защита от непредсказуемо долгой буферизации большого видео при старте.
  - **Облачные файлы (CLOUD — Google Drive, OneDrive и т.д.):** приложение пытается открыть файл напрямую через облачный стрим (как при обычном воспроизведении). Видео открывается в Паузе, аудио — с автостартом. Если облачный клиент возвращает ошибку (нет токена, файл недоступен, таймаут) — показывается Toast + сброс стейта + обычный главный экран.
  - **Любая неожиданная ошибка** на любом этапе восстановления: Toast + сброс стейта + обычный главный экран.

## 3. Необходимые шаги для реализации (Technical Plan)
1. **Модель данных и хранилище:** Добавить/расширить хранилище (Preferences, DataStore или Room) структурой о последнем запущенном файле. Поля: `uri` файла, ID `ресурса/подключения`, `тип экрана` (Browser/Player), `сортировка`, `настройки плеера` (например, слайд-шоу), `is_playing` (состояние play/pause), **`timestamp` (время сохранения для TTL)**.
2. **Точки сохранения (Save State):**
   - Интегрироваться в текущий механизм сохранения позиции. Обеспечить запись полного контекста вместе с позицией.
   - Записывать флаг состояния: играло или было на паузе.
   - Записывать текущее время сохранения для будущего контроля срока годности стейта (TTL).
3. **Обнуление (Clear State):**
   - Добавить явную очистку данных "последнего медиафайла" в обработчики штатного выхода (`onBackPressed`, нажатие кнопки закрытия в UI, onDestroy Activity в случае `isFinishing == true`).
   - Добавить очистку при ошибке возобновления или **отзыве разрешений (Permissions)** на доступ к хранилищу.
   - Добавить очистку при **смене корневого ресурса** пользователем или явной остановке воспроизведения.
4. **Механизм восстановления и роутинга (Restore State):**
   - Изучить стартовую точку (`MainActivity`) для проверки Intent. Если запуск произошел от основной иконки лаунчера (категория `LAUNCHER`, action `MAIN`), и есть сохраненное состояние — начать процесс восстановления.
   - **Срок годности (TTL):** Если стейт старше заданного лимита (например, 24-48 часов или настраиваемо), игнорировать его и произвести очистку (обычный старт).
   - **Проверка разрешений:** Убедиться, что разрешения для доступа к файлам все еще выданы. Если отозваны — очистка стейта + обычный запрос разрешений.
   - **Блокировка UI (Splash/Loader):** При возобновлении (особенно сетевых файлов, где проверка коннекта может занять 1-3 сек) отображать экран загрузки/splash-скрин, чтобы избежать зависания интерфейса до прыжка в плеер/браузер.
   - Выполнить проверку доступности ресурса/файла. Если ошибка — Toast + сброс + обычный старт.
   - Если ок — роутинг в Браузер (с центровкой) или ПлеЕР. **Критично:** необходимо восстановить **полную очередь воспроизведения (плейлист)** с учетом `сортировки` и текущей папки, а не только один файл, чтобы корректно работали кнопки "Next/Prev". Передать параметры (слайд-шоу, сортировка, play/pause).
   - **Совместимость с сервисом:** Убедиться, что логика обнуления/восстановления в MainActivity не конфликтует с системным автоматическим рестартом `AudioPlaybackService` (если процесс был завершен ОС из-за нехватки памяти).

## 4. Что нужно изучить перед реализацией
1. **Текущий механизм сохранения позиции:** Как и где сейчас сохраняется позиция воспроизведения. Подключиться к этому процессу для сохранения контекста.
2. **Архитектура запуска (Entry point):** Где происходит начальная маршрутизация (`MainActivity`, Start Flow) и как отличить запуск по иконке от запуска через виджет или сторонний интент.
3. **Навигационные механизмы:** Как сейчас реализован переход от стартового экрана в Браузер папки или напрямую в Плеер с заполнением списка (Playlist).
4. **Жизненный цикл экранов:** Изучить `onStop`, `onDestroy` текущего плеера для корректной дифференциации штатного `isFinishing` (явный выход) от "убийства" системой или смахивания из Recents.
5. **Механизм центровки списка:** Убедиться, что при открытии браузера на конкретном файле сработает существующая логика прокрутки списка так, чтобы медиафайл был по центру экрана.

## 5. Что нужно проверить (Test Cases)
1. **Штатное завершение:** Воспроизвести файл -> Нажать "Назад" / "Крестик" для закрытия плеера -> Полностью закрыть приложение -> Запустить заново. *Ожидание: Приложение открывается на обычном главном экране. Стейт очищен при выходе.*
2. **Crash-тест — локальный файл:** Воспроизвести локальный аудио/видео -> Свернуть приложение (Home) -> Убить процесс (смахнуть из Recents или через IDE) -> Запустить заново по иконке. *Ожидание: Приложение минует главное меню, открывает нужный экран и файл. Продолжает играть если играло, или остаётся на паузе если была пауза.*
3. **Crash-тест — сетевой аудиофайл (SMB/FTP/SFTP):** Воспроизвести аудио с сетевого ресурса -> Убить процесс -> Запустить по иконке, Wi-Fi включён. *Ожидание: Открывается плеер/браузер, показывается прогресс буферизации, воспроизведение стартует с сохранённой позиции автоматически.*
4. **Crash-тест — сетевой видеофайл (SMB/FTP/SFTP):** Воспроизвести видео с сетевого ресурса -> Убить процесс -> Запустить по иконке, Wi-Fi включён. *Ожидание: Открывается плеер на нужном файле, но в режиме Паузы. Пользователь сам нажимает Play.*
5. **Crash-тест — облачный файл (Google Drive / OneDrive):** Воспроизвести аудио или видео из облака -> Убить процесс -> Запустить по иконке, интернет включён. *Ожидание: Приложение пытается восстановить стрим из облака. Аудио стартует автоматически, видео открывается на паузе.*
6. **Ошибка сети:** Воспроизвести файл с SMB сервера -> Выключить Wi-Fi -> Убить процесс -> Запустить приложение. *Ожидание: Показ Toast "Возобновление невозможно...", возврат на главный экран, очистка сохранённого состояния.*
7. **Облако недоступно:** Воспроизвести облачный файл -> Выйти из аккаунта или отключить интернет -> Убить процесс -> Запустить приложение. *Ожидание: Toast + главный экран + состояние очищено.*
8. **Внешний запуск (Widgets / Intents):** Сохранить стейт (сымитировав нештатное закрытие) -> Запустить приложение через виджет конкретной папки. *Ожидание: Приложение открывает папку из виджета, старый стейт игнорируется.*
9. **Навигация без воспроизведения:** Открыть браузер, попутешествовать по папкам, ничего не играть -> Убить приложение -> Открыть заново. *Ожидание: Главный экран, потому что стейт возобновления никогда не был записан (нет активного воспроизведения).*
10. **Навигация во время воспроизведения:** Играет inline-аудио в браузере, пользователь переходит в подпапку той же библиотеки -> Убить приложение -> Открыть заново. *Ожидание: Восстановление работает — открывается браузер на нужной подпапке, аудио возобновляется. Навигация по подпапкам одного ресурса НЕ сбрасывает стейт.*
11. **Смена ресурса:** Играл файл из Ресурса A -> Переключился на Ресурс B, ничего не запустил -> Убить процесс -> Открыть заново. *Ожидание: Главный экран, так как переключение на другой ресурс очищает стейт предыдущего.*
